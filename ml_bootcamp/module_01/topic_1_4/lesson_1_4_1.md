## Зачем это нужно

Обучение идёт на удалённом сервере, и терминал там — основной интерфейс. Три ситуации, которые случаются
с каждым:

1. **Обучение шло 14 часов и умерло вместе с Wi-Fi.** Процесс был привязан к SSH-сессии и получил сигнал
   завершения, когда соединение оборвалось.
2. **Датасет на 40 ГБ не помещается в pandas на ноутбуке**, а нужно всего лишь узнать распределение классов.
   Конвейер из `cut | sort | uniq -c` отвечает за секунды и не требует памяти под весь файл.
3. **Скрипт подготовки данных «успешно» завершился, а половины файлов нет.** Одна из команд упала, bash молча
   перешёл к следующей, и ошибка всплыла только на этапе обучения.

Все примеры урока выполняются на маленьких тестовых файлах. Создайте их:

```bash
mkdir -p ~/bash-lab/data ~/bash-lab/logs && cd ~/bash-lab

cat > data/train.csv <<'EOF'
id,text,label
1,great product,positive
2,terrible support,negative
3,works as expected,neutral
4,love it,positive
5,broke after a week,negative
6,fast delivery,positive
7,not sure yet,neutral
8,best purchase this year,positive
9,waste of money,negative
10,highly recommend,positive
EOF

cat > logs/train.log <<'EOF'
2026-03-01 10:00:01 INFO  loading dataset data/train.csv
2026-03-01 10:00:05 WARNING 12 rows dropped: empty text
2026-03-01 10:04:10 INFO  epoch=1 train_loss=0.9123 val_loss=0.8811 val_acc=0.6120
2026-03-01 10:08:15 INFO  epoch=2 train_loss=0.7045 val_loss=0.7302 val_acc=0.7015
2026-03-01 10:12:21 INFO  epoch=3 train_loss=0.5530 val_loss=0.6544 val_acc=0.7480
2026-03-01 10:16:02 WARNING learning rate reduced to 0.0005
2026-03-01 10:16:30 INFO  epoch=4 train_loss=0.4312 val_loss=0.6671 val_acc=0.7455
2026-03-01 10:20:44 INFO  epoch=5 train_loss=0.3498 val_loss=0.7013 val_acc=0.7390
```

Конструкция `<<'EOF' ... EOF` называется here-document: всё между маркерами подаётся команде на stdin.
Кавычки вокруг первого `EOF` отключают подстановку переменных; без кавычек `$HOME` внутри текста раскрылся бы.

## 1. Потоки и перенаправления

У каждого процесса три стандартных потока: **stdin** (номер 0) — ввод, **stdout** (1) — результат,
**stderr** (2) — ошибки и диагностика. По умолчанию stdout и stderr оба выводятся в терминал, поэтому кажутся
одним потоком. Библиотеки пишут предупреждения и прогресс-бары в stderr, а `print()` пишет в stdout.

| Запись | Что делает |
|---|---|
| `cmd > out.log` | stdout в файл, файл перезаписывается |
| `cmd >> out.log` | stdout в конец файла |
| `cmd 2> err.log` | stderr в файл |
| `cmd > out.log 2>&1` | stdout в файл, stderr туда же |
| `cmd &> out.log` | то же самое, короткая запись (только bash) |
| `cmd 2> /dev/null` | выбросить stderr |
| `cmd < input.txt` | содержимое файла на stdin |
| `cmd1 \| cmd2` | stdout первой команды на stdin второй |
| `cmd1 2>&1 \| cmd2` | в канал попадают и stdout, и stderr |
| `cmd \| tee out.log` | вывод одновременно на экран и в файл (`tee -a` — дописывать) |

Типичный запуск обучения с сохранением полного лога и выводом на экран:

```bash
python -u train.py --config configs/baseline.yaml 2>&1 | tee logs/baseline.log
```

Два замечания к этой строке.

**Порядок перенаправлений важен.** Запись `2>&1` означает «направить stderr туда, куда сейчас смотрит stdout».
В `cmd > file 2>&1` stdout уже смотрит в файл, и stderr уходит туда же. В `cmd 2>&1 > file` на момент обработки
`2>&1` stdout ещё смотрит в терминал — ошибки останутся на экране, в файл попадёт только stdout.

**Буферизация.** Когда stdout направлен не в терминал, а в файл или канал, Python копит вывод блоками:
обучение идёт, а лог пуст. Флаг `-u` или переменная `PYTHONUNBUFFERED=1` отключают буферизацию.

## 2. Пайпы: конструктор из маленьких утилит

Каждая утилита делает одно действие над текстовыми строками, а канал `|` соединяет их в конвейер.

| Утилита | Действие | Частые флаги |
|---|---|---|
| `head`, `tail` | первые или последние строки | `-n 20`; `tail -n +2` — начиная со 2-й строки; `tail -f` — следить за файлом |
| `wc` | подсчёт | `-l` — строки |
| `grep` | отбор строк по шаблону | `-c` — число совпадений, `-v` — инверсия, `-E` — расширенные регулярные выражения, `-o` — только совпавшая часть, `-r` — рекурсивно |
| `cut` | вырезать столбцы | `-d,` — разделитель, `-f3` — номер поля |
| `sort` | сортировка | `-n` — числа, `-r` — по убыванию, `-t, -k3,3` — по третьему столбцу, `-u` — без повторов |
| `uniq` | схлопнуть одинаковые соседние строки | `-c` — с подсчётом (вход должен быть отсортирован) |
| `sed` | замена и извлечение по шаблону | `-n`, `-E`, `s/что/на что/p` |
| `awk` | обработка по столбцам, арифметика | `-F,` — разделитель; `$1`, `$NF`, `NR` |
| `find` | поиск файлов | `-name`, `-mtime`, `-size`, `-print0`, `-delete` |
| `xargs` | превратить строки stdin в аргументы команды | `-0`, `-n 1`, `-P 4`, `-I {}` |

### Задача 1. Распределение классов в CSV

```bash
tail -n +2 data/train.csv | cut -d, -f3 | sort | uniq -c | sort -rn
```

```text
      5 positive
      3 negative
      2 neutral
```

Читается слева направо: отбросить заголовок, взять третий столбец, отсортировать, схлопнуть повторы
с подсчётом, отсортировать по убыванию числа. То же с долями — на `awk`:

```bash
awk -F, 'NR > 1 { n[$3]++ }
         END { for (c in n) printf "%-10s %d %.1f%%\n", c, n[c], 100 * n[c] / (NR - 1) }' data/train.csv |
    sort -k2,2nr
```

```text
positive   5 50.0%
negative   3 30.0%
neutral    2 20.0%
```

`awk` выполняет блок `{ ... }` для каждой строки, подходящей под условие перед ним, а блок `END` — после
последней строки. `n` — ассоциативный массив «класс → счётчик».

**Ограничение.** `cut -d,` и `awk -F,` режут строку по каждой запятой и не понимают кавычек CSV. Если в тексте
встречается `"Hello, world"`, столбцы съедут. Для быстрой разведки этого достаточно, для точного подсчёта
берите Python.

Тем же `awk` CSV превращается в JSONL (один JSON-объект в строке), а классы в JSONL считает `grep -o`:

```bash
awk -F, 'NR > 1 { printf "{\"id\": %s, \"text\": \"%s\", \"label\": \"%s\"}\n", $1, $2, $3 }' \
    data/train.csv > data/train.jsonl
grep -o '"label": "[a-z]*"' data/train.jsonl | sort | uniq -c | sort -rn
```

```text
      5 "label": "positive"
      3 "label": "negative"
      2 "label": "neutral"
```

### Задача 2. Метрики из лога обучения

```bash
grep -c ERROR logs/train.log                          # сколько строк с ошибками: 1
grep -E 'WARNING|ERROR' logs/train.log                # показать предупреждения и ошибки
awk '{ print $3 }' logs/train.log | sort | uniq -c    # сколько строк каждого уровня
tail -f logs/train.log | grep --line-buffered val_acc # следить за метрикой в реальном времени
```

Лучшая эпоха по `val_acc`:

```bash
sed -nE 's/.*epoch=([0-9]+).*val_acc=([0-9.]+).*/\2 \1/p' logs/train.log | sort -rn | head -n 1
```

```text
0.7480 3
```

`sed -n ... p` печатает только строки, где замена сработала; `\1` и `\2` — группы в круглых скобках. Тем же
приёмом лог превращается в CSV для построения графика:

```bash
sed -nE 's/.*epoch=([0-9]+).*val_loss=([0-9.]+).*/\1,\2/p' logs/train.log > val_loss.csv
```

### Задача 3. Действие над множеством файлов

```bash
find checkpoints -name '*.pt' -mtime +7                       # чекпоинты старше 7 дней
find checkpoints -name '*.pt' -print0 | xargs -0 du -ch | tail -n 1   # суммарный размер чекпоинтов
find data -name '*.csv' -print0 | xargs -0 -n 1 wc -l         # число строк в каждом CSV
find data -name '*.csv' -print0 | xargs -0 -P 4 -I {} gzip -k {}      # сжать в 4 потока, оригиналы оставить
```

Пара `-print0` и `-0` разделяет имена нулевым байтом. Без неё файл `my model.pt` превратится в два аргумента:
`my` и `model.pt`.

## 3. Коды возврата и строгий режим

Каждая команда завершается с числом от 0 до 255. **0 — успех, всё остальное — ошибка.** Код последней команды
лежит в `$?`.

```bash
python train.py && python evaluate.py     # evaluate запустится только при успехе train
python train.py || echo "обучение упало"  # правая часть выполнится только при ошибке
```

В скрипте bash по умолчанию игнорирует ошибки и идёт дальше. Поэтому каждый скрипт курса начинается так:

```bash
#!/usr/bin/env bash
set -euo pipefail
```

| Флаг | Что меняет |
|---|---|
| `-e` | скрипт останавливается на первой команде с ненулевым кодом |
| `-u` | обращение к неопределённой переменной — ошибка (ловит опечатки вроде `rm -rf "$DATA_DIR_/"`) |
| `-o pipefail` | конвейер считается упавшим, если упала любая его команда, а не только последняя |

Зачем `pipefail`: без него `python train.py | tee train.log` всегда возвращает 0, потому что `tee` отработал
успешно. Скрипт сочтёт упавшее обучение удачным и перейдёт к оценке модели.

Оговорки: `-e` не действует на команды внутри условия `if`, слева от `&&` и `||`. Команду, которой разрешено
падать, пишите как `command || true`. Команда `grep`, не нашедшая совпадений, возвращает 1 — в строгом режиме
это остановит скрипт.

## 4. Process substitution

Запись `<(команда)` подставляет вывод команды туда, где ожидается имя файла. Так сравнивают результаты двух
команд без временных файлов:

```bash
# совпадает ли набор классов в train и val
diff <(cut -d, -f3 data/train.csv | sort -u) <(cut -d, -f3 data/val.csv | sort -u)

# сколько id встречается в обоих файлах (признак утечки данных между выборками)
comm -12 <(tail -n +2 data/train.csv | cut -d, -f1 | sort) \
         <(tail -n +2 data/val.csv | cut -d, -f1 | sort) | wc -l
```

`diff` молчит и возвращает 0, если входы одинаковы. `comm -12` оставляет строки, общие для двух
отсортированных входов.

## 5. Job control и сигналы

| Действие | Команда |
|---|---|
| запустить в фоне | `python train.py > train.log 2>&1 &` |
| список фоновых задач оболочки | `jobs` (с PID: `jobs -l`) |
| приостановить задачу на переднем плане | `Ctrl+Z` |
| продолжить приостановленную в фоне | `bg %1` |
| вернуть на передний план | `fg %1` |
| дождаться фоновых задач | `wait` |
| отправить сигнал | `kill %1`, `kill 41237`, `kill -9 41237` |

`%1` — номер задачи из `jobs`, число без процента — PID процесса.

| Сигнал | Номер | Откуда | Можно перехватить |
|---|---|---|---|
| `SIGINT` | 2 | `Ctrl+C` | да |
| `SIGTERM` | 15 | `kill` без флагов, остановка сервиса | да |
| `SIGKILL` | 9 | `kill -9` | нет |
| `SIGHUP` | 1 | закрытие терминала, обрыв SSH | да |
| `SIGTSTP` | 20 | `Ctrl+Z` | да |

Порядок остановки обучения: сначала `kill PID` (SIGTERM) — у программы есть возможность завершиться
корректно: сохранить чекпоинт, освободить GPU. `kill -9` — только если процесс не отреагировал за разумное
время: после SIGKILL не выполняются никакие обработчики, а временные файлы остаются на диске.

**Обрыв SSH.** При обрыве соединения или закрытии окна терминала оболочка получает SIGHUP и рассылает его
своим задачам — они завершаются. Два способа отвязать процесс от терминала:

```bash
nohup python -u train.py > train.log 2>&1 &   # запустить с игнорированием SIGHUP

# если обучение уже запущено без nohup: Ctrl+Z, затем
bg %1
disown -h %1                                  # оболочка не пошлёт этой задаче SIGHUP
```

У обоих способов общий недостаток: к процессу нельзя «вернуться» и увидеть его вывод вживую. Поэтому основной
инструмент — `tmux`.

## 6. tmux: сессии, которые переживают SSH

`tmux` запускает оболочку внутри сервера сессий. SSH-соединение можно закрыть, а сессия со всеми процессами
продолжит работать.

```bash
sudo apt install -y tmux
tmux new -s train              # создать сессию с именем train и войти в неё
# ... запустить обучение, затем отсоединиться: Ctrl+b, потом d
tmux ls                        # список сессий
tmux attach -t train           # подключиться снова, в том числе после переподключения по SSH
tmux kill-session -t train     # завершить сессию вместе с процессами в ней
```

| Клавиши (после `Ctrl+b`) | Действие |
|---|---|
| `d` | отсоединиться, сессия продолжает работать |
| `c`, `n`, `p` | новое окно, следующее, предыдущее |
| `%`, `"` | разделить окно на левую и правую панели; на верхнюю и нижнюю |
| стрелки | переход между панелями |
| `[` | режим прокрутки истории (выход — `q`) |

Рабочая раскладка на время обучения: в одной панели сам запуск, во второй `tail -f` по логу, в третьей
`watch -n 1 nvidia-smi` (следующий урок).

**Правило курса:** всё, что работает дольше нескольких минут на удалённом сервере, запускается внутри `tmux`.

## 7. Основы скриптов

```bash
#!/usr/bin/env bash
# Проверяет CSV-файлы перед обучением: достаточно ли строк и нет ли повторяющихся id.
set -euo pipefail

readonly DATA_DIR="${1:-data}"          # первый аргумент, по умолчанию data
readonly MIN_ROWS="${MIN_ROWS:-5}"      # переменная окружения со значением по умолчанию

log() {
    printf '%s [%s] %s\n' "$(date '+%F %T')" "$1" "$2" >&2
}

tmp_dir="$(mktemp -d)"
cleanup() {
    rm -rf "$tmp_dir"
}
trap cleanup EXIT

count_duplicate_ids() {
    local file="$1"
    tail -n +2 "$file" | cut -d, -f1 | sort > "$tmp_dir/ids.txt"
    uniq -d "$tmp_dir/ids.txt" | wc -l
}

for file in "$DATA_DIR"/*.csv; do
    rows="$(tail -n +2 "$file" | wc -l)"
    duplicates="$(count_duplicate_ids "$file")"
    if (( rows < MIN_ROWS || duplicates > 0 )); then
        log ERROR "$file: строк $rows (минимум $MIN_ROWS), повторяющихся id: $duplicates"
        exit 1
    fi
    log INFO "$file: строк $rows, повторов id нет"
done
```

Сохраните как `check_data.sh`, выдайте право на исполнение и запустите:

```bash
chmod +x check_data.sh
./check_data.sh data                 # код возврата 0
MIN_ROWS=100 ./check_data.sh data    # код возврата 1: в train.csv меньше 100 строк
```

Что здесь важно:

- **Shebang** `#!/usr/bin/env bash` в первой строке сообщает системе, каким интерпретатором выполнять файл.
- **Присваивание пишется без пробелов:** `name=value`. Запись `name = value` — это запуск команды `name`.
- **Переменные всегда в двойных кавычках:** `"$file"`. Без кавычек значение с пробелом распадается
  на несколько аргументов. В одинарных кавычках подстановка не происходит вовсе.
- **`$(команда)`** подставляет вывод команды; **`${var:-значение}`** — значение по умолчанию;
  **`$1`, `$2`, `"$@"`, `$#`** — аргументы скрипта, все аргументы и их количество.
- **`[[ ... ]]`** проверяет строки и файлы (`[[ -f "$file" ]]`, `[[ -z "$var" ]]`),
  **`(( ... ))`** сравнивает целые числа.
- **`local`** ограничивает переменную функцией. Без него все переменные в bash глобальные.
- **Диагностика идёт в stderr** (`>&2`), чтобы stdout скрипта можно было передать дальше по конвейеру.
- **`trap cleanup EXIT`** вызывает функцию при любом завершении скрипта: штатном, по ошибке, по `Ctrl+C`.
  Временная папка из `mktemp -d` будет удалена, даже если скрипт упал на середине.

Проверяйте скрипты линтером `shellcheck` (`sudo apt install -y shellcheck`) — он находит забытые кавычки
и другие типовые ошибки: `shellcheck check_data.sh`. Проверка синтаксиса без запуска: `bash -n check_data.sh`.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Ошибки видны на экране, но в лог-файл не попали | перенаправлен только stdout или перепутан порядок: `2>&1 > file` | `cmd > file 2>&1` или `cmd 2>&1 \| tee file` |
| Лог обучения пуст, хотя процесс работает | Python буферизует stdout, направленный в файл или канал | `python -u` или `PYTHONUNBUFFERED=1` |
| Обучение завершилось при обрыве SSH | процесс получил SIGHUP вместе с сессией | запускайте в `tmux`; для уже запущенного — `bg` и `disown -h` |
| `No such file or directory` на существующем файле с пробелом в имени | переменная без кавычек | `"$file"`, в конвейерах — `find -print0 \| xargs -0` |
| Скрипт «успешно» завершился после упавшей команды | нет строгого режима | `set -euo pipefail` в начале скрипта |
| `python train.py \| tee log` возвращает 0 при падении обучения | код конвейера равен коду последней команды | `set -o pipefail` или `${PIPESTATUS[0]}` |
| `uniq -c` выдаёт один и тот же класс несколько раз | вход не отсортирован | `sort \| uniq -c` |
| Скрипт с `pipefail` изредка падает с кодом 141 на `... \| head -n 1` | `head` закрыл канал, команда слева получила SIGPIPE | отбирать строки через `awk 'NR <= 1'` или `sed -n 1p`, которые читают вход до конца |
| `command not found` на строке `name = value` | пробелы вокруг `=` | `name=value` |
| После `kill -9` на диске остались временные файлы | SIGKILL не даёт выполниться `trap` | сначала `kill` (SIGTERM), `-9` — крайняя мера |
