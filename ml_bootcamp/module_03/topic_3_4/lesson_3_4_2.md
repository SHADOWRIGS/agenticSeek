## Зачем это нужно

Метод соседей из прошлого урока хранит сходство каждой пары и не обобщает: если два товара ни разу
не встретились у одного пользователя, их сходство — ноль, даже когда оба нравятся одним и тем же людям
через цепочку третьих товаров. Матричная факторизация сжимает всю матрицу в короткие векторы
пользователей и товаров. Это даёт обобщение, компактную модель (десятки чисел на объект вместо строки
сходств) и готовые векторные представления товаров — на них строятся поиск похожих, кластеризация
и признаки для других моделей. ALS для неявного отклика — рабочая лошадка рекомендательных систем
и обязательная базовая линия перед нейросетевыми моделями (модуль 5).

## 1. Идея скрытых факторов

Предположим, что вкус пользователя и свойства товара описываются короткими векторами $p_u, q_i \in
\mathbb{R}^f$, а оценка пары — их скалярным произведением:

$$\hat r_{ui} = p_u^\top q_i \qquad\Longleftrightarrow\qquad R \approx P Q^\top$$

Матрица $R$ размера 3 000 × 2 000 приближается произведением матриц 3 000 × $f$ и 2 000 × $f$. Факторы
никто не задаёт — они находятся из данных; иногда их удаётся истолковать («премиальность», «для детей»),
чаще нет. В наших данных настоящих факторов восемь, и в разделе 7 мы проверим, находит ли их модель.

Данные, разбиение и функции оценки — из урока 3.4.1 (модуль `rec_utils.py`). Гиперпараметры в этом
уроке подбираем честно, поэтому заводим проверочный период: модель учится на январе–апреле и проверяется
на покупках мая. Июнь остаётся тестом и используется один раз — в итоговой таблице.


## 2. Усечённое SVD

Сингулярное разложение даёт лучшее приближение матрицы матрицей ранга $f$ по сумме квадратов отклонений:
$R \approx U_f \Sigma_f V_f^\top$. Для разреженных матриц есть `scipy.sparse.linalg.svds`, которая
находит только $f$ старших компонент и не превращает матрицу в плотную.

```python
from scipy.sparse.linalg import svds

U, s, Vt = svds(val.train, k=8, random_state=0)
scores = (U[val.test_users] * s) @ Vt   # восстановленные строки матрицы
val.evaluate(scores)["recall"]          # 0.1589
```

| Число компонент | 8 | 16 | 32 | 64 |
|---|---|---|---|---|
| Recall@10 на проверочном периоде | **0.159** | 0.152 | 0.133 | 0.106 |
| Покрытие | 8 % | 11 % | 16 % | 23 % |

Разложение считается за сотые доли секунды, и восемь компонент уже лучше kNN на тех же данных
(user-kNN — 0.149, item-kNN — 0.140). Чем больше компонент, тем точнее восстанавливается обучающая
матрица вместе с её шумом и тем хуже рекомендации.

**Ограничение.** SVD приближает **всю** матрицу, включая пустые ячейки, и считает их нулями. Для
неявного отклика это терпимо: «нет взаимодействия» действительно ближе к нулю, чем к единице. Для оценок
это ошибка: модель будет учиться предсказывать 0 там, где оценка просто неизвестна, а 99.7 % ячеек
именно такие. Кроме того, у SVD нет ни регуляризации, ни весов. Обе проблемы решает явная запись
функции потерь.

## 3. Факторизация по известным оценкам

Будем минимизировать ошибку только по известным оценкам (множество $K$) и добавим регуляризацию. Сразу
учтём, что часть оценки вообще не связана с парой: есть строгие и щедрые пользователи, хорошие и плохие
товары. Для этого вводятся **смещения** (biases): общее среднее $\mu$, поправка пользователя $b_u$
и товара $b_i$.

$$\hat r_{ui} = \mu + b_u + b_i + p_u^\top q_i$$

$$L = \sum_{(u,i) \in K} (r_{ui} - \hat r_{ui})^2 + \lambda \left( b_u^2 + b_i^2 + \lVert p_u \rVert^2 +
\lVert q_i \rVert^2 \right)$$

Эту модель называют Funk SVD — по имени участника конкурса Netflix Prize; к сингулярному разложению
она отношения уже не имеет. Обучение — стохастический градиентный спуск: берём одну оценку, считаем
ошибку $e_{ui} = r_{ui} - \hat r_{ui}$ и сдвигаем только параметры этой пары:

$$b_u \leftarrow b_u + \eta (e_{ui} - \lambda b_u), \qquad
p_u \leftarrow p_u + \eta (e_{ui} q_i - \lambda p_u), \qquad
q_i \leftarrow q_i + \eta (e_{ui} p_u - \lambda q_i)$$

```python
def funk_svd(u, i, r, n_users, n_items, factors=16, lr=0.01, reg=0.05, n_epochs=30, seed=0):
    rng = np.random.default_rng(seed)
    mu = r.mean()
    bu, bi = np.zeros(n_users), np.zeros(n_items)
    P = rng.normal(0, 0.1, (n_users, factors))
    Q = rng.normal(0, 0.1, (n_items, factors))
    for _ in range(n_epochs):
        for j in rng.permutation(len(r)):
            uj, ij = u[j], i[j]
            err = r[j] - (mu + bu[uj] + bi[ij] + P[uj] @ Q[ij])
            bu[uj] += lr * (err - reg * bu[uj])
            bi[ij] += lr * (err - reg * bi[ij])
            # обновляем одновременно: правая часть считается по старым значениям
            P[uj], Q[ij] = P[uj] + lr * (err * Q[ij] - reg * P[uj]), Q[ij] + lr * (err * P[uj] - reg * Q[ij])
    return mu, bu, bi, P, Q
```

Цикл по оценкам здесь оправдан: в SGD каждое обновление зависит от предыдущего. Данные — оценки покупок:
19 611 в обучении (до июня), 4 903 в тесте (пары, где и пользователь, и товар встречались в обучении).

```python
purchases = shop.events[shop.events["event"] == "purchase"]
train_r, test_r = purchases[purchases["timestamp"] < JUNE], purchases[purchases["timestamp"] >= JUNE]
u = data.user_index.loc[train_r["user_id"]].to_numpy()
i = data.item_index.loc[train_r["item_id"]].to_numpy()
r = train_r["rating"].to_numpy()

```

Второй вывод важнее: **RMSE оценок — не та метрика**, которая нужна магазину. Модель учится только
на купленных товарах, которые пользователь и так выбрал сам, и ничего не знает о том, что он выберет.
Для блока рекомендаций нужна модель неявного отклика — к ней и идём.

## 4. ALS: чередование двух Ridge-регрессий

Функция потерь факторизации не выпукла по $P$ и $Q$ вместе. Но если **зафиксировать** факторы товаров
$Q$, задача распадается на независимые задачи для каждого пользователя:

$$\min_{p_u} \sum_{i \in I_u} (r_{ui} - p_u^\top q_i)^2 + \lambda \lVert p_u \rVert^2$$

Посмотрите на неё как на регрессию: объекты — товары, оценённые пользователем; признаки объекта —
вектор $q_i$; целевая переменная — оценка $r_{ui}$; веса модели — $p_u$. Это в точности Ridge-регрессия
из урока 3.1.1 без свободного члена, и у неё есть аналитическое решение:

$$p_u = (Q_u^\top Q_u + \lambda I)^{-1} Q_u^\top r_u$$

где $Q_u$ — матрица факторов товаров, оценённых пользователем, $r_u$ — вектор его оценок. Точно так же
при фиксированных $P$ находится каждый $q_i$. **Alternating Least Squares** чередует эти два шага:
каждый шаг точно минимизирует функцию потерь по своей половине параметров, поэтому потери не растут.

```python
def explicit_als(R, factors=16, reg=5.0, n_iter=15, seed=0):
    """ALS по известным оценкам: R — разреженная матрица (центрированных) оценок."""
    rng = np.random.default_rng(seed)
    Q = rng.normal(0, 0.1, (R.shape[1], factors))
    Ru, Ri = R.tocsr(), R.T.tocsr()

    def half_step(M, F):
        out = np.zeros((M.shape[0], factors))
        for row in range(M.shape[0]):
            lo, hi = M.indptr[row], M.indptr[row + 1]
            if lo == hi:
                continue
            Fo = F[M.indices[lo:hi]]  # факторы «другой стороны» для заполненных ячеек строки
            out[row] = np.linalg.solve(Fo.T @ Fo + reg * np.eye(factors), Fo.T @ M.data[lo:hi])
        return out

    for _ in range(n_iter):
        P = half_step(Ru, Q)
        Q = half_step(Ri, P)
    return P, Q


residuals = sp.csr_matrix((r - mu - bu[u] - bi[i], (u, i)), shape=data.train.shape)
P, Q = explicit_als(residuals, factors=16, reg=3)
```

Цикл идёт по пользователям и по товарам (5 000 маленьких систем уравнений на итерацию), а не по парам;
как и в уроке 3.1.1, решаем систему через `solve`, а не обращаем матрицу. Здесь ALS применён к остаткам
после вычитания смещений.

Результат (16 факторов): при λ = 3 RMSE на обучении 0.436, на тесте 0.855; при λ = 10 — 0.716 и 0.833.

Вывод тот же, что у SGD: при слабой регуляризации — переобучение, при сильной — факторы сжимаются к нулю
и остаются одни смещения. Зато ALS впятеро быстрее, у него нет шага обучения, и шаги для разных
пользователей независимы — их можно считать параллельно. Поэтому ALS стал стандартом для больших данных.

## 5. ALS для неявного отклика

Для неявного отклика постановку меняют (Hu, Koren, Volinsky, 2008). Вместо оценки у каждой ячейки —
две величины:

- **предпочтение** $p_{ui}$: 1, если взаимодействие было, иначе 0;
- **уверенность** $c_{ui} = 1 + \alpha r_{ui}$, где $r_{ui}$ — «сила» взаимодействия (у нас 1 или 3).

$$L = \sum_{u, i} c_{ui} \left( p_{ui} - x_u^\top y_i \right)^2 + \lambda \Big( \sum_u \lVert x_u \rVert^2 +
\sum_i \lVert y_i \rVert^2 \Big)$$

Почему это другая задача, а не «ALS с другими числами»:

1. Сумма идёт по **всем** ячейкам матрицы, а не только по заполненным. Пустые ячейки — нули, но с малой
   уверенностью 1: «скорее всего не интересно, но мы не уверены».
2. Сила сигнала влияет не на то, что предсказывать (всегда 1), а на то, насколько дорого ошибиться.
   Покупка при $\alpha = 10$ весит 31, просмотр — 11, пустая ячейка — 1.
3. Модель предсказывает не оценку, а склонность к взаимодействию; значения пригодны только для
   ранжирования.

Шаг для пользователя — взвешенная Ridge-регрессия по всем товарам:
$x_u = (Y^\top C^u Y + \lambda I)^{-1} Y^\top C^u p_u$, где $C^u$ — диагональная матрица уверенностей.
«В лоб» это 2 000 товаров на каждого пользователя. Спасает тождество

$$Y^\top C^u Y = Y^\top Y + Y_u^\top (C^u - I)\, Y_u$$

Первое слагаемое одно на всех и считается один раз за шаг; второе содержит только товары из истории
пользователя. В правой части $Y^\top C^u p_u$ ненулевые слагаемые тоже только у товаров из истории.

```python
def als_half_step(C, F, reg, alpha):
    """Для каждой строки матрицы C решает Ridge-задачу при фиксированных факторах F другой стороны."""
    f = F.shape[1]
    gram = F.T @ F + reg * np.eye(f)  # вклад всех ячеек с уверенностью 1 и регуляризация
    out = np.zeros((C.shape[0], f))
    for row in range(C.shape[0]):
        lo, hi = C.indptr[row], C.indptr[row + 1]
        if lo == hi:
            continue
        Fo = F[C.indices[lo:hi]]
        extra = alpha * C.data[lo:hi]  # c − 1 для заполненных ячеек
        A = gram + (Fo * extra[:, None]).T @ Fo
        b = Fo.T @ (1 + extra)
        out[row] = np.linalg.solve(A, b)
    return out


def implicit_als(train, factors=16, reg=30.0, alpha=10.0, n_iter=15, seed=0, callback=None):
    rng = np.random.default_rng(seed)
    Y = rng.normal(0, 0.01, (train.shape[1], factors))
    Cu, Ci = train.tocsr(), train.T.tocsr()
    for it in range(n_iter):
        X = als_half_step(Cu, Y, reg, alpha)
        Y = als_half_step(Ci, X, reg, alpha)
        if callback:
            callback(it, X, Y)
    return X, Y


X, Y = implicit_als(val.train, factors=8, reg=100, alpha=10)
val.evaluate(X[val.test_users] @ Y.T)["recall"]  # 0.1893
```

## 6. Подбор гиперпараметров и сходимость

Recall@10 на проверочном периоде ($\alpha = 10$, 15 итераций):

| Факторов \ λ | 3 | 10 | 30 | 100 | 300 |
|---|---|---|---|---|---|
| 8 | 0.183 | 0.185 | 0.185 | **0.189** | 0.099 |
| 16 | 0.145 | 0.148 | 0.158 | 0.186 | 0.104 |
| 32 | 0.112 | 0.121 | 0.131 | 0.184 | 0.106 |
| 64 | 0.094 | 0.104 | 0.118 | 0.187 | 0.107 |

- Лучшая модель — 8 факторов, ровно столько заложено в генератор. При слабой регуляризации каждый
  лишний фактор вредит: 64 фактора при λ = 3 вдвое хуже восьми.
- Сильная регуляризация (λ = 100) почти уравнивает модели разного размера — она сама «выключает» лишние
  факторы. При λ = 300 модель задавлена и вырождается в «популярное» (покрытие 2 %).
- Число факторов и λ нужно подбирать **вместе**: вывод «32 фактора хуже 8» верен при λ = 10 и неверен
  при λ = 100.
- Точность и покрытие снова тянут в разные стороны: у модели с 64 факторами и λ = 3 покрытие 38 %,
  у лучшей по recall — 12 %.

Уверенность (8 факторов, λ = 100):

| $\alpha$ | 1 | 3 | 10 | 30 | 100 |
|---|---|---|---|---|---|
| Recall@10 | 0.067 | 0.132 | **0.189** | 0.173 | 0.119 |
| Покрытие | 1 % | 4 % | 12 % | 21 % | 34 % |

При малом $\alpha$ шесть миллионов пустых ячеек перевешивают 42 тысячи заполненных, и модель предсказывает
популярность. Заметьте, что $\alpha$ и λ связаны: рост $\alpha$ ослабляет относительный вес
регуляризации. Наконец, если заменить веса «просмотр 1, покупка 3» бинарной матрицей, recall падает
с 0.189 до 0.152 ($\alpha = 10$) и 0.161 ($\alpha = 30$): разная уверенность для просмотра и покупки —
существенная часть качества.

**Сходимость.** Значение функции потерь и recall@10 на проверочном периоде по итерациям:

| Итерация | 1 | 2 | 3 | 5 | 10 | 15 | 20 |
|---|---|---|---|---|---|---|---|
| Потери | 747 026 | 535 853 | 493 187 | 481 687 | 478 936 | 478 667 | 478 624 |
| Recall@10 | 0.052 | 0.091 | 0.136 | 0.177 | 0.185 | 0.189 | 0.190 |

Потери убывают монотонно — так и должно быть, каждый полушаг решает свою задачу точно. Если потери
растут, в реализации ошибка. Десяти–пятнадцати итераций достаточно. Потери считаются по всем ячейкам,
но без плотной матрицы весов: сумма квадратов всех предсказаний плюс поправка
$c_{ui}(1 - \hat p_{ui})^2 - \hat p_{ui}^2$ по заполненным ячейкам.

**Восстановились ли заложенные факторы?** В синтетических данных это можно проверить. Сами оси
совпадать не обязаны: если повернуть пространство факторов, произведение $X Y^\top$ не изменится. Поэтому
проверяем иначе — можно ли линейной регрессией выразить истинные факторы через найденные ($R^2$ на
кросс-валидации, среднее по восьми истинным факторам):

| Что выражаем | Через что | $R^2$ |
|---|---|---|
| Истинные факторы товаров (1 243 товара с 10+ взаимодействиями) | найденные факторы | 0.63 |
| То же | категория товара (one-hot) | 0.34 |
| Истинные факторы товаров с 1–4 взаимодействиями (296 товаров) | найденные факторы | 0.17 |
| Истинные факторы пользователей с 10+ взаимодействиями (1 744) | найденные факторы | 0.64 |

Модель восстановила около двух третей изменчивости скрытых факторов — вдвое больше, чем объясняет
категория. Значит, она нашла и то, чего нет в признаках товара. Для редких товаров восстановление почти
не работает: по четырём взаимодействиям вектор не оценить. На реальных данных такой проверки не бывает —
остаются качество на отложенных данных и просмотр соседей глазами.

## 8. Новый пользователь без переобучения: fold-in

Пользователь, пришедший после обучения, не имеет вектора. Переобучать модель ради него не нужно:
вектор пользователя — решение Ridge-задачи при фиксированных факторах товаров, то есть **один полушаг
ALS** по его истории. Функция уже есть:

```python
history = data.train[new_users]                      # строки истории новых пользователей
X_new = als_half_step(history, Y, reg=100, alpha=10)
scores = X_new @ Y.T
```

**Проверка 1.** Скроем от модели 380 случайных тестовых пользователей (обнулим их строки), обучим ALS
без них и получим их векторы через fold-in.

| Рекомендации для 380 скрытых пользователей | Recall@10 | NDCG@10 |
|---|---|---|
| Популярное | 0.078 | 0.049 |
| Fold-in по модели, обученной без них | 0.209 | 0.157 |
| Модель, обученная вместе с ними | 0.212 | 0.169 |

Fold-in почти не уступает полному обучению и занимает 0.01 секунды на всех 380 пользователей.

**Проверка 2.** Настоящие новички: пользователи, зарегистрировавшиеся в июне. История — их первые $m$
взаимодействий, цель — последующие покупки.

| Первых взаимодействий $m$ | Пользователей | Популярное | Item-kNN | Fold-in |
|---|---|---|---|---|
| 1 | 99 | 0.179 | 0.048 | 0.091 |
| 3 | 37 | 0.113 | 0.054 | 0.182 |
| 5 | 18 | 0.139 | 0.130 | 0.157 |

Выборки маленькие, и числа шумные, но картина осмысленная: после одного просмотра «популярное» вдвое
лучше персональных моделей — один случайный клик ничего не говорит о вкусе. После трёх взаимодействий
fold-in выходит вперёд. Практический вывод — переключение по длине истории (урок 3.4.3). Для **новых
товаров** fold-in не помогает: у товара без взаимодействий история пуста.

## 9. Сравнение на тесте и библиотеки

Гиперпараметры каждой модели выбраны по проверочному периоду (user-kNN: 100 соседей; item-kNN:
100 соседей, профиль с весами; SVD: 8 компонент; ALS: 8 факторов, λ = 100, $\alpha$ = 10). Затем модели
обучены на всём обучающем периоде и один раз оценены на июне.

| Модель | Precision | Recall | Hit rate | MAP | NDCG | Покрытие | Время, с |
|---|---|---|---|---|---|---|---|
| Популярное | 0.018 | 0.070 | 0.171 | 0.027 | 0.047 | 1.2 % | 0.01 |
| Популярное в категории | 0.035 | 0.122 | 0.277 | 0.048 | 0.083 | 9.1 % | 0.02 |
| User-kNN | 0.054 | 0.181 | 0.378 | 0.086 | 0.138 | 14 % | 0.24 |
| Item-kNN | 0.051 | 0.169 | 0.363 | 0.080 | 0.129 | 38 % | 0.24 |
| Усечённое SVD | 0.057 | 0.190 | 0.395 | 0.097 | 0.150 | 9 % | 0.01 |
| ALS для неявного отклика (наш) | 0.062 | **0.209** | 0.427 | 0.109 | 0.166 | 14 % | 1.0 |
| ALS из библиотеки `implicit` | 0.064 | **0.215** | 0.435 | 0.110 | 0.169 | 14 % | 0.3 |

1. ALS лучше user-kNN на 15 % по recall и на 20 % по NDCG, лучше «популярного в категории» в 1.7 раза.
2. Усечённое SVD — неожиданно сильная и почти бесплатная базовая линия: между kNN и ALS.
3. По покрытию лидирует item-kNN: факторные модели с сильной регуляризацией рекомендуют узкий набор
   товаров. Если длинный хвост важен, это аргумент при выборе модели, а не мелочь.

**Библиотеки.** Обе проверены на Python 3.12 и NumPy 2.5.

`implicit` 0.7.3 — быстрые ALS, BPR и kNN для неявного отклика. Модель ждёт матрицу уже посчитанной
уверенности. С теми же параметрами результат близок к нашей реализации (recall 0.215 против 0.209 —
различаются начальное приближение и детали вычислений), обучение втрое быстрее, и разрыв растёт
с размером данных.

```python
from implicit.als import AlternatingLeastSquares

users = data.test_users
confidence = data.train.copy()
confidence.data = 1 + 10 * confidence.data  # c = 1 + alpha · r
model = AlternatingLeastSquares(
    factors=8, regularization=100, alpha=1.0, iterations=15, random_state=0, dtype=np.float64
)
model.fit(confidence, show_progress=False)
scores = model.user_factors[users] @ model.item_factors.T
ids, _ = model.recommend(users[:3], data.train[users[:3]], N=5, filter_already_liked_items=True)
```

Перед запуском задайте переменную окружения `OPENBLAS_NUM_THREADS=1` — иначе библиотека выдаёт
предупреждение о вложенной многопоточности и работает медленнее.

`scikit-surprise` 1.1.5 — модели для явных оценок. Её `SVD(n_factors=16, n_epochs=30, lr_all=0.01,
reg_all=0.05)` — это Funk SVD из раздела 3: данные передаются через `Dataset.load_from_df` и
`build_full_trainset()`, прогноз даёт `algo.predict(user_id, item_id).est`. RMSE на тесте — 0.835 против
0.838 у нашей реализации с теми же параметрами, обучение — 0.1 секунды вместо 4.8: алгоритм тот же,
но цикл написан на Cython.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Модель оценок предсказывает значения около нуля | SVD по матрице, где пропуски заменены нулями | факторизация только по известным оценкам |
| RMSE на обучении падает, на тесте растёт | переобучение факторов | увеличить λ, уменьшить число факторов, ранняя остановка |
| Потери ALS не убывают монотонно | ошибка в формуле полушага или в индексации | проверить на маленькой матрице против прямого решения Ridge |
| ALS для неявного отклика рекомендует всем одно и то же | мала уверенность $\alpha$ или слишком велика λ | подобрать $\alpha$ и λ совместно по валидации |
| Шаг ALS идёт минуты | для каждого пользователя перебираются все товары | тождество $Y^\top C^u Y = Y^\top Y + Y_u^\top (C^u - I) Y_u$ |
| В `implicit` качество хуже ожидаемого | перепутаны строки и столбцы матрицы или передана не уверенность | матрица «пользователь × товар» в CSR; проверить на «популярном» |
