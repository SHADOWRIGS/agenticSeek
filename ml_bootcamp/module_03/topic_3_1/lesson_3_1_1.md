## Зачем это нужно

Линейные модели — не «простой алгоритм для разминки перед бустингом». Это:

- **базовая линия** в любой задаче: если сложная модель не обгоняет линейную, проблема в данных или признаках;
- **рабочая лошадка** там, где нужны скорость, объяснимость и стабильность: кредитный скоринг, ценообразование,
  реклама с миллионами разреженных признаков;
- **последний слой** любой нейросети: всё, что вы узнаете о градиентном спуске, масштабировании
  и регуляризации, один в один переносится на глубокое обучение.

На собеседованиях вопросы «выведите решение линейной регрессии» и «почему Lasso зануляет веса» задают
чаще, чем вопросы про любую другую модель.

## 1. Модель и функция потерь

Данные урока — синтетические цены квартир. Скопируйте [`flats_data.py`](flats_data.py) в проект.

```python
import numpy as np
from flats_data import FEATURES, TARGET, make_flats

flats = make_flats()                    # 200 квартир: area, rooms, age, distance, price
X = flats[FEATURES].to_numpy()
y = flats[TARGET].to_numpy()
```

Цена сгенерирована по известной формуле:
`price = 2.0 + 0.11·area + 0.3·rooms − 0.04·age − 0.15·distance + шум`. Знание истинных коэффициентов
позволит проверять, насколько хорошо модель их восстанавливает.

Линейная модель предсказывает взвешенную сумму признаков:

$$\hat{y} = w_0 + w_1 x_1 + \dots + w_p x_p$$

Если добавить к матрице признаков столбец из единиц, свободный член $w_0$ становится обычным весом,
и вся модель записывается одним матричным умножением:

$$\hat{y} = Xw$$

где $X$ — матрица $n \times (p+1)$, $w$ — вектор из $p+1$ весов. Качество измеряем среднеквадратичной
ошибкой (MSE):

$$L(w) = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2 = \frac{1}{n}\lVert y - Xw \rVert^2$$

Почему квадрат, а не модуль: квадратичная функция гладкая, у неё единственный минимум и он находится
аналитически. С точки зрения статистики минимизация MSE — это метод максимального правдоподобия
в предположении, что шум нормальный. Обратная сторона: квадрат сильно штрафует большие ошибки, поэтому
модель чувствительна к выбросам.

## 2. Аналитическое решение

Градиент функции потерь по весам:

$$\nabla L(w) = -\frac{2}{n} X^\top (y - Xw)$$

В точке минимума градиент равен нулю, откуда получаются **нормальные уравнения**:

$$X^\top X\, w = X^\top y \quad\Rightarrow\quad w = (X^\top X)^{-1} X^\top y$$

```python
Xb = np.column_stack([np.ones(len(X)), X])          # столбец единиц для свободного члена

w_inv = np.linalg.inv(Xb.T @ Xb) @ Xb.T @ y         # формула «в лоб» — так делать не надо
w, *_ = np.linalg.lstsq(Xb, y, rcond=None)          # правильный способ
w.round(3)
# array([ 1.797,  0.108,  0.403, -0.042, -0.147])
```

`LinearRegression` из scikit-learn даёт те же числа. Сравним с истиной (2.0, 0.11, 0.3, −0.04, −0.15):
коэффициенты при площади, возрасте и расстоянии восстановлены хорошо, а при числе комнат — 0.403 вместо 0.3.
К причине вернёмся в разделе 4.

**Геометрический смысл.** Условие $X^\top (y - Xw) = 0$ означает, что вектор ошибок перпендикулярен
каждому столбцу признаков. Предсказание $\hat{y}$ — это проекция $y$ на пространство, натянутое на столбцы $X$:
ближайшая к $y$ точка, которую вообще можно получить линейной комбинацией признаков.

**Почему не `inv`.** Обращение матрицы численно неустойчиво и не работает, когда $X^\top X$ вырождена:
признаков больше, чем объектов, или один признак линейно выражается через другие. `lstsq` решает задачу
через сингулярное разложение и справляется с этими случаями. Мера «плохости» задачи — число
обусловленности: для наших данных `np.linalg.cond(Xb.T @ Xb)` равно 108 000.

Аналитическое решение требует порядка $np^2 + p^3$ операций и хранения всей матрицы в памяти. При сотнях
тысяч признаков или данных, не помещающихся в память, используют градиентные методы.

## 3. Градиентный спуск и масштабирование

Идея: начать с произвольных весов и много раз сдвигать их против градиента.

$$w \leftarrow w - \eta \, \nabla L(w)$$

где $\eta$ — шаг обучения (learning rate).

```python
def gradient_descent(X, y, learning_rate, n_iter):
    w = np.zeros(X.shape[1])
    history = []
    for _ in range(n_iter):
        gradient = 2 / len(y) * X.T @ (X @ w - y)
        w -= learning_rate * gradient
        history.append(((X @ w - y) ** 2).mean())
    return w, np.array(history)
```

Запустим на исходных признаках. Оптимальное значение MSE, найденное аналитически, — 0.6464.

| Шаг обучения | Итераций | MSE |
|---|---|---|
| 2·10⁻⁴ | 200 | 5·10¹⁰⁰ — расходится |
| 10⁻⁴ | 1 000 | 0.8957 |
| 10⁻⁴ | 10 000 | 0.8227 |
| 10⁻⁴ | 100 000 | 0.6622 |
| 10⁻⁴ | 1 000 000 | 0.6464 |

Чтобы подойти к оптимуму на 1 %, понадобилась 134 871 итерация. Чуть больший шаг — и спуск расходится.

Причина — в разном масштабе признаков. Площадь меняется от 30 до 120, число комнат — от 1 до 5, столбец
единиц постоянен. Поверхность функции потерь — сильно вытянутый овраг: вдоль одних направлений она очень
крутая, вдоль других почти плоская. Шаг приходится выбирать по самому крутому направлению (иначе спуск
расходится), и по пологим направлениям движение получается черепашьим. Степень вытянутости — то самое число
обусловленности 108 000.

Стандартизуем признаки: вычтем среднее и поделим на стандартное отклонение.


| стандартизованные | 17.8 | 0.01 | 893 |

**28 итераций вместо 134 871.** Вывод, который действует для всех моделей, обучаемых градиентными методами,
включая нейросети: **признаки нужно приводить к одному масштабу**.

После стандартизации меняется и смысл коэффициентов: вес показывает изменение цены при увеличении признака
на одно стандартное отклонение. Веса становятся сравнимыми между собой:

## 4. Мультиколлинеарность

Число комнат и площадь связаны: корреляция 0.89. Модель не может надёжно разделить их вклад — отсюда
оценка 0.403 вместо 0.3. Чтобы увидеть масштаб проблемы, 500 раз сгенерируем по 50 квартир и посмотрим на
разброс коэффициентов (признаки стандартизованы):

| Модель | | area | rooms | age | distance |
|---|---|---|---|---|---|
| Без регуляризации | среднее | 2.845 | 0.350 | −0.573 | −1.025 |
| | разброс (σ) | 0.308 | 0.260 | 0.127 | 0.131 |

У коррелирующих признаков разброс оценок в два с лишним раза больше, чем у независимых. Доведём ситуацию
до предела: добавим пятый признак — ту же площадь в квадратных футах с небольшой погрешностью (корреляция
с площадью 0.999998).

| Шум в пятом признаке | Вес `area` | Вес `area_ft` | R² |
|---|---|---|---|
| вариант 1 | −57.97 | 60.71 | 0.947 |
| вариант 2 | −8.72 | 11.45 | 0.947 |
| вариант 3 | 62.41 | −59.67 | 0.947 |

Качество предсказаний не пострадало, но коэффициенты потеряли смысл: огромные, противоположных знаков,
и меняются до неузнаваемости от ничтожного изменения данных. Модель подбирает большую положительную
и большую отрицательную величину, которые почти сокращаются.

Чем это плохо:

- коэффициенты нельзя интерпретировать: «цена падает на 58 млн за каждое σ площади» — бессмыслица;
- модель хрупкая: на новых данных, где связь между признаками чуть другая, огромные веса перестают
  сокращаться и предсказания «улетают».

Большие по модулю веса — общий симптом и мультиколлинеарности, и переобучения. Отсюда идея лечения:
запретить модели большие веса.

о качестве. Смотреть нужно только на отложенные данные.

## 6. L2-регуляризация: Ridge

Добавим к функции потерь штраф за большие веса:

$$L_{ridge}(w) = \lVert y - Xw \rVert^2 + \alpha \lVert w \rVert_2^2 = \sum_i (y_i - \hat{y}_i)^2 + \alpha \sum_j w_j^2$$

Параметр $\alpha \ge 0$ задаёт силу регуляризации: при $\alpha = 0$ получаем обычную регрессию, при
$\alpha \to \infty$ все веса стремятся к нулю. Свободный член не штрафуется: он отвечает за средний уровень
целевой переменной, а не за сложность модели.

Решение по-прежнему аналитическое:

$$w = (X^\top X + \alpha I)^{-1} X^\top y$$

Добавка $\alpha I$ делает матрицу обратимой всегда — даже когда признаков больше, чем объектов.

```python
from sklearn.linear_model import Ridge

y_centered = y - y.mean()
for alpha in [0, 1, 10, 100, 1000]:
    w = np.linalg.solve(X_scaled.T @ X_scaled + alpha * np.eye(4), X_scaled.T @ y_centered)
```

| α | area | rooms | age | distance | Норма весов |
|---|---|---|---|---|---|
| 0 | 2.736 | 0.477 | −0.598 | −1.067 | 3.034 |
| 1 | 2.679 | 0.525 | −0.593 | −1.059 | 2.988 |
| 10 | 2.323 | 0.809 | −0.554 | −0.999 | 2.713 |
| 100 | 1.454 | 1.096 | −0.370 | −0.685 | 1.980 |
| 1000 | 0.462 | 0.426 | −0.092 | −0.174 | 0.659 |

Результат совпадает с `Ridge(alpha=alpha).fit(X_scaled, y).coef_`. Два наблюдения:

1. Веса плавно уменьшаются, но **ни один не становится точно нулём**.
2. Вес коррелирующих признаков перераспределяется: `area` уменьшается, `rooms` растёт. Ridge делит вклад
   между похожими признаками поровну.

Вернёмся к трём проблемным случаям:

| Ситуация | Без регуляризации | Ridge |
|---|---|---|
| Разброс весов `area` / `rooms` на 500 выборках | 0.308 / 0.260 | 0.140 / 0.160 (α = 10) |
| Площадь в м² и футах: веса двух копий | от −58 до +62 | 1.36 и 1.35 (α = 1), R² тот же |
| Многочлен степени 15: MSE на тесте, максимальный вес | 0.1100, 1 652 | 0.0715, 7.8 (α = 0.001) |

Платой стало смещение: средняя оценка веса `area` — 1.89 вместо 2.85. Это и есть **компромисс между
смещением и разбросом** (bias–variance tradeoff): регуляризация намеренно вносит систематическую ошибку,
чтобы сильнее уменьшить случайную.

## 7. L1-регуляризация: Lasso

Заменим сумму квадратов весов на сумму модулей:

$$L_{lasso}(w) = \frac{1}{2n}\lVert y - Xw \rVert^2 + \alpha \lVert w \rVert_1 = \frac{1}{2n}\sum_i (y_i - \hat{y}_i)^2 + \alpha \sum_j |w_j|$$

Изменение выглядит косметическим, но поведение принципиально другое: Lasso **обнуляет** часть весов,
то есть отбирает признаки. Эксперимент: 50 признаков, из которых на ответ влияют только первые пять.

```python
from sklearn.linear_model import Lasso

rng = np.random.default_rng(7)
X_wide = rng.normal(size=(200, 50))
true_w = np.zeros(50)
true_w[:5] = [3, -2, 1.5, 1, -0.5]
y_wide = X_wide @ true_w + rng.normal(0, 1.0, 200)
```

Половина данных — обучение, половина — тест:

| Модель | Ненулевых весов | Из них настоящих | R² на тесте |
|---|---|---|---|
| Без регуляризации | 50 | 5 | 0.877 |
| Ridge, лучшая α по кросс-валидации | 50 | 5 | 0.902 |
| Lasso, α = 0.01 | 44 | 5 | 0.910 |
| Lasso, α = 0.1 | 20 | 5 | 0.948 |
| Lasso, α = 0.3 | 5 | 5 | 0.931 |
| Lasso, α = 1.0 | 4 | 4 | 0.692 |
| Lasso, α = 3.5 | 0 | 0 | −0.001 |

При α = 0.3 Lasso оставил ровно пять настоящих признаков. При слишком большой α начинают пропадать нужные
признаки, и качество падает. Ridge на этих данных проигрывает: он не умеет исключать 45 шумовых признаков
и только приглушает их.

### Почему L1 обнуляет веса

Рассмотрим один вес в простейшем случае, когда признаки не коррелируют и стандартизованы. Пусть $w^{ols}$ —
значение веса без регуляризации. Тогда решения записываются явно:

$$w^{ridge} = \frac{w^{ols}}{1 + \alpha} \qquad\qquad w^{lasso} = \operatorname{sign}(w^{ols}) \cdot \max(|w^{ols}| - \alpha,\ 0)$$

- Ridge **делит** вес на константу. Маленький вес становится ещё меньше, но нулём не станет никогда.
- Lasso **вычитает** из модуля веса константу. Всё, что по модулю меньше α, превращается в ноль. Эта
  операция называется мягким порогом (soft thresholding).

Проверка на данных с ортогональными признаками, α = 0.2:

| | $w_1$ | $w_2$ | $w_3$ | $w_4$ | $w_5$ |
|---|---|---|---|---|---|
| Без регуляризации | 2.000 | −1.007 | 0.298 | 0.042 | 0.000 |
| Ridge: деление на 1.2 | 1.667 | −0.839 | 0.248 | 0.035 | 0.000 |
| Lasso: вычитание 0.2 | 1.800 | −0.807 | 0.098 | 0 | 0 |

Числа из `Ridge` и `Lasso` scikit-learn совпадают с формулами до третьего знака.

Интуиция через градиент штрафа: у $w^2$ производная равна $2w$ — чем ближе вес к нулю, тем слабее его туда
тянет. У $|w|$ производная постоянна (±1): вес тянет к нулю с одинаковой силой до самого конца. Геометрическое
объяснение, которое любят на собеседованиях: область допустимых весов для L2 — круг, для L1 — ромб
с вершинами на осях координат, и линии уровня функции потерь чаще всего касаются ромба именно в вершине,
где одна из координат равна нулю.

У Lasso нет аналитического решения в общем случае (модуль не дифференцируем в нуле); его находят
покоординатным спуском: по очереди для каждого веса применяют мягкий порог при фиксированных остальных.

### ElasticNet

Lasso из группы сильно коррелирующих признаков оставляет один, причём какой именно — зависит от случайных
особенностей выборки. ElasticNet сочетает оба штрафа и ведёт себя устойчивее:

```python
from sklearn.linear_model import ElasticNet

ElasticNet(alpha=0.1, l1_ratio=0.5)      # l1_ratio=1 — чистый Lasso, l1_ratio=0 — чистый Ridge
```

| | Ridge (L2) | Lasso (L1) | ElasticNet |
|---|---|---|---|
| Обнуляет веса | нет | да | да |
| Коррелирующие признаки | делит вес между ними | оставляет один | оставляет группу |
| Решение | аналитическое | покоординатный спуск | покоординатный спуск |
| Когда выбирать | много признаков, каждый немного полезен | полезных признаков мало, нужен отбор | много коррелирующих признаков и нужен отбор |

## 8. Правила применения

**1. Масштабирование обязательно.** Штраф накладывается на величину веса, а она зависит от единиц
измерения. Lasso на исходных признаках квартир, расстояние в километрах и в метрах:

| Единицы расстояния | Вес | Эффект в пересчёте на 1 км |
|---|---|---|
| километры | −0.1403 | −0.1403 |
| метры | −0.00015 | −0.1498 |

Одна и та же модель с одним и тем же α по-разному штрафует один и тот же признак. В метрах вес в тысячу раз
меньше — и штраф его практически не замечает. Без масштабирования сила регуляризации для каждого признака
определяется случайным выбором единиц.

**2. Масштабирование — внутри пайплайна.** Среднее и стандартное отклонение должны вычисляться только по
обучающей части. Иначе информация из теста попадает в обучение.

```python
from sklearn.pipeline import make_pipeline

model = make_pipeline(StandardScaler(), Ridge(alpha=10.0))
model.fit(X_train, y_train)
```

**3. α подбирается кросс-валидацией** по логарифмической сетке — у scikit-learn для этого есть готовые классы:

```python
from sklearn.linear_model import LassoCV, RidgeCV

ridge = RidgeCV(alphas=np.logspace(-3, 3, 25)).fit(X_train, y_train)     # ridge.alpha_ — лучшее значение
lasso = LassoCV(cv=5, random_state=0).fit(X_train, y_train)              # lasso.alpha_
```

На данных раздела 7 `LassoCV` выбрал α = 0.115 и оставил 19 признаков (R² = 0.948), а не 5. Это типично:
значение α, лучшее для точности прогноза, обычно пропускает несколько лишних признаков. Если цель — отбор
признаков, берут α побольше.

**4. В разных классах α означает разное.** В scikit-learn функции потерь записаны так:

| Класс | Функция потерь |
|---|---|
| `Ridge` | $\lVert y - Xw \rVert^2 + \alpha \lVert w \rVert_2^2$ |
| `Lasso` | $\frac{1}{2n}\lVert y - Xw \rVert^2 + \alpha \lVert w \rVert_1$ |
| `ElasticNet` | $\frac{1}{2n}\lVert y - Xw \rVert^2 + \alpha \rho \lVert w \rVert_1 + \frac{\alpha(1-\rho)}{2} \lVert w \rVert_2^2$, где ρ — `l1_ratio` |
| `LogisticRegression` | параметр `C` — **обратная** сила регуляризации |

В `Ridge` ошибка не делится на число объектов, поэтому подходящее α растёт вместе с размером выборки;
в `Lasso` — делится. Значения α между этими классами сравнивать нельзя.

**5. Категориальные признаки** после one-hot кодирования тоже попадают под штраф; линейной модели
с регуляризацией не нужно удалять один из столбцов кодирования.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Градиентный спуск расходится: потери растут до `inf` или `nan` | слишком большой шаг или признаки разного масштаба | стандартизовать признаки, уменьшить шаг |
| Спуск сходится очень медленно | признаки разного масштаба | `StandardScaler` |
| Огромные веса противоположных знаков | мультиколлинеарность | регуляризация; убрать дублирующие признаки |
| `LinAlgError: Singular matrix` | вырожденная $X^\top X$: признаков больше, чем объектов, или точная линейная зависимость | `lstsq` вместо `inv`; регуляризация |
| Отличное качество на обучении, плохое на тесте | переобучение | регуляризация, меньше признаков, больше данных |
| Регуляризация «не работает» на части признаков | признаки не масштабированы | `StandardScaler` в пайплайне |
| Lasso обнулил все веса | α слишком велика | сетка α по логарифмической шкале, `LassoCV` |
| `ConvergenceWarning` у Lasso | не хватило итераций покоординатного спуска | масштабировать признаки, увеличить `max_iter` |
| Качество на кросс-валидации выше, чем на новых данных | `StandardScaler` обучен на всех данных до разбиения | масштабирование внутри `Pipeline` |
| Перенесли α из `Ridge` в `Lasso` и получили другую модель | разные определения функции потерь | подбирать α для каждого класса отдельно |
| Веса Lasso «прыгают» между коррелирующими признаками от запуска к запуску | Lasso оставляет один признак из группы | `ElasticNet` |
