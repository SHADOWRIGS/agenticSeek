## Зачем это нужно

Модель оттока показала: у клиентов с подключённой услугой «автоплатёж» отток ниже. Менеджер спрашивает:
«Если мы подключим автоплатёж всем, отток упадёт?» От вашего ответа зависит, потратит ли компания бюджет
на кампанию. Чтобы ответить честно, нужно различать три разных утверждения:

1. **в данных есть связь** — коэффициент отличается от нуля не случайно;
2. **связь большая** — эффект имеет практическое значение;
3. **связь причинная** — изменив признак, мы изменим результат.

Линейная модель с её статистическим аппаратом отвечает на первый вопрос и помогает со вторым. На третий
она не отвечает никогда — и значительная часть урока посвящена тому, как не выдать первое за третье.

## 1. Что означает коэффициент

Данные — квартиры из прошлого урока (скопируйте [`flats_data.py`](flats_data.py)). Установите библиотеку
статистических моделей:

```bash
uv add statsmodels
```

```python
import numpy as np
import pandas as pd
import statsmodels.formula.api as smf
from flats_data import make_flats

flats = make_flats()
model = smf.ols("price ~ area + rooms + age + distance", data=flats).fit()
print(model.summary())
```

```
==============================================================================
                 coef    std err          t      P>|t|      [0.025      0.975]
------------------------------------------------------------------------------
Intercept      1.7969      0.227      7.901      0.000       1.348       2.245
area           0.1079      0.005     21.361      0.000       0.098       0.118
rooms          0.4027      0.108      3.722      0.000       0.189       0.616
age           -0.0416      0.004    -10.336      0.000      -0.050      -0.034
distance      -0.1468      0.008    -18.416      0.000      -0.162      -0.131
==============================================================================
```

Точная формулировка для коэффициента `area`: **среди квартир с одинаковым числом комнат, возрастом дома
и расстоянием до центра квартира на 1 м² больше стоит в среднем на 0.108 млн рублей дороже.**

Три части этой фразы обязательны:

- «с одинаковым числом комнат, возрастом и расстоянием» — коэффициент показывает связь **при фиксированных
  остальных признаках модели**. Добавьте или уберите признак — коэффициент изменится;
- «в среднем» — это свойство совокупности, а не обещание для конкретной квартиры;
- «стоит дороже», а не «подорожает» — модель описывает различия между квартирами, а не то, что случится,
  если к квартире пристроить метр.

**Сравнение важности признаков.** Коэффициенты в исходных единицах сравнивать нельзя: 0.108 за метр
и −0.147 за километр — величины разной размерности. Для сравнения признаки стандартизуют (урок 3.1.1):
тогда коэффициент показывает эффект изменения признака на одно стандартное отклонение.

**Категориальные признаки** кодируются набором столбцов-индикаторов, один уровень выбирается базовым.
Коэффициент уровня — разница с базовым, а не «эффект уровня сам по себе»:

```python
# flats_d — те же квартиры с добавленным столбцом district (Центр, Север, Юг) и надбавкой к цене за район
smf.ols("price ~ area + rooms + age + distance + C(district, Treatment(reference='Север'))", data=flats_d)
# [T.Центр]  1.281    — в центре в среднем на 1.28 млн дороже, чем на севере, при прочих равных
# [T.Юг]    -0.678    — на юге на 0.68 млн дешевле, чем на севере
```

Смена базового уровня меняет все коэффициенты и их p-value, не меняя предсказаний модели.

**Логарифмы.** Если и целевая переменная, и признак прологарифмированы, коэффициент — эластичность:
на сколько процентов меняется цена при изменении признака на 1 %. В модели
`np.log(price) ~ np.log(area) + ...` коэффициент при `np.log(area)` равен 1.046: площадь больше на 1 % —
цена выше примерно на 1.05 %. Признак `age` в той же модели не прологарифмирован, и его коэффициент
`−0.0067` читается иначе: каждый год возраста — минус 0.67 % цены.

## 2. Откуда берётся неопределённость

Коэффициенты посчитаны по выборке из 200 квартир. Другая выборка из того же города дала бы другие числа.
Насколько другие — показывает **стандартная ошибка**: стандартное отклонение оценки коэффициента при
многократном повторении сбора данных.

При предположениях классической линейной модели (раздел 6) ковариационная матрица оценок равна

$$\operatorname{Var}(\hat{w}) = \sigma^2 (X^\top X)^{-1}$$

где $\sigma^2$ — дисперсия шума. Она неизвестна и оценивается по остаткам:

$$\hat{\sigma}^2 = \frac{1}{n - k}\sum_i (y_i - \hat{y}_i)^2$$

где $k$ — число оцениваемых параметров (с учётом свободного члена). Проверим вручную:

```python
from scipy import stats

X = np.column_stack([np.ones(len(flats)), flats[["area", "rooms", "age", "distance"]].to_numpy()])
y = flats["price"].to_numpy()
n, k = X.shape

w = np.linalg.lstsq(X, y, rcond=None)[0]
residuals = y - X @ w
sigma2 = residuals @ residuals / (n - k)  # оценка дисперсии шума: 0.8142 в квадрате
covariance = sigma2 * np.linalg.inv(X.T @ X)
standard_errors = np.sqrt(np.diag(covariance))  # [0.2274, 0.0051, 0.1082, 0.0040, 0.0080]
```

Числа совпадают со столбцом `std err`. Оценка шума 0.814 близка к заложенному в генератор значению 0.8.

От чего зависит стандартная ошибка коэффициента:

| Фактор | Влияние |
|---|---|
| Шум в данных ($\sigma$) | чем больше шум, тем больше ошибка |
| Размер выборки | ошибка убывает как $1/\sqrt{n}$: чтобы уменьшить её вдвое, нужно вчетверо больше данных |
| Разброс самого признака | чем шире диапазон значений признака, тем точнее оценка |
| Корреляция с другими признаками | чем сильнее признак выражается через остальные, тем больше ошибка |

Последний пункт — причина, по которой у `rooms` относительная ошибка намного больше, чем у остальных:
число комнат на 80 % объясняется площадью.

## 3. t-статистика, p-value и доверительный интервал

**t-статистика** — оценка коэффициента в единицах его стандартной ошибки:

$$t = \frac{\hat{w}_j}{\operatorname{SE}(\hat{w}_j)}$$

Для `rooms`: 0.4027 / 0.1082 = 3.72 — оценка отстоит от нуля на 3.7 стандартной ошибки.

**p-value** отвечает на вопрос: если бы настоящий коэффициент был равен нулю, как часто из-за одной лишь
случайности получалась бы t-статистика такой же или большей по модулю?

```python
t_stat = w / standard_errors
p_values = 2 * stats.t.sf(np.abs(t_stat), df=n - k)  # для rooms: 0.0003
```

**Доверительный интервал** — диапазон правдоподобных значений коэффициента:

```python
t_critical = stats.t.ppf(0.975, df=n - k)  # 1.972
lower, upper = w - t_critical * standard_errors, w + t_critical * standard_errors
# rooms: [0.189, 0.616]
```

Интервал информативнее p-value: он показывает и то, что эффект отличен от нуля (ноль не входит в интервал),
и то, насколько он может быть велик. Для `rooms` — от 0.19 до 0.62 млн за комнату: разброс втрое.
Истинное значение 0.3 лежит внутри.

### Что такое «95 %»

Проверим определение экспериментом: 2 000 раз сгенерируем выборку, каждый раз построим интервалы
и посчитаем, как часто они накрывают истинные коэффициенты.

| Коэффициент | Доля интервалов, накрывших истинное значение |
|---|---|
| Intercept | 0.948 |
| area | 0.947 |
| rooms | 0.958 |
| age | 0.950 |
| distance | 0.950 |

95 % — это свойство **процедуры**: если строить интервалы таким способом много раз, 95 % из них накроют
истину. Про конкретный интервал [0.189, 0.616] нельзя сказать «с вероятностью 95 % истина внутри» —
но в качестве рабочей интерпретации «правдоподобный диапазон» это допустимо.

### Чего p-value не означает

| Неверно | Верно |
|---|---|
| «p = 0.03 — вероятность, что эффекта нет, равна 3 %» | p-value считается в предположении, что эффекта нет; вероятность самого предположения он не оценивает |
| «p = 0.4 — эффекта нет» | данных недостаточно, чтобы отличить эффект от нуля |
| «p = 0.0001 — эффект большой» | p-value смешивает размер эффекта и объём данных |
| «признак значим — значит, он причина» | значимость говорит о связи в данных, а не о причинности |

## 4. Три ловушки

### Ловушка 1. Мало данных: настоящий эффект «незначим»

Эффект числа комнат в генераторе настоящий. Как часто модель его обнаруживает при уровне 0.05?

| Размер выборки | Доля выборок, где `rooms` значим |
|---|---|
| 30 | 18 % |
| 50 | 30 % |
| 100 | 55 % |
| 200 | 83 % |
| 1 000 | 100 % |

На 50 квартирах в 70 % случаев вы получите «число комнат не влияет на цену». Эта доля называется
**мощностью**. Вывод: «незначимо» — это утверждение о данных, а не об устройстве мира.

### Ловушка 2. Много данных: значимо всё

Добавим признак «этаж» с настоящим, но ничтожным эффектом: 2 000 рублей за этаж при средней цене квартиры
около 8 млн.

| Размер выборки | Оценка | p-value | Доверительный интервал |
|---|---|---|---|
| 200 | −0.0049 | 0.50 | [−0.0191, 0.0093] |
| 2 000 | 0.0020 | 0.43 | [−0.0031, 0.0071] |
| 20 000 | 0.0018 | 0.033 | [0.0001, 0.0034] |
| 200 000 | 0.0019 | 8·10⁻¹⁴ | [0.0014, 0.0024] |

На 200 тысячах наблюдений p-value — тринадцать нулей после запятой, а эффект по-прежнему 2 000 рублей.
**Статистическая значимость и практическая — разные вещи.** На больших данных смотрят на размер эффекта
и его доверительный интервал, а не на p-value.

### Ловушка 3. Много проверок: значимое находится само

Добавим к модели 50 признаков из чистого шума и посмотрим, сколько окажется «значимыми» при уровне 0.05.
Повторим 200 раз:

- в среднем значимыми оказываются **2.6 шумовых признака из 50** — как и следует из определения: 5 % от 50;
- хотя бы один «значимый» шумовой признак находится в **92 % запусков**.

Если перебрать сотню гипотез и сообщить только о значимых, ложные находки гарантированы. Способы защиты:

- поправка Бонферрони: порог делят на число проверок (0.05 / 50 = 0.001). В нашем первом запуске после
  поправки не остаётся ни одного ложного срабатывания;
- отложенная выборка: гипотезу, найденную на одних данных, проверяют на других;
- заранее записанный список гипотез вместо перебора.

То же относится к отбору признаков: если признаки выбраны по p-value или с помощью Lasso, а затем
p-value посчитаны на тех же данных, они занижены и ничего не доказывают.

## 5. Мультиколлинеарность и пропущенные переменные

**Фактор инфляции дисперсии (VIF)** показывает, во сколько раз дисперсия оценки коэффициента выросла из-за
связи признака с остальными: $\mathrm{VIF}_j = 1 / (1 - R_j^2)$, где $R_j^2$ — качество предсказания
признака $j$ по остальным признакам.

```python
from statsmodels.stats.outliers_influence import variance_inflation_factor
```

| Признак | VIF |
|---|---|
| area | 4.95 |
| rooms | 4.96 |
| age | 1.01 |
| distance | 1.01 |

Дисперсия оценок для площади и комнат в пять раз выше, чем была бы для независимых признаков. Ориентиры:
VIF выше 5 — повод присмотреться, выше 10 — серьёзная проблема.

Напрашивается решение — убрать один из пары. Посмотрим, что произойдёт:

| Модель | Коэффициент `rooms` | Коэффициент `area` | R² |
|---|---|---|---|
| Все признаки | 0.403 ± 0.108 | 0.108 ± 0.005 | 0.947 |
| Без `area` | **2.467** ± 0.089 | — | 0.822 |
| Без `rooms` | — | 0.125 ± 0.002 | 0.943 |

Без площади коэффициент при комнатах вырос в шесть раз и стал «очень точным». Он неверен: истинный эффект
комнаты — 0.3. Модель приписала комнатам влияние площади, потому что площадь из модели исчезла, а связана
с комнатами. Это **смещение из-за пропущенной переменной** — главная причина, по которой коэффициенты
нельзя читать как причинные эффекты:

> Коэффициент признака вбирает в себя влияние всех не включённых в модель факторов, которые связаны
> и с этим признаком, и с целевой переменной.

В реальных данных вы никогда не знаете, все ли такие факторы включены. Клиенты с автоплатежом могут уходить
реже не из-за автоплатежа, а потому, что его подключают более лояльные клиенты. Проверить причинность
можно только экспериментом (A/B-тест) или специальными методами причинного вывода.

## 6. Предпосылки и что делать при их нарушении

Формулы раздела 2 верны при следующих условиях:

| Предпосылка | Что ломается при нарушении | Как проверить |
|---|---|---|
| Зависимость линейна | оценки смещены | график остатков против предсказаний: не должно быть изгиба |
| Наблюдения независимы | стандартные ошибки занижены | знание того, как собраны данные: повторы по клиенту, временные ряды |
| Дисперсия шума постоянна | стандартные ошибки неверны | график остатков против признаков: разброс не должен меняться |
| Шум нормален | интервалы неточны на малых выборках | Q-Q график остатков; на больших выборках не критично |

Коэффициенты при нарушении последних трёх предпосылок остаются несмещёнными — страдают только стандартные
ошибки, а с ними p-value и интервалы.

**Непостоянная дисперсия (гетероскедастичность).** Пусть цена нетиповых квартир — очень маленьких и очень
больших — предсказуема хуже, чем типовых: разброс шума 0.63 для площади 60–90 м² и 2.67 для крайних.
На 2 000 выборках:

| Стандартные ошибки | Средняя оценка SE для `area` | Фактический разброс оценки | Покрытие 95 % интервала |
|---|---|---|---|
| классические | 0.0099 | 0.0107 | 93.1 % |
| устойчивые (HC3) | 0.0107 | 0.0107 | 94.7 % |

Классическая формула занижает ошибку на 8 %, и интервалы накрывают истину реже заявленного. Устойчивые
ошибки включаются одним параметром:

```python
robust = smf.ols("price ~ area + rooms + age + distance", data=flats).fit(cov_type="HC3")
```

Два наблюдения из этого эксперимента, которые расходятся с упрощёнными объяснениями:

- если разброс шума просто растёт с площадью (в десять с лишним раз от малых квартир к большим),
  классические ошибки для `area` в наших данных остаются практически верными: покрытие 94.7 %. Искажение
  возникает, когда дисперсия шума связана с **квадратом отклонения признака от среднего**;
- стандартный тест Бройша — Пагана на данных с «нетиповыми» квартирами даёт p = 0.60 и проблему не видит:
  он ищет линейную связь дисперсии с признаками.

Практический вывод: устойчивые ошибки почти ничего не стоят, когда предпосылка выполнена, и защищают,
когда нарушена. Использовать `cov_type="HC3"` по умолчанию — разумная привычка.

**Зависимые наблюдения.** Несколько строк на одного клиента, измерения во времени — в этих случаях
эффективный объём данных меньше числа строк, а ошибки занижены сильнее всего. Для групп используют
кластерные ошибки: `fit(cov_type="cluster", cov_kwds={"groups": data["client_id"]})`.

## 7. Бутстреп: интервалы для любой модели

Формулы стандартных ошибок есть только для простых моделей. Для Ridge, Lasso и чего угодно ещё работает
универсальный приём: многократно пересобрать выборку с возвращением, каждый раз обучить модель и посмотреть
на разброс результата.

```python
rng = np.random.default_rng(0)
features = flats[["area", "rooms", "age", "distance"]].to_numpy()
coefficients = []
for _ in range(2000):
    idx = rng.integers(0, len(flats), len(flats))  # выборка с возвращением
    Xb = np.column_stack([np.ones(len(idx)), features[idx]])
    coefficients.append(np.linalg.lstsq(Xb, y[idx], rcond=None)[0][1:])

np.percentile(coefficients, [2.5, 97.5], axis=0)
```

| Коэффициент | Интервал по формуле | Интервал бутстрепом |
|---|---|---|
| area | [0.098, 0.118] | [0.099, 0.117] |
| rooms | [0.189, 0.616] | [0.211, 0.598] |
| age | [−0.050, −0.034] | [−0.049, −0.035] |
| distance | [−0.163, −0.131] | [−0.162, −0.132] |

Интервалы близки, и бутстреп не потребовал ни одной формулы. Тот же цикл с `Ridge` внутри даёт интервалы
для регуляризованной модели, для которой готовых формул нет.

Оговорка: регуляризация намеренно смещает коэффициенты (урок 3.1.1), поэтому интервал бутстрепа для Ridge
описывает устойчивость оценки, но может не накрывать «истинный» коэффициент.

## 8. Интервал для предсказания

Неопределённость есть и у предсказаний, причём двух видов:

```python
new_flat = pd.DataFrame({"area": [60.0], "rooms": [2.0], "age": [10.0], "distance": [5.0]})
model.get_prediction(new_flat).summary_frame(alpha=0.05)
```

```
    mean  mean_se  mean_ci_lower  mean_ci_upper  obs_ci_lower  obs_ci_upper
0  7.928    0.121          7.689          8.168         6.305         9.552
```

| Интервал | Значение | Отвечает на вопрос |
|---|---|---|
| доверительный (`mean_ci`) | [7.69, 8.17] | какова **средняя** цена таких квартир |
| предсказательный (`obs_ci`) | [6.31, 9.55] | сколько может стоить **конкретная** квартира |

Второй интервал почти в семь раз шире: он включает разброс отдельных квартир вокруг среднего. С ростом выборки
доверительный интервал сужается к нулю, предсказательный — нет: шум в данных никуда не девается. Заказчику,
который спрашивает «за сколько продастся эта квартира», нужен второй.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Коэффициент меняет знак при добавлении признака | мультиколлинеарность или пропущенная переменная | проверить VIF; не интерпретировать коэффициенты сильно связанных признаков по отдельности |
| «Признак незначим, удаляем» — и качество падает | малая мощность; признак работает в сочетании с другими | решать по качеству на отложенных данных, а не по p-value |
| На большой выборке значимы все признаки | p-value отражает объём данных | смотреть на размер эффекта и интервал |
| Из 100 проверенных гипотез подтвердилось 5 | множественные проверки | поправка на число проверок, отложенная выборка |
| p-value посчитаны после отбора признаков на тех же данных | отбор уже использовал эти данные | разделить данные: отбор на одной части, выводы на другой |
| Интервалы подозрительно узкие | зависимые наблюдения: повторы по клиенту, время | кластерные стандартные ошибки |
| Коэффициент истолкован как эффект вмешательства | корреляция принята за причинность | формулировать как связь; для причинных выводов — эксперимент |
| Сравнивают величину коэффициентов признаков в разных единицах | коэффициенты не стандартизованы | сравнивать стандартизованные коэффициенты |
| Заказчику дали доверительный интервал вместо предсказательного | перепутаны два вида интервалов | для отдельного объекта — `obs_ci` |
| Изменился базовый уровень категории — «изменились выводы» | коэффициенты уровней — разницы с базовым | явно задавать базовый уровень и называть его в выводах |
