## Зачем это нужно

Две задачи, которые встречаются в каждой компании:

- **«Случится или нет»**: уйдёт ли клиент, кликнет ли по баннеру, вернёт ли кредит. Ответ — вероятность
  от 0 до 1;
- **«Сколько раз»**: сколько обращений в поддержку, сколько покупок, сколько страховых случаев. Ответ —
  неотрицательное число.

Линейная регрессия предсказывает любое число от минус до плюс бесконечности и для обеих задач даёт
бессмысленные ответы: вероятность 1.2 или минус 0.9 обращения. Обобщённые линейные модели (GLM) решают
эту проблему, сохраняя главное достоинство линейных моделей — понятные коэффициенты. Логистическая
регрессия — самая используемая модель классификации в индустрии и стандартная базовая линия; пуассоновская
и родственные ей — основа страхового ценообразования и прогнозирования спроса.

## 1. Данные и провал линейной регрессии

Данные урока — клиенты интернет-провайдера. Скопируйте [`churn_data.py`](churn_data.py).

```python
import numpy as np
import pandas as pd
import statsmodels.api as sm
import statsmodels.formula.api as smf
from churn_data import make_clients

clients = make_clients()  # 5 000 клиентов
clients["fee_k"] = clients["monthly_fee"] / 1000  # абонентская плата в тысячах рублей
clients["annual"] = (clients["contract"] == "annual").astype(int)
clients["autopay_i"] = clients["autopay"].astype(int)
```

| Столбец | Смысл |
|---|---|
| `tenure_months` | сколько месяцев клиент с компанией |
| `monthly_fee` | абонентская плата, руб. |
| `services` | число подключённых услуг |
| `contract` | тип контракта: `monthly` или `annual` |
| `autopay` | подключён ли автоплатёж |
| `support_calls` | число обращений в поддержку за последний год |
| `exposure_years` | какая часть последнего года наблюдалась (у новых клиентов меньше 1) |
| `churn` | ушёл ли клиент: 1 или 0 |

Ушли 35.5 % клиентов. Обучим обычную линейную регрессию на признак `churn`:

```python
formula = "churn ~ tenure_months + fee_k + annual + autopay_i + support_calls"
linear = smf.ols(formula, data=clients).fit()
predictions = linear.predict(clients)
predictions.min(), predictions.max()  # (-0.283, 1.197)
```

Для 4.4 % клиентов «вероятность» отрицательна, для части — больше единицы. Та же картина со счётчиком
обращений: линейная модель предсказывает отрицательное число обращений для 3 % клиентов, а разброс её
ошибок растёт вместе с предсказанием — дисперсия остатков 1.05 в нижней трети предсказаний и 3.22
в верхней. Предпосылка постоянной дисперсии (урок 3.1.2) нарушена по самой природе данных: у счётчиков
разброс растёт вместе со средним.

## 2. Три составляющие GLM

Обобщённая линейная модель задаётся тремя решениями:

1. **Распределение** целевой переменной: какие значения она принимает и как связаны среднее и разброс.
2. **Линейный предиктор**: $\eta = w_0 + w_1 x_1 + \dots + w_p x_p$ — то же, что в линейной регрессии.
3. **Функция связи** $g$: как линейный предиктор превращается в среднее значение, $g(\mu) = \eta$.

| Модель | Целевая переменная | Распределение | Функция связи | Среднее |
|---|---|---|---|---|
| Линейная регрессия | любое число | нормальное | тождественная: $\mu = \eta$ | $\eta$ |
| Логистическая регрессия | 0 или 1 | Бернулли | логит: $\ln\frac{\mu}{1-\mu} = \eta$ | $\frac{1}{1+e^{-\eta}}$ |
| Пуассоновская регрессия | 0, 1, 2, … | Пуассона | логарифм: $\ln\mu = \eta$ | $e^{\eta}$ |
| Гамма-регрессия | положительное число | гамма | логарифм | $e^{\eta}$ |

Функция связи гарантирует, что предсказание попадает в допустимую область: сигмоида даёт число от 0 до 1,
экспонента — положительное число. Веса находят методом максимального правдоподобия: подбирают так, чтобы
наблюдаемые данные были наиболее вероятны.

## 3. Логистическая регрессия

### Модель

Вероятность ухода — сигмоида от линейной комбинации признаков:

$$p = \sigma(\eta) = \frac{1}{1 + e^{-\eta}}, \qquad \eta = w^\top x$$

Обратное преобразование показывает, что именно модель считает линейным:

$$\ln\frac{p}{1 - p} = w^\top x$$

Отношение $p / (1-p)$ называется **шансами** (odds): при вероятности 0.8 шансы равны 4 — «четыре к одному».
Логистическая регрессия линейна в **логарифме шансов**.

### Функция потерь

Правдоподобие одного наблюдения: $p$, если $y = 1$, и $1 - p$, если $y = 0$. Логарифм правдоподобия всей
выборки с обратным знаком, делённый на число объектов, — это **логистическая функция потерь** (log loss,
она же бинарная кросс-энтропия):

$$L(w) = -\frac{1}{n}\sum_{i=1}^{n}\bigl[y_i \ln p_i + (1 - y_i)\ln(1 - p_i)\bigr]$$

Она сильно штрафует уверенные ошибки: предсказать 0.01 для объекта класса 1 стоит $-\ln 0.01 = 4.6$,
предсказать 0.5 — всего 0.69.

Градиент выглядит так же, как у линейной регрессии, — ошибка предсказания, умноженная на признаки:

$$\nabla L(w) = \frac{1}{n} X^\top (p - y)$$

Аналитического решения нет, но функция выпуклая, и метод Ньютона сходится за несколько шагов. На наших
данных, начиная с нулевых весов:

| Итерация | Log loss | Вес `tenure_months` | Вес `fee_k` |
|---|---|---|---|
| 1 | 0.69315 | −0.0204 | 0.2706 |
| 2 | 0.54459 | −0.0288 | 0.3630 |
| 3 | 0.53661 | −0.0304 | 0.3790 |
| 4 | 0.53643 | −0.0305 | 0.3795 |
| 5 | 0.53643 | −0.0305 | 0.3795 |

Начальное значение 0.693 — это $\ln 2$: потери модели, которая всем предсказывает вероятность 0.5.

## 4. Интерпретация коэффициентов

### Отношения шансов

Коэффициент — изменение логарифма шансов при увеличении признака на единицу. Экспонента коэффициента —
**отношение шансов** (odds ratio): во сколько раз меняются шансы.

```python
np.exp(logit.params)  # отношения шансов
np.exp(logit.conf_int())  # их доверительные интервалы
```

| Признак | Коэффициент | Отношение шансов | 95 % интервал | Как читать |
|---|---|---|---|---|
| `tenure_months` | −0.031 | 0.970 | [0.966, 0.974] | каждый месяц стажа снижает шансы ухода на 3 % |
| `fee_k` | 0.380 | 1.461 | [1.245, 1.716] | каждая тысяча рублей платы повышает шансы в 1.46 раза |
| `annual` | −1.449 | 0.235 | [0.203, 0.272] | у клиентов с годовым контрактом шансы ухода в 4.3 раза ниже |
| `autopay_i` | −0.686 | 0.503 | [0.440, 0.576] | с автоплатежом шансы ухода вдвое ниже |
| `support_calls` | 0.397 | 1.487 | [1.422, 1.554] | каждое обращение повышает шансы почти в полтора раза |

Отношение шансов постоянно для всех клиентов — в этом его удобство. Но **шансы — не вероятность**. «Шансы
вдвое ниже» не означает «вероятность вдвое ниже».

### Изменение вероятности

Заказчику нужны вероятности. Эффект в вероятностях зависит от того, с какого уровня мы стартуем:

| Стаж, месяцев | Автоплатёж | Вероятность ухода |
|---|---|---|
| 3 | нет | 0.591 |
| 3 | да | 0.421 |
| 36 | нет | 0.346 |
| 36 | да | 0.210 |

(Остальные признаки: плата 790 рублей, помесячный контракт, одно обращение.)

Один и тот же коэффициент −0.686 соответствует разнице в 17 процентных пунктов для нового клиента и
в 13.6 пункта для клиента с трёхлетним стажем. Сигмоида крутая в середине и пологая по краям: чем ближе
вероятность к 0 или 1, тем слабее на неё действует то же изменение логарифма шансов.

Одним числом эффект описывает **средний предельный эффект** — изменение вероятности, усреднённое по всем
клиентам:

```python
logit.get_margeff().summary()
```

| Признак | Средний предельный эффект |
|---|---|
| `tenure_months` | −0.0055 |
| `fee_k` | 0.068 |
| `annual` | −0.261 |
| `autopay_i` | −0.124 |
| `support_calls` | 0.072 |

«Клиенты с годовым контрактом уходят в среднем на 26 процентных пунктов реже при прочих равных» —
формулировка, которую можно нести заказчику.

### Связь — ещё не причина

Вернёмся к вопросу из урока 3.1.2: снизит ли отток подключение автоплатежа всем клиентам? В генераторе
данных есть скрытая лояльность клиента: лояльные чаще подключают автоплатёж и реже уходят. Истинный эффект
автоплатежа известен, поэтому можно сравнить:

| Модель | Коэффициент при автоплатеже | Отношение шансов |
|---|---|---|
| Только автоплатёж | −0.905 | 0.40 |
| С остальными наблюдаемыми признаками | −0.686 | 0.50 |
| С добавлением скрытой лояльности | −0.230 | 0.79 |
| Заложено в генератор | −0.200 | 0.82 |

Модель на наблюдаемых данных завышает эффект автоплатежа более чем втрое. Кампания по подключению
автоплатежа, рассчитанная по коэффициенту −0.686, дала бы намного меньше обещанного. В реальных данных
лояльность измерить нельзя — и узнать настоящий эффект можно только экспериментом.

## 5. scikit-learn: регуляризация по умолчанию

`LogisticRegression` в scikit-learn — модель для предсказаний, а не для статистического вывода: она
не считает стандартных ошибок и по умолчанию применяет L2-регуляризацию с параметром `C=1.0`, где `C` —
**обратная** сила регуляризации (чем меньше `C`, тем сильнее штраф).

```python
from sklearn.linear_model import LogisticRegression

X = clients[["tenure_months", "fee_k", "annual", "autopay_i", "support_calls"]]
y = clients["churn"]

LogisticRegression(max_iter=1000).fit(X, y)  # C=1.0 по умолчанию
LogisticRegression(C=np.inf, max_iter=1000).fit(X, y)  # без регуляризации
```

| Модель | Свободный член | `tenure` | `fee_k` | `annual` | `autopay` | `calls` |
|---|---|---|---|---|---|---|
| statsmodels | −0.239 | −0.031 | 0.380 | −1.449 | −0.686 | 0.397 |
| sklearn, `C=inf` | −0.239 | −0.030 | 0.380 | −1.449 | −0.686 | 0.397 |
| sklearn, по умолчанию | −0.239 | −0.030 | 0.377 | −1.441 | −0.684 | 0.396 |
| sklearn, `C=0.01` | −0.309 | −0.029 | 0.221 | −0.963 | −0.496 | 0.374 |

На 5 000 наблюдений штраф по умолчанию почти незаметен. На выборке из 200 клиентов разница уже ощутима:
коэффициент при `fee_k` равен 1.27 без регуляризации и 1.08 с ней.

Что нужно помнить:

- если коэффициенты будут интерпретироваться — отключайте регуляризацию (`C=np.inf`) или используйте
  statsmodels;
- если регуляризация включена — признаки нужно масштабировать (урок 3.1.1), иначе штраф зависит от единиц
  измерения. В таблице выше признак `fee_k` при `C=0.01` «сжался» почти вдвое, а `tenure_months` почти
  не изменился именно из-за разного масштаба;
- в scikit-learn начиная с версии 1.8 параметр `penalty` объявлен устаревшим: запись `penalty=None`
  выдаёт предупреждение. Регуляризация отключается через `C=np.inf`, а её тип задаётся параметром
  `l1_ratio`. Если встретите `penalty` в чужом коде или в старых руководствах — замените;
- `predict` возвращает класс по порогу 0.5, `predict_proba` — вероятности. Порог 0.5 почти никогда
  не оптимален; его выбору посвящена тема 3.2.

### Идеальная разделимость

Если какой-то признак идеально разделяет классы, максимум правдоподобия недостижим: веса растут
до бесконечности, делая сигмоиду всё круче.

```python
separable = pd.DataFrame({"x": [1.0, 2, 3, 4, 5, 6, 7, 8], "y": [0, 0, 0, 0, 1, 1, 1, 1]})
smf.logit("y ~ x", data=separable).fit()  # PerfectSeparationWarning, коэффициент 39.7
```

| Модель | Коэффициент при `x` |
|---|---|
| statsmodels | 39.7, с предупреждением и без сходимости |
| sklearn, `C=1` | 1.17 |
| sklearn, `C=100` | 5.65 |
| sklearn, `C=10⁶` | 18.4 |

В реальных данных это случается с редкими категориями («все трое клиентов из города N ушли»)
и с признаками, в которые просочилась целевая переменная. Огромный коэффициент с огромной стандартной
ошибкой — повод проверить признак на утечку. Регуляризация делает задачу корректной — это одна из причин,
по которой в scikit-learn она включена по умолчанию.

## 6. Пуассоновская регрессия

### Модель

Целевая переменная — число обращений в поддержку. Модель предполагает, что число событий распределено
по Пуассону со средним

$$\mu = e^{w^\top x}$$

Логарифмическая связь означает, что признаки действуют **мультипликативно**: увеличение признака на единицу
умножает ожидаемое число событий на $e^{w_j}$. Эта величина называется **отношением интенсивностей**
(rate ratio).

У распределения Пуассона дисперсия равна среднему — модель «знает», что у активных клиентов разброс
больше, и не требует постоянной дисперсии.

### Время наблюдения

Новый клиент, пришедший три месяца назад, не мог обратиться в поддержку столько же раз, сколько клиент
с годовой историей. Сравнивать нужно не число событий, а интенсивность — число событий в единицу времени:

$$\mu = t \cdot e^{w^\top x} \quad\Rightarrow\quad \ln\mu = \ln t + w^\top x$$

Слагаемое $\ln t$ входит в модель с фиксированным коэффициентом 1 и называется **смещением** (offset).

```python
poisson = smf.glm(
    "support_calls ~ services + autopay_i",
    data=clients,
    family=sm.families.Poisson(),
    offset=np.log(clients["exposure_years"]),
).fit()
```

В генератор заложен коэффициент 0.25 при числе услуг — модель восстановила его точно. А вот автоплатёж
в генераторе на обращения **не влияет вовсе**: связь целиком создана скрытой лояльностью. Если добавить
её в модель, коэффициент при автоплатеже становится равным −0.017.

Предсказание для новых клиентов — с тем же смещением:

| Услуг | Автоплатёж | Период наблюдения | Ожидаемое число обращений |
|---|---|---|---|
| 1 | нет | год | 1.26 |
| 5 | нет | год | 3.36 |
| 5 | да | 3 месяца | 0.64 |

Что будет, если забыть про время наблюдения: модель без смещения даёт почти те же коэффициенты при признаках
(на этих данных период наблюдения не связан с признаками), но занижает свободный член и хуже описывает
данные. Если бы новые клиенты отличались от старых по набору услуг, коэффициенты были бы смещены.

### Избыточная дисперсия

Предположение «дисперсия равна среднему» в реальных данных часто нарушается: дисперсия оказывается больше.
Проверка — отношение статистики хи-квадрат Пирсона к числу степеней свободы; для корректной модели оно
близко к единице.

```python
poisson.pearson_chi2 / poisson.df_resid  # 1.13
```

У нас 1.13: разброс на 13 % больше, чем предполагает модель. Причина — неучтённая лояльность: с ней
в модели показатель равен 1.00. При избыточной дисперсии коэффициенты остаются верными, но стандартные
ошибки занижены. Что делать:

| Способ | Код | Когда |
|---|---|---|
| Устойчивые стандартные ошибки | `.fit(cov_type="HC3")` | умеренная избыточность; подходит по умолчанию |
| Квазипуассоновская модель | `.fit(scale="X2")` | то же: ошибки умножаются на корень из показателя дисперсии |
| Отрицательная биномиальная регрессия | `sm.families.NegativeBinomial()` | сильная избыточность, показатель заметно больше 1.5–2 |

На наших данных стандартная ошибка коэффициента при `services` равна 0.0081 по классической формуле
и 0.0085–0.0086 с поправкой.

### scikit-learn

```python
from sklearn.linear_model import PoissonRegressor

rate = clients["support_calls"] / clients["exposure_years"]  # интенсивность: обращений в год
model = PoissonRegressor(alpha=0, max_iter=1000)
model.fit(clients[["services", "autopay_i"]], rate, sample_weight=clients["exposure_years"])
```

Две особенности:

- параметра для смещения нет. Вместо этого предсказывают интенсивность, а время наблюдения передают
  как вес объекта — результат совпадает с моделью со смещением: коэффициенты −0.019, 0.246, −0.268;
- **регуляризация включена по умолчанию** (`alpha=1.0`), и она сильная. С параметрами по умолчанию
  коэффициенты получаются 0.090, 0.194 и −0.086 — эффект автоплатежа занижен втрое.

Качество пуассоновской модели измеряют средним пуассоновским отклонением (`mean_poisson_deviance`):
1.430 у модели против 1.692 у предсказания средним для всех.

## 7. Как выбрать модель

| Целевая переменная | Примеры | Модель |
|---|---|---|
| Да или нет | отток, клик, дефолт | логистическая регрессия |
| Один из нескольких классов | категория обращения | мультиномиальная логистическая регрессия |
| Число событий | обращения, покупки, аварии | пуассоновская; при избыточной дисперсии — отрицательная биномиальная |
| Число событий за разное время | страховые случаи за срок полиса | пуассоновская со смещением |
| Положительная величина со скошенным распределением | сумма убытка, длительность | гамма-регрессия с логарифмической связью |
| Сумма со множеством нулей | выплаты по полисам | регрессия Твиди (`TweedieRegressor`) |
| Любое число, симметричный шум | температура, отклонение от плана | линейная регрессия |

Градиентный бустинг (модуль 4) поддерживает те же функции потерь: логистическую, пуассоновскую, гамма
и Твиди. Понимание GLM напрямую переносится на более сильные модели.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Предсказанные «вероятности» меньше 0 или больше 1 | линейная регрессия для бинарной цели | логистическая регрессия |
| Отрицательные предсказания числа событий | линейная регрессия для счётчика | пуассоновская регрессия |
| Коэффициенты sklearn и statsmodels не совпадают | регуляризация по умолчанию в sklearn | `C=np.inf` для логистической, `alpha=0` для пуассоновской |
| «Шансы вдвое ниже» пересказано как «вероятность вдвое ниже» | перепутаны шансы и вероятность | переводить эффект в вероятности для конкретных клиентов или в средний предельный эффект |
| Огромный коэффициент с огромной стандартной ошибкой | идеальная разделимость; утечка целевой переменной | проверить признак, объединить редкие категории, регуляризация |
| `ConvergenceWarning` | немасштабированные признаки, мало итераций, разделимость | масштабировать, увеличить `max_iter`, проверить данные |
| Предупреждение об устаревшем параметре `penalty` | код написан под старую версию scikit-learn | `C=np.inf` и `l1_ratio` |
| Новые клиенты «реже обращаются в поддержку» | не учтено время наблюдения | смещение `offset=np.log(t)` |
| Подозрительно узкие интервалы в пуассоновской модели | избыточная дисперсия | проверить показатель дисперсии; устойчивые ошибки |
| Порог 0.5 даёт плохие бизнес-результаты | порог не подобран под цену ошибок | выбор порога — тема 3.2 |
| Эффект кампании оказался намного меньше расчётного | коэффициент принят за причинный эффект | эксперимент; в отчёте — формулировка «связано», а не «снижает» |
