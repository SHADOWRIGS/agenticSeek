на кластерах «неправильной» формы — и как выбирать число кластеров, если его никто не знает.

## 2. Алгоритм Ллойда и его функция потерь

K-means ищет $k$ центров $\mu_1, \dots, \mu_k$, минимизируя сумму квадратов расстояний от каждого объекта
до ближайшего центра — **инерцию** (within-cluster sum of squares, WCSS):

$$J = \sum_{i=1}^{n} \min_{j} \lVert x_i - \mu_j \rVert^2$$

Алгоритм Ллойда чередует два шага: отнести каждый объект к ближайшему центру; перенести каждый центр
в среднее своих объектов. Это та же функция, что вы писали в практике 2.2.4, с записью инерции:

```python
def lloyd(X, centers, max_iter=100):
    history = []
    for _ in range(max_iter):
        distances = ((X[:, None, :] - centers[None, :, :]) ** 2).sum(axis=2)
        labels = distances.argmin(axis=1)
        history.append(distances.min(axis=1).sum())
        new_centers = np.array([X[labels == j].mean(axis=0) for j in range(len(centers))])
        if np.allclose(new_centers, centers):
            break
        centers = new_centers
    return labels, centers, history
```

Оба шага не увеличивают $J$: при фиксированных центрах ближайший центр — лучший выбор для объекта,
при фиксированном разбиении среднее — точка с минимальной суммой квадратов расстояний. Вариантов
разбиения конечное число, значит, алгоритм остановится. Запустим его на подготовленных признаках
(функция `prepare` — логарифм и стандартизация — объясняется в разделе 4):

```python
from sklearn.preprocessing import StandardScaler

LOG_FEATURES = ["recency_days", "frequency", "avg_check", "account_age_days"]


def prepare(customers, log=True):
    X = customers[FEATURES].astype(float)
    if log:
        X[LOG_FEATURES] = np.log1p(X[LOG_FEATURES])
    return StandardScaler().fit_transform(X)


Z = prepare(customers)
for seed in [0, 1, 2, 3]:
    start = Z[np.random.default_rng(seed).choice(len(Z), 6, replace=False)]  # шесть случайных клиентов
    labels, centers, history = lloyd(Z, start)
    print(seed, len(history), round(history[0]), round(history[-1], 1), adjusted_rand_score(segment, labels))
```

При старте 0 инерция по итерациям: 15 005 → 9 668 → 8 020 → 6 769 → 6 591 → … → 6 468. Она ни разу

## 3. Инициализация: k-means++ и `n_init`

Результат зависит от начальных центров. Случайный выбор часто ставит два центра в один кластер
и ни одного — в другой; шаги Ллойда такую ошибку исправляют не всегда.

**K-means++** выбирает начальные центры по одному. Первый — случайный объект. Каждый следующий — объект,
выбранный с вероятностью, пропорциональной **квадрату расстояния** до ближайшего из уже выбранных центров:

$$P(x_i) = \frac{D(x_i)^2}{\sum_{l} D(x_l)^2}$$

Далёкие от уже выбранных центров объекты получают большую вероятность, и центры расходятся по разным
областям данных. Выбор остаётся случайным: если бы всегда брали самую далёкую точку, центрами
становились бы выбросы.

Сравним 200 запусков с одной попыткой каждый на клиентах и на наборе из 15 круглых облаков:

```python
from sklearn.datasets import make_blobs


def init_study(X, k, truth, n_runs=200):
    rows = {}
    for init in ["random", "k-means++"]:
        models = [KMeans(k, init=init, n_init=1, random_state=run).fit(X) for run in range(n_runs)]
        inertia = pd.Series([model.inertia_ for model in models])
        rows[init] = inertia.agg(["min", "mean", "max"]).to_dict()
        rows[init]["near_best"] = (inertia <= 1.01 * inertia.min()).mean()
        rows[init]["min_ari"] = min(adjusted_rand_score(truth, model.labels_) for model in models)
    return pd.DataFrame(rows).T


init_study(Z, 6, segment)
blobs15, blobs15_labels = make_blobs(3000, centers=15, cluster_std=0.6, center_box=(-12, 12), random_state=7)
init_study(blobs15, 15, blobs15_labels)
```

| Данные | Инициализация | Лучшая инерция | Средняя | Худшая | Запусков в 1 % от лучшего | Худший ARI |
|---|---|---|---|---|---|---|
| клиенты, k = 6 | случайная | 5 919 | 6 255 | 8 578 | 46 % | 0.634 |
| клиенты, k = 6 | k-means++ | 5 919 | 6 177 | 6 529 | 54 % | 0.805 |
| 15 облаков | случайная | 2 020 | 5 476 | 14 785 | 0.5 % | 0.531 |
| 15 облаков | k-means++ | 2 020 | 2 207 | 2 954 | 27.5 % | 0.768 |

Выводы:

- при шести кластерах k-means++ убирает худшие исходы (худшая инерция 6 529 против 8 578), но в среднем
  выигрывает мало: почти половина запусков всё равно попадает в локальный минимум;
- при пятнадцати кластерах разница принципиальная: средняя инерция случайной инициализации в 2.7 раза
  выше лучшей, у k-means++ — на 9 %. Чем больше кластеров, тем вероятнее неудачный случайный старт;
- даже k-means++ за одну попытку находит лучшее решение меньше чем в трети случаев. Нужны повторы.

Параметр `n_init` задаёт число запусков с разными стартами; возвращается запуск с наименьшей инерцией.
Доля из 50 экспериментов, в которых результат оказался в пределах 1 % от лучшей известной инерции:

| Инициализация | `n_init` | Клиенты, k = 6 | 15 облаков |
|---|---|---|---|
| случайная | 1 | 44 % | 0 % |
| случайная | 10 | 100 % | 8 % |
| k-means++ | 1 | 52 % | 26 % |
| k-means++ | 3 | 84 % | 64 % |
| k-means++ | 10 | 100 % | 88 % |

В scikit-learn по умолчанию `init="k-means++"` и `n_init="auto"`, а «auto» для k-means++ означает
**один** запуск. На наших данных это монетка: с вероятностью около половины вы получите разбиение
с ARI 0.84 вместо 0.95 и не узнаете об этом. Задавайте `n_init=10` явно и всегда фиксируйте
`random_state`.

## 4. Масштаб и скошенные признаки

K-means работает с евклидовыми расстояниями, а в них вклад признака пропорционален квадрату его разброса.

```python
X_raw = customers[FEATURES]
(X_raw.var() / X_raw.var().sum()).round(4)  # avg_check: 0.9987, остальные шесть вместе: 0.0013

raw = KMeans(6, n_init=10, random_state=0).fit(X_raw)
only_check = KMeans(6, n_init=10, random_state=0).fit(X_raw[["avg_check"]])
adjusted_rand_score(raw.labels_, only_check.labels_)  # 1.0
adjusted_rand_score(segment, raw.labels_)  # 0.130
```

Кластеризация по семи признакам **в точности совпала** с кластеризацией по одному среднему чеку:
рубли измеряются тысячами, доли — сотыми, и шесть признаков из семи в расстояние ничего не вносят.
Размеры кластеров — 2 534, 282, 114, 51, 14 и 5 клиентов: четыре пятых базы попали в один кластер
«обычный чек», остальные пять делят хвост распределения.

Стандартизация (урок 3.1.1) уравнивает разбросы, но не форму распределений. Средний чек распределён
логнормально, как почти все денежные величины: коэффициент асимметрии 6.4. После стандартизации редкие
огромные значения остаются на расстоянии десятков стандартных отклонений и перетягивают центры на себя.
Логарифм превращает «во сколько раз больше» в «на сколько больше»: для денег, счётчиков и длительностей
это и есть естественное понятие похожести — клиенты с чеком 1 000 и 2 000 рублей различаются сильнее,
чем с чеком 51 000 и 52 000. Используем `log1p`, чтобы нули не давали минус бесконечность. Асимметрия
после него: средний чек — 1.21 вместо 6.39, давность — 0.15 вместо 2.24, число заказов — 0.25 вместо 1.65.

```python
for name, matrix in [("исходные", X_raw), ("стандартизация", prepare(customers, log=False)), ("log1p", Z)]:
    labels = KMeans(6, n_init=10, random_state=0).fit_predict(matrix)
    print(name, adjusted_rand_score(segment, labels))
```

| Подготовка признаков | ARI с истинными сегментами |
|---|---|
| без подготовки | 0.130 |
| стандартизация | 0.840 |
| `log1p` скошенных признаков + стандартизация | 0.953 |

Доли и число категорий логарифмировать не нужно: они ограничены и не скошены. Правило: логарифмируем
неотрицательные признаки с длинным правым хвостом, стандартизуем все.

## 5. Какие кластеры k-means находит, а какие нет

Минимизация суммы квадратов расстояний до центра неявно предполагает, что кластеры **шарообразные,
примерно одного размера и одного разброса**. Граница между двумя кластерами — всегда плоскость
посередине между центрами. Проверим на наборах из `shapes_data.py`, где истинные метки известны:

```python
from shapes_data import make_shapes

shapes = make_shapes()
for name in ["blobs", "moons", "aniso", "variance", "sizes"]:
    points, truth = shapes[name]
    labels = KMeans(len(set(truth)), n_init=10, random_state=0).fit_predict(points)
    print(name, adjusted_rand_score(truth, labels), np.bincount(labels))
```

| Набор | Что в нём | ARI | Что произошло |
|---|---|---|---|
| `blobs` | три круглых облака | 0.998 | идеальный для k-means случай |
| `moons` | два полумесяца | 0.255 | разрезал оба полумесяца прямой |
| `aniso` | три вытянутых облака | 0.605 | режет облака поперёк |
| `variance` | среднее облако втрое шире крайних | 0.778 | края широкого облака отданы соседям: 377, 562 и 561 точка вместо 500 |
| `sizes` | большое облако и два маленьких | 0.177 | большое облако разрезано на три: 293, 880 и 327 точек вместо 1 350, 75, 75 |

Картинка с этими наборами — в уроке 3.3.2, там же алгоритмы, которые с ними справляются.

**Выбросы.** Среднее чувствительно к далёким точкам, а квадрат расстояния усиливает их влияние.
Добавим к трём облакам по 1 000 точек всего 10 далёких:

```python
points, truth = make_blobs(1000, centers=[[0, 0], [6, 0], [3, 5]], cluster_std=1.0, random_state=0)
outliers = np.random.default_rng(1).uniform(25, 40, size=(10, 2))
with_outliers = KMeans(3, n_init=10, random_state=0).fit(np.vstack([points, outliers]))
adjusted_rand_score(truth, with_outliers.labels_[:1000])  # 0.565; без выбросов 1.0
np.bincount(with_outliers.labels_)  # [667  10 333]
```

Один процент точек забрал себе отдельный центр, а два настоящих кластера слились. На клиентах эффект
слабее, но заметен, и логарифм его смягчает. Параметр `outlier_share` генератора задаёт долю клиентов
с аномальным чеком: при 0 %, 1 % (как в данных темы) и 5 % ARI равен 0.889, 0.840 и 0.814 с одной
стандартизацией и 0.961, 0.953 и 0.920 с логарифмом. При 5 % без логарифма появляется кластер из трёх
клиентов. Крошечный кластер — типичный признак того, что центр «украден» выбросами.

## 6. Сколько кластеров

Инерция с ростом $k$ только падает (при $k = n$ она равна нулю), поэтому выбирать $k$ по её минимуму
нельзя. Шесть способов:

| Способ | Идея | Как читать |
|---|---|---|
| Метод локтя | после «настоящего» $k$ инерция падает медленно | ищем излом на графике |
| Силуэт | для объекта: $s = \frac{b - a}{\max(a, b)}$, где $a$ — среднее расстояние до своего кластера, $b$ — до ближайшего чужого | среднее по объектам, чем больше, тем лучше; от −1 до 1 |
| Calinski–Harabasz | отношение межкластерного разброса к внутрикластерному с поправкой на $k$ | чем больше, тем лучше |
| Davies–Bouldin | среднее по кластерам отношение «свой разброс к расстоянию до самого похожего соседа» | чем меньше, тем лучше |
| Gap statistic | сравнение $\ln J$ с тем, что получается на данных без кластеров | наименьшее $k$, для которого $\text{gap}(k) \ge \text{gap}(k+1) - s_{k+1}$ |
| Устойчивость | настоящие кластеры не должны зависеть от того, какие объекты попали в выборку | наибольшее $k$ с устойчивостью около 1 |

Gap statistic и устойчивости в scikit-learn нет; обе пишутся в несколько строк:

```python
def gap_statistic(X, k_values, n_refs=10, seed=0):
    rng = np.random.default_rng(seed)
    low, high = X.min(axis=0), X.max(axis=0)
    refs = [rng.uniform(low, high, X.shape) for _ in range(n_refs)]  # данные без кластеров
    rows = []
    for k in k_values:
        log_inertia = np.log(KMeans(k, n_init=3, random_state=seed).fit(X).inertia_)
        ref_log = [np.log(KMeans(k, n_init=3, random_state=seed).fit(ref).inertia_) for ref in refs]
        s = np.std(ref_log) * np.sqrt(1 + 1 / n_refs)
        rows.append({"k": k, "gap": np.mean(ref_log) - log_inertia, "s": s})
    return pd.DataFrame(rows).set_index("k")


def stability(X, k, n_runs=10, share=0.8, seed=0):
    rng = np.random.default_rng(seed)
    reference = KMeans(k, n_init=10, random_state=seed).fit_predict(X)
    scores = []
    for _ in range(n_runs):
        sample = rng.choice(len(X), int(share * len(X)), replace=False)
        labels = KMeans(k, n_init=10, random_state=seed).fit(X[sample]).predict(X)
        scores.append(adjusted_rand_score(reference, labels))
    return np.mean(scores)
```

Устойчивость здесь — средний ARI между разбиением, обученным на всех клиентах, и разбиениями, обученными
на случайных 80 %. Остальные метрики — готовые функции:

```python
from sklearn.metrics import calinski_harabasz_score, davies_bouldin_score, silhouette_score

rows = {}
for k in range(2, 11):
    model = KMeans(k, n_init=10, random_state=0).fit(Z)
    rows[k] = {
        "inertia": model.inertia_,
        "silhouette": silhouette_score(Z, model.labels_),
        "calinski_harabasz": calinski_harabasz_score(Z, model.labels_),
        "davies_bouldin": davies_bouldin_score(Z, model.labels_),
        "stability": stability(Z, k),
        "ari": adjusted_rand_score(segment, model.labels_),
    }
selection = pd.DataFrame(rows).T
gap = gap_statistic(Z, range(1, 12))
```

| Метод | Ответ | Комментарий |
|---|---|---|
| Локоть | 5 или 6 | после 6 падение меньше 5 %; но излом между 5 и 6 тоже виден — решает глаз смотрящего |

| Устойчивость | 6 | при k ≤ 6 разбиения почти идентичны, при k = 7 устойчивость резко падает |

Методы **расходятся**, и четыре из шести ошиблись на единицу. Причина в данных, а не в методах: при k = 5
k-means объединяет оптовиков с ценителями — два небольших сегмента (5 % и 10 % клиентов) с высоким чеком.
С точки зрения геометрии это одно рыхлое облако «дорогих» клиентов, и метрики компактности честно
предпочитают его не делить. С точки зрения бизнеса оптовики дают 65 % выручки, и потерять этот сегмент
нельзя (урок 3.3.3).

Практические выводы: ни один метод не даёт «правильного» k, но вместе они отсекают заведомо плохие
варианты — здесь все согласны, что k равно 5 или 6. Внутренние метрики одобряют слияние маленьких
кластеров, устойчивость — нет, поэтому смотрят на оба вида критериев. Финальный выбор между кандидатами
делают по профилям кластеров: появился ли при переходе от 5 к 6 новый осмысленный сегмент.

Средний силуэт полезно разложить по кластерам (`silhouette_samples` возвращает значение для каждого
объекта). При k = 6:

```python
from sklearn.metrics import silhouette_samples

model = KMeans(6, n_init=10, random_state=0).fit(Z)
per_object = pd.Series(silhouette_samples(Z, model.labels_))
per_object.groupby(model.labels_).agg(["size", "mean", lambda s: (s < 0).mean()])
```

| Кластер (сегмент по истинным меткам) | Размер | Средний силуэт | Доля объектов с силуэтом < 0 |
|---|---|---|---|
| новички | 568 | 0.459 | 0.0 % |
| оптовики | 160 | 0.452 | 0.0 % |
| лояльные | 672 | 0.425 | 0.0 % |

| охотники за скидками | 579 | 0.350 | 0.2 % |
| ценители | 301 | 0.262 | 2.0 % |

Отрицательный силуэт означает, что объект в среднем ближе к чужому кластеру, чем к своему. Самый размытый
кластер — ценители; его границы стоит проверить в первую очередь.

## 7. Большие данные: MiniBatchKMeans

Шаг Ллойда считает расстояния от всех объектов до всех центров. `MiniBatchKMeans` на каждом шаге берёт
случайную порцию объектов (`batch_size`, по умолчанию 1 024) и сдвигает центры в сторону средних этой
порции. Замеры при одном запуске (`n_init=1`) на четырёх ядрах:

```python
big, big_segment = make_customers(n=1_000_000, seed=1)
Z_big = prepare(big)
for model in [KMeans(6, n_init=1, random_state=0), MiniBatchKMeans(6, n_init=1, random_state=0)]:
    started = time.perf_counter()
    model.fit(Z_big)
    print(type(model).__name__, time.perf_counter() - started, model.inertia_)
```

| Данные | Модель | Время, с | Инерция относительно KMeans | ARI |
|---|---|---|---|---|
| клиенты: 1 млн × 7, k = 6 | `KMeans` | 0.5 | — | 0.944 |
| | `MiniBatchKMeans` | 18.8 | +1.1 % | 0.936 |
| | `MiniBatchKMeans(batch_size=10_000)` | 1.7 | +0.0 % | 0.944 |
| облака: 500 тыс. × 50, k = 100 | `KMeans` | 9.7 | — | 0.951 |
| | `MiniBatchKMeans` | 4.8 | −0.8 % | 0.963 |
| | `MiniBatchKMeans(batch_size=10_000)` | 1.5 | +2.6 % | 0.928 |

Расхожее «MiniBatch быстрее» на первой задаче **не подтвердилось**: при семи признаках и шести кластерах
полный k-means сходится за 8 итераций и работает в 36 раз быстрее, чем MiniBatch с параметрами
по умолчанию, который тратит время на тысячи мелких шагов. Выигрыш появляется, когда итерация дорогая:
много признаков и много кластеров. Там MiniBatch быстрее в 2–6 раз ценой до 3 % инерции (а при одном
запуске может и выиграть — как во второй строке блока, где полный k-means попал в локальный минимум).
Вторая причина выбрать его — данные не помещаются в память: метод `partial_fit` обучает модель порциями.
Вывод: сначала измерьте обычный `KMeans`, он может оказаться достаточно быстрым.

## 8. Родственные алгоритмы

**K-medoids.** Центр кластера — не среднее, а один из объектов (медоид), минимизирующий сумму расстояний
до остальных. Устойчивее к выбросам, работает с любой мерой расстояния, а центр — реальный клиент,
которого можно показать заказчику. Цена — квадратичная сложность. **K-modes** для категориальных
признаков заменяет расстояние числом несовпадающих категорий, а среднее — модой; **k-prototypes**
объединяет оба подхода для смешанных данных. В scikit-learn этих алгоритмов нет — нужны отдельные пакеты.

**Смесь гауссиан (GMM).** Модель предполагает, что данные порождены $k$ нормальными распределениями,
каждое со своим центром, матрицей ковариации и весом. Обучение EM-алгоритмом чередует те же два шага,
что алгоритм Ллойда, но принадлежность «мягкая»: объект принадлежит каждому кластеру с вероятностью.
K-means — частный случай GMM с одинаковыми шарообразными ковариациями и жёстким назначением.

```python
from sklearn.mixture import GaussianMixture

for name in ["aniso", "variance", "sizes", "moons"]:
    points, truth = shapes[name]
    gmm = GaussianMixture(len(set(truth)), n_init=5, random_state=0).fit(points)
    print(name, adjusted_rand_score(truth, gmm.predict(points)))
```

ARI на `aniso` — 1.000 (у k-means 0.605), на `variance` — 0.939 (0.778), на `sizes` — 1.000 (0.177),
на `moons` — 0.505 (0.255). Эллипсы, разный разброс и разный размер GMM исправляет; невыпуклые
полумесяцы — нет. Число компонент
выбирают по BIC (чем меньше, тем лучше): правдоподобие со штрафом за число параметров.

```python
for covariance_type in ["full", "tied"]:
    for k in range(2, 11):
        gmm = GaussianMixture(k, covariance_type=covariance_type, n_init=3, random_state=0).fit(Z)
        print(covariance_type, k, round(gmm.bic(Z)), adjusted_rand_score(segment, gmm.predict(Z)))
```

| k | BIC, `full` | ARI, `full` | BIC, `tied` | ARI, `tied` |
|---|---|---|---|---|
| 4 | 39 471 | 0.717 | 42 614 | 0.645 |
| 5 | 38 624 | 0.928 | 41 991 | 0.914 |
| 6 | 24 437 | 0.776 | 39 917 | **0.965** |
| 7 | 23 981 | 0.801 | 39 850 | 0.876 |
| 8 | 21 211 | 0.703 | 39 798 | 0.809 |
| 10 | 20 658 | 0.518 | 39 618 | 0.722 |

На клиентах «учебниковый» рецепт не сработал: BIC продолжает падать и при k = 10 и числа компонент
не называет, а GMM с полной ковариацией при k = 6 хуже k-means (0.776 против 0.953). Причина видна
по резкому падению BIC между 5 и 6: шестая компонента забрала 431 клиента ровно с одним заказом.
У них `frequency = 1`, `n_categories = 1` и `recency_days = account_age_days`, то есть они лежат
на подпространстве меньшей размерности; гауссиана с почти нулевой дисперсией вдоль этих направлений
получает огромное правдоподобие. Дискретные и вырожденные признаки — слабое место GMM. С общей
ковариацией для всех компонент (`covariance_type="tied"`) вырождение невозможно, и при k = 6 ARI
равен 0.965 — лучше k-means, но k по-прежнему приходится выбирать самим.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Результат меняется от запуска к запуску | не задан `random_state`; `n_init="auto"` даёт один запуск | `n_init=10`, фиксированный `random_state` |
| Кластеры определяются одним признаком | признаки в разных единицах, не было масштабирования | `StandardScaler` перед k-means |
| Один огромный кластер и несколько крошечных | скошенные признаки или выбросы | `log1p` для денег и счётчиков; разобраться с выбросами отдельно |
| Кластер из нескольких объектов | центр «украден» выбросами | найти и исключить выбросы, либо k-medoids |
| Длинное облако разрезано поперёк | k-means предполагает шарообразные кластеры | GMM; алгоритмы урока 3.3.2 |
| Разные методы называют разное k | так и должно быть: методы измеряют разное | сузить диапазон, решить по устойчивости и смыслу сегментов |
| `MiniBatchKMeans` работает дольше `KMeans` | мало признаков и кластеров, итерация и так дешёвая | измерить `KMeans`; увеличить `batch_size` |
| BIC у GMM падает без остановки | дискретные или вырожденные признаки | `covariance_type="tied"` или `"diag"`, параметр `reg_covar` |
