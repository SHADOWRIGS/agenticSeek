## Зачем это нужно

Индексация — это половина кода любого ML-пайплайна: выбрать батч, перемешать выборку, отделить тест,
взять вероятность правильного класса, найти десять ближайших соседей, собрать матрицу ошибок. Каждую
из этих операций можно написать циклом, и каждая из них в NumPy записывается одной строкой, которая
работает в 50–100 раз быстрее.

Вторая причина — ошибки, которые не выглядят ошибками. Присваивание, которое молча ничего не изменило.
Градиент, в котором потерялись повторяющиеся токены. Функция потерь, получившая матрицу вместо вектора.
Ни одна из них не вызывает исключения, и каждая разобрана в этом уроке.

Примеры проверены на NumPy 2.5. Замеры зависят от машины: важен порядок величин.

## 1. Булевы маски

Сравнение массива с числом даёт массив `bool` той же формы — маску. Маской можно индексировать:

```python
import numpy as np

rng = np.random.default_rng(42)
ages = np.array([25, 41, -1, 33, 120, 58])
income = np.array([50.0, 82.0, 61.0, np.nan, 40.0, 95.0])

mask = (ages >= 0) & (ages <= 100)      # array([ True,  True, False,  True, False,  True])
mask.sum(), mask.mean()                 # 4 подходящих значения, доля 0.667
ages[mask]                              # array([25, 41, 33, 58])
np.flatnonzero(~mask)                   # array([2, 4]) — номера «плохих» элементов

valid = mask & ~np.isnan(income)
income[valid].mean()                    # 75.67 — средний доход по корректным строкам
```

Условия объединяются операторами `&`, `|`, `~`, и каждое условие берётся в скобки. `and` и `or` с массивами
не работают: `ages[ages >= 0 and ages <= 100]` завершается ошибкой
`ValueError: The truth value of an array with more than one element is ambiguous`. Ту же ошибку даёт запись
без скобок `ages >= 0 & ages <= 100`: приоритет `&` выше, чем у сравнений.

Маска по строкам двумерного массива отбирает строки целиком, присваивание по маске меняет массив на месте:

```python
X = np.arange(12).reshape(4, 3)
X[X.sum(axis=1) > 10]                   # строки, сумма которых больше 10: форма (3, 3)
X[:, X.max(axis=0) > 10]                # столбцы, в которых есть значение больше 10: форма (4, 1)

cleaned = ages.copy()
cleaned[cleaned < 0] = 0                # array([ 25,  41,   0,  33, 120,  58])
np.isin(ages, [25, 33, 99])             # array([ True, False, False,  True, False, False])
```

## 2. `np.where`, `np.select`, `np.clip`

```python
np.where(ages > 100, 100, ages)                 # array([ 25,  41,  -1,  33, 100,  58]): «если — то — иначе»
np.where(mask, ages, np.median(ages[mask]))     # array([25., 41., 37., 33., 37., 58.]): замена медианой

score = np.array([0.05, 0.4, 0.75, 0.95])
np.select([score < 0.3, score < 0.8], ["low", "mid"], default="high")   # ['low', 'mid', 'mid', 'high']

np.clip(ages, 0, 100)                           # array([ 25,  41,   0,  33, 100,  58])
```

`np.where` с тремя аргументами выбирает поэлементно из двух вариантов, `np.select` — из нескольких: условия
проверяются по порядку, срабатывает первое истинное. `np.clip` ограничивает значения диапазоном.

Ловушка `np.where`: оба варианта вычисляются целиком **до** выбора. `np.where(den != 0, 1.0 / den, 0.0)`
вернёт правильный результат, но выдаст `RuntimeWarning: divide by zero` — деление выполнилось для всех
элементов. Правильный способ — `np.divide(..., out=..., where=...)` из прошлого урока.

Главное применение `np.clip` в ML — защита логарифма:

```python
p = np.array([0.0, 0.5, 1.0])
np.log(np.clip(p, 1e-15, 1.0))                  # array([-34.54,  -0.69,   0.  ]) вместо -inf
```

## 3. Индексация массивами целых чисел (fancy indexing)

Индексом может быть список или массив целых. Результат имеет **форму массива индексов**:

```python
x = np.arange(10, 20)
x[[0, 3, 3, -1]]                        # array([10, 13, 13, 19]) — повторы и любой порядок разрешены
x[np.array([[0, 1], [8, 9]])]           # array([[10, 11], [18, 19]]) — форма индекса (2, 2)
```

В двумерном случае массивы индексов по разным осям **объединяются в пары**, а не в «решётку»:

```python
X = np.arange(20).reshape(4, 5)
X[[0, 2]]                               # строки 0 и 2: форма (2, 5)
X[[0, 2], [1, 4]]                       # array([ 1, 14]) — элементы (0, 1) и (2, 4)
X[np.ix_([0, 2], [1, 4])]               # array([[ 1,  4], [11, 14]]) — пересечение строк и столбцов
X[1:3, [0, 4]]                          # срез и список сочетаются: строки 1–2, столбцы 0 и 4
X[np.arange(4), [0, 1, 2, 3]]           # array([ 0,  6, 12, 18]) — по одному элементу из каждой строки
```

Вторая строка — самая частая неожиданность: вместо подматрицы 2×2 получаются два элемента. Массивы
индексов согласуются по правилам broadcasting, поэтому `X[[0, 1, 2], [1, 4]]` — ошибка
`shape mismatch: indexing arrays could not be broadcast together with shapes (3,) (2,)`. Подматрицу
даёт `np.ix_`. Последняя строка — приём «по одному элементу из каждой строки», на нём построен расчёт
cross-entropy (раздел 6).

Перемешивание, разбиение на обучение и тест и нарезка на батчи — это fancy indexing перестановкой:

```python
n = 10
features, target = np.arange(n * 2).reshape(n, 2), np.arange(n) % 2

perm = rng.permutation(n)               # array([5, 6, 0, 7, 3, 2, 4, 9, 1, 8])
test_idx, train_idx = perm[:3], perm[3:]
X_train, y_train = features[train_idx], target[train_idx]      # одни и те же индексы для X и y
X_test, y_test = features[test_idx], target[test_idx]

for start in range(0, len(train_idx), 4):
    batch_idx = train_idx[start : start + 4]
    X_batch, y_batch = features[batch_idx], target[batch_idx]  # батчи форм (4, 2), (3, 2)
```

Перестановка индексов надёжнее, чем перемешивание самих массивов: `X` и `y` невозможно перемешать
по-разному, а исходные данные остаются нетронутыми.

## 4. View или копия

Правило короткое: **срез возвращает view, маска и массив индексов — копию**.

```python
base = np.arange(6)
s, f, m = base[1:4], base[[1, 2, 3]], base[base > 2]
np.shares_memory(base, s), np.shares_memory(base, f), np.shares_memory(base, m)   # (True, False, False)
```

Из него следуют три вида ошибок.

**Присваивание в копию теряется.** Запись `a[...] = значение` всегда меняет `a`. Но цепочка из двух
индексаций сначала создаёт копию, а потом меняет её:

```python
X = np.arange(12).reshape(3, 4)
X[X > 5][0] = -1                # ничего не изменилось: X[X > 5] — временная копия
X[[0, 1]][:, 0] = -1            # тоже ничего: X[[0, 1]] — копия
X[[0, 1], 0] = -1               # работает: одна операция присваивания
X[:, 0]                         # array([-1, -1,  8])
```

**Изменение view портит исходные данные.** Батч, взятый срезом, — это view:

```python
data = np.arange(12.0).reshape(3, 4)
batch = data[:2]
batch -= batch.mean(axis=0)     # «нормализовали батч» — и испортили первые две строки data
```

Батч, взятый через `data[batch_idx]`, — копия, и с ним так не случится. Код, который работал с
перемешанными батчами, ломается при переходе на последовательные срезы.

**Копии стоят времени и памяти.** На массиве 100 000×100 срез `big[::2]` выполняется за 0.1 мкс,
а `big[idx]` с теми же строками — за 9.3 мс: копируется 40 МБ. Если индексы образуют регулярный шаг,
используйте срез.

## 5. Повторяющиеся индексы

```python
grad = np.zeros(5)
token_ids = np.array([1, 3, 1, 1])              # токен 1 встретился в батче трижды
updates = np.array([0.1, 0.2, 0.3, 0.4])

grad[token_ids] += updates                      # array([0. , 0.4, 0. , 0.2, 0. ]) — неверно
```

Ожидалось `0.1 + 0.3 + 0.4 = 0.8` в позиции 1, получилось `0.4`. Запись `grad[idx] += upd` — это
`grad[idx] = grad[idx] + upd`: сначала читаются значения (три нуля для индекса 1), к ним прибавляются
обновления, затем результат записывается — и последняя запись затирает предыдущие. Так теряются градиенты
слоя эмбеддингов, счётчики частот, суммы по группам. Правильные варианты:

```python
grad = np.zeros(5)
np.add.at(grad, token_ids, updates)                     # array([0. , 0.8, 0. , 0.2, 0. ])
np.bincount(token_ids, weights=updates, minlength=5)    # то же значение, новый массив
```

На миллионе обновлений в массив из 1000 элементов `np.add.at` работает 1.4 мс, `np.bincount` — 1.6 мс,
цикл Python — 227 мс. `np.add.at` годится и для двумерного случая (строки эмбеддингов),
`np.bincount` — только для одномерных сумм с неотрицательными целыми индексами.

## 6. Сортировка, top-k и выбор по индексам вдоль оси

```python
scores = np.array([0.1, 0.7, 0.3, 0.9, 0.5])
order = np.argsort(scores)              # array([0, 2, 4, 1, 3]) — индексы по возрастанию значения
np.argsort(-scores)                     # array([3, 1, 4, 2, 0]) — по убыванию
ranks = np.empty_like(order)
ranks[order] = np.arange(len(scores))   # array([0, 3, 1, 4, 2]) — ранг каждого элемента

top2 = np.argpartition(scores, -2)[-2:] # array([1, 3]) — индексы двух наибольших, порядок не гарантирован
top2[np.argsort(-scores[top2])]         # array([3, 1]) — упорядочили только найденные
```

`argsort` сортирует всё (O(n log n)), `argpartition` только отделяет k наибольших (O(n)). Для top-10
из миллиона значений: 28.2 мс против 2.1 мс. Для стабильного порядка при равных значениях — `kind="stable"`.

Для батча предсказаний индексы есть в каждой строке свои. Выбрать по ним значения помогает
`np.take_along_axis`:

```python
probs = np.array([[0.1, 0.6, 0.05, 0.25], [0.3, 0.1, 0.4, 0.2], [0.25, 0.25, 0.3, 0.2]])
y_true = np.array([1, 0, 3])

topk = np.argpartition(probs, -2, axis=1)[:, -2:]       # (3, 2): два самых вероятных класса в строке
np.take_along_axis(probs, topk, axis=1)                 # (3, 2): их вероятности
(topk == y_true[:, np.newaxis]).any(axis=1).mean()      # 0.667 — top-2 accuracy
```

Результат совпадает с `sklearn.metrics.top_k_accuracy_score`. Сбор вероятностей истинного класса для
cross-entropy — приём «по одному элементу из строки»:

```python
picked = probs[np.arange(len(y_true)), y_true]          # array([0.6, 0.3, 0.2])
loss = -np.log(picked).mean()                           # 1.108 — совпадает с sklearn.metrics.log_loss
```

Опасная опечатка — `probs[:, y_true]`: срез и массив индексов дают не три числа, а матрицу 3×3
(столбцы 1, 0, 3 целиком), и среднее по ней — правдоподобное, но неверное значение функции потерь.

## 7. `searchsorted`, `unique`, `bincount`

**`np.searchsorted`** — двоичный поиск в отсортированном массиве: возвращает позицию, в которую нужно
вставить значение, чтобы порядок сохранился.

```python
edges = np.array([18, 30, 45, 60])
np.searchsorted(edges, [15, 18, 29, 45, 72], side="right")     # array([0, 1, 1, 3, 4]) — номер интервала

cdf = np.cumsum([0.1, 0.6, 0.3])                                # array([0.1, 0.7, 1. ])
np.searchsorted(cdf, [0.05, 0.1, 0.5, 0.95], side="right")      # array([0, 1, 1, 2]) — выборка классов
```

Первый пример — разбиение признака на интервалы (биннинг), второй — выборка из дискретного распределения
по равномерным случайным числам. Поиск 100 000 значений в отсортированном массиве из миллиона занимает
3.4 мс.

**`np.unique`** возвращает отсортированные уникальные значения, а с параметрами — ещё и коды:

```python
cities = np.array(["Казань", "Москва", "Казань", "Уфа", "Москва", "Казань"])
names, codes, counts = np.unique(cities, return_inverse=True, return_counts=True)
names                   # array(['Казань', 'Москва', 'Уфа'])
codes                   # array([0, 1, 0, 2, 1, 0]) — номер уникального значения для каждого элемента
counts                  # array([3, 2, 1])
```

`codes` — это готовое кодирование категорий целыми числами (label encoding), `names[codes]` восстанавливает
исходный массив.

**`np.bincount`** считает, сколько раз встретилось каждое целое от 0 до максимума, а с `weights` —
суммирует веса. Вместе с `codes` это групповые агрегаты без pandas:

```python
revenue = np.array([10.0, 20.0, 5.0, 7.0, 3.0, 8.0])
sums = np.bincount(codes, weights=revenue)      # array([23., 23.,  7.]) — выручка по городам
sums / np.bincount(codes)                       # array([ 7.67, 11.5 ,  7.  ]) — средняя по городам
```

Матрица ошибок — тот же приём: пара «истинный класс, предсказанный класс» кодируется одним числом.

```python
y_true8 = np.array([0, 1, 2, 2, 1, 0, 2, 2])
y_pred8 = np.array([0, 2, 2, 2, 1, 1, 0, 2])
k = 3
cm = np.bincount(y_true8 * k + y_pred8, minlength=k * k).reshape(k, k)
# array([[1, 1, 0],
#        [0, 1, 1],
#        [1, 0, 3]])
recall = np.diag(cm) / cm.sum(axis=1)           # array([0.5 , 0.5 , 0.75])
```

Строки — истинные классы, столбцы — предсказанные; результат совпадает с
`sklearn.metrics.confusion_matrix`. На миллионе меток и десяти классах: 2.6 мс через `bincount`, 238 мс
циклом. Параметр `minlength` обязателен: без него классы, которых нет в данных, не попадут в результат,
и `reshape` упадёт. Ограничения `bincount`: только неотрицательные целые (метки `-1` вызовут
`ValueError`), а массив результата имеет длину «максимум + 1» — идентификаторы вида `10**9` сначала
перекодируйте через `np.unique`.

## 8. Структурированные массивы

Структурированный массив хранит в каждом элементе запись из полей разных типов:

```python
dt = np.dtype([("user_id", np.int32), ("score", np.float32), ("label", np.uint8)])
recs = np.array([(10, 0.9, 1), (11, 0.2, 0), (12, 0.7, 1), (13, 0.4, 0)], dtype=dt)

recs.dtype.itemsize, recs.nbytes                # (9, 36): 4 + 4 + 1 байт на запись
recs["score"].mean()                            # 0.55 — поле целиком
recs[recs["label"] == 1]["user_id"]             # array([10, 12], dtype=int32)
recs[np.argsort(recs["score"])]["user_id"]      # array([11, 13, 12, 10], dtype=int32)
```

Поле `recs["score"]` — это view с шагом 9 байт (`strides == (9,)`): данные одного поля не лежат подряд.
За это платят скоростью: сумма поля в массиве из двух миллионов записей — 1.26 мс, сумма обычного массива
`float32` той же длины — 0.45 мс. Сортировка через `np.sort(recs, order="score")` на том же массиве
заняла 3.9 с, через `recs[np.argsort(recs["score"])]` — 91 мс: параметр `order` сравнивает записи
медленным универсальным способом, не используйте его на больших данных.

| Задача | Что выбрать |
|---|---|
| Прочитать бинарный файл или сетевой пакет с записями фиксированного формата (`np.fromfile`, `np.frombuffer`, `np.memmap`) | структурированный массив |
| Обмен данными с кодом на C/C++, передача записей в Numba (урок 2.2.3) | структурированный массив |
| Компактное хранение сотен миллионов однотипных записей | структурированный массив |
| Анализ: группировки, объединения, пропуски, строки, даты | pandas |
| Числовые вычисления над признаками | обычные массивы — по одному на признак или матрица |

Переход между форматами — одна строка: `pd.DataFrame(recs)` сохраняет типы полей, `df.to_records(index=False)`
возвращает структурированный массив. Практическое правило: структурированный массив — формат на границе
системы (файл, сеть, C-код), а внутри пайплайна данные живут в DataFrame или в обычных массивах.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `The truth value of an array ... is ambiguous` | `and`/`or` вместо `&` и `\|` или условия без скобок | `(a > 0) & (a < 10)` |
| Присваивание выполнилось, массив не изменился | цепочка `a[mask][0] = ...` пишет во временную копию | одно присваивание: `a[idx_rows, idx_cols] = ...` |
| Изменились исходные данные после обработки батча | батч взят срезом и изменён на месте | `.copy()` или операции, создающие новый массив |
| Вместо подматрицы получился вектор | `X[[0, 2], [1, 4]]` выбирает пары элементов | `X[np.ix_(rows, cols)]` |
| Функция потерь правдоподобна, но неверна | `probs[:, y]` вместо `probs[np.arange(n), y]` | проверять форму: должен получиться вектор `(n,)` |
| Счётчики или градиенты занижены | `a[idx] += v` с повторяющимися индексами | `np.add.at` или `np.bincount` |
| `RuntimeWarning` в `np.where`, хотя условие защищает от деления на ноль | обе ветви вычисляются полностью | `np.divide(..., out=..., where=...)` |
| `cannot reshape array` при сборке матрицы ошибок | `bincount` без `minlength` | `minlength=k * k` |
| Top-k возвращает правильные элементы в странном порядке | `argpartition` не упорядочивает результат | досортировать k найденных элементов |
| `X` и `y` «разъехались» после перемешивания | массивы перемешаны независимо | одна перестановка индексов для обоих массивов |
