## Зачем это нужно

Большая часть признаков в табличных задачах — это агрегаты по группам: средний чек клиента, доля товара
в выручке магазина, продажи за прошлую неделю, отклонение цены от средней по категории. Модель градиентного
бустинга сама такие признаки не построит: ей нужно дать готовый столбец. Поэтому скорость и правильность
работы с `groupby` напрямую определяют скорость ваших экспериментов.

Вторая причина — утечки данных. Признак «средние продажи товара», посчитанный по всей истории, включает
будущее относительно каждой строки. На валидации модель выглядит отлично, в продакшене — нет. В этом уроке
вы увидите, как одной строкой отличается корректный признак от признака с утечкой.

## 2. Агрегация: `agg`

**Именованная агрегация** — основной способ посчитать несколько показателей сразу:

```python
summary = sales.groupby(["city", "category"]).agg(
    revenue=("revenue", "sum"),
    units=("units", "sum"),
    avg_price=("price", "mean"),
    promo_share=("promo", "mean"),
    days=("date", "nunique"),
)
summary.head(6).round(2)
```

```
                                 revenue    units  avg_price  promo_share  days
city        category
Владивосток Аксессуары        38390310.0  10903.0    3613.25         0.08   731
            Для дома          20140940.0   4021.0    6911.75         0.08   731
            Товары в дорогу   11635640.0   4818.0    2392.34         0.08   731
            Электроника      191638740.0   3676.0   51952.36         0.09   731
Казань      Аксессуары       107257430.0  30837.0    3616.51         0.08   731
            Для дома          57207040.0  11411.0    6909.36         0.08   731
```

Синтаксис: `имя_результата=("исходный_столбец", "функция")`. Среднее по булеву столбцу `promo` — это доля
строк со значением `True`: приём, который пригодится постоянно.

Что важно знать о пропусках:

| Функция | Поведение |
|---|---|
| `sum`, `mean`, `min`, `max`, `std` | пропуски игнорируются |
| `count` | число непустых значений |
| `size` | число строк в группе, включая пропуски |
| `nunique` | число уникальных значений без учёта пропусков |

Разница между `count` и `size` — быстрый способ найти группы с пропусками.

Параметры `groupby`, о которых стоит помнить:

| Параметр | Что делает |
|---|---|
| `as_index=False` | ключи группировки остаются обычными столбцами, а не уходят в индекс |
| `dropna=False` | строки с пропуском в ключе образуют отдельную группу, а не отбрасываются молча |
| `observed=False` | для категориальных ключей показывать и те категории, которых нет в данных |
| `sort=False` | не сортировать группы по ключу — немного быстрее |

Группировка по времени делается через `pd.Grouper`:

```python
monthly = sales.groupby([pd.Grouper(key="date", freq="ME"), "city"])["revenue"].sum()
```

`"ME"` — конец месяца (month end). Подробно работу с датами разберём в уроке 2.1.3.

## 3. `transform`: агрегат, развёрнутый обратно на строки

`agg` сжимает группу в одну строку. `transform` считает то же самое, но возвращает результат **той же длины,
что и исходная таблица**: каждой строке — значение её группы. Это главный инструмент построения признаков.

```python
sales["store_day_revenue"] = sales.groupby(["store_id", "date"])["revenue"].transform("sum")
sales["share_in_store_day"] = sales["revenue"] / sales["store_day_revenue"]
```

Теперь у каждой строки есть доля товара в дневной выручке магазина. Без `transform` пришлось бы
агрегировать и затем присоединять результат через `merge` — длиннее и медленнее.

Операции, которые сами по себе работают «внутри группы» и возвращают столбец исходной длины:

```python
daily = sales.groupby(["store_id", "date"], as_index=False)["revenue"].sum()

daily["cum_revenue"] = daily.groupby("store_id")["revenue"].cumsum()          # накопленная сумма
daily["prev_day"] = daily.groupby("store_id")["revenue"].shift(1)             # значение предыдущего дня
daily["rank_in_day"] = daily.groupby("date")["revenue"].rank(ascending=False, method="first").astype(int)
```

```
  store_id       date    revenue  cum_revenue   prev_day  rank_in_day
0      S01 2023-01-01  1023290.0    1023290.0        NaN            2
1      S01 2023-01-02   944280.0    1967570.0  1023290.0            1
2      S01 2023-01-03   699730.0    2667300.0   944280.0            3
```

`shift` и `cumsum` опираются на порядок строк: перед ними таблица должна быть отсортирована по времени
внутри группы.

## 4. `filter` и «топ-N в группе»

`filter` оставляет или отбрасывает группы целиком:

```python
big = sales.groupby("store_id").filter(lambda g: g["revenue"].sum() > 400_000_000)
big["store_id"].unique()    # ['S01', 'S02', 'S04', 'S06']
```

Типичное применение в ML — убрать редкие группы: товары с историей меньше 30 дней, пользователей с одним
заказом.

Топ-N строк в каждой группе — сортировка и `head`:

```python
by_product = sales.groupby(["city", "product"], as_index=False)["revenue"].sum()
top2 = by_product.sort_values("revenue", ascending=False).groupby("city").head(2)
```

## 5. Какой метод выбрать

| Нужно получить | Метод | Размер результата |
|---|---|---|
| Сводку по группам | `agg` | одна строка на группу |
| Признак для каждой строки на основе её группы | `transform` | как исходная таблица |
| Подмножество групп целиком | `filter` | строки отобранных групп |
| Накопления, сдвиги, ранги внутри группы | `cumsum`, `shift`, `rank`, `diff` | как исходная таблица |
| Что-то, чего нельзя выразить методами выше | `apply` | зависит от функции |

`apply` — последнее средство: он вызывает Python-функцию для каждой группы и поэтому медленный (раздел 9).

## 6. Признаки без утечки

Средние продажи товара в магазине — естественный признак. Два способа его посчитать:

```python
sales = sales.sort_values(["store_id", "product", "date"], ignore_index=True)
grouped = sales.groupby(["store_id", "product"])["units"]

sales["units_mean_all"] = grouped.transform("mean")                                     # с утечкой
sales["units_mean_past"] = grouped.transform(lambda s: s.shift(1).expanding().mean())  # без утечки
```

```
           date  units  units_mean_all  units_mean_past
2924 2023-01-01   22.0           16.36              NaN
2925 2023-01-02   14.0           16.36             22.0
2926 2023-01-03    NaN           16.36             18.0
2927 2023-01-04   13.0           16.36             18.0
```

`units_mean_all` для строки от 1 января 2023 года уже «знает» продажи за весь 2024 год. В момент прогноза
этой информации не существует. `units_mean_past` использует только прошлое: `shift(1)` исключает текущий
день, `expanding().mean()` усредняет всё, что было раньше. У первой строки группы прошлого нет — там
пропуск, и это честно.

Правило: **любой агрегат, который станет признаком, должен считаться только по данным, доступным на момент
прогноза**. К этой теме вернёмся в уроках 2.3.1 и 2.3.2.

## 7. MultiIndex

Группировка по двум ключам вернула таблицу с двухуровневым индексом. Это не усложнение ради усложнения:
MultiIndex — способ хранить многомерные данные в двумерной таблице.

```python
summary.index.names          # ['city', 'category']
```

**Выборка:**

```python
summary.loc["Москва"]                                # все категории одного города
summary.loc[("Москва", "Электроника")]               # одна строка; ключ — кортеж
summary.xs("Электроника", level="category")          # срез по второму уровню

idx = pd.IndexSlice
summary.loc[idx[["Казань", "Москва"], ["Аксессуары", "Электроника"]], "revenue"]
```

```
city    category
Казань  Аксессуары     1.072574e+08
        Электроника    5.325843e+08
Москва  Аксессуары     2.311620e+08
        Электроника    1.158021e+09
Name: revenue, dtype: float64
```

`pd.IndexSlice` позволяет задавать условия по каждому уровню отдельно; `idx[:, "Электроника"]` означает
«любой город, категория Электроника».

**Срезы диапазоном требуют отсортированного индекса.** На перемешанной таблице
`summary.loc[idx["Казань":"Москва", :]]` завершится ошибкой `UnsortedIndexError`. После любых операций,
меняющих порядок строк, вызывайте `sort_index()`.

**Перестройка:**

```python
wide = summary["revenue"].unstack("category")        # уровень индекса -> столбцы
(wide / 1e6).round(1)
```

```
category     Аксессуары  Для дома  Товары в дорогу  Электроника
city
Владивосток        38.4      20.1             11.6        191.6
Казань            107.3      57.2             33.0        532.6
Москва            231.2     126.0             71.4       1158.0
Новосибирск       119.1      65.5             36.2        587.6
```

| Операция | Что делает |
|---|---|
| `unstack(level)` | переносит уровень индекса в столбцы (длинный формат → широкий) |
| `stack()` | переносит столбцы в уровень индекса (широкий → длинный) |
| `swaplevel()` | меняет уровни местами; после него нужен `sort_index()` |
| `groupby(level="city")` | агрегирует по уровню индекса |
| `reset_index()` | превращает уровни индекса в обычные столбцы |

**MultiIndex в столбцах** появляется, когда к нескольким столбцам применяют несколько функций:

```python
multi = sales.groupby("city")[["revenue", "units"]].agg(["sum", "mean"])
multi.columns.tolist()
# [('revenue', 'sum'), ('revenue', 'mean'), ('units', 'sum'), ('units', 'mean')]

multi.columns = ["_".join(col) for col in multi.columns]     # revenue_sum, revenue_mean, ...
```

Перед подачей таблицы в модель столбцы всегда «сплющивают» в обычные имена: библиотеки ML не работают
с кортежами в названиях признаков. Именованная агрегация из раздела 2 даёт плоские имена сразу.

## 8. Сводные таблицы

`pivot_table` — это `groupby` + `unstack` в одном вызове:

```python
pt = sales.pivot_table(
    index="city", columns="category", values="revenue", aggfunc="sum", margins=True, margins_name="Итого"
)
(pt / 1e6).round(1)
```

```
category     Аксессуары  Для дома  Товары в дорогу  Электроника   Итого
city
Владивосток        38.4      20.1             11.6        191.6   261.8
Казань            107.3      57.2             33.0        532.6   730.1
Москва            231.2     126.0             71.4       1158.0  1586.5
Новосибирск       119.1      65.5             36.2        587.6   808.5
Итого             495.9     268.8            152.3       2469.9  3386.9
```

Сравнение двух лет — частая задача аналитики:

```python
sales["year"] = sales["date"].dt.year
by_year = sales.pivot_table(index=["city", "category"], columns="year", values="revenue", aggfunc="sum")
growth = (by_year[2024] / by_year[2023] - 1).round(3)
```

```
city         category
Владивосток  Аксессуары         0.211
             Для дома           0.236
             Товары в дорогу    0.275
             Электроника        0.293
```

**`pivot` против `pivot_table`.** `pivot` только меняет форму таблицы и требует, чтобы каждой паре
«строка — столбец» соответствовало одно значение. Если значений несколько, он падает:

```python
sales.pivot(index="date", columns="city", values="revenue")
# ValueError: Index contains duplicate entries, cannot reshape
```

`pivot_table` в этой ситуации агрегирует. Отсюда правило: если дубликатов быть не должно, используйте
`pivot` — ошибка сообщит о проблеме в данных, а `pivot_table` молча усреднил бы дубликаты.

**`melt`** — обратная операция, из широкого формата в длинный:

```python
daily_city = sales.groupby(["date", "city"], as_index=False)["revenue"].sum()
wide = daily_city.pivot(index="date", columns="city", values="revenue")
long = wide.reset_index().melt(id_vars="date", var_name="city", value_name="revenue")
```

Длинный формат удобен для группировок и для моделей, широкий — для графиков и корреляций между рядами.

**`crosstab`** считает частоты сочетаний двух признаков; `normalize="index"` переводит их в доли по строкам:

```python
pd.crosstab(sales["category"], sales["promo"], normalize="index").round(3)
```

```
promo            False  True
category
Аксессуары       0.922  0.078
Для дома         0.920  0.080
Товары в дорогу  0.917  0.083
Электроника      0.924  0.076
```

Таблица сопряжённости «признак × целевая переменная» — первый шаг при знакомстве с категориальным признаком.

## 9. Производительность

Pandas быстр, когда вычисления выполняет скомпилированный код, и медленен, когда для каждой группы
вызывается Python-функция. Замеры на данных урока (ваши цифры будут отличаться, порядок — нет):

| Операция | Время | Во сколько раз медленнее |
|---|---|---|
| `g["revenue"].sum()` | 0.57 мс | — |
| `g["revenue"].agg(lambda s: s.sum())` | 2.06 мс | 3.6 |
| `g.apply(lambda d: d["revenue"].sum())` | 19.5 мс | 34 |
| `groupby("date")["revenue"].transform("mean")` | 1.32 мс | — |
| `groupby("date")["revenue"].transform(lambda s: s.mean())` | 47.9 мс | 36 |

Здесь `g = sales.groupby(["store_id", "product"])`. Разница между строкой `"mean"` и `lambda s: s.mean()` —
в 36 раз, хотя результат одинаковый. На 70 тысячах строк это миллисекунды, на 70 миллионах — минуты против
часов.

Практические выводы:

1. Передавайте имена функций строками: `"sum"`, `"mean"`, `"std"`, `"nunique"`, `"first"`, `"last"`.
2. Сложный агрегат разложите на простые: средневзвешенную цену считают как `sum(price * units) / sum(units)`
   через два встроенных `sum`, а не через `apply`.
3. `apply` и `lambda` оставляйте для случаев, когда встроенных средств действительно нет.

Об экономии памяти и категориальных типах — следующий урок.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| После `groupby` пропали строки | в ключе группировки были пропуски | `groupby(..., dropna=False)` или заполнить пропуски заранее |
| `KeyError` при обращении к столбцу после `groupby` | ключ ушёл в индекс | `as_index=False` или `reset_index()` |
| `UnsortedIndexError` при срезе MultiIndex | индекс не отсортирован | `sort_index()` |
| `ValueError: Index contains duplicate entries` в `pivot` | в данных есть дубликаты по паре «строка — столбец» | разобраться с дубликатами или агрегировать через `pivot_table` |
| Модель требует строковые имена признаков | в столбцах остался MultiIndex | «сплющить» имена или использовать именованную агрегацию |
| Отличная метрика на валидации, плохая в продакшене | агрегаты посчитаны по всей истории, включая будущее | `shift(1)` перед накопительными и скользящими функциями |
| `shift` и `cumsum` дают бессмысленные значения | таблица не отсортирована по времени внутри группы | `sort_values` перед группировкой |
| Группировка работает минутами | Python-функция в `apply` или `transform` | заменить на встроенные агрегаты |
| Среднее отличается от ожидаемого | пропуски молча исключены из расчёта | сравнить `count` и `size` по группам |

2. **Средневзвешенная цена.** Посчитайте по каждой категории среднюю цену, взвешенную по числу проданных
   единиц, двумя способами: через `apply` и через встроенные агрегаты. Убедитесь, что результаты совпадают,
   и сравните время через `%timeit`.
3. **Признаки.** Добавьте в таблицу столбцы:
   - доля товара в выручке своей категории в этом магазине за этот день;
   - ранг магазина по выручке за день среди магазинов своего города;
   - продажи того же товара в том же магазине 7 дней назад;
   - среднее число проданных единиц товара в магазине за все предыдущие дни (без утечки).
4. **Сводная таблица.** Постройте таблицу «день недели × категория» со средней выручкой и итогами. В какой
   день недели продажи максимальны? Отличается ли ответ по категориям?
5. **Эффект промо.** Для каждого товара посчитайте, во сколько раз среднее число проданных единиц в дни
   с промо выше, чем в дни без промо. Результат — таблица с индексом `product` и столбцом `promo_lift`,
   отсортированная по убыванию.
6. **Рост.** Найдите три пары «город — товар» с наибольшим ростом выручки в 2024 году относительно 2023-го.

**Критерии приёмки:**

- [ ] ни в одном задании не используется цикл `for` по строкам или группам;
- [ ] в задании 2 оба способа дают одинаковый результат (`pd.testing.assert_series_equal` или `np.allclose`);
- [ ] признак из последнего пункта задания 3 для первой строки каждой пары «магазин — товар» равен `NaN`;
- [ ] в итоговой таблице с признаками нет MultiIndex ни в строках, ни в столбцах;
- [ ] ноутбук выполняется целиком сверху вниз (Restart Kernel and Run All Cells).

Подсказка к заданию 5: в генераторе данных заложен эффект промо 1.8. Если у вас получились значения около
этого числа — расчёт верен.
