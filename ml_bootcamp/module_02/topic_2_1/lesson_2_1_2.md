## Зачем это нужно

Pandas держит таблицу в оперативной памяти целиком, а многие операции (`merge`, `groupby`, `sort_values`)
временно требуют ещё столько же или больше. Практическое правило: для комфортной работы нужно в 3–5 раз
больше памяти, чем занимает сама таблица. Таблица на 4 ГБ на ноутбуке с 16 ГБ — уже на грани.

Когда память кончается, процесс не выдаёт понятной ошибки: ядро Jupyter просто «умирает», а в Docker
контейнер завершается без сообщения. Обычная реакция — «нужна машина побольше». Инженерная — сначала
посмотреть, на что память расходуется: в большинстве случаев таблицу можно уменьшить в 5–10 раз за десять
минут работы.

## 2. Категориальный тип

Столбец `city` хранит 70 тысяч раз одно из четырёх слов. Тип `category` хранит слова один раз, а в столбце —
номера:

```python
for column in ["store_id", "city", "category", "product"]:
    sales[column] = sales[column].astype("category")
```

Каждый из четырёх столбцов теперь занимает 0.07 МБ, таблица — 2.6 МБ вместо 8.36. Попутно ускоряются
`groupby` и сравнения: операции идут над целыми числами, а не над строками.

Когда `category` **не** помогает: если почти все значения уникальны (идентификаторы заказов, тексты).
Словарь получается размером с сам столбец, и память только растёт — на 70 тысячах уникальных строк
1.47 МБ против 1.19 МБ.

Подводные камни:

| Ситуация | Что происходит | Что делать |
|---|---|---|
| Присвоение значения, которого нет среди категорий | `TypeError: Cannot setitem on a Categorical with a new category` | сначала `cat.add_categories([...])` |
| `concat` или `merge` таблиц с разными наборами категорий | столбец молча превращается обратно в строки | привести обе таблицы к общему `CategoricalDtype` |
| `groupby` по категориальному ключу с `observed=False` | в результате появляются пустые группы для отсутствующих категорий | оставить значение по умолчанию `observed=True` |
| Категории train и test закодированы независимо | одинаковым значениям соответствуют разные номера | задавать один `CategoricalDtype` для всех частей данных |

Последняя строка — источник реальных ошибок в моделях. Общий тип задаётся явно:

```python
city_type = pd.CategoricalDtype(categories=["Владивосток", "Казань", "Москва", "Новосибирск"])
train["city"] = train["city"].astype(city_type)
test["city"] = test["city"].astype(city_type)
```

## 3. Числовые типы

| Тип | Диапазон | Байт |
|---|---|---|
| `int8` / `uint8` | −128 … 127 / 0 … 255 | 1 |
| `int16` / `uint16` | −32 768 … 32 767 / 0 … 65 535 | 2 |
| `int32` / `uint32` | около ±2.1 млрд / 0 … 4.3 млрд | 4 |
| `int64` | около ±9.2 × 10¹⁸ | 8 |
| `float32` | 6–7 значащих цифр | 4 |
| `float64` | 15–16 значащих цифр | 8 |

```python
sales["price"] = pd.to_numeric(sales["price"], downcast="unsigned")     # int64 -> uint32
sales["units"] = sales["units"].astype("Int16")                         # float64 -> Int16
sales["revenue"] = pd.to_numeric(sales["revenue"], downcast="float")    # float64 -> float32
```

Таблица теперь занимает **1.69 МБ вместо 8.36 — в 5 раз меньше** (и в 14.5 раза меньше, чем со строками
Python).

**`Int16` с заглавной буквы** — тип pandas, который умеет хранить пропуски в целочисленном столбце.
Обычный `int16` пропусков не допускает; именно поэтому столбец `units` с пропусками изначально был `float64`.
Перед передачей в библиотеку, которая ожидает массив NumPy, такой столбец преобразуют явно:

```python
units = sales["units"].to_numpy(dtype="float32", na_value=np.nan)
```

### Чем приходится платить

**Переполнение целых.** NumPy не проверяет выход за границы типа:

```python
np.array([127], dtype="int8") + np.array([1], dtype="int8")     # array([-128], dtype=int8)
```

Ошибки нет, значение неверное. Тип выбирают с запасом на будущие данные и на результаты операций:
сумма столбца `int16` легко выходит за 32 767.

**Точность `float32`.** У `float32` около семи значащих цифр. Отдельные значения выручки сохранились точно,
но сумма столбца — уже нет:

```python
sales["revenue"].sum()                      # 3386869504.0 — float32
sales["revenue"].astype("float64").sum()    # 3386869320.0 — float64
```

Расхождение 184 рубля на 3.4 миллиарда. Для признаков модели это несущественно: нейросети и градиентный
бустинг сами работают с `float32`. Для денежных итогов в отчёте — недопустимо.

Практическое правило: **признаки для модели — `float32`, деньги и идентификаторы — без потери точности**
(целые копейки в `int64`; идентификаторы — целые или строки, но не `float`).

## 4. Типы при чтении

Преобразовывать типы после загрузки — значит сначала загрузить «тяжёлую» версию. Если файл едва помещается
в память, типы задают при чтении:

```python
dtypes = {
    "store_id": "category",
    "city": "category",
    "category": "category",
    "product": "category",
    "price": "uint32",
    "units": "Int16",
    "revenue": "float32",
}
sales = pd.read_csv("data/sales.csv", dtype=dtypes, parse_dates=["date"])
```

| Способ чтения `sales.csv` | Память |
|---|---|
| `pd.read_csv(path)` | 9.03 МБ |
| с `dtype=` и `parse_dates=` | 1.69 МБ |
| только три столбца (`usecols=`) с типами | 0.91 МБ |

Обратите внимание на первую строку: без `parse_dates` столбец `date` читается как строки. CSV не хранит
типов — при каждом чтении pandas угадывает их заново. Самый дешёвый способ сэкономить память — не читать
столбцы, которые не нужны: параметр `usecols`.

## 5. Чтение по частям

Файл, который не помещается в память целиком, обрабатывают кусками:

```python
total = None
for chunk in pd.read_csv("data/sales.csv", usecols=["city", "revenue"], dtype={"city": "category"}, chunksize=10_000):
    part = chunk.groupby("city", observed=True)["revenue"].sum()
    total = part if total is None else total.add(part, fill_value=0)
```

`chunksize` превращает `read_csv` в итератор: в памяти одновременно находится только один кусок из
10 000 строк. Результат совпадает с расчётом по всей таблице.

Схема одна и та же для любых задач: **обработать кусок → получить небольшой промежуточный результат →
объединить результаты**. Так считаются суммы, количества, минимумы, максимумы, гистограммы. Не всё
раскладывается так просто:

| Задача | Как считать по частям |
|---|---|
| Сумма, количество, минимум, максимум | объединять напрямую |
| Среднее | хранить сумму и количество, делить в конце |
| Дисперсия | хранить количество, сумму и сумму квадратов |
| Число уникальных значений | объединять множества значений (или приближённые алгоритмы) |
| Медиана, квантили | точно — только с полными данными; приближённо — по выборке |
| Сортировка, `merge` больших таблиц | нужны другие инструменты: DuckDB, Polars, Dask, Spark |

В реальных данных значения ключа могут не попасть в отдельный кусок, поэтому объединять надо через
`add(..., fill_value=0)`, а не простым сложением: иначе отсутствующая в куске группа превратит итог в `NaN`.

## 6. Parquet вместо CSV

CSV — текст: нет типов, нет сжатия, чтобы прочитать один столбец, нужно разобрать весь файл. Parquet —
колоночный бинарный формат, стандарт для аналитических данных.

```python
sales.to_parquet("data/sales.parquet", index=False)
```

| | CSV | Parquet |
|---|---|---|
| Размер файла | 6.42 МБ | 0.18 МБ |
| Полное чтение | 28 мс | 5 мс |
| Чтение трёх столбцов | нужно разобрать весь файл | 3.3 мс |
| Типы после чтения | угадываются заново | сохраняются, включая `category` и `Int16` |

Сжатие в 35 раз — особенность синтетических данных с повторяющимися значениями; на реальных таблицах
обычно получается в 3–10 раз.

Parquet умеет читать не только нужные столбцы, но и нужные строки:

```python
part = pd.read_parquet(
    "data/sales.parquet",
    columns=["date", "store_id", "revenue"],
    filters=[("city", "==", "Казань"), ("date", ">=", pd.Timestamp("2024-01-01"))],
)
```

Файл хранит статистику по блокам строк, и блоки, заведомо не подходящие под условие, пропускаются без чтения.

Правило курса: **CSV — только для обмена с внешним миром. Внутри проекта данные хранятся в Parquet.**

## 7. Разреженные данные

Разреженная (sparse) структура хранит только значения, отличные от «фонового» — обычно нуля. Основной
источник таких данных в ML — one-hot кодирование и мешок слов для текстов.

```python
from sklearn.preprocessing import OneHotEncoder

rng = np.random.default_rng(0)
sales["sku"] = rng.integers(0, 5000, len(sales))      # признак с 5000 разных значений

X = OneHotEncoder().fit_transform(sales[["sku"]])
X.shape, X.nnz                                        # (70176, 5000), 70176
```

В матрице 351 миллион ячеек и только 70 176 ненулевых — плотность 0.02 %.

| Представление | Память |
|---|---|
| Плотная матрица `float64` | 2 807 МБ |
| Плотная матрица `bool` | 351 МБ |
| Разреженная матрица SciPy (CSR) | 1.12 МБ |

`OneHotEncoder` возвращает разреженную матрицу по умолчанию, а линейные модели и градиентный бустинг
принимают её напрямую: `Ridge().fit(X, y)` на этой матрице обучается за 8 мс. Плотный вариант на
большинстве ноутбуков не поместится в память вовсе.

В pandas есть собственные разреженные столбцы:

```python
dummies = pd.get_dummies(sales["sku"], prefix="sku", sparse=True)   # 0.35 МБ
dummies.sparse.density                                              # 0.0002
matrix = dummies.sparse.to_coo().tocsr()                            # в формат SciPy для моделей
```

**Разреженность выгодна не всегда.** One-hot кодирование четырёх столбцов наших данных даёт 28 признаков
с плотностью 14 %:

| Представление (28 столбцов) | Память | Обучение `Ridge` |
|---|---|---|
| Плотная матрица `bool` | 1.97 МБ | — |
| Плотная матрица `float64` | 15.7 МБ | 16 мс |
| Разреженная CSR `float64` | 3.65 МБ | 63 мс |

Разреженная матрица хранит для каждого ненулевого значения ещё и его координаты, а операции над ней
сложнее. При плотности 14 % она занимает больше памяти, чем плотная `bool`, и обучение на ней вчетверо
медленнее. Ориентир: разреженное представление оправдано при плотности ниже нескольких процентов.

## 8. Копии данных

В pandas 3 действует правило copy-on-write: любая выборка ведёт себя как независимая копия, но физически
данные копируются только в момент изменения.

```python
subset = sales[sales["price"] > 3000]     # копирования пока нет
subset["price"] = 0                       # копия создаётся здесь; sales не меняется
```

Следствие: «цепочечное» присваивание не работает — pandas выдаёт предупреждение `ChainedAssignmentError`,
а исходная таблица остаётся прежней:

```python
sales[sales["price"] > 3000]["promo"] = True        # не работает
sales.loc[sales["price"] > 3000, "promo"] = True    # правильно
```

Как не плодить копии большой таблицы:

- не создавайте промежуточные переменные `df2`, `df3`, `df_clean` — каждая удерживает память, пока существует;
- собирайте преобразования в цепочку методов или в функцию: промежуточные результаты освобождаются сами;
- ненужную большую таблицу удаляйте явно: `del raw`;
- `inplace=True` память не экономит — внутри всё равно создаётся новый объект.

## Порядок действий, когда не хватает памяти

1. Измерить: `memory_usage(deep=True)` по столбцам.
2. Не читать лишнее: `usecols` или `columns`, фильтры Parquet.
3. Строки с малым числом уникальных значений — в `category`.
4. Числа — в минимально достаточный тип; признаки — в `float32`.
5. Перевести хранение из CSV в Parquet.
6. Обрабатывать по частям, если нужны только агрегаты.
7. Если и этого мало — другой инструмент (DuckDB, Polars, Spark) или машина побольше.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Ядро Jupyter перезапускается без сообщения | закончилась память | измерить таблицу, пройти по списку выше |
| После уменьшения типа появились отрицательные или странные значения | переполнение целого типа | проверять `min` и `max` столбца перед преобразованием, брать тип с запасом |
| Итоговые суммы расходятся с отчётом в младших разрядах | суммирование в `float32` | деньги считать в `float64` или в целых копейках |
| `category` увеличил память | почти все значения уникальны | оставить строковый тип |
| После `concat` столбец снова строковый | у таблиц разные наборы категорий | общий `CategoricalDtype` |
| `ValueError` при `astype("int32")` | в столбце есть пропуски | использовать `Int32` или сначала обработать пропуски |
| Итог по частям содержит `NaN` | в одном из кусков не было какой-то группы | `add(..., fill_value=0)` |
| После чтения CSV даты оказались строками | CSV не хранит типы | `parse_dates` или переход на Parquet |
| Присваивание не изменило таблицу | цепочечное присваивание | `df.loc[условие, столбец] = значение` |
| Модель обучается на one-hot признаках очень долго или падает по памяти | плотная матрица с тысячами столбцов | разреженная матрица (`OneHotEncoder` возвращает её по умолчанию) |
