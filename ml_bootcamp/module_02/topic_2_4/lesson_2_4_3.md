## Цели урока

После урока вы сможете:

- за минуту получить обзорный отчёт по незнакомой таблице и знать, что в нём смотреть в первую очередь;
- читать предупреждения отчёта и понимать, какие из них важны для модели, а какие — шум;
- настраивать отчёт под размер данных и отключать дорогие расчёты;
- сравнивать две выборки (train и test) и находить сдвиг данных;
- объяснить, чего автоматический отчёт не увидит никогда.

## Зачем это нужно

Знакомство с новой таблицей начинается с одних и тех же действий: типы столбцов, пропуски, дубликаты,
распределения, корреляции. На таблице из 50 столбцов это сотня однообразных ячеек в ноутбуке — и именно
на однообразной работе пропускают важное: константный столбец, идентификатор в роли признака, признак
с 97 % пропусков. Генератор отчётов делает эту рутину за секунды и не устаёт к сороковому столбцу.

Важно понимать, чем отчёт не является. Он не знает, что означают ваши данные, какая переменная целевая
и что будет известно в момент прогноза. Отчёт — это список мест, куда стоит посмотреть, а не анализ.

## 1. Название, установка и отдельное окружение

**О названии.** В плане курса урок называется по историческому имени библиотеки. Она переименовывалась
дважды, а программный интерфейс при этом почти не менялся:

| Пакет | Импорт | Состояние |
|---|---|---|
| `pandas-profiling` | `pandas_profiling` | старое имя, давно не обновляется |
| `ydata-profiling` | `ydata_profiling` | при импорте версии 4.18.4 — предупреждение: пакет больше не получит обновлений |
| `fg-data-profiling` | `data_profiling` | текущее имя; на него ссылается предупреждение из `ydata-profiling` |

В уроке используется `fg-data-profiling`. В статьях и чужих проектах вы встретите все три имени — код
отличается только строкой импорта.

**Об окружении.** Основное окружение курса работает на pandas 3.x, а библиотека требует pandas младше 3.0.
Попытка добавить её в проект курса заканчивается так:

```

      And because your project depends on pandas>=3, we can conclude that your

```

Понижать pandas во всём проекте ради одного инструмента не нужно. Нормальная практика — отдельное
окружение под инструмент с более старыми зависимостями:

```bash

```

Примеры урока проверены в таком окружении: Python 3.12.13, fg-data-profiling 4.20.0, pandas 2.3.3,
numpy 2.5.4. Тот же код с импортом `ydata_profiling` проверен на ydata-profiling 4.18.4 (pandas 2.3.3,

В примерах данные создаются на месте: скопируйте [`sales_data.py`](../topic_2_1/sales_data.py) в папку
`profiling` (файл работает и на pandas 2).

## 2. Первый отчёт

К продажам добавим несколько столбцов с типичными проблемами — чтобы увидеть, как отчёт на них реагирует:

```python
import numpy as np
import pandas as pd
from data_profiling import ProfileReport
from sales_data import make_sales

sales = make_sales()
rng = np.random.default_rng(0)

df = sales.copy()
df["currency"] = "RUB"                                                       # константа
df["price_usd"] = (df["price"] / 90).round(2)                                # тот же признак в долларах
df["cashier"] = "K" + pd.Series(rng.integers(1, 301, len(df))).astype(str).str.zfill(3)    # 300 значений
df["comment"] = pd.Series("уточнить", index=df.index).where(rng.random(len(df)) < 0.03)    # почти пусто
df = pd.concat([df, df.sample(300, random_state=0)], ignore_index=True)      # 300 строк-дубликатов

profile = ProfileReport(df, title="Продажи: первичный обзор")
profile.to_file("reports/sales_full.html")
```

Таблица из 70 476 строк и 13 столбцов обработана за 7 секунд, файл отчёта — 2.3 МБ. Отчёт
самодостаточен: стили и скрипты встроены, он открывается в браузере без сети. В ноутбуке тот же отчёт
показывает `profile.to_notebook_iframe()`.

Разделы отчёта:

| Раздел | Что в нём | На что смотреть |
|---|---|---|
| Overview | число строк и столбцов, пропущенных ячеек, дубликатов, типы столбцов | сходится ли размер с ожидаемым; вкладка **Alerts** |
| Variables | по каждому столбцу: число уникальных значений, пропуски, статистики, гистограмма, частые и крайние значения | тип, который определил отчёт; минимум и максимум; хвосты |
| Interactions | точечные графики для пар числовых столбцов | нелинейные связи, группы точек |
| Correlations | тепловая карта связей между столбцами | дублирующие друг друга признаки |
| Missing values | количество и взаимное расположение пропусков | пропадают ли столбцы вместе |
| Sample | первые и последние строки таблицы | как данные выглядят «вживую» |
| Duplicate rows | самые частые полностью совпадающие строки | случайные дубли или законные повторы |

## 3. Предупреждения (alerts)

Вкладка Alerts — главное место отчёта. Те же предупреждения доступны из кода:

```python
description = profile.get_description()
for alert in description.alerts:
    print(alert)
```

```
[currency] has a constant value
[comment] has a constant value
Dataset has 300 (0.4%) duplicate rows
[category] is highly overall correlated with [price] and 2 other fields
[city] is highly overall correlated with [store_id]
[price] is highly overall correlated with [category] and 3 other fields
[price_usd] is highly overall correlated with [category] and 3 other fields
[product] is highly overall correlated with [category] and 2 other fields
[revenue] is highly overall correlated with [price] and 1 other fields
[store_id] is highly overall correlated with [city]
[promo] is highly imbalanced (0.5993766141294108)
[comment] 68399 (97.1%) missing values
[store_id] is uniformly distributed
[category] is uniformly distributed
[product] is uniformly distributed
[units] has 6230 (8.8%) zeros
[revenue] has 6230 (8.8%) zeros
```

Семнадцать предупреждений, и ценность у них разная. Что каждое значит для будущей модели:

| Тип | Смысл | Что делать |
|---|---|---|
| `CONSTANT` | в столбце одно значение | удалить: признак не несёт информации. `comment` попал сюда, потому что единственное непустое значение у него одно |
| `MISSING` | много пропусков | выяснить причину; решить, удалять столбец, заполнять или превращать сам факт пропуска в признак |
| `DUPLICATES` | есть полностью совпадающие строки | выяснить происхождение; дубли, попавшие и в train, и в test, завышают метрику |
| `HIGH_CORRELATION` | столбец сильно связан с другими | искать дубли признаков (`price` и `price_usd`) и признаки, выводимые друг из друга |
| `IMBALANCE` | одно значение категории преобладает | для целевой переменной — выбирать метрику и схему валидации с учётом дисбаланса |
| `ZEROS` | много нулей | понять природу нулей: «не продали» или «не записали»; для линейных моделей — думать о преобразовании |
| `HIGH_CARDINALITY` | у категориального столбца больше 50 значений | one-hot кодирование не подойдёт; нужны другие способы кодирования (тема 2.3) |
| `UNIQUE` | все значения различны | скорее всего, идентификатор: в признаки не брать |
| `SKEWED` | сильная асимметрия распределения | логарифмирование, устойчивые к выбросам метрики |
| `UNIFORM` | значения распределены равномерно | обычно ничего: так устроены справочные столбцы |

Три наблюдения, ради которых стоит читать предупреждения внимательно, а не по диагонали.

**Половина предупреждений — следствие устройства данных.** `city` связан с `store_id`, потому что магазин
стоит в одном городе. `category` связана с `price`, потому что товар входит в одну категорию и имеет одну
цену. `store_id` распределён равномерно, потому что в таблице есть строка на каждый магазин за каждый
день. Отчёт этого не знает — отделять находки от очевидного приходится вам.

**Отсутствие предупреждения — не отсутствие проблемы.** У выручки среднее 48 486 руб., медиана 15 940 руб.,
а 95-й процентиль — 224 970 руб.: распределение с тяжёлым правым хвостом. Предупреждения `SKEWED` нет:
порог по умолчанию — коэффициент асимметрии 20, а здесь 3.4. Пропуски в `units` (0.5 %) тоже не отмечены.
Столбец `cashier` с 300 значениями отчёт отнёс к типу Text и о кардинальности промолчал; предупреждение
`[cashier] has 300 (0.4%) distinct values` появляется, только если явно указать тип:
`ProfileReport(df, type_schema={"cashier": "categorical"})`.

**Пороги настраиваются.** Корреляция считается высокой при значении выше 0.5, дисбаланс — выше 0.5,
кардинальность — больше 50 значений. Это умолчания, а не истина.

Предупреждения удобно разбирать программно — например, собрать кандидатов на удаление:

```python
constant = [a.column_name for a in description.alerts if a.alert_type.name == "CONSTANT"]
correlated = sorted(a.column_name for a in description.alerts if a.alert_type.name == "HIGH_CORRELATION")
# ['currency', 'comment']
# ['category', 'city', 'price', 'price_usd', 'product', 'revenue', 'store_id']
```

Второй список показывает, почему удалять столбцы по предупреждению нельзя: в нём оказались почти все
полезные признаки.

## 4. Настройки и цена отчёта

Полный отчёт считает корреляции нескольких видов и строит точечный график для **каждой пары** числовых
столбцов. Число пар растёт как квадрат числа столбцов — отсюда и цена. Замеры (на вашей машине цифры
будут другими, соотношения — теми же):

| Данные | `minimal=True` | Полный отчёт |
|---|---|---|
| продажи, 9 столбцов, 10 тыс. строк | 2.3 с | 3.2 с |
| продажи, 9 столбцов, 100 тыс. строк | 2.1 с | 4.1 с |
| продажи, 9 столбцов, 1 млн строк | 3.2 с | 17.2 с |
| 20 тыс. строк, 10 числовых столбцов | 2.8 с, 0.8 МБ | 11.7 с, 5.8 МБ |
| 20 тыс. строк, 30 числовых столбцов | 7.1 с, 1.8 МБ | 97 с, 46 МБ |
| 20 тыс. строк, 60 числовых столбцов | 19.9 с, 3.3 МБ | 335 с, 180 МБ |
| то же, 60 столбцов, `interactions={"continuous": False}` | — | 26.7 с, 3.6 МБ |

Выводы:

1. Число строк почти не страшно: миллион строк узкой таблицы — 17 секунд.
2. Число столбцов решает всё: 60 числовых столбцов — это 3600 точечных графиков, пять с половиной минут
   и файл в 180 МБ, который браузер открывает с трудом.
3. Почти вся цена — раздел Interactions: без него те же 60 столбцов обрабатываются за 27 секунд.

Способы удешевить отчёт:

```python
ProfileReport(df, minimal=True, title="Продажи: быстрый обзор")          # без корреляций, пар и дубликатов

ProfileReport(df.sample(50_000, random_state=0), title="Продажи: выборка 50 тыс. строк")

ProfileReport(
    df,
    title="Продажи",
    correlations={"auto": {"calculate": True}, "pearson": {"calculate": True}},
    interactions={"continuous": False},                                  # без точечных графиков пар
    missing_diagrams={"bar": True, "matrix": False, "heatmap": False},
    samples={"head": 0, "tail": 0, "random": 0},                         # без строк данных в отчёте
    duplicates={"head": 0},
    variables={"descriptions": {"units": "Продано штук за день", "revenue": "Выручка за день, руб."}},
)
```

`minimal=True` — разумный первый шаг для любой таблицы шире 20–30 столбцов: в отчёте остаются обзор,
предупреждения и описание каждого столбца. Корреляции потом считают отдельно для отобранных признаков.
Отчёт по выборке указывайте в заголовке: редкие категории и выбросы в выборку могут не попасть.
Параметр `variables` добавляет к столбцам человеческие описания — полезно, если отчёт увидит кто-то ещё.

Библиотека печатает предупреждения своих зависимостей (statsmodels, pandas). Они не относятся к вашим
данным; в скриптах их отключают через `warnings.simplefilter("ignore")`.

## 6. Сравнение двух выборок

Модель обучают на одних данных, а применяют к другим. Если распределения признаков различаются, качество
на новых данных будет хуже, чем на валидации. Отчёт умеет сравнивать две таблицы.

Разделим продажи по времени и внесём в «новые» данные изменение, о котором аналитика не предупредили:
смартфоны подорожали на 20 %.

```python
train = sales[sales["date"] < "2024-07-01"]
test = sales[sales["date"] >= "2024-07-01"].copy()
phones = test["product"] == "Смартфон"
test.loc[phones, "price"] = (test.loc[phones, "price"] * 1.2).astype(int)

train_report = ProfileReport(train, title="train", minimal=True)
test_report = ProfileReport(test, title="test", minimal=True)
train_report.compare(test_report).to_file("reports/train_vs_test.html")
```

В отчёте-сравнении статистики и гистограммы каждого столбца стоят рядом, двумя цветами. Те же числа можно
достать из описаний:

```python
a, b = train_report.get_description().variables, test_report.get_description().variables
columns = ["price", "units", "revenue"]
shift = pd.DataFrame(
    {"train_mean": {c: a[c]["mean"] for c in columns}, "test_mean": {c: b[c]["mean"] for c in columns}}
)
shift["change"] = shift["test_mean"] / shift["train_mean"] - 1
```

```
         train_mean  test_mean  change
price     16243.866  17055.309   0.050
units         4.112      5.222   0.270
revenue   45465.359  57498.763   0.265
```

Отчёт показал три сдвига и ни одного не объяснил. Средняя цена выросла на 5 % — это подорожавшие
смартфоны: один товар из двенадцати, зато дорогой. Продажи в штуках выросли на 27 % — но это не поломка,
а тренд и сезонность: в test попала вторая половина года с декабрьским пиком. Чтобы отличить одно
от другого, нужно знать данные: открыть раздел Variables, увидеть в частых значениях `price` новую цену
59 988 руб. вместо 49 990 руб. и спросить, откуда она взялась.

Правило: **сравнение train и test — обязательный шаг перед обучением**. Сдвиг по времени, новая категория,
изменившиеся единицы измерения дешевле найти в отчёте, чем в упавшей метрике.

## 7. Временные ряды

Режим `tsmode=True` добавляет к описанию числовых столбцов проверку стационарности, поиск сезонности,
график ряда и автокорреляцию, а в отчёте появляется раздел Time Series. Нужна таблица, где строка —
момент времени, а столбцы — ряды:

```python
daily = sales.pivot_table(index="date", columns="city", values="revenue", aggfunc="sum").reset_index()
daily.columns.name = None

ts_report = ProfileReport(daily, tsmode=True, sortby="date", title="Дневная выручка по городам")
{name: var["type"] for name, var in ts_report.get_description().variables.items()}
# {'date': 'DateTime', 'Владивосток': 'Numeric', 'Казань': 'Numeric', 'Москва': 'TimeSeries',
#  'Новосибирск': 'Numeric'}
```

Рядом отчёт признал только Москву. Столбец считается временным рядом, если автокорреляция с предыдущим
значением выше 0.7, а дневная выручка небольших городов для этого слишком шумная. Тип можно задать явно:

```python
ts_report = ProfileReport(
    daily,
    tsmode=True,
    sortby="date",
    type_schema={city: "timeseries" for city in ["Владивосток", "Казань", "Новосибирск"]},
)
```

Теперь все четыре столбца получают предупреждения `is non stationary` и `is seasonal` — и это верно:
в данных есть рост на 25 % в год, недельная и годовая сезонность. Для прогнозирования это означает, что
ряд нельзя подавать в модель как есть: понадобятся лаги, разности и календарные признаки (урок 2.1.3).

## 8. Ограничения

**Отчёт не заменяет мышление.** Он не знает:

- что нули и пропуски в `units` — разные вещи («не продали» и «не записали»), см. практику 2.1.4;
- какой столбец целевой и какие признаки содержат информацию из будущего (утечки, урок 2.1.1);
- что считать объектом: 300 «дубликатов» могут быть ошибкой выгрузки, а могут — законными повторами;
- что корреляция `city` и `store_id` тривиальна, а корреляция `price` и `price_usd` — дубль признака.

Отчёт отвечает на вопрос «что лежит в таблице», но не на вопрос «что с этим делать».

**Цена на широких таблицах** — раздел 4. Сначала `minimal=True`, затем полный отчёт по отобранным столбцам.

**Приватность.** HTML-отчёт содержит сами данные: строки из начала и конца таблицы, частые и крайние
значения каждого столбца, значения категорий. Проверка на отчётах этого урока — встречается ли в файле
название города:

| Отчёт | «Владивосток» есть в HTML |
|---|---|
| полный | да |
| с `samples={"head": 0, "tail": 0, "random": 0}` | да: остались частые значения столбцов |
| `ProfileReport(df, sensitive=True)` | нет |

Отключить показ строк недостаточно. Для таблиц с персональными или коммерческими данными используйте
`sensitive=True` — и всё равно относитесь к отчёту как к данным: не отправляйте в общий чат,
не выкладывайте в открытый репозиторий.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `uv add` сообщает `requirements are unsatisfiable` | библиотека требует pandas младше 3.0 | отдельное окружение для отчётов |
| `No module named 'pkg_resources'` | `ydata-profiling` 4.18 рассчитывает на старый setuptools | перейти на `fg-data-profiling` или добавить `setuptools<81` |
| `No module named 'pandas_profiling'` | код из старого руководства | `from data_profiling import ProfileReport` |
| Отчёт считается десятки минут, файл весит сотни мегабайт | полный отчёт по широкой таблице | `minimal=True` или `interactions={"continuous": False}` |
| Идентификатор определён как число, категория — как текст | типы определяются автоматически | `type_schema={...}`; привести типы до построения отчёта |
| По предупреждению `HIGH_CORRELATION` удалены полезные признаки | предупреждение принято за инструкцию | смотреть, какие именно столбцы связаны и почему |
| В отчёте не видно редкой категории | отчёт построен по выборке | строить описание редких значений по полным данным |
| Отчёт с данными клиентов оказался в репозитории | HTML содержит значения из таблицы | `sensitive=True`; папку с отчётами — в `.gitignore` |
