## Зачем это нужно

Статичный график отвечает на один вопрос — тот, который вы задали, когда его строили. При разведочном
анализе вопросы появляются быстрее, чем вы успеваете перестраивать картинки: «а что это за точка?»,
«а если только Казань?», «а что было в марте?». Интерактивный график отвечает на них без нового кода:
наведение показывает значения, щелчок по легенде скрывает ряд, выделение области приближает.

Вторая причина — заказчик. Аналитик, менеджер, инженер по данным не будут запускать ваш ноутбук. HTML-файл
с графиком или небольшое веб-приложение с фильтрами открываются в браузере у кого угодно.

Обратная сторона: интерактивный график — это программа на JavaScript внутри страницы. Он весит мегабайты,
не вставляется в PDF и тормозит на больших данных.

## 1. Статичный или интерактивный

| Ситуация | Что выбрать |
|---|---|
| Отчёт в PDF, статья, слайд, README | статичный (matplotlib, seaborn) |
| Сотни однотипных графиков в цикле | статичный: быстрее и легче |
| Разбор отдельных точек: выбросы, ошибки модели | интерактивный: `hover` покажет, что это за объект |
| Много рядов или категорий, которые хочется включать и выключать | интерактивный |
| Один и тот же вопрос для разных срезов данных | дашборд с фильтрами |
| Результат смотрит человек без Python | HTML-файл или дашборд |

Правило: интерактивность оправдана, когда читатель графика будет задавать ему вопросы. Если вывод уже
сделан и его нужно только показать — статичная картинка с подписью честнее и надёжнее.

import pandas as pd

sales = make_sales()

## 3. Plotly Express: график одной функцией

Plotly Express (`px`) работает с таблицей в длинном формате: вы называете столбцы, библиотека сама делит
данные на ряды, подбирает цвета и собирает легенду.

```python
labels = {"date": "Месяц", "revenue": "Выручка, руб.", "city": "Город"}
fig = px.line(monthly, x="date", y="revenue", color="city", markers=True, labels=labels,
              title="Месячная выручка по городам")
fig.show()
```

В ноутбуке `fig.show()` рисует график в ячейке, в обычном скрипте — открывает вкладку браузера. Параметр
`labels` заменяет имена столбцов на понятные подписи сразу везде: на осях, в легенде и во всплывающей
подсказке.

Остальные функции устроены так же, а параметры `color`, `labels`, `hover_data` (дополнительные столбцы
в подсказке), `facet_col` и `facet_row` (отдельная панель на каждое значение столбца) у них общие:

```python
by_cat = sales.groupby(["city", "category"], as_index=False)["revenue"].sum()
px.bar(by_cat, x="city", y="revenue", color="category", barmode="group")

daily = sales.groupby(["date", "store_id", "city"], as_index=False).agg(
    revenue=("revenue", "sum"), units=("units", "sum")
)
px.scatter(daily, x="units", y="revenue", color="city", hover_data=["store_id", "date"], opacity=0.5)
px.histogram(daily, x="revenue", color="city", nbins=60, barmode="overlay", opacity=0.6)
px.box(daily, x="store_id", y="revenue", color="city")
```

`hover_data` — главный довод в пользу Plotly при разборе данных: наведя курсор на точку-выброс, вы сразу
видите, какой это магазин и какая дата. Тепловая карта (`px.imshow`) строится по широкой таблице:

```python
profile = sales.assign(weekday=sales["date"].dt.day_of_week).pivot_table(
    index="category", columns="weekday", values="revenue", aggfunc="mean"
)
profile.columns = ["Пн", "Вт", "Ср", "Чт", "Пт", "Сб", "Вс"]
px.imshow(profile, text_auto=".0f", aspect="auto", color_continuous_scale="Blues")
```

**Панели (facets)** — один и тот же график для каждого значения столбца:

```python
keys = [pd.Grouper(key="date", freq="MS"), "city", "category"]
by_month = sales.groupby(keys, as_index=False)["revenue"].sum()
facets = px.line(by_month, x="date", y="revenue", color="category", facet_col="city", facet_col_wrap=2)
facets.for_each_annotation(lambda a: a.update(text=a.text.split("=")[-1]))   # "city=Москва" -> "Москва"
facets.update_yaxes(matches=None, showticklabels=True)                        # у каждой панели своя шкала
```

По умолчанию у панелей общая шкала Y: удобно сравнивать уровни, но Владивосток рядом с Москвой
превращается в прямую линию. С `matches=None` у каждой панели своя шкала — сравнивают форму кривых.

**Анимация** — по кадру на каждое значение столбца, под графиком появляются кнопка запуска и ползунок:

```python
by_month["month"] = by_month["date"].dt.strftime("%Y-%m")
px.bar(by_month, x="category", y="revenue", color="city", animation_frame="month", range_y=[0, 1.7e8])
```

Пользуйтесь ей умеренно: сравнивать 24 кадра по памяти труднее, чем 24 точки на одной линии. Диапазон
осей фиксируйте явно (`range_y`), иначе шкала будет меняться от кадра к кадру.

## 4. Устройство Figure

Любой график Plotly — это объект `Figure` из двух частей:

- `data` — кортеж **трасс** (traces). Трасса — один набор данных одного типа: линия, набор столбцов,
  тепловая карта. `px.line` с `color="city"` создал четыре трассы типа `scatter`, по одной на город;
- `layout` — всё остальное: заголовок, оси, легенда, поля, аннотации.

```python
len(fig.data), fig.data[0].type, fig.data[0].name      # (4, 'scatter', 'Владивосток')
fig.layout.title.text, fig.layout.yaxis.title.text     # ('Месячная выручка по городам', 'Выручка, руб.')
```

Внутри это вложенный словарь, который превращается в JSON и передаётся библиотеке plotly.js в браузере:
Python ничего не рисует, он только готовит описание графика. Отсюда главный приём работы: Plotly Express
создаёт фигуру, а дальше вы меняете её свойства.

```python
fig.update_traces(line_width=3, hovertemplate="%{y:,.0f} руб.")
fig.update_traces(line_dash="dot", selector={"name": "Владивосток"})          # только одна трасса
fig.update_layout(template="plotly_white", hovermode="x unified", legend_title_text="Город")
fig.update_xaxes(dtick="M3", tickformat="%b\n%Y")
fig.update_yaxes(rangemode="tozero", tickformat=",.0f")
```

`update_traces` меняет трассы (все или отобранные через `selector`), `update_layout` — заголовок, легенду,
поля и шаблон, `update_xaxes` и `update_yaxes` — оси, в том числе на всех панелях сразу. Запись
`line_width=3` — сокращение для `line={"width": 3}`: подчёркивание заменяет вложенность. Опечатку в имени
свойства Plotly не пропустит и подскажет правильное:

```
ValueError: Invalid property specified for object of type plotly.graph_objs.Layout: 'titel'
Did you mean "title"?
```

`hovermode="x unified"` показывает одну общую подсказку для всех рядов на выбранной дате — для временных
рядов это почти всегда удобнее отдельных подсказок.

## 5. graph_objects: когда Express не хватает

Модуль `plotly.graph_objects` (`go`) — уровень ниже: трассы создаются явно. Он нужен, когда на одном
графике встречаются данные разной природы. Пример: выручка сети столбцами и доля промо линией на второй
оси.

```python
import plotly.graph_objects as go
from plotly.subplots import make_subplots

network = (
    sales.groupby(pd.Grouper(key="date", freq="MS"))
    .agg(revenue=("revenue", "sum"), promo_share=("promo", "mean"))
    .reset_index()
)
combo = make_subplots(specs=[[{"secondary_y": True}]])
combo.add_trace(go.Bar(x=network["date"], y=network["revenue"], name="Выручка"), secondary_y=False)
combo.add_trace(
    go.Scatter(x=network["date"], y=network["promo_share"], name="Доля промо", mode="lines+markers"),
    secondary_y=True,
)
combo.update_yaxes(title_text="Выручка, руб.", secondary_y=False)
combo.update_yaxes(title_text="Доля строк с промо", tickformat=".1%", showgrid=False, secondary_y=True)

best = network.loc[network["revenue"].idxmax()]                        # декабрь 2024 года, 219.1 млн руб.
combo.add_annotation(x=best["date"], y=best["revenue"], text="Максимум", showarrow=True, arrowhead=2, ay=-40)
combo.add_vline(x=pd.Timestamp("2024-01-01"), line_dash="dash", line_color="gray")
combo.add_hline(y=network["revenue"].mean(), line_dash="dot", annotation_text="Среднее за два года")
combo.update_layout(title="Выручка сети и доля промо", legend={"orientation": "h", "y": -0.15})
```

Вторая ось — инструмент с подвохом: подбором шкал можно «доказать» любую связь между рядами. Здесь доля
промо меняется от 6.9 % до 8.9 %, и на своей шкале эти колебания выглядят драматично. Если показатели
можно привести к одной шкале или развести по двум панелям — так и сделайте.

**Подграфики** с произвольной сеткой задаёт параметр `specs`:

```python
day = sales.groupby("date", as_index=False)["revenue"].sum()
cats = sales.groupby("category")["revenue"].sum().sort_values()

grid = make_subplots(
    rows=2,
    cols=2,
    specs=[[{"colspan": 2}, None], [{}, {}]],                 # верхний график занимает обе колонки
    subplot_titles=["Дневная выручка сети", "По категориям", "По дням недели"],
)
grid.add_trace(go.Scatter(x=day["date"], y=day["revenue"]), row=1, col=1)
grid.add_trace(go.Bar(x=cats.to_numpy(), y=cats.index, orientation="h"), row=2, col=1)
grid.add_trace(go.Bar(x=profile.columns, y=profile.mean().to_numpy()), row=2, col=2)
```

Заголовки в `subplot_titles` перечисляются только для занятых ячеек: здесь их три, а не четыре.

**Шаблоны** избавляют от повторения оформления в каждом графике. Встроенные: `plotly` (по умолчанию),
`plotly_white`, `plotly_dark`, `simple_white`, `ggplot2`, `seaborn`, `presentation`. Свой шаблон задаёт
шрифт, палитру и поля один раз на весь проект:

```python
import plotly.io as pio

pio.templates["course"] = go.layout.Template(
    layout={"font": {"family": "Arial", "size": 13}, "colorway": px.colors.qualitative.Safe}
)
pio.templates.default = "plotly_white+course"            # шаблоны складываются через "+"
```

## 6. Сохранение

**HTML** — основной формат: интерактивность сохраняется, файл открывается в любом браузере. Главный
параметр — `include_plotlyjs`: куда деть саму библиотеку plotly.js. Замер на графике `fig` из раздела 4:

```python
fig.write_html("monthly.html", include_plotlyjs=True)
```

| `include_plotlyjs` | Размер HTML | Что происходит |
|---|---|---|
| `True` (по умолчанию) | 4 829 199 байт | библиотека встроена в файл: работает без сети, но весит 4.8 МБ |
| `"cdn"` | 13 535 байт | библиотека загружается из интернета при открытии; без сети график пуст |
| `"directory"` | 13 421 байт | рядом один раз создаётся `plotly.min.js` (4.8 МБ), общий для всех файлов папки |
| `False` | 13 283 байта | библиотеки нет: вы подключаете её на странице сами |

Сам график — 13 КБ; всё остальное — библиотека. Десять графиков с настройкой по умолчанию — это 48 МБ.
Отчёт из нескольких файлов сохраняйте с `"directory"`, одиночный файл для отправки по почте — с `True`,
страницу для сайта — с `"cdn"`. Блок `<div>` для вставки в собственную страницу возвращает
`fig.to_html(full_html=False, include_plotlyjs=False)`. HTML-файлы графиков в Git не коммитят.

**Статичные картинки** делает пакет kaleido: он запускает браузер Chrome без окна и снимает с графика
изображение.

```python
fig.write_image("monthly.png", width=900, height=450, scale=2)     # 180 КБ, около 4 секунд
fig.write_image("monthly.svg")                                     # 33 КБ
fig.write_image("monthly.pdf")                                     # 20 КБ
```

Kaleido 1.x не содержит браузер внутри себя: ему нужен установленный Chrome или Chromium. Без него
`write_image` завершается ошибкой `Kaleido requires Google Chrome to be installed` и предлагает команду
`plotly_get_chrome`. Несколько секунд на картинку — цена запуска браузера, поэтому сотни картинок в цикле
быстрее рисовать в matplotlib.

## 7. Производительность: сколько точек выдержит браузер

Все точки графика передаются в браузер и хранятся в HTML. Дальше возможны два способа рисования:

- **SVG** (трасса `scatter`) — каждая точка становится отдельным элементом страницы. Качество идеальное,
  но десятки тысяч элементов браузер перерисовывает медленно;
- **WebGL** (трасса `scattergl`) — точки рисует видеокарта на одном холсте.

Замер: точечный график «дата — выручка строки» по данным `make_sales` за 29 лет (1 млн строк),
`write_html(..., include_plotlyjs="directory")`, Chromium без графического ускорения:

| Точек | Режим | Размер HTML | Первая отрисовка | Перерисовка при приближении |
|---|---|---|---|---|
| 1 000 | SVG | 0.05 МБ | 0.4 с | 0.04 с |
| 10 000 | SVG | 0.41 МБ | 0.6 с | 0.28 с |
| 10 000 | WebGL | 0.41 МБ | 0.7 с | 0.17 с |
| 100 000 | SVG | 4.0 МБ | 2.7 с | 2.8 с |
| 100 000 | WebGL | 4.0 МБ | 0.9 с | 0.45 с |
| 1 000 000 | SVG | 40 МБ | 24.8 с | 27.0 с |
| 1 000 000 | WebGL | 40 МБ | 2.1 с | 3.4 с |
| 6 056 (недельные суммы по категориям) | SVG, линии | 0.25 МБ | 0.7 с | 0.2 с |

Ваши цифры будут другими, порядок — тем же. Выводы:

1. До 10 тысяч точек SVG справляется; на 100 тысячах каждое приближение занимает почти 3 секунды —
   графиком уже нельзя пользоваться. WebGL отодвигает границу примерно на порядок.
2. Plotly Express переключается на WebGL сам: `px.scatter` и `px.line` создают `scattergl`, когда точек
   больше 1000. Поведением управляет параметр `render_mode` (`"auto"`, `"svg"`, `"webgl"`); в
   `graph_objects` выбирайте `go.Scattergl` явно.
3. WebGL не уменьшает файл: миллион точек — это 40 МБ HTML в любом режиме.
4. Последняя строка таблицы — тот же миллион строк, но сначала агрегированный в pandas. Файл в 160 раз
   меньше, график отзывчив, а тренд и сезонность видны лучше, чем в облаке из миллиона точек.

Отсюда главное правило: **агрегируйте до рисования**. Браузеру отдают столько точек, сколько человек
способен рассмотреть.

- вместо точек по каждой строке во времени — `groupby` по дню, неделе или месяцу и линия;
- вместо точечного графика на миллион точек — случайная подвыборка (`df.sample(20_000)`);
- вместо `px.histogram` по сырому столбцу — `np.histogram` в Python и `px.bar` по готовым столбикам.
  `px.histogram` передаёт в браузер все исходные значения и считает столбики уже там: для 488 тысяч строк
  получился файл 5.3 МБ, а тот же график из заранее посчитанных 100 столбиков занял 9.6 КБ.

## 8. Dash: график становится приложением

Dash — веб-фреймворк от авторов Plotly. Приложение пишется целиком на Python и состоит из двух частей:
**макета** (что находится на странице) и **callback-функций** (что происходит при действиях пользователя).

```python
import pandas as pd
import plotly.express as px
from dash import Dash, Input, Output, callback, dcc, html
from sales_data import make_sales

SALES = make_sales()
CITIES = sorted(SALES["city"].unique())
METRICS = {"revenue": "Выручка, руб.", "units": "Продажи, шт."}

app = Dash(__name__)
app.layout = html.Div(
    [
        html.H2("Продажи по категориям"),
        dcc.Dropdown(id="city", options=CITIES, value="Москва", clearable=False),
        dcc.RadioItems(id="metric", options=METRICS, value="revenue", inline=True),
        dcc.Graph(id="chart"),
    ],
    style={"maxWidth": "900px", "margin": "0 auto"},
)


@callback(Output("chart", "figure"), Input("city", "value"), Input("metric", "value"))
def update_chart(city, metric):
    selected = SALES[SALES["city"] == city]
    monthly = selected.groupby([pd.Grouper(key="date", freq="MS"), "category"], as_index=False)[metric].sum()
    labels = {"date": "Месяц", metric: METRICS[metric], "category": "Категория"}
    title = f"{city}: динамика по месяцам"
    return px.line(monthly, x="date", y=metric, color="category", labels=labels, title=title)


if __name__ == "__main__":
    app.run(debug=True)
```

```bash
uv run python app.py        # Dash is running on http://127.0.0.1:8050/
```

**Макет** — дерево компонентов. `html.*` повторяют теги HTML (`html.Div`, `html.H2`, `html.Button`),
`dcc.*` (Dash Core Components) — готовые элементы управления:

| Компонент | Что это | Свойство со значением |
|---|---|---|
| `dcc.Graph` | график Plotly | `figure`; действия пользователя — `clickData`, `selectedData` |
| `dcc.Dropdown` | выпадающий список, с `multi=True` — множественный выбор | `value` |
| `dcc.RadioItems`, `dcc.Checklist` | переключатель и набор флажков | `value` |
| `dcc.DatePickerRange` | выбор периода | `start_date`, `end_date` |
| `dcc.Slider`, `dcc.RangeSlider` | ползунки | `value` |
| `dcc.Store` | невидимое хранилище данных в браузере пользователя | `data` |

У каждого компонента, участвующего во взаимодействии, должен быть уникальный `id`.

**Callback** связывает свойства компонентов. Декоратор читается так: «когда изменится `value` у `city`
или `metric`, вызови функцию и запиши результат в `figure` компонента `chart`». Dash вызывает функцию
и при первой загрузке страницы — поэтому график появляется сразу.

| Зависимость | Смысл |
|---|---|
| `Output(id, свойство)` | куда записать результат; одно свойство может быть выходом только одного callback |
| `Input(id, свойство)` | изменение этого свойства запускает функцию |
| `State(id, свойство)` | значение передаётся в функцию, но его изменение функцию не запускает |

`State` нужен, когда пересчёт дорогой и запускать его следует по кнопке, а не при каждом движении фильтра.
В макет добавляется `html.Button("Построить", id="apply")`, а декоратор меняется так:

```python
@callback(
    Output("chart", "figure"),
    Input("apply", "n_clicks"),
    State("city", "value"),
    State("metric", "value"),
    prevent_initial_call=True,             # не вызывать при загрузке страницы, пока кнопку не нажали
)
def update_chart(n_clicks, city, metric): ...
```

**Callback — чистая функция.** Результат зависит только от аргументов; функция ничего не меняет вне себя.
Это не вопрос стиля. В рабочем режиме приложение обслуживают несколько процессов: запросы одного
пользователя попадают в разные процессы, а один процесс обслуживает многих пользователей. Глобальная
переменная, изменённая в callback, в одном процессе изменится, в другом нет — и будет общей для всех
посетителей. Отсюда правила хранения данных:

- исходные данные, общие для всех, — глобальная переменная, загруженная при старте; в callback её только
  читают. `SALES[SALES["city"] == city]` создаёт новую таблицу — это безопасно, `SALES["new"] = ...` — ошибка;
- выбор конкретного пользователя — в самих компонентах или в `dcc.Store`, то есть в его браузере;
- результат тяжёлого расчёта — кэш по аргументам функции, а не глобальная переменная.

**Запуск и отладка.** `app.run(debug=True)` включает режим разработки: сервер перезапускается при
сохранении файла, ошибка в callback показывается прямо в браузере, а на панели внизу страницы виден граф
зависимостей между компонентами. В старых руководствах встречается `app.run_server(...)` — в Dash 4 этого
метода нет: `ObsoleteAttributeException: app.run_server has been replaced by app.run`.

Режим отладки — только для своей машины. Для других пользователей приложение запускают через сервер
приложений, например gunicorn: в модуль добавляют строку `server = app.server` и выполняют
`gunicorn app:server`. В отличие от HTML-файлов Plotly, страница Dash не обращается к CDN: plotly.js
и остальные скрипты отдаёт сам сервер приложения.

## 9. Альтернативы Dash

| Инструмент | Как устроен | Когда выбирают |
|---|---|---|
| Dash | макет и callback-функции заданы явно; обновляются только связанные компоненты | дашборд с несколькими графиками и фильтрами; приложение, которое будет расти |
| Streamlit | скрипт целиком выполняется заново при каждом действии пользователя | прототип или демонстрация модели за час, простая логика |
| Panel | виджеты и графики многих библиотек, работает прямо из ноутбука | готовый ноутбук с графиками нужно превратить в приложение |

В курсе используется Dash: он опирается на Plotly, а функции с явными входами и выходами легко тестировать.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| HTML-файл открывается пустым на другом компьютере | `include_plotlyjs="cdn"`, а сети нет | `include_plotlyjs=True` или `"directory"` вместе с `plotly.min.js` |
| Вкладка браузера зависает при открытии графика | сотни тысяч точек в режиме SVG | агрегировать или взять подвыборку; `render_mode="webgl"` |
| `ValueError: Invalid property specified` | опечатка в имени свойства | прочитать подсказку `Did you mean` в тексте ошибки |
| `write_image` падает с сообщением о Chrome | kaleido не нашёл браузер | установить Chrome или Chromium, либо выполнить `plotly_get_chrome` |
| Callback не срабатывает | `id` в `Input` не совпадает с `id` компонента; свойство указано как `State` | сверить `id`; посмотреть граф зависимостей на панели отладки |
| `Duplicate callback outputs` | два callback пишут в одно свойство | объединить их в один callback с несколькими `Input` |
| У разных пользователей «перемешиваются» данные | состояние хранится в глобальной переменной | хранить выбор в компонентах или `dcc.Store` |
| `ObsoleteAttributeException` при запуске | `app.run_server` из старого руководства | `app.run` |
