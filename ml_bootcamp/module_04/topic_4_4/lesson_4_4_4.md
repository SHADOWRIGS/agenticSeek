## Задача

В практике 2.3.4 вы улучшали результат в конкурсе Kaggle только признаками: модель была зафиксирована.
Теперь признаки зафиксированы, а меняется всё остальное. Возьмите свой набор признаков из той работы
и ответьте на вопрос: **сколько даёт ансамбль сверх лучшей одиночной модели и стоит ли он усилий?**

Ответ «ансамбль улучшил результат на 0.003» ничего не стоит без трёх уточнений: относительно чего
(лучшая модель настроена или взята с параметрами по умолчанию?), как измерено (на тех же предсказаниях,
на которых подбирались веса?) и больше ли это шума. Работа устроена так, чтобы на все три вопроса
пришлось ответить.

Две части:

1. **Реализация.** Стенд для построения ансамблей: out-of-fold предсказания, корреляции ошибок,
   усреднение, подбор весов, стекинг и честная оценка. Проверяется автотестами.
2. **Применение.** 3–5 разных моделей на данных конкурса, подбор гиперпараметров через Optuna
   с фиксированным бюджетом, три вида ансамблей, отправка решений и сравнение локальной оценки
   с лидербордом.

## Часть 1. Стенд

Точные требования — в docstring заготовки. Таблицы предсказаний устроены одинаково: строка — объект,
столбец — модель. `oof` — предсказания для обучающей выборки, `test` — для тестовой.

### Шаг 1. `out_of_fold_predictions`

Главная функция стенда. Для каждой модели и каждого фолда обучается копия модели; её предсказания для
проверочной части фолда попадают в `oof`, а предсказания для теста усредняются по фолдам.

Подводные камни:

- **фолды общие для всех моделей.** Разбиение вычисляется один раз (`list(cv.split(X, y))`). Тест
  `test_same_folds_for_all_models` передаёт перемешивающее разбиение без `random_state`: при повторных
  вызовах `split` две одинаковые модели получат разные фолды и дадут разные столбцы;
- **сопоставление по позиции.** У `X` произвольный индекс, `y` может быть массивом или `Series`
  с другим индексом: работайте через `iloc` и `np.asarray(y)`;
- **не всякое разбиение годится.** `ShuffleSplit` и `TimeSeriesSplit` не дают каждому объекту ровно
  одно out-of-fold предсказание — функция должна отказаться;
- **переданные модели не обучаются** — только их копии (`sklearn.base.clone`).

Два теста проверяют главное свойство — отсутствие утечки:

- `test_own_target_does_not_leak` меняет ответ одного объекта и требует, чтобы его собственное
  предсказание не изменилось (а предсказания объектов из других фолдов — изменились);
- `test_memorizing_model_gains_nothing` обучает 1-NN на случайных ответах. На своих обучающих объектах
  эта модель «угадывает» всё; на out-of-fold её точность должна быть около 0.5.

```bash
uv run pytest -q -k TestOutOfFoldPredictions
```

### Шаг 2. `error_correlation`

Корреляции ошибок, а не предсказаний: тест `test_errors_not_predictions` строит две модели, предсказания
которых коррелируют на 0.95 и выше, а ошибки независимы.

### Шаг 3. `average` и `rank_average`

Веса нормируются, отрицательные и нулевые в сумме — ошибка, названия должны совпадать со столбцами.
Ранги — `method="average"`, деление на число строк; результат не должен зависеть от шкалы столбцов.

### Шаг 4. `fit_blend_weights`

Метрика конкурса — как правило, ROC-AUC, а она как функция весов ступенчатая: градиентный подбор
из урока 4.4.1 для неё не работает. Стенд использует жадный отбор с возвращением (R. Caruana и др.):
на каждом шаге в набор добавляется модель, с которой метрика среднего по набору наилучшая; вес модели —
доля её вхождений в лучший из получившихся наборов. Метод работает с любой метрикой, веса неотрицательны
и дают в сумме 1, а результат на `oof` по построению не хуже лучшей одиночной модели: набор из одного
элемента — это она.

Храните накопленную сумму предсказаний набора: среднее с кандидатом — `(total + column) / size`.

### Шаг 5. `fit_stacker` и `predict_stacker`

Логистическая регрессия на логитах вероятностей (урок 4.4.1: метамодель на самих вероятностях портит
log loss). Вероятности обрезаются до `[EPS, 1 - EPS]`: у леса и kNN встречаются ровно 0 и 1.
Метамодель должна помнить названия столбцов: `predict_stacker` обязана дать тот же результат при
любом порядке столбцов.

### Шаг 6. `evaluate_ensembles`

Сводная таблица. Одиночные модели, простое среднее и среднее рангов оцениваются на `oof` напрямую —
у них нет обучаемых параметров. Веса и метамодель обучаются на `oof`, поэтому оценивать их на тех же
строках нельзя: строки `oof` делятся разбиением, веса подбираются на одной части и применяются к другой.

Тесты `test_stacking_score_is_honest` и `test_weighted_score_is_honest` подают 15 «моделей» из чистого
шума на 60 объектах. Подгонка на своих строках даёт ROC-AUC выше 0.65 и log loss ниже 0.6 — «ансамбль
работает». Честная оценка обязана показать, что он не работает.

```bash
uv run python -W error -m pytest -q
```

## Часть 2. Ансамбль

```python
from ensemble_lab import (
    average, error_correlation, evaluate_ensembles, fit_blend_weights,
    fit_stacker, out_of_fold_predictions, predict_stacker, rank_average,
)
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import StratifiedKFold

cv = StratifiedKFold(5, shuffle=True, random_state=0)
oof, test_pred = out_of_fold_predictions(models, X, y, X_test, cv)
error_correlation(oof, y)
table = evaluate_ensembles(oof, y, roc_auc_score)

weights = fit_blend_weights(oof, y, roc_auc_score)
stacker = fit_stacker(oof, y)
final = {
    "average": average(test_pred),
    "rank_average": rank_average(test_pred),
    "weighted": average(test_pred, weights),
    "stacking": predict_stacker(stacker, test_pred),
}
submission = pd.DataFrame({"id": test["id"], TARGET: final["weighted"].to_numpy()})
```

План:

1. **Схема валидации.** Та же, что в практике 2.3.4, одна для всех моделей и всех этапов. Если в данных
   есть группы или время, `StratifiedKFold` не подходит (урок 3.2.3) — и `out_of_fold_predictions`
   должна получить соответствующее разбиение.
2. **Модели.** От трёх до пяти, минимум из двух разных семейств: линейная модель, бустинг, лес, kNN,
   нейросеть. Три бустинга — это одно семейство. Для каждой модели — своя подготовка признаков внутри
   `Pipeline`.
3. **Optuna.** Подберите гиперпараметры хотя бы одной модели — той, что лучше остальных с параметрами
   по умолчанию. Бюджет фиксируется заранее и записывается: число попыток, `seed`, время. Фолды — те же.

   ```python
   def objective(trial):
       params = {
           "lgbmclassifier__num_leaves": trial.suggest_int("num_leaves", 2, 32, log=True),
           "lgbmclassifier__min_child_samples": trial.suggest_int("min_child_samples", 10, 300, log=True),
           "lgbmclassifier__colsample_bytree": trial.suggest_float("colsample_bytree", 0.3, 1.0),
           "lgbmclassifier__subsample": trial.suggest_float("subsample", 0.5, 1.0),
           "lgbmclassifier__reg_lambda": trial.suggest_float("reg_lambda", 1e-2, 100.0, log=True),
           "lgbmclassifier__learning_rate": trial.suggest_float("learning_rate", 0.01, 0.1, log=True),
       }
       model = lightgbm_pipeline.set_params(lgbmclassifier__subsample_freq=1, **params)
       return cross_val_score(model, X, y, cv=cv, scoring="roc_auc").mean()


   study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=0))
   study.optimize(objective, n_trials=40)
   ```

   Число деревьев здесь зафиксировано (300), поэтому шаг входит в пространство поиска; если вы
   используете раннюю остановку, шаг фиксируется (урок 4.4.2).
4. **OOF и корреляции.** Таблица качества моделей и матрица корреляций ошибок. До построения ансамблей
   запишите прогноз: какие модели, судя по корреляциям и качеству, получат ненулевой вес?
5. **Ансамбли.** Простое среднее, среднее рангов, взвешенное среднее, стекинг — таблица
   `evaluate_ensembles`. Рядом выпишите оптимистичные оценки (веса и метамодель оценены на тех же
   строках, на которых обучены): насколько они завышены?
6. **Отправки.** Не меньше трёх: лучшая одиночная модель, взвешенное среднее, стекинг. Для каждой —
   локальная оценка и публичный результат. Отправки для итогового зачёта выбираются **по локальной
   оценке**, а не по публичной таблице (практика 2.3.4).
7. **Заключение.** Одна страница в `README.md` проекта: что дал подбор гиперпараметров, что дал ансамбль,
   больше ли это шума, согласована ли локальная оценка с лидербордом, стали бы вы использовать этот
   ансамбль в рабочей системе.

- **ансамбль не дал ничего.** Взвешенное среднее отдаёт 83 % веса лучшей модели и выигрывает 0.0002
  на OOF, а на приватной части неотличимо от неё (0.8256 и 0.8255); стекинг проигрывает 0.0002.
  Простое среднее хуже лучшей модели на 0.009: три из пяти моделей заметно слабее неё;
- **публичная таблица показывает другое.** По ней лучший — стекинг (0.8379 против 0.8373). На приватной
  части он проигрывает 0.0001. Обе разности — шум: в публичной части 1 150 строк;
- **честная оценка отличается от оптимистичной мало** (0.8127 и 0.8129, 0.8123 и 0.8134), потому что
  метамодель простая, а строк 8 000. Чем меньше данных и чем сложнее метамодель, тем больше разрыв;
- если убрать логистическую регрессию, лучшей становится LightGBM (0.8053), взвешенное среднее
  оставшихся даёт 0.8050, стекинг — 0.8046: ансамбль четырёх «древесных и соседских» моделей тоже
  бесполезен.

На настоящем конкурсе с вашими признаками картина будет другой, но порядок величин — нет: выигрыш
ансамбля над хорошо настроенной лучшей моделью обычно лежит в пределах 0.001–0.005 ROC-AUC.

## Когда ансамбль не стоит усилий

Демо-данные — пример задачи, где ансамбль не нужен, и по ним видны признаки такой ситуации. Проверьте
их на своих данных до того, как строить многоуровневые конструкции.

| Признак | Как увидеть | На демо-данных |
|---|---|---|
| одна модель заметно сильнее остальных | таблица качества на OOF | разрыв 0.007 между первой и второй |
| подбор весов отдаёт почти всё одной модели | `fit_blend_weights` | 0.83 у логистической регрессии |
| ошибки кандидатов почти совпадают | `error_correlation` | 0.98–0.99 между лучшими тремя |
| выигрыш меньше шума | разброс выигрыша по фолдам, бутстреп-интервал, разница публичной и приватной частей | +0.0002 при шуме в тысячные |
| то же усилие в другом месте даёт больше | сравнить с подбором гиперпараметров и новыми признаками | подбор: +0.012; признаки в практике 2.3.4: +0.019 |
| цена предсказания важна | время предсказания ансамбля и лучшей модели | kNN и лес на порядок медленнее линейной модели |

Что делать, если признаки налицо: оставить одну модель и вложить время в признаки и данные. Что делать,
если модели сопоставимы по силе, а корреляции ошибок заметно ниже 0.98: начать со взвешенного среднего
двух-трёх моделей разных семейств и остановиться, когда добавление следующей модели перестаёт давать
выигрыш больше шума. Стекинг и второй уровень — только в соревновании и только с честной оценкой.

## Критерии приёмки

- [ ] `uv run pytest -q` — все 70 тестов проходят, полный прогон занимает меньше 60 секунд
      (эталон — 22 секунды);
- [ ] `uv run python -W error -m pytest -q` проходит: код не вызывает предупреждений библиотек;
- [ ] `uv run ruff check .` проходит без ошибок;
- [ ] в репозитории нет папки `catboost_info`, файлов баз Optuna, данных конкурса и файлов отправок;
- [ ] обучено от трёх до пяти моделей минимум из двух семейств, у всех одно разбиение;
- [ ] гиперпараметры хотя бы одной модели подобраны через Optuna; бюджет (число попыток, `seed`, время)
      записан, приведено качество до и после;
- [ ] есть матрица корреляций ошибок и прогноз, сделанный до построения ансамблей;
- [ ] есть таблица: одиночные модели, простое среднее, взвешенное среднее, стекинг — с честной оценкой
      и выигрышем относительно лучшей одиночной модели;
- [ ] для настоящего конкурса сделано не меньше трёх отправок, локальная оценка сопоставлена с публичной;
      для демо-данных — с публичной и приватной частями `score_submission`;
- [ ] заключение отвечает на три вопроса: относительно чего выигрыш, как он измерен, больше ли он шума.

## Как оценить свою работу

| Уровень | Признаки |
|---|---|
| Базовый | все тесты проходят; есть таблица моделей и ансамблей и хотя бы одна отправка |
| Уверенный | вы можете объяснить, почему оценка весов на тех же строках завышена и как тесты это ловят; в заключении выигрыш сопоставлен с шумом, а локальная оценка — с лидербордом |
| Продвинутый | выполнено хотя бы два задания из раздела ниже |

## Идеи для усложнения

1. **Интервал для выигрыша.** Постройте бутстреп-интервал разности метрик взвешенного среднего и лучшей
   модели на OOF. Содержит ли он ноль? Сколько строк понадобилось бы, чтобы выигрыш в 0.001 стал значимым?
2. **Полная вложенная схема.** `evaluate_ensembles` делит уже готовую таблицу OOF. Строго честная оценка
   пересчитывает OOF базовых моделей внутри каждого внешнего фолда. Реализуйте её и сравните три числа:
   оптимистичное, из стенда, вложенное.
3. **Разнообразие по seed и по признакам.** Обучите лучшую модель с пятью значениями seed и усредните.
   Обучите её на разных подмножествах признаков. Что даёт больше — это или модели других семейств?
4. **Метамодель и исходные признаки.** Добавьте в `fit_stacker` два-три исходных признака (аналог
   `passthrough`). Меняются ли веса моделей в разных областях данных?
5. **Подбор весов через Optuna.** Сравните жадный отбор с подбором весов на симплексе через Optuna
   (распределение Дирихле: нормированные `suggest_float`). Какой способ сильнее подгоняется под OOF?
6. **Цена.** Измерьте время предсказания каждой модели и ансамбля для одной строки и для 100 тысяч строк.
   Найдите ансамбль с лучшим качеством при ограничении «не медленнее лучшей модели более чем вдвое».
7. **Shake-up.** Повторите эксперимент с лидербордом из практики 2.3.4 на своих отправках: насколько
   меняется порядок ваших решений между публичной и приватной частями?

## Что дальше

Модуль 4 закончен: деревья, лес, три библиотеки бустинга, подбор гиперпараметров и ансамбли — это
основной набор инструментов для табличных данных, и в большинстве таких задач хорошо настроенный бустинг
с хорошими признаками остаётся решением, которое трудно обогнать. В модуле 5 начинаются нейронные сети.
Многое из этой темы перейдёт туда без изменений: подбор гиперпараметров с отсечением по кривым обучения,
усреднение моделей, честная оценка на отложенных данных.
