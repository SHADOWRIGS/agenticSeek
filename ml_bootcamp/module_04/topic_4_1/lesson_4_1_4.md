## Что нужно реализовать

### Шаг 1. `impurity`

Неоднородность узла по счётчикам классов: индекс Джини и энтропия (урок 4.1.2). Два подводных камня:
логарифм нуля для отсутствующего класса и пустой узел.

```bash
uv run pytest -q -k TestImpurity
```

### Шаг 2. `best_split`

Сердце алгоритма: для узла найти признак и порог с наибольшим уменьшением неоднородности.

Точные правила — в docstring. Главное:

- пороги — середины между соседними **различными** значениями признака;
- учитывается `min_samples_leaf`;
- разбиение с нулевым выигрышем допустимо: без этого дерево не решит «исключающее или» (урок 4.1.1);
- при равном выигрыше — меньший номер признака, затем меньший порог. Правило нужно, чтобы результат был
  однозначным и его можно было проверить.

Начните с простой версии: цикл по признакам, цикл по порогам, для каждого — маска и пересчёт
неоднородности. Она пройдёт все тесты на корректность и провалит тест скорости:

```bash
uv run pytest -q -k TestBestSplit
```

**Затем ускорьте.** Простая версия для каждого из $n$ порогов заново перебирает $n$ объектов — это $n^2$
операций на признак. На 20 000 объектов и 10 признаках поиск одного разбиения занимает около полутора
минут; быстрая версия справляется за 0.07 секунды.

Идея быстрой версии:

1. отсортировать объекты по значению признака;
2. идти по порогам слева направо: при переходе к следующему порогу один объект переезжает из правого
   потомка в левый — достаточно обновить счётчики классов, а не пересчитывать их;
3. на NumPy это записывается без цикла по порогам: накопленные суммы (`np.cumsum`) по отсортированным
   меткам в one-hot кодировании дают счётчики классов левого потомка сразу для всех порогов; счётчики
   правого — разность с общими.

Получается $n \log n$ на признак вместо $n^2$. Тот же приём — основа всех промышленных реализаций.

### Шаг 4. Предсказание

`predict_proba` возвращает доли классов листа, `predict` — метку самого частого класса.

Простой способ — для каждого объекта спуститься от корня к листу. На миллионе объектов это миллион
обходов на Python, и тест скорости его не пропустит. Быстрый способ — спускать по дереву не объекты,
а **группы объектов**: в узле массив индексов делится маской на две части, каждая уходит в своего потомка.
Обходов столько, сколько узлов в дереве, а не сколько объектов.

```bash
uv run pytest -q -k TestPrediction
```

### Шаг 5. Сверка и скорость

```bash
uv run pytest -q -k TestAgainstSklearn
uv run pytest -q -k TestEngineering
```

Полного совпадения деревьев со scikit-learn тесты не требуют: при равном выигрыше scikit-learn выбирает
разбиение иначе, чем задано в нашей спецификации. Проверяется близость качества и доля совпавших
предсказаний.

## Замеры для отчёта

Сравните свою реализацию со scikit-learn и запишите результаты в `README.md` проекта.

1. **Скорость обучения.** Время `fit` для 1 000, 10 000 и 100 000 объектов при 10 признаках
   и `max_depth=8` — ваше дерево и `DecisionTreeClassifier`. Во сколько раз scikit-learn быстрее?
   Как время растёт с числом объектов?
2. **Где тратится время.** Профилируйте `fit` на 100 000 объектов (урок 1.2.3). Какая доля времени
   уходит на сортировку, какая — на накопленные суммы, какая — на рекурсию?
3. **Качество.** На данных об оттоке из темы 3.1: точность, log loss и ROC-AUC на тесте для вашего дерева
   и дерева scikit-learn при `max_depth=5, min_samples_leaf=50`.
4. **Сортировка один раз.** Сейчас каждый узел сортирует свои объекты заново. Оцените, сколько времени
   сэкономила бы однократная предварительная сортировка каждого признака.

## Идеи для усложнения

1. **Регрессия.** Напишите `MyDecisionTreeRegressor` с критерием дисперсии. Накопленные суммы значений
   и их квадратов позволяют считать дисперсию обоих потомков для всех порогов без циклов. Сверьте
   с `DecisionTreeRegressor`.
2. **Обрезка.** Реализуйте обрезку по стоимости сложности: для каждого внутреннего узла вычислите
   значение $\alpha$, при котором его поддерево выгоднее заменить листом, и срезайте слабейшие звенья
   (урок 4.1.3). Сверьте последовательность $\alpha$ с `cost_complexity_pruning_path`.
3. **Важность признаков.** Добавьте атрибут `feature_importances_` (урок 4.1.2) и сверьте со scikit-learn
   на дереве ограниченной глубины.
4. **Пропуски.** Научите `best_split` работать с `nan`: для каждого порога попробуйте отправить все
   объекты с пропуском влево и вправо и выберите лучший вариант.
5. **Гистограммы.** Замените точный перебор порогов перебором по 255 корзинам: разбейте каждый признак
   на квантили один раз до обучения. Сравните скорость и качество. Вы только что реализовали основную
   идею LightGBM (урок 4.3.2).
6. **Печать дерева.** Напишите аналог `export_text` и функцию, которая для объекта возвращает путь от корня
   до листа в виде списка условий на русском языке.
