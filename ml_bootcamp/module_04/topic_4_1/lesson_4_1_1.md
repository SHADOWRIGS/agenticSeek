## Зачем это нужно

Одно дерево решений редко бывает лучшей моделью. Но случайный лес и градиентный бустинг — модели, которые
побеждают на табличных данных чаще всех остальных, — это сотни и тысячи деревьев. Все их сильные и слабые
стороны унаследованы от одного дерева: нечувствительность к масштабу признаков, умение находить
взаимодействия, неспособность экстраполировать, склонность к переобучению. Не понимая одного дерева,
ансамбли можно только настраивать вслепую.

Вторая причина — интерпретируемость. Неглубокое дерево — единственная модель, которую можно распечатать
на одной странице и отдать юристу, врачу или аудитору.

## 1. Дерево как набор правил

Данные — клиенты провайдера из темы 3.1 (скопируйте `churn_data.py` из папки `module_03/topic_3_1`).

```python
import numpy as np
import pandas as pd
from churn_data import make_clients
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text

clients = make_clients()
X = pd.DataFrame(
    {
        "tenure_months": clients["tenure_months"],
        "fee_k": clients["monthly_fee"] / 1000,
        "services": clients["services"],
        "annual": (clients["contract"] == "annual").astype(int),
        "autopay": clients["autopay"].astype(int),
        "support_calls": clients["support_calls"],
    }
)
y = clients["churn"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

tree = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X_train, y_train)
print(export_text(tree, feature_names=list(X.columns)))
```

```
|   |   |--- tenure_months <= 30.50
|   |   |   |--- class: 0
|   |   |--- tenure_months >  30.50
|   |   |   |--- class: 0
|   |--- support_calls >  2.50
|   |   |--- support_calls <= 4.50
|   |   |   |--- class: 1
|   |   |--- support_calls >  4.50
|   |   |   |--- class: 1
|--- annual >  0.50
|   |--- support_calls <= 3.50
|   |   |--- autopay <= 0.50
|   |   |   |--- class: 0
|   |   |--- autopay >  0.50
|   |   |   |--- class: 0
|   |--- support_calls >  3.50
|   |   |--- fee_k <= 0.99
|   |   |   |--- class: 0
|   |   |--- fee_k >  0.99
|   |   |   |--- class: 1
```

Терминология:

- **корень** — первый вопрос (`annual <= 0.5`), через него проходят все объекты;
- **внутренний узел** — вопрос вида «признак ≤ порог»;
- **лист** — конечный узел с ответом;
- **глубина** — число вопросов на самом длинном пути от корня до листа.

Дерево читается как вложенные «если — то». Клиент с помесячным контрактом и тремя и более обращениями
в поддержку получает прогноз «уйдёт». Модель сама нашла то, что в логистической регрессии пришлось бы
добавлять вручную: порог по числу обращений и то, что этот порог разный для разных типов контракта
(2.5 и 3.5), — то есть **взаимодействие признаков**.

Два листа с одинаковым классом под одним узлом — не ошибка: листья различаются долей ушедших, а значит,
предсказанной вероятностью (`predict_proba`).

## 2. Алгоритм построения

Найти наилучшее дерево перебором невозможно: число деревьев растёт сверхэкспоненциально. Все практические
алгоритмы — жадные:

```
построить_узел(объекты):
    если выполнено условие остановки:
        вернуть лист с ответом по объектам
    перебрать все признаки и все пороги
    выбрать разбиение, после которого две группы наиболее однородны
    левый потомок  = построить_узел(объекты, где признак <= порог)
    правый потомок = построить_узел(остальные объекты)
```

Три составляющие:

1. **Мера неоднородности** группы. Для классификации чаще всего — индекс Джини; для двух классов
   с долей положительных $p$ он равен $2p(1-p)$: ноль, когда все объекты одного класса, и максимум 0.5
   при равных долях. Меры подробно разбираются в следующем уроке.
2. **Качество разбиения** — взвешенная неоднородность потомков:
   $\frac{n_{left}}{n} G_{left} + \frac{n_{right}}{n} G_{right}$. Чем меньше, тем лучше.
3. **Условие остановки**: все объекты одного класса, достигнута максимальная глубина, в узле слишком мало
   объектов. Этим управляют гиперпараметры (урок 4.1.3).

Ответ в листе: для классификации — самый частый класс и доли классов как вероятности; для регрессии —
среднее значение целевой переменной.

### Первый шаг вручную

Двенадцать клиентов:

| № | contract | calls | tenure | churn |
|---|---|---|---|---|
| 0 | monthly | 4 | 2 | 1 |
| 1 | monthly | 0 | 30 | 0 |
| 2 | annual | 1 | 24 | 0 |
| 3 | monthly | 3 | 5 | 1 |
| 4 | annual | 0 | 40 | 0 |
| 5 | monthly | 5 | 3 | 1 |
| 6 | annual | 2 | 12 | 0 |
| 7 | monthly | 1 | 8 | 1 |
| 8 | monthly | 3 | 20 | 1 |
| 9 | annual | 4 | 6 | 1 |
| 10 | monthly | 0 | 15 | 0 |
| 11 | annual | 0 | 50 | 0 |

Ушли шестеро из двенадцати: индекс Джини в корне равен $2 \cdot 0.5 \cdot 0.5 = 0.5$.

Кандидаты в разбиения для числового признака — середины между соседними различными значениями. Для `calls`
это 0.5, 1.5, 2.5, 3.5, 4.5. Посчитаем один вручную, `calls <= 2.5`:

- слева 7 клиентов (№ 1, 2, 4, 6, 7, 10, 11), ушёл один: $G = 2 \cdot \frac{1}{7} \cdot \frac{6}{7} = 0.245$;
- справа 5 клиентов (№ 0, 3, 5, 8, 9), ушли все: $G = 0$;
- взвешенное значение: $\frac{7}{12} \cdot 0.245 + \frac{5}{12} \cdot 0 = 0.143$.

Перебор всех кандидатов:

```python
def gini(y):
    p = y.mean()
    return 2 * p * (1 - p)


def split_score(y, mask):
    n = len(y)
    return mask.sum() / n * gini(y[mask]) + (~mask).sum() / n * gini(y[~mask])
```

| Разбиение | Взвешенный Джини | Слева / справа |
|---|---|---|
| `calls <= 2.5` | **0.143** | 7 / 5 |
| `tenure <= 10` | **0.143** | 5 / 7 |
| `tenure <= 7` | 0.250 | 4 / 8 |
| `calls <= 0.5` | 0.250 | 4 / 8 |
| `tenure <= 22` | 0.250 | 8 / 4 |
| `calls <= 1.5` | 0.278 | 6 / 6 |
| `contract = annual` | 0.371 | 5 / 7 |
| … | | |

Два разбиения делят первое место. Алгоритм возьмёт одно из них — scikit-learn выбрал `calls <= 2.5`.
Дальше процедура повторяется для каждой половины отдельно. Правая уже однородна — это лист. В левой
(7 клиентов, один ушедший) разбиение `tenure <= 10` отделяет ушедшего клиента № 7 идеально:

```
|--- calls <= 2.50
|   |--- tenure <= 10.00
|   |   |--- class: 1
|   |--- tenure >  10.00
|   |   |--- class: 0
|--- calls >  2.50
|   |--- class: 1
```

Три листа, ошибок на обучающих данных нет. Заметьте: признак `contract` в дерево не попал, хотя связан
с оттоком, — на каждом шаге находился признак лучше.

### Цена перебора

Для каждого узла нужно для каждого признака отсортировать значения и пройти по порогам, обновляя счётчики
классов. Обучение дерева стоит порядка $p \cdot n \log n$ операций на уровень. Замеры для дерева глубины 10
на 10 признаках:

| Объектов | Обучение | Предсказание для всех объектов |
|---|---|---|
| 10 000 | 0.13 с | 0.001 с |
| 100 000 | 1.16 с | 0.013 с |
| 1 000 000 | 17 с | 0.13 с |

Предсказание — это несколько сравнений на объект, поэтому деревья очень быстры на инференсе. Обучение на
миллионах строк с точным перебором порогов уже ощутимо; библиотеки бустинга ускоряют его, заменяя точные
пороги гистограммами (тема 4.3).

## 3. CART, ID3, C4.5

Описанная схема — общая. Исторически сложилось несколько алгоритмов, отличающихся деталями.

| | ID3 | C4.5 | CART |
|---|---|---|---|
| Автор, год | Куинлан, 1986 | Куинлан, 1993 | Брейман и др., 1984 |
| Задачи | классификация | классификация | классификация и регрессия |
| Разбиения | по числу значений категории | многозначные для категорий, бинарные для чисел | только бинарные |
| Критерий | прирост информации | отношение прироста информации | Джини; MSE для регрессии |
| Числовые признаки | нет | да, порогом | да, порогом |
| Пропуски | нет | да, распределяет объект по ветвям долями | да, суррогатные разбиения |
| Обрезка | нет | да, по оценке ошибки | да, по стоимости сложности |

**Что реализовано в scikit-learn:** оптимизированный вариант CART — бинарные разбиения, критерии Джини,
энтропия или MSE. Два отличия от оригинала: категориальные признаки напрямую не поддерживаются (строки
нужно закодировать числами, иначе `ValueError: could not convert string to float`), а пропуски обрабатываются
не суррогатными разбиениями — объекты с пропуском целиком направляются в ту ветвь, где это даёт лучшее
качество.

### Зачем C4.5 понадобилось отношение прироста

ID3 делит узел по категориальному признаку на столько ветвей, сколько у него значений, и выбирает признак
с наибольшим **приростом информации** — уменьшением энтропии. У этого критерия есть дефект: он любит
признаки с большим числом значений. Добавим к двенадцати клиентам идентификатор клиента:

| Признак | Ветвей | Прирост информации | Отношение прироста |
|---|---|---|---|
| `contract` | 2 | 0.196 | 0.200 |
| `calls` выше 2.5 | 2 | 0.655 | 0.668 |
| `client_id` | 12 | **1.000** | 0.279 |

Разбиение по идентификатору создаёт двенадцать листьев по одному клиенту — «идеально чистых» и абсолютно
бесполезных для новых клиентов. Прирост информации максимален. C4.5 делит прирост на энтропию самого
разбиения (чем больше ветвей, тем она выше), и идентификатор теряет первое место.

CART этой проблемы избегает иначе: разбиения только бинарные. Но она возвращается в другом виде: признак
с большим числом различных значений имеет больше порогов-кандидатов и чаще случайно находит «удачный».
Это искажает оценки важности признаков — вернёмся к этому в уроке 4.2.1.

## 4. Свойства, которые следуют из алгоритма

### Масштаб признаков не важен

Разбиение зависит только от порядка значений признака. Любое монотонное преобразование — умножение,
логарифм, стандартизация — меняет пороги, но не разбиения.

```python
X_scaled = X_train.assign(fee_k=X_train["fee_k"] * 1000, tenure_months=np.log1p(X_train["tenure_months"]))
```

Дерево, обученное на преобразованных признаках, даёт на тесте в точности те же предсказания. Деревьям
не нужны `StandardScaler` и логарифмирование признаков, а выбросы в признаках им почти безразличны.

### Границы параллельны осям

Каждый вопрос касается одного признака, поэтому дерево режет пространство прямоугольниками. Пусть класс
определяется условием $x_1 + x_2 > 1$ — граница идёт по диагонали:

| Модель | Листьев | Точность на тесте |
|---|---|---|
| Дерево глубины 1 | 2 | 0.740 |
| Дерево глубины 2 | 4 | 0.858 |
| Дерево глубины 4 | 15 | 0.951 |
| Дерево без ограничений | 48 | 0.978 |
| Логистическая регрессия | — | 0.999 |
| Дерево глубины 1 на признаке $x_1 + x_2$ | 2 | 1.000 |

Дерево приближает диагональ «лесенкой» из 48 листьев и всё равно проигрывает линейной модели с тремя
параметрами. Один правильно построенный признак решает задачу единственным вопросом. Вывод на всю работу
с ансамблями: **построение признаков деревьям по-прежнему нужно** — суммы, разности и отношения признаков
они сами не находят.

### Жадность

Алгоритм выбирает лучшее разбиение на текущем шаге и не заглядывает вперёд. Классический контрпример —
«исключающее или»: класс равен 1, когда признаки $x_1$ и $x_2$ разного знака. По отдельности ни один
из них ничего не говорит о классе; добавим ещё три шумовых признака.

| Глубина | Точность на обучении | Точность на тесте |
|---|---|---|
| 1 | 0.529 | 0.475 |
| 2 | 0.743 | 0.762 |
| 3 | 0.998 | 0.993 |
| 4 | 1.000 | 0.995 |

Лучший выигрыш в индексе Джини в корне — 0.003 при исходном значении 0.5: первый вопрос выбирается
практически наугад. Идеальное дерево для этой задачи имеет глубину 2, жадному понадобилась глубина 3.
Здесь данных много, и дерево справилось; на малых данных с большим числом шумовых признаков первый шаг
может уйти по шуму. Линейная модель эту задачу не решает вовсе: точность логистической регрессии — 0.495.

### Кусочно-постоянные предсказания

Дерево регрессии предсказывает в каждом листе константу — среднее по объектам листа. Обучим его на
зависимости $y = 2x + 5$ при $x$ от 0 до 10 и спросим про значения за пределами этого диапазона:

| $x$ | Истина | Дерево глубины 4 | Линейная регрессия |
|---|---|---|---|
| 2 | 9.0 | 8.98 | 9.02 |
| 5 | 15.0 | 15.18 | 15.02 |
| 9.9 | 24.8 | 24.75 | 24.82 |
| 12 | 29.0 | 24.75 | 29.01 |
| 15 | 35.0 | 24.75 | 35.01 |
| 20 | 45.0 | 24.75 | 45.00 |

**Деревья не экстраполируют.** За пределами обучающих данных предсказание равно значению крайнего листа.
Дерево (и любой ансамбль деревьев) никогда не предскажет значение больше максимального или меньше
минимального из тех, что видело. Для задач с трендом — продажи растущей компании, цены — это принципиальное
ограничение; его обходят, предсказывая не саму величину, а её изменение или отношение к недавнему уровню.

### Переобучение

Дерево без ограничений растёт, пока в каждом листе не останутся объекты одного класса.

| Глубина | Листьев | Точность на обучении | Точность на тесте |
|---|---|---|---|
| 1 | 2 | 0.645 | 0.645 |
| 2 | 4 | 0.704 | 0.693 |
| 3 | 8 | 0.705 | 0.692 |
| 5 | 32 | 0.729 | 0.711 |
| 8 | 185 | 0.766 | 0.687 |
| 12 | 703 | 0.864 | 0.645 |
| без ограничений | 1 336 | 0.956 | 0.646 |

Дерево с 1 336 листьями на 3 500 обучающих клиентов запомнило выборку — и на тесте работает не лучше
предсказания «никто не уйдёт» (0.645). Лучшее дерево, глубины 5, достигает 0.711; логистическая регрессия
на тех же данных — 0.714. Борьбе с переобучением посвящён урок 4.1.3.

### Неустойчивость

Обучим дерево глубины 4 двадцать раз на случайных 90 % обучающих данных и сравним предсказания на тесте
с деревом, обученным на всех данных:

| Модель | Совпадение предсказаний: в среднем | в худшем случае |
|---|---|---|
| Дерево глубины 4 | 95.6 % | 77.5 % |
| Логистическая регрессия | 99.0 % | 97.7 % |

Удаление десятой части данных в худшем случае изменило прогноз дерева почти для четверти клиентов.
Первые два вопроса во всех двадцати деревьях совпали; различия появляются глубже, где объектов в узлах
меньше и выбор разбиения решают единицы наблюдений. Неустойчивость — главный недостаток одиночного дерева
и одновременно то, на чём построен случайный лес: если модели сильно различаются от выборки к выборке,
их усреднение многое даёт (тема 4.2).

## 5. Итог: сильные и слабые стороны

| Сильные стороны | Слабые стороны |
|---|---|
| Не требует масштабирования и преобразования признаков | Переобучается без ограничений |
| Находит пороги и взаимодействия сам | Неустойчиво к изменению данных |
| Работает с пропусками | Плохо приближает линейные и диагональные зависимости |
| Устойчиво к выбросам в признаках | Не экстраполирует |
| Неглубокое дерево полностью интерпретируемо | Жадное построение не гарантирует лучшего дерева |
| Быстрое предсказание | Одиночное дерево обычно уступает по качеству ансамблям |

Одиночное дерево выбирают, когда нужны правила, понятные человеку: медицинские протоколы, скоринговые
карты, объяснение сегментов. Когда нужно качество — ансамбли.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Точность на обучении около 100 %, на тесте — как у константы | дерево без ограничений запомнило выборку | ограничить глубину и размер листа (урок 4.1.3) |
| `ValueError: could not convert string to float` | категориальный признак передан строками | закодировать числами: порядковое или one-hot кодирование |
| Прогноз продаж не растёт вместе с трендом | деревья не экстраполируют | предсказывать прирост или отношение, а не уровень |
| Дерево огромное, а качество посредственное | зависимость линейная или диагональная | добавить признаки-комбинации; сравнить с линейной моделью |
| Дерево полностью изменилось после добавления данных | неустойчивость одиночного дерева | не интерпретировать глубокие уровни; использовать ансамбль |
| Идентификатор или дата оказались самым важным признаком | у признака много уникальных значений, он позволяет запомнить объекты | убрать идентификаторы из признаков |
| Признаки зря стандартизованы перед деревом | перенос привычки от линейных моделей | деревьям масштабирование не нужно |
| Признак с очевидной связью не попал в дерево | на каждом шаге находился признак сильнее; информация дублируется | это не значит, что признак бесполезен |
