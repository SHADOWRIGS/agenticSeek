## Цели урока

После урока вы сможете:

- объяснить, почему дерево без ограничений переобучается всегда и почему дополнительные данные от этого
  не спасают;
- ограничивать рост дерева параметрами остановки и понимать, что делает каждый из них;
- обрезать уже построенное дерево по стоимости сложности и подбирать силу обрезки кросс-валидацией;
- выбирать параметры под нужную метрику — и видеть, что лучшие параметры для точности и для качества
  вероятностей разные.

## Зачем это нужно

Параметры, которые вы разберёте на одном дереве, — `max_depth`, `min_samples_leaf`, `max_leaf_nodes`,
`min_impurity_decrease` — это те же параметры, которые вы будете подбирать в случайном лесе, XGBoost,
LightGBM и CatBoost, иногда под другими именами. На одном дереве их действие видно напрямую: можно
распечатать дерево и посмотреть, что изменилось. На ансамбле из тысячи деревьев — уже нет.

Данные и разбиение на обучение и тест — те же, что в уроке 4.1.1: 3 500 клиентов в обучении, 1 500 в тесте.

## 1. Что происходит с деревом без ограничений

```python
from sklearn.metrics import log_loss, roc_auc_score
from sklearn.tree import DecisionTreeClassifier

full = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
```

| Показатель | Значение |
|---|---|
| Листьев | 1 336 |
| Глубина | 26 |
| Точность на обучении | 0.956 |
| Точность на тесте | 0.646 |
| Точность ответа «никто не уйдёт» | 0.645 |
| ROC-AUC на тесте | 0.615 |
| Log loss на тесте | **12.0** |
| Log loss предсказания средним | 0.651 |

Дерево на 3 500 клиентов завело 1 336 листьев — в среднем по 2.6 клиента на лист. Лист из двух-трёх
клиентов — это не закономерность, а запись о конкретных людях.

Особенно показателен log loss. В листе с одним-двумя объектами доля класса равна 0 или 1, и дерево
выдаёт абсолютно уверенные предсказания: у 94 % тестовых клиентов вероятность ухода равна ровно 0 или
ровно 1. Каждая уверенная ошибка стоит в log loss очень дорого — отсюда 12.0 при 0.651 у предсказания,
одинакового для всех. **Вероятности необрезанного дерева бесполезны.**

### Больше данных не помогает

У большинства моделей переобучение лечится данными. Проверим:

| Клиентов в обучении | Дерево без ограничений: листьев | точность на тесте | Ограниченное дерево: листьев | точность на тесте |
|---|---|---|---|---|
| 200 | 64 | 0.621 | 3 | 0.690 |
| 500 | 161 | 0.631 | 8 | 0.691 |
| 1 000 | 363 | 0.625 | 15 | 0.711 |
| 2 000 | 713 | 0.620 | 19 | 0.715 |
| 3 500 | 1 336 | 0.646 | 22 | 0.707 |

Число листьев дерева без ограничений растёт пропорционально объёму данных: сложность модели ничем
не ограничена, и новые данные она тратит на новые листья, а не на уточнение старых. Качество стоит на месте.
Ограниченное дерево (`max_depth=5, min_samples_leaf=50`) с ростом данных улучшается.

Способов ограничить сложность два: не дать дереву вырасти (ранняя остановка) или вырастить и обрезать.

## 2. Ранняя остановка

| Параметр | Что ограничивает | По умолчанию |
|---|---|---|
| `max_depth` | число вопросов от корня до листа | нет ограничения |
| `min_samples_leaf` | минимальное число объектов в листе | 1 |
| `min_samples_split` | минимальное число объектов в узле, который разрешено делить | 2 |
| `max_leaf_nodes` | общее число листьев | нет ограничения |
| `min_impurity_decrease` | минимальный выигрыш, ради которого делается разбиение | 0 |

Действие каждого на наших данных:

| Параметр | Листьев | Обучение | Тест | Log loss | ROC-AUC |
|---|---|---|---|---|---|
| без ограничений | 1 336 | 0.956 | 0.646 | 12.007 | 0.615 |
| `max_depth=3` | 8 | 0.705 | 0.692 | 0.575 | 0.723 |
| `max_depth=5` | 32 | 0.729 | 0.711 | 0.588 | 0.745 |
| `max_depth=8` | 185 | 0.766 | 0.687 | 1.627 | 0.721 |
| `min_samples_leaf=5` | 465 | 0.805 | 0.664 | 2.641 | 0.689 |
| `min_samples_leaf=20` | 130 | 0.753 | 0.691 | 0.711 | 0.739 |
| `min_samples_leaf=50` | 52 | 0.736 | 0.715 | 0.571 | 0.744 |
| `min_samples_leaf=100` | 27 | 0.726 | 0.703 | **0.565** | 0.741 |
| `min_samples_leaf=300` | 9 | 0.711 | 0.711 | 0.570 | 0.735 |
| `max_leaf_nodes=8` | 8 | 0.715 | 0.715 | 0.568 | 0.736 |
| `max_leaf_nodes=32` | 32 | 0.741 | 0.715 | 0.573 | 0.736 |
| `min_impurity_decrease=0.001` | 19 | 0.731 | 0.710 | 0.568 | 0.736 |

Что здесь важно.

**`max_depth` — грубый инструмент.** Он ограничивает все ветви одинаково, хотя в одной части данных
закономерности простые, а в другой сложные. При `max_depth=5` дерево даёт лучшую точность, но log loss
хуже, чем при глубине 3: среди 32 листьев появились листья из нескольких объектов с вероятностями 0 и 1.
При глубине 8 таких листьев много, и log loss подскакивает до 1.63.

**`min_samples_leaf` — главный параметр для вероятностей.** Доля класса, посчитанная по 100 объектам,
— осмысленная оценка вероятности; по трём — нет. Ограничение на размер листа одновременно ограничивает
сложность и делает вероятности надёжными. Заметьте: при `min_samples_leaf=50` глубина дерева достигает 10
— оно растёт вглубь там, где данных много, и останавливается там, где их мало.

**`max_leaf_nodes` меняет порядок построения.** Без этого параметра дерево строится в глубину. С ним —
«лучший первым»: на каждом шаге делится тот лист, разбиение которого даёт наибольший выигрыш. Восемь
листьев, выбранных таким способом, дают 0.715 на тесте; восемь листьев дерева глубины 3 — 0.692. Этот же
способ роста использует LightGBM (урок 4.3.2).

**`min_impurity_decrease` страдает от близорукости.** Разбиение с малым выигрышем может открывать дорогу
отличному следующему разбиению — вспомните «исключающее или» из урока 4.1.1, где первый шаг не даёт почти
ничего. Порог на выигрыш такие ветви отсекает. Обрезка построенного дерева лишена этого недостатка.

## 3. Обрезка по стоимости сложности

Идея: вырастить полное дерево и срезать ветви, которые не оправдывают своей сложности. Для дерева $T$
вводится штрафованная ошибка

$$R_\alpha(T) = R(T) + \alpha \cdot |T|$$

где $R(T)$ — суммарная неоднородность листьев на обучающих данных, $|T|$ — число листьев, $\alpha \ge 0$ —
цена одного листа. При $\alpha = 0$ лучшее дерево — полное. С ростом $\alpha$ выгоднее становятся
всё меньшие деревья.

Алгоритм «слабейшего звена»: для каждого внутреннего узла вычисляется, при каком $\alpha$ замена его
поддерева одним листом перестаёт увеличивать $R_\alpha$. Узел с наименьшим таким значением срезается
первым, затем следующий — получается последовательность вложенных деревьев от полного до одного корня.

```python
path = DecisionTreeClassifier(random_state=0).cost_complexity_pruning_path(X_train, y_train)
len(path.ccp_alphas)        # 524 значения: от 0 до 0.046
```

Каждому значению `ccp_alpha` соответствует своё дерево:

| `ccp_alpha` | Листьев | Обучение | Тест | Log loss | ROC-AUC |
|---|---|---|---|---|---|
| 0 | 1 336 | 0.956 | 0.646 | 12.007 | 0.615 |
| 0.0002 | 754 | 0.908 | 0.657 | 7.968 | 0.622 |
| 0.0005 | 79 | 0.767 | 0.691 | 0.886 | 0.722 |
| 0.001 | 19 | 0.731 | 0.710 | 0.568 | 0.736 |
| 0.002 | 8 | 0.715 | 0.715 | 0.568 | 0.736 |
| 0.005 | 4 | 0.704 | 0.693 | 0.585 | 0.705 |
| 0.01 | 3 | 0.704 | 0.693 | 0.589 | 0.693 |
| 0.03 | 2 | 0.645 | 0.645 | 0.603 | 0.655 |

Переход от 0.0002 к 0.001 сокращает дерево с 754 листьев до 19. Обрезка работает как регуляризация
в линейных моделях (урок 3.1.1): один параметр плавно переводит модель от переобученной к недообученной.

Совпадение с ранней остановкой не случайно: дерево при `ccp_alpha=0.002` и дерево при `max_leaf_nodes=8`
на этих данных совпадают по всем показателям, как и деревья из 19 листьев при `ccp_alpha=0.001`
и `min_impurity_decrease=0.001`. Когда в данных нет «скрытых» разбиений вроде исключающего или,
обрезка и остановка приводят к близким результатам.

## 4. Подбор параметров

Параметры выбирают по качеству на данных, которые не участвовали в обучении. Тестовую выборку для этого
использовать нельзя — она останется единственной честной оценкой итоговой модели. Используем
кросс-валидацию на обучающей части.

```python
from sklearn.model_selection import GridSearchCV, StratifiedKFold

cv = StratifiedKFold(5, shuffle=True, random_state=0)
search = GridSearchCV(
    DecisionTreeClassifier(random_state=0),
    {"ccp_alpha": np.geomspace(1e-4, 2e-2, 25)},
    cv=cv,
    scoring="neg_log_loss",
).fit(X_train, y_train)
```

| `ccp_alpha` | Log loss на кросс-валидации | Стандартная ошибка |
|---|---|---|
| 0.0001 | 12.371 | 0.246 |
| 0.0002 | 8.565 | 0.172 |
| 0.0006 | 1.241 | 0.073 |
| 0.0014 | 0.586 | 0.031 |
| 0.0018 | **0.560** | 0.004 |
| 0.0034 | 0.563 | 0.005 |
| 0.0083 | 0.570 | 0.003 |
| 0.0200 | 0.597 | 0.003 |

Лучшее значение — 0.0018: дерево из 9 листьев, точность на тесте 0.715, log loss 0.569.

**Правило одной стандартной ошибки.** Оценка на кросс-валидации — случайная величина. Значения 0.560
и 0.563 неразличимы: разница меньше стандартной ошибки. Правило: из всех моделей, качество которых
отличается от лучшего не больше чем на одну стандартную ошибку, выбрать самую простую. Здесь это
`ccp_alpha=0.0034` — дерево из пяти листьев. На тесте оно чуть хуже (точность 0.693, log loss 0.580),
зато его можно прочитать вслух. Правило применяют, когда простота модели имеет самостоятельную ценность.

### Метрика определяет ответ

Переберём сетку из `max_depth` и `min_samples_leaf` и выберем лучшую пару по двум метрикам:

| Метрика подбора | Лучшие параметры |
|---|---|
| Log loss | `max_depth=8`, `min_samples_leaf=100` |
| Точность | `max_depth=6`, `min_samples_leaf=25` |

Log loss на кросс-валидации по всей сетке:

| `max_depth` \ `min_samples_leaf` | 1 | 10 | 25 | 50 | 100 | 200 |
|---|---|---|---|---|---|---|
| 3 | 0.593 | 0.593 | 0.564 | 0.563 | 0.563 | 0.566 |
| 4 | 0.586 | 0.586 | 0.558 | 0.558 | 0.561 | 0.564 |
| 5 | 0.720 | 0.661 | 0.609 | 0.606 | 0.557 | 0.562 |
| 6 | 1.018 | 0.786 | 0.628 | 0.607 | 0.557 | 0.562 |
| 8 | 2.469 | 1.135 | 0.714 | 0.610 | 0.557 | 0.562 |
| без ограничений | 12.562 | 1.375 | 0.718 | 0.610 | 0.557 | 0.562 |

Таблица читается так:

- при листьях от 100 объектов глубина перестаёт что-либо значить: дерево останавливается само;
- при мелких листьях каждая дополнительная единица глубины резко ухудшает вероятности;
- для точности достаточно, чтобы в листе правильно определялось большинство, поэтому она терпит мелкие
  листья; для вероятностей нужна надёжная оценка доли, поэтому log loss требует крупных.

Если модель используется для ранжирования клиентов или расчёта ожидаемой выгоды (практика 3.2.4),
подбирать параметры нужно по log loss или ROC-AUC, а не по точности.

## 5. Насколько хорошо лучшее дерево

| Модель | Точность на тесте | Log loss | ROC-AUC |
|---|---|---|---|
| Дерево без ограничений | 0.646 | 12.007 | 0.615 |
| Лучшее дерево (`min_samples_leaf=100`) | 0.703 | 0.565 | 0.741 |
| Логистическая регрессия | 0.715 | 0.548 | 0.761 |

Обрезка превратила бесполезную модель в рабочую, но логистическая регрессия всё равно лучше. Это честный
результат: данные об оттоке сгенерированы моделью, линейной в логарифме шансов, и ступенчатая функция
из 27 листьев приближает её хуже, чем сама линейная модель. На данных с порогами и взаимодействиями
картина обратная.

Одно дерево — компромисс: чтобы не переобучаться, оно должно быть маленьким, а маленькое дерево — грубая
модель. Ансамбли снимают это противоречие двумя способами: случайный лес усредняет много глубоких
переобученных деревьев (тема 4.2), бустинг складывает много мелких (тема 4.3).

## 6. Практические рекомендации

1. **Никогда не оставляйте параметры по умолчанию.** `DecisionTreeClassifier()` без аргументов — это
   дерево без ограничений.
2. **Начинайте с `min_samples_leaf`.** Разумный старт — 1–3 % от размера обучающей выборки; затем
   уточняйте по кросс-валидации.
3. **Если нужны вероятности** — подбирайте по log loss и не допускайте листьев меньше нескольких
   десятков объектов.
4. **Если нужно объяснимое дерево** — `max_leaf_nodes` или `ccp_alpha` с правилом одной стандартной
   ошибки: они дают лучшее дерево заданного размера.
5. **`max_depth` — как страховка**, а не как основной параметр.
6. **Сравнивайте с простой базовой линией**: логистической регрессией и предсказанием средним.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Точность на обучении близка к 100 %, на тесте — как у константы | дерево с параметрами по умолчанию | `min_samples_leaf`, `ccp_alpha` или `max_leaf_nodes` |
| Log loss в разы хуже, чем у предсказания средним | листья из одного-двух объектов дают вероятности 0 и 1 | увеличить `min_samples_leaf` |
| Параметры подобраны, а на новых данных качество ниже | параметры выбирались по тестовой выборке | подбор — кросс-валидацией на обучающей части, тест — один раз в конце |
| «Лучшая» глубина меняется от запуска к запуску | разница между вариантами меньше шума оценки | смотреть на стандартную ошибку; правило одной стандартной ошибки |
| Модель подобрана по точности, а используется для ранжирования | метрика подбора не соответствует применению | подбирать по log loss или ROC-AUC |
| Добавили данных — дерево выросло, качество не изменилось | сложность не ограничена | ограничить размер листа относительно объёма данных |
| `min_impurity_decrease` обрезает дерево до пня | порог слишком велик для данных | взять значения из `cost_complexity_pruning_path` как ориентир масштаба |
| Обрезанное дерево всё равно хуже линейной модели | зависимость в данных гладкая или линейная | это свойство задачи; использовать линейную модель или ансамбль |
