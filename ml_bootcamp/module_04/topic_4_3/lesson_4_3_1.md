## 1. Бустинг: каждое дерево исправляет ошибки предыдущих

Модель бустинга — сумма деревьев: $F_M(x) = F_0 + \eta \sum_{m=1}^{M} f_m(x)$, где $F_0$ — константа,
$\eta$ — шаг обучения. Деревья строятся по одному. Для квадратичной ошибки рецепт простой: посчитать, на
сколько текущая модель ошибается на каждом объекте, и обучить следующее дерево предсказывать эту ошибку.

```python
import numpy as np
from sklearn.tree import DecisionTreeRegressor


class MyBoosting:
    def __init__(self, n_estimators=100, learning_rate=0.1, max_depth=3):
        self.n_estimators, self.learning_rate, self.max_depth = n_estimators, learning_rate, max_depth

    def fit(self, X, y):
        self.init_ = float(np.mean(y))
        pred = np.full(len(y), self.init_)
        self.trees_ = []
        for _ in range(self.n_estimators):
            residual = y - pred  # то, что модель пока не объяснила
            tree = DecisionTreeRegressor(max_depth=self.max_depth, random_state=0).fit(X, residual)
            pred += self.learning_rate * tree.predict(X)
            self.trees_.append(tree)
        return self

    def predict(self, X):
        return self.init_ + self.learning_rate * sum(tree.predict(X) for tree in self.trees_)
```

RMSE на тесте: 2.843 после первого дерева, 1.870 после десяти, 0.980 после пятидесяти и 0.761 после двухсот
(константа даёт 3.053).

Сверка с `GradientBoostingRegressor(n_estimators=200, learning_rate=0.1, max_depth=3, random_state=0)`:
первые двадцать деревьев совпадают с точностью $10^{-15}$, итоговый RMSE — 0.761 у нас и 0.760 у scikit-learn.
После двадцатого дерева предсказания расходятся (на отдельных квартирах до 0.76 млн руб.): где-то нашлись
два равноценных разбиения, библиотеки выбрали разные, и все следующие деревья учились уже на разных
остатках. Деревья бустинга зависят друг от друга, поэтому мелкое расхождение не затухает, а качество
при этом одинаковое. Алгоритм — тот же самый.

## 2. Градиентный бустинг: спуск в пространстве функций

Остаток $y - F$ — это антиградиент квадратичной ошибки $\frac{1}{2}(y - F)^2$ по предсказанию $F$.
Отсюда обобщение (Фридман, 2001): считать предсказания на обучающих объектах параметрами, а очередное
дерево — шагом градиентного спуска. Дерево обучается на **антиградиенте функции потерь**
$r_i = -\partial L(y_i, F(x_i)) / \partial F$, и шаг получается одинаковым для объектов одного листа —
поэтому его можно сделать и для новых объектов.

| Задача | Что предсказывает сумма деревьев $F$ | Потери $L(y, F)$ | Антиградиент $r$ |
|---|---|---|---|
| Регрессия, MSE | само значение | $\frac{1}{2}(y - F)^2$ | $y - F$ |
| Классификация, log loss | логарифм шансов, $p = \sigma(F)$ | $-y \ln p - (1 - y)\ln(1 - p)$ | $y - p$ |
| Счётчики, пуассоновская | логарифм среднего, $\mu = e^F$ | $\mu - y \ln \mu$ | $y - \mu$ |

Во всех трёх строках антиградиент — «факт минус прогноз» в естественной шкале: те же обобщённые линейные
модели из урока 3.1.3, только вместо линейной комбинации признаков — сумма деревьев. Чтобы сменить
задачу, в коде достаточно заменить одну строку — `residual = y - sigmoid(pred)`. Проверим на оттоке
(100 деревьев глубины 3, шаг 0.1, log loss на тесте; у константы 0.651):

| Модель | Log loss | ROC-AUC |
|---|---|---|
| Логистическая регрессия | **0.548** | 0.761 |
| Наш бустинг на антиградиенте, шаг 0.1 | 0.558 | 0.757 |
| Наш бустинг на антиградиенте, шаг 1.0 | 0.553 | 0.757 |
| `GradientBoostingClassifier` | 0.549 | 0.759 |
| `XGBClassifier`, те же 100 деревьев глубины 3 и шаг 0.1 | 0.551 | 0.757 |
| `XGBClassifier()` с параметрами по умолчанию | 0.630 | 0.726 |

Три наблюдения. Первое: наш вариант отстаёт от библиотечных, потому что антиградиент log loss задаёт
направление, но не длину шага: при $p$, близком к 0 или 1, он мал, и модель движется медленно. Библиотеки
пересчитывают значения в листьях с учётом второй производной — об этом раздел 6. Второе: данные об оттоке
сгенерированы моделью, линейной в логарифме шансов, и логистическая регрессия остаётся лучшей — бустинг
не обязан выигрывать. Третье: XGBoost с параметрами по умолчанию проиграл всем и по log loss едва лучше
константы. Бустинг без настройки переобучается; почему — следующие разделы.

## 3. Бустинг снижает смещение — и поэтому переобучается

Лес и бустинг из одинаковых мелких деревьев глубины 3 (обучение на всех 3 500 объектах, RMSE):

| Деревьев | Лес: обучение | Лес: тест | Бустинг: обучение | Бустинг: тест |
|---|---|---|---|---|
| 1 | 1.650 | 1.777 | 2.850 | 2.843 |
| 10 | 1.550 | 1.630 | 1.817 | 1.870 |
| 100 | 1.556 | 1.643 | 0.623 | 0.828 |
| 1000 | 1.544 | 1.628 | 0.302 | **0.714** |

Усреднение не меняет смещения: лес из деревьев с восемью листьями остаётся грубой моделью, сколько бы
деревьев в нём ни было (урок 4.2.1). Бустинг складывает исправления: сумма тысячи восьмилистных деревьев —
гибкая функция. Сто мелких деревьев бустинга уже равны лесу из 300 глубоких (тест 0.826), тысяча —
заметно лучше.

Обратная сторона: у леса лишние деревья безвредны, у бустинга каждое новое дерево подгоняет модель
к обучающим данным ещё точнее. Кривые для деревьев глубины 4 (обучение на `X_fit`, проверка на `X_valid`):

| Деревьев | Шаг 0.1: обучение | Шаг 0.1: валидация | Шаг 1.0: обучение | Шаг 1.0: валидация |
|---|---|---|---|---|
| 1 | 2.795 | 2.906 | 1.323 | 1.372 |
| 10 | 1.539 | 1.603 | 0.707 | 0.969 |
| 30 | 0.833 | 0.940 | 0.499 | 1.011 |
| 100 | 0.477 | 0.675 | 0.234 | 1.081 |
| 300 | 0.308 | **0.658** | 0.033 | 1.112 |
| 1000 | 0.121 | 0.666 | 0.000 | 1.115 |
| 3000 | 0.014 | 0.670 | — | — |

Ошибка на обучении падает до нуля; на валидации проходит минимум (271 дерево при шаге 0.1, 19 деревьев
при шаге 1.0) и растёт. При малом шаге рост пологий: 0.656 в минимуме против 0.670 на 3000 деревьях. Это
типичная картина для регрессии; для log loss переобучение по числу деревьев обычно резче, потому что
уверенные ошибки стоят дорого. **Число деревьев в бустинге — параметр сложности, а не «чем больше, тем
лучше».**

## 4. Шаг обучения и число деревьев

Шаг $\eta$ (shrinkage, `learning_rate`) — доля, с которой каждое дерево входит в сумму. XGBoost, глубина 4,
число деревьев выбрано по валидации (как именно — в следующем разделе):

| `learning_rate` | Деревьев в минимуме | RMSE на валидации | RMSE на тесте |
|---|---|---|---|
| 1.0 | 8 | 0.928 | 0.959 |
| 0.5 | 36 | 0.685 | 0.768 |
| 0.2 | 79 | 0.640 | 0.740 |
| 0.1 | 402 | 0.623 | 0.721 |
| 0.05 | 514 | 0.635 | 0.723 |
| 0.02 | 1268 | 0.638 | 0.731 |
| 0.01 | 2878 | 0.635 | 0.725 |

Шаг и число деревьев связаны обратной зависимостью: вдвое меньше шаг — примерно вдвое больше деревьев.
Большой шаг вреден: первые деревья забирают слишком много и подгоняются под шум. Но «чем меньше, тем
лучше» здесь не видно: ниже 0.1 качество перестаёт меняться, разница между 0.721 и 0.731 — шум оценки
на 700 валидационных объектах. Практический вывод: шаг и число деревьев настраивают парой — шаг задают
(0.05–0.1 на время экспериментов), число деревьев подбирают ранней остановкой.

## 5. Ранняя остановка

Идея: после каждого дерева считать ошибку на отложенных данных и остановиться, когда она не улучшается
заданное число шагов подряд.

```python
import xgboost as xgb

model = xgb.XGBRegressor(
    n_estimators=5000,              # верхняя граница, а не число деревьев
    learning_rate=0.05,
    max_depth=4,
    early_stopping_rounds=100,      # терпение: сколько деревьев ждать улучшения
    random_state=0,
)
model.fit(X_fit, y_fit, eval_set=[(X_valid, y_valid)], verbose=False)
model.best_iteration + 1, model.best_score          # 514 деревьев, RMSE на валидации 0.635
```

| Вариант | Деревьев | RMSE на тесте |
|---|---|---|
| Без остановки, все 5000 деревьев | 5000 | 0.730 |
| Остановка по валидации | 514 | 0.723 |
| Остановка по тесту (**так нельзя**) | 652 | 0.719 |
| Переобучение на всей обучающей выборке с 514 деревьями | 514 | 0.700 |
| То же с запасом: 514 · 1.25 = 642 дерева | 642 | **0.694** |

Правила:

- **Останавливаться по тесту нельзя.** Число деревьев — гиперпараметр; выбрать его по тесту значит
  подогнать модель под тест. 0.719 в таблице — не оценка качества, а минимум из 5000 измерений на тех же
  данных. Нужна третья часть данных — валидационная. Если данные упорядочены по времени, валидация берётся
  из самого позднего периода обучения (урок 2.3.1).
- **Валидационные данные не пропадают.** Найдя число деревьев, модель переобучают на всей обучающей
  выборке. Данных стало на четверть больше, поэтому деревьев берут столько же или чуть больше.
- **Момент остановки — шумная величина.** Для пяти разных разбиений на обучение и валидацию он составил
  514, 478, 855, 524 и 614 деревьев, а RMSE на тесте — от 0.696 до 0.723. Надёжнее усреднять по фолдам:
  `xgb.cv` в разделе 9.

## 6. Что добавляет XGBoost: вторая производная и регуляризация

XGBoost (Чен и Гестрин, 2016) на шаге $t$ минимизирует потери вместе со штрафом за сложность нового
дерева $f$ с $T$ листьями и весами листьев $w_j$:

$$\sum_i L\bigl(y_i, F_{t-1}(x_i) + f(x_i)\bigr) + \gamma T + \frac{\lambda}{2}\sum_{j=1}^{T} w_j^2$$

Потери раскладываются в ряд Тейлора до второго порядка. Обозначим
$g_i = \partial L / \partial F$ и $h_i = \partial^2 L / \partial F^2$ в точке $F_{t-1}(x_i)$:

$$L\bigl(y_i, F_{t-1} + f\bigr) \approx L(y_i, F_{t-1}) + g_i f(x_i) + \tfrac{1}{2} h_i f(x_i)^2$$

Все объекты листа $j$ получают одно значение $w_j$. Пусть $G_j$ и $H_j$ — суммы $g_i$ и $h_i$ по листу.
Тогда вклад листа — парабола $G_j w_j + \frac{1}{2}(H_j + \lambda) w_j^2$ с минимумом в точке

$$w_j^* = -\frac{G_j}{H_j + \lambda}, \qquad \text{значение: } -\frac{1}{2}\,\frac{G_j^2}{H_j + \lambda}$$

Выигрыш от разбиения листа на левую и правую части — разность значений до и после минус плата за лист:

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda}
- \frac{(G_L + G_R)^2}{H_L + H_R + \lambda}\right] - \gamma$$

Это критерий разбиения XGBoost: вместо неоднородности из урока 4.1.2 — прямое уменьшение функции потерь.
Для MSE $g = F - y$, $h = 1$; для log loss $g = p - y$, $h = p(1 - p)$.

### Проверка на восьми точках

```python
x = np.arange(1.0, 9.0).reshape(-1, 1)
y = np.array([1.0, 1.4, 0.9, 3.1, 2.8, 3.3, 6.0, 5.6])
tree = xgb.XGBRegressor(n_estimators=1, max_depth=1, learning_rate=1.0, reg_lambda=1.0, base_score=0.0,
                        tree_method="exact", min_child_weight=0).fit(x, y)
tree.get_booster().trees_to_dataframe()
```

Стартовое предсказание 0, значит $g_i = -y_i$, $h_i = 1$, $\lambda = 1$. Вручную (четыре порога из семи):

| Порог | $G_L$ | $G_R$ | Выражение в скобках | $w_L$ | $w_R$ |
|---|---|---|---|---|---|
| 2.5 | −2.4 | −21.7 | 4.656 | 0.800 | 3.100 |
| 3.5 | −3.3 | −20.8 | **10.295** | 0.825 | 3.467 |
| 4.5 | −6.4 | −17.7 | 6.316 | 1.280 | 3.540 |
| 7.5 | −18.5 | −5.6 | −6.073 | 2.313 | 2.800 |

XGBoost построил: порог 3.5, `Gain = 10.294716`, листья 0.825 и 3.466667 — совпадение полное. Что видно
на этом примере:

- среднее в правом листе равно 4.16, а вес листа — 3.467: $\lambda$ стягивает веса к нулю, и тем сильнее,
  чем меньше объектов в листе. Это L2-регуляризация из урока 3.1.1, применённая к листьям;
- у порога 7.5 выражение в скобках отрицательное: из-за $\lambda$ отделять один объект невыгодно даже
  без платы за лист;
- столбец `Gain` в XGBoost — выражение в скобках без множителя $\frac{1}{2}$, и параметр `gamma`
  сравнивается именно с ним: при `gamma=10.2` разбиение делается, при `gamma=10.4` — нет, дерево остаётся
  одним листом с весом $24.1 / 9 = 2.678$. То есть `gamma` библиотеки — это $2\gamma$ из формулы;
- с `reg_alpha=2`, `reg_lambda=0` и шагом 0.3 листья равны 0.130 и 1.128: L1-штраф уменьшает $|G|$
  на $\alpha$ перед делением — $0.3 \cdot (3.3 - 2)/3$ и $0.3 \cdot (20.8 - 2)/5$;
- для классификации (`y = [0, 0, 1, 0, 1, 1, 1, 1]`, стартовая вероятность 0.5) $g = 0.5 - y$,
  $h = 0.25$; расчёт вручную даёт порог 4.5, выигрыш 2.1667 и листья −0.5 и 1.0 — столько же у XGBoost.
  Столбец `Cover` — это сумма $h$: 2.0 в корне, по 1.0 в листьях.

## 7. Параметры XGBoost

Значения по умолчанию прочитаны из конфигурации обученной модели версии 3.4.1.

| Параметр (sklearn-обёртка) | По умолчанию | Что делает |
|---|---|---|
| `n_estimators` | 100 | число деревьев; с ранней остановкой — верхняя граница |
| `learning_rate` (`eta`) | 0.3 | шаг обучения |
| `max_depth` | 6 | глубина деревьев; рост по уровням (`grow_policy="depthwise"`) |
| `min_child_weight` | 1 | минимальная сумма $h$ в листе; для MSE это число объектов |
| `reg_lambda` (`lambda`) | 1 | L2-штраф на веса листьев |
| `reg_alpha` (`alpha`) | 0 | L1-штраф на веса листьев |
| `gamma` (`min_split_loss`) | 0 | минимальный выигрыш, ради которого делается разбиение |
| `subsample` | 1 | доля строк, случайно выбираемых для каждого дерева |
| `colsample_bytree` | 1 | доля признаков для каждого дерева; есть `colsample_bylevel`, `colsample_bynode` |
| `max_bin` | 256 | число корзин гистограммы признака |
| `tree_method` | `auto` (то же, что `hist`) | способ поиска разбиений |

**`min_child_weight` — не число объектов.** Это ограничение на сумму вторых производных. Для MSE $h = 1$,
и параметр равен `min_samples_leaf`. Для log loss $h = p(1-p) \le 0.25$: при значении 1 в листе должно
быть минимум четыре объекта, а там, где модель уверена, — десятки и сотни. В примере выше при
`min_child_weight=1.1` разбиение восьми точек становится невозможным: у каждого потомка `Cover = 1.0`.

**Подвыборки строк и столбцов** — приём из случайного леса: деревья становятся менее похожими, модель
устойчивее, обучение быстрее. В отличие от леса, строки выбираются без возвращения.

**`tree_method="hist"`** — признак заранее разбивается на `max_bin` корзин по квантилям, и разбиения
ищутся только по границам корзин, а не по всем значениям (идея из практики 4.1.4). На данных
о мошенничестве (36 000 строк, 300 деревьев глубины 6) `exact` обучается 3.1 с, `approx` — 2.2 с,
`hist` — 0.5 с. Начиная с версии 2.0 `hist` используется по умолчанию; подробно о гистограммах —
в уроке 4.3.2.

**Пропуски** XGBoost обрабатывает сам. При поиске разбиения объекты с пропуском в признаке пробуются
и в левой, и в правой ветви; запоминается направление с большим выигрышем — направление по умолчанию.
Пример: `x = [1, 2, 3, 4, 5, 6, nan, nan, nan]`, `y = [1.0, 1.1, 0.9, 3.0, 3.1, 2.9, 3.2, 2.8, 3.0]`.
Дерево делит по порогу 3.5 и отправляет пропуски вправо (столбец `Missing` в `trees_to_dataframe()`):
там объекты с похожими значениями целевой переменной. На квартирах, где у 30 % объектов случайно удалено
время до метро, встроенная обработка даёт RMSE 0.759 против 0.775 при заполнении медианой; если пропуски
неслучайны (удалены 80 % значений больше 15 минут) — 0.727 против 0.742. Заполнять пропуски перед
XGBoost не нужно; пропуск должен быть `np.nan`, а не −1 или 999.

## 8. Два API

**Обёртка scikit-learn** (`XGBRegressor`, `XGBClassifier`) работает в `Pipeline`, `cross_val_score` и со
всеми инструментами scikit-learn; параметры остановки — в конструкторе, валидационные данные — в `fit`.
Это выбор по умолчанию. **Нативный API** (`xgb.DMatrix`, `xgb.train`) принимает параметры словарём
с «родными» именами (`eta`, `lambda`) и нужен для `xgb.cv`, собственных функций потерь и метрик,
обучения на данных, не помещающихся в память.

```python
dfit, dvalid = xgb.DMatrix(X_fit, label=y_fit), xgb.DMatrix(X_valid, label=y_valid)
params = {"objective": "reg:squarederror", "eta": 0.05, "max_depth": 4, "seed": 0}
booster = xgb.train(params, dfit, num_boost_round=5000, evals=[(dvalid, "valid")],
                    early_stopping_rounds=100, verbose_eval=False)
booster.best_iteration                                           # 513 — как у обёртки
booster.predict(xgb.DMatrix(X_test), iteration_range=(0, booster.best_iteration + 1))
```

С этими параметрами оба API строят одну и ту же модель: предсказания совпадают до бита. Ловушка —
в предсказании: `XGBRegressor.predict` после ранней остановки использует деревья до лучшей итерации,
а `Booster.predict` без `iteration_range` — все 614 построенных, включая сто «лишних». Расхождение
на тесте — до 0.20 млн руб. на объект.

## 9. Порядок ручной настройки

Автоматический подбор — тема 4.4. Вручную параметры настраивают по одной группе, от самых влиятельных
к уточняющим, оценивая каждое изменение кросс-валидацией с ранней остановкой:

```python
dtrain = xgb.DMatrix(X_train, label=y_train)
cv = xgb.cv(params, dtrain, num_boost_round=5000, nfold=5, early_stopping_rounds=100, seed=0)
len(cv), cv["test-rmse-mean"].iloc[-1]             # число деревьев и средний RMSE по пяти фолдам
```

| Шаг | Что изменено | Деревьев | RMSE на CV | RMSE на тесте |
|---|---|---|---|---|
| 0 | параметры по умолчанию (шаг 0.3, глубина 6, 100 деревьев) | 100 | 0.706 | 0.745 |
| 1 | шаг 0.1, число деревьев — ранней остановкой | 128 | 0.665 | 0.716 |
| 2 | сложность дерева: `max_depth=4`, `min_child_weight=20` | 458 | 0.637 | 0.695 |
| 3 | подвыборки: `colsample_bytree=0.8`, `subsample=1` | 432 | 0.633 | 0.688 |
| 4 | регуляризация: лучше значений по умолчанию не нашлось | 432 | 0.633 | 0.688 |
| 5 | шаг 0.02, число деревьев — заново | 1897 | 0.631 | **0.680** |

Столбец с тестом приведён, чтобы показать, что улучшения настоящие; в работе тест открывают один раз,
в конце. На шаге 2 перебирались глубины 2, 3, 4, 5, 6, 8 и `min_child_weight` 1, 5, 20. RMSE
на кросс-валидации при глубине 4 — 0.651, 0.646 и 0.637; при глубине 2 — около 0.67; при глубине 8 —
0.736, 0.699 и 0.668.

Что из этого следует.

1. **Самое дешёвое улучшение — уменьшить шаг и включить раннюю остановку** (0.745 → 0.716 на тесте).
   У модели по умолчанию RMSE на обучении 0.11 при 0.71 на проверке: сто деревьев глубины 6 с шагом 0.3
   запоминают выборку.
2. **Затем — сложность дерева.** Оптимум здесь при глубине 4 с крупными листьями; глубина 8 заметно
   хуже. Мелкие деревья с ограничением на лист — обычное состояние хорошо настроенного бустинга: смещение
   убирает их количество, а не глубина.
3. **Подвыборки и штрафы — уточнение.** `colsample_bytree=0.8` дал 0.004 на кросс-валидации при разбросе
   между фолдами около 0.03; `gamma=1` ухудшил результат до 0.67–0.70, `reg_lambda=30` — до 0.645.
4. **В конце — уменьшить шаг** и увеличить число деревьев: небольшая прибавка ценой времени обучения.

## 10. Функция потерь и монотонные ограничения

Функция потерь задаётся параметром `objective`: `reg:squarederror`, `reg:absoluteerror`, `reg:gamma`,
`reg:tweedie`, `count:poisson`, `binary:logistic`, `multi:softprob`, `rank:ndcg` и другие. Метрика для
ранней остановки — отдельный параметр `eval_metric` (`rmse`, `mae`, `logloss`, `auc`, `aucpr`, ...);
по умолчанию она соответствует функции потерь.

Цена квартиры в наших данных — произведение множителей, и шум мультипликативный. Сравним функции потерь
(шаг 0.05, остановка по валидации, метрики на тесте):

| Функция потерь | Деревьев | RMSE | MAE | MAPE |
|---|---|---|---|---|
| `reg:squarederror` | 1381 | 0.701 | 0.462 | 7.6 % |
| `reg:absoluteerror` | 3374 | 0.710 | 0.449 | 7.3 % |
| `reg:gamma` (логарифмическая связь) | 629 | 0.660 | 0.429 | 6.9 % |
| `reg:squarederror` для логарифма цены | 620 | **0.659** | 0.433 | 7.0 % |

Смена шкалы дала больше, чем вся настройка параметров из раздела 9. В логарифмах множители становятся
слагаемыми, а сумма деревьев — естественная модель для суммы эффектов. Это тот же приём, который в теме
4.2 вывел линейную модель на уровень леса (0.816).

**Монотонные ограничения.** Заказчику трудно объяснить, почему при увеличении площади на метр оценка
квартиры упала. Без ограничений такое случается: если менять только площадь, у всех 300 проверенных
квартир теста предсказание где-нибудь убывает, 7.6 % шагов по одному метру идут вниз, самый большой
провал — 0.28 млн руб. У случайного леса то же самое (10 % шагов).
Ограничение задаётся параметром `monotone_constraints={"area": 1}` (1 — не убывает, −1 — не возрастает).
С ограничением убывающих шагов нет ни одного: разбиение по площади допускается, только если вес правого
листа не меньше веса левого. RMSE на тесте почти не меняется: 0.680 → 0.687 для цены и 0.653 → 0.648 для
логарифма цены. Ограничение, которое соответствует природе данных, работает как регуляризация; ограничение
«цена не убывает по возрасту дома» здесь было бы ошибкой — в исторических районах зависимость обратная.

## 11. Дисбаланс классов: `scale_pos_weight`

Параметр умножает градиенты объектов положительного класса на заданный вес — аналог `class_weight` из
урока 3.2.2. Данные о мошенничестве (1.92 % положительных; отношение классов 51), шаг 0.05, глубина 3,
остановка по PR-AUC на валидации:

| `scale_pos_weight` | ROC-AUC | PR-AUC | Log loss | Средняя вероятность | Log loss после поправки |
|---|---|---|---|---|---|
| 1 | 0.886 | 0.300 | **0.067** | 0.019 | — |
| 7.2 (корень из отношения) | 0.885 | 0.301 | 0.111 | 0.079 | 0.068 |
| 51.2 (отношение классов) | 0.883 | 0.288 | 0.358 | 0.254 | 0.069 |

Ранжирование от веса не улучшилось, а вероятности испорчены: модель с весом 51 в среднем предсказывает
25 % мошенничества при фактических 1.9 %. Это ровно ловушка из урока 3.2.2, и лечится она так же —
поправкой $p = p_w / (p_w + (1 - p_w) \cdot w)$ или калибровкой на отложенных данных. Если нужны
вероятности, вес лучше не трогать; если нужно только решение по порогу, порог проще подобрать, чем
перевзвешивать классы.

Вторая ловушка: с весом классов нельзя останавливаться по log loss (поэтому в таблице — PR-AUC). При весе 51
остановка по log loss не сработала за 3000 деревьев, а ROC-AUC на тесте упал до 0.848.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Ошибка на обучении почти нулевая, на тесте хуже, чем у простой модели | параметры по умолчанию: шаг 0.3, глубина 6, остановки нет | шаг 0.05–0.1, ранняя остановка, `max_depth` 3–5, `min_child_weight` |
| Качество на новых данных ниже, чем на «тесте» | ранняя остановка или подбор параметров по тесту | отдельная валидационная часть или `xgb.cv`; тест — один раз |
| `fit() got an unexpected keyword argument 'early_stopping_rounds'` | параметр перенесён из `fit` в конструктор | `XGBRegressor(early_stopping_rounds=...)`, в `fit` — только `eval_set` |
| Нативная модель после ранней остановки предсказывает иначе, чем обёртка | `Booster.predict` использует все деревья | `iteration_range=(0, best_iteration + 1)` |
| Уменьшили шаг — стало хуже | число деревьев осталось прежним | шаг и число деревьев меняют вместе; число деревьев — ранней остановкой |
| Средняя вероятность в разы больше доли класса | `scale_pos_weight` | поправка априорной вероятности или калибровка (урок 3.2.2); либо не использовать вес |
| С `scale_pos_weight` ранняя остановка не срабатывает | остановка по log loss при перевзвешенных классах | `eval_metric="aucpr"` или `"auc"` |
