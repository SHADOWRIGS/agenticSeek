## 1. Target statistics и утечка

Target statistic (в уроке 2.3.2 — target encoding) заменяет категорию сглаженным средним значением
целевой переменной:

$$\hat{x}_i = \frac{\sum_{j:\, x_j = x_i} y_j + a \cdot p}{n_{x_i} + a}$$

где $p$ — среднее по всей выборке (prior), $a$ — вес сглаживания. Для дерева это идеальный признак:
одно число, упорядоченное по смыслу. Беда в том, что в сумму входит $y_i$ самого объекта. У продавца
с тремя заказами статистика на треть состоит из ответа, который модель должна предсказать.

Сравним четыре способа посчитать статистику для обучающей выборки (для валидации и теста во всех
вариантах — статистика по всему обучению, $a = 1$):

```python
def ordered_ts(categories, target, prior, a=1.0, seed=0):
    order = np.random.default_rng(seed).permutation(len(target))    # случайный порядок объектов
    cat, y = categories.iloc[order], target.iloc[order]
    groups = y.groupby(cat)
    before_sum = groups.cumsum() - y        # сумма y у объектов той же категории, стоящих раньше
    before_count = groups.cumcount()        # сколько таких объектов
    encoded = (before_sum + a * prior) / (before_count + a)
    encoded[cat.isna()] = prior
    return encoded.reindex(target.index)
```

Пять категориальных признаков закодированы статистиками и вместе с числовыми переданы в LightGBM
(`num_leaves=8`, `min_child_samples=100`, шаг 0.05):

| Статистика для обучения | С остановкой: деревьев | обучение | тест | ROC-AUC | 300 деревьев: обучение | тест |
|---|---|---|---|---|---|---|
| Наивная: по всей обучающей выборке | 17 | 0.385 | 0.426 | 0.667 | 0.321 | 0.455 |
| Out-of-fold, 5 фолдов (урок 2.3.2) | 182 | 0.392 | 0.402 | 0.732 | 0.384 | 0.402 |
| Упорядоченная, случайная перестановка | 234 | 0.393 | 0.403 | 0.732 | 0.389 | 0.403 |
| Упорядоченная, порядок по времени | 201 | 0.395 | 0.403 | 0.731 | 0.389 | 0.403 |

С наивной статистикой модель без ранней остановки хуже константы (0.455 против 0.452), а остановка
срабатывает на 17-м дереве. Механизм виден по одному числу: корреляция закодированного продавца с целевой
переменной — 0.39 на обучении и 0.165 на валидации. Модель учится доверять признаку, который на новых
данных в два с лишним раза слабее. У упорядоченной статистики корреляция на обучении 0.147 — признак
в обучении ведёт себя так же, как будет вести себя потом.

## 2. Упорядоченные статистики в CatBoost

Идея упорядоченной статистики (ordered target statistics): расположить объекты в случайном порядке
и для каждого считать среднее только по тем объектам его категории, которые стоят **раньше**:

$$\hat{x}_i = \frac{\sum_{j \in P_i} y_j + a \cdot p}{|P_i| + a}$$

где $P_i$ — объекты $j$ той же категории ($x_j = x_i$), стоящие в перестановке $\sigma$ раньше объекта $i$:
$\sigma(j) < \sigma(i)$.

Собственный ответ объекта в его статистику не попадает никогда. По сравнению с out-of-fold схемой
используется вся выборка без разбиения на фолды. Плата — шум: у первых объектов перестановки статистика
посчитана по одному-двум предшественникам. CatBoost смягчает это, используя несколько перестановок:
для разных деревьев берутся разные. При предсказании статистика считается по всей обучающей выборке;
новая категория получает prior.

Детали реализации, которые полезно знать:

- статистик несколько: с разными prior и отдельная статистика-счётчик (частота категории). В параметрах
  обученной модели это `simple_ctr`: `Borders` с тремя prior и `Counter`;
- признаки с числом значений до `one_hot_max_size` (по умолчанию 2) кодируются one-hot, остальные —
  статистиками;
- если данные упорядочены по времени, `has_time=True` заменяет случайные перестановки порядком строк:
  статистика считается только по прошлому.

## 3. Смещение предсказаний и упорядоченный бустинг

Та же утечка есть в самом бустинге, без всяких категорий. Остатки для дерева $t$ считаются по модели
$F_{t-1}$, которая обучалась на этих же объектах, поэтому остатки на обучении систематически меньше, чем
были бы на новых данных. Дерево учится на искажённой цели; авторы CatBoost назвали это смещением
предсказаний (prediction shift).

Упорядоченный бустинг (ordered boosting) применяет ту же идею перестановки: остаток объекта считается
по модели, обученной только на объектах, стоящих раньше него. Точная реализация потребовала бы отдельной
модели для каждого объекта; CatBoost хранит вспомогательные модели для префиксов перестановки, длины
которых растут в геометрической прогрессии. Режим включается параметром `boosting_type="Ordered"`;
в наших запусках на CPU по умолчанию использовался `"Plain"` — обычный бустинг с упорядоченными
статистиками для категорий.

Что даёт упорядоченный бустинг (параметры по умолчанию, среднее по трём случайным подвыборкам обучения,
log loss на полном тесте):

| Объектов в обучении | `Plain` | `Ordered` | Время обучения: `Plain` / `Ordered`, с |
|---|---|---|---|
| 500 | 0.440 | 0.434 | 2.8 / 5.2 |
| 2 000 | 0.426 | 0.423 | 3.9 / 6.5 |
| 8 000 | 0.412 | 0.410 | 8.8 / 12.5 |
| 26 593 (с валидацией и остановкой) | 0.3991 | 0.3998 | 6.0 / 12.6 |

Выигрыш есть на малых выборках и убывает с ростом данных: 0.007 на 500 объектах, 0.002 на 8 000,
ничего на 26 000. Время обучения — в полтора-два раза больше. Вывод: `Ordered` стоит пробовать, когда
объектов тысячи, а не сотни тысяч.

## 4. Симметричные деревья

CatBoost по умолчанию строит симметричные деревья (oblivious trees): **на каждом уровне все узлы делятся
по одному и тому же признаку и порогу**. Дерево глубины 6 — это шесть вопросов, одинаковых для всех
объектов, и 64 листа; номер листа — шестизначное двоичное число из ответов.

**Почему это быстро при предсказании.** Обычное дерево требует прохода от корня с ветвлением на каждом
шаге. Симметричное — шести сравнений, которые выполняются независимо и векторно, и одного обращения
к таблице из 64 значений. Предсказание для 200 000 объектов (30 числовых признаков, глубина 6;
у LightGBM 63 листа):

| Модель | CatBoost | XGBoost | LightGBM |
|---|---|---|---|
| 100 деревьев, 4 потока | 28 мс | 73 мс | 378 мс |
| 1000 деревьев, 1 поток | 0.09 с | 2.7 с | 13.0 с |
| Один объект, 100 деревьев (вызов из Python) | 0.30 мс | 0.20 мс | 0.44 мс |

На пакетах разница — один-два порядка. На одном объекте всё время уходит на вызов библиотеки из Python,
и библиотеки неразличимы.

**Почему это регуляризация.** Обычное дерево глубины 6 выбирает до 63 разных разбиений, симметричное —
шесть. Каждое разбиение обязано быть полезным сразу для всех ветвей, поэтому отдельное дерево — слабая
и устойчивая модель, и подогнать его под шум трудно. Другие способы роста тоже есть:

| `grow_policy` | Деревьев | Log loss на тесте | ROC-AUC |
|---|---|---|---|
| `SymmetricTree` (по умолчанию) | 193 | **0.3991** | 0.739 |
| `Depthwise` — по уровням, как XGBoost | 145 | 0.4004 | 0.736 |
| `Lossguide` — по листьям, как LightGBM | 166 | 0.4015 | 0.735 |

## 5. Комбинации категорий

Возврат в наших данных зависит от пары «категория товара × способ оплаты»: эффект пары не сводится
к сумме эффектов. Дерево может выучить такое взаимодействие двумя разбиениями подряд, но статистики
по отдельным признакам о паре ничего не знают. CatBoost строит комбинации жадно: при выборе очередного
разбиения он рассматривает комбинации категориальных признаков, уже использованных в дереве, с остальными
и считает статистику для комбинации как для нового признака. Наибольшее число признаков в комбинации —
`max_ctr_complexity` (по умолчанию 4).

С `max_ctr_complexity=1` (без комбинаций) log loss на тесте 0.4003 вместо 0.3991. Выигрыш небольшой:
у пары всего 36 значений, и деревья справляются сами. Он растёт, когда взаимодействуют признаки
с большим числом значений.

## 6. Работа «из коробки»

```python
from catboost import CatBoostClassifier, Pool

X_train[CAT_FEATURES] = X_train[CAT_FEATURES].fillna("нет")          # то же для валидации и теста

model = CatBoostClassifier(
    cat_features=CAT_FEATURES,          # имена или номера категориальных столбцов
    random_seed=0,
    verbose=0,                          # или verbose=100: печатать каждую сотую итерацию
    allow_writing_files=False,
)
model.fit(X_train, y_train, eval_set=(X_valid, y_valid), early_stopping_rounds=100)
model.best_iteration_, model.tree_count_          # 192 и 193
```

Что здесь важно.

- **Категории передаются как есть** — строками или целыми числами. Кодировать их не нужно и вредно:
  с кодами категорий в роли чисел (без `cat_features`) log loss на тесте 0.412 вместо 0.399.
- **Пропуск в категориальном признаке — ошибка:** `cat_features must be integer or string, real number
  values and NaN values should be converted to string`. Пропуски заменяют строкой. В числовых признаках
  пропуски допустимы (`nan_mode="Min"`: пропуск считается меньше любого значения).
- **`eval_set` и `use_best_model`.** Если задана валидационная выборка, `use_best_model` включается сам:
  после обучения модель обрезается до лучшей итерации (193 дерева), даже если ранней остановки не было —
  тогда строятся все 1000 деревьев, а 807 выбрасываются. С `use_best_model=False` остаются все 1000,
  а `best_iteration_` только сообщает, где был минимум.
- **Ранняя остановка** — `early_stopping_rounds` в `fit`. Это сокращение для детектора переобучения
  `od_type="Iter"`, `od_wait=100`; второй тип, `"IncToDec"`, останавливает по статистическому критерию.
- **Шаг обучения выбирается автоматически** по размеру данных и числу итераций: 0.042 для наших
  26 593 объектов и 1000 итераций, 0.071 — при заданной валидационной выборке. Зададите другое число
  итераций — изменится и шаг.
- **Файлы.** По умолчанию CatBoost создаёт в текущей папке каталог `catboost_info` с журналами обучения.
  `allow_writing_files=False` отключает запись, `train_dir="путь"` переносит её в другое место. Добавьте
  `catboost_info/` в `.gitignore`.
- **`Pool`** — контейнер данных CatBoost, аналог `DMatrix`: `Pool(X, y, cat_features=CAT_FEATURES)`.
  Он нужен для функций, которым требуются данные вместе с описанием столбцов (важность признаков, SHAP),
  и экономит время при повторных обучениях. Модель, обученная на `Pool`, совпала с моделью выше до бита.
- **Текстовые признаки** передаются параметром `text_features`: CatBoost сам разбивает текст на слова
  и строит по ним числовые признаки для классификации.

`PredictionValuesChange` — насколько в среднем меняется предсказание при изменении признака; считается
по самой модели, данных не требует и показывает, чем модель пользуется. `LossFunctionChange` — насколько
ухудшится функция потерь на переданных данных, если признак исключить из модели; считается по отложенной
выборке и показывает, что из этого полезно. Разница та же, что между встроенной и перестановочной
важностью в уроке 4.2.1: `weekday`, `is_app` и `month` модель использует (3 % важности первого типа),
а пользы от них нет — значения второго типа нулевые или отрицательные.

**SHAP-значения** раскладывают предсказание для каждого объекта на вклады признаков. Результат — матрица
«объекты × (признаки + 1)»: последний столбец — базовое значение (−1.82 в логарифмах шансов), сумма
строки равна предсказанию модели в логарифмах шансов (проверено: расхождение $5 \cdot 10^{-15}$). Для
первого заказа теста: база −1.82, категория «одежда» +0.48, скидка 46 % +0.24, девять прошлых заказов
покупателя −0.20, остальные признаки по мелочи; итог −1.39, вероятность возврата 0.199. Расчёт для
6 665 объектов занял 0.2 секунды — для симметричных деревьев есть быстрый точный алгоритм.

**Сохранение.** `model.save_model("model.cbm")`, загрузка — `CatBoostClassifier().load_model("model.cbm")`;
предсказания после загрузки совпадают до бита. Файл нашей модели занимает 4.8 МБ при 193 деревьях:
вместе с деревьями хранятся таблицы статистик для всех категорий и комбинаций. Есть экспорт
в JSON (`format="json"`) и другие форматы.

Главные отличия CatBoost: тысяча деревьев с автоматическим шагом вместо сотни с фиксированным,
подвыборка строк и L2-штраф включены сразу, случайность добавляется и в выбор разбиений. Значения
по умолчанию у него — уже регуляризованная модель.

## 10. Когда CatBoost выигрывает и когда проигрывает

**Значения по умолчанию.** Все модели — без единого параметра, без валидации, обучение на всей обучающей
выборке (квартиры — RMSE, остальное — log loss на тесте):

| Данные | XGBoost | LightGBM | `HistGradientBoosting` | CatBoost | Лучшее из прошлых уроков |
|---|---|---|---|---|---|
| Квартиры | 0.745 | 0.711 | 0.701 | **0.655** | 0.648 — XGBoost после настройки, логарифм цены |
| Отток | 0.630 | 0.573 | 0.574 | **0.560** | 0.548 — логистическая регрессия |
| Мошенничество | 0.0764 | 0.0700 | **0.0680** | 0.0692 | 0.0666 — LightGBM с ранней остановкой |
| Заказы (категории встроенными средствами) | 0.670 | 0.419 | ошибка | **0.400** | 0.398 — CatBoost, шаг 0.05, глубина 4 |

На квартирах CatBoost «из коробки» дал то, к чему XGBoost пришёл после пяти шагов настройки и перехода
к логарифму цены. `HistGradientBoosting` на заказах не запустился: категориальный признак должен
иметь не больше 255 значений; а на мошенничестве он лучший, потому что на выборках больше 10 000
объектов сам включает раннюю остановку.

**Мало данных и много категорий.** Те же модели по умолчанию на подвыборках заказов:

| Объектов в обучении | CatBoost | LightGBM | XGBoost |
|---|---|---|---|
| 500 | **0.440** | 0.577 | 1.209 |
| 2 000 | **0.426** | 0.493 | 1.114 |
| 8 000 | **0.412** | 0.434 | 0.915 |
| 26 593 | **0.400** | 0.419 | 0.670 |

У константы 0.452: на 500 и 2 000 объектах LightGBM и XGBoost без настройки хуже, чем отсутствие модели,
а CatBoost уже полезен.

**Время обучения.** Четыре потока, время в секундах:

| Задача | CatBoost | LightGBM | XGBoost |
|---|---|---|---|
| Числовые признаки, 1 млн строк × 30, 100 деревьев | 7.8 | 7.6 | 6.4 |
| Числовые признаки, 100 тыс. строк, 1000 деревьев, 1 поток | 26.6 | 13.0 | 17.2 |
| Заказы с категориями, 266 тыс. строк, 200 деревьев | 23.6 | 3.4 | 5.0 |
| Квартиры, 3 500 строк, параметры по умолчанию | 1.2 | 0.11 | 0.10 |

На числовых признаках при одинаковом числе деревьев и четырёх потоках CatBoost не медленнее остальных —
распространённое утверждение о его медлительности здесь не воспроизвелось. Медленнее он в трёх случаях:
в один поток (в полтора-два раза), с категориальными признаками (в 5–7 раз: статистики и комбинации
пересчитываются для каждой перестановки) и с параметрами по умолчанию, потому что деревьев в десять раз
больше. На заказах эта цена куплена качеством: log loss 0.391 против 0.401 у LightGBM и 0.409 у XGBoost.

**Итог.**

| CatBoost — первый выбор | Лучше начать с LightGBM или XGBoost |
|---|---|
| есть категориальные признаки с десятками и тысячами значений | признаки числовые, данных много, нужно много экспериментов |
| данных мало (сотни — тысячи объектов) | обучение по расписанию с жёстким ограничением по времени |
| нет времени или инфраструктуры на подбор параметров | нужны возможности, которых нет в CatBoost, или привычный API |
| важна скорость предсказания на пакетах | модель должна занимать мало места при тысячах категорий |

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `cat_features must be integer or string ... NaN values should be converted to string` | пропуски в категориальном столбце | `fillna("нет")` до обучения и предсказания |
| Качество как у порядкового кодирования | столбцы с кодами категорий не объявлены в `cat_features` | передать `cat_features`; не кодировать заранее |
| В репозитории появилась папка `catboost_info` | журналы обучения пишутся в текущую папку | `allow_writing_files=False` или `train_dir`; `.gitignore` |
| Задали `iterations=200`, модель стала хуже | автоматический шаг рассчитан на другое число итераций | задать `learning_rate` явно либо оставить `iterations` и остановку |
| Target encoding до CatBoost ухудшил модель | самодельная статистика с утечкой вместо встроенной | отдать категории CatBoost как есть |
| Обучение идёт все 1000 итераций, хотя есть `eval_set` | `use_best_model` обрезает модель, но не останавливает обучение | `early_stopping_rounds` |
| `HistGradientBoosting` падает на категориальном признаке | больше 255 значений | другое кодирование или другая библиотека |
| Данные по времени, а качество на будущем хуже ожидаемого | случайные перестановки и случайная валидация | разбиение по времени, `has_time=True` |
| Обучение с категориями в разы медленнее LightGBM | цена статистик и комбинаций | меньше `max_ctr_complexity`, больше `one_hot_max_size`, подвыборка для экспериментов |
| Файл модели — десятки мегабайт | хранятся таблицы статистик по всем категориям | убрать бесполезные признаки высокой кардинальности |
