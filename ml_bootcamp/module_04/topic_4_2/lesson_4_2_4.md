## Задача

Агентство недвижимости хочет инструмент оценки квартир: по параметрам объявления получить цену
и объяснение, из чего она складывается. Объяснение нужно двум людям: руководителю — чтобы решить, можно ли
модели доверять, и риелтору — чтобы ответить клиенту на вопрос «почему столько».

Работа состоит из двух частей:

1. **Реализация.** Написать случайный лес для регрессии поверх готового дерева
   `sklearn.tree.DecisionTreeRegressor`, вместе с out-of-bag оценкой, перестановочной важностью
   и частичной зависимостью — так, чтобы проходили тесты.
2. **Применение.** Своим лесом и своими инструментами решить задачу оценки на данных `housing_data.py`
   и написать отчёт для заказчика.

В практике 4.1.4 вы писали дерево с нуля; здесь дерево берётся готовое, а всё, что вокруг него, —
ваше. Зачем: в лесе нет ничего, кроме бутстрепа, цикла и усреднения, и после этой практики вы будете
знать это по собственному коду. А перестановочная важность и частичная зависимость не привязаны
к лесу — ваши функции будут работать с любой моделью, у которой есть `predict`.

## Часть 1. Реализация

Точные требования записаны в docstring заготовки. Ниже — порядок работы и подводные камни.

### Шаг 1. `r2_score`

Метрика, по которой считаются OOB-оценка и важность признаков. Единственная тонкость — постоянная
целевая переменная, при которой знаменатель равен нулю.

```bash
uv run pytest -q -k TestR2
```

### Шаг 2. Обучение: бутстреп и воспроизводимая случайность

Цикл из урока 4.2.1: для каждого дерева — выборка $n$ номеров объектов с возвращением и обучение дерева
на ней. Параметры `max_features`, `max_depth`, `min_samples_leaf` лес просто передаёт дереву: случайный
выбор признаков в узле уже реализован в `DecisionTreeRegressor`.

Главное в этом шаге — случайность. Наивное решение — один генератор на весь лес — работает, но у него
два недостатка: дерево номер 5 зависит от того, сколько случайных чисел израсходовали деревья 0–4,
и обучение нельзя распараллелить, не изменив результат. Правильная схема — **независимый генератор
для каждого дерева**, порождённый из общего `random_state`:

```python
import numpy as np

seeds = np.random.SeedSequence(42).spawn(3)  # три независимых потомка одного seed
[int(np.random.default_rng(seed).integers(0, 100)) for seed in seeds]
```

Потомки `SeedSequence` статистически независимы, а потомок с номером `b` не зависит от того, сколько
их запрошено. Отсюда свойство, которое проверяет тест `test_tree_does_not_depend_on_forest_size`: первые
пять деревьев леса из двадцати совпадают с лесом из пяти деревьев.

```bash
uv run pytest -q -k "TestFit or TestRandomness"
```

### Шаг 3. Предсказание

`tree_predictions` возвращает матрицу «дерево × объект», `predict` — её среднее по деревьям. Матрица
пригодится и сама по себе: разброс предсказаний деревьев для объекта — грубая оценка неуверенности
модели (см. идеи для усложнения).

```bash
uv run pytest -q -k TestPredict
```

### Шаг 4. Out-of-bag оценка

Для каждого объекта нужно усреднить предсказания только тех деревьев, в бутстреп-выборку которых он
не попал. Удобно делать это прямо в цикле обучения: булева маска OOB-объектов дерева, один вызов
`predict` для них, накопление суммы предсказаний и счётчика деревьев по каждому объекту.

Подводные камни:

- объект, попавший в выборки всех деревьев (при малом числе деревьев таких много), OOB-предсказания
  не имеет: в `oob_prediction_` для него стоит `nan`, в `oob_score_` он не участвует. Деление на нулевой
  счётчик не должно порождать предупреждений;
- при `bootstrap=False` OOB-объектов нет вообще;
- вызывать `predict` отдельно для каждого объекта нельзя: тест скорости этого не пропустит.

Тест `test_object_is_excluded_from_its_own_prediction` ловит самую частую ошибку — усреднение по всем
деревьям. В нём у одного объекта целевая переменная равна 1000 при обычных значениях до 60: деревья,
видевшие этот объект, помнят выброс, остальные о нём не знают.

```bash
uv run pytest -q -k TestOob
```

### Шаг 5. Перестановочная важность

Функция получает обученную модель и отложенные данные, для каждого признака несколько раз перемешивает
его столбец и измеряет падение $R^2$ (урок 4.2.1). Модель при этом не переобучается.

Подводные камни: изменение переданной таблицы вместо копии; перестановка сразу нескольких столбцов
или целых строк; генерация новых значений вместо перестановки имеющихся; одна и та же перестановка
для всех повторов.

```bash
uv run pytest -q -k TestPermutationImportance
```

### Шаг 6. Частичная зависимость

Восемь строк из урока 4.2.3. Тест сверяет результат с `sklearn.inspection.partial_dependence`
в режиме `method="brute"`.

```bash
uv run pytest -q -k TestPartialDependence
```

### Шаг 7. Сверка и скорость

```bash
uv run pytest -q -k "TestAgainstSklearn or TestEngineering"
uv run pytest -q
```

Совпадения предсказаний со scikit-learn тесты не требуют: случайные числа расходуются по-разному.
Проверяется близость качества на тесте и OOB-оценки.

## Часть 2. Оценка квартир

Работайте в ноутбуке рядом с `my_forest.py`. Используйте свой лес и свои функции; scikit-learn —
для разбиения данных, базовых моделей и сверки.

```python
from housing_data import DISTRICT_COEF, FEATURES, TARGET, make_housing
from my_forest import MyRandomForestRegressor, r2_score
from sklearn.model_selection import train_test_split

flats = make_housing()
X = flats[FEATURES].copy()
X["district"] = X["district"].map({name: code for code, name in enumerate(sorted(DISTRICT_COEF))})
X_train, X_test, y_train, y_test = train_test_split(X, flats[TARGET], test_size=0.3, random_state=0)

forest = MyRandomForestRegressor(n_estimators=300, max_features=0.5, random_state=0).fit(X_train, y_train)
forest.oob_score_, r2_score(y_test, forest.predict(X_test))
```

План:

1. **Данные.** Посмотрите на распределения и корреляции признаков. Какие признаки дублируют друг друга?
   Какие выглядят бесполезными? Запишите гипотезы до обучения модели.
2. **Точки отсчёта.** Константа (средняя цена), линейная регрессия, одно дерево. Метрики на тесте:
   RMSE, MAE, MAPE, $R^2$.
3. **Лес.** Подберите `max_features` и `min_samples_leaf` по OOB-оценке, не заглядывая в тест.
   Проверьте по OOB, что 300 деревьев достаточно.
4. **Признаки.** Посчитайте перестановочную важность на тесте. Проверьте группу связанных с площадью
   признаков удалением с переобучением (урок 4.2.1). Примите решение о составе признаков и обоснуйте его.
5. **Честная оценка.** Итоговые метрики на тесте; сравнение OOB и теста; ошибка по сегментам — по возрасту
   дома и по ценовым квартилям. Отдельно — проверка во времени: обучите лес на месяцах 0–23, проверьте
   на 24–35. Что должен знать заказчик о работе модели через полгода после внедрения?
6. **Объяснение.** Графики частичной зависимости для трёх-четырёх признаков вашей функцией. Сверьте их
   с `true_price` — в учебных данных это возможно — и запишите, что модель восстановила, а что нет.
   Для двух квартир из теста покажите, как менялось бы предсказание при изменении одного признака
   (частичная зависимость по таблице из одной строки — это ICE-кривая).
7. **Отчёт.** В `README.md` проекта: одна страница для руководителя агентства. Что модель умеет, насколько
   ошибается и где ошибается сильнее, от чего зависит цена, чего от модели ждать нельзя.

## Идеи для усложнения

1. **Параллельное обучение.** Обучайте деревья в несколько процессов (`joblib.Parallel`). Благодаря
   независимым генераторам результат должен совпасть с последовательным до бита — добавьте такой тест.
   Измерьте ускорение на 2 и 4 ядрах.
2. **Extra Trees.** Добавьте параметр `splitter` и передавайте его дереву: `splitter="random"` вместе
   с `bootstrap=False` превращает ваш лес в Extra Trees. Сравните с таблицей урока 4.2.2 (RMSE 0.786).
3. **Неуверенность модели.** Стандартное отклонение предсказаний деревьев для объекта связано с ошибкой:
   у эталона корреляция Спирмена с абсолютной ошибкой — 0.35, а MAE по четвертям этого разброса — 0.33,
   0.40, 0.50 и 0.90 млн руб. Но интервал между 5-м и 95-м перцентилями предсказаний деревьев накрывает
   фактическую цену в 96 % случаев вместо 90 % — это не доверительный интервал. Разберитесь почему
   и постройте честный интервал по OOB-остаткам.
4. **Логарифм цены.** Обучите лес на логарифме цены. У эталона MAPE снижается с 9.0 % до 8.5 %, а RMSE
   растёт с 0.827 до 0.874. Объясните, почему метрики расходятся, и решите, что важнее заказчику.
5. **Встроенная важность.** Усредните `feature_importances_` деревьев и сравните с перестановочной
   важностью на полном наборе из 14 признаков. Какие признаки меняются местами?
6. **OOB-важность.** Реализуйте исходный вариант Бреймана: для каждого дерева перемешивайте признак
   только среди его OOB-объектов и усредняйте падение качества по деревьям. Отложенная выборка при этом
   не нужна. Сравните с важностью на тесте.
7. **Группы и ICE.** Добавьте перемешивание группы признаков одной перестановкой и функцию `ice`.
   Постройте ICE-кривые возраста дома с раскраской по району (урок 4.2.3).
8. **Классификация.** Напишите `MyRandomForestClassifier`, усредняющий вероятности, и воспроизведите
   на данных об оттоке таблицу из урока 4.2.1: лес по умолчанию и лес с `min_samples_leaf=20`.

## Что дальше
