## Зачем это нужно

В уроке 4.2.1 случайность оказалась инструментом: бутстреп и случайный выбор признаков делают деревья
разными, а усреднение превращает их разнообразие в устойчивость. Естественный вопрос — можно ли добавить
ещё случайности и что за это придётся отдать. Ответ на него — семейство методов, из которых случайный лес
лишь один. Они устроены одинаково, отличаются двумя-тремя параметрами и на конкретных данных могут
отличаться по качеству и скорости в разы. Знать всё семейство — значит не перебирать вслепую.

## 1. Ось «сколько случайности»

При построении дерева есть три места, куда можно внести случайность:

| Метод | Объекты для дерева | Признаки-кандидаты в узле | Порог |
|---|---|---|---|
| Одно дерево | все | все | лучший |
| Бэггинг | бутстреп-выборка | все | лучший |
| Случайный лес | бутстреп-выборка | случайные `max_features` | лучший |
| Extra Trees | все | случайные `max_features` | случайный |

**Extremely Randomized Trees** (Extra Trees; Гёртс, Эрнст, Вехенкель, 2006) делают последний шаг:
для каждого признака-кандидата порог не ищется перебором, а берётся **один случайный порог** — равномерно
между минимумом и максимумом признака в узле. Из этих случайных разбиений (по одному на кандидата)
выбирается лучшее. Раз случайности уже достаточно, бутстреп отключён: по умолчанию `bootstrap=False`,
каждое дерево учится на всех объектах.

Данные — объявления о продаже квартир из урока 4.2.1 (`housing_data.py`), то же разбиение.

```python
import time

import numpy as np
import pandas as pd
from housing_data import DISTRICT_COEF, FEATURES, TARGET, make_housing
from sklearn.ensemble import BaggingRegressor, ExtraTreesRegressor, IsolationForest, RandomForestRegressor
from sklearn.metrics import root_mean_squared_error
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor

flats = make_housing()
X = flats[FEATURES].copy()
X["district"] = X["district"].map({name: code for code, name in enumerate(sorted(DISTRICT_COEF))})
y = flats[TARGET]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

for model in [RandomForestRegressor(300, random_state=0), ExtraTreesRegressor(300, random_state=0)]:
    start = time.perf_counter()
    model.fit(X_train, y_train)
    rmse = root_mean_squared_error(y_test, model.predict(X_test))
    print(f"{type(model).__name__}: RMSE {rmse:.3f}, обучение {time.perf_counter() - start:.1f} с")
```

Все модели — 300 деревьев, обучение на одном ядре:

| Модель | RMSE на тесте | $R^2$ на обучении | Обучение | Листьев в дереве |
|---|---|---|---|---|
| Одно дерево | 1.178 | 1.000 | 0.03 с | 3 499 |
| Бэггинг (`RandomForestRegressor`, `max_features=1.0`) | 0.826 | 0.991 | 4.4 с | 2 210 |
| Случайный лес, `max_features=0.5` | 0.850 | 0.991 | 2.6 с | 2 211 |
| Extra Trees, `max_features=1.0` (по умолчанию) | **0.786** | 1.000 | 3.0 с | 3 498 |
| Extra Trees, `max_features=0.5` | 0.872 | 1.000 | 1.9 с | 3 499 |
| Extra Trees, `max_features=1.0`, `bootstrap=True` | 0.807 | 0.991 | 2.3 с | 2 212 |
| Extra Trees, `max_features=1.0`, `min_samples_leaf=3` | 0.801 | 0.986 | 1.9 с | 950 |

Что видно:

- Extra Trees с настройками по умолчанию — лучшая модель: RMSE на 5 % ниже, чем у бэггинга;
- он быстрее: 3.0 с против 4.4 с при всех признаках и 1.9 с против 2.6 с при половине. Случайному
  порогу не нужна сортировка значений признака в узле. Выигрыш был бы больше, но деревья Extra Trees
  крупнее: они учатся на всех 3500 объектах, а не на 2200 различных объектах бутстреп-выборки;
- $R^2$ на обучении ровно 1: без бутстрепа каждое дерево помнит каждый объект. По той же причине
  **у Extra Trees по умолчанию нет OOB-оценки** — `oob_score=True` требует `bootstrap=True`, а бутстреп
  здесь ухудшает качество (0.807 против 0.786). Для оценки нужна кросс-валидация;
- уменьшение `max_features` Extra Trees переносит хуже, чем лес: 0.872 против 0.850.

### Смещение и разброс

Повторим разложение из урока 4.2.1 (40 обучающих выборок по 1000 объектов, 100 деревьев):

| Модель | Смещение² | Разброс | Сумма | $\sigma^2$ дерева | $\rho$ |
|---|---|---|---|---|---|
| Бэггинг | 0.514 | 0.188 | 0.702 | 1.49 | 0.114 |
| Extra Trees, `max_features=1.0` | 0.489 | 0.187 | **0.676** | 1.86 | 0.089 |
| Случайный лес, `max_features=0.5` | 0.698 | 0.148 | 0.846 | 2.50 | 0.048 |
| Extra Trees, `max_features=0.5` | 0.771 | 0.162 | 0.933 | 3.11 | 0.041 |

Обычно пишут, что Extra Trees по сравнению с лесом уменьшает разброс ценой роста смещения. Здесь
получилось иначе, и полезно понять почему:

- отдельное дерево Extra Trees действительно хуже: его дисперсия 1.86 против 1.49. Зато деревья слабее
  коррелируют (0.089 против 0.114), и после усреднения разброс ансамблей одинаков;
- смещение у Extra Trees не выросло, а немного снизилось. Причин две. Дерево видит все объекты,
  а не 63 % различных. И случайные пороги при усреднении дают более гладкую функцию, чем «лучшие» пороги,
  которые у всех деревьев встают в одни и те же места, — а цена в наших данных зависит от площади
  и возраста гладко;
- при `max_features=0.5` случайности становится слишком много: к случайному порогу добавляется риск,
  что узлу не достанется ни одного полезного признака, и смещение растёт быстрее, чем у леса.

## 2. Когда Extra Trees выигрывает, а когда проигрывает

Проверим на трёх вариантах данных о квартирах и на стандартной синтетической задаче Фридмана
(`make_friedman1`: гладкая нелинейная зависимость от пяти признаков, остальные признаки шумовые).
RMSE на тесте, 300 деревьев; «часть» — `max_features=0.5` для квартир и `1/3` для задачи Фридмана:

| Данные | Признаков (шумовых) | Лес, все | Лес, часть | Extra Trees, все | Extra Trees, часть |
|---|---|---|---|---|---|
| Квартиры без шумовых и дублирующих | 9 (0) | 0.793 | 0.824 | **0.756** | 0.810 |
| Квартиры | 14 (3) | 0.826 | 0.850 | **0.786** | 0.872 |
| Квартиры + 30 шумовых признаков | 44 (33) | 0.905 | 0.932 | **0.844** | 0.929 |
| Фридман | 5 (0) | 1.713 | 1.839 | **1.631** | 1.911 |
| Фридман | 10 (5) | 1.871 | 1.969 | **1.735** | 2.015 |
| Фридман | 50 (45) | 2.071 | 2.171 | **1.916** | 2.326 |

И третий эксперимент — зависимость из резких ступенек:
$y = 3 \cdot [x_0 > 0.3] + 2 \cdot [x_1 > 0.7][x_2 > 0.5]$ плюс шум со стандартным отклонением 0.5;
ещё семь признаков шумовые. RMSE на тесте при всех признаках
в узле (предел, заданный шумом, — 0.5):

| Обучающих объектов | Лес | Extra Trees |
|---|---|---|
| 300 | **0.559** | 0.665 |
| 3000 | **0.525** | 0.539 |

Выводы:

- **на гладких зависимостях Extra Trees со всеми признаками в узле стабильно лучше леса** — на 5–7 %
  во всех шести строках. Шумовые признаки ему при этом не мешают: из случайных разбиений по всем
  признакам всё равно выбирается лучшее;
- **Extra Trees с уменьшенным `max_features` при большом числе шумовых признаков — худший вариант**
  (2.326 в последней строке). Две рандомизации складываются: узлу достаются в основном шумовые признаки
  со случайными порогами;
- **на резких порогах и малых данных Extra Trees проигрывает**: 0.665 против 0.559. Чтобы воспроизвести
  ступеньку, порог должен попасть точно в 0.3; лес находит его перебором, Extra Trees — только
  приближается к нему случайными попытками, и на 300 объектах попыток не хватает. Сюда же относятся
  бинарные и категориальные признаки с сильным эффектом и бизнес-правила с жёсткими границами;
- на шумной классификации разницы почти нет. Отток клиентов, 500 деревьев, `min_samples_leaf=20`:
  Extra Trees — точность 0.711, log loss 0.559, ROC-AUC 0.751; лес — 0.721, 0.553, 0.757. Без ограничения
  листа Extra Trees ещё хуже леса (log loss 3.41): каждое дерево помнит все объекты, и вероятности
  получаются из одних нулей и единиц.

Практическое правило: Extra Trees — это замена одного слова в коде. Его стоит пробовать всегда, начиная
с `max_features=1.0` для регрессии, и сравнивать с лесом на кросс-валидации.

## 3. Обобщение: бэггинг на подвыборках

Бутстреп — не единственный способ сделать обучающие выборки разными. `BaggingRegressor`
и `BaggingClassifier` принимают любую базовую модель и четыре параметра:

- `max_samples` — сколько объектов получает каждая модель (доля или число);
- `bootstrap` — выбирать объекты с возвращением (`True`) или без (`False`);
- `max_features` — сколько признаков получает каждая модель;
- `bootstrap_features` — выбирать признаки с возвращением или без.

Исторические названия методов — это комбинации этих параметров:

| Метод | `bootstrap` | `max_samples` | `max_features` | Что случайно |
|---|---|---|---|---|
| Bagging (Брейман, 1996) | `True` | 1.0 | 1.0 | объекты, с возвращением |
| Pasting (Брейман, 1999) | `False` | < 1.0 | 1.0 | объекты, без возвращения |
| Random Subspaces (Хо, 1998) | `False` | 1.0 | < 1.0 | признаки |
| Random Patches (Лупп, Гёртс, 2012) | любой | < 1.0 | < 1.0 | и объекты, и признаки |

```python
patches = BaggingRegressor(
    DecisionTreeRegressor(random_state=0),
    n_estimators=300,
    bootstrap=False,
    max_samples=0.632,
    max_features=0.75,
    random_state=0,
    n_jobs=-1,
).fit(X_train, y_train)
root_mean_squared_error(y_test, patches.predict(X_test))
```

Деревья без ограничений, 300 штук:

| Вариант | Параметры | RMSE на тесте | Обучение |
|---|---|---|---|
| Bagging | по умолчанию | **0.828** | 4.4 с |
| Pasting | `bootstrap=False, max_samples=0.632` | 0.836 | 4.2 с |
| Без подвыборок | `bootstrap=False, max_samples=1.0` | 1.119 | 7.0 с |
| Random Subspaces | `bootstrap=False, max_features=0.75` | 1.014 | 5.3 с |
| Random Subspaces | `bootstrap=False, max_features=0.5` | 1.378 | 4.0 с |
| Random Patches | `bootstrap=False, max_samples=0.632, max_features=0.75` | 0.992 | 3.6 с |
| Random Patches | `bootstrap=False, max_samples=0.632, max_features=0.5` | 1.363 | 2.5 с |
| Random Patches | `bootstrap_features=True, max_features=0.5` | 1.684 | 2.6 с |
| Случайный лес | `max_features=0.5` **в узле** | 0.850 | 2.6 с |

- Pasting с долей 0.632 почти равен бэггингу: важно, что выборки разные, а не как именно они получены.
- Без подвыборок все деревья учатся на одних и тех же данных и различаются только тем, как разрешаются
  равенства между разбиениями. Усреднять нечего: 1.119 при 1.178 у одного дерева.
- Подвыборки признаков здесь проваливаются, и это главный урок раздела. В `BaggingRegressor` параметр
  `max_features` выбирает признаки **один раз на всё дерево**. Дерево, которому не достались площадь
  или район, безнадёжно — а при `max_features=0.5` район не достаётся половине деревьев. В случайном лесе
  подмножество выбирается **заново в каждом узле**, и каждое дерево рано или поздно использует все
  признаки: то же значение 0.5 даёт 0.850 вместо 1.378.
- С `bootstrap_features=True` ещё хуже: признаки в подвыборке повторяются, различных остаётся меньше.

Когда Random Subspaces и Random Patches полезны:

- признаков очень много (тысячи), и большинство слабо информативны — тексты, генетика, сигналы:
  ни один признак не критичен, а обучение на части столбцов ускоряет работу и снижает корреляцию моделей;
- базовая модель — не дерево, и выбора признаков в узле у неё нет;
- данные не помещаются в память: каждая модель учится на небольшом «лоскуте» таблицы — отсюда название.

У `BaggingRegressor` тоже есть OOB-оценка (`oob_score=True` при `bootstrap=True`): для бэггинга деревьев
здесь $R^2$ = 0.935.

## 4. `max_samples` в случайном лесе

У `RandomForestRegressor` и `RandomForestClassifier` есть собственный параметр `max_samples` — размер
бутстреп-выборки для каждого дерева. По умолчанию он равен числу объектов. На больших данных его
уменьшение — самый простой способ ускорить обучение: время построения дерева растёт быстрее, чем
линейно по числу объектов.

```python
big = make_housing(75_000, seed=1)
X_big = big[FEATURES].copy()
X_big["district"] = X_big["district"].map({name: code for code, name in enumerate(sorted(DISTRICT_COEF))})
Xb_train, Xb_test, yb_train, yb_test = train_test_split(X_big, big[TARGET], test_size=0.2, random_state=0)

fast = RandomForestRegressor(100, max_features=0.5, max_samples=0.2, random_state=0, n_jobs=-1)
root_mean_squared_error(yb_test, fast.fit(Xb_train, yb_train).predict(Xb_test))
```

60 000 обучающих объектов, 100 деревьев, 4 ядра:

| `max_samples` | Объектов на дерево | RMSE на тесте | Обучение | Размер модели |
|---|---|---|---|---|
| `None` | 60 000 | **0.632** | 4.7 с | 546 МБ |
| 0.5 | 30 000 | 0.642 | 2.8 с | 340 МБ |
| 0.2 | 12 000 | 0.671 | 1.2 с | 156 МБ |
| 0.1 | 6 000 | 0.710 | 0.7 с | 82 МБ |
| 0.05 | 3 000 | 0.773 | 0.4 с | 42 МБ |
| 0.01 | 600 | 1.010 | 0.2 с | 9 МБ |
| `None`, `min_samples_leaf=5` | 60 000 | 0.641 | 3.1 с | 87 МБ |

- Половина данных на дерево — потеря 1.6 % качества при ускорении в 1.7 раза; пятая часть — 6 %
  и ускорение вчетверо. Для перебора гиперпараметров и первых экспериментов это выгодный обмен.
- Маленькие подвыборки увеличивают смещение: дерево на 600 объектах слишком грубое (1.010 — на уровне
  линейной регрессии, у которой здесь 1.034).
- Если цель — память, а не время, `min_samples_leaf` эффективнее: модель в шесть раз меньше при том же
  качестве, что у `max_samples=0.5`.
- Попутное наблюдение: на 60 000 объектов лес даёт 0.632 при пределе 0.518, на 3500 объектах было 0.850
  при пределе 0.548. Лесу нужно много данных, чтобы приблизить гладкую зависимость ступеньками.

## 5. Бэггинг над другими моделями

`BaggingRegressor` принимает любую модель. Стоит ли усреднять линейные регрессии?

```python
from sklearn.linear_model import LinearRegression

X_onehot = pd.get_dummies(X, columns=["district"], dtype=float)
A_train, A_test = X_onehot.loc[X_train.index], X_onehot.loc[X_test.index]
single = LinearRegression().fit(A_train, y_train)
bagged = BaggingRegressor(LinearRegression(), n_estimators=100, random_state=0).fit(A_train, y_train)
root_mean_squared_error(y_test, single.predict(A_test)), root_mean_squared_error(y_test, bagged.predict(A_test))
```

| Базовая модель | Одна модель | Бэггинг, 100 моделей | Разброс предсказаний между моделями | Корреляция ошибок моделей |
|---|---|---|---|---|
| Линейная регрессия | 1.0609 | 1.0609 | 0.08 | 0.995 |
| Метод 5 ближайших соседей | 1.151 | 1.125 | 0.54 | 0.775 |
| Дерево без ограничений | 1.179 | **0.818** | 0.82 | 0.430 |

Разброс — среднее по тестовым объектам стандартное отклонение предсказаний ста моделей ансамбля;
корреляция — средняя попарная корреляция их ошибок на тесте.

Бэггинг линейной регрессии совпал с одной регрессией до четвёртого знака. Объяснение — формула
из урока 4.2.1: разброс ансамбля не опускается ниже $\rho\sigma^2$. Линейная регрессия — устойчивая
модель: на разных бутстреп-выборках она даёт почти одинаковые коэффициенты, корреляция ошибок 0.995,
собственный разброс мал. Её ошибка — это смещение, а смещение усреднением не лечится. Метод ближайших
соседей занимает промежуточное положение, дерево — самая неустойчивая модель и выигрывает больше всех.

Правило: **бэггинг нужен неустойчивым моделям с малым смещением**. Для линейных моделей, наивного
Байеса, метода опорных векторов с линейным ядром он только умножает время обучения на число моделей.

## 6. Isolation Forest: случайные деревья для поиска аномалий

Extra Trees строит разбиения почти наугад. Если довести идею до конца — выбирать и признак, и порог
полностью случайно, вообще не глядя на целевую переменную, — получится инструмент для другой задачи.

**Isolation Forest** (Лю, Тин, Чжоу, 2008): каждое дерево строится на небольшой подвыборке (по умолчанию
256 объектов) и делит её случайными разбиениями, пока объекты не окажутся в отдельных листьях. Необычный
объект отделяется от остальных за несколько разбиений, типичный — только в глубине дерева. Мера
аномальности — средняя по деревьям длина пути до объекта: чем короче, тем подозрительнее. Разметка
не нужна.

```python
table = pd.DataFrame(
    {
        "price_m2": flats["price"] / flats["area"],
        "living_share": flats["living_area"] / flats["area"],
        "floors_above": flats["floors_total"] - flats["floor"],
        "area": flats["area"],
    }
)
detector = IsolationForest(n_estimators=300, random_state=0).fit(table)
suspicion = -detector.score_samples(table)  # чем больше, тем подозрительнее
table.assign(suspicion=suspicion).nlargest(3, "suspicion")
```

Эксперимент: к 5000 объявлениям добавлено 60 испорченных шести видов, по 10 каждого: цена умножена на 5;
цена поделена на 5; жилая площадь больше общей; этаж выше этажности дома; площадь 400 м²; квартира
22 м² в доме 90 лет за 25 млн руб. Смотрим, сколько испорченных объявлений попало в число самых
подозрительных:

| Что подано в Isolation Forest | ROC-AUC | Из 60 первых | Из 120 первых |
|---|---|---|---|
| Все 15 столбцов: 14 признаков и цена | 0.770 | 1 | 3 |
| 6 столбцов: площади, этаж, этажность, возраст, цена | 0.866 | 8 | 18 |
| 4 построенных признака (код выше) | **0.933** | 22 | 30 |

На построенных признаках среди 120 самых подозрительных: площадь 400 м² — 10 из 10; маленькая старая
дорогая квартира — 10 из 10; жилая площадь больше общей — 6; цена ×5 — 4; цена ÷5 — 0; этаж выше
этажности — 0.

Результат скромнее, чем обещают описания метода, и это полезно увидеть:

- Isolation Forest находит объекты, **далёкие от остальных вдоль отдельных осей**. Несогласованность
  значений (жилая площадь больше общей) он не видит, пока она не выражена признаком;
- посторонние столбцы размывают результат: в таблице из 15 столбцов разбиения чаще попадают на день
  недели и идентификатор риелтора, чем на цену. Отбор и построение признаков здесь важнее, чем в обучении
  с учителем, где бесполезные признаки отсеивает сама модель;
- порог выбирается равномерно между минимумом и максимумом, поэтому аномалии у длинного хвоста
  распределения заметны, а у короткого — нет: цена метра впятеро ниже обычной ближе к основной массе,
  чем впятеро выше;
- оценить детектор без разметки нельзя. Здесь мы знали, какие объявления испорчены; в жизни хотя бы
  несколько десятков подтверждённых аномалий придётся найти вручную.

Isolation Forest — быстрый первый инструмент для поиска ошибок в данных и грубого мошенничества,
но не замена проверкам согласованности, написанным вручную.

## 7. Как настраивать лес

| Параметр | Что делать | Почему |
|---|---|---|
| `n_estimators` | не подбирать: 100–500 по бюджету | оптимума нет, только плато (урок 4.2.1) |
| `max_features` | **подбирать**: 3–5 значений от $\sqrt{p}$ до $p$ | главный параметр; оптимум зависит от доли шумовых признаков |
| `min_samples_leaf` | **подбирать**, если нужны вероятности или данные шумные: 1, 5, 20, 50 | сглаживает ответы листьев; заодно уменьшает модель |
| `max_depth` | обычно не трогать | `min_samples_leaf` решает ту же задачу мягче |
| `max_samples` | уменьшать на больших данных | ускорение ценой небольшого роста смещения |
| `bootstrap` | оставить `True` | иначе нет OOB-оценки |
| `criterion` | не подбирать | влияние в пределах шума (урок 4.1.2) |
| `random_state` | фиксировать, но не подбирать | «лучший seed» — это подгонка под тест |
| `n_jobs` | `-1` | деревья независимы |
| Лес или Extra Trees | попробовать оба | одна строка кода; исход зависит от данных |

Порядок работы: зафиксировать 200–300 деревьев → перебрать `max_features` и `min_samples_leaf` по
OOB-оценке (если она применима, см. урок 4.2.1) → сравнить с Extra Trees на кросс-валидации → в конце
при необходимости увеличить число деревьев. Обычно это 10–20 обучений, а не сотни.

Чего от настройки ждать не стоит. На квартирах всё, что дал перебор, — переход от 0.850 к 0.786,
то есть 8 %. Удаление дублирующих и шумовых признаков дало ещё 4 % (0.756). А увеличение выборки
с 3500 до 60 000 объектов — 26 %. Лес мало чувствителен к гиперпараметрам; данные и признаки важнее.

### Чем будет отличаться бустинг

Лес и бустинг (тема 4.3) — два способа собрать ансамбль из деревьев, и устроены они противоположно:

| | Случайный лес | Градиентный бустинг |
|---|---|---|
| Деревья строятся | независимо, параллельно | последовательно: каждое исправляет ошибки предыдущих |
| Что уменьшается | разброс | в первую очередь смещение |
| Деревья | глубокие | мелкие |
| Больше деревьев | не вредит | может переобучить, нужна ранняя остановка |
| Чувствительность к настройкам | низкая | высокая |

Лес — надёжная точка отсчёта, которую трудно испортить; бустинг при аккуратной настройке обычно точнее.
Как именно — в уроке 4.3.1.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `ValueError` при `ExtraTreesRegressor(oob_score=True)` | OOB-оценка требует `bootstrap=True`, у Extra Trees по умолчанию `False` | кросс-валидация; либо `bootstrap=True`, если потеря качества приемлема |
| Extra Trees заметно хуже леса | резкие пороги, мало данных или малый `max_features` при множестве шумовых признаков | вернуть `max_features=1.0`; выбрать лес |
| $R^2$ Extra Trees на обучении равен 1, вывод «переобучение» | без бутстрепа каждое дерево помнит все объекты | оценивать только на отложенных данных |
| `BaggingRegressor` с `max_features=0.5` намного хуже леса с тем же значением | в бэггинге признаки выбираются один раз на дерево, в лесе — в каждом узле | для деревьев использовать лес; подвыборки признаков — для тысяч слабых признаков |
| Бэггинг линейной модели не дал улучшения | модель устойчива, её ошибка — смещение | бэггинг не поможет; нужны новые признаки или другая модель |
| `bootstrap=False, max_samples=1.0` в бэггинге деревьев: ансамбль как одно дерево | все модели учатся на одних данных | включить бутстреп или уменьшить `max_samples` |
| Лес на миллионах строк обучается часами | каждое дерево строится на всей выборке | `max_samples`, `min_samples_leaf`, `n_jobs=-1` |
| Isolation Forest помечает обычные объекты и пропускает явные ошибки | много посторонних столбцов; аномалия — несогласованность признаков | отобрать столбцы, построить признаки-отношения |
| Треть данных помечена аномалиями методом `predict` | порог по умолчанию не связан с долей аномалий в данных | работать с `score_samples` и выбирать порог самостоятельно |
| Подобран «лучший» `random_state` | качество на тесте подогнано | оценить разброс по нескольким seed и сообщать его |
