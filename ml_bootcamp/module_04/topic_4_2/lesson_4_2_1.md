## Зачем это нужно

Тема 4.1 закончилась противоречием: глубокое дерево находит сложные зависимости, но запоминает шум
и меняется от выборки к выборке; мелкое — устойчиво, но грубо. Случайный лес снимает его неожиданно
простым способом: берёт сотни глубоких переобученных деревьев и усредняет их.

Лес — модель, с которой на табличных данных начинают: он почти не требует настройки и даёт оценку
качества без отдельной валидации. А перестановочная важность применима к любой модели.

## 1. Бэггинг: бутстреп и усреднение

В уроке 4.1.1 дерево, обученное на 90 % данных, в худшем случае меняло прогноз для четверти клиентов.
Будь у нас сто независимых обучающих выборок, можно было бы обучить сто деревьев и усреднить ответы:
случайные ошибки погасили бы друг друга. Выборка одна, поэтому новые имитируют **бутстрепом**: из $n$
объектов $n$ раз выбирают объект с возвращением. **Бэггинг** (bootstrap aggregating) — обучение моделей
на бутстреп-выборках и усреднение их ответов (в классификации — вероятностей).

Данные урока — объявления о продаже квартир из генератора `housing_data.py` (лежит в папке темы):
5000 объявлений, 14 признаков, цена в миллионах рублей. Истинная зависимость цены от признаков известна
и описана в docstring функции `true_price` — это позволит проверять выводы.

```python
import numpy as np
import pandas as pd
from housing_data import DISTRICT_COEF, FEATURES, TARGET, make_housing, true_price
from sklearn.metrics import root_mean_squared_error
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor

DISTRICTS = sorted(DISTRICT_COEF)


def encode(flats):
    """Признаки для деревьев: район заменён номером по алфавиту."""
    X = flats[FEATURES].copy()
    X["district"] = X["district"].map({name: code for code, name in enumerate(DISTRICTS)})
    return X


flats = make_housing()
X, y = encode(flats), flats[TARGET]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

rng = np.random.default_rng(0)
n = len(X_train)
predictions = []
for _ in range(100):
    sample = rng.integers(0, n, size=n)  # бутстреп: n номеров объектов с возвращением
    tree = DecisionTreeRegressor(random_state=0).fit(X_train.iloc[sample], y_train.iloc[sample])
    predictions.append(tree.predict(X_test))
root_mean_squared_error(y_test, np.mean(predictions, axis=0))
```

| Модель | RMSE на тесте, млн руб. | $R^2$ |
|---|---|---|
| Линейная регрессия (район — one-hot) | 1.061 | 0.879 |
| Одно дерево без ограничений (3 499 листьев) | 1.178 | 0.851 |
| Среднее 100 таких деревьев на бутстреп-выборках | **0.835** | 0.925 |
| Истинная зависимость `true_price` (предел, заданный шумом) | 0.548 | 0.968 |

Ошибка упала на 29 %. Каждое дерево по-прежнему переобучено, но по-разному, и среднее получается гладким.

## 2. Почему это работает: смещение и разброс

Ошибку модели в точке можно разложить на три части: **смещение** (насколько модель в среднем по всем
возможным обучающим выборкам отклоняется от истины), **разброс** (насколько её ответ меняется от выборки
к выборке) и неустранимый шум. Измерить их можно только там, где истина известна. Сгенерируем 40
обучающих выборок по 1000 квартир, обучим модель на каждой и сравним предсказания для 2000 новых квартир
с `true_price` (`RandomForestRegressor` с `max_features=1.0` — это в точности бэггинг деревьев):

```python
from sklearn.ensemble import RandomForestRegressor

new_flats = make_housing(2000, seed=999)
X_new, truth = encode(new_flats), true_price(new_flats)
train_sets = [make_housing(1000, seed=100 + s) for s in range(40)]


def decompose(make_model):
    preds = np.array([make_model(s).fit(encode(d), d[TARGET]).predict(X_new) for s, d in enumerate(train_sets)])
    variance = preds.var(axis=0, ddof=1).mean()
    # поправка: квадрат отклонения среднего по 40 выборкам завышен на variance / 40
    bias2 = ((preds.mean(axis=0) - truth) ** 2).mean() - variance / len(train_sets)
    return bias2, variance


decompose(lambda s: DecisionTreeRegressor(random_state=0))
decompose(lambda s: RandomForestRegressor(100, max_features=1.0, random_state=s, n_jobs=-1))
```

| Модель | Смещение² | Разброс | Сумма |
|---|---|---|---|
| Линейная регрессия | 0.814 | 0.022 | 0.836 |
| Дерево глубины 4 | 1.268 | 0.599 | 1.867 |
| Дерево без ограничений | 0.389 | 1.249 | 1.638 |
| Бэггинг: 100 деревьев без ограничений | 0.514 | **0.188** | **0.702** |

Что видно:

- у глубокого дерева смещение мало, разброс огромен; у линейной модели — наоборот;
- бэггинг уменьшил разброс в 6.6 раза;
- смещение бэггинга не меньше, чем у дерева, — даже чуть больше (0.514 против 0.389). Причина:
  в бутстреп-выборке только около 63 % различных объектов (раздел 6), и дерево на ней немного грубее.
  У одного дерева из леса смещение² равно 0.53 — столько же, сколько у всего леса.

Вывод, на котором стоит весь урок: **усреднение лечит разброс и не лечит смещение**. Поэтому в бэггинг
берут модели с малым смещением и большим разбросом — глубокие деревья. Усреднять мелкие деревья или
линейные модели почти бесполезно (проверим в уроке 4.2.2).

### Формула и её следствие

Пусть предсказания $B$ деревьев в точке — случайные величины с одинаковой дисперсией $\sigma^2$ и попарной
корреляцией $\rho$. Дисперсия суммы — это $B$ дисперсий и $B(B-1)$ ковариаций $\rho\sigma^2$; после деления
на $B^2$:

$$\mathrm{Var}\left(\frac{1}{B}\sum_{b=1}^{B} T_b\right) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$$

Второе слагаемое исчезает с ростом числа деревьев. Первое — нет: это предел, ниже которого разброс
не опустится. Деревья бэггинга коррелируют: они учатся на пересекающихся выборках и в первых узлах
выбирают одни и те же сильные признаки.

В нашем эксперименте для бэггинга: $\sigma^2 = 1.49$, $\rho = 0.114$. Формула предсказывает разброс 0.302
для 10 деревьев и 0.183 для 100; измерено 0.310 и 0.188. Предел $\rho\sigma^2 = 0.170$: сто деревьев уже
выбрали почти всё.

Чтобы уменьшить разброс дальше, нужно уменьшать $\rho$ — делать деревья менее похожими.

## 3. Случайный лес: декорреляция деревьев

Случайный лес (Брейман, 2001) — это бэггинг деревьев плюс одна поправка: **в каждом узле лучшее разбиение
ищется не по всем признакам, а по случайному подмножеству** из `max_features` признаков. Подмножество
выбирается заново в каждом узле, а не один раз на дерево. Сильный признак больше не попадает в корень
каждого дерева, и деревья становятся разнообразнее.

Тот же эксперимент для разных `max_features` (признаков 14). Два последних столбца — лес из 300 деревьев
на полной обучающей выборке в 3500 объектов:

| `max_features` | Смещение² | $\sigma^2$ дерева | $\rho$ | Предел $\rho\sigma^2$ | Разброс леса | Сумма | RMSE на тесте | Обучение |
|---|---|---|---|---|---|---|---|---|
| 14 (бэггинг) | 0.514 | 1.49 | 0.114 | 0.170 | 0.188 | **0.702** | **0.826** | 4.5 с |
| 7 | 0.698 | 2.50 | 0.048 | 0.120 | 0.148 | 0.846 | 0.850 | 2.6 с |
| 4 | 1.169 | 3.80 | 0.028 | 0.106 | 0.147 | 1.316 | 1.006 | 1.9 с |
| 2 | 2.110 | 5.31 | 0.018 | 0.096 | 0.152 | 2.262 | 1.344 | 1.4 с |

Декорреляция работает: $\rho$ падает с 0.114 до 0.018, предел разброса снижается. Но у неё есть цена,
о которой учебники говорят реже:

- отдельное дерево становится хуже: его дисперсия выросла в 3.6 раза;
- **растёт смещение**: узел, которому не достался ни один полезный признак, делит данные по шуму.

На этих данных цена оказалась выше выигрыша: лучший вариант — все 14 признаков. Причина в данных: цену
почти целиком определяют площадь и район, три признака шумовые, два дублируют площадь. При четырёх
кандидатах из четырнадцати многие узлы выбирают между плохим и очень плохим разбиением.

Практические выводы:

- `max_features` — главный параметр леса, и универсального значения нет. Чем больше в данных
  бесполезных признаков и чем сильнее доминируют один-два признака, тем большее значение нужно;
- значения по умолчанию в scikit-learn разные: `"sqrt"` у `RandomForestClassifier` и `1.0` у
  `RandomForestRegressor` — регрессионный «лес» по умолчанию является бэггингом;
- меньшее значение пропорционально ускоряет обучение: значение 7 даёт здесь на 3 % худший RMSE
  за 58 % времени. Дальше в уроке используется лес с `max_features=0.5`.

## 4. Сколько нужно деревьев

```python
forest = RandomForestRegressor(300, max_features=0.5, oob_score=True, random_state=0, n_jobs=-1)
forest.fit(X_train, y_train)
root_mean_squared_error(y_test, forest.predict(X_test))
```

| Деревьев | RMSE на тесте | $R^2$ на обучении | Обучение (1 ядро) | Предсказание | Размер модели |
|---|---|---|---|---|---|
| 1 | 1.374 | 0.925 | 0.01 с | 0.002 с | 0.3 МБ |
| 10 | 0.936 | 0.983 | 0.11 с | 0.004 с | 3.2 МБ |
| 30 | 0.878 | 0.988 | 0.26 с | 0.011 с | 9.6 МБ |
| 100 | 0.853 | 0.990 | 0.88 с | 0.032 с | 32 МБ |
| 300 | 0.850 | 0.991 | 2.80 с | 0.095 с | 96 МБ |
| 1000 | 0.852 | 0.991 | 8.99 с | 0.329 с | 319 МБ |

- **Лес не переобучается с ростом числа деревьев.** Ошибка на тесте падает и выходит на плато; тысяча
  деревьев не хуже трёхсот. Это прямое следствие формулы: добавление деревьев только уменьшает второе
  слагаемое. Сравните с глубиной дерева в теме 4.1, где «больше» быстро становилось «хуже».
- Число деревьев поэтому не подбирают, а выбирают по бюджету: берут столько, сколько не жалко времени
  и памяти. Первые 30 деревьев дают почти весь выигрыш, после 100–300 улучшения в пределах шума.
- Цена линейна: время обучения, время предсказания и размер модели растут пропорционально числу
  деревьев. Модель в 319 МБ для 3500 объектов — аргумент против «на всякий случай 1000». Деревья
  независимы, поэтому обучение идеально распараллеливается: `n_jobs=-1` задействует все ядра.
- $R^2$ на обучении 0.99 при 0.92 на тесте — для леса норма: объект участвует в обучении 63 % деревьев,
  и те его помнят. Оценивать лес по обучающей выборке бессмысленно.

## 5. Глубина деревьев и вероятности

В регрессии на квартирах лесу нужны глубокие деревья: при `min_samples_leaf` 1, 3, 10 и 30 RMSE на тесте
равен 0.850, 0.862, 0.953 и 1.191 (а размер модели — 96, 27, 7.5 и 2.5 МБ).
Так и говорит теория: смещение усреднением не исправить, поэтому деревья растят до конца. Но это верно
не всегда. Вернёмся к оттоку клиентов из тем 3.1 и 4.1 — с тем же разбиением и теми же шестью признаками.

```python
from churn_data import make_clients
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, log_loss, roc_auc_score

clients = make_clients()
Xc = clients.assign(fee_k=clients["monthly_fee"] / 1000, annual=(clients["contract"] == "annual").astype(int))
Xc["autopay"] = Xc["autopay"].astype(int)
Xc = Xc[["tenure_months", "fee_k", "services", "annual", "autopay", "support_calls"]]
yc = clients["churn"]
Xc_train, Xc_test, yc_train, yc_test = train_test_split(Xc, yc, test_size=0.3, random_state=0, stratify=yc)

churn_forest = RandomForestClassifier(500, min_samples_leaf=20, oob_score=True, random_state=0, n_jobs=-1)
proba = churn_forest.fit(Xc_train, yc_train).predict_proba(Xc_test)[:, 1]
accuracy_score(yc_test, proba > 0.5), log_loss(yc_test, proba), roc_auc_score(yc_test, proba)
```

| `min_samples_leaf` | Листьев в дереве | Точность | Log loss | ROC-AUC |
|---|---|---|---|---|
| 1 (по умолчанию) | 989 | 0.669 | 0.717 | 0.687 |
| 5 | 287 | 0.704 | 0.564 | 0.745 |
| 20 | 76 | **0.721** | **0.553** | **0.757** |
| 50 | 30 | 0.717 | 0.556 | 0.756 |
| 100 | 15 | 0.699 | 0.562 | 0.751 |

Лес по умолчанию здесь хуже одного аккуратного дерева. Данные об оттоке очень шумные: исход клиента
во многом случаен, а лист из одного-двух клиентов выдаёт «вероятность» 0 или 1. Среднее пятисот таких
ответов — оценка вероятности с большим разбросом, и log loss за это наказывает.

Правило: **если нужны вероятности или данные сильно зашумлены, `min_samples_leaf` нужно подбирать**
(начать стоит с 5–50). Если целевая переменная определяется признаками почти точно — оставлять 1.
Параметр `max_features` на этих данных почти ничего не меняет: при `min_samples_leaf=50` значения 2, 3
и 6 дают log loss 0.556, 0.555 и 0.555.

## 6. Out-of-bag оценка

Вероятность того, что конкретный объект ни разу не выбран за $n$ попыток, равна

$$\left(1 - \frac{1}{n}\right)^n \xrightarrow[n \to \infty]{} e^{-1} \approx 0.368$$

Уже при $n = 10$ это 0.349, при $n = 100$ — 0.366, при $n = 3500$ — 0.3678. Проверка: в тысяче
бутстреп-выборок из 3500 объектов доля различных объектов в среднем 0.632.

Значит, для каждого дерева около 36.8 % объектов — **out-of-bag (OOB)**: дерево их не видело. Для каждого
объекта можно усреднить предсказания только тех деревьев, которые на нём не учились (их примерно треть),
и сравнить с ответом. Получается оценка качества на «отложенных» данных без отложенной выборки.

```python
forest.oob_score_, forest.score(X_test, y_test)
```

| Данные | Метрика | OOB | Кросс-валидация, 5 блоков | Тест |
|---|---|---|---|---|
| Квартиры | $R^2$ | 0.932 | 0.926 ± 0.005 | 0.923 |
| Квартиры | RMSE | 0.802 | 0.832 | 0.850 |
| Отток (`min_samples_leaf=50`) | точность | 0.723 | 0.725 ± 0.016 | 0.717 |

OOB-оценка согласуется с кросс-валидацией и стоит в 4–6 раз дешевле, потому что получается попутно,
за одно обучение: 0.9 с против 3.6 с на квартирах, 1.3 с против 7.3 с на оттоке. Обе оценки отличаются
от теста в пределах его собственного шума. Для классификатора
`oob_score_` — точность; вероятности лежат в `oob_decision_function_`, для регрессора предсказания —
в `oob_prediction_`, по ним считается любая метрика. Подбор `min_samples_leaf` и `max_features` по OOB —
стандартный приём, тест при этом остаётся нетронутым.

Тонкость: OOB-предсказание усредняет около трети деревьев, поэтому при малом их числе оценка
пессимистична (30 деревьев: OOB $R^2$ 0.915 при 0.917 на тесте; 300 — 0.932 при 0.923).

### Когда OOB обманывает

OOB честна, только если объекты независимы. Два случая, когда это не так.

**Группы и дубликаты.** Повторим каждое объявление обучающей выборки три раза — как если бы квартиру
выставили на трёх площадках:

| Обучающая выборка | OOB $R^2$ | OOB RMSE | RMSE на тесте |
|---|---|---|---|
| Исходная | 0.932 | 0.802 | 0.850 |
| Каждое объявление трижды | **0.999** | **0.112** | 0.835 |

Копия объекта почти всегда есть в выборке дерева, для которого сам объект — OOB, и дерево «угадывает»
ответ. То же с несколькими записями одного клиента или пациента. Нужна групповая проверка (`GroupKFold`).

**Время.** В данных есть рост цен на 0.6 % в месяц. Обучим лес на первых 24 месяцах и проверим на
последних 12 — так модель будет использоваться в жизни:

| | OOB (месяцы 0–23) | Месяцы 24–35 |
|---|---|---|
| RMSE | 0.788 | 1.039 |
| Сумма прогнозов / сумма фактических цен: 24–27, 28–31, 32–35 | — | 0.946, 0.937, 0.907 |
| То же для линейной регрессии | — | 0.990, 1.002, 0.985 |

OOB обещает ошибку 0.79, в будущем она 1.04, и лес систематически занижает цены — чем дальше, тем сильнее.
Это отсутствие экстраполяции из урока 4.1.1: для месяца 30 лес отвечает как для месяца 23. Линейная модель
тренд продолжает. OOB этого не видит, потому что перемешивает прошлое с будущим; для данных со временем
нужна проверка на более позднем периоде (`TimeSeriesSplit`).

## 7. Важность признаков

### Встроенная важность и её смещение

`feature_importances_` леса — это MDI из урока 4.1.2, усреднённая по деревьям. Недостатки унаследованы.
Добавим к данным об оттоке четыре шумовых признака с разным числом уникальных значений и обучим лес
с настройками по умолчанию:

```python
from sklearn.inspection import permutation_importance

rng = np.random.default_rng(0)
m = len(Xc)
Xn = Xc.assign(noise_bin=rng.integers(0, 2, m), noise_10=rng.integers(0, 10, m))
Xn = Xn.assign(noise_cont=rng.normal(size=m), noise_id=rng.permutation(m))
Xn_train, Xn_test = Xn.loc[Xc_train.index], Xn.loc[Xc_test.index]
noisy_forest = RandomForestClassifier(500, random_state=0, n_jobs=-1).fit(Xn_train, yc_train)
perm = permutation_importance(noisy_forest, Xn_test, yc_test, n_repeats=10, random_state=0, scoring="roc_auc")
pd.DataFrame({"mdi": noisy_forest.feature_importances_, "perm": perm.importances_mean}, index=Xn.columns)
```

### Перестановочная важность

Идея: если признак важен, то без него модель ошибается сильнее. Убрать признак, не переобучая модель,
можно, **перемешав его значения между объектами отложенной выборки**: распределение признака сохраняется,
связь с ответом и остальными признаками рвётся. Важность — падение метрики, усреднённое по нескольким
перестановкам. В таблице выше — падение ROC-AUC на тесте: `annual` 0.101, шумовые признаки 0.002–0.007.

Что нужно знать:

- считать на **отложенных** данных. На обучающих тот же лес приписывает `noise_id` важность 0.024 —
  в пять раз больше, чем на тесте: он действительно пользуется шумом, чтобы помнить обучающие объекты;
- важность может быть отрицательной — это шум оценки, а не «вредный признак»;
- `importances_std` — разброс только по перестановкам, без учёта случайности самой тестовой выборки:
  значение 0.007 ± 0.003 не доказывает пользу. Полезно добавить заведомо шумовой признак как эталон;
- метод работает с любой моделью и любой метрикой; стоимость — `n_repeats` предсказаний на каждый признак.

### Ловушка коррелирующих признаков

В данных о квартирах `living_area` почти точно равна 0.62 · `area` (корреляция 0.98), `rooms` тоже
определяется площадью. В формулу цены входит только `area`. Лес с `max_features=0.5`, важность на тесте
по $R^2$ (показаны 10 признаков из 14):

| Признак | MDI | Перестановочная (тест) |
|---|---|---|
| `district` | 0.380 | 0.877 ± 0.024 |
| `area` | 0.271 | 0.412 ± 0.010 |
| `living_area` | 0.168 | 0.102 ± 0.005 |
| `rooms` | 0.049 | 0.007 ± 0.001 |
| `metro_min` | 0.032 | 0.034 ± 0.003 |
| `age` | 0.027 | 0.023 ± 0.001 |
| `desc_len` (шум) | 0.010 | −0.000 ± 0.000 |
| `agent_id` (шум) | 0.010 | −0.001 ± 0.000 |
| `floor` | 0.008 | 0.001 ± 0.000 |
| `balcony` | 0.002 | 0.000 ± 0.000 |

Шум здесь перестановочная важность отсеяла чисто, а MDI поставила длину описания и идентификатор
риелтора выше балкона и этажа, которые в формуле цены есть. Но посмотрите на площадь: 0.41 — вдвое меньше,
чем у района, хотя цена пропорциональна площади. Проверим:

| Проверка | Результат |
|---|---|
| Перемешать `area`, `living_area`, `rooms` вместе, одной перестановкой | падение $R^2$ на **0.983** |
| Важность `area` в лесе, обученном без `living_area` и `rooms` | **0.940** |
| Переобучить без `living_area` | $R^2$ 0.920 (было 0.923) |
| Переобучить без `area` | $R^2$ 0.908 |
| Переобучить без всех трёх | $R^2$ 0.406 |

Когда `area` перемешана, лес берёт почти ту же информацию из `living_area`. Важность группы **делится**
между её членами, причём доли зависят от настроек: MDI площади, жилой площади и комнат равна
0.43 / 0.05 / 0.00 при `max_features=1.0` и 0.23 / 0.19 / 0.08 при `1/3`. Когда дублёров много, каждый
получает важность около нуля — и можно ошибочно выбросить их все.

Как проверять: найти группы связанных признаков (корреляции, кластеризация признаков); перемешивать
группу целиком или оставить по одному представителю; для окончательного ответа — **удаление столбца
с переобучением**. Вопросы при этом разные. Перестановочная важность: «насколько *эта модель* опирается
на признак». Удаление с переобучением: «насколько признак нужен *для задачи*». Для `area` ответы —
0.41 и 0.015.

### Важность — не причинность

`living_area` получила заметную важность, хотя на цену не влияет: модель использует её как заменитель
площади. Увеличение жилой площади перепланировкой цену не изменит. Точно так же в уроке 3.1.2 автоплатёж
был связан с оттоком сильнее своего настоящего эффекта из-за скрытой лояльности. Важность признака
описывает модель и данные, но не устройство мира: из неё нельзя вывести, что произойдёт при вмешательстве.

## 8. Лес против дерева и логистической регрессии

Данные об оттоке, те же метрики, что в уроке 4.1.3:

| Модель | Точность | Log loss | ROC-AUC |
|---|---|---|---|
| Дерево без ограничений | 0.646 | 12.007 | 0.615 |
| Лучшее одиночное дерево (`min_samples_leaf=100`) | 0.703 | 0.565 | 0.741 |
| Бэггинг, 500 деревьев без ограничений | 0.669 | 0.690 | 0.687 |
| Случайный лес по умолчанию, 500 деревьев | 0.669 | 0.717 | 0.687 |
| Случайный лес, `min_samples_leaf=20` | **0.721** | 0.553 | 0.757 |
| Логистическая регрессия | 0.715 | **0.548** | **0.761** |

Настроенный лес обошёл лучшее дерево по всем трём метрикам. Логистическую регрессию — только по точности,
и то в пределах шума теста; по log loss и ROC-AUC он ей немного уступает. Это не неудача леса, а свойство
данных: отток здесь сгенерирован моделью, линейной в логарифме шансов, — ровно той, которую подбирает
логистическая регрессия. Лесу приходится приближать гладкую зависимость ступеньками, и на 3500 объектах
шума больше, чем выигрыша от гибкости. На квартирах, где цена — произведение нелинейных множителей,
картина обратная: RMSE леса 0.826–0.850 против 1.061 у линейной регрессии. Лес не обязан побеждать:
простая модель с правильной структурой — сильный соперник, и сравнивать с ней нужно всегда.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| $R^2$ леса на обучении 0.99, вывод «модель переобучена, нужно меньше деревьев» | объект помнят деревья, в выборку которых он попал; число деревьев на переобучение не влияет | оценивать по OOB или отложенной выборке |
| Лес даёт плохой log loss, хотя точность приемлема | листья из одного-двух объектов дают вероятности 0 и 1 | подобрать `min_samples_leaf`; при необходимости калибровка (урок 3.2.2) |
| `RandomForestRegressor` по умолчанию назван «случайным лесом», а работает как бэггинг | `max_features=1.0` по умолчанию | подобрать `max_features` по OOB |
| OOB-оценка почти идеальна, на новых данных модель слабая | дубликаты или группы связанных объектов | `GroupKFold`; удалить дубликаты |
| OOB хороша, а прогноз на следующий месяц систематически занижен | тренд: лес не экстраполирует, OOB перемешивает время | проверка на позднем периоде; предсказывать прирост |
| Идентификатор или шумовой признак в лидерах `feature_importances_` | смещение MDI к признакам с большим числом значений | перестановочная важность на отложенных данных |
| Все признаки из группы похожих получили малую важность и были удалены | важность делится между коррелирующими признаками | перемешивать группу целиком; удаление с переобучением |
| «Признак важен — значит, на него надо воздействовать» | важность не является причинным эффектом | эксперимент или причинный анализ (урок 3.1.2) |
