## Зачем это нужно

Всё глубокое обучение держится на одном алгоритме: посчитать потери (прямой проход), посчитать
производные потерь по всем весам (обратный проход), сдвинуть веса. В PyTorch обратный проход — одна
строка `loss.backward()`, и руками его никто не пишет. Но понимать его нужно по трём причинам:

- **отладка.** «Потери не падают», `nan` на третьей эпохе, сеть выдаёт константу — всё это диагностируется
  через градиенты. Нельзя смотреть на градиенты, не понимая, откуда они берутся;
- **стоимость.** Сколько памяти нужно на обучение, почему оно дороже предсказания, что даёт
  `torch.no_grad()` — ответы следуют из устройства обратного прохода;
- **собеседования.** «Выведите градиент softmax с кросс-энтропией» — стандартный вопрос.

## 1. Нейрон, слой, сеть

**Нейрон** — это линейная модель, к выходу которой применена нелинейная функция $\varphi$ (функция
активации): $h = \varphi(w^\top x + b)$. Логистическая регрессия из урока 3.1.3 — один нейрон с сигмоидой.

**Слой** — несколько нейронов, получающих один и тот же вход. Веса $m$ нейронов складываются в матрицу,
и весь слой для батча из $n$ объектов считается одним матричным умножением:

$$H = \varphi(XW + b), \qquad X: n \times d, \quad W: d \times m, \quad b: m, \quad H: n \times m$$

Вектор $b$ прибавляется к каждой строке по правилам broadcasting (урок 2.2.1). **Многослойный перцептрон**
(MLP) — несколько слоёв подряд: выход одного служит входом следующего. Сеть с одним скрытым слоем
для классификации на $K$ классов:

$$Z_1 = XW_1 + b_1, \qquad H = \varphi(Z_1), \qquad Z_2 = HW_2 + b_2$$

Строки $Z_2$ (форма $n \times K$) называют **логитами**: это оценки классов до превращения в вероятности.
Скрытый слой — обучаемое преобразование признаков, последний — softmax-регрессия на новых признаках.

## 2. Зачем нужна нелинейность

Уберём $\varphi$. Тогда два слоя сворачиваются в один:

$$(XW_1 + b_1)W_2 + b_2 = X\underbrace{(W_1W_2)}_{W} + \underbrace{(b_1W_2 + b_2)}_{b}$$

Проверка на случайных матрицах через `np.allclose` это подтверждает (расхождение 4·10⁻¹⁶).
Сколько бы линейных слоёв ни стояло подряд, получится линейная модель. Проверим на данных, где линейной
модели недостаточно: `make_moons(n_samples=1000, noise=0.2, random_state=0)`, 30 % — тест. Сети — один
скрытый слой из 16 нейронов, 3 000 шагов полного градиентного спуска с шагом 0.5.

| Модель | Точность на обучении | Точность на тесте |
|---|---|---|
| `LogisticRegression` | 0.861 | 0.870 |
| Сеть 2–16–2 без активации | 0.864 | 0.870 |
| Сеть 2–16–2, ReLU | 0.970 | 0.970 |
| Сеть 2–16–2, tanh | 0.969 | 0.970 |

Сеть без активации дала то же качество, что и логистическая регрессия: 82 параметра вместо трёх ничего
не добавили. Дальше в уроке используется ReLU: $\varphi(z) = \max(z, 0)$; выбор активации — тема урока 5.1.2.

## 3. Прямой проход

Данные урока — рукописные цифры `load_digits`: 1 797 изображений 8×8, вытянутых в вектор из 64 чисел
от 0 до 16.

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

X, y = load_digits(return_X_y=True)
X = X / 16.0  # приводим признаки к отрезку [0, 1]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)


def init_params(n_in, n_hidden, n_out, seed=0):
    rng = np.random.default_rng(seed)
    return [
        rng.normal(0, np.sqrt(2 / n_in), (n_in, n_hidden)),  # масштаб весов — тема урока 5.1.2
        np.zeros(n_hidden),
        rng.normal(0, np.sqrt(2 / n_hidden), (n_hidden, n_out)),
        np.zeros(n_out),
    ]


def forward(params, X):
    W1, b1, W2, b2 = params
    Z1 = X @ W1 + b1
    H = np.maximum(Z1, 0)
    Z2 = H @ W2 + b2
    return Z1, H, Z2
```

Формы для сети 64–32–10 и батча из 128 объектов:

| Величина | `X` | `W1` | `b1` | `Z1`, `H` | `W2` | `b2` | `Z2` |
|---|---|---|---|---|---|---|---|
| Форма | (128, 64) | (64, 32) | (32,) | (128, 32) | (32, 10) | (10,) | (128, 10) |

## 4. Функция потерь

Для регрессии выход сети сравнивают с ответом среднеквадратичной ошибкой, как в уроке 3.1.1. Для
классификации логиты превращают в вероятности функцией softmax и берут кросс-энтропию — это log loss
из урока 3.1.3, обобщённый на $K$ классов:

$$p_{ik} = \frac{e^{z_{ik}}}{\sum_j e^{z_{ij}}}, \qquad L = -\frac{1}{n}\sum_{i=1}^{n} \log p_{i,y_i}$$

Реализация «по формуле» ломается на больших логитах: для `[1000, 0, -1000]` она возвращает
`[nan, 0, 0]` и предупреждение о переполнении, потому что `exp(1000)` — это `inf`, а `inf / inf` — `nan`.
Вторая ловушка — сначала получить вероятность,
а потом взять логарифм: для логитов `[0, 800]` вероятность первого класса округляется до нуля,
и потери равны `inf`, хотя правильный ответ — 800. Обе проблемы решает вычисление сразу **логарифма**
softmax с вынесением максимума (приём log-sum-exp):

$$\log p_{ik} = (z_{ik} - m_i) - \log\sum_j e^{z_{ij} - m_i}, \qquad m_i = \max_j z_{ij}$$

Вычитание константы из всех логитов строки не меняет softmax, но теперь наибольший показатель экспоненты
равен нулю: переполнение невозможно, а сумма под логарифмом не меньше единицы.

```python
def log_softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)
    return Z - np.log(np.exp(Z).sum(axis=1, keepdims=True))


def loss_fn(params, X, y):
    return -log_softmax(forward(params, X)[2])[np.arange(len(y)), y].mean()


log_softmax(np.array([[1000.0, 0.0, -1000.0]]))  # [[0., -1000., -2000.]]
```

По той же причине в PyTorch функция потерь `cross_entropy` принимает логиты, а не вероятности.
Потери необученной сети на первом батче — 2.2916. Это близко к $\ln 10 = 2.3026$: сеть, которая ничего
не знает, должна давать каждому из 10 классов вероятность около 0.1. К этой проверке вернёмся в уроке 5.1.2.

## 5. Обратное распространение ошибки

Нужны производные потерь по всем 2 410 параметрам. Обратное распространение (backpropagation) — это
цепное правило, применённое в удобном порядке: от потерь назад ко входу, с переиспользованием уже
посчитанных производных. Обозначим $dA = \partial L / \partial A$ — массив той же формы, что и $A$.

**Шаг 1: логиты.** Для одного объекта с правильным классом $y$: $L = -z_y + \log\sum_j e^{z_j}$. Тогда

$$\frac{\partial L}{\partial z_k} = -[k = y] + \frac{e^{z_k}}{\sum_j e^{z_j}} = p_k - [k = y]$$

В матричном виде, с учётом усреднения по батчу: $dZ_2 = (P - Y)/n$, где $Y$ — one-hot кодирование ответов.
Это главный результат урока: **градиент по логитам — разность предсказанных вероятностей и правильного
ответа**. Тот же вид имел градиент логистической регрессии; для MSE с линейным выходом получается
$2(\hat{y} - y)/n$. Сложные производные softmax и логарифма сократились.

**Шаг 2: линейный слой** $Z_2 = HW_2 + b_2$. Элемент $W_2[j, k]$ влияет на логит $k$ каждого объекта
с коэффициентом $H[i, j]$, поэтому $dW_2[j, k] = \sum_i H[i, j] \cdot dZ_2[i, k]$, то есть $dW_2 = H^\top dZ_2$.
Смещение прибавляется ко всем объектам: $db_2 = \sum_i dZ_2[i, :]$. Градиент по входу слоя: $dH = dZ_2 W_2^\top$.

**Шаг 3: активация и первый слой.** Производная ReLU — 1 при $z > 0$ и 0 иначе: $dZ_1 = dH \odot [Z_1 > 0]$.
Для первого слоя — формулы шага 2 с $X$ вместо $H$.

| Величина | Формула | Форма (батч 128) |
|---|---|---|
| $dZ_2$ | $(P - Y)/n$ | (128, 10) |
| $dW_2$ | $H^\top dZ_2$ | (32, 10) |
| $db_2$ | сумма $dZ_2$ по объектам | (10,) |
| $dH$ | $dZ_2 W_2^\top$ | (128, 32) |
| $dZ_1$ | $dH \odot [Z_1 > 0]$ | (128, 32) |
| $dW_1$ | $X^\top dZ_1$ | (64, 32) |
| $db_1$ | сумма $dZ_1$ по объектам | (32,) |

Формулы не нужно запоминать: градиент обязан иметь форму своей переменной, а собрать массив формы (32, 10)
из $H$ (128, 32) и $dZ_2$ (128, 10) можно единственным способом — $H^\top dZ_2$.

```python
def loss_and_grads(params, X, y):
    W1, b1, W2, b2 = params
    n = len(y)
    Z1, H, Z2 = forward(params, X)
    log_probs = log_softmax(Z2)
    loss = -log_probs[np.arange(n), y].mean()

    dZ2 = np.exp(log_probs)
    dZ2[np.arange(n), y] -= 1  # P - Y без построения one-hot матрицы
    dZ2 /= n
    dW2 = H.T @ dZ2
    db2 = dZ2.sum(axis=0)
    dH = dZ2 @ W2.T
    dZ1 = dH * (Z1 > 0)
    dW1 = X.T @ dZ1
    db1 = dZ1.sum(axis=0)
    return loss, [dW1, db1, dW2, db2]
```

Обратному проходу нужны `Z1` и `H` — результаты прямого прохода приходится хранить до конца вычислений.

## 6. Численная проверка градиента

Двенадцать строк выше легко написать с ошибкой, и сеть при этом будет «как-то» учиться. Надёжный способ
проверки — сравнить с определением производной. Сдвигаем один параметр на $\pm\varepsilon$ и смотрим,
как изменились потери (центральная разность):

$$\frac{\partial L}{\partial \theta_j} \approx \frac{L(\theta + \varepsilon e_j) - L(\theta - \varepsilon e_j)}{2\varepsilon}$$

```python
def numerical_gradient(f, x, eps=1e-6):
    grad = np.zeros_like(x)
    for idx in np.ndindex(*x.shape):
        old = x[idx]
        x[idx] = old + eps
        f_plus = f()
        x[idx] = old - eps
        f_minus = f()
        x[idx] = old
        grad[idx] = (f_plus - f_minus) / (2 * eps)
    return grad


def rel_error(a, b):
    return np.abs(a - b).max() / max(1e-12, np.abs(a).max() + np.abs(b).max())
```

Сравнивают по **относительной** ошибке: градиенты бывают порядка $10^{-6}$, и абсолютная разница $10^{-7}$
для них — провал, а не успех. Проверим на 20 объектах (2 410 параметров — 4 820 прямых проходов, 0.1 с)
верную реализацию и три версии с типичными ошибками:

| Реализация | $dW_1$ | $db_1$ | $dW_2$ | $db_2$ |
|---|---|---|---|---|
| верная | 2·10⁻⁹ | 2·10⁻⁹ | 1·10⁻⁹ | 1·10⁻⁹ |
| забыта маска ReLU: `dZ1 = dH` | **0.56** | **0.55** | 1·10⁻⁹ | 1·10⁻⁹ |
| забыто деление на `n` | **0.90** | **0.90** | **0.90** | **0.90** |
| `db1` — среднее вместо суммы | 2·10⁻⁹ | **0.90** | 1·10⁻⁹ | 1·10⁻⁹ |

Разрыв между «верно» и «неверно» — восемь порядков, спутать невозможно. Проверка по каждому параметру
отдельно ещё и локализует ошибку: во второй строке выходной слой верен, значит, ошибка между ним и первым
слоем. Ориентиры для float64: меньше $10^{-7}$ — верно; больше $10^{-4}$ — почти наверняка ошибка;
между ними — разбирайтесь.

Важен выбор $\varepsilon$. Ошибка для $dW_2$ при разных значениях:

| $\varepsilon$ | 10⁻¹ | 10⁻² | 10⁻⁴ | 10⁻⁶ | 10⁻⁸ | 10⁻¹⁰ | 10⁻¹² |
|---|---|---|---|---|---|---|---|
| центральная разность | 2·10⁻⁴ | 2·10⁻⁶ | 2·10⁻¹⁰ | 1·10⁻⁹ | 2·10⁻⁷ | 1·10⁻⁵ | 1·10⁻³ |

При большом $\varepsilon$ мешает кривизна функции (ошибка центральной разности пропорциональна
$\varepsilon^2$; у односторонней — $\varepsilon$, при $\varepsilon = 10^{-4}$ она даёт 9·10⁻⁶ вместо 2·10⁻¹⁰),
при малом — округление: разность двух почти равных чисел
теряет значащие цифры. Рабочий диапазон — $10^{-4}$–$10^{-6}$. Три правила:

- **только float64.** Во float32 лучшая достижимая ошибка на той же задаче — 6·10⁻⁵ при $\varepsilon = 10^{-2}$,
  а при $\varepsilon = 10^{-6}$ — 0.39: верный градиент неотличим от неверного;
- **изломы.** В точке $z = 0$ у ReLU нет производной, и если сдвиг на $\varepsilon$ переводит нейрон через
  ноль, численная оценка неверна. Типичный случай — нулевые смещения: если у объекта погасли все нейроны
  слоя, вход следующего слоя равен смещению, то есть в точности нулю. Перед проверкой задавайте смещениям
  небольшие случайные значения;

Проверка требует двух прямых проходов на каждый параметр, поэтому её делают на маленькой сети и батче
в несколько объектов — перед обучением, а не вместо него.

## 7. Граф вычислений и автоматическое дифференцирование

Вывод раздела 5 был механическим: вычисление разбито на элементарные операции, и для каждой известно
локальное правило — как, зная градиент по выходу, получить градиент по входам.

| Операция | Градиент по входам при известном градиенте $g$ по выходу |
|---|---|
| $c = a + b$ | $da = g$, $db = g$ |
| $c = a \cdot b$ (поэлементно) | $da = g \cdot b$, $db = g \cdot a$ |
| $C = AB$ | $dA = gB^\top$, $dB = A^\top g$ |
| $c = \max(a, 0)$ | $da = g \cdot [a > 0]$ |
| $c = \sum a$ | $da = g$, растянутый до формы $a$ |

Это и есть автоматическое дифференцирование в обратном режиме (autograd). Каждая операция при выполнении
запоминает свои входы и локальное правило — так строится **граф вычислений**. Обратный проход обходит
граф от потерь к параметрам; порядок обхода — обратный топологический: узел обрабатывается после всех
узлов, которые от него зависят. Если значение используется в нескольких местах, градиенты складываются.

Полная реализация — в файле [`minigrad.py`](minigrad.py), около 70 строк кода. Каждый узел графа — объект
`Tensor` с полями `data`, `grad`, `_parents` и функцией `_backward`. Операция и обход графа:

```python
    def __matmul__(self, other):
        out = Tensor(self.data @ other.data, (self, other))

        def _backward():  # локальное правило: как раздать out.grad родителям
            self.grad += out.grad @ other.data.T
            other.grad += self.data.T @ out.grad

        out._backward = _backward
        return out

    def backward(self):
        order, visited = [], set()

        def visit(node):
            if id(node) not in visited:
                visited.add(id(node))
                for parent in node._parents:
                    visit(parent)
                order.append(node)  # узел попадает в список после всех своих родителей

        visit(self)
        self.grad = np.ones_like(self.data)
        for node in reversed(order):
            node._backward()
```

Остальные операции (`+`, `*`, `relu`, `exp`, `log`, `sum`) устроены так же. Единственная тонкость — сложение
и умножение с broadcasting: если операнд был растянут, его градиент нужно просуммировать по растянутым осям
(функция `unbroadcast`). Именно поэтому в разделе 5 получилось $db = \sum_i dZ[i, :]$. Та же сеть, но без
единой формулы для производных:

```python
W1, b1, W2, b2 = (Tensor(p) for p in init_params(64, 32, 10))
z = (Tensor(X_batch) @ W1 + b1).relu() @ W2 + b2
z = z - z.data.max(axis=1, keepdims=True)  # сдвиг на константу: градиент через него не нужен
log_probs = z - z.exp().sum(axis=1).log()
loss = -(log_probs * np.eye(10)[y_batch]).sum() * (1.0 / len(y_batch))
loss.backward()  # градиенты — в W1.grad, b1.grad, W2.grad, b2.grad
```

## 8. PyTorch: необходимый минимум

PyTorch — это NumPy-подобные массивы (тензоры) плюс autograd, устроенный так же, как `minigrad`, только
на C++ и с сотнями операций.

```python
import torch

w = torch.tensor([1.0, 2.0], requires_grad=True)  # за этим тензором autograd следит
loss = (w**2).sum()
loss.backward()
w.grad  # tensor([2., 4.])

(w**2).sum().backward()
w.grad  # tensor([4., 8.]) — градиенты накапливаются, а не перезаписываются
w.grad.zero_()
```

Что нужно знать сразу:

- `backward()` вызывают у скаляра; градиенты появляются в атрибуте `.grad` параметров и **суммируются**
  с уже лежащими там. Поэтому перед каждым шагом обучения их обнуляют;
- внутри блока `with torch.no_grad():` граф не строится: так считают предсказания и метрики — быстрее
  и без хранения промежуточных результатов;
- тип по умолчанию — `float32` (у NumPy — `float64`); `torch.tensor(массив_numpy)` сохраняет тип массива,
  обратно в NumPy и Python значения возвращают `.numpy()` и `.item()`.

Сети собирают из модулей. `nn.Module` хранит параметры и описывает прямой проход; обратный строится сам.

```python
from torch import nn


class MLP(nn.Module):
    def __init__(self, n_in, n_hidden, n_out):
        super().__init__()
        self.fc1 = nn.Linear(n_in, n_hidden)
        self.fc2 = nn.Linear(n_hidden, n_out)

    def forward(self, x):
        return self.fc2(torch.relu(self.fc1(x)))


model = MLP(64, 32, 10)
[(name, tuple(p.shape)) for name, p in model.named_parameters()]
# [('fc1.weight', (32, 64)), ('fc1.bias', (32,)), ('fc2.weight', (10, 32)), ('fc2.bias', (10,))]
```

`nn.Linear` хранит матрицу весов в форме (выходы, входы) и вычисляет $xW^\top + b$ — она транспонирована
относительно нашей записи. Модель вызывают как функцию: `model(x)`, а не `model.forward(x)`.

## 10. Мини-батчи и обучение

Градиент по всей выборке считать на каждом шаге дорого, а по одному объекту — шумно. Компромисс —
**мини-батч**: несколько десятков объектов. **Эпоха** — один проход по перемешанной обучающей выборке;
при 1 347 объектах и батче 32 в эпохе 43 шага, последний батч неполный (3 объекта). Цикл обучения
на NumPy — перемешать индексы, нарезать на батчи, для каждого вызвать `loss_and_grads` и сдвинуть параметры:
`p -= lr * g`. Тот же цикл на PyTorch — пять строк, которые вы будете писать в каждом проекте:

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
for idx in batches:  # индексы объектов очередного батча
    loss = nn.functional.cross_entropy(model(X_t[idx]), y_t[idx])
    optimizer.zero_grad()  # обнулить градиенты прошлого шага
    loss.backward()  # посчитать новые
    optimizer.step()  # сдвинуть веса
```

| Эпох | Средние потери за последнюю эпоху | Точность на обучении | Точность на тесте |
|---|---|---|---|
| 1 | 1.8782 | 0.682 | 0.691 |
| 5 | 0.3559 | 0.938 | 0.927 |
| 20 | 0.1106 | 0.982 | 0.964 |

При одинаковых начальных весах и порядке батчей история потерь NumPy и PyTorch за 20 эпох (860 шагов)
совпадает с точностью 10⁻¹⁶. Логистическая регрессия на тех же данных даёт 0.969 — простая сеть со
стандартными настройками её пока не обогнала. Что с этим делать — в следующих трёх уроках; там же
выяснится, что шаг по батчу из трёх объектов в конце каждой эпохи не так безобиден, как кажется.

**Сколько стоит обратный проход.** Сеть 256–512–10, батч 4 096 объектов, float64. NumPy: прямой проход —
19.1 мс, прямой с обратным — 43.1 мс (в 2.3 раза больше); PyTorch: 14.7 и 30.7 мс (в 2.1 раза). Обратный
проход стоит примерно столько же, сколько прямой: все градиенты получаются за время порядка одного
вычисления функции, тогда как численное дифференцирование потребовало бы двух прямых проходов на каждый
из 136 714 параметров. Это свойство и делает обучение больших сетей возможным.

**Память.** Параметры этой сети занимают 1.0 МБ, а сохранённые для обратного прохода `Z1`, `H` и `Z2` —
32.3 МБ. При обучении память определяется активациями (размер батча × ширина × глубина), а не весами.
Поэтому при нехватке памяти первым делом уменьшают батч, а предсказания считают под `torch.no_grad()`.

## Типичные ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Потери равны `nan` или `inf` с первых шагов | softmax «по формуле» переполняется или даёт `log(0)` | `log_softmax` с вынесением максимума; в PyTorch передавать в `cross_entropy` логиты |
| Сеть учится, но заметно хуже ожидаемого | ошибка в одном из градиентов | численная проверка по каждому параметру |
| Численная проверка даёт ошибку 10⁻³–10⁻² на верном коде | проверка во float32 или слишком малый $\varepsilon$ | float64, $\varepsilon$ = 10⁻⁵–10⁻⁶ |
| Численная проверка не сходится только для слоя с ReLU | излом в нуле: нулевые смещения, «погасшие» объекты | случайные ненулевые смещения перед проверкой |
| В PyTorch потери скачут и растут, шаг «как будто» всё больше | не вызван `optimizer.zero_grad()`: градиенты копятся | `zero_grad()` перед каждым `backward()` |
| `RuntimeError: mat1 and mat2 must have the same dtype` | данные из NumPy — float64, модель — float32 | `torch.tensor(X, dtype=torch.float32)` или `X.astype(np.float32)` |
