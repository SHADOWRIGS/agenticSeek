> **Модуль 5:** Deep Learning & Modern Architectures · **Тема 5.1:** Нейронные сети основы
> **Тип:** практика · **Время:** 6–8 часов

## Задача

Написать на чистом NumPy маленькую библиотеку для обучения нейронных сетей: слои с прямым и обратным
проходом, функцию потерь, два оптимизатора и цикл обучения — так, чтобы градиенты сходились с численными
до седьмого знака, а сеть за секунду обучалась распознавать рукописные цифры с точностью выше 95 %.

Зачем писать то, что есть в PyTorch:

- **понимание.** `loss.backward()` и `optimizer.step()` перестанут быть заклинаниями: вы будете знать, какие
  массивы каких форм за ними стоят, и сможете отлаживать сеть, а не перезапускать её с другим seed;
- **собеседования.** «Напишите обратный проход для линейного слоя» и «реализуйте Adam» — стандартные задачи;
- **инженерный навык.** Здесь вы отработаете главный приём разработки численного кода: каждая формула
  сначала проверяется численным градиентом на крошечном примере, и только потом идёт в обучение.

## Соглашения

Они же записаны в docstring модуля; тесты на них опираются.

- Батч — массив формы `(n, d)`, строка — объект; все вычисления во float64.
- Слой — объект с методами `forward(x)` и `backward(grad_out)` и атрибутами `params` и `grads` (списки
  массивов; у слоя без параметров — пустые).
- `forward` запоминает то, что понадобится обратному проходу, и не изменяет вход.
- `backward` получает градиент потерь по выходу слоя, **перезаписывает** градиенты по параметрам
  и возвращает градиент потерь по входу.
- Оптимизатор получает список массивов-параметров и обновляет их **на месте**.

## Что нужно реализовать

### Шаг 1. `numerical_gradient`

Центральные разности из урока 5.1.1. Это ваш главный инструмент на всю практику: тесты слоёв и сети
сверяют `backward` именно с вашей функцией, поэтому начните с неё.

```bash
uv run pytest -q -k TestNumericalGradient
```

### Шаг 2. `softmax_cross_entropy`

Возвращает средние по батчу потери и градиент по логитам — $(P - Y)/n$. Требования: устойчивость
на логитах ±1000 (приём log-sum-exp), вход не изменяется, никаких циклов по объектам. Выбрать вероятности
правильных классов без цикла позволяет индексация парой массивов: `log_probs[np.arange(n), y]`.

```bash
uv run pytest -q -k TestSoftmaxCrossEntropy
```

### Шаг 3. `Linear`

$out = xW + b$ с инициализацией Хе (урок 5.1.2). Формулы обратного прохода — из урока 5.1.1:
$dW = x^\top g$, $db = \sum_i g_i$, градиент по входу — $gW^\top$. Проверьте себя до запуска тестов:

```python
layer = Linear(6, 4, np.random.default_rng(0))
x = np.random.default_rng(1).normal(size=(5, 6))
r = np.random.default_rng(2).normal(size=(5, 4))  # случайные веса превращают выход слоя в число


def f():
    return float((layer.forward(x) * r).sum())


layer.forward(x)
grad_x = layer.backward(r)
np.abs(grad_x - numerical_gradient(f, x)).max()  # должно быть порядка 1e-9
```

```bash
uv run pytest -q -k TestLinear
```

### Шаг 4. `ReLU` и `Tanh`

Слои без параметров. Ловушка: `np.maximum(x, 0, out=x)` и подобные операции «на месте» портят вход,
который ещё нужен предыдущему слою для обратного прохода.

```bash
uv run pytest -q -k TestActivations
```

### Шаг 5. `Sequential`

Прямой проход — по слоям по порядку, обратный — в обратном порядке. `parameters()` и `gradients()`
возвращают списки **тех же** массивов, что лежат в слоях: оптимизатор должен менять веса самой модели,
а не их копии.

```bash
uv run pytest -q -k TestSequential
```

Тесты проверяют градиенты всей сети по каждому параметру и по входу. Если падает сеть с ReLU, но не с tanh,
вспомните про изломы из урока 5.1.1; тест задаёт ненулевые смещения именно из-за них.

### Шаг 6. `SGD` и `Adam`

Формулы — в docstring, они совпадают с `torch.optim` (урок 5.1.3). Ожидаемые значения в тестах посчитаны
на эталонном решении и сверены с `torch.optim.SGD` и `torch.optim.Adam`. Две типичные ошибки:

- `p = p - lr * g` создаёт новый массив, а модель продолжает держать старый — нужно `p -= lr * g`;
- состояние (скорость, моменты) должно быть своим у каждого параметра.

```bash
uv run pytest -q -k TestOptimizers
```

### Шаг 7. `train`

Мини-батчи, перемешивание генератором `np.random.default_rng(seed)` в каждой эпохе, история средних
потерь по эпохам. Тесты проверяют воспроизводимость, число шагов, то, что каждая эпоха обходит все объекты
ровно по одному разу в новом порядке, и то, что история — именно среднее по объектам.

```bash
uv run pytest -q -k TestTrain
```

### Шаг 8. Цифры и скорость

```bash
uv run pytest -q -k TestDigits
uv run pytest -q -k TestEngineering
uv run pytest -q
```

Сеть 64–64–10 должна за 30 эпох дать на тесте `load_digits` не меньше 0.95 и запомнить 64 объекта
до нулевой ошибки. Последнее — стандартная проверка любой новой сети: модель, не способная переобучиться
на одном батче, содержит ошибку.

## Почему решение с циклами не пройдёт

Тест `test_speed` делает прямой и обратный проход по 200 000 объектов и сравнивает время с самым дешёвым
из возможных циклов по объектам — одним умножением вектора на матрицу для каждого объекта. Проход должен
занять меньше 0.7 от времени такого цикла.

| Реализация | Отношение ко времени цикла | Полный прогон тестов |
|---|---|---|
| эталон: без циклов по объектам | 0.27 | 2.3 с |
| цикл по объектам только в `ReLU.forward` | 1.8 | 4.2 с |
| цикл по объектам только в `Linear.backward` | 4.1 | 7.7 с |
| цикл по объектам только в `softmax_cross_entropy` | 5.5 | 7.1 с |

Одного цикла в любом месте достаточно, чтобы тест не прошёл. Порог относительный, поэтому от скорости
вашего компьютера он не зависит. Все нужные приёмы — матричное умножение вместо суммы внешних
произведений, булевы маски, индексация массивами — разбирались в уроке 2.2.1.

## Идеи для усложнения

1. **Dropout.** Слой с режимами обучения и предсказания: при обучении обнуляет случайную долю `p` входов
   и делит остальные на `1 - p`, при предсказании ничего не делает. Добавьте в `Sequential` методы
   `train()` и `eval()`. Для численной проверки зафиксируйте маску.
2. **BatchNorm.** Слой из урока 5.1.2 с обучаемыми масштабом и сдвигом и скользящими статистиками. Обратный
   проход здесь заметно сложнее, чем у `Linear`: среднее и дисперсия батча зависят от всех объектов.
   Выведите его и проверьте численно; сверьте с `torch.nn.BatchNorm1d`.
3. **Свой autograd вместо ручных `backward`.** Перепишите слои на `Tensor` из `minigrad.py`: в слоях
   останется только `forward`. Сравните скорость с ручной версией и объясните разницу.
4. **Регуляризация и новые оптимизаторы.** Добавьте затухание весов в `SGD`, реализуйте AdamW и Lion,
   косинусное расписание с разогревом (урок 5.1.3). Числа для тестов получите из `torch.optim`.
5. **Свёртка.** Слой `Conv2d` для входа формы `(n, c, h, w)`: сначала с циклами по позициям окна, затем
   без них (приём im2col — развернуть все окна в строки матрицы и свести свёртку к матричному умножению).
   Цифры 8×8 подойдут для проверки: сеть со свёрткой должна обойти полносвязную.
6. **Данные побольше.** Обучите свою сеть на MNIST (60 000 изображений 28×28). На таком объёме станет
   важным всё, что на цифрах 8×8 не имело значения: float32 вместо float64, размер батча, расписание шага.
7. **Сохранение модели.** Методы `save` и `load` через `np.savez`; тест — предсказания до сохранения
   и после загрузки совпадают побитно.
