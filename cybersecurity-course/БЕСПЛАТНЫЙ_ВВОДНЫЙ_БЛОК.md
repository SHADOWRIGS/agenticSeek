## 1. Что такое кибербезопасность?

### Простыми словами

**Кибербезопасность** — это защита компьютеров, сетей и данных от несанкционированного доступа, кражи и повреждения.

Представьте дом:
- **Дверной замок** — это пароль
- **Сигнализация** — это система обнаружения вторжений (IDS)
- **Видеокамера** — это логирование и мониторинг (SIEM)
- **Охранник** — это SOC-аналитик (вы!)
- **Полиция** — это команда реагирования на инциденты (IR)

### Три кита безопасности (триада CIA)

```
        Конфиденциальность (Confidentiality)
              ╱              ╲
             ╱                ╲
            ╱                  ╲
    Целостность ──────────── Доступность
    (Integrity)              (Availability)
```

| Принцип | Что значит | Пример нарушения |
|---------|-----------|------------------|
| **Конфиденциальность** | Только авторизованные видят данные | Утечка базы паролей |
| **Целостность** | Данные не изменены без разрешения | Подмена суммы в переводе |
| **Доступность** | Система работает когда нужна | DDoS-атака на сайт банка |

### Кто нападает и зачем?

| Атакующий | Мотивация | Пример |
|-----------|-----------|--------|
| **Хактивисты** | Политические/идеологические цели | Дефейс сайтов |
| **Киберпреступники** | Деньги | Ransomware, фишинг, кражи |
| **APT-группировки** | Шпионаж, геополитика | Целевые атаки на госструктуры |
| **Инсайдеры** | Обида, корысть | Слив данных бывшим сотрудником |
| **Script kiddies** | Развлечение, самоутверждение | Сканирование, DDoS по инструкции |

### Масштаб проблемы (2024–2026)

- **Ущерб от киберпреступлений** в мире: $10.5 трлн в год (прогноз 2025)
- **Средняя стоимость утечки данных**: $4.88 млн (IBM, 2024)
- **Среднее время обнаружения** атаки: 204 дня (IBM, 2024)
- **Дефицит специалистов** по ИБ в мире: 4 млн человек
- В России: спрос на ИБ-специалистов растёт на 30–40% ежегодно

## 2. Почему защита важнее атаки

### «Все хотят стать хакерами — а кто будет защищать?»

Киноиндустрия и медиа создали образ: кибербезопасность = взлом. На самом деле:

| Факт | Атака (Red Team) | Защита (Blue Team) |
|------|-------------------|-------------------|
| **Доля вакансий** | ~15% | **~70%** |
| **Порог входа** | Высокий (нужен опыт) | Ниже (есть плейбуки) |
| **Зарплата junior** | 80–120 тыс. ₽ | **80–150 тыс. ₽** |
| **Зарплата senior** | 200–350 тыс. ₽ | **200–400 тыс. ₽** |
| **Спрос на рынке** | Средний | **Критический дефицит** |
| **Карьерный рост** | Линейный | В CISO, GRC, архитектуру |

### Аналогия

Представьте футбол:
- **Нападающие** — красивые голы, их знают все (пентестеры)
- **Защитники и вратарь** — без них команда проигрывает 0:10 (blue team)
- В каждой команде 10 защитников на 1–2 нападающих

**В кибербезопасности так же:** на каждого пентестера нужно 10–20 защитников.

### Что делают защитники (Blue Team)

```
Типичные роли Blue Team:

SOC-аналитик L1 (Tier 1) — Мониторинг
├── Смотрит алерты в SIEM
├── Первичная классификация: ложная тревога или нет?
├── Эскалирует подтверждённые инциденты на L2
└── Зарплата: 80–150 тыс. ₽

SOC-аналитик L2 (Tier 2) — Расследование
├── Глубокий анализ инцидента
├── Определяет масштаб: что затронуто?
├── Собирает доказательства (forensics)
└── Зарплата: 150–250 тыс. ₽

SOC-аналитик L3 (Tier 3) — Threat Hunting
├── Проактивный поиск угроз (без алертов)
├── Пишет правила детекции (Sigma, Suricata)
├── Разрабатывает плейбуки
└── Зарплата: 200–350 тыс. ₽

Инженер безопасности
├── Настраивает и поддерживает СЗИ (SIEM, IDS, WAF, EDR)
├── Hardening (усиление защиты)
├── Управление уязвимостями
└── Зарплата: 150–300 тыс. ₽

Incident Responder
├── Реагирование на инциденты
├── Форензика и анализ вредоносного ПО
├── Восстановление после атаки
└── Зарплата: 200–400 тыс. ₽
```

## 3. ТОП-5 самых частых атак и защита от них

### Атака 1: Фишинг (Phishing)

**Что это:** Мошенническое письмо/сообщение, притворяющееся легитимным (банк, коллега, сервис), чтобы украсть логин/пароль или заставить открыть вредоносный файл.

**Пример:**
```
От: security@bank-r0ssia.com   ← обратите внимание: «0» вместо «о»
Тема: Срочно: ваш аккаунт заблокирован!

Уважаемый клиент,
Мы обнаружили подозрительную активность. Подтвердите данные:
[Войти в аккаунт]  ← ссылка ведёт на фейковый сайт
```

**Как защитить (Blue Team):**

| Слой | Мера |
|------|------|
| **Превенция** | SPF + DKIM + DMARC на почтовом домене |
| **Превенция** | Обучение сотрудников (security awareness) |
| **Превенция** | Отключить макросы в Office |
| **Детекция** | Email gateway: проверка URL и вложений |
| **Детекция** | SIEM: алерт на Office → cmd.exe / powershell.exe |
| **Реагирование** | Заблокировать домен отправителя |
| **Реагирование** | Проверить, кто ещё получил письмо |

**Простой скрипт: проверка SPF/DKIM/DMARC:**

```bash
#!/bin/bash
# check_email_security.sh <domain>
# Проверяет, настроены ли SPF, DKIM и DMARC для домена

DOMAIN="${1:?Использование: $0 example.com}"

echo "=== Проверка email-безопасности для $DOMAIN ==="

echo -e "\n[SPF]"
SPF=$(dig +short TXT "$DOMAIN" | grep "v=spf1")
if [ -n "$SPF" ]; then
    echo "  ✅ SPF настроен: $SPF"
else
    echo "  ❌ SPF НЕ настроен! Фишинг от имени $DOMAIN возможен."
fi

echo -e "\n[DMARC]"
DMARC=$(dig +short TXT "_dmarc.$DOMAIN")
if [ -n "$DMARC" ]; then
    echo "  ✅ DMARC настроен: $DMARC"
    if echo "$DMARC" | grep -q "p=reject"; then
        echo "  ✅ Политика: reject (максимальная защита)"
    elif echo "$DMARC" | grep -q "p=quarantine"; then
        echo "  ⚠️  Политика: quarantine (средняя защита)"
    else
        echo "  ❌ Политика: none (мониторинг, без защиты)"
    fi
else
    echo "  ❌ DMARC НЕ настроен!"
fi

echo -e "\n[DKIM]"
# Проверяем стандартные селекторы
for SELECTOR in default google s1 s2 selector1 selector2; do
    DKIM=$(dig +short TXT "${SELECTOR}._domainkey.$DOMAIN")
    if [ -n "$DKIM" ]; then
        echo "  ✅ DKIM найден (selector: $SELECTOR)"
        break
    fi
done
[ -z "$DKIM" ] && echo "  ⚠️  DKIM не найден (стандартные селекторы)"

echo -e "\nГотово."
```

### Атака 2: Подбор пароля (Brute Force)

**Что это:** Автоматический перебор паролей к учётной записи — от простых списков (dictionary attack) до полного перебора.

**Как защитить:**

| Мера | Как реализовать |
|------|----------------|
| **Сильные пароли** | Политика: минимум 12 символов, буквы + цифры + спецсимволы |
| **MFA** | Второй фактор (SMS, TOTP, ключ) — даже украденный пароль бесполезен |
| **Блокировка** | Блокировать аккаунт после 5 неудачных попыток на 30 минут |
| **fail2ban** | Блокировать IP после 5 неудачных попыток |
| **SIEM-алерт** | Правило: 10+ Event 4625 за 5 минут с одного IP |

**Мини-практика: настройка fail2ban:**

```bash
# Установка
sudo apt install fail2ban -y

# Конфигурация
sudo tee /etc/fail2ban/jail.local << 'EOF'
[DEFAULT]
bantime = 3600      # Блокировка на 1 час
findtime = 300      # Окно наблюдения: 5 минут
maxretry = 5        # Порог: 5 неудачных попыток

[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/auth.log
EOF

# Запуск
sudo systemctl enable --now fail2ban

# Проверка
sudo fail2ban-client status sshd
```

### Атака 3: Ransomware (Шифровальщик)

**Что это:** Малварь, которая шифрует файлы и требует выкуп за ключ расшифровки.

**Цепочка атаки:**
```
Фишинг / RDP → Доступ → Разведка → Lateral Movement → 
  → Удаление бэкапов → Шифрование → Записка с требованием выкупа
```

**Как защитить:**

| Мера | Приоритет |
|------|-----------|
| **Бэкапы (3-2-1)** | 3 копии, 2 типа носителей, 1 offsite. КРИТИЧЕСКИ ВАЖНО |
| **Immutable backup** | Бэкапы, которые нельзя удалить/изменить |
| **Сегментация сети** | Чтобы малварь не распространилась |
| **Отключить RDP** | Или: MFA + VPN + ограничение по IP |
| **Обновления** | Патчить уязвимости (особенно RDP, SMB, VPN) |
| **EDR/антивирус** | С актуальными сигнатурами |
| **Canary-файлы** | Файлы-приманки: при изменении → алерт |

### Атака 4: DDoS

**Что это:** Distributed Denial of Service — множество компьютеров одновременно отправляют запросы на сервер, перегружая его.

**Как защитить:**

```bash
# Базовая защита на уровне iptables
# Ограничить SYN-пакеты (защита от SYN Flood)
iptables -A INPUT -p tcp --syn -m limit --limit 50/s --limit-burst 100 -j ACCEPT
iptables -A INPUT -p tcp --syn -j DROP

# Ограничить подключения от одного IP
iptables -A INPUT -p tcp -m connlimit --connlimit-above 50 -j DROP

# Включить SYN cookies
sysctl -w net.ipv4.tcp_syncookies=1
```

Для серьёзной защиты: Cloudflare, Akamai или отечественные CDN (Qrator, DDoS-Guard).

### Атака 5: Утечка данных (Data Breach)

**Что это:** Несанкционированный доступ к конфиденциальным данным — через взлом, инсайдера или ошибку конфигурации.

**Как защитить:**

| Мера | Описание |
|------|----------|
| **Классификация данных** | Знать, какие данные конфиденциальны и где хранятся |
| **Шифрование** | At rest + in transit |
| **DLP** | Контроль исходящих каналов (email, USB, облака) |
| **Принцип минимальных привилегий** | Доступ только к тому, что нужно для работы |
| **Аудит доступа** | Логировать, кто к чему обращается |
| **MFA** | Для всех учётных записей с доступом к данным |

## 5. Практика: установка Wazuh за 30 минут

### Что такое Wazuh?

**Wazuh** — бесплатная (open source) SIEM + XDR платформа. Собирает логи, обнаруживает угрозы, мониторит целостность файлов, проверяет соответствие стандартам.

Это тот же класс инструментов, что MaxPatrol SIEM или Splunk, но **бесплатный** и идеальный для обучения.

### Установка (Ubuntu/Debian)

```bash
#!/bin/bash
# install_wazuh.sh — установка Wazuh All-in-One (сервер + дашборд)
# Время: ~15-20 минут
# Требования: Ubuntu 22.04 LTS, 4 CPU, 8 GB RAM, 50 GB disk

echo "=== Установка Wazuh SIEM (All-in-One) ==="
echo "Это установит: Wazuh Manager + Wazuh Indexer + Wazuh Dashboard"

# 1. Скачать установщик
curl -sO https://packages.wazuh.com/4.9/wazuh-install.sh

# 2. Запустить установку (всё в одном)
sudo bash ./wazuh-install.sh -a

# 3. После установки:
# - Dashboard доступен по: https://<IP>:443
# - Логин: admin
# - Пароль: выведен в конце установки (сохраните!)

echo ""
echo "=== Установка завершена ==="
echo "Dashboard: https://$(hostname -I | awk '{print $1}')"
echo "Логин: admin"
echo "Пароль: см. вывод выше"
```

### Подключение первого агента (Linux)

```bash
# На машине, которую хотим мониторить:

# 1. Добавить репозиторий
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | gpg --dearmor | \
  sudo tee /usr/share/keyrings/wazuh.gpg > /dev/null

echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | \
  sudo tee /etc/apt/sources.list.d/wazuh.list

# 2. Установить агент
sudo apt update
sudo WAZUH_MANAGER="<IP_вашего_Wazuh_сервера>" apt install wazuh-agent -y

# 3. Запустить
sudo systemctl daemon-reload
sudo systemctl enable --now wazuh-agent

# 4. Проверить
sudo systemctl status wazuh-agent
# Должен быть: active (running)
```

### Подключение Windows-агента

```powershell
# На Windows-машине (от Администратора):

# 1. Скачать MSI-пакет
Invoke-WebRequest -Uri "https://packages.wazuh.com/4.x/windows/wazuh-agent-4.9.0-1.msi" -OutFile "wazuh-agent.msi"

# 2. Установить с указанием сервера
msiexec.exe /i wazuh-agent.msi /q WAZUH_MANAGER="<IP_вашего_Wazuh_сервера>"

# 3. Запустить службу
net start WazuhSvc

# 4. Проверить
sc query WazuhSvc
# Должен быть: STATE = RUNNING
```

### Что вы увидите в Wazuh Dashboard

После подключения агентов, зайдите в Dashboard (https://<IP>:443):

```
Главная страница:
├── Security Events — все события безопасности
├── Integrity Monitoring — изменения файлов
├── Vulnerability Detection — найденные уязвимости
├── MITRE ATT&CK — маппинг событий на MITRE
├── Regulatory Compliance — соответствие PCI DSS, GDPR, HIPAA
└── Security Configuration Assessment — проверка конфигурации

Попробуйте:
1. Откройте "Security Events" → увидите логи от агентов
2. Откройте "MITRE ATT&CK" → увидите тактики и техники
3. Попробуйте неудачный вход (ssh с неправильным паролем) →
   увидите алерт в реальном времени!
```

### Первый тест: обнаружение brute force

```bash
# На любой машине (не на Wazuh-сервере):
# Попробуйте 6 неудачных SSH-входов:
for i in $(seq 1 6); do
    sshpass -p "wrongpassword" ssh testuser@<IP_агента> 2>/dev/null
done

# Через 30 секунд в Wazuh Dashboard:
# Modules → Security Events → фильтр по "authentication_failed"
# Вы увидите алерт: "sshd: authentication failure"
# Wazuh правило 5710 → 5712 (multiple failures)
```

## 6. Практика: ваше первое Sigma-правило

### Что такое Sigma?

**Sigma** — универсальный формат правил детекции (как Snort/Suricata для сети, но для логов). Пишете правило один раз → конвертируете в формат вашего SIEM (Splunk SPL, Elastic KQL, MaxPatrol PDQL, Wazuh и т.д.).

### Структура Sigma-правила

```yaml
title: Название правила (что обнаруживаем)
id: уникальный UUID
status: stable / test / experimental
description: Подробное описание
author: Вы
```

### Ваше первое правило: обнаружение подозрительного PowerShell

```yaml
# Сохраните как: my_first_sigma_rule.yml

title: Мой первый Sigma-правило — подозрительный PowerShell
id: 12345678-abcd-ef01-2345-6789abcdef01
status: test
description: >
  Обнаруживает запуск PowerShell с подозрительными параметрами:
  скрытое окно, обход политики выполнения, закодированная команда.
author: Студент курса Кибер-Щит
date: 2026/11/11

logsource:
  product: windows
  category: process_creation

detection:
  selection_process:
    Image|endswith:
      - '\powershell.exe'
      - '\pwsh.exe'
  selection_suspicious:
    CommandLine|contains:
      - '-WindowStyle Hidden'
      - '-w hidden'
      - '-enc'
      - '-EncodedCommand'
      - '-ExecutionPolicy Bypass'
      - '-exec bypass'
  condition: selection_process and selection_suspicious

falsepositives:
  - Легитимные скрипты автоматизации (проверить по имени скрипта)
  - SCCM/MECM деплойменты

level: high

tags:
  - attack.execution
  - attack.t1059.001
```
