## Модуль 61: Обход AMSI — Обнаружение и защита

### Что это за угроза

AMSI (Antimalware Scan Interface) — интерфейс Windows, через который скриптовые движки (PowerShell, VBScript, JScript, .NET) передают содержимое для антивирусной проверки. Злоумышленники модифицируют функцию `AmsiScanBuffer` в памяти процесса, чтобы вернуть «чисто» для любого кода. Это позволяет запускать вредоносные PowerShell-скрипты без детекции антивирусом.

### Индикаторы компрометации (IoC)

- Вызов `VirtualProtect` на адрес `amsi.dll!AmsiScanBuffer` с правами `PAGE_EXECUTE_READWRITE`
- Обращение к `[Ref].Assembly.GetType('System.Management.Automation.AmsiUtils')` в PowerShell
- Загрузка `amsi.dll` с последующей модификацией памяти через `WriteProcessMemory`
- Первые байты `AmsiScanBuffer` заменены на `mov eax, 0x80070057; ret` (возврат E_INVALIDARG)
- PowerShell-логи с обрезанным или отсутствующим ScriptBlock Logging после определённого момента

```powershell
# Проверка целостности AmsiScanBuffer в памяти
# Запускать как SYSTEM или с правами администратора

function Test-AmsiIntegrity {
    [CmdletBinding()]
    param()

    $amsi = [System.Runtime.InteropServices.RuntimeEnvironment]::GetRuntimeDirectory()
    $result = @{
        Timestamp = Get-Date -Format 'yyyy-MM-dd HH:mm:ss'
        Status    = 'OK'
        Details   = ''
    }

    try {
        # Проверяем, работает ли AMSI-сканирование
        $testScript = 'Invoke-Expression "Write-Host test"'
        $amsiContext = $null

        # Попытка вызвать AMSI через .NET — если патч, вернёт S_OK для малвари
        Add-Type -TypeDefinition @"
using System;
using System.Runtime.InteropServices;
public class AmsiCheck {
    [DllImport("amsi.dll")]
    public static extern int AmsiInitialize(string appName, out IntPtr context);
    [DllImport("amsi.dll")]
    public static extern int AmsiScanString(
        IntPtr context, string content, string name,
        IntPtr session, out int result);
}
"@
        $ctx = [IntPtr]::Zero
        $initResult = [AmsiCheck]::AmsiInitialize("TestApp", [ref]$ctx)

        if ($initResult -ne 0) {
            $result.Status = 'ALERT'
            $result.Details = "AmsiInitialize вернул ошибку: $initResult"
            return $result
        }

        # Тестовая строка EICAR
        $eicar = 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*'
        $scanResult = 0
        $scanRet = [AmsiCheck]::AmsiScanString(
            $ctx, $eicar, "test", [IntPtr]::Zero, [ref]$scanResult)

        if ($scanResult -lt 32768) {
            $result.Status = 'CRITICAL'
            $result.Details = "AMSI НЕ ОБНАРУЖИЛ EICAR! Возможен патчинг. ScanResult=$scanResult"
        }
        else {
            $result.Details = "AMSI работает корректно. EICAR обнаружен. ScanResult=$scanResult"
        }
    }
    catch {
        $result.Status = 'ERROR'
        $result.Details = "Ошибка проверки: $_"
    }

    return $result
}

# Запуск проверки
$check = Test-AmsiIntegrity
Write-Host "[$($check.Timestamp)] AMSI Status: $($check.Status)"
Write-Host "Детали: $($check.Details)"

if ($check.Status -eq 'CRITICAL') {
    # Отправка алерта в SIEM
    Write-EventLog -LogName 'Application' -Source 'AmsiMonitor' `
        -EventId 9001 -EntryType Error `
        -Message "AMSI BYPASS DETECTED: $($check.Details)"
}
```

### Защита и предотвращение

1. **Включить Script Block Logging (обязательно)**
   ```
   Computer Configuration → Administrative Templates → Windows Components →
   Windows PowerShell → Turn on PowerShell Script Block Logging → Enabled
   ```

2. **Включить Constrained Language Mode** для PowerShell:
   ```powershell
   # Через AppLocker или WDAC — принудительный CLM
   # Не позволяет вызывать .NET API напрямую
   $ExecutionContext.SessionState.LanguageMode = 'ConstrainedLanguage'
   ```

3. **Мониторинг Windows Defender:**
   - Event ID 1116 — обнаружение вредоносного ПО
   - Event ID 1117 — действие по защите
   - Event ID 5007 — изменение настроек (возможно отключение)

4. **Защита памяти процессов** — включить Exploit Protection:
   - Arbitrary Code Guard (ACG) для powershell.exe
   - Code Integrity Guard (CIG)

5. **WDAC (Windows Defender Application Control)** — контроль запуска скриптов по хешам и издателям.

|-----------|------------|
| **Sysmon** (Event ID 7, 10) | Загрузка модулей, доступ к процессам |

## Модуль 62: Патчинг ETW — Обнаружение и защита

### Что это за угроза

ETW (Event Tracing for Windows) — основной механизм телеметрии Windows. EDR-решения, Sysmon и Windows Defender полагаются на ETW-провайдеры для получения событий. Злоумышленники патчат функцию `EtwEventWrite` (в `ntdll.dll`) в памяти текущего процесса, чтобы подавить генерацию событий. Это «ослепляет» мониторинг на уровне процесса.

### Индикаторы компрометации (IoC)

- Модификация байтов `ntdll.dll!EtwEventWrite` в памяти процесса
- Вызов `VirtualProtect` на регионы ntdll.dll
- Использование `NtProtectVirtualMemory` с правами RWX на ntdll
- Отсутствие ожидаемых ETW-событий от процесса при активной работе
- Обращение к `System.Reflection.Assembly` для доступа к внутренним .NET-классам ETW

### Обнаружение

**Обнаружение «тишины» ETW — аномалия отсутствия событий:**

```python
#!/usr/bin/env python3
"""
Детектор аномального молчания ETW-провайдеров.
Сравнивает ожидаемый поток событий с реальным.
"""

import subprocess
import json
import time
from datetime import datetime, timedelta
from collections import defaultdict

class ETWSilenceDetector:
    def __init__(self):
        self.baseline = {}  # pid -> ожидаемое число событий/мин
        self.current = defaultdict(int)

    def get_etw_sessions(self):
        """Получить список активных ETW-сессий"""
        result = subprocess.run(
            ['logman', 'query', '-ets'],
            capture_output=True, text=True
        )
        sessions = []
        for line in result.stdout.splitlines():
            line = line.strip()
            if line and not line.startswith('-') and not line.startswith('Data'):
                parts = line.split()
                if parts and parts[0] not in ('Name', 'The'):
                    sessions.append(parts[0])
        return sessions

    def check_provider_health(self):
        """Проверить, что критичные ETW-провайдеры активны"""
        critical_providers = [
            'Microsoft-Windows-Sysmon',
            'Microsoft-Windows-PowerShell',
            'Microsoft-Windows-Security-Auditing',
            'Microsoft-Antimalware-Scan-Interface',
            'Microsoft-Windows-Kernel-Process',
        ]

        result = subprocess.run(
            ['logman', 'query', 'providers'],
            capture_output=True, text=True
        )

        active_providers = set()
        for line in result.stdout.splitlines():
            for provider in critical_providers:
                if provider.lower() in line.lower():
                    active_providers.add(provider)

        missing = set(critical_providers) - active_providers
        if missing:
            print(f"[ALERT] Отсутствуют критичные ETW-провайдеры: {missing}")
            return False
        return True

    def detect_event_gap(self, log_name, minutes=5, min_expected=10):
        """Обнаружить аномальное отсутствие событий в журнале"""
        time_threshold = datetime.now() - timedelta(minutes=minutes)
        time_str = time_threshold.strftime('%Y-%m-%dT%H:%M:%S')

        cmd = (
            f'wevtutil qe {log_name} /c:100 /rd:true '
            f'/q:"*[System[TimeCreated[@SystemTime>=\'{time_str}\']]]" /f:text'
        )

        result = subprocess.run(cmd, capture_output=True, text=True, shell=True)
        event_count = result.stdout.count('Event[')

        if event_count < min_expected:
            print(f"[ALERT] {log_name}: получено {event_count} событий "
                  f"за {minutes} мин (ожидалось >= {min_expected}). "
                  f"Возможен патчинг ETW!")
            return True
        else:
            print(f"[OK] {log_name}: {event_count} событий за {minutes} мин")
            return False

if __name__ == '__main__':
    detector = ETWSilenceDetector()
    print("=== Проверка здоровья ETW ===")
    print(f"Время: {datetime.now()}")

    detector.check_provider_health()

    logs_to_check = [
        ('Security', 20),
        ('Microsoft-Windows-Sysmon/Operational', 5),
        ('Microsoft-Windows-PowerShell/Operational', 2),
    ]

    alerts = []
    for log_name, min_events in logs_to_check:
        if detector.detect_event_gap(log_name, minutes=5, min_expected=min_events):
            alerts.append(log_name)

    if alerts:
        print(f"\n[CRITICAL] Обнаружено подавление ETW в журналах: {alerts}")
```

### Защита и предотвращение

1. **Включить Protected Process Light (PPL)** для критичных сервисов — не позволяет непривилегированным процессам модифицировать память защищённых процессов.

2. **Мониторинг целостности ntdll.dll** в памяти:
   - Инструмент **pe-sieve** для сканирования патченных DLL
   - Периодическое сравнение загруженной ntdll с копией на диске

3. **Kernel-level ETW** — использовать провайдеры уровня ядра, которые сложнее патчить из usermode:
   - `Microsoft-Windows-Kernel-Process`
   - `Microsoft-Windows-Kernel-File`

4. **EDR с защитой от отключения** — решения с kernel-mode сенсорами (CrowdStrike Falcon, Microsoft Defender for Endpoint).

5. **Аудит доступа к ntdll.dll** через Sysmon Event ID 10 (ProcessAccess) для отслеживания попыток чтения/записи в системные DLL.

### Инструменты защитника

| Инструмент | Назначение |
|-----------|------------|
| **pe-sieve** / **HollowsHunter** | Обнаружение патченных DLL в памяти |
| **SilkETW** | ETW-мониторинг с детекцией аномалий |
| **Sysmon** (Event ID 10) | Отслеживание ProcessAccess к ntdll |
| **logman** | Проверка активных ETW-сессий |
| **Velociraptor** | Массовая проверка целостности ETW на хостах |

## Модуль 63: Уклонение от Sysmon — Обнаружение и защита

### Что это за угроза

Sysmon (System Monitor) — мощный инструмент от Microsoft Sysinternals для расширенного аудита Windows. Злоумышленники могут: выгрузить драйвер Sysmon, изменить конфигурацию (убрать правила мониторинга), заблокировать запись в лог, или использовать техники, не покрываемые текущими правилами. «Ослепление» Sysmon лишает SOC ключевой телеметрии.

### Индикаторы компрометации (IoC)

- Выгрузка драйвера через `fltMC.exe unload SysmonDrv`
- Остановка сервиса: `sc stop Sysmon64` или `net stop Sysmon64`
- Изменение конфигурации: `sysmon -c <новый_конфиг>` (с пустыми правилами)
- Удаление Sysmon: `sysmon -u`
- Подмена бинарника Sysmon
- Отсутствие Sysmon-событий при наличии активности

### Обнаружение

**Скрипт мониторинга здоровья Sysmon:**

```powershell
# Monitor-SysmonHealth.ps1
# Проверяет состояние Sysmon и генерирует алерт при проблемах

function Test-SysmonHealth {
    $results = @{
        Timestamp = Get-Date -Format 'yyyy-MM-dd HH:mm:ss'
        ServiceRunning = $false
        DriverLoaded = $false
        ConfigHash = ''
        RecentEvents = 0
        Status = 'UNKNOWN'
    }

    # 1. Проверка сервиса
    $svc = Get-Service -Name 'Sysmon64' -ErrorAction SilentlyContinue
    if (-not $svc) {
        $svc = Get-Service -Name 'Sysmon' -ErrorAction SilentlyContinue
    }
    $results.ServiceRunning = ($svc -and $svc.Status -eq 'Running')

    # 2. Проверка драйвера
    $driver = fltMC.exe 2>$null | Select-String 'SysmonDrv'
    $results.DriverLoaded = ($null -ne $driver)

    # 3. Хеш конфигурации
    $configPath = "$env:ProgramData\Sysmon\config.xml"
    if (Test-Path $configPath) {
        $results.ConfigHash = (Get-FileHash $configPath -Algorithm SHA256).Hash
    }

    # 4. Количество событий за последние 5 минут
    $fiveMinAgo = (Get-Date).AddMinutes(-5)
    try {
        $events = Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' `
            -FilterXPath "*[System[TimeCreated[@SystemTime>='$($fiveMinAgo.ToUniversalTime().ToString("o"))']]]" `
            -MaxEvents 1000 -ErrorAction SilentlyContinue
        $results.RecentEvents = if ($events) { $events.Count } else { 0 }
    }
    catch {
        $results.RecentEvents = -1  # Ошибка чтения журнала
    }

    # 5. Итоговый статус
    if (-not $results.ServiceRunning) {
        $results.Status = 'CRITICAL: Сервис Sysmon не запущен!'
    }
    elseif (-not $results.DriverLoaded) {
        $results.Status = 'CRITICAL: Драйвер SysmonDrv не загружен!'
    }
    elseif ($results.RecentEvents -eq 0) {
        $results.Status = 'WARNING: Нет событий за последние 5 минут'
    }
    elseif ($results.RecentEvents -lt 5) {
        $results.Status = 'WARNING: Подозрительно мало событий'
    }
    else {
        $results.Status = 'OK'
    }

    return $results
}

# Сохранённый эталонный хеш конфигурации
$expectedConfigHash = 'PLACEHOLDER_HASH_СЮДА_ВСТАВИТЬ_РЕАЛЬНЫЙ'

$health = Test-SysmonHealth

Write-Host "=== Sysmon Health Check ==="
Write-Host "Время: $($health.Timestamp)"
Write-Host "Сервис: $(if ($health.ServiceRunning) {'Running'} else {'STOPPED'})"
Write-Host "Драйвер: $(if ($health.DriverLoaded) {'Loaded'} else {'UNLOADED'})"
Write-Host "Конфиг хеш: $($health.ConfigHash)"
Write-Host "Событий за 5 мин: $($health.RecentEvents)"
Write-Host "Статус: $($health.Status)"

# Проверка изменения конфигурации
if ($health.ConfigHash -and $expectedConfigHash -ne 'PLACEHOLDER_HASH_СЮДА_ВСТАВИТЬ_РЕАЛЬНЫЙ') {
    if ($health.ConfigHash -ne $expectedConfigHash) {
        Write-Host "[ALERT] Конфигурация Sysmon ИЗМЕНЕНА!" -ForegroundColor Red
    }
}
```

### Защита и предотвращение

1. **Переименование бинарника Sysmon** при установке — усложняет обнаружение:
   ```cmd
   copy Sysmon64.exe C:\Windows\svcmonitor.exe
   svcmonitor.exe -i sysmonconfig.xml -d svcdrv
   ```

2. **Защита сервиса от остановки:**
   ```cmd
   sc sdset Sysmon64 D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCLCSWRPWPDTLOCRRC;;;BA)
   ```

3. **Мониторинг Event ID 255** (Sysmon error) — указывает на проблемы.

4. **Дублирование телеметрии** — не полагайтесь только на Sysmon:
   - Windows Event Forwarding (WEF)
   - EDR-агенты
   - Auditd на Linux

## Модуль 64: Манипуляция логами — Обнаружение и защита

### Что это за угроза

Злоумышленники очищают или модифицируют системные журналы, чтобы скрыть следы компрометации. Под удар попадают: Windows Event Log (`wevtutil cl`), Linux syslog/auth.log, журналы Apache/Nginx, логи приложений. Это критичная техника «заметания следов» (T1070.001, T1070.002).

- Вызов `wevtutil cl Security`

- Изменение конфигурации rsyslog/journald
- Команда `journalctl --vacuum-time=1s`

**Python-скрипт контроля размеров логов:**

```python
#!/usr/bin/env python3
"""
Детектор аномальных изменений размера лог-файлов.
Уменьшение размера лога — верный признак его очистки.
"""

import os
import json
import time
from pathlib import Path
from datetime import datetime

BASELINE_FILE = '/var/lib/log-monitor/baseline.json'
LOG_FILES = [
    '/var/log/auth.log',
    '/var/log/syslog',
    '/var/log/kern.log',
    '/var/log/messages',
    '/var/log/secure',
    '/var/log/apache2/access.log',
    '/var/log/nginx/access.log',
]

def get_log_sizes():
    sizes = {}
    for logfile in LOG_FILES:
        if os.path.exists(logfile):
            stat = os.stat(logfile)
            sizes[logfile] = {
                'size': stat.st_size,
                'mtime': stat.st_mtime,
                'inode': stat.st_ino,
            }
    return sizes

def load_baseline():
    if os.path.exists(BASELINE_FILE):
        with open(BASELINE_FILE) as f:
            return json.load(f)
    return {}

def save_baseline(data):
    os.makedirs(os.path.dirname(BASELINE_FILE), exist_ok=True)
    with open(BASELINE_FILE, 'w') as f:
        json.dump(data, f, indent=2)

def check_anomalies():
    baseline = load_baseline()
    current = get_log_sizes()
    alerts = []

    for logfile, info in current.items():
        if logfile in baseline:
            prev = baseline[logfile]

            # Лог УМЕНЬШИЛСЯ — подозрительно
            if info['size'] < prev['size'] * 0.5 and prev['size'] > 1024:
                alerts.append({
                    'file': logfile,
                    'alert': 'LOG_SHRUNK',
                    'prev_size': prev['size'],
                    'curr_size': info['size'],
                    'reduction': f"{(1 - info['size']/prev['size'])*100:.0f}%",
                })

            # Inode изменился — файл пересоздан
            if info['inode'] != prev['inode']:
                alerts.append({
                    'file': logfile,
                    'alert': 'INODE_CHANGED',
                    'detail': 'Файл был пересоздан (новый inode)',
                })

            # Файл стал пустым
            if info['size'] == 0 and prev['size'] > 0:
                alerts.append({
                    'file': logfile,
                    'alert': 'LOG_EMPTIED',
                    'prev_size': prev['size'],
                })

    save_baseline(current)
    return alerts

if __name__ == '__main__':
    ts = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
    alerts = check_anomalies()

    if alerts:
        print(f"[{ts}] ALERT: Обнаружена манипуляция логами!")
        for a in alerts:
            print(f"  - {a['file']}: {a['alert']}")
            if 'prev_size' in a:
                print(f"    Был: {a['prev_size']} байт → Стал: {a.get('curr_size', 0)} байт")
    else:
        print(f"[{ts}] OK: Аномалий не обнаружено")
```

## Модуль 65: Timestomping — Обнаружение и защита

### Что это за угроза

Timestomping — изменение временных меток файлов (Created, Modified, Accessed, Entry Modified), чтобы скрыть момент создания или модификации вредоносного файла. Злоумышленники изменяют `$STANDARD_INFORMATION` в NTFS MFT, но не всегда меняют `$FILE_NAME`. Разница между этими двумя атрибутами — ключевой индикатор.

### Индикаторы компрометации (IoC)

- Расхождение между `$STANDARD_INFORMATION` и `$FILE_NAME` timestamps в MFT
- Файл с датой создания раньше даты создания каталога, в котором он лежит
- Файл «2015 года» в каталоге «2024 года»
- Использование утилит: `timestomp`, `SetMACE`, `NirCmd`
- PowerShell-команды: `(Get-Item file).CreationTime = ...`
- Секунды и миллисекунды с нулевыми значениями (артефакт некоторых инструментов)

### Обнаружение

**Python-скрипт обнаружения timestomping через MFT-анализ:**

```python
#!/usr/bin/env python3
"""
Обнаружение timestomping через сравнение атрибутов MFT.
Требует: analyzeMFT или python-ntfs для парсинга $MFT.
Этот скрипт работает с CSV-выгрузкой из analyzeMFT.
"""

import csv
import sys
from datetime import datetime, timedelta

def parse_mft_csv(csv_path):
    """Анализ выгрузки MFT на признаки timestomping"""
    alerts = []

    with open(csv_path, 'r', encoding='utf-8', errors='replace') as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                filename = row.get('Filename', '')

                # $STANDARD_INFORMATION timestamps
                si_created = row.get('SI_CRTime', '')
                si_modified = row.get('SI_MTime', '')

                # $FILE_NAME timestamps
                fn_created = row.get('FN_CRTime', '')
                fn_modified = row.get('FN_MTime', '')

                if not all([si_created, fn_created]):
                    continue

                # Парсинг дат
                si_cr = datetime.strptime(si_created[:19], '%Y-%m-%d %H:%M:%S')
                fn_cr = datetime.strptime(fn_created[:19], '%Y-%m-%d %H:%M:%S')

                # ИНДИКАТОР 1: $SI создан РАНЬШЕ $FN
                # (Невозможно при нормальной работе — $FN всегда <= $SI)
                if si_cr < fn_cr - timedelta(seconds=2):
                    alerts.append({
                        'file': filename,
                        'type': 'SI_BEFORE_FN',
                        'si_created': si_created,
                        'fn_created': fn_created,
                        'severity': 'HIGH',
                    })

                # ИНДИКАТОР 2: Дата подозрительно далеко в прошлом
                if si_cr.year < 2010 and fn_cr.year > 2020:
                    alerts.append({
                        'file': filename,
                        'type': 'SUSPICIOUS_OLD_DATE',
                        'si_created': si_created,
                        'fn_created': fn_created,
                        'severity': 'MEDIUM',
                    })

                # ИНДИКАТОР 3: Нулевые наносекунды (артефакт инструментов)
                if '.000000' in si_created and '.000000' not in fn_created:
                    alerts.append({
                        'file': filename,
                        'type': 'ZERO_NANOSECONDS',
                        'detail': 'SI имеет нулевые наносекунды — признак timestomping',
                        'severity': 'MEDIUM',
                    })

            except (ValueError, KeyError):
                continue

    return alerts

if __name__ == '__main__':
    if len(sys.argv) < 2:
        print("Использование: python3 timestomp_detector.py <mft_export.csv>")
        sys.exit(1)

    results = parse_mft_csv(sys.argv[1])

    if results:
        print(f"Обнаружено {len(results)} подозрительных файлов:")
        for r in results:
            print(f"  [{r['severity']}] {r['file']}: {r['type']}")
            if 'si_created' in r:
                print(f"    $SI Created: {r['si_created']}")
                print(f"    $FN Created: {r['fn_created']}")
    else:
        print("Аномалий не обнаружено.")
```

## Модуль 66: Злоупотребление подписью кода — Обнаружение и защита

### Что это за угроза

Цифровая подпись кода (Code Signing) — механизм доверия в Windows и macOS. Злоумышленники крадут сертификаты подписи, используют просроченные/отозванные сертификаты, или самоподписывают вредоносный код, чтобы пройти проверки SmartScreen, AppLocker и антивирусов. Известные APT-группы (Stuxnet, ShadowHammer) использовали украденные сертификаты.

### Индикаторы компрометации (IoC)

- Исполняемый файл подписан сертификатом с несоответствующим CN (Subject)
- Самоподписанный сертификат для кода (Self-Signed Code Signing)
- Подпись отозванным сертификатом (Revoked)
- Сертификат выдан недоверенным CA
- Несовпадение SignerName и CompanyName в метаданных PE
- Файл подписан, но SignerCertificate.NotAfter < текущей даты (просрочен)

### Обнаружение

```powershell
# Scan-CodeSignatures.ps1
# Проверка подписей всех исполняемых файлов в каталоге

function Scan-Signatures {
    param(
        [string]$Path = 'C:\Users',
        [string]$ReportPath = 'C:\Reports\signature_scan.csv'
    )

    $results = @()
    $extensions = @('*.exe', '*.dll', '*.ps1', '*.sys', '*.ocx')

    foreach ($ext in $extensions) {
        Get-ChildItem -Path $Path -Filter $ext -Recurse -ErrorAction SilentlyContinue |
        ForEach-Object {
            $sig = Get-AuthenticodeSignature $_.FullName

            if ($sig.Status -ne 'Valid') {
                $results += [PSCustomObject]@{
                    Path        = $_.FullName
                    Status      = $sig.Status
                    Signer      = $sig.SignerCertificate.Subject
                    Issuer      = $sig.SignerCertificate.Issuer
                    NotAfter    = $sig.SignerCertificate.NotAfter
                    Thumbprint  = $sig.SignerCertificate.Thumbprint
                    Algorithm   = $sig.SignerCertificate.SignatureAlgorithm.FriendlyName
                }
            }
        }
    }

    $results | Export-Csv -Path $ReportPath -NoTypeInformation -Encoding UTF8
    Write-Host "Найдено $($results.Count) файлов с проблемными подписями"
    Write-Host "Отчёт: $ReportPath"

    # Выделяем критичные
    $critical = $results | Where-Object { $_.Status -in 'Revoked','Invalid' }
    if ($critical) {
        Write-Host "[ALERT] Критичные находки:" -ForegroundColor Red
        $critical | Format-Table Path, Status, Signer -AutoSize
    }

    return $results
}

Scan-Signatures -Path 'C:\Users' -ReportPath 'C:\Reports\signature_scan.csv'
```

## Модуль 67: Руткиты — Обнаружение и защита

### Что это за угроза

Руткит — вредоносное ПО, скрывающее своё присутствие (и присутствие других вредоносных компонентов) в операционной системе. User-mode руткиты перехватывают API-вызовы (hooking), kernel-mode руткиты модифицируют структуры ядра (DKOM, SSDT hooking). Bootkits заражают загрузчик (MBR/UEFI). Руткиты — одна из сложнейших угроз для обнаружения.

### Индикаторы компрометации (IoC)

- Процесс виден в памяти ядра, но отсутствует в `tasklist`/`ps`
- Файл существует на диске (raw read), но не виден в проводнике/`ls`
- Сетевое соединение есть в raw sockets, но не в `netstat`
- Изменения в SSDT (System Service Descriptor Table)
- Неизвестные модули ядра (`lsmod` / `modules`)
- Модифицированные системные библиотеки (libc, ntdll)
- Аномалии в MBR/UEFI

### Обнаружение

**YARA-правило — обнаружение Linux-руткитов:**

```yara
rule Linux_Rootkit_Indicators
```

```bash
        fi
    fi

    echo "  Запуск rkhunter..."
    rkhunter --check --skip-keypress --report-warnings-only 2>/dev/null | head -20
else
```

## Модуль 68: Anti-VM/Anti-Sandbox — Обнаружение и защита

### Что это за угроза

Вредоносное ПО проверяет, не работает ли оно в виртуальной машине или песочнице (sandbox). Если да — не запускает вредоносный функционал, чтобы обмануть аналитиков. Проверки: MAC-адрес VMware/VirtualBox, наличие файлов/процессов гипервизора, низкое количество CPU/RAM, отсутствие пользовательской активности, ускорение таймеров, красные пиксели курсора мыши.

### Индикаторы компрометации (IoC)

- Запросы WMI: `Win32_ComputerSystem.Model` содержит «Virtual», «VMware», «VirtualBox»
- Проверка MAC-адреса: `00:0C:29` (VMware), `08:00:27` (VirtualBox)
- Поиск файлов: `C:\Windows\System32\drivers\vm*.sys`, `VBoxGuest.sys`
- Проверка процессов: `vmtoolsd.exe`, `VBoxService.exe`, `SandboxieRpcSs.exe`
- Проверка реестра: `HKLM\SOFTWARE\VMware, Inc.`, `HKLM\SOFTWARE\Oracle\VirtualBox Guest Additions`
- CPUID instruction с определёнными значениями EAX/EBX

```python
#!/usr/bin/env python3
"""
Чеклист: насколько ваша песочница устойчива к обнаружению.
Запускать ВНУТРИ песочницы для самопроверки.
"""

import subprocess
import platform
import os
import re

class SandboxHardeningCheck:
    def __init__(self):
        self.issues = []
        self.checks = 0

    def check(self, name, condition, recommendation):
        self.checks += 1
        if condition:
            self.issues.append({
                'check': name,
                'recommendation': recommendation,
            })
            print(f"  [FAIL] {name}")
            print(f"         Рекомендация: {recommendation}")
        else:
            print(f"  [PASS] {name}")

    def run_all(self):
        print("=== Проверка устойчивости песочницы к обнаружению ===\n")

        if platform.system() == 'Windows':
            self._check_windows()
        else:
            self._check_linux()

        print(f"\n=== Итого: {len(self.issues)} проблем из {self.checks} проверок ===")
        return self.issues

    def _check_windows(self):
        # Проверка WMI — модель
        try:
            r = subprocess.check_output(
                'wmic computersystem get model', shell=True
            ).decode()
            vm_keywords = ['virtual', 'vmware', 'virtualbox', 'kvm', 'xen', 'qemu']
            is_vm = any(kw in r.lower() for kw in vm_keywords)
            self.check(
                'WMI Model раскрывает виртуализацию',
                is_vm,
                'Изменить Model в WMI через гипервизор (CPUID masking, SMBIOS spoofing)'
            )
        except Exception:
            pass

        # Проверка MAC-адреса
        try:
            r = subprocess.check_output('getmac', shell=True).decode()
            vm_macs = ['00-0C-29', '00-50-56', '08-00-27', '52-54-00']
            has_vm_mac = any(mac in r for mac in vm_macs)
            self.check(
                'MAC-адрес выдаёт виртуализацию',
                has_vm_mac,
                'Рандомизировать MAC-адрес в настройках гипервизора'
            )
        except Exception:
            pass

        # Проверка числа CPU
        cpu_count = os.cpu_count() or 1
        self.check(
            f'Мало CPU ({cpu_count})',
            cpu_count < 2,
            'Назначить >= 2 vCPU песочнице'
        )

        # Проверка RAM (ориентировочно)
        try:
            r = subprocess.check_output(
                'wmic OS get TotalVisibleMemorySize', shell=True
            ).decode()
            mem_kb = int(re.search(r'(\d+)', r).group(1))
            mem_gb = mem_kb / (1024 * 1024)
            self.check(
                f'Мало RAM ({mem_gb:.1f} GB)',
                mem_gb < 3.5,
                'Назначить >= 4 GB RAM'
            )
        except Exception:
            pass

    def _check_linux(self):
        # Проверка DMI
        try:
            dmi = open('/sys/class/dmi/id/product_name').read().lower()
            vm_names = ['virtual', 'vmware', 'virtualbox', 'kvm', 'qemu', 'xen']
            self.check(
                'DMI product_name раскрывает виртуализацию',
                any(v in dmi for v in vm_names),
                'Скрыть DMI через SMBIOS spoofing'
            )
        except Exception:
            pass

        # CPU
        cpu_count = os.cpu_count() or 1
        self.check(
            f'Мало CPU ({cpu_count})',
            cpu_count < 2,
            'Назначить >= 2 vCPU'
        )

        # Наличие guest additions
        try:
            ps = subprocess.check_output(['ps', 'aux']).decode().lower()
            self.check(
                'Guest Additions запущены',
                'vmtoolsd' in ps or 'vboxservice' in ps or 'qemu-ga' in ps,
                'Удалить или скрыть Guest Additions'
            )
        except Exception:
            pass

if __name__ == '__main__':
    checker = SandboxHardeningCheck()
    checker.run_all()
```

## Модуль 69: Обфускация кода — Обнаружение и защита

### Что это за угроза

Обфускация — намеренное запутывание кода для обхода антивирусных сигнатур и затруднения анализа. Методы: Base64-кодирование, XOR-шифрование, string concatenation, переименование переменных, control flow flattening, packing (UPX, Themida), PowerShell `-EncodedCommand`, JavaScript `eval(atob(...))`.

### Индикаторы компрометации (IoC)

- PowerShell с `-EncodedCommand` или `-enc`
- Большие строки Base64 в скриптах
- Цепочки `char()` / `chr()` вместо читаемых строк
- `eval()`, `Invoke-Expression (iex)` с динамическим аргументом
- Файлы с высокой энтропией (упакованные/зашифрованные)
- Множественные уровни декодирования: base64→decompress→execute

```python
#!/usr/bin/env python3
"""
Детектор обфускации/упаковки через анализ энтропии.
Высокая энтропия (>7.0 для исполняемых) = подозрение.
"""

import math
import os
import sys
from collections import Counter

def calculate_entropy(data):
    """Вычислить энтропию Шеннона для данных"""
    if not data:
        return 0.0

    counter = Counter(data)
    length = len(data)
    entropy = 0.0

    for count in counter.values():
        if count > 0:
            probability = count / length
            entropy -= probability * math.log2(probability)

    return entropy

def analyze_file(filepath):
    """Анализ файла на обфускацию/упаковку"""
    with open(filepath, 'rb') as f:
        data = f.read()

    total_entropy = calculate_entropy(data)

    # Анализ по секциям (каждые 256 байт)
    section_size = 256
    high_entropy_sections = 0
    total_sections = max(1, len(data) // section_size)

    for i in range(0, len(data), section_size):
        section = data[i:i + section_size]
        if calculate_entropy(section) > 7.0:
            high_entropy_sections += 1

    high_ratio = high_entropy_sections / total_sections

    result = {
        'file': filepath,
        'size': len(data),
        'entropy': total_entropy,
        'high_entropy_ratio': high_ratio,
        'verdict': 'CLEAN',
    }

    # Оценка
    if total_entropy > 7.5:
        result['verdict'] = 'PACKED/ENCRYPTED'
    elif total_entropy > 7.0:
        result['verdict'] = 'SUSPICIOUS'
    elif total_entropy > 6.5 and high_ratio > 0.5:
        result['verdict'] = 'POSSIBLY_OBFUSCATED'

    # Проверка известных пакеров
    if data[:2] == b'MZ':  # PE file
        pe_text = data[:4096]
        packers = {
            b'UPX': 'UPX',
            b'Themida': 'Themida',
            b'ASPack': 'ASPack',
            b'PECompact': 'PECompact',
            b'MPRESS': 'MPRESS',
        }
        for sig, name in packers.items():
            if sig in pe_text:
                result['packer'] = name
                result['verdict'] = f'PACKED ({name})'
                break

    return result

def scan_directory(path, extensions=None):
    """Массовое сканирование каталога"""
    if extensions is None:
        extensions = {'.exe', '.dll', '.ps1', '.bat', '.vbs', '.js', '.py'}

    results = []
    for root, dirs, files in os.walk(path):
        for fname in files:
            ext = os.path.splitext(fname)[1].lower()
            if ext in extensions:
                fpath = os.path.join(root, fname)
                try:
                    r = analyze_file(fpath)
                    if r['verdict'] != 'CLEAN':
                        results.append(r)
                except (PermissionError, OSError):
                    continue

    return results

if __name__ == '__main__':
    target = sys.argv[1] if len(sys.argv) > 1 else '.'

    if os.path.isfile(target):
        r = analyze_file(target)
        print(f"Файл: {r['file']}")
        print(f"Размер: {r['size']} байт")
        print(f"Энтропия: {r['entropy']:.4f}")
        print(f"Доля высокоэнтропийных секций: {r['high_entropy_ratio']:.2%}")
        print(f"Вердикт: {r['verdict']}")
    else:
        results = scan_directory(target)
        if results:
            print(f"Найдено {len(results)} подозрительных файлов:")
            for r in sorted(results, key=lambda x: x['entropy'], reverse=True):
                print(f"  [{r['verdict']}] {r['file']} "
                      f"(entropy={r['entropy']:.2f})")
        else:
            print("Подозрительных файлов не найдено.")
```

## Модуль 70: Стеганография — Обнаружение и защита

### Что это за угроза

Стеганография — скрытие данных внутри обычных файлов (изображений, аудио, видео, документов). Используется для эксфильтрации данных, передачи команд C2, хранения конфигурации вредоносного ПО. В отличие от шифрования, стеганография скрывает сам факт наличия тайного сообщения.

### Индикаторы компрометации (IoC)

- Аномально большие изображения для их разрешения (например, 1024x768 JPEG размером 15 MB)
- Изображения, скачиваемые процессами, которым они не нужны
- Статистические аномалии в LSB (Least Significant Bit) изображений
- Наличие дополнительных данных после маркера конца файла (EOF)
- Инструменты стеганографии на хосте: `steghide`, `openstego`, `snow`
- Регулярная загрузка одних и тех же изображений с внешнего ресурса

### Обнаружение

**Python-скрипт обнаружения стеганографии:**

```python
#!/usr/bin/env python3
"""
Базовый детектор стеганографии в изображениях.
Проверяет: размер vs разрешение, данные после EOF, статистику LSB.
"""

import os
import struct
import sys
import math
from collections import Counter

def check_jpeg_eof(filepath):
    """Проверить наличие данных после маркера конца JPEG (FFD9)"""
    with open(filepath, 'rb') as f:
        data = f.read()

    # Поиск маркера конца JPEG
    eof_marker = data.rfind(b'\xff\xd9')
    if eof_marker == -1:
        return None

    trailing = len(data) - (eof_marker + 2)
    if trailing > 16:  # Больше 16 байт после EOF — подозрительно
        return {
            'file': filepath,
            'alert': 'DATA_AFTER_EOF',
            'trailing_bytes': trailing,
            'severity': 'HIGH' if trailing > 1024 else 'MEDIUM',
        }
    return None

def check_png_chunks(filepath):
    """Проверить подозрительные чанки PNG"""
    with open(filepath, 'rb') as f:
        data = f.read()

    # PNG signature
    if data[:8] != b'\x89PNG\r\n\x1a\n':
        return None

    suspicious_chunks = []
    offset = 8
    known_chunks = {b'IHDR', b'PLTE', b'IDAT', b'IEND', b'cHRM',
                    b'gAMA', b'iCCP', b'sBIT', b'sRGB', b'bKGD',
                    b'hIST', b'tRNS', b'pHYs', b'sPLT', b'tIME',
                    b'iTXt', b'tEXt', b'zTXt'}

    while offset < len(data) - 8:
        try:
            length = struct.unpack('>I', data[offset:offset + 4])[0]
            chunk_type = data[offset + 4:offset + 8]

            if chunk_type not in known_chunks:
                suspicious_chunks.append({
                    'type': chunk_type.decode('ascii', errors='replace'),
                    'length': length,
                    'offset': offset,
                })

            offset += 12 + length  # length + type + data + crc
        except (struct.error, IndexError):
            break

    if suspicious_chunks:
        return {
            'file': filepath,
            'alert': 'SUSPICIOUS_PNG_CHUNKS',
            'chunks': suspicious_chunks,
            'severity': 'MEDIUM',
        }
    return None

def check_size_ratio(filepath):
    """Проверить отношение размера файла к разрешению"""
    file_size = os.path.getsize(filepath)
    ext = os.path.splitext(filepath)[1].lower()

    # Грубая эвристика: JPEG обычно ~0.5-3 байт на пиксель
    # PNG: ~1-4 байт на пиксель
    # Стеганография увеличивает размер
    if ext in ('.jpg', '.jpeg'):
        max_reasonable_bpp = 5.0  # байт на пиксель
    elif ext == '.png':
        max_reasonable_bpp = 8.0
    else:
        return None

    # Без PIL просто проверяем абсолютный размер vs расширение
    if ext in ('.jpg', '.jpeg') and file_size > 10 * 1024 * 1024:  # > 10 MB JPEG
        return {
            'file': filepath,
            'alert': 'OVERSIZED_IMAGE',
            'size_mb': file_size / (1024 * 1024),
            'severity': 'LOW',
        }
    return None

def scan_directory(path):
    """Сканирование каталога на стеганографию"""
    alerts = []
    extensions = {'.jpg', '.jpeg', '.png', '.bmp', '.gif'}

    for root, dirs, files in os.walk(path):
        for fname in files:
            ext = os.path.splitext(fname)[1].lower()
            if ext not in extensions:
                continue

            fpath = os.path.join(root, fname)
            try:
                if ext in ('.jpg', '.jpeg'):
                    result = check_jpeg_eof(fpath)
                    if result:
                        alerts.append(result)

                if ext == '.png':
                    result = check_png_chunks(fpath)
                    if result:
                        alerts.append(result)

                result = check_size_ratio(fpath)
                if result:
                    alerts.append(result)

            except (PermissionError, OSError):
                continue

    return alerts

if __name__ == '__main__':
    target = sys.argv[1] if len(sys.argv) > 1 else '.'
    results = scan_directory(target)

    if results:
        print(f"Обнаружено {len(results)} подозрительных файлов:")
        for r in results:
            print(f"  [{r['severity']}] {r['file']}: {r['alert']}")
            if 'trailing_bytes' in r:
                print(f"    Данные после EOF: {r['trailing_bytes']} байт")
            if 'chunks' in r:
                for c in r['chunks']:
                    print(f"    Неизвестный чанк: {c['type']} ({c['length']} байт)")
    else:
        print("Подозрительных изображений не обнаружено.")
```

## Модуль 71: Злоупотребление шифрованием трафика — Обнаружение и защита

### Что это за угроза

Злоумышленники используют шифрованные каналы (TLS/SSL, SSH, DNS over HTTPS) для скрытия C2-коммуникаций и эксфильтрации данных. Легитимный HTTPS-трафик маскирует вредоносный. Ключевая проблема: нельзя инспектировать содержимое без расшифровки, но можно анализировать метаданные (JA3, certificate fingerprints, traffic patterns).

### Индикаторы компрометации (IoC)

- Самоподписанные TLS-сертификаты на нестандартных портах
- JA3-хеши, соответствующие известным C2-фреймворкам (Cobalt Strike, Metasploit)
- TLS на нестандартных портах (443 → нормально, 8443/4443/1337 → подозрительно)
- DNS over HTTPS (DoH) на нестандартные серверы
- Аномально длинные TLS-сессии (beaconing)
- Маленькие объёмы данных с регулярной периодичностью (heartbeat)

## Модуль 73: Tor и анонимные сети — Обнаружение и защита

### Что это за угроза

Tor (The Onion Router) и аналогичные сети (I2P, Freenet) анонимизируют трафик, пропуская его через цепочку зашифрованных узлов. Злоумышленники используют Tor для: анонимного C2, эксфильтрации данных, доступа к .onion-ресурсам с вредоносным ПО, обхода сетевых блокировок.

### Индикаторы компрометации (IoC)

- Соединения с IP-адресами из списка Tor exit/relay nodes (публичный список)
- Порт 9001 (OR port), 9030 (Directory), 9050/9150 (SOCKS)
- Процессы: `tor.exe`, `tor`, `obfs4proxy`
- Трафик на Tor bridges (obfs4, meek, snowflake)
- DNS-запросы к `.onion` доменам

### Обнаружение

**Скрипт автоматической загрузки и применения Tor exit node list:**

```bash
#!/bin/bash
# update_tor_blocklist.sh
# Загружает актуальный список Tor exit nodes и обновляет правила

TOR_LIST_URL="https://check.torproject.org/torbulkexitlist"
BLOCKLIST_DIR="/etc/threat-intel/tor"
BLOCKLIST_FILE="$BLOCKLIST_DIR/tor_exit_nodes.txt"

mkdir -p "$BLOCKLIST_DIR"

# Загрузка актуального списка
echo "[$(date)] Загрузка Tor exit nodes..."
curl -sS "$TOR_LIST_URL" -o "$BLOCKLIST_FILE.new" 2>/dev/null

if [ -s "$BLOCKLIST_FILE.new" ]; then
    NODE_COUNT=$(wc -l < "$BLOCKLIST_FILE.new")
    echo "  Загружено $NODE_COUNT exit nodes"
    mv "$BLOCKLIST_FILE.new" "$BLOCKLIST_FILE"
else
    echo "  [ERROR] Не удалось загрузить список"
    rm -f "$BLOCKLIST_FILE.new"
    exit 1
fi

# Генерация правил для iptables
echo "[$(date)] Обновление iptables..."
iptables -F TOR_BLOCK 2>/dev/null
iptables -N TOR_BLOCK 2>/dev/null

while IFS= read -r ip; do
    [[ "$ip" =~ ^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$ ]] && \
        iptables -A TOR_BLOCK -s "$ip" -j DROP
done < "$BLOCKLIST_FILE"

iptables -A TOR_BLOCK -d any -p tcp --dport 9001 -j DROP
iptables -A TOR_BLOCK -d any -p tcp --dport 9030 -j DROP

echo "  Правила обновлены"

# Генерация списка для Suricata
SURICATA_FILE="/etc/suricata/rules/tor-nodes.rules"
echo "# Auto-generated Tor exit node rules" > "$SURICATA_FILE"
echo "# Updated: $(date)" >> "$SURICATA_FILE"

while IFS= read -r ip; do
    if [[ "$ip" =~ ^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$ ]]; then
        echo "drop ip $ip any -> \$HOME_NET any (msg:\"Tor Exit Node Connection\"; classtype:policy-violation; sid:2000${RANDOM: -3}; rev:1;)" >> "$SURICATA_FILE"
    fi
done < "$BLOCKLIST_FILE"

echo "[$(date)] Готово. Tor exit nodes: $NODE_COUNT"
```

## Модуль 74: Fast Flux DNS — Обнаружение и защита

### Что это за угроза

Fast Flux — техника, при которой DNS-запись домена меняет IP-адрес каждые несколько минут/секунд. Используется ботнетами для устойчивости C2-инфраструктуры: если один IP заблокирован, домен уже указывает на другой. Разновидности: Single Flux (один уровень), Double Flux (меняются и NS-серверы).

### Индикаторы компрометации (IoC)

- Домен с TTL < 300 секунд (обычно 60 или менее)
- Один домен разрешается в десятки разных IP за час
- IP-адреса домена в разных AS/странах
- Резолвится в IP из «домашних» диапазонов (ботнет-узлы)
- Частая смена NS-серверов (Double Flux)

### Обнаружение

**Python-скрипт обнаружения Fast Flux:**

```python
#!/usr/bin/env python3
"""
Детектор Fast Flux DNS на основе анализа passive DNS-логов.
Анализирует: количество уникальных IP, TTL, geographic spread.
"""

import json
import sys
from collections import defaultdict
from datetime import datetime, timedelta
from ipaddress import ip_address

class FastFluxDetector:
    def __init__(self):
        # Пороги обнаружения
        self.min_unique_ips = 5       # Минимум уникальных IP за период
        self.max_ttl = 300            # TTL ниже этого — подозрительный
        self.analysis_window = 3600   # Окно анализа: 1 час (секунды)
        self.min_asn_diversity = 3    # Минимум разных ASN

    def analyze_dns_logs(self, log_entries):
        """
        Анализ DNS-логов на Fast Flux.
        log_entries: список словарей {domain, resolved_ip, ttl, timestamp}
        """
        domain_stats = defaultdict(lambda: {
            'ips': set(),
            'ttls': [],
            'timestamps': [],
            'first_seen': None,
            'last_seen': None,
        })

        for entry in log_entries:
            domain = entry['domain'].lower().rstrip('.')
            stats = domain_stats[domain]
            stats['ips'].add(entry['resolved_ip'])
            stats['ttls'].append(entry.get('ttl', 300))
            stats['timestamps'].append(entry['timestamp'])

            if stats['first_seen'] is None:
                stats['first_seen'] = entry['timestamp']
            stats['last_seen'] = entry['timestamp']

        alerts = []
        for domain, stats in domain_stats.items():
            # Пропускаем CDN-домены (белый список)
            if self._is_whitelisted(domain):
                continue

            unique_ips = len(stats['ips'])
            avg_ttl = sum(stats['ttls']) / len(stats['ttls'])
            score = 0

            # Много уникальных IP
            if unique_ips >= self.min_unique_ips:
                score += 30

            if unique_ips >= self.min_unique_ips * 2:
                score += 20

            # Низкий TTL
            if avg_ttl < self.max_ttl:
                score += 20
            if avg_ttl < 120:
                score += 15

            # IP-адреса в «домашних» диапазонах
            residential_count = sum(
                1 for ip in stats['ips']
                if self._is_residential(ip)
            )
            if residential_count > len(stats['ips']) * 0.5:
                score += 15

            if score >= 50:
                alerts.append({
                    'domain': domain,
                    'score': score,
                    'unique_ips': unique_ips,
                    'avg_ttl': avg_ttl,
                    'ip_sample': list(stats['ips'])[:10],
                    'verdict': 'FAST_FLUX' if score >= 70 else 'SUSPICIOUS',
                })

        return sorted(alerts, key=lambda x: x['score'], reverse=True)

    def _is_whitelisted(self, domain):
        """CDN и крупные сервисы, использующие множество IP легитимно"""
        cdn_patterns = [
            'cloudfront.net', 'akamai', 'cloudflare',
            'googleapis.com', 'amazonaws.com', 'azure',
            'microsoft.com', 'google.com', 'facebook.com',
            'apple.com', 'cdn.', '.cdn',
        ]
        return any(p in domain for p in cdn_patterns)

    def _is_residential(self, ip_str):
        """Грубая эвристика: IP в «домашних» диапазонах"""
        try:
            ip = ip_address(ip_str)
            return ip.is_private
        except ValueError:
            return False

if __name__ == '__main__':
    detector = FastFluxDetector()

    # Пример: сгенерированные данные для демонстрации
    example_logs = [
        {'domain': 'suspicious-domain.xyz', 'resolved_ip': f'185.{i}.{j}.{k}',
         'ttl': 60, 'timestamp': datetime.now().isoformat()}
        for i in range(10) for j in [1] for k in [1]
    ]

    results = detector.analyze_dns_logs(example_logs)
    for r in results:
        print(f"[{r['verdict']}] {r['domain']} "
              f"(score={r['score']}, ips={r['unique_ips']}, ttl={r['avg_ttl']:.0f})")
```

### Защита и предотвращение

1. **DNS Response Policy Zones (RPZ)** — блокировка Fast Flux доменов на DNS-уровне.

2. **Passive DNS мониторинг** — запись всех DNS-ответов для ретроспективного анализа.

3. **Пороговые правила на SIEM:** домен с >10 уникальными IP за час + TTL <300 = алерт.

4. **Threat Intelligence интеграция** — подписки на фиды Fast Flux доменов.

5. **Блокировка по ASN** — если домен разрешается в IP из сомнительных ASN (hoster'ы для ботнетов).

### Инструменты защитника

| Инструмент | Назначение |
|-----------|------------|
| **PassiveDNS (pdns)** | Запись и анализ DNS-ответов |
| **Zeek DNS logging** | Логирование всех DNS-запросов |
| **DNSDB (Farsight)** | База passive DNS |
| **Response Policy Zones** | DNS-фильтрация |
| **MISP** | Threat Intelligence с Fast Flux индикаторами |

### Практическое задание

1. Настройте Zeek для логирования всех DNS-ответов (dns.log)
2. Проанализируйте dns.log за день: найдите домены с >5 уникальными IP
3. Запустите скрипт FastFluxDetector на реальных логах
4. Настройте RPZ на DNS-сервере для блокировки Fast Flux доменов из фидов
5. Создайте дашборд: «Домены с аномально высоким числом IP и низким TTL»

## Модуль 75: DGA (Domain Generation Algorithms) — Обнаружение и защита

### Что это за угроза

DGA — алгоритмы генерации доменных имён, используемые ботнетами для поддержания связи с C2. Малварь ежедневно генерирует сотни/тысячи потенциальных доменных имён, злоумышленник регистрирует одно из них. Примеры: Conficker, Necurs, Emotet, TrickBot, Dridex.

DGA-домены обычно выглядят «случайно»: `xjk4r9f2m1.com`, `qwpoe3bh.net`, `asdfjklqwe.xyz`.

### Индикаторы компрометации (IoC)

- DNS-запросы к доменам с высокой энтропией (случайные строки)
- Массовые NXDOMAIN-ответы (большинство DGA-доменов не зарегистрированы)
- Длинные доменные имена без словарных слов
- Множество запросов к доменам в «мусорных» TLD (.xyz, .top, .buzz)
- Паттерн: один хост генерирует 100+ DNS-запросов за минуту, 90%+ = NXDOMAIN

### Обнаружение

**Python-скрипт обнаружения DGA-доменов:**

```python
#!/usr/bin/env python3
"""
Детектор DGA-доменов на основе:
1. Энтропии имени
2. Соотношения согласных/гласных
3. Длины
4. N-gram анализа (биграммы, характерные для языка vs случайные)
5. NXDOMAIN-статистики
"""

import math
import re
import sys
from collections import Counter, defaultdict

# Частые биграммы в английских/русских словах (нормализованные)
COMMON_BIGRAMS = {
    'th', 'he', 'in', 'er', 'an', 'on', 'en', 're', 'ed', 'es',
    'st', 'nt', 'le', 'ng', 'at', 'is', 'it', 'or', 'al', 'ar',
    'te', 'se', 'to', 'ha', 'ou', 'io', 'co', 'de', 'ra', 'li',
    'go', 'oo', 'ma', 'me', 'ne', 'no', 'pa', 'pe', 'po', 'ro',
    'so', 'ta', 'ti', 'un', 'us', 've', 'wa', 'we', 'wi',
}

VOWELS = set('aeiouy')
CONSONANTS = set('bcdfghjklmnpqrstvwxz')

class DGADetector:
    def __init__(self, threshold=0.65):
        self.threshold = threshold

    def analyze_domain(self, domain):
        """Анализ одного доменного имени на признаки DGA"""
        # Берём только 2nd-level domain
        parts = domain.lower().rstrip('.').split('.')
        if len(parts) < 2:
            return None

        sld = parts[-2]  # Second-level domain
        tld = parts[-1]

        if len(sld) < 4:
            return None  # Слишком короткий для анализа

        scores = {}

        # 1. Энтропия
        entropy = self._entropy(sld)
        scores['entropy'] = min(entropy / 4.5, 1.0)  # Нормализация

        # 2. Соотношение согласных/гласных
        vowel_count = sum(1 for c in sld if c in VOWELS)
        consonant_count = sum(1 for c in sld if c in CONSONANTS)
        total_alpha = vowel_count + consonant_count

        if total_alpha > 0:
            vowel_ratio = vowel_count / total_alpha
            # Нормальный английский ~40% гласных; DGA отклоняется
            scores['vowel_deviation'] = abs(vowel_ratio - 0.40) * 3
        else:
            scores['vowel_deviation'] = 1.0

        # 3. Длина
        scores['length'] = min(len(sld) / 25.0, 1.0)

        # 4. Биграммный анализ
        bigrams = [sld[i:i+2] for i in range(len(sld) - 1)]
        if bigrams:
            common_count = sum(1 for bg in bigrams if bg in COMMON_BIGRAMS)
            scores['bigram_rarity'] = 1.0 - (common_count / len(bigrams))
        else:
            scores['bigram_rarity'] = 0.5

        # 5. Числа в домене
        digit_count = sum(1 for c in sld if c.isdigit())
        scores['digit_ratio'] = digit_count / len(sld) if len(sld) > 0 else 0

        # 6. Подозрительный TLD
        suspicious_tlds = {'xyz', 'top', 'buzz', 'tk', 'ml', 'ga', 'cf', 'gq', 'pw', 'cc'}
        scores['suspicious_tld'] = 1.0 if tld in suspicious_tlds else 0.0

        # Итоговый score
        weights = {
            'entropy': 0.25,
            'vowel_deviation': 0.15,
            'length': 0.10,
            'bigram_rarity': 0.25,
            'digit_ratio': 0.10,
            'suspicious_tld': 0.15,
        }

        total_score = sum(scores[k] * weights[k] for k in weights)

        return {
            'domain': domain,
            'sld': sld,
            'score': round(total_score, 3),
            'is_dga': total_score >= self.threshold,
            'details': {k: round(v, 3) for k, v in scores.items()},
        }

    def analyze_nxdomain_ratio(self, dns_logs):
        """Анализ NXDOMAIN-статистики по хостам"""
        host_stats = defaultdict(lambda: {'total': 0, 'nxdomain': 0, 'domains': set()})

        for entry in dns_logs:
            host = entry.get('src_ip', 'unknown')
            stats = host_stats[host]
            stats['total'] += 1
            stats['domains'].add(entry['domain'])
            if entry.get('rcode') == 'NXDOMAIN':
                stats['nxdomain'] += 1

        alerts = []
        for host, stats in host_stats.items():
            if stats['total'] < 10:
                continue

            nxdomain_ratio = stats['nxdomain'] / stats['total']
            unique_domains = len(stats['domains'])

            if nxdomain_ratio > 0.7 and unique_domains > 20:
                alerts.append({
                    'host': host,
                    'total_queries': stats['total'],
                    'nxdomain_ratio': f"{nxdomain_ratio:.0%}",
                    'unique_domains': unique_domains,
                    'verdict': 'DGA_ACTIVITY',
                })

        return alerts

    @staticmethod
    def _entropy(s):
        if not s:
            return 0.0
        counter = Counter(s)
        length = len(s)
        return -sum(
            (c / length) * math.log2(c / length)
            for c in counter.values()
        )

if __name__ == '__main__':
    detector = DGADetector()

    test_domains = [
        # Легитимные
        'google.com',
        'stackoverflow.com',
        'github.com',
        'microsoft.com',
        'amazon.com',
        # DGA-подобные
        'xjk4r9f2m1.com',
        'qwpoe3bhxz.net',
        'asdfjklqwe.xyz',
        'h7k2m9p4q1.top',
        'bvnxcmzlkj.tk',
        'rt83hd92kf.buzz',
        # Conficker-подобные
        'mpawqvin.ws',
        'grjohkqn.info',
        'pkxwvena.biz',
    ]

    print("=== DGA Detector ===\n")
    print(f"{'Домен':<30} {'Score':>6} {'DGA?':>5}")
    print('-' * 45)

    for domain in test_domains:
        result = detector.analyze_domain(domain)
        if result:
            flag = '  !!!' if result['is_dga'] else ''
            print(f"{domain:<30} {result['score']:>6.3f} "
                  f"{'DA' if result['is_dga'] else 'Нет':>5}{flag}")
```
