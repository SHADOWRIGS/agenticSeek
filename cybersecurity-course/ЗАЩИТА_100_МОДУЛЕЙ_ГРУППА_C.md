## Модуль 46: DNS Tunneling — Обнаружение и защита

### Что это за угроза

DNS-туннелирование — техника, при которой атакующий кодирует данные (команды C2, украденные файлы) внутри DNS-запросов и ответов. Поскольку DNS-трафик редко блокируется и часто не инспектируется, это один из самых скрытных каналов эксфильтрации данных и управления вредоносным ПО.

**MITRE ATT&CK:** T1071.004 (Application Layer Protocol: DNS)

Типичные инструменты атакующего: iodine, dnscat2, dns2tcp, Cobalt Strike DNS beacon.

### Индикаторы компрометации (IoC)

**Сетевые:**
- Аномально длинные DNS-запросы (имена > 52 символов в поддомене)
- Необычные типы записей: TXT, NULL, CNAME с большими payload
- Высокая частота DNS-запросов к одному домену (> 50 запросов/мин)
- Запросы к доменам с высокой энтропией (Base32/Base64-кодирование)
- Прямые DNS-запросы к внешним серверам (мимо корпоративного резолвера)

**Хостовые:**
- Процессы, генерирующие аномальное количество DNS-запросов
- Нестандартные DNS-клиенты (iodine, dnscat2 в процессах)
- Запуск nslookup/dig с необычными параметрами из скриптов

**Статистические:**
- Соотношение запрос/ответ сильно отличается от нормы
- Объём DNS-трафика на хост > 1 МБ/час (нормально: < 100 КБ/час)
- Энтропия поддоменов > 3.5 бит/символ

#### Zeek-скрипт: Анализ энтропии DNS

```zeek
@load base/frameworks/notice

module DNSTunnel;

export {
  redef enum Notice::Type += {
    DNS_Tunnel_Entropy,
    DNS_Tunnel_Volume
  };

  const entropy_threshold = 3.5 &redef;
  const query_volume_threshold = 100 &redef;
}

global dns_query_count: table[addr] of count &default=0 &create_expire=1min;

event dns_request(c: connection, msg: dns_msg, query: string, qtype: count, qclass: count)
{
  local subdomain = split_string(query, /\./)[0];
  if ( |subdomain| > 30 )
  {
    local ent = find_entropy(subdomain)$entropy;
    if ( ent > entropy_threshold )
    {
      NOTICE([$note=DNS_Tunnel_Entropy,
              $msg=fmt("High entropy DNS subdomain: %s (entropy=%.2f)", query, ent),
              $conn=c,
              $identifier=cat(c$id$orig_h, query)]);
    }
  }

  dns_query_count[c$id$orig_h] += 1;
  if ( dns_query_count[c$id$orig_h] > query_volume_threshold )
  {
    NOTICE([$note=DNS_Tunnel_Volume,
            $msg=fmt("High DNS query volume from %s: %d queries/min", c$id$orig_h, dns_query_count[c$id$orig_h]),
            $conn=c]);
  }
}
```

```python
import math
from collections import Counter

def entropy(s):
    """Рассчитать энтропию Шеннона строки"""
    if not s:
        return 0
    freq = Counter(s)
    probs = [count / len(s) for count in freq.values()]
    return -sum(p * math.log2(p) for p in probs)
```

## Модуль 47: HTTPS C2 Beaconing — Обнаружение и защита

### Что это за угроза

HTTPS-биконинг (beaconing) — самый распространённый метод C2-коммуникации, при котором вредоносное ПО периодически обращается к серверу управления по HTTPS. Шифрование делает контент невидимым для инспекции, но паттерн обращений (периодичность, размер, JA3/JA4) остаётся детектируемым.

**MITRE ATT&CK:** T1071.001 (Web Protocols), T1573.002 (Encrypted Channel: Asymmetric Cryptography)

Типичные инструменты: Cobalt Strike, Sliver, Covenant, Havoc, Mythic.

### Индикаторы компрометации (IoC)

**Сетевые:**
- Регулярные HTTPS-запросы с фиксированным или слабо рандомизированным интервалом (jitter)
- Подозрительные JA3/JA3S-хеши (уникальные для C2-фреймворков)
- Самоподписанные или недавно выпущенные TLS-сертификаты
- Домены с коротким временем жизни (< 30 дней)
- Anomaly: малый размер POST-запросов, большие ответы
- HTTP-заголовки, не совпадающие с заявленным User-Agent

**Хостовые:**
- Процессы, делающие регулярные HTTP/S-запросы (svchost.exe → внешний IP)
- Запуск процессов, обычно не обращающихся к интернету
- Нестандартные TLS-библиотеки в процессах

**Статистические:**
- Коэффициент вариации интервалов между запросами < 0.1 (слишком регулярно)
- Одинаковый размер пакетов в серии запросов

#### Python: Детектор beaconing по NetFlow/Zeek-логам

```python
"""
Beacon Detection Script
Анализ conn.log Zeek для выявления C2 beaconing
"""
import pandas as pd
import numpy as np
from collections import defaultdict

def load_zeek_conn(filepath):
    """Загрузка conn.log Zeek"""
    df = pd.read_csv(filepath, sep='\t', comment='#',
                     names=['ts','uid','id.orig_h','id.orig_p',
                            'id.resp_h','id.resp_p','proto','service',
                            'duration','orig_bytes','resp_bytes',
                            'conn_state','local_orig','local_resp',
                            'missed_bytes','history','orig_pkts',
                            'orig_ip_bytes','resp_pkts','resp_ip_bytes',
                            'tunnel_parents'])
    df['ts'] = pd.to_datetime(df['ts'], unit='s')
    return df

def detect_beaconing(df, min_connections=10, max_cv=0.3):
    """
    Обнаружение beaconing по коэффициенту вариации интервалов.
    Низкий CV = регулярные интервалы = возможный beacon.
    """
    results = []

    # Группировка по src -> dst
    groups = df.groupby(['id.orig_h', 'id.resp_h', 'id.resp_p'])

    for (src, dst, port), group in groups:
        if len(group) < min_connections:
            continue

        # Расчёт интервалов между соединениями
        timestamps = group['ts'].sort_values()
        intervals = timestamps.diff().dt.total_seconds().dropna()

        if len(intervals) < 5:
            continue

        mean_interval = intervals.mean()
        std_interval = intervals.std()

        if mean_interval == 0:
            continue

        cv = std_interval / mean_interval  # Коэффициент вариации

        if cv < max_cv:
            results.append({
                'src': src,
                'dst': dst,
                'port': port,
                'connections': len(group),
                'mean_interval_sec': round(mean_interval, 2),
                'cv': round(cv, 4),
                'risk': 'HIGH' if cv < 0.1 else 'MEDIUM'
            })

    return pd.DataFrame(results).sort_values('cv')
```

## Модуль 48: Domain Fronting — Обнаружение и защита

### Что это за угроза

Domain Fronting — техника, при которой атакующий маскирует C2-трафик под обращение к легитимному домену (например, google.com), используя CDN. В TLS SNI указывается легитимный домен, а в HTTP Host-заголовке — реальный C2-домен. CDN перенаправляет запрос на C2-сервер.

**MITRE ATT&CK:** T1090.004 (Proxy: Domain Fronting)

### Индикаторы компрометации (IoC)

- Расхождение между SNI (TLS) и Host-заголовком HTTP
- Обращения к CDN-провайдерам (cloudfront, akamai, azure) с подозрительным поведением
- Высокий объём трафика к CDN от необычных процессов
- HTTPS-трафик к CDN-IP без стандартного браузерного User-Agent

### Обнаружение

#### Sigma-правило: SNI/Host mismatch

```yaml

    sni: '%cs-host%'

  - attack.command_and_control
  - attack.t1090.004
```

#### TLS-инспекция: сравнение SNI и Host

```python
"""
Скрипт для Zeek-логов: выявление domain fronting
Сравнивает SNI из ssl.log с Host из http.log
"""
import pandas as pd

def detect_domain_fronting(ssl_log, http_log):
    """Обнаружение расхождений SNI ↔ HTTP Host"""
    ssl = pd.read_csv(ssl_log, sep='\t', comment='#',
                      names=['ts','uid','id.orig_h','id.orig_p',
                             'id.resp_h','id.resp_p','version',
                             'cipher','curve','server_name',
                             'resumed','last_alert','next_protocol',
                             'established','cert_chain_fuids',
                             'client_cert_chain_fuids','subject',
                             'issuer','client_subject','client_issuer',
                             'validation_status','ja3','ja3s'])

    http = pd.read_csv(http_log, sep='\t', comment='#',
                       names=['ts','uid','id.orig_h','id.orig_p',
                              'id.resp_h','id.resp_p','trans_depth',
                              'method','host','uri','referrer',
                              'version','user_agent','origin',
                              'request_body_len','response_body_len',
                              'status_code','status_msg','info_code',
                              'info_msg','tags','username','password',
                              'proxied','orig_fuids','orig_filenames',
                              'orig_mime_types','resp_fuids',
                              'resp_filenames','resp_mime_types'])

    # Совмещение по uid (session ID)
    merged = ssl.merge(http, on='uid', suffixes=('_ssl', '_http'))

    # Поиск расхождений
    mismatches = merged[merged['server_name'] != merged['host']]
    mismatches = mismatches[mismatches['server_name'].notna() & mismatches['host'].notna()]

    cdn_domains = ['.cloudfront.net', '.azureedge.net', '.akamaized.net', '.fastly.net']
    suspicious = mismatches[
        mismatches['server_name'].apply(
            lambda x: any(cdn in str(x) for cdn in cdn_domains)
        )
    ]

    return suspicious[['ts_ssl', 'id.orig_h_ssl', 'server_name', 'host',
                        'method', 'uri', 'user_agent']]
```

## Модуль 49: Dead Drop Resolver — Обнаружение и защита

### Что это за угроза

Dead Drop Resolver (DDR) — техника, при которой атакующий размещает адрес C2-сервера на легитимной платформе (Pastebin, GitHub, Twitter/X, Telegram, Google Docs). Вредоносное ПО обращается к легитимному сервису, парсит публикацию и извлекает оттуда адрес реального C2.

### Индикаторы компрометации (IoC)

### Что это за угроза

Custom Protocol C2 — использование атакующими нестандартных или собственных протоколов для управления вредоносным ПО. Это может быть: трафик поверх ICMP, кастомный бинарный протокол на нестандартных портах, стеганографическое скрытие данных в изображениях, использование Raw Sockets.

## Модуль 51: Process Injection — Обнаружение и защита

### Что это за угроза

Внедрение в процесс (Process Injection) — семейство техник, при которых атакующий внедряет код в адресное пространство другого (легитимного) процесса. Это позволяет выполнять вредоносный код от имени доверенного процесса, обходить EDR и скрывать активность.

**MITRE ATT&CK:** T1055 (Process Injection) и подтехники:
- T1055.001 — DLL Injection
- T1055.002 — PE Injection
- T1055.003 — Thread Execution Hijacking
- T1055.004 — Asynchronous Procedure Call
- T1055.012 — Process Hollowing

### Индикаторы компрометации (IoC)

**Windows API вызовы (цепочка):**
- `OpenProcess` → `VirtualAllocEx` → `WriteProcessMemory` → `CreateRemoteThread`
- `NtCreateSection` → `NtMapViewOfSection` (process hollowing)
- `CreateProcess(SUSPENDED)` → `WriteProcessMemory` → `ResumeThread`

**Sysmon-события:**
- **EventID 8** — CreateRemoteThread (ключевой индикатор)
- **EventID 10** — ProcessAccess (PROCESS_VM_WRITE + PROCESS_CREATE_THREAD)
- **EventID 1** — процесс запускается suspended (CreationFlags: 0x4)

**Поведенческие:**
- svchost.exe без ожидаемого parent (services.exe)
- notepad.exe делает сетевые подключения
- explorer.exe порождает cmd.exe/powershell.exe с подозрительными аргументами

### Обнаружение

#### Sysmon-конфигурация: Ловим инъекции

```xml
<Sysmon schemaversion="4.90">

    <!-- EventID 8: CreateRemoteThread -->

      <TargetImage condition="is">C:\Windows\System32\csrss.exe</TargetImage>
      <TargetImage condition="is">C:\Windows\System32\services.exe</TargetImage>
    </CreateRemoteThread>

    <!-- EventID 10: ProcessAccess с опасными флагами -->
    <ProcessAccess onmatch="include">
      <GrantedAccess condition="is">0x1FFFFF</GrantedAccess>  <!-- PROCESS_ALL_ACCESS -->
      <GrantedAccess condition="is">0x1F0FFF</GrantedAccess>
      <GrantedAccess condition="is">0x001F0FFF</GrantedAccess>
    </ProcessAccess>

    <!-- EventID 1: Процесс создан в suspended режиме -->
    <ProcessCreate onmatch="include">
      <CommandLine condition="contains">-suspended</CommandLine>
    </ProcessCreate>
  </EventFiltering>
</Sysmon>
```

## Модуль 52: Fileless Malware — Обнаружение и защита

### Что это за угроза

Бесфайловое вредоносное ПО (Fileless Malware) — вредоносный код, который работает исключительно в оперативной памяти, не оставляя файлов на диске. Использует легитимные системные инструменты (PowerShell, WMI, .NET), реестр Windows или процессы в памяти. Традиционные антивирусы, сканирующие файлы на диске, не могут его обнаружить.

**MITRE ATT&CK:** T1059 (Command and Scripting Interpreter), T1546 (Event Triggered Execution), T1547 (Boot or Logon Autostart Execution)

### Индикаторы компрометации (IoC)

**В памяти:**
- Незнакомый код в легитимных процессах (malfind в Volatility)
- .NET Assembly загруженные в PowerShell без файла на диске
- Shellcode-паттерны в памяти процессов

**В реестре:**
- VBS/JS/PowerShell-скрипты в HKCU\Software\Microsoft\Windows\CurrentVersion\Run
- Encoded-данные в нестандартных ключах реестра
- WMI-подписки в `root\subscription`

**Поведенческие:**
- PowerShell с параметрами `-EncodedCommand`, `-NoProfile`, `-WindowStyle Hidden`
- mshta.exe выполняет VBScript
- regsvr32.exe загружает скрипт с URL
- certutil.exe декодирует файлы из Base64

### Обнаружение

#### Sigma-правило: Fileless PowerShell

```powershell
# Скрипт анализа PowerShell Script Block Logs
# Выявление подозрительных паттернов

$suspiciousPatterns = @(
    'Net\.WebClient',
    'DownloadString',
    'IEX|Invoke-Expression',
    'FromBase64String',
    'EncodedCommand',
    'Reflection\.Assembly',
    'VirtualAlloc',
    'CreateThread',
    'Mimikatz|sekurlsa',
    'Kerberoast',
    'BloodHound|SharpHound',
    'Rubeus',
    'Get-Credential',
    'ConvertTo-SecureString.*-AsPlainText'
)

$events = Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" `
  -FilterXPath "*[System[EventID=4104]]" -MaxEvents 2000 -ErrorAction SilentlyContinue

$alerts = foreach ($event in $events) {
    $scriptBlock = $event.Properties[2].Value
    foreach ($pattern in $suspiciousPatterns) {
        if ($scriptBlock -match $pattern) {
            [PSCustomObject]@{
                Timestamp   = $event.TimeCreated
                Pattern     = $pattern
                Level       = if ($pattern -match 'Mimikatz|VirtualAlloc|CreateThread') { 'CRITICAL' } else { 'HIGH' }
                ScriptBlock = $scriptBlock.Substring(0, [Math]::Min(300, $scriptBlock.Length))
                ScriptBlockId = $event.Properties[3].Value
            }
            break
        }
    }
}

$alerts | Sort-Object Timestamp -Descending | Format-Table -AutoSize
Write-Host "`n[*] Найдено подозрительных событий: $($alerts.Count)" -ForegroundColor Yellow
```


3. **Just Enough Administration (JEA)**

4. **Логирование (обязательно):**
   - Script Block Logging (EventID 4104)
   - Module Logging
   - Transcription (запись всех сессий в файлы)

## Модуль 57: Reflective DLL Loading — Обнаружение и защита

### Что это за угроза

Reflective DLL Loading — техника загрузки DLL-библиотеки непосредственно в память процесса, минуя стандартный Windows PE Loader (LoadLibrary). DLL не записывается на диск и не регистрируется в PEB (Process Environment Block), что делает её невидимой для большинства инструментов мониторинга.

**MITRE ATT&CK:** T1620 (Reflective Code Loading)

### Индикаторы компрометации (IoC)

- Выделение RWX-памяти (PAGE_EXECUTE_READWRITE) в процессе
- Загруженные модули в памяти без соответствующей записи в PEB LdrModuleList
- PE-заголовки (MZ / PE) в RWX-регионах памяти
- Вызов VirtualAlloc с флагом 0x40 (PAGE_EXECUTE_READWRITE)
- Использование RtlMoveMemory / memcpy для копирования PE в выделенную память

### Обнаружение

## Модуль 58: Thread Execution Hijacking — Обнаружение и защита

### Что это за угроза

Thread Execution Hijacking — атакующий приостанавливает поток (thread) легитимного процесса, изменяет его контекст (instruction pointer) на адрес вредоносного кода и возобновляет выполнение. Это позволяет выполнить код в контексте доверенного процесса без создания нового потока.

**MITRE ATT&CK:** T1055.003 (Process Injection: Thread Execution Hijacking)

### Индикаторы компрометации (IoC)

**API-вызовы (цепочка):**
- `OpenThread` → `SuspendThread` → `SetThreadContext` / `Wow64SetThreadContext` → `ResumeThread`
- `VirtualAllocEx` + `WriteProcessMemory` перед `SetThreadContext`
- `GetThreadContext` → модификация RIP/EIP → `SetThreadContext`

**Sysmon:**
- EventID 10 (ProcessAccess) с правами THREAD_SUSPEND_RESUME + THREAD_SET_CONTEXT
- EventID 8 (CreateRemoteThread) может не сработать (поток не создаётся, а перехватывается)

### Обнаружение

#### Sigma-правило: Thread Context Manipulation

```yaml

  product: windows

  selection:
    GrantedAccess|contains:
      - '0x0042'   # THREAD_SUSPEND_RESUME | THREAD_SET_CONTEXT
      - '0x001F03FF' # THREAD_ALL_ACCESS
      - '0x1FFFFF'   # PROCESS_ALL_ACCESS
  filter:
    SourceImage|endswith:
      - '\csrss.exe'
      - '\MsMpEng.exe'
      - '\dwm.exe'
      - '\smss.exe'
  condition: selection and not filter
level: high
tags:
  - attack.defense_evasion
  - attack.t1055.003
```

#### ETW: Мониторинг через Windows Threat Intelligence


### Защита и предотвращение

1. **CFG (Control Flow Guard)**
   - Включение CFG для всех приложений: не позволяет переключить EIP/RIP на произвольный адрес
   ```
   # Через Windows Security → App & Browser Control → Exploit Protection
   # Или GPO: Override Control Flow Guard → On
   ```

2. **CIG (Code Integrity Guard)**
   - Запрет загрузки неподписанного кода в защищённые процессы
   - Включается для процессов через PROCESS_CREATION_MITIGATION_POLICY

3. **Sysmon + SIEM корреляция**
   - ProcessAccess (EventID 10) с THREAD_SUSPEND_RESUME → коррелировать с ProcessCreate
   - Если suspend→resume произошёл от неожиданного процесса → Critical

4. **EDR с поведенческим анализом**
   - CrowdStrike, SentinelOne, Defender for Endpoint отслеживают SetThreadContext

### Практическое задание

1. Настройте Sysmon для логирования ProcessAccess (EventID 10) с нужными GrantedAccess
2. Найдите все события с THREAD_SUSPEND_RESUME за 24 часа
3. Определите, какие из них легитимны (debuggers, AV, Windows Update)
4. Создайте корреляционное правило в SIEM: suspend+context_change+resume → alert

## Модуль 59: APC Injection — Обнаружение и защита

### Что это за угроза

Asynchronous Procedure Call (APC) Injection — техника, при которой атакующий ставит в очередь APC-вызов для потока другого процесса. Когда поток переходит в alertable state (WaitForSingleObjectEx, SleepEx), APC выполняется — в контексте целевого процесса.

**MITRE ATT&CK:** T1055.004 (Process Injection: Asynchronous Procedure Call)

Вариант Early Bird: APC ставится в очередь до начала выполнения основного потока (CreateProcess SUSPENDED → QueueUserAPC → ResumeThread).

### Индикаторы компрометации (IoC)

**API-вызовы:**
- `OpenProcess` → `VirtualAllocEx` → `WriteProcessMemory` → `QueueUserAPC` → `ResumeThread`
- Early Bird: `CreateProcess(SUSPENDED)` → `VirtualAllocEx` → `WriteProcessMemory` → `QueueUserAPC` → `ResumeThread`

**Sysmon:**
- EventID 10: ProcessAccess с PROCESS_VM_WRITE + PROCESS_VM_OPERATION
- EventID 1: Процесс создан в suspended mode (parent не services.exe)
- EventID 8: CreateRemoteThread может не зафиксировать APC (нет нового потока)

### Обнаружение

#### Sigma-правило: Early Bird APC (suspended process + injection)

   - Включается per-process через Windows Security

2. **CFG + CIG** (см. Модуль 58)
   - Control Flow Guard + Code Integrity Guard

3. **Parent-child валидация**
   - svchost.exe → parent только services.exe

4. **EDR behavioral detection**

4. Документируйте: легитимные пары parent→child для системных процессов

## Модуль 60: Named Pipe Impersonation — Обнаружение и защита

### Что это за угроза

Named Pipe Impersonation — техника, при которой атакующий создаёт именованный канал (named pipe) и ожидает подключения привилегированного процесса. Когда процесс подключается, атакующий вызывает ImpersonateNamedPipeClient() и получает токен безопасности подключившегося клиента. Это один из основных методов повышения привилегий в Windows.

**MITRE ATT&CK:** T1134.001 (Access Token Manipulation: Token Impersonation/Theft)

Используется в: PrintSpoofer, RottenPotato, JuicyPotato, GodPotato, SweetPotato.

### Индикаторы компрометации (IoC)

**Хостовые:**
- Создание named pipe с именем, похожим на системное (\\.\pipe\spoolss, \\.\pipe\efsrpc)
- Процесс без привилегий создаёт pipe с системным именем
- Вызов ImpersonateNamedPipeClient() от непривилегированного процесса
- Sysmon EventID 17 (PipeCreated) / EventID 18 (PipeConnected)

**Процессы-индикаторы:**
- PrintSpoofer.exe, JuicyPotato.exe, GodPotato.exe в процессах
- Неожиданные pipe с именами: \\.\pipe\test, \\.\pipe\evil, случайные имена
- cmd.exe / powershell.exe запущенные от SYSTEM после pipe impersonation

### Обнаружение

#### Sysmon: Мониторинг Named Pipes

```xml
<!-- Sysmon: логирование создания и подключения к named pipes -->

  <EventFiltering>

    <PipeEvent onmatch="include">
      <!-- Ловим все pipe, кроме известных -->

      <PipeName condition="excludes">\wkssvc</PipeName>
      <PipeName condition="excludes">\lsass</PipeName>
      <PipeName condition="excludes">\ntsvcs</PipeName>
    </PipeEvent>

    <!-- EventID 18: Pipe Connected -->
    <PipeEvent onmatch="include">

    </PipeEvent>

</Sysmon>
```

#### PowerShell: Аудит Named Pipes

```powershell
# Список всех текущих named pipes
[System.IO.Directory]::GetFiles("\\.\pipe\") | ForEach-Object {
  $pipeName = $_ -replace '^\\\\.\\pipe\\', ''
  $owner = try {
    $acl = Get-Acl "\\.\pipe\$pipeName" -ErrorAction Stop
    $acl.Owner
  } catch { "N/A" }

  [PSCustomObject]@{
    PipeName = $pipeName
    Owner    = $owner
  }
} | Sort-Object PipeName | Format-Table -AutoSize

# Мониторинг новых pipe в реальном времени (Sysmon EventID 17)
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 200 |
  Where-Object { $_.Id -eq 17 } |
  Select-Object TimeCreated,
    @{N='PipeName';E={$_.Properties[5].Value}},
    @{N='Image';E={$_.Properties[4].Value}} |
  Format-Table -AutoSize
```

### Защита и предотвращение

1. **Ограничение SeImpersonatePrivilege**
   - Удалить SeImpersonatePrivilege у service accounts, где не требуется
   - GPO: Computer Config → Windows Settings → Security Settings → Local Policies → User Rights Assignment → «Impersonate a client after authentication»
   - Оставить только: LOCAL SERVICE, NETWORK SERVICE, Administrators, IIS APPPOOL\DefaultAppPool

2. **Запрет создания Global named pipes**
   - Ограничить создание named pipes через DACL
   - Мониторинг pipe с глобальной видимостью от непривилегированных процессов

3. **Патчинг уязвимостей**
   - PrintSpoofer → отключение Print Spooler на серверах, где не нужен
   - EFSPotato → патч EFS RPC
   ```powershell
   # Отключение Print Spooler
   Stop-Service Spooler
   Set-Service Spooler -StartupType Disabled
   ```

4. **Мониторинг Sysmon EventID 17/18**
   - Все PipeCreated/PipeConnected события → SIEM
   - Алерт при создании pipe процессом с нестандартным parent

5. **Windows Credential Guard**
   - Защита токенов SYSTEM от кражи через аппаратную изоляцию

### Практическое задание

1. Запустите `PipeList.exe` и задокументируйте все текущие named pipes
2. Настройте Sysmon для логирования EventID 17/18
3. Запустите PowerShell-скрипт мониторинга pipes
4. Проверьте, у каких service accounts есть SeImpersonatePrivilege:
   ```powershell
   whoami /priv | findstr "Impersonate"
   # Для всех аккаунтов:
   secedit /export /areas USER_RIGHTS /cfg c:\temp\rights.cfg
   type c:\temp\rights.cfg | findstr "SeImpersonate"
   ```
5. Создайте план: какие аккаунты можно лишить SeImpersonatePrivilege без нарушения работы
