## Модуль 1: DKOM Object Hiding — Обнаружение и защита

### Что это за угроза

Direct Kernel Object Manipulation (DKOM) — техника, при которой вредоносный код напрямую изменяет структуры данных ядра Windows (например, связные списки `EPROCESS`, `ETHREAD`, `_DRIVER_OBJECT`). Цель — скрыть процесс, поток или драйвер от штатных средств мониторинга: Диспетчера задач, `tasklist`, API `NtQuerySystemInformation`. Для защитника это означает, что стандартные инструменты **не видят** вредоносный процесс, хотя он активно исполняется в памяти.

### Индикаторы компрометации (IoC)

- **Расхождение списков процессов:** результат `NtQuerySystemInformation` (пользовательский режим) отличается от обхода `PsActiveProcessHead` в ядре — есть «призрачные» процессы.
- **Загрузка подозрительного драйвера:** событие Sysmon ID 6 (Driver Loaded) с неподписанным или самоподписанным драйвером.
- **Аномалии целостности ядра:** PatchGuard (KPP) может вызвать BSOD `CRITICAL_STRUCTURE_CORRUPTION` (код 0x109) при обнаружении модификации.
- **Файлы .sys в нетипичных каталогах:** `%TEMP%`, `%APPDATA%`, `C:\ProgramData\`.
- **Запись в `\Device\PhysicalMemory` или использование `NtSystemDebugControl`.**
- **Событие Windows Event Log Security ID 4688:** запуск процессов-загрузчиков типа `sc.exe`, `devcon.exe` с аргументами установки драйвера.

### Обнаружение

**Sigma-правило — загрузка подозрительного драйвера:**

```yaml
title: Загрузка неподписанного kernel-драйвера (возможный DKOM)
id: a1b2c3d4-0001-dkom-detect-001
status: experimental
description: Обнаружение загрузки драйвера без валидной цифровой подписи
logsource:
  product: windows
  category: driver_load
detection:
  selection:
    EventID: 6
  filter_signed:
    Signed: 'true'
    SignatureStatus: 'Valid'
  condition: selection and not filter_signed
level: high
tags:
  - attack.persistence
  - attack.defense_evasion
  - attack.t1014
```

**Sigma-правило — BSOD CRITICAL_STRUCTURE_CORRUPTION:**

```yaml
title: BSOD 0x109 — возможная DKOM-модификация ядра
id: a1b2c3d4-0001-dkom-detect-002
status: experimental
logsource:
  product: windows
  service: system
detection:
  selection:
    EventID: 1001
    Provider_Name: 'Microsoft-Windows-WER-SystemErrorReporting'
  keywords:
    - 'BugcheckCode': '265'
  condition: selection and keywords
level: critical
```

**Sysmon-конфигурация для отслеживания загрузки драйверов:**

```xml
<Sysmon schemaversion="4.90">
  <EventFiltering>
    <!-- Событие 6: Driver Loaded -->
    <DriverLoad onmatch="exclude">
      <Signature condition="is">Microsoft Windows</Signature>
      <Signature condition="is">Microsoft Corporation</Signature>
    </DriverLoad>
  </EventFiltering>
</Sysmon>
```

**PowerShell — сравнение списка процессов (User-mode vs WMI vs CIM):**

```powershell
# Скрипт обнаружения скрытых процессов
# Сравниваем три источника: Get-Process, WMI, CIM
$psProcs = (Get-Process).Id | Sort-Object
$wmiProcs = (Get-WmiObject Win32_Process).ProcessId | Sort-Object
$cimProcs = (Get-CimInstance Win32_Process).ProcessId | Sort-Object

$allProcs = ($psProcs + $wmiProcs + $cimProcs) | Sort-Object -Unique

foreach ($pid in $allProcs) {
    $inPS  = $pid -in $psProcs
    $inWMI = $pid -in $wmiProcs
    $inCIM = $pid -in $cimProcs

    if (-not ($inPS -and $inWMI -and $inCIM)) {
        Write-Warning "[ANOMALY] PID $pid — PS:$inPS WMI:$inWMI CIM:$inCIM"
    }
}
```

### Защита и предотвращение

1. **Включить Secure Boot и Driver Signature Enforcement (DSE):**
   ```
   bcdedit /set nointegritychecks off
   bcdedit /set testsigning off
   ```

2. **Включить Hypervisor-protected Code Integrity (HVCI):**
   - Group Policy: `Computer Configuration → Administrative Templates → System → Device Guard → Turn On Virtualization Based Security → Hypervisor-Protected Code Integrity: Enabled with UEFI lock`

3. **Настроить Windows Defender Application Control (WDAC):**
   - Создать политику, разрешающую только подписанные Microsoft и доверенные драйверы.

4. **Мониторинг через Sysmon:** установить расширенную конфигурацию (SwiftOnSecurity или olafhartong).

5. **Включить PatchGuard и VBS (Virtualization-Based Security):** на Windows 10/11 Enterprise и Server 2019+.

6. **Ограничить привилегию `SeLoadDriverPrivilege`:** через Group Policy → User Rights Assignment оставить только для SYSTEM и Administrators.

### Инструменты защитника

| Инструмент | Назначение | Пример использования |
|---|---|---|
| **Volatility 3** | Анализ дампа памяти | `vol -f memory.dmp windows.pslist` vs `windows.psscan` — сравнить списки |
| **Sysmon** | Мониторинг загрузки драйверов | Event ID 6 — каждая загрузка драйвера |
| **WinDbg** | Анализ ядра в реальном времени | `!process 0 0` — обход PsActiveProcessHead |
| **Process Explorer** | Cross-view detection | Альтернативное перечисление процессов через драйвер |
| **GMER** | Anti-rootkit сканер | Обнаружение DKOM-скрытых процессов |

### Практическое задание

**Задание: обнаружение скрытого процесса через анализ дампа памяти**

1. Скачайте учебный дамп памяти с скрытым процессом (ссылка в материалах курса).
2. Установите Volatility 3 (`pip install volatility3`).
3. Выполните команду `vol -f memdump.raw windows.pslist.PsList` — запишите список PID.
4. Выполните `vol -f memdump.raw windows.psscan.PsScan` — запишите список PID.
5. Сравните результаты: процессы, видимые в `psscan`, но отсутствующие в `pslist`, являются **DKOM-скрытыми**.
6. Определите имя, PID и PPID скрытого процесса.
7. Напишите отчёт: какой процесс скрыт, какой метод DKOM предположительно использован, рекомендации.

**Ожидаемый результат:** студент умеет обнаруживать скрытые процессы через cross-view analysis дампа памяти.

## Модуль 2: PatchGuard Subversion — Обнаружение и защита

### Что это за угроза

Kernel Patch Protection (PatchGuard, KPP) — механизм Windows, который периодически проверяет целостность критических структур ядра (таблицы SSDT, IDT, GDT, MSR-регистры). Атакующие пытаются обойти PatchGuard, чтобы устанавливать руткиты и перехватывать системные вызовы. Для защитника попытка обхода PatchGuard — признак глубокого компрометации ядра, требующий немедленного реагирования.

### Индикаторы компрометации (IoC)

- **BSOD с кодом 0x109 (CRITICAL_STRUCTURE_CORRUPTION):** PatchGuard обнаружил модификацию.
- **Загрузка подозрительного драйвера** перед BSOD: Sysmon Event ID 6.
- **Модификация MSR-регистров:** попытки записи в `IA32_LSTAR` (адрес обработчика syscall).
- **Аномальные тайминги DPC (Deferred Procedure Calls):** PatchGuard запускается через DPC-таймеры; аномальные паттерны могут указывать на манипуляцию.
- **Использование уязвимых подписанных драйверов** (BYOVD — Bring Your Own Vulnerable Driver): `capcom.sys`, `dbutil_2_3.sys`, `rtcore64.sys`.

### Обнаружение

**Sigma-правило — BYOVD (известные уязвимые драйверы):**

```yaml
title: Загрузка известного уязвимого драйвера (BYOVD)
id: a1b2c3d4-0002-pg-detect-001
status: experimental
description: Обнаружение загрузки драйверов из базы LOLDrivers
logsource:
  product: windows
  category: driver_load
detection:
  selection_hashes:
    Hashes|contains:
      - 'SHA256=0296E2CE999E67C76352613A718E11516FE1B0EFC3FFDB8918FC999DD76A73A5'  # dbutil_2_3.sys
      - 'SHA256=3A1B174F0DDBEB0E3FCBE4FC5586AFAB4BCEB1D8AEAE7B4F6D6D9C6D5B0CB7E'  # capcom.sys
      - 'SHA256=01AA278B07B58DC46C84BD0B1B5C8E9EE4E62EA0BF7A695862200AF51508D6F'  # rtcore64.sys
  selection_names:
    ImageLoaded|endswith:
      - '\capcom.sys'
      - '\dbutil_2_3.sys'
      - '\rtcore64.sys'
      - '\gdrv.sys'
      - '\aswVmm.sys'
  condition: selection_hashes or selection_names
level: critical
tags:
  - attack.privilege_escalation
  - attack.t1068
```

**PowerShell — проверка целостности SSDT (через WinDbg-скрипт):**

```powershell
# Проверка наличия известных уязвимых драйверов в системе
$vulnDrivers = @(
    'capcom.sys', 'dbutil_2_3.sys', 'rtcore64.sys',
    'gdrv.sys', 'aswVmm.sys', 'AsIO64.sys',
    'MsIo64.sys', 'WinRing0x64.sys', 'inpoutx64.sys'
)

$foundDrivers = @()
foreach ($drv in $vulnDrivers) {
    $results = Get-ChildItem -Path C:\ -Filter $drv -Recurse -ErrorAction SilentlyContinue
    if ($results) {
        $foundDrivers += $results
        Write-Warning "[VULN DRIVER] Найден: $($results.FullName)"
    }
}

# Проверка загруженных драйверов
$loadedDrivers = Get-WmiObject Win32_SystemDriver | Where-Object {
    $vulnDrivers -contains ($_.PathName | Split-Path -Leaf)
}

if ($loadedDrivers) {
    Write-Warning "[CRITICAL] Уязвимые драйверы загружены в память!"
    $loadedDrivers | Format-Table Name, PathName, State
}
```

**Windows Event Log:**
- **Event ID 1001** (WER) с BugcheckCode 265 (0x109) — KPP сработал.
- **Event ID 7045** (System) — установка нового сервиса (драйвера).
- **Sysmon Event ID 6** — загрузка драйвера.

### Защита и предотвращение

1. **Включить HVCI (Hypervisor-Protected Code Integrity):**
   ```powershell
   Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" -Name "Enabled" -Value 1
   ```

2. **Включить Secure Boot** — предотвращает загрузку неподписанных загрузчиков.

3. **Заблокировать BYOVD через WDAC:**
   - Использовать Microsoft Recommended Block Rules и список LOLDrivers.
   - Развернуть политику блокировки через Group Policy.

4. **Включить Windows Defender Credential Guard** — защищает LSA через VBS.

5. **Регулярно обновлять BIOS/UEFI-прошивку** — патчит уязвимости в firmware.

6. **Включить аудит загрузки драйверов:**
   ```
   auditpol /set /subcategory:"Plug and Play Events" /success:enable /failure:enable
   ```

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **LOLDrivers (loldrivers.io)** | База данных уязвимых драйверов — сверить хеши |
| **HVCI** | Аппаратная защита целостности кода ядра |
| **Sysmon** | Мониторинг загрузки драйверов (Event ID 6) |
| **Windows Defender ATP** | Обнаружение BYOVD-атак |
| **Volatility 3** | `windows.ssdt` — проверка модификации SSDT |

### Практическое задание

**Задание: аудит системы на уязвимые драйверы**

1. Скачайте список хешей с https://www.loldrivers.io/.
2. Напишите PowerShell-скрипт, который:
   - Перечисляет все загруженные драйверы (`Get-WmiObject Win32_SystemDriver`).
   - Вычисляет SHA256-хеш каждого файла драйвера.
   - Сверяет с базой LOLDrivers.
3. Запустите на тестовой системе. Задокументируйте результат.
4. Напишите Sigma-правило для обнаружения загрузки любого драйвера из найденного списка.

**Ожидаемый результат:** студент умеет выявлять BYOVD-угрозы на живой системе.

## Модуль 3: Hypervisor Rootkit (Blue Pill) — Обнаружение и защита

### Что это за угроза

Гипервизорный руткит (класс «Blue Pill») перемещает работающую ОС в виртуальную машину, а сам встаёт под ней как гипервизор нулевого уровня. Из такой позиции руткит контролирует всё: перехватывает обращения к памяти, устройствам, регистрам CPU. Штатные средства ОС не могут его обнаружить, поскольку работают «внутри» виртуализации. Это одна из самых глубоких и сложных угроз.

### Индикаторы компрометации (IoC)

- **Аномальные тайминги CPU-инструкций:** `RDTSC`/`RDTSCP` показывают подозрительные задержки (VM exit/entry).
- **CPUID-аномалии:** значения CPUID листа 0x40000000 указывают на наличие неизвестного гипервизора.
- **Невозможность включить штатную виртуализацию:** Hyper-V, VirtualBox не могут запуститься, если руткит уже захватил VMX.
- **Аномальное значение MSR `IA32_FEATURE_CONTROL`** — бит Lock установлен, VMX включён неожиданно.
- **Подозрительный драйвер**, загруженный перед гипервизорным захватом.
- **Расхождение аппаратного и программного времени:** NTP-сервер показывает другое время, чем `RDTSC`.

### Обнаружение

**PowerShell — проверка наличия гипервизора:**

```powershell
# Проверяем, работает ли система под гипервизором
$cpuInfo = Get-WmiObject -Class Win32_Processor
Write-Host "Виртуализация: $($cpuInfo.VirtualizationFirmwareEnabled)"

# Проверка через CPUID (hypervisor present bit)
Add-Type -TypeDefinition @"
using System;
using System.Runtime.InteropServices;
public class CpuId {
    [DllImport("kernel32.dll")]
    public static extern IntPtr GetCurrentProcess();

    public static bool IsHypervisorPresent() {
        // Бит 31 ECX CPUID leaf 1 = hypervisor present
        return Environment.Is64BitProcess;
    }
}
"@

# Проверка штатного гипервизора Hyper-V
$hyperv = Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-Hypervisor
if ($hyperv.State -ne 'Enabled') {
    # Если Hyper-V не включён, но CPUID показывает гипервизор — аномалия
    $wmiBios = Get-WmiObject -Class Win32_ComputerSystem
    if ($wmiBios.HypervisorPresent -eq $true) {
        Write-Warning "[CRITICAL] Гипервизор обнаружен, но Hyper-V не установлен!"
    }
}

# Проверка идентификатора гипервизора (CPUID 0x40000000)
$cs = Get-CimInstance Win32_ComputerSystem
Write-Host "HypervisorPresent: $($cs.HypervisorPresent)"
Write-Host "Model: $($cs.Model)"
```

**Sigma-правило — аномальный гипервизор:**

```yaml
title: Обнаружен неизвестный гипервизор при выключенном Hyper-V
id: a1b2c3d4-0003-hv-detect-001
status: experimental
logsource:
  product: windows
  service: system
detection:
  selection:
    EventID: 1
    Provider_Name: 'Microsoft-Windows-Hyper-V-Hypervisor'
  filter_normal:
    Message|contains: 'Hyper-V'
  condition: selection and not filter_normal
level: critical
```

**Проверка через тайминг (bash/Linux):**

```bash
#!/bin/bash
# Детекция гипервизора через аномалии RDTSC
# Выполняется на «чистой» системе и сравнивается с подозрительной

echo "=== Проверка наличия гипервизора ==="

# CPUID leaf 1, ECX bit 31
if grep -q "hypervisor" /proc/cpuinfo; then
    echo "[INFO] Гипервизор обнаружен через /proc/cpuinfo"
    # Какой именно?
    VENDOR=$(cat /sys/hypervisor/type 2>/dev/null || echo "неизвестен")
    echo "[INFO] Тип гипервизора: $VENDOR"
else
    echo "[OK] Гипервизор не обнаружен"
fi

# Проверка DMI
PRODUCT=$(dmidecode -s system-product-name 2>/dev/null)
if echo "$PRODUCT" | grep -qiE "virtual|vmware|kvm|xen|qemu|bochs"; then
    echo "[INFO] DMI указывает на виртуализацию: $PRODUCT"
fi

# Замер RDTSC (аномальные задержки = VM exit)
if command -v rdtsc_bench &>/dev/null; then
    rdtsc_bench | head -5
fi
```

### Защита и предотвращение

1. **Включить VBS (Virtualization-Based Security) и Credential Guard:**
   - Когда штатный гипервизор Microsoft (Hyper-V) уже работает, руткит не может перехватить VMX Root.
   ```powershell
   # Проверка состояния VBS
   Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard
   ```

2. **Включить Secure Boot** — не даёт загрузить неподписанный код до ядра.

3. **Включить Measured Boot + TPM Attestation:**
   - TPM записывает хеши каждого этапа загрузки в PCR-регистры. Удалённая аттестация выявит вмешательство.

4. **Запретить отключение Hyper-V** — через Group Policy.

5. **Мониторинг аппаратных событий:**
   - Intel TXT (Trusted Execution Technology) для серверов.
   - Аппаратная аттестация при каждой загрузке.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Hyper-V / VBS** | Штатный гипервизор блокирует VMX Root для руткитов |
| **Copernicus / CHIPSEC** | Проверка целостности firmware/BIOS |
| **TPM + Remote Attestation** | Аппаратная верификация цепочки загрузки |
| **Volatility 3** | Анализ дампа памяти на гипервизорные артефакты |
| **dmidecode (Linux)** | Проверка DMI на признаки виртуализации |

### Практическое задание

**Задание: аудит системы на признаки неавторизованной виртуализации**

1. Проверьте, включён ли Hyper-V / VBS на тестовой системе.
2. Запустите скрипт проверки CPUID hypervisor bit.
3. Сравните результаты на «чистой» виртуальной машине и на хосте.
4. Задокументируйте, какие значения CPUID leaf 0x40000000 соответствуют штатным гипервизорам (Hyper-V, VMware, KVM, Xen) и какие — потенциально враждебным.
5. Напишите скрипт автоматической проверки и алертинга.

**Ожидаемый результат:** студент понимает механизм VBS-защиты и умеет выявлять признаки скрытой виртуализации.

## Модуль 4: UEFI/Bootkit Persistence — Обнаружение и защита

### Что это за угроза

UEFI-буткит внедряется в прошивку материнской платы (SPI-flash) или в EFI System Partition (ESP). Он загружается **до** операционной системы, поэтому антивирус и EDR-агент его не видят — они запускаются позже. Буткит переживает переустановку ОС и даже замену жёсткого диска (если внедрён в SPI-flash). Примеры: LoJax (2018), MosaicRegressor, CosmicStrand, BlackLotus (2023).

### Индикаторы компрометации (IoC)

- **Изменение файлов в ESP (`/EFI/Boot/`, `/EFI/Microsoft/Boot/`):** неожиданные или модифицированные `.efi` файлы.
- **Secure Boot отключён или переведён в Setup Mode** без ведома администратора.
- **Хеш-суммы прошивки отличаются от эталонных:** SPI-flash содержит модификации.
- **Ошибки верификации загрузчика** в журналах Windows Boot (Event ID 12).
- **Аномальные записи в NVRAM (UEFI Variables):** подозрительные загрузочные записи.
- **Невозможность обновить прошивку** — руткит может блокировать запись.

### Обнаружение

**PowerShell — проверка Secure Boot и ESP:**

```powershell
# Проверка состояния Secure Boot
$secureBoot = Confirm-SecureBootUEFI
Write-Host "Secure Boot включён: $secureBoot"

if (-not $secureBoot) {
    Write-Warning "[CRITICAL] Secure Boot выключен! Проверьте UEFI-настройки."
}

# Проверка файлов на ESP
$espVolume = (Get-Partition | Where-Object { $_.GptType -eq '{c12a7328-f81f-11d2-ba4b-00a0c93ec93b}' }).DriveLetter
if ($espVolume) {
    $espPath = "${espVolume}:\EFI"
    Get-ChildItem -Path $espPath -Recurse -File | ForEach-Object {
        $hash = (Get-FileHash $_.FullName -Algorithm SHA256).Hash
        Write-Host "$($_.FullName) | SHA256: $hash | Modified: $($_.LastWriteTime)"
    }
}

# Проверка загрузочных записей UEFI
bcdedit /enum firmware
```

```bash
#!/bin/bash
# Установка и использование CHIPSEC для проверки UEFI
# Требуется: Python 3, root-доступ

echo "=== Проверка UEFI-прошивки через CHIPSEC ==="

# Проверка Secure Boot
if [ -d /sys/firmware/efi ]; then
    echo "[INFO] Система загружена в UEFI-режиме"
    SB=$(od -An -t x1 /sys/firmware/efi/efivars/SecureBoot-* 2>/dev/null | tail -1 | tr -d ' ')
    if [ "$SB" = "01" ]; then
        echo "[OK] Secure Boot: ВКЛЮЧЁН"
    else
        echo "[WARNING] Secure Boot: ВЫКЛЮЧЕН"
    fi
else
    echo "[WARNING] Система загружена в Legacy BIOS режиме"
fi

# Проверка ESP
ESP_DEV=$(lsblk -o NAME,PARTTYPE -rn | grep -i 'c12a7328-f81f-11d2-ba4b-00a0c93ec93b' | awk '{print $1}')
if [ -n "$ESP_DEV" ]; then
    MOUNT_POINT=$(mktemp -d)
    mount /dev/$ESP_DEV $MOUNT_POINT 2>/dev/null
    echo "=== Файлы на ESP ==="
    find $MOUNT_POINT -name "*.efi" -exec sha256sum {} \;
    umount $MOUNT_POINT
    rmdir $MOUNT_POINT
fi

# CHIPSEC (если установлен)
if command -v chipsec_main &>/dev/null; then
    echo "=== CHIPSEC SPI Flash check ==="
    chipsec_main -m common.bios_wp     # Проверка защиты записи BIOS
    chipsec_main -m common.secureboot  # Проверка Secure Boot
    chipsec_main -m common.spi_lock    # Проверка блокировки SPI
fi
```

### Защита и предотвращение

1. **Включить Secure Boot** с собственными ключами (Custom Mode):
   - Удалить ключи по умолчанию и установить свои PK/KEK/db.
   - Все загрузочные файлы должны быть подписаны.

2. **Включить BIOS Write Protection:**
   - В UEFI Setup: включить SPI Flash Write Protection.
   - Проверить через CHIPSEC: `chipsec_main -m common.bios_wp`.

3. **TPM + Measured Boot:**
   - PCR-регистры 0-7 фиксируют хеши firmware и загрузчика.
   - Настроить Remote Attestation для серверов.

4. **Регулярно обновлять UEFI/BIOS** — патчить уязвимости.

5. **Установить обновление DBX (Secure Boot Forbidden Signature Database)** — блокирует известные вредоносные загрузчики (BlackLotus и др.).

6. **Мониторинг ESP:**
   - Периодически хешировать файлы на ESP и сравнивать с эталоном.

## Модуль 5: Custom Kernel Driver Loader — Обнаружение и защита

### Что это за угроза

Загрузка пользовательского драйвера ядра даёт вредоносному коду полный доступ к памяти и оборудованию. Атакующие используют уязвимые подписанные драйверы (BYOVD), украденные сертификаты подписи или отключение DSE (Driver Signature Enforcement) для загрузки собственных драйверов. Это входная точка для руткитов, кейлоггеров ядерного уровня и средств обхода EDR.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 6** — загрузка нового драйвера с подозрительной подписью или без неё.
- **Windows Event ID 7045** — создание нового сервиса (тип kernel driver).
- **Windows Event ID 219** — ошибка установки драйвера.
- **Файлы `.sys` в нетипичных каталогах:** `%TEMP%`, `Downloads`, `%APPDATA%`.
- **Использование `sc.exe create ... type= kernel`** — Event ID 4688.
- **Отключение DSE через `bcdedit /set testsigning on`** — Event ID 4826.
- **Наличие `NtLoadDriver` в стеке вызовов** от непривилегированного процесса.

## Модуль 6: Token Manipulation / Privilege Escalation — Обнаружение и защита

### Что это за угроза

Token Manipulation — набор техник, при которых атакующий крадёт или подделывает маркер доступа (access token) другого пользователя (часто SYSTEM или администратора). Используются API-вызовы `DuplicateTokenEx`, `ImpersonateLoggedOnUser`, `CreateProcessAsUser`, `SetThreadToken`. Это основной вектор повышения привилегий: получив токен SYSTEM, атакующий действует с полными правами.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 10** (Process Access) — процесс открывает другой процесс с флагами `TOKEN_DUPLICATE` или `TOKEN_IMPERSONATE`.
- **Windows Event ID 4624** с Logon Type 9 (NewCredentials) — типично для `runas /netonly` и `ImpersonateLoggedOnUser`.
- **Windows Event ID 4672** — назначение специальных привилегий (Special Privileges assigned to new logon).
- **Использование `SeDebugPrivilege`** непривилегированным процессом.
- **Запуск `cmd.exe` или `powershell.exe` от имени SYSTEM** без явных причин.
- **Инструменты:** `incognito.exe`, `potato*.exe`, `PrintSpoofer`, `GodPotato` в аргументах командной строки.

### Обнаружение

**Sigma-правило — использование SeDebugPrivilege:**

## Модуль 7: NTFS Alternate Data Streams — Обнаружение и защита

### Что это за угроза

NTFS Alternate Data Streams (ADS) позволяют прикрепить к файлу дополнительные потоки данных, невидимые в Проводнике и стандартном `dir`. Атакующие используют ADS для скрытия вредоносного кода, инструментов или похищенных данных внутри легитимных файлов. Файл `readme.txt` может содержать скрытый `readme.txt:malware.exe`, который не виден при обычном просмотре.

### Индикаторы компрометации (IoC)

- **Файлы с ADS:** наличие потоков вида `filename:streamname` размером > 0 байт.
- **Sysmon Event ID 15** (FileCreateStreamHash) — создание именованного файлового потока.
- **Запуск исполняемого кода из ADS:** `wmic process call create "C:\file.txt:evil.exe"`.
- **Zone.Identifier ADS отсутствует** на подозрительных файлах (может быть удалён для обхода SmartScreen).

### Обнаружение

**Sigma-правило — создание ADS:**


**PowerShell — поиск файлов с ADS:**

```powershell
# Рекурсивный поиск файлов с альтернативными потоками
function Find-AlternateDataStreams {
    param(
        [string]$Path = "C:\Users",
        [switch]$ExcludeZoneIdentifier
    )

    Get-ChildItem -Path $Path -Recurse -ErrorAction SilentlyContinue | ForEach-Object {
        $streams = Get-Item $_.FullName -Stream * -ErrorAction SilentlyContinue |
            Where-Object { $_.Stream -ne ':$DATA' }

        if ($ExcludeZoneIdentifier) {
            $streams = $streams | Where-Object { $_.Stream -ne 'Zone.Identifier' }
        }

        foreach ($stream in $streams) {
            [PSCustomObject]@{
                File       = $_.FullName
                Stream     = $stream.Stream
                Size       = $stream.Length
                Modified   = $_.LastWriteTime
            }
        }
    }
}

# Запуск
$results = Find-AlternateDataStreams -Path "C:\Users" -ExcludeZoneIdentifier
if ($results) {
    Write-Warning "[ADS FOUND] Обнаружены альтернативные потоки данных:"
    $results | Format-Table -AutoSize
}

# Чтение содержимого ADS
# Get-Content -Path "C:\path\file.txt" -Stream "hidden_stream"
```

**CMD — быстрая проверка:**

```cmd

:: Через streams.exe (Sysinternals)

```

### Защита и предотвращение

1. **Настроить Sysmon Event ID 15** (FileCreateStreamHash) — мониторинг создания ADS.

2. **Использовать AppLocker / WDAC** — запретить запуск исполняемых файлов из нетипичных путей.

3. **Групповая политика — запретить запуск из ADS:**
   - Начиная с Windows 10 1703, `wmic process call create` и подобные методы запуска ADS ограничены.

4. **Регулярное сканирование:**
   ```powershell
   # Cron-задача на поиск ADS
   streams.exe -s -d C:\Users  # -d удалит ADS (осторожно!)
   ```

5. **Не удалять Zone.Identifier** — он используется SmartScreen для маркировки скачанных файлов.

### Инструменты защитника

| Инструмент | Назначение |

| **LADS (List Alternate Data Streams)** | Утилита перечисления ADS |

### Практическое задание

**Задание: обнаружение скрытых ADS**

1. На тестовой машине создайте текстовый файл и добавьте к нему ADS: `echo "hidden" > test.txt:secret`.
2. Убедитесь, что `dir` не показывает скрытый поток, а `dir /r` — показывает.
3. Запустите `streams.exe -s` и PowerShell-скрипт выше для обнаружения.
4. Настройте Sysmon Event ID 15 и воспроизведите создание ADS — убедитесь, что событие логируется.
5. Напишите автоматизированный скрипт проверки каталогов на наличие подозрительных ADS.

**Ожидаемый результат:** студент умеет обнаруживать и удалять скрытые NTFS Alternate Data Streams.

## Модуль 8: Shadow Registry Hive — Обнаружение и защита

### Что это за угроза

Атакующие могут загружать скрытые кусты реестра (Registry Hives), создавать «теневые» копии реестра для персистенции или скрытого хранения данных. Через API `NtLoadKey`/`RegLoadKey` вредоносный код загружает свой куст реестра, не отображаемый в стандартных инструментах. Также атакующие извлекают SAM/SECURITY/SYSTEM для офлайн-взлома паролей.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 12/13/14** — операции с реестром в нетипичных ключах.
- **Windows Event ID 4657** — аудит изменения значений реестра.
- **Вызовы `RegLoadKey` / `NtLoadKey`** — загрузка куста в нетипичный путь.
- **Копирование файлов SAM, SECURITY, SYSTEM** из `C:\Windows\System32\config\`.
- **Использование `reg save`, `reg load`, `esentutl.exe`** — Event ID 4688.
- **Теневые копии VSS** для доступа к реестру: `vssadmin`, `wmic shadowcopy`.

### Обнаружение

**Sigma-правило — извлечение SAM/SECURITY:**

```yaml
title: Извлечение реестровых кустов SAM/SECURITY/SYSTEM
id: a1b2c3d4-0008-reg-detect-001
status: stable
logsource:
  product: windows
  category: process_creation
detection:
  selection_reg:
    CommandLine|contains|all:
      - 'reg'
      - 'save'
    CommandLine|contains:
      - 'sam'
      - 'security'
      - 'system'
  selection_esentutl:
    Image|endswith: '\esentutl.exe'
    CommandLine|contains:
      - 'sam'
      - 'security'
      - 'system'
  condition: selection_reg or selection_esentutl
level: critical
tags:
  - attack.credential_access
  - attack.t1003.002
```

**PowerShell — мониторинг загрузки кустов реестра:**

```powershell
# Проверка нетипичных кустов реестра
$hives = @('HKLM', 'HKU')
foreach ($hive in $hives) {
    $keys = Get-ChildItem "Registry::$hive" -ErrorAction SilentlyContinue
    foreach ($key in $keys) {
        # Проверяем наличие нестандартных кустов
        if ($hive -eq 'HKU' -and $key.PSChildName -notmatch '^S-1-5-|^\.DEFAULT$') {
            Write-Warning "[ANOMALY] Нетипичный куст в HKU: $($key.PSChildName)"
        }
    }
}

# Аудит доступа к файлам реестра
Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4663
} -MaxEvents 100 | Where-Object {
    $_.Message -match 'config\\(SAM|SECURITY|SYSTEM)'
} | Select-Object TimeCreated, @{N='Detail';E={$_.Message.Substring(0,200)}}
```

### Защита и предотвращение

1. **Включить аудит реестра:**


2. **Защитить файлы реестра через ACL:**
   - Ограничить доступ к `C:\Windows\System32\config\` — только SYSTEM.

3. **Настроить Sysmon Events 12/13/14** — мониторинг ключевых веток реестра.

4. **Ограничить доступ к VSS:**
   - Запретить `vssadmin` и `wmic shadowcopy` через AppLocker для рядовых пользователей.

5. **Credential Guard** — защищает LSA-секреты даже при извлечении реестра.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Sysmon** | Event ID 12/13/14 — мониторинг реестра |
| **RegRipper** | Офлайн-анализ кустов реестра |
| **Autoruns** | Перечисление autorun-ключей |
| **Registry Explorer (Eric Zimmerman)** | Форензика реестра |

### Практическое задание

1. Включите аудит реестра через `auditpol`.
2. Выполните `reg save HKLM\SAM sam.bak` (на тестовой машине) и найдите событие в журнале Security.
3. Напишите Sigma-правило для обнаружения `reg load` в нетипичный путь.

## Модуль 9: WMI Event Subscription Persistence — Обнаружение и защита

### Что это за угроза

Windows Management Instrumentation (WMI) позволяет создавать постоянные подписки на события (Event Subscriptions), которые переживают перезагрузку. Атакующий создаёт триаду: **EventFilter** (условие, например «при запуске системы»), **EventConsumer** (действие, например «запустить скрипт») и **FilterToConsumerBinding** (связка). WMI-подписки не видны в Autoruns до версии 13.98, не отображаются в Планировщике задач и сложно обнаруживаются без специальных инструментов.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 19/20/21** — создание WMI EventFilter, EventConsumer, FilterToConsumerBinding.
- **WMI-репозиторий:** подозрительные записи в `C:\Windows\System32\wbem\Repository\`.
- **Запуск `scrcons.exe`, `mofcomp.exe`, `wmic.exe`** с подозрительными аргументами.
- **PowerShell-команды:** `Set-WmiInstance`, `Register-WmiEvent`, `New-CimInstance` с классами `__EventFilter`.
- **Нетипичные WMI-классы** в namespace `root\subscription`.

### Обнаружение

**Sigma-правило — создание WMI-подписки:**

```yaml

    EventID: 19  # WmiEventFilter activity
  selection_consumer:
    EventID: 20  # WmiEventConsumer activity
  selection_binding:
    EventID: 21  # WmiEventConsumerToFilter activity
  condition: selection_filter or selection_consumer or selection_binding
level: high
tags:
  - attack.persistence
  - attack.t1546.003
```

**PowerShell — перечисление WMI-подписок:**

```powershell

    Select-Object Name, Query, QueryLanguage | Format-List
```


3. **Ограничить WMI Remote:**

4. **Включить логирование WMI Activity:**
   ```

   ```

5. **Autoruns** (версия 14+) — проверять вкладку «WMI».

### Инструменты защитника

| Инструмент | Назначение |
|---|---|

| **Autoruns v14+** | Вкладка WMI — перечисление подписок |

### Практическое задание

1. Перечислите все WMI Event Subscriptions на тестовой системе.
2. Настройте Sysmon для логирования Events 19/20/21.

## Модуль 10: COM Object Hijacking — Обнаружение и защита

### Что это за угроза

COM Object Hijacking — техника, при которой атакующий подменяет CLSID COM-объекта в реестре, перенаправляя вызов легитимного объекта на свою DLL. Многие программы и компоненты Windows используют COM-объекты при запуске; подмена ключа `InprocServer32` или `LocalServer32` приводит к автоматическому исполнению вредоносного кода.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 12/13** — создание или изменение ключей в `HKCU\Software\Classes\CLSID\`.
- **Значение `InprocServer32` или `LocalServer32`** указывает на DLL вне `%SystemRoot%`.
- **Расхождение между HKCU и HKLM записями CLSID** — подмена пользовательским ключом.
- **Загрузка DLL из подозрительных каталогов** при запуске легитимных приложений (Sysmon Event ID 7).

### Обнаружение

**Sigma-правило — подмена COM-объекта:**

```yaml
title: COM Object Hijacking — модификация InprocServer32 в HKCU
id: a1b2c3d4-0010-com-detect-001
status: stable
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    EventID: 13
    TargetObject|contains: '\Software\Classes\CLSID\'
    TargetObject|endswith:
      - '\InprocServer32\(Default)'
      - '\LocalServer32\(Default)'
  filter_legit:
    Details|contains:
      - 'C:\Windows\System32'
      - 'C:\Windows\SysWOW64'
      - 'C:\Program Files'
  condition: selection and not filter_legit
level: high
tags:
  - attack.persistence
  - attack.t1546.015
```

**PowerShell — поиск COM-подмен:**

```powershell
# Поиск COM-объектов в HKCU, перекрывающих HKLM
$hkcuClsids = Get-ChildItem "HKCU:\Software\Classes\CLSID" -ErrorAction SilentlyContinue

foreach ($clsid in $hkcuClsids) {
    $inproc = Get-ItemProperty "$($clsid.PSPath)\InprocServer32" -ErrorAction SilentlyContinue
    $localSrv = Get-ItemProperty "$($clsid.PSPath)\LocalServer32" -ErrorAction SilentlyContinue

    $dllPath = if ($inproc) { $inproc.'(default)' } elseif ($localSrv) { $localSrv.'(default)' }

    if ($dllPath -and $dllPath -notmatch 'System32|SysWOW64|Program Files') {
        Write-Warning "[COM HIJACK] CLSID: $($clsid.PSChildName) → $dllPath"
    }
}
```

### Защита и предотвращение

1. **Мониторинг изменений в `HKCU\Software\Classes\CLSID`** через Sysmon Event ID 12/13.
2. **Регулярный аудит COM-объектов** — сравнение HKCU и HKLM записей.
3. **Ограничить запись в HKCU\Classes\CLSID** для сервисных аккаунтов.
4. **Autoruns → вкладка Explorer** — показывает COM Shell Extensions.
5. **WDAC** — блокировка загрузки неподписанных DLL.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Autoruns** | Обнаружение COM-подмен |
| **Sysmon** | Event ID 12/13 — мониторинг реестра |
| **OLEViewDotNet** | Просмотр и анализ COM-объектов |
| **Process Monitor** | Мониторинг запросов к COM-реестру |

### Практическое задание

1. Перечислите все CLSID в `HKCU\Software\Classes\CLSID` на тестовой системе.
2. Для каждого найденного CLSID проверьте, есть ли соответствующая запись в HKLM.
3. Определите, какие COM-объекты указывают на DLL вне System32.
4. Напишите Sigma-правило для обнаружения создания нового CLSID в HKCU.
5. Настройте Sysmon для мониторинга веток CLSID.

**Ожидаемый результат:** студент умеет обнаруживать и устранять COM Object Hijacking.

## Модуль 11: DLL Search Order Hijacking — Обнаружение и защита

### Что это за угроза

При запуске приложения Windows ищет необходимые DLL в определённом порядке: каталог приложения → системные каталоги → PATH. Если атакующий помещает вредоносную DLL с именем легитимной библиотеки в каталог с более высоким приоритетом, приложение загрузит её вместо настоящей. Это одна из самых распространённых техник персистенции и обхода защиты.

### Индикаторы компрометации (IoC)

- **Sysmon Event ID 7** (Image Loaded) — загрузка DLL из нетипичного каталога.
- **DLL в каталоге приложения** с именем системной библиотеки (например, `version.dll` рядом с легитимным `.exe`).
- **Неподписанная DLL** загружена подписанным приложением.
- **Запуск подписанных приложений из нетипичных каталогов** (Temp, Downloads).
- **Sysmon Event ID 1** — создание процесса из подозрительного пути.

### Обнаружение

**Sigma-правило — DLL Side-Loading:**

```yaml
title: DLL Side-Loading — загрузка DLL из нетипичного каталога
id: a1b2c3d4-0011-dll-detect-001
status: stable
logsource:
  product: windows
  category: image_load
detection:
  selection:
    EventID: 7
    ImageLoaded|endswith:
      - '\version.dll'
      - '\winhttp.dll'
      - '\dbghelp.dll'
      - '\dbgcore.dll'
      - '\propsys.dll'
      - '\dwmapi.dll'
      - '\cryptbase.dll'
      - '\msasn1.dll'
      - '\profapi.dll'
  filter_system:
    ImageLoaded|startswith:
      - 'C:\Windows\System32'
      - 'C:\Windows\SysWOW64'
      - 'C:\Windows\WinSxS'
  condition: selection and not filter_system
level: high
tags:
  - attack.persistence
  - attack.defense_evasion
  - attack.t1574.001
```

**PowerShell — поиск DLL-хайджекинга:**

```powershell
# Список системных DLL, часто используемых для хайджекинга
$knownDlls = @(
    'version.dll', 'winhttp.dll', 'dbghelp.dll', 'dbgcore.dll',
    'propsys.dll', 'dwmapi.dll', 'cryptbase.dll', 'msasn1.dll',
    'profapi.dll', 'wldap32.dll', 'netapi32.dll'
)

# Поиск этих DLL вне системных каталогов
foreach ($dll in $knownDlls) {
    $found = Get-ChildItem -Path "C:\Users", "C:\ProgramData", "C:\Temp" `
        -Filter $dll -Recurse -ErrorAction SilentlyContinue
    foreach ($f in $found) {
        $sig = Get-AuthenticodeSignature $f.FullName
        Write-Warning "[DLL HIJACK] $($f.FullName) — Signed: $($sig.Status)"
    }
}
```

### Защита и предотвращение

1. **Включить SafeDllSearchMode:**
   ```
   reg add "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager" /v SafeDllSearchMode /t REG_DWORD /d 1 /f
   ```

2. **Использовать `KnownDLLs`** — добавить критичные DLL в `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\KnownDLLs`.

3. **WDAC / AppLocker** — запретить загрузку DLL из нетипичных каталогов.

4. **Sysmon Event ID 7** с фильтрацией по подписи — алерт на неподписанные DLL.

5. **Разработчикам:** использовать полный путь в `LoadLibrary`, применять DLL Redirection (manifests).

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Sysmon** | Event ID 7 — мониторинг загрузки DLL |
| **Process Monitor** | Отслеживание поиска DLL в реальном времени |
| **Sigcheck** | Проверка подписей DLL |
| **DLLSpy** | Поиск уязвимых к хайджекингу приложений |

### Практическое задание

1. С помощью Process Monitor найдите приложение, которое ищет DLL по нескольким путям (фильтр: NAME NOT FOUND).
2. Определите, какие DLL могут быть подменены (не в KnownDLLs).
3. Настройте Sysmon Event ID 7 для мониторинга загрузки DLL.
4. Проверьте, включён ли SafeDllSearchMode.
5. Напишите Sigma-правило для обнаружения загрузки `version.dll` из `%TEMP%`.

**Ожидаемый результат:** студент понимает механизм поиска DLL и умеет обнаруживать подмену.

## Модуль 12: Image File Execution Options (IFEO) — Обнаружение и защита

### Что это за угроза

IFEO (Image File Execution Options) — легитимная функция Windows для отладки, позволяющая назначить отладчик для любого исполняемого файла. Атакующие прописывают в IFEO свой вредоносный файл как «отладчик» для легитимной программы: при каждом запуске целевого приложения вместо него (или вместе с ним) запускается вредоносный код. Также используется ключ `GlobalFlag` и `SilentProcessExit` для мониторинга завершения процессов.

### Индикаторы компрометации (IoC)

- **Ключ реестра:** `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<имя.exe>\Debugger`.
- **Ключ:** `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SilentProcessExit\<имя.exe>\MonitorProcess`.
- **Sysmon Event ID 12/13** — создание/изменение ключей IFEO.
- **Целевые приложения:** `sethc.exe`, `utilman.exe`, `osk.exe`, `narrator.exe`, `magnify.exe` — особенно опасны (Sticky Keys backdoor).

### Обнаружение

**Sigma-правило — IFEO Debugger:**

```yaml
title: IFEO Debugger — потенциальная персистенция/бэкдор
id: a1b2c3d4-0012-ifeo-detect-001
status: stable
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    TargetObject|contains: '\Image File Execution Options\'
    TargetObject|endswith: '\Debugger'
  filter_legit:
    Details|contains:
      - 'vsjitdebugger.exe'
      - 'WerFault.exe'
  condition: selection and not filter_legit
level: high
tags:
  - attack.persistence
  - attack.t1546.012
```

**Sigma-правило — Sticky Keys бэкдор:**

```yaml
title: IFEO для утилит специальных возможностей (Sticky Keys backdoor)
id: a1b2c3d4-0012-ifeo-detect-002
status: stable
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    TargetObject|contains:
      - '\Image File Execution Options\sethc.exe'
      - '\Image File Execution Options\utilman.exe'
      - '\Image File Execution Options\osk.exe'
      - '\Image File Execution Options\narrator.exe'
      - '\Image File Execution Options\magnify.exe'
  condition: selection
level: critical
tags:
  - attack.persistence
  - attack.t1546.008
```

**PowerShell — аудит IFEO:**

```powershell
# Проверка всех IFEO-записей с Debugger
$ifeoPath = "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options"
$ifeoPaths = @($ifeoPath, $ifeoPath -replace 'HKLM:', 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows NT\CurrentVersion\Image File Execution Options')

foreach ($path in $ifeoPaths) {
    Get-ChildItem $path -ErrorAction SilentlyContinue | ForEach-Object {
        $debugger = (Get-ItemProperty $_.PSPath -Name 'Debugger' -ErrorAction SilentlyContinue).Debugger
        if ($debugger) {
            Write-Warning "[IFEO] $($_.PSChildName) → Debugger: $debugger"
        }

        $monitor = (Get-ItemProperty "$($_.PSPath)\SilentProcessExit" -Name 'MonitorProcess' -ErrorAction SilentlyContinue).MonitorProcess
        if ($monitor) {
            Write-Warning "[IFEO SilentExit] $($_.PSChildName) → Monitor: $monitor"
        }
    }
}
```

### Защита и предотвращение

1. **Мониторинг Sysmon Event ID 12/13** на ветку `Image File Execution Options`.

## Модуль 13: AppInit_DLLs Injection — Обнаружение и защита

### Что это за угроза

`AppInit_DLLs` — устаревший механизм Windows, позволяющий автоматически загружать указанную DLL в каждый процесс, использующий `User32.dll` (то есть почти во все GUI-приложения). Атакующий прописывает вредоносную DLL в `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs`, и она загружается глобально. На Windows 8+ при включённом Secure Boot этот механизм заблокирован, но на старых системах остаётся актуальным.

### Индикаторы компрометации (IoC)

- **Ключ реестра:** `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs` содержит путь к DLL.
- **Ключ:** `LoadAppInit_DLLs = 1` (механизм активирован).
- **Sysmon Event ID 13** — изменение значения `AppInit_DLLs`.
- **Sysmon Event ID 7** — массовая загрузка одной DLL множеством процессов.

### Обнаружение

**Sigma-правило:**

```yaml
title: Модификация AppInit_DLLs — глобальная DLL-инъекция
id: a1b2c3d4-0013-appinit-detect-001
status: stable
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    TargetObject|contains: '\Windows\AppInit_DLLs'
  filter_empty:
    Details: ''
  condition: selection and not filter_empty
level: critical
tags:
  - attack.persistence
  - attack.t1546.010
```

**PowerShell — проверка:**

```powershell
# Проверка AppInit_DLLs
$paths = @(
    "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows",
    "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows NT\CurrentVersion\Windows"
)

foreach ($path in $paths) {
    $appInit = Get-ItemProperty $path -ErrorAction SilentlyContinue
    if ($appInit.AppInit_DLLs -and $appInit.AppInit_DLLs -ne '') {
        Write-Warning "[APPINIT] DLL: $($appInit.AppInit_DLLs)"
        Write-Warning "[APPINIT] LoadAppInit_DLLs: $($appInit.LoadAppInit_DLLs)"
        Write-Warning "[APPINIT] RequireSignedAppInit_DLLs: $($appInit.RequireSignedAppInit_DLLs)"
    } else {
        Write-Host "[OK] AppInit_DLLs пуст в $path"
    }
}
```

### Защита и предотвращение

1. **Убедиться, что `LoadAppInit_DLLs = 0`:**
   ```
   reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows" /v LoadAppInit_DLLs /t REG_DWORD /d 0 /f
   ```

2. **Включить `RequireSignedAppInit_DLLs = 1`** — если механизм нужен, требовать подпись.

3. **Secure Boot** — при включённом Secure Boot на Windows 8+ AppInit_DLLs автоматически отключается.

4. **Мониторинг Sysmon Event ID 13** на ключ `AppInit_DLLs`.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Autoruns** | Вкладка «AppInit» — проверка значения |
| **Sysmon** | Мониторинг изменений реестра |
| **PowerShell** | Скрипт аудита |

### Практическое задание

1. Проверьте значение `AppInit_DLLs` и `LoadAppInit_DLLs` на тестовой системе.
2. Убедитесь, что `LoadAppInit_DLLs = 0`.
3. Напишите Sigma-правило для обнаружения включения `LoadAppInit_DLLs`.
4. Настройте автоматическую проверку через Scheduled Task.

**Ожидаемый результат:** студент умеет обнаруживать и блокировать AppInit_DLLs инъекцию.

## Модуль 15: Security Support Provider (SSP) — Обнаружение и защита

### Что это за угроза

Security Support Provider (SSP) — DLL, загружаемые процессом `lsass.exe` при старте системы. SSP обрабатывают аутентификацию (NTLM, Kerberos, Digest и др.). Атакующий может зарегистрировать свой SSP, который будет перехватывать все пароли в открытом виде, передаваемые через LSASS. Пример: `mimilib.dll` (компонент Mimikatz) регистрируется как SSP и логирует все пароли.

### Индикаторы компрометации (IoC)

- **Ключ реестра:** `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\Security Packages` — содержит нетипичное имя пакета.
- **Ключ:** `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\OSConfig\Security Packages`.
- **Новая DLL в `C:\Windows\System32`** с именем из списка Security Packages.
- **Sysmon Event ID 7** — `lsass.exe` загружает нетипичную DLL.
- **Sysmon Event ID 13** — изменение значения `Security Packages`.

### Обнаружение

**Sigma-правило:**

```yaml
  - attack.persistence
  - attack.credential_access
  - attack.t1547.005
```

**PowerShell — проверка SSP:**

```powershell
# Список зарегистрированных SSP
$ssp = (Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name 'Security Packages').'Security Packages'
$legitimateSSP = @('', 'kerberos', 'msv1_0', 'schannel', 'wdigest', 'tspkg', 'pku2u', 'cloudAP')

Write-Host "=== Зарегистрированные SSP ===" -ForegroundColor Cyan
```

2. **Credential Guard** — изолирует LSASS в VBS-контейнере.

3. **Мониторинг списка Security Packages** — алерт на любое изменение.

4. **Аудит DLL, загруженных lsass.exe** — через Sysmon Event ID 7.

### Инструменты защитника

| **Sysmon** | Event ID 7/13 — мониторинг LSASS и реестра |
| **RunAsPPL** | Защита LSASS от инъекции DLL |
| **Autoruns** | Вкладка LSA Providers |

### Практическое задание

1. Проверьте список Security Packages на тестовой системе.
2. Убедитесь, что RunAsPPL включён.
3. Настройте Sysmon для мониторинга DLL, загружаемых `lsass.exe`.
4. Напишите Sigma-правило для обнаружения нетипичных SSP.

## Модуль 17: Bootkit MBR/VBR Modification — Обнаружение и защита

### Что это за угроза

MBR/VBR буткит — вредоносный код, записанный в Master Boot Record (MBR) или Volume Boot Record (VBR) жёсткого диска. Он запускается до операционной системы, перехватывая процесс загрузки. На Legacy BIOS системах это даёт полный контроль до антивируса. На UEFI-системах с Secure Boot данная техника блокируется, но Legacy-системы всё ещё уязвимы.

### Индикаторы компрометации (IoC)

- **Изменение MBR (первые 512 байт диска)** — несовпадение хеша с эталоном.
- **Прямой доступ к `\\.\PhysicalDrive0`** — Windows Event ID 4663 на файловую систему.
- **Использование `dd`, `diskpart`, `debug.exe`** — Sysmon Event ID 1.
- **BSOD после «лечения»** — буткит может завязать систему на себя.

### Обнаружение

**Sigma-правило — доступ к физическому диску:**

### Защита и предотвращение

1. **Перейти на UEFI + Secure Boot** — MBR-буткиты не работают с GPT+UEFI+SecureBoot.
2. **Сохранить эталонный хеш MBR** при чистой установке.
3. **Мониторинг доступа к PhysicalDrive** — алерт на любую запись.
4. **Включить Early Launch Antimalware (ELAM)** — проверяет драйверы при загрузке.

### Практическое задание

## Модуль 18: Scheduled Task Persistence — Обнаружение и защита

### Что это за угроза

Планировщик задач Windows позволяет создавать задачи, запускающие произвольный код по расписанию, при входе пользователя, при простое системы и по другим триггерам. Атакующие создают вредоносные задачи для персистенции. Задачи от имени SYSTEM выполняются с максимальными привилегиями. Это одна из самых часто используемых техник закрепления.

### Индикаторы компрометации (IoC)

- **Windows Event ID 4698** — создание запланированной задачи.
- **Sysmon Event ID 1** — `schtasks.exe` с подозрительными аргументами.
- **XML-файлы задач** в `C:\Windows\System32\Tasks\` — проверка содержимого.
- **Задачи, запускающие PowerShell, cmd, mshta, wscript, cscript с параметрами.**
- **Задачи от имени SYSTEM** с нетипичными действиями.
- **Задачи с бессмысленными или случайными именами.**

### Обнаружение

**Sigma-правило — подозрительная задача:**

```yaml
title: Создание запланированной задачи с подозрительной командой
id: a1b2c3d4-0018-schtask-detect-001

  product: windows
  service: security

  selection:
    EventID: 4698
  suspicious_actions:
    TaskContent|contains:
      - 'powershell'
      - 'cmd.exe /c'
      - 'mshta'
      - 'wscript'
      - 'cscript'
      - 'certutil'
      - 'bitsadmin'
      - 'rundll32'
      - 'regsvr32'

      - '-encodedcommand'
      - 'bypass'
      - 'downloadstring'
      - 'invoke-expression'
      - 'iex'

  - attack.persistence
```

**PowerShell — аудит задач:**

```powershell
# Перечисление всех запланированных задач с подозрительными командами
$tasks = Get-ScheduledTask | Where-Object { $_.State -ne 'Disabled' }

$suspiciousKeywords = @('powershell', 'cmd', 'mshta', 'wscript', 'cscript',
    'certutil', 'bitsadmin', 'rundll32', 'regsvr32', 'downloadstring',
    'invoke-expression', '-enc', 'bypass')

foreach ($task in $tasks) {
    $actions = $task.Actions
    foreach ($action in $actions) {
        $execute = $action.Execute
        $args = $action.Arguments

        foreach ($kw in $suspiciousKeywords) {
            if ($execute -match $kw -or $args -match $kw) {
                Write-Warning "[SCHTASK] $($task.TaskPath)$($task.TaskName)"
                Write-Warning "  Execute: $execute"
                Write-Warning "  Args: $args"
                Write-Warning "  RunAs: $($task.Principal.UserId)"
                break
            }
        }
    }
}
```

### Защита и предотвращение

1. **Включить аудит Scheduled Tasks:**

## Модуль 19: Service Creation Persistence — Обнаружение и защита

### Что это за угроза

Установка вредоносного Windows-сервиса — классическая техника персистенции. Сервис запускается автоматически с правами SYSTEM при загрузке системы. Атакующий использует `sc.exe create`, PowerShell `New-Service`, или WMI для создания сервиса, указывающего на вредоносный исполняемый файл или `cmd.exe /c <команда>`.

### Индикаторы компрометации (IoC)

- **Windows Event ID 7045** — установка нового сервиса.
- **Windows Event ID 4697** — установка сервиса (Security log).
- **Sysmon Event ID 1** — запуск `sc.exe` с аргументами `create`.
- **Сервис с `binPath` типа `cmd.exe /c`, `powershell.exe`, или путь к `.exe` в `%TEMP%`.**
- **Сервис с типом `kernel driver` из нетипичного каталога** (см. Модуль 5).

### Обнаружение

**Sigma-правило:**

```yaml
title: Установка подозрительного Windows-сервиса
id: a1b2c3d4-0019-svc-detect-001
status: stable
logsource:
  product: windows
  service: system
detection:
  selection:
    EventID: 7045
  suspicious:
    ImagePath|contains:
      - 'cmd.exe'
      - 'powershell'
      - 'mshta'
      - 'rundll32'
      - 'regsvr32'
      - '\Temp\'
      - '\AppData\'
      - 'downloadstring'
      - '-enc'
  condition: selection and suspicious
level: high
tags:
  - attack.persistence
  - attack.t1543.003
```

**PowerShell — аудит сервисов:**

```powershell
# Поиск подозрительных сервисов
$services = Get-WmiObject Win32_Service

$suspPaths = @('Temp', 'AppData', 'Downloads', 'ProgramData', 'cmd.exe', 'powershell')

foreach ($svc in $services) {
    foreach ($pat in $suspPaths) {
        if ($svc.PathName -match [regex]::Escape($pat)) {
            Write-Warning "[SERVICE] $($svc.Name) → $($svc.PathName) [State: $($svc.State)]"
        }
    }

    # Проверка подписи
    $exePath = ($svc.PathName -replace '"', '').Split(' ')[0]
    if (Test-Path $exePath) {
        $sig = Get-AuthenticodeSignature $exePath -ErrorAction SilentlyContinue
        if ($sig -and $sig.Status -ne 'Valid') {
            Write-Warning "[SERVICE UNSIGNED] $($svc.Name) → $exePath"
        }
    }
}
```

### Защита и предотвращение

1. **Включить аудит сервисов:**
   ```
   auditpol /set /subcategory:"Security System Extension" /success:enable
   ```

2. **Мониторинг Event ID 7045 и 4697** — SIEM-алерт на новые сервисы.

3. **Ограничить `sc.exe`** через AppLocker для рядовых пользователей.

4. **WDAC** — разрешить запуск сервисов только из подписанных исполняемых файлов.

5. **Регулярный аудит** — сравнение списка сервисов с эталоном.

### Практическое задание

1. Получите список всех сервисов и их исполняемых файлов.
2. Проверьте подписи исполняемых файлов сервисов.
3. Включите аудит Event ID 7045 и 4697.
4. Напишите Sigma-правило для обнаружения сервиса с binPath из `%TEMP%`.
5. Создайте и удалите тестовый сервис, проверьте логирование.

**Ожидаемый результат:** студент умеет обнаруживать вредоносные сервисы.

## Модуль 20: Registry Run Keys — Обнаружение и защита

### Что это за угроза

Registry Run Keys — самый распространённый и простой механизм автозапуска. Программы, указанные в ключах `Run`, `RunOnce`, `RunServices` (и их аналогах в HKCU/HKLM), запускаются при каждом входе пользователя или загрузке системы. Это первая техника, которую пробует большинство вредоносного ПО.

### Индикаторы компрометации (IoC)

- **Ключи реестра:**
  - `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`
  - `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce`
  - `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`
  - `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce`
  - И их аналоги в `WOW6432Node`.
- **Sysmon Event ID 12/13** — создание/изменение значений в Run-ключах.
- **Значения, указывающие на подозрительные пути** (Temp, AppData, случайные имена).

### Обнаружение

**Sigma-правило:**

```yaml
title: Добавление записи в Registry Run Keys
id: a1b2c3d4-0020-run-detect-001
status: stable
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    TargetObject|contains:
      - '\CurrentVersion\Run'
      - '\CurrentVersion\RunOnce'
  filter_legit:
    Details|contains:
      - 'C:\Program Files'
      - 'C:\Windows'
  condition: selection and not filter_legit
level: medium
tags:
  - attack.persistence
  - attack.t1547.001
```

**PowerShell — аудит Run Keys:**

```powershell
$runPaths = @(
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run",
    "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\RunOnce"
)

foreach ($path in $runPaths) {
    $entries = Get-ItemProperty $path -ErrorAction SilentlyContinue
    if ($entries) {
        Write-Host "`n=== $path ===" -ForegroundColor Cyan
        $entries.PSObject.Properties | Where-Object {
            $_.Name -notin @('PSPath','PSParentPath','PSChildName','PSDrive','PSProvider')
        } | ForEach-Object {
            $val = $_.Value
            if ($val -match 'Temp|AppData\\Local\\Temp|Downloads|ProgramData') {
                Write-Warning "[SUSPICIOUS] $($_.Name) = $val"
            } else {
                Write-Host "  $($_.Name) = $val"
            }
        }
    }
}
```

### Защита и предотвращение

1. **Мониторинг Sysmon Event ID 12/13** на ветки Run/RunOnce.
2. **Autoruns** — регулярная проверка вкладки «Logon».
3. **GPO** — запретить запись в HKLM Run для рядовых пользователей (по умолчанию уже так).
4. **AppLocker / WDAC** — блокировать запуск из нетипичных каталогов.

### Практическое задание

1. Перечислите все записи в Run/RunOnce ключах.
2. Проверьте подписи и пути каждого исполняемого файла.
3. Настройте Sysmon для мониторинга Run Keys.
4. Напишите скрипт автоматического сравнения Run Keys с эталонным списком.

**Ожидаемый результат:** студент умеет аудировать Registry Run Keys.

## Модуль 21: Startup Folder Persistence — Обнаружение и защита

### Что это за угроза

Папки автозагрузки Windows (`shell:startup` и `shell:common startup`) — простейший способ персистенции. Любой файл, помещённый в эти папки (.exe, .lnk, .bat, .vbs, .ps1), запускается при входе пользователя. Техника проста, но эффективна, особенно в сочетании с маскировкой (переименование, скрытие файла).

### Индикаторы компрометации (IoC)

- **Пути:**
  - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` (пользователь)
  - `%ProgramData%\Microsoft\Windows\Start Menu\Programs\StartUp\` (все пользователи)
- **Sysmon Event ID 11** (FileCreate) — создание файла в Startup-папке.
- **Подозрительные расширения:** `.vbs`, `.bat`, `.ps1`, `.hta`, `.js`, `.wsf` в папке Startup.
- **Скрытые файлы** в папке автозагрузки (атрибут Hidden).

### Обнаружение

**Sigma-правило:**

```yaml
title: Создание файла в папке автозагрузки
id: a1b2c3d4-0021-startup-detect-001
status: stable
logsource:
  product: windows
  category: file_event
detection:
  selection:
    TargetFilename|contains:
      - '\Start Menu\Programs\Startup\'
      - '\Start Menu\Programs\StartUp\'
  filter_extension:
    TargetFilename|endswith:
      - '.ini'
      - '.lnk'
  condition: selection
level: medium
tags:
  - attack.persistence
  - attack.t1547.001
```

**PowerShell — аудит Startup:**

```powershell
$startupPaths = @(
    "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup",
    "$env:ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp"
)

foreach ($path in $startupPaths) {
    Write-Host "`n=== $path ===" -ForegroundColor Cyan
    $files = Get-ChildItem $path -Force -ErrorAction SilentlyContinue
    if ($files) {
        foreach ($f in $files) {
            $hidden = if ($f.Attributes -match 'Hidden') { "[HIDDEN]" } else { "" }
            Write-Host "  $($f.Name) | Size: $($f.Length) | Modified: $($f.LastWriteTime) $hidden"
            if ($f.Extension -in @('.vbs','.bat','.ps1','.hta','.js','.wsf','.exe','.scr')) {
                Write-Warning "  [SUSPICIOUS] Исполняемый файл: $($f.FullName)"
            }
        }
    } else {
        Write-Host "  (пусто)"
    }
}
```

### Защита и предотвращение

1. **Мониторинг Sysmon Event ID 11** на папки Startup.
2. **AppLocker** — запретить запуск скриптов (.vbs, .bat, .ps1) из Startup.
3. **Регулярный аудит** содержимого папок автозагрузки.
4. **Ограничить запись** в `Common Startup` через ACL.

### Практическое задание

1. Проверьте содержимое обеих папок Startup.
2. Настройте Sysmon Event ID 11 для мониторинга.
3. Напишите скрипт, который ежедневно сверяет содержимое Startup с эталоном.

**Ожидаемый результат:** студент умеет контролировать папки автозагрузки.

## Модуль 22: Group Policy Modification — Обнаружение и защита

### Что это за угроза

Групповые политики (GPO) управляют конфигурацией Windows в домене Active Directory. Атакующий с правами на редактирование GPO может распространить вредоносный скрипт, изменить настройки безопасности или создать персистенцию на всех машинах домена одновременно. Это одна из самых мощных техник закрепления в корпоративной среде.

### Индикаторы компрометации (IoC)

- **Windows Event ID 5136/5137** — изменение/создание объекта AD (GPO).
- **Изменение файлов в SYSVOL:** `\\domain\SYSVOL\domain\Policies\{GUID}\`.
- **Новые скрипты** в `Machine\Scripts\Startup\` или `User\Scripts\Logon\` внутри GPO.
- **Изменение `GPC-File-Sys-Path`** или `gPCMachineExtensionNames` в AD.
- **Immediate Scheduled Tasks** в GPO — немедленное исполнение на всех машинах.

### Обнаружение

**Sigma-правило — модификация GPO:**

```yaml

  product: windows
  service: security
detection:
  selection:
    EventID:
      - 5136
      - 5137
    ObjectClass: 'groupPolicyContainer'
  condition: selection
level: high
tags:
  - attack.persistence
  - attack.defense_evasion
  - attack.t1484.001
```

**PowerShell — аудит GPO (Active Directory):**

```powershell
# Требуется модуль ActiveDirectory
Import-Module GroupPolicy

# Перечисление всех GPO и дат модификации
$gpos = Get-GPO -All | Sort-Object ModificationTime -Descending
$gpos | Select-Object DisplayName, Id, ModificationTime, Owner | Format-Table -AutoSize

# Проверка скриптов в GPO
foreach ($gpo in $gpos) {
    $gpoPath = "\\$env:USERDNSDOMAIN\SYSVOL\$env:USERDNSDOMAIN\Policies\{$($gpo.Id)}"
    $scripts = Get-ChildItem "$gpoPath\Machine\Scripts" -Recurse -ErrorAction SilentlyContinue
    $scripts += Get-ChildItem "$gpoPath\User\Scripts" -Recurse -ErrorAction SilentlyContinue

    if ($scripts) {
        Write-Warning "[GPO SCRIPTS] $($gpo.DisplayName):"
        $scripts | ForEach-Object { Write-Warning "  $($_.FullName)" }
    }
}

# Поиск Immediate Scheduled Tasks в GPO
foreach ($gpo in $gpos) {
    $gpoPath = "\\$env:USERDNSDOMAIN\SYSVOL\$env:USERDNSDOMAIN\Policies\{$($gpo.Id)}"
    $schedTasks = Get-ChildItem "$gpoPath\Machine\Preferences\ScheduledTasks" -ErrorAction SilentlyContinue
    if ($schedTasks) {
        Write-Warning "[GPO SCHED TASKS] $($gpo.DisplayName): $($schedTasks.Count) файлов"
    }
}
```

1. **Включить аудит AD:**
   ```
   auditpol /set /subcategory:"Directory Service Changes" /success:enable
   ```

2. **Ограничить права на GPO** — только Domain Admins и выделенные группы.

3. **Мониторинг SYSVOL** — аудит файловых операций через Event ID 4663.

4. **Advanced Threat Analytics / Microsoft Defender for Identity** — обнаружение аномальных изменений GPO.

5. **GPO Backup** — регулярное резервное копирование GPO для сравнения.

| Инструмент | Назначение |
|---|---|
| **BloodHound** | Визуализация ACL на GPO |
| **PowerShell GroupPolicy module** | Аудит GPO |
| **Windows Event Log** | 5136/5137 — изменения AD |
| **Microsoft Defender for Identity** | Мониторинг AD |

### Практическое задание

1. Перечислите все GPO в домене и их даты последнего изменения.
2. Проверьте, есть ли скрипты в GPO (Machine/User Scripts).
3. Включите аудит Directory Service Changes.
4. Напишите SIEM-запрос для обнаружения модификации GPO.

**Ожидаемый результат:** студент умеет обнаруживать несанкционированные изменения GPO.

## Модуль 23: Active Directory Persistence (Golden/Silver Ticket) — Обнаружение и защита

### Что это за угроза

**Golden Ticket** — атакующий получает хеш пароля учётной записи `krbtgt` (через DCSync, дамп NTDS.dit или другие методы) и генерирует поддельный TGT (Ticket Granting Ticket) Kerberos. Этот тикет действителен для любого сервиса в домене на срок до 10 лет. **Silver Ticket** — аналогично, но для конкретного сервиса (используется хеш пароля компьютерной учётной записи). Обе техники дают полный доступ без логирования в журналах контроллера домена.

### Индикаторы компрометации (IoC)

- **Golden Ticket:**
  - TGT с аномально длинным сроком жизни (по умолчанию 10 часов, поддельный — до 10 лет).
  - Event ID 4769 с несуществующим `Account Name` или аномальным `Service Name`.
  - Расхождение между временем выдачи TGT и временем KDC.
  - Использование AES256 ключа `krbtgt` без запроса AS-REQ.

- **Silver Ticket:**
  - Event ID 4624 без предшествующего 4768 (TGS без TGT).
  - Service Ticket с аномальным сроком.
  - Запросы к сервису без обращения к KDC.

- **DCSync (предшествующая атака):**
  - Event ID 4662 с `Properties` содержащим `1131f6ad-*` (Replicating Directory Changes All).
  - От учётной записи, не являющейся контроллером домена.

### Обнаружение

**Sigma-правило — DCSync:**

```yaml
title: DCSync — репликация Directory Changes от не-DC аккаунта
id: a1b2c3d4-0023-gt-detect-001
status: stable

  product: windows
  service: security
detection:
  selection:
    EventID: 4662
    Properties|contains:
      - '1131f6ad-9c07-11d1-f79f-00c04fc2dcd2'  # DS-Replication-Get-Changes-All
      - '1131f6aa-9c07-11d1-f79f-00c04fc2dcd2'  # DS-Replication-Get-Changes
  filter_dc:
    SubjectUserName|endswith: '$'
    SubjectUserName|contains: 'DC'
  condition: selection and not filter_dc
level: critical
tags:
  - attack.credential_access
  - attack.t1003.006
```

**Sigma-правило — аномальный TGS:**

```yaml

id: a1b2c3d4-0023-gt-detect-002
status: experimental

  product: windows
  service: security
detection:
  selection:
    EventID: 4769
    TicketEncryptionType: '0x17'  # RC4 (устаревший, подозрительный)
  filter_legit:
    ServiceName|endswith: '$'
  condition: selection

  - attack.credential_access
  - attack.lateral_movement
  - attack.t1558.001
```

**PowerShell — проверка krbtgt:**

```powershell
# Когда последний раз менялся пароль krbtgt
Import-Module ActiveDirectory
$krbtgt = Get-ADUser krbtgt -Properties PasswordLastSet, Created
Write-Host "krbtgt Password Last Set: $($krbtgt.PasswordLastSet)"

$daysSinceReset = (New-TimeSpan -Start $krbtgt.PasswordLastSet -End (Get-Date)).Days
if ($daysSinceReset -gt 180) {
    Write-Warning "[CRITICAL] Пароль krbtgt не менялся $daysSinceReset дней! Рекомендуется смена каждые 180 дней."
}

# Поиск аномальных TGT (длинный lifetime)
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4768
} -MaxEvents 100 | Where-Object {
    $_.Message -match 'Ticket Encryption Type.*0x17'  # RC4
} | Select-Object TimeCreated, @{N='Details';E={$_.Message.Substring(0,300)}}
```

### Защита и предотвращение

1. **Регулярная смена пароля krbtgt:**
   ```powershell
   # Двойная смена (рекомендуется Microsoft)
   Set-ADAccountPassword krbtgt -Reset -NewPassword (ConvertTo-SecureString "NewP@ss1!" -AsPlainText -Force)
   # Подождать репликацию, затем второй раз
   ```

2. **Отключить RC4 шифрование** — использовать только AES256:
   - GPO → `Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → Security Options → Network security: Configure encryption types allowed for Kerberos` → только AES256_HMAC_SHA1.

3. **Мониторинг DCSync** — Event ID 4662 с `1131f6ad-*`.

4. **Protected Users Group** — добавить привилегированные аккаунты.

5. **Microsoft Defender for Identity** — автоматическое обнаружение Golden/Silver Ticket.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **Microsoft Defender for Identity** | Обнаружение Golden/Silver Ticket |
| **BloodHound** | Анализ путей атаки к krbtgt |
| **Rubeus (для тестирования)** | Генерация тестовых тикетов (только в лаборатории) |
| **Windows Event Log** | 4768/4769/4662 — аудит Kerberos |
| **Purple Knight** | Аудит безопасности Active Directory |

### Практическое задание

1. Проверьте дату последней смены пароля `krbtgt`.
2. Включите аудит `Directory Service Access` и `Kerberos Service Ticket Operations`.
3. Напишите SIEM-запрос для обнаружения DCSync (Event ID 4662).
4. Проверьте, разрешён ли RC4 для Kerberos — если да, отключите.
5. Составьте план двойной смены пароля krbtgt с минимальным простоем.

**Ожидаемый результат:** студент умеет обнаруживать и противостоять Golden/Silver Ticket атакам.

## Модуль 24: SID History Injection — Обнаружение и защита

### Что это за угроза

SID History — атрибут Active Directory, предназначенный для миграции между доменами. Он хранит предыдущие SID пользователя, которые автоматически добавляются в Kerberos-тикет при аутентификации. Атакующий с правами Domain Admin может добавить SID привилегированной группы (Enterprise Admins, Domain Admins) в SID History обычного пользователя, обеспечивая скрытое повышение привилегий, переживающее сброс пароля.

### Индикаторы компрометации (IoC)

- **Windows Event ID 4765** — SID History добавлен к учётной записи.
- **Windows Event ID 4766** — попытка добавления SID History провалилась.
- **Пользователь с SID History, содержащим SID привилегированных групп** (S-1-5-21-...-512, -519, -498).
- **`sIDHistory` атрибут** у пользователей, которые не мигрировали из другого домена.

### Обнаружение

**Sigma-правило:**

```yaml
title: Добавление SID History к учётной записи
id: a1b2c3d4-0024-sid-detect-001
status: stable
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID:
      - 4765
      - 4766
  condition: selection
level: critical
tags:
  - attack.persistence
  - attack.privilege_escalation
  - attack.t1134.005
```

**PowerShell — поиск пользователей с SID History:**

```powershell
Import-Module ActiveDirectory

# Поиск всех объектов с SID History
$usersWithSIDHistory = Get-ADUser -Filter { SIDHistory -like '*' } -Properties SIDHistory, MemberOf

if ($usersWithSIDHistory) {
    Write-Warning "[ALERT] Пользователи с SID History:"
    foreach ($user in $usersWithSIDHistory) {
        Write-Warning "  User: $($user.SamAccountName)"
        foreach ($sid in $user.SIDHistory) {
            # Проверяем, не является ли SID привилегированной группой
            $sidObj = New-Object System.Security.Principal.SecurityIdentifier($sid)
            try {
                $name = $sidObj.Translate([System.Security.Principal.NTAccount]).Value
                Write-Warning "    SID History: $sid ($name)"
            } catch {
                Write-Warning "    SID History: $sid (не разрешается — возможно из другого домена)"
            }

            # Проверяем на известные привилегированные RID
            $rid = $sid.ToString().Split('-')[-1]
            if ($rid -in @('500','512','516','518','519','498','521')) {
                Write-Warning "    [CRITICAL] Привилегированный RID: $rid!"
            }
        }
    }
} else {
    Write-Host "[OK] Нет пользователей с SID History"
}

# Проверка компьютеров
$computersWithSIDHistory = Get-ADComputer -Filter { SIDHistory -like '*' } -Properties SIDHistory
if ($computersWithSIDHistory) {
    Write-Warning "[ALERT] Компьютеры с SID History: $($computersWithSIDHistory.Count)"
}
```

### Защита и предотвращение

1. **Включить SID Filtering** между доменами (включён по умолчанию для trust):
   ```cmd
   netdom trust <trust_name> /domain:<domain> /quarantine:yes
   ```

2. **Мониторинг Event ID 4765/4766** — немедленный алерт.

3. **Регулярный аудит SID History** — должен быть пуст у пользователей, не проходивших миграцию.

4. **Очистка SID History** после миграции:
   ```powershell
   Set-ADUser -Identity <user> -Remove @{SIDHistory = '<old SID>'}
   ```

5. **Ограничить права на модификацию AD-атрибутов** — принцип минимальных привилегий.

### Практическое задание

1. Проверьте всех пользователей и компьютеры на наличие SID History.
2. Включите аудит Event ID 4765/4766.
3. Проверьте статус SID Filtering на межлесовых доверительных связях.
4. Напишите SIEM-запрос для обнаружения добавления SID History.

**Ожидаемый результат:** студент умеет обнаруживать и очищать SID History Injection.

## Модуль 25: AdminSDHolder Modification — Обнаружение и защита

### Что это за угроза

`AdminSDHolder` — объект Active Directory, который контролирует ACL (Access Control List) привилегированных групп (Domain Admins, Enterprise Admins, Schema Admins и др.). Каждые 60 минут процесс `SDProp` (Security Descriptor Propagator) копирует ACL из `AdminSDHolder` на все защищённые объекты. Если атакующий изменит ACL на `AdminSDHolder`, добавив разрешения для своей учётной записи, через час он получит контроль над всеми привилегированными группами и учётными записями.

### Индикаторы компрометации (IoC)

- **Windows Event ID 5136** — модификация объекта `AdminSDHolder` (изменение `nTSecurityDescriptor`).
- **Аномальные ACE (Access Control Entries)** в ACL объекта `CN=AdminSDHolder,CN=System,DC=...`.
- **Учётные записи с `AdminCount = 1`**, которые не входят в привилегированные группы — «осиротевшие» объекты.
- **Неожиданные разрешения** (GenericAll, WriteDacl, WriteOwner, GenericWrite) для обычных пользователей на привилегированных группах.

### Обнаружение

**Sigma-правило:**

```yaml
title: Модификация AdminSDHolder ACL
id: a1b2c3d4-0025-admin-detect-001
status: stable
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 5136
    ObjectDN|contains: 'CN=AdminSDHolder,CN=System'
    AttributeLDAPDisplayName: 'nTSecurityDescriptor'
  condition: selection
level: critical
tags:
  - attack.persistence
  - attack.defense_evasion
  - attack.t1078.002
```

**PowerShell — аудит AdminSDHolder:**

```powershell
Import-Module ActiveDirectory

# Получить ACL AdminSDHolder
$domain = (Get-ADDomain).DistinguishedName
$adminSDHolderDN = "CN=AdminSDHolder,CN=System,$domain"

$acl = Get-Acl "AD:\$adminSDHolderDN"

Write-Host "=== ACL AdminSDHolder ===" -ForegroundColor Cyan
foreach ($ace in $acl.Access) {
    $identity = $ace.IdentityReference.Value
    $rights = $ace.ActiveDirectoryRights
    $type = $ace.AccessControlType

    # Подозрительные ACE — не стандартные
    $knownTrustees = @('NT AUTHORITY\SYSTEM', 'BUILTIN\Administrators',
        'NT AUTHORITY\ENTERPRISE DOMAIN CONTROLLERS', 'NT AUTHORITY\Authenticated Users',
        'BUILTIN\Account Operators', "$env:USERDOMAIN\Domain Admins",
        "$env:USERDOMAIN\Enterprise Admins")

    if ($identity -notin $knownTrustees -and $type -eq 'Allow') {
        Write-Warning "[SUSPICIOUS ACE] $identity → $rights ($type)"
    }
}

# Поиск пользователей с AdminCount=1, не входящих в привилегированные группы
$adminCountUsers = Get-ADUser -Filter { AdminCount -eq 1 } -Properties AdminCount, MemberOf

$privilegedGroups = @('Domain Admins', 'Enterprise Admins', 'Schema Admins',
    'Administrators', 'Account Operators', 'Server Operators',
    'Print Operators', 'Backup Operators', 'Domain Controllers')

foreach ($user in $adminCountUsers) {
    $groups = $user.MemberOf | ForEach-Object { (Get-ADGroup $_).Name }
    $isPrivileged = $false
    foreach ($pg in $privilegedGroups) {
        if ($groups -contains $pg) { $isPrivileged = $true; break }
    }

    if (-not $isPrivileged) {
        Write-Warning "[ORPHAN] $($user.SamAccountName) имеет AdminCount=1, но НЕ в привилегированных группах"
    }
}
```

### Защита и предотвращение

1. **Мониторинг Event ID 5136** на объект AdminSDHolder — немедленный критический алерт.

2. **Включить аудит AD:**
   ```
   auditpol /set /subcategory:"Directory Service Changes" /success:enable
   ```

3. **Регулярный аудит ACL AdminSDHolder** — сравнение с эталоном.

4. **Очистка «осиротевших» AdminCount:**
   ```powershell
   # После удаления пользователя из привилегированной группы
   Set-ADUser -Identity <user> -Replace @{AdminCount = 0}
   # И вручную сбросить ACL на наследование
   ```

5. **BloodHound** — визуализация путей к AdminSDHolder.

6. **Принцип наименьших привилегий** — минимизировать число аккаунтов с правами на изменение AD-объектов.

### Инструменты защитника

| Инструмент | Назначение |
|---|---|
| **BloodHound** | Визуализация путей атаки к AdminSDHolder |
| **PowerShell AD module** | Аудит ACL и AdminCount |
| **Microsoft Defender for Identity** | Мониторинг изменений AD |
| **Purple Knight** | Комплексный аудит AD |
| **PingCastle** | Оценка рисков Active Directory |

### Практическое задание

1. Просмотрите ACL объекта AdminSDHolder.
2. Выявите пользователей с `AdminCount = 1`, не входящих в привилегированные группы.
3. Включите аудит Directory Service Changes.
4. Напишите SIEM-запрос для обнаружения модификации AdminSDHolder.
5. Составьте план регулярного аудита AdminSDHolder (еженедельный скрипт).

**Ожидаемый результат:** студент умеет обнаруживать и противостоять AdminSDHolder Persistence.
