# МАТРИЦА ТРЁХСЛОЙНОЙ ЗАЩИТЫ: 100 МОДУЛЕЙ

> Каждая атака — 3 слоя обороны. Ни одна техника не пройдёт все три.
> **Концепция:** Defense-in-Depth (эшелонированная оборона)
> **Позиционирование:** Blue Team / SOC / DFIR / Purple Team
> **Формат:** Превенция → Детекция → Реагирование

---

## Как читать матрицу

| Слой | Когда | Цель | Пример |
|------|-------|------|--------|
| 🛡️ **Превенция** | До атаки | Сделать атаку невозможной | Отключить макросы, заблокировать порт, белый список |
| 🔍 **Детекция** | Во время атаки | Обнаружить и поднять алерт | Sigma-правило, Sysmon-триггер, IDS-сигнатура |
| ⚡ **Реагирование** | После обнаружения | Изолировать, нейтрализовать, восстановить | Kill process, isolate host, block IP, forensic |

### Принцип эшелонированной обороны

```
Атакующий
    │
    ▼
┌─────────────────────────┐
│  🛡️ ПРЕВЕНЦИЯ            │  ← Hardening, политики, конфигурация
│  Цель: не дать начать    │
└─────────┬───────────────┘
          │ (если прорвался)
          ▼
┌─────────────────────────┐

│  Цель: заметить          │

          │ (если обнаружен)
          ▼

│  Цель: остановить        │
```

# ГРУППА A: PERSISTENCE & KERNEL (Модули 1–25)

> Техники закрепления в системе и атаки уровня ядра. Наиболее опасные — требуют глубокой защиты.

---

### Модуль 1: DKOM Object Hiding

**Угроза:** Прямая манипуляция объектами ядра (Direct Kernel Object Manipulation) для сокрытия процессов, драйверов и сетевых соединений от утилит пользовательского режима.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Включить Secure Boot + HVCI; запретить загрузку неподписанных драйверов через WDAC | Device Guard, bcdedit, WDAC | `bcdedit /set hypervisorlaunchtype auto` + `bcdedit /set loadoptions DISABLE-LSA-ISO,DISABLE-VBS` — **не применять**, наоборот: включить VBS |
| 🛡️ Превенция | Политика целостности кода: только подписанные Microsoft/WHQL драйверы | WDAC Code Integrity Policy | `New-CIPolicy -Level Publisher -FilePath policy.xml` |
| 🔍 Детекция | Мониторинг загрузки драйверов: Sysmon EID 6 (Driver Loaded) — алерт на неподписанные | Sysmon, SIEM | `Sigma: win_sysmon_driver_load_unsigned` — `EventID: 6`, фильтр `Signed: false` |
| 🔍 Детекция | Периодическое сравнение списка процессов: userland (tasklist) vs kernel (Volatility psxview) | Volatility, PowerShell | `vol.py -f mem.raw windows.pslist` vs `vol.py -f mem.raw windows.psscan` — расхождения = скрытые процессы |
| ⚡ Реагирование | Снять дамп памяти → анализ Volatility → изолировать хост через EDR → откатить до чистого образа | Volatility 3, MDE/CrowdStrike | `vol.py -f dump.raw windows.driverscan` + EDR: `Isolate-Host -ComputerName TARGET` |
| ⚡ Реагирование | Заблокировать хеш вредоносного драйвера в WDAC-политике, распространить через GPO | WDAC, GPO | `Add-SignerRule -FilePath policy.xml -CertificatePath mal_driver.cer -Deny` |

### Модуль 2: PatchGuard Subversion

**Угроза:** Обход Windows Kernel Patch Protection (PatchGuard / KPP) для модификации критических структур ядра — таблиц SSDT, IDT, GDT.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Включить VBS (Virtualization-Based Security) и HVCI — гиперконтролёр запрещает модификацию ядра | Hyper-V, Device Guard | GPO: `Computer Configuration → Admin Templates → System → Device Guard → Turn On VBS: Enabled with UEFI Lock` |
| 🛡️ Превенция | Обязательная подпись драйверов + Secure Boot | UEFI Settings, bcdedit | `bcdedit /set testsigning off` + Secure Boot: Enabled в BIOS |
| 🔍 Детекция | Мониторинг BugCheck (BSOD) с кодами PatchGuard: 0x109 (CRITICAL_STRUCTURE_CORRUPTION) | Windows Event Log, SIEM | EID 1001 (BugCheck) в `System` log, фильтр: `BugcheckCode = 0x00000109` |
| 🔍 Детекция | Аудит загрузки драйверов ядра + проверка цифровых подписей | Sysmon EID 6, Sigcheck | `sigcheck64.exe -e -u C:\Windows\System32\drivers\*` — флаг `-u` показывает неподписанные |
| ⚡ Реагирование | При BSOD 0x109: снять crashdump → анализ WinDbg → определить вредоносный драйвер → заблокировать | WinDbg, Volatility | `!analyze -v` в WinDbg → найти виновный модуль → `lm` для списка драйверов |
| ⚡ Реагирование | Удалить вредоносный драйвер из автозагрузки, обновить WDAC-политику | sc.exe, WDAC | `sc delete MalDriver` + обновить CI-политику |

### Модуль 3: Hypervisor Rootkit (Blue Pill)

**Угроза:** Руткит уровня гипервизора — перехватывает управление CPU через аппаратную виртуализацию (Intel VT-x / AMD-V), размещаясь «под» ОС.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Включить VBS — Windows сама использует гипервизор, блокируя установку стороннего | Hyper-V / VBS | GPO: `Device Guard → Turn On VBS` с UEFI Lock — после этого сторонний гипервизор не встанет |
| 🛡️ Превенция | Secure Boot + Measured Boot (TPM) — цепочка доверия от прошивки до ядра | TPM 2.0, UEFI | BIOS: Secure Boot = Enabled, TPM = Enabled; Windows: `tpm.msc` → проверить статус |
| 🔍 Детекция | Мониторинг аномалий производительности: гипервизор-руткит добавляет задержку на VM-exit | Performance Monitor, специализированные тесты | Тест тайминга `CPUID` / `RDTSC` — аномально высокие значения указывают на вложенную виртуализацию |
| 🔍 Детекция | Проверка Measured Boot log через TPM PCR (Platform Configuration Registers) | TPM, Windows Event Log | EID 12 в `Microsoft-Windows-Measured-Boot` — изменение PCR значений = компрометация цепочки загрузки |
| ⚡ Реагирование | Полная переустановка ОС с верифицированного носителя; обновление прошивки UEFI | Установочный USB, UEFI update | Руткит уровня гипервизора не лечится — только пересборка + проверка прошивки |
| ⚡ Реагирование | Форензика: снять дамп физической памяти до перезагрузки → анализ гипервизорных структур | AVML (Linux) / WinPmem | `winpmem_mini.exe memdump.raw` → Volatility: поиск аномальных VMX-структур |

### Модуль 4: UEFI/Bootkit Persistence

**Угроза:** Запись вредоносного кода в UEFI-прошивку или EFI System Partition — выживает переустановку ОС и замену диска.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Secure Boot в режиме «полный» (не just «совместимый»), запрет загрузки неподписанных EFI | UEFI Settings | BIOS: Secure Boot = Enabled, Mode = Standard (не Custom без ключей) |
| 🛡️ Превенция | Защита SPI Flash от записи (BIOS write protection), обновление BIOS только с подписью вендора | BIOS Settings, CHIPSEC | `chipsec_main.py -m common.bios_wp` — проверка, включена ли защита записи BIOS |
| 🔍 Детекция | Сканирование EFI System Partition: сравнение хешей EFI-файлов с эталонами | PowerShell, UEFI scanner | `Get-FileHash "X:\EFI\Boot\bootx64.efi"` — сравнить с хешем от Microsoft/вендора |
| 🔍 Детекция | Measured Boot + Remote Attestation: TPM фиксирует хеши загрузочной цепочки | TPM, Windows HGS | EID в `Microsoft-Windows-Measured-Boot/Operational` — отклонение PCR = модификация загрузчика |
| ⚡ Реагирование | Перепрошивка UEFI с чистого образа от вендора; замена диска (ESP) | UEFI Flash tool | Скачать прошивку с сайта производителя → прошить через утилиту вендора (не через ОС, если скомпрометирована) |
| ⚡ Реагирование | Форензика: экстракция и анализ SPI-flash дампа | CHIPSEC, UEFITool | `chipsec_util.py spi dump rom.bin` → анализ в UEFITool: поиск неизвестных DXE-модулей |

### Модуль 5: Custom Kernel Driver Loader

**Угроза:** Загрузка вредоносного драйвера ядра через уязвимые подписанные драйверы (BYOVD — Bring Your Own Vulnerable Driver) или через эксплуатацию механизма загрузки.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Блокировка известных уязвимых драйверов через Microsoft Vulnerable Driver Blocklist | WDAC, Windows Update | GPO: `Computer Config → Admin Templates → System → Device Installation → Block listed drivers` + обновлять blocklist |
| 🛡️ Превенция | HVCI — гипервизор проверяет целостность кода в ядре в runtime | Device Guard | `Set-ProcessMitigation -System -Enable CFG, HVCI` |
| 🔍 Детекция | Sysmon EID 6 (Driver Loaded) — алерт на любой драйвер вне белого списка | Sysmon, SIEM (Sigma) | Sigma: `title: Vulnerable Driver Load; logsource: sysmon; EventID: 6; filter: ImageLoaded contains known_vuln_drivers_list` |
| 🔍 Детекция | Мониторинг создания сервисов типа `kernel driver` (sc create type= kernel) | Security Log EID 4697, Sysmon EID 13 | `Sigma: win_security_service_install_kernel` |
| ⚡ Реагирование | Остановить и удалить вредоносный сервис/драйвер; заблокировать хеш в WDAC | sc.exe, WDAC | `sc stop MalSvc & sc delete MalSvc` + добавить хеш в deny-политику WDAC |
| ⚡ Реагирование | Проверить все загруженные драйверы на подписи | Sigcheck, Autoruns | `sigcheck64.exe -vt -e C:\Windows\System32\drivers\` — `-vt` проверяет на VirusTotal |

### Модуль 6: Token Manipulation / Privilege Escalation

**Угроза:** Кража или создание токенов безопасности Windows для повышения привилегий — имперсонация, дубликация токенов, SeDebugPrivilege.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Убрать SeDebugPrivilege у всех, кроме SYSTEM; ограничить SeImpersonatePrivilege | GPO: User Rights Assignment | `Computer Config → Windows Settings → Security Settings → Local Policies → User Rights Assignment → Debug programs: пусто` |
| 🛡️ Превенция | Включить UAC на максимальный уровень, отключить авто-повышение для администраторов | GPO | `Admin Approval Mode = Enabled; Behavior of elevation prompt = Prompt for credentials` |
| 🔍 Детекция | Мониторинг Security Log EID 4672 (Special Privileges Assigned) — аномальные привилегии | SIEM, Sigma | `Sigma: win_security_special_privileges_logon` — алерт если SeDebugPrivilege у не-SYSTEM |
| 🔍 Детекция | Sysmon EID 10 (Process Access) с правами TOKEN_DUPLICATE / TOKEN_IMPERSONATE | Sysmon | `EventID: 10, GrantedAccess: 0x0040 (TOKEN_DUPLICATE)` — access к lsass.exe / winlogon.exe |
| ⚡ Реагирование | Завершить процесс, выполнивший манипуляцию; сбросить пароли затронутых учёток | EDR, Active Directory | `taskkill /F /PID <PID>` + `Set-ADAccountPassword -Identity compromised_user -Reset` |
| ⚡ Реагирование | Ревокация всех Kerberos-тикетов пользователя; принудительная смена пароля krbtgt (если domain admin скомпрометирован) | AD PowerShell | `klist -li 0x3e7 purge` (на хосте) + `Reset-KrbtgtAccountPassword` (если масштабная компрометация) |

### Модуль 7: NTFS Alternate Data Streams

**Угроза:** Сокрытие данных и малвари в альтернативных потоках данных NTFS (ADS) — невидимы для стандартных инструментов.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Аудит ADS через политику: GPO + включить аудит файловой системы | GPO, SACL | `auditpol /set /subcategory:"File System" /success:enable /failure:enable` |
| 🛡️ Превенция | AppLocker/WDAC — запуск только из разрешённых путей, ADS не в белом списке | AppLocker | `New-AppLockerPolicy -RuleType Path -Allow "%WINDIR%\*"` — ADS из temp не пройдёт |
| 🔍 Детекция | Сканирование файловых систем на наличие ADS | PowerShell, streams.exe (Sysinternals) | `Get-ChildItem -Recurse -Path C:\ | ForEach-Object { Get-Item $_.FullName -Stream * }` или `streams64.exe -s C:\` |
| 🔍 Детекция | Sysmon EID 15 (FileCreateStreamHash) — логирование создания ADS | Sysmon | Sysmon config: `<FileCreateStreamHash onmatch="exclude">` (логировать всё) → Sigma: `win_sysmon_ads_creation` |
| ⚡ Реагирование | Удалить вредоносный ADS; скопировать файл без ADS на другую ФС | PowerShell, Sysinternals | `Remove-Item -Path "C:\file.txt:hidden_stream" -Stream hidden_stream` или `streams64.exe -d C:\file.txt` |
| ⚡ Реагирование | Проверить все файлы в директории пользователя на ADS → отчёт | PowerShell | `Get-ChildItem -Recurse -Path C:\Users\ | Get-Item -Stream * | Where-Object { $_.Stream -ne ':$DATA' }` |

### Модуль 8: Shadow Registry Hive

**Угроза:** Создание скрытых кустов реестра или манипуляция с транзакционным реестром (TxR) для сокрытия конфигурации малвари.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Ограничить права на загрузку кустов реестра (RegLoadKey) — только SYSTEM и администраторы | GPO, Registry ACL | Убедиться: `HKLM\SYSTEM` — Full Control только SYSTEM; администраторы — Read |
| 🛡️ Превенция | Мониторинг целостности реестра через FIM (File Integrity Monitoring) | OSSEC/Wazuh, Tripwire | Wazuh: `<directories check_all="yes">HKLM\SOFTWARE</directories>` в syscheck |
| 🔍 Детекция | Sysmon EID 12/13/14 (Registry Create/Set/Rename) на подозрительные пути | Sysmon, SIEM | Sigma: `win_sysmon_registry_persistence` — мониторинг ключей автозагрузки + нестандартных кустов |
| 🔍 Детекция | Поиск несмонтированных кустов реестра на диске | Autoruns, Registry Explorer | `reg query HKLM\SYSTEM\CurrentControlSet\Control\hivelist` — сравнить с файлами в `\System32\config\` |
| ⚡ Реагирование | Экспорт подозрительных ключей → анализ → очистка | reg.exe, Registry Explorer | `reg export HKLM\SOFTWARE\MalKey export.reg` → анализ → `reg delete HKLM\SOFTWARE\MalKey /f` |
| ⚡ Реагирование | Форензика транзакционного реестра: анализ .TM/.TxR файлов | Registry Transaction Logs parser | Парсинг `%SystemRoot%\System32\config\TxR\` — поиск скрытых транзакций |

### Модуль 9: WMI Event Subscription Persistence

**Угроза:** Закрепление через подписки на WMI-события — EventFilter + EventConsumer + FilterToConsumerBinding выполняют код при наступлении условия.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Ограничить доступ к WMI namespace: только администраторы | WMI Control (wmimgmt.msc) | `wmimgmt.msc → Properties → Security → Root → ограничить Remote Enable` для непривилегированных |
| 🛡️ Превенция | Отключить WMI service на рабочих станциях, если не используется (агрессивно) | GPO, sc.exe | `sc config winmgmt start= disabled` — **осторожно**: ломает SCCM и другие средства управления |
| 🔍 Детекция | Sysmon EID 19/20/21 (WMI Event) — создание фильтров, потребителей и привязок | Sysmon, SIEM | Sigma: `win_wmi_persistence` — `EventID: 19 OR 20 OR 21` |
| 🔍 Детекция | Периодический аудит активных WMI-подписок | PowerShell | `Get-WMIObject -Namespace root\Subscription -Class __EventFilter` + `__EventConsumer` + `__FilterToConsumerBinding` |
| ⚡ Реагирование | Удалить вредоносную подписку | PowerShell (WMI) | `Get-WMIObject -Namespace root\Subscription -Class __EventFilter -Filter "Name='MalFilter'" | Remove-WMIObject` |
| ⚡ Реагирование | Перестроить WMI-репозиторий, если повреждён | winmgmt.exe | `winmgmt /resetrepository` — **крайний случай**, сбрасывает все WMI-данные |

### Модуль 10: COM Object Hijacking

**Угроза:** Перехват COM-объектов через подмену CLSID в реестре — вредоносная DLL загружается вместо легитимной при вызове COM.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Мониторинг и защита ключей CLSID в `HKCU\Software\Classes\CLSID\` — они приоритетнее HKLM | Registry ACL, GPO | Аудит записи в `HKCU\...\CLSID` через SACL |
| 🛡️ Превенция | Application Whitelisting — разрешить загрузку DLL только из доверенных директорий | AppLocker (DLL rules), WDAC | AppLocker: `Executable Rules + DLL Rules` — включить DLL enforcement |
| 🔍 Детекция | Sysmon EID 12/13 — создание/модификация ключей в `CLSID` | Sysmon, SIEM | Sigma: `win_com_hijack_registry` — `TargetObject contains "Classes\CLSID"` + нестандартный `InprocServer32` |
| 🔍 Детекция | Сравнение HKCU\CLSID vs HKLM\CLSID — пересечения указывают на hijack | PowerShell | Script: перечислить все CLSID из HKCU, проверить наличие в HKLM — совпадения = подозрительно |
| ⚡ Реагирование | Удалить подменённый CLSID из HKCU, заблокировать хеш DLL | reg.exe, WDAC | `reg delete "HKCU\Software\Classes\CLSID\{MAL-GUID}" /f` |
| ⚡ Реагирование | Проверить, какие процессы загрузили вредоносную DLL | Process Explorer, Sysmon EID 7 | Process Explorer: `View → Lower Pane View → DLLs` → поиск подозрительных путей |

### Модуль 11: DLL Search Order Hijacking

**Угроза:** Размещение вредоносной DLL в директории, из которой приложение загружает библиотеки раньше, чем из системной (эксплуатация порядка поиска DLL).

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Включить SafeDllSearchMode (по умолчанию включён, убедиться что не отключён) | Registry | `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\SafeDllSearchMode = 1` |
| 🛡️ Превенция | Установить корректные ACL на директории приложений — запрет записи для обычных пользователей | NTFS ACL | `icacls "C:\Program Files\App" /remove:g Users:(W)` — убрать запись для Users |
| 🔍 Детекция | Sysmon EID 7 (Image Loaded) — DLL загружена из нестандартного пути | Sysmon, SIEM | Sigma: `win_sysmon_dll_load_from_suspicious_path` — `ImageLoaded NOT startswith "C:\Windows\System32"` для системных DLL |
| 🔍 Детекция | Аудит создания DLL в директориях приложений | Sysmon EID 11 (File Create) | `EventID: 11, TargetFilename endswith ".dll", TargetFilename contains "Program Files"` |
| ⚡ Реагирование | Удалить подложную DLL, проверить целостность приложения | SFC, PowerShell | `Remove-Item "C:\App\evil.dll"` + `sfc /scannow` для системных файлов |
| ⚡ Реагирование | Идентифицировать все приложения, загрузившие DLL через Process Monitor | ProcMon (Sysinternals) | Фильтр: `Operation = CreateFile, Path contains .dll, Result = SUCCESS` — найти нелегитимные загрузки |

### Модуль 12: Image File Execution Options (IFEO)

**Угроза:** Использование ключей реестра IFEO для перехвата запуска программ — debugger-redirect, GlobalFlag, SilentProcessExit.

| Слой | Действие | Инструмент | Команда / правило |

### Модуль 75: Domain Generation Algorithm (DGA)

**Угроза:** Малварь генерирует псевдослучайные доменные имена алгоритмически — атакующий регистрирует нужные заранее, защитник не может заблокировать все.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Белый список DNS: разрешить только known-good домены (агрессивно, но эффективно) | DNS firewall | Proxy: allow only categorized domains; block uncategorized |
| 🛡️ Превенция | Новые домены < 30 дней — блокировать или требовать ручное одобрение | Threat Intel, Proxy | `domain_age < 30d → block OR warn` |
| 🔍 Детекция | ML-модели: анализ энтропии и n-gram доменного имени | DGA detection models, Zeek | Zeek + ML: `entropy(domain) > threshold AND n-gram_score < threshold → DGA` |
| 🔍 Детекция | Множественные NXDOMAIN = DGA-домены, которые не были зарегистрированы | DNS logs, SIEM | `dns.response_code = NXDOMAIN AND source_ip = X AND count > 100/5m → DGA` |
| ⚡ Реагирование | Заблокировать source IP (заражённый хост); изолировать | EDR, Firewall | EDR isolate + DNS sinkhole для найденных DGA-доменов |
| ⚡ Реагирование | Реверс DGA-алгоритма → предсказать будущие домены → заблокировать превентивно | Reverse engineering | Извлечь seed/algorithm → сгенерировать список на месяц вперёд → sinkhole |

### Модуль 76: Pass-the-Hash

**Угроза:** Использование NTLM-хеша пароля (без знания самого пароля) для аутентификации на удалённых системах.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | LAPS (Local Administrator Password Solution) — уникальный пароль администратора на каждой машине | LAPS, AD | `Install-Module LAPS; Initialize-AdmsServiceAccount` → уникальный пароль на каждый ПК |
| 🛡️ Превенция | Отключить NTLM где возможно, использовать только Kerberos | GPO | `Network security: Restrict NTLM: Outgoing NTLM traffic = Deny all` |
| 🔍 Детекция | EID 4624 LogonType 3 (Network) с NTLM auth от нестандартных источников | SIEM, Sigma | Sigma: `win_pass_the_hash` — `EventID: 4624, LogonType: 3, AuthPackage: NTLM, SourceIP NOT IN expected_list` |
| 🔍 Детекция | EID 4776 (NTLM validation) — если username = Administrator и source = workstation → PtH | SIEM | `EventID: 4776, TargetUserName: "Administrator", Workstation NOT expected` |
| ⚡ Реагирование | Сбросить пароль скомпрометированной учётки; ротировать LAPS-пароли | AD, LAPS | `Reset-AdmPwdPassword -ComputerName *` → принудительная ротация всех LAPS-паролей |
| ⚡ Реагирование | Определить source хост → изолировать → форензика: как получен хеш | EDR, SIEM | Traceback: source IP → EDR → как атакующий получил NTLM-хеш (LSASS dump?) |

### Модуль 77: Pass-the-Ticket

**Угроза:** Использование украденного Kerberos TGT/TGS для аутентификации без знания пароля.

| Слой | Действие | Инструмент | Команда / правило |

### Модуль 78: Overpass-the-Hash

**Угроза:** Конвертация NTLM-хеша в Kerberos TGT — получение Kerberos-аутентификации из NTLM-хеша.

| Слой | Действие | Инструмент | Команда / правило |

| 🔍 Детекция | Регулярный аудит: новые учётки в привилегированных группах | AD PowerShell, SIEM | `Get-ADGroupMember "Domain Admins" | Where-Object { $_.Created -gt (Get-Date).AddDays(-7) }` |
| ⚡ Реагирование | Удалить backdoor-учётку; откатить группы членства | AD PowerShell | `Remove-ADUser -Identity backdoor_account` + `Remove-ADGroupMember -Identity "Domain Admins" -Members attacker_account` |
| ⚡ Реагирование | Аудит: что делала вредоносная учётка за время существования | SIEM | `EventID: 4624 AND TargetUserName = backdoor_account` → полный timeline |

### Модуль 98: Clipboard Hijacking

**Угроза:** Мониторинг и подмена содержимого буфера обмена — кража паролей, подмена криптокошельков, перехват данных.

| 🔍 Детекция | ETW: мониторинг clipboard access от подозрительных процессов | ETW, SIEM | `Microsoft-Windows-Win32k: ClipboardAccess` от процесса в %TEMP% → алерт |

### Модуль 100: Anti-Forensics

**Угроза:** Уничтожение цифровых улик: очистка логов, перезапись slack space, timestomping, удаление артефактов — затруднение расследования.

| Слой | Действие | Инструмент | Команда / правило |
|------|----------|------------|-------------------|
| 🛡️ Превенция | Централизованное логирование в реальном времени — логи вне досягаемости атакующего | SIEM, Syslog, WEF | Wazuh agent → SIEM: даже если локальные логи стёрты, копия в SIEM |
| 🛡️ Превенция | Immutable logs: WORM-хранилище для логов (нельзя перезаписать/удалить) | S3 Object Lock, Splunk SmartStore | Логи хранятся в immutable storage → anti-forensics бесполезен |
| 🔍 Детекция | EID 1102 (Security Log Cleared), EID 104 (System Log Cleared) — немедленный алерт | SIEM, Sigma | Sigma: `win_event_log_cleared` — `EventID: 1102 OR 104` → P1 alert |
| 🔍 Детекция | Sysmon EID 1: запуск wevtutil, vssadmin (shadow copy deletion), bcdedit (boot config change) | Sysmon | `Image endswith "vssadmin.exe" AND CommandLine contains "delete shadows"` → ransomware/anti-forensics |
| ⚡ Реагирование | Форензика: восстановление из SIEM-копии, shadow copies, MFT, USN Journal | SIEM, Forensic tools | Логи из SIEM + `vol.py windows.evtlogs` (из памяти) + USN Journal parsing |
| ⚡ Реагирование | Юридическая фиксация: снять forensic image ДО любых действий на хосте | FTK Imager, dd | `dd if=/dev/sda of=evidence.raw bs=4M conv=noerror,sync` → chain of custody |
