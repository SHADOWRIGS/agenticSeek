# ПЛЕЙБУК 1: RANSOMWARE INCIDENT

**Категория:** Ransomware
**Приоритет:** P1 Critical
**SLA реагирования:** 15 минут
**MITRE ATT&CK:** T1486 (Data Encrypted for Impact), T1490 (Inhibit System Recovery)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- EDR: массовое переименование файлов с новым расширением (.locked, .encrypted, .crypt)
- SIEM: всплеск событий доступа к файлам (Event ID 4663) за короткий период
- Пользователь: сообщение о недоступности файлов, записка о выкупе на рабочем столе
- AV/EDR: детект известного семейства ransomware
- Бэкап-система: ошибки при создании теневых копий (vssadmin delete shadows)

**SIEM-правило (Sigma):**

```yaml
title: Массовое переименование файлов (возможный ransomware)
status: experimental
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4663
    ObjectType: File
    AccessMask:
      - '0x2'    # WriteData
      - '0x100'  # WriteAttributes
  timeframe: 5m
  condition: selection | count(ObjectName) by SubjectUserName > 100
level: critical
tags:
  - attack.impact
  - attack.t1486
```

**Wazuh-правило:**

```xml
<rule id="100200" level="14">
  <if_sid>60103</if_sid>
  <field name="win.eventdata.objectType">File</field>
  <frequency>100</frequency>
  <timeframe>300</timeframe>
  <description>Ransomware: массовое изменение файлов за 5 мин</description>
  <mitre>
    <id>T1486</id>
  </mitre>
</rule>
```

**ELK-запрос (KQL):**

```
event.code: "4663" AND winlog.event_data.ObjectType: "File"
| stats count by user.name, @timestamp
| where count > 100
```

**Первичная проверка (5 минут):**
- [ ] Определить хост(ы), на которых сработал алерт
- [ ] Проверить, идёт ли шифрование прямо сейчас (процесс активен?)
- [ ] Посмотреть расширения зашифрованных файлов — определить семейство
- [ ] Проверить, есть ли записка о выкупе (ransom note) и её содержимое
- [ ] Оценить масштаб: один хост или несколько? Сетевые диски затронуты?

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| Файлы реально зашифрованы, не открываются | Да → TP | Нет → FP |
| Расширения файлов изменены на нестандартные | Да → TP | Нет → FP |
| Есть ransom note (README.txt, DECRYPT.html и т.п.) | Да → TP | Нет → проверить |
| Процесс, выполняющий шифрование, неизвестный | Да → TP | Легитимный (напр., архиватор) → FP |
| Теневые копии (VSS) удалены | Да → TP | Нет → проверить |

**Вопросы для определения масштаба:**
- Сколько хостов затронуто?
- Затронуты ли сетевые диски (SMB shares)?
- Есть ли признаки латерального движения (PsExec, WMI, RDP)?
- Какие бизнес-системы недоступны?
- Есть ли актуальные бэкапы? Когда последний?
- Были ли попытки удаления бэкапов (vssadmin, wbadmin, bcdedit)?

**Критерии эскалации:**
- **На L2 немедленно:** подтверждён ransomware на любом хосте
- **На L3 / IR Lead:** затронуто >3 хостов ИЛИ сетевые диски ИЛИ серверы
- **На руководство:** бизнес-критичные системы недоступны
- **На юристов:** если есть утечка данных (double extortion)

---

### 3. Сдерживание (Containment)

**Немедленные действия (первые 15 минут):**

- [ ] **Изолировать заражённые хосты от сети** (НЕ выключать — нужен дамп памяти):

```powershell
# EDR: изолировать хост через консоль EDR (CrowdStrike/Defender)
# Или вручную отключить сетевой адаптер:
Get-NetAdapter | Disable-NetAdapter -Confirm:$false

# Если нет удалённого доступа — физически выдернуть сетевой кабель
# Wi-Fi — отключить через аппаратный переключатель или:
netsh wlan disconnect
```

- [ ] **Остановить подозрительный процесс** (если шифрование ещё идёт):

```powershell
# Найти процесс с аномальной нагрузкой на диск:
Get-Process | Sort-Object -Property CPU -Descending | Select-Object -First 10 Name, Id, CPU, WS

# Остановить (записать PID для форензики!):
Stop-Process -Id <PID> -Force

# Или через taskkill:
taskkill /PID <PID> /F
```

- [ ] **Снять дамп памяти ДО выключения** (критично для форензики):

```powershell
# С помощью WinPmem:
winpmem_mini_x64.exe memory.raw

# Или DumpIt:
DumpIt.exe
```

- [ ] **Зафиксировать время начала инцидента** (UTC):

```powershell
Get-Date -Format "yyyy-MM-dd HH:mm:ss UTC" ([DateTime]::UtcNow)
```

**Расширенное сдерживание:**

- [ ] **Заблокировать распространение по сети:**

```powershell
# На файрволе: заблокировать SMB между рабочими станциями
New-NetFirewallRule -DisplayName "Block SMB Lateral" -Direction Inbound -LocalPort 445 -Protocol TCP -Action Block

# Заблокировать PsExec / удалённое выполнение:
New-NetFirewallRule -DisplayName "Block RPC" -Direction Inbound -LocalPort 135 -Protocol TCP -Action Block
```

- [ ] **Сбросить пароли сервисных учёток** (если компрометация AD):

```powershell
# Сбросить пароль учётки:
Set-ADAccountPassword -Identity "svc_account" -Reset -NewPassword (ConvertTo-SecureString "NewStr0ng!Pass#2024" -AsPlainText -Force)

# Отключить подозрительные учётки:
Disable-ADAccount -Identity "compromised_user"
```

- [ ] **Отключить скомпрометированные учётные записи в AD**
- [ ] **Проверить и остановить запланированные задачи** (persistence):

```powershell
Get-ScheduledTask | Where-Object {$_.State -eq "Ready" -and $_.Date -gt (Get-Date).AddDays(-7)} | Format-Table TaskName, TaskPath, Date
```

- [ ] **Изолировать заражённый сегмент сети на уровне switch/VLAN**

### 4. Устранение (Eradication)

- [ ] **Определить вектор заражения** (как ransomware попал в сеть):
  - Проверить email-логи (фишинг?)
  - Проверить RDP-логи (брутфорс?)
  - Проверить VPN-логи (скомпрометированный доступ?)
  - Проверить web-прокси (drive-by download?)

```powershell
# Проверить последние входы через RDP:
Get-WinEvent -LogName "Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational" -MaxEvents 50 |
  Select-Object TimeCreated, @{N='User';E={$_.Properties[0].Value}}, @{N='IP';E={$_.Properties[2].Value}}
```

- [ ] **Идентифицировать семейство ransomware:**
  - Загрузить ransom note и образец зашифрованного файла на [ID Ransomware](https://id-ransomware.malwarehunterteam.com/)
  - Проверить хеш вредоноса на VirusTotal
  - Проверить наличие дешифратора на [No More Ransom](https://www.nomoreransom.org/)

- [ ] **Удалить все артефакты вредоноса:**

```powershell
# Найти файлы вредоноса по известным IoC:
Get-ChildItem -Path C:\ -Recurse -Force -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match "malware_name|ransom_binary" }

# Проверить автозапуск:
Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
Get-ItemProperty -Path "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"

# Проверить службы:
Get-Service | Where-Object {$_.Status -eq "Running" -and $_.StartType -eq "Automatic"} |
  Where-Object {$_.DisplayName -notmatch "Windows|Microsoft"}
```

- [ ] **Проверить все хосты сети на IoC** (hash, filename, C2 IP):

```bash
# Через YARA на Linux:
yara -r ransomware_rules.yar /path/to/scan/

# Через Wazuh — поиск IoC по всей инфраструктуре:
# ossec-control -> syscheck
```

- [ ] **Закрыть вектор заражения** (пропатчить, отключить RDP, усилить email-фильтрацию)
- [ ] **Проверить persistence-механизмы** (scheduled tasks, services, registry, WMI subscriptions)

---

### 5. Восстановление (Recovery)

- [ ] **Восстановить данные из бэкапов:**
  - Проверить целостность бэкапов ПЕРЕД восстановлением
  - Восстановить на чистые системы (не на заражённые)
  - Начать с бизнес-критичных систем

- [ ] **Переустановить заражённые хосты:**

```powershell
# Или восстановить из golden image
# Убедиться, что образ не скомпрометирован
```

- [ ] **Восстановить сетевое подключение поэтапно:**
  - Сначала серверы → затем рабочие станции
  - Мониторить трафик на признаки повторного заражения

- [ ] **Усиленный мониторинг 72 часа:**

```yaml
# Sigma-правило для мониторинга после инцидента:
title: Пост-инцидент мониторинг — подозрительная файловая активность
logsource:
  product: windows
  service: sysmon
detection:
  selection:
    EventID: 11  # FileCreate
    TargetFilename|endswith:
      - '.locked'
      - '.encrypted'
      - '.crypt'
      - '.enc'
  condition: selection
level: critical
```

- [ ] **Проверить, что все IoC заблокированы** на периметре (IP, домены, хеши)

---

### 6. Lessons Learned

**Провести ретроспективу в течение 5 рабочих дней:**

- [ ] Составить полный таймлайн инцидента (UTC)
- [ ] Определить root cause (как именно попал ransomware)
- [ ] Оценить финансовый ущерб (простой, восстановление, потери данных)
- [ ] Что сработало хорошо в реагировании?
- [ ] Что можно улучшить?
- [ ] Какие контроли добавить/усилить?

**Типичные улучшения после ransomware:**
- Внедрить/усилить email-фильтрацию (sandbox для вложений)
- Ограничить макросы в Office (GPO)
- Настроить AppLocker/WDAC
- Сегментировать сеть (VLAN между рабочими станциями)
- Внедрить immutable бэкапы (правило 3-2-1-1-0)
- Отключить/ограничить RDP с интернета
- Включить MFA на все внешние сервисы

# ПЛЕЙБУК 2: PHISHING — СКОМПРОМЕТИРОВАННАЯ УЧЁТНАЯ ЗАПИСЬ

**Категория:** Phishing / Account Compromise
**Приоритет:** P2 High
**SLA реагирования:** 1 час
**MITRE ATT&CK:** T1566 (Phishing), T1078 (Valid Accounts)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- Пользователь сообщил о подозрительном письме / переходе по ссылке / вводе учётных данных
- SIEM: вход в учётку с нового IP/геолокации
- Email-gateway: ретроспективная детекция фишинг-ссылки
- MFA: множественные запросы на подтверждение (MFA fatigue)
- Impossible travel: вход из двух городов за короткий период

**SIEM-правило (Sigma):**

```yaml
title: Вход с новой геолокации после фишинг-алерта
status: experimental
logsource:
  product: azure
  service: signinlogs
detection:
  selection:
    eventName: Sign-in activity
    status.errorCode: 0
  filter_known:
    location.countryOrRegion:
      - "RU"
      - "BY"   # добавить легитимные страны
  condition: selection and not filter_known
level: high
tags:
  - attack.initial_access
  - attack.t1078
```

**Wazuh-запрос:**

```
rule.groups: "authentication_success" AND NOT srcip: ("10.0.0.0/8" OR "172.16.0.0/12" OR "192.168.0.0/16")
```

**ELK-запрос:**

```
event.action: "logon" AND event.outcome: "success" AND NOT source.ip: (10.0.0.0/8 OR 172.16.0.0/12)
| stats dc(source.geo.country_name) as countries by user.name
| where countries > 1
```

**Первичная проверка (5 минут):**
- [ ] Получить имя пользователя, чья учётка потенциально скомпрометирована
- [ ] Определить, когда пользователь перешёл по ссылке / ввёл учётные данные
- [ ] Проверить, включена ли MFA на учётке
- [ ] Посмотреть последние входы (логи аутентификации) — есть ли аномальные?
- [ ] Определить, что пользователь делал после перехода по ссылке

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| Пользователь подтвердил, что вводил учётные данные | Да → TP | Нет → проверить |
| Вход с нового IP/страны после момента фишинга | Да → TP | Нет → вероятно FP |
| Созданы правила пересылки в почте | Да → TP | Нет → проверить |
| MFA fatigue (множество запросов) | Да → TP | Нет → проверить |
| Аномальные действия от имени учётки | Да → TP | Нет → мониторить |

**Вопросы для определения масштаба:**
- Какой тип фишинга (credential harvesting, malware, BEC)?
- Сколько пользователей получили такое же письмо?
- Введены ли данные на поддельной странице?
- Есть ли признаки, что атакующий уже использовал учётку?
- Есть ли доступ к критичным системам через эту учётку?
- Была ли переписка с клиентами/партнёрами от имени учётки?

**Критерии эскалации:**
- **На L2:** подтверждён ввод учётных данных на фишинг-странице
- **На L3:** учётка уже использовалась атакующим (новые входы, правила пересылки)
- **На руководство:** фишинг-рассылка от имени скомпрометированной учётки (BEC)
- **На юристов:** если отправлены платёжные данные или персональные данные

---

### 3. Сдерживание (Containment)

**Немедленные действия (первые 15 минут):**

- [ ] **Сбросить пароль учётной записи:**

```powershell
# Active Directory:
Set-ADAccountPassword -Identity "username" -Reset -NewPassword (ConvertTo-SecureString "TempP@ss!Change2024" -AsPlainText -Force)
Set-ADUser -Identity "username" -ChangePasswordAtLogon $true

# Azure AD / Entra ID:
# Через портал admin.microsoft.com → Пользователи → Сбросить пароль
```

- [ ] **Отозвать все активные сессии:**

```powershell
# Azure AD:
Revoke-AzureADUserAllRefreshToken -ObjectId (Get-AzureADUser -SearchString "username").ObjectId

# Microsoft 365 (Exchange Online):
Get-PSSession | Remove-PSSession
```

- [ ] **Проверить и удалить правила пересылки в почте:**

```powershell
# Exchange Online:
Get-InboxRule -Mailbox "user@domain.com" | Where-Object {$_.ForwardTo -or $_.ForwardAsAttachmentTo -or $_.RedirectTo}

# Удалить подозрительные правила:
Remove-InboxRule -Mailbox "user@domain.com" -Identity "Rule Name" -Confirm:$false
```

- [ ] **Проверить делегирование почтового ящика:**

```powershell
Get-MailboxPermission -Identity "user@domain.com" | Where-Object {$_.User -ne "NT AUTHORITY\SELF"}
Get-MailboxFolderPermission -Identity "user@domain.com:\Inbox"
```

**Расширенное сдерживание:**

- [ ] **Заблокировать фишинговый URL на прокси/файрволе:**

```bash
# Suricata:
# Добавить в blocklist:
echo "phishing-domain.com" >> /etc/suricata/rules/blocklist-domains.txt
suricatasc -c reload-rules
```

- [ ] **Найти всех получателей фишингового письма:**

```powershell
# Exchange Online — поиск по теме/отправителю:
Get-MessageTrace -SenderAddress "phisher@evil.com" -StartDate (Get-Date).AddDays(-7) -EndDate (Get-Date) |
  Select-Object Received, SenderAddress, RecipientAddress, Subject, Status
```

- [ ] **Удалить фишинговое письмо из всех ящиков:**

```powershell
# Exchange Online — Compliance Search:
New-ComplianceSearch -Name "PhishRemoval" -ExchangeLocation All -ContentMatchQuery 'subject:"Тема фишинга" AND from:phisher@evil.com'
Start-ComplianceSearch -Identity "PhishRemoval"
# После завершения:
New-ComplianceSearchAction -SearchName "PhishRemoval" -Purge -PurgeType SoftDelete
```

- [ ] **Уведомить всех получателей** о фишинге (НЕ пересылать фишинговое письмо!)

---

### 4. Устранение (Eradication)

- [ ] **Проверить, были ли действия от имени учётки:**

```powershell
# Azure AD Sign-in Logs:
Get-AzureADAuditSignInLogs -Filter "userPrincipalName eq 'user@domain.com'" -Top 50 |
  Select-Object CreatedDateTime, IpAddress, Location, Status, AppDisplayName
```

- [ ] **Проверить изменения в учётке** (добавлены методы MFA? Доверенные устройства?):

```powershell
Get-AzureADAuditDirectoryLogs -Filter "targetResources/any(t:t/userPrincipalName eq 'user@domain.com')" -Top 20
```

- [ ] **Проверить OAuth-приложения** (атакующий мог добавить вредоносное приложение):

```powershell
Get-AzureADUserOAuth2PermissionGrant -ObjectId (Get-AzureADUser -SearchString "user").ObjectId
```

- [ ] **Удалить подозрительные OAuth-разрешения**
- [ ] **Если BEC — проверить исходящую переписку** на предмет мошенничества
- [ ] **Добавить фишинговый домен/IP в глобальный blocklist**

---

### 5. Восстановление (Recovery)

- [ ] **Восстановить доступ пользователю** (новый пароль + проверка MFA)
- [ ] **Проинструктировать пользователя:**
  - Проверить все OAuth-приложения самостоятельно
  - Сообщать о подозрительных письмах
  - Не использовать старый пароль нигде
- [ ] **Мониторинг учётки 14 дней** (усиленный):

```yaml
# Sigma — мониторинг конкретного пользователя:
title: Пост-инцидент мониторинг скомпрометированной учётки
detection:
  selection:
    User: "compromised_user"
    EventID:
      - 4624  # Successful logon
      - 4625  # Failed logon
      - 4672  # Special privileges
  condition: selection
level: high
```

- [ ] **Проверить, что правила пересылки не восстановились**

---

### 6. Lessons Learned

- [ ] Была ли email-фильтрация достаточной? Почему письмо прошло?
- [ ] Была ли MFA включена? Если да — как обошли?
- [ ] Насколько быстро пользователь сообщил?
- [ ] Нужно ли дополнительное security awareness обучение?

**Типичные улучшения:**
- Усилить email-фильтрацию (sandbox, URL rewrite)
- Провести фишинг-симуляцию для сотрудников
- Внедрить phishing-resistant MFA (FIDO2/WebAuthn)
- Настроить Conditional Access (заблокировать входы из нелегитимных стран)
- Автоматизировать отзыв сессий при фишинг-алерте (SOAR)

# ПЛЕЙБУК 3: MALWARE DETECTION

**Категория:** Malware
**Приоритет:** P2 High
**SLA реагирования:** 1 час
**MITRE ATT&CK:** T1059 (Command and Scripting), T1204 (User Execution)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- AV/EDR: детекция вредоносного файла (сигнатура или поведенческий анализ)
- Sysmon: подозрительный дочерний процесс (Event ID 1)
- SIEM: аномальная сетевая активность от хоста
- Песочница: детонация вложения с вердиктом «malicious»

**Sigma-правило:**

```yaml
title: Подозрительный дочерний процесс от Office
status: stable
logsource:
  product: windows
  category: process_creation
detection:
  selection_parent:
    ParentImage|endswith:
      - '\WINWORD.EXE'
      - '\EXCEL.EXE'
      - '\POWERPNT.EXE'
      - '\OUTLOOK.EXE'
  selection_child:
    Image|endswith:
      - '\cmd.exe'
      - '\powershell.exe'
      - '\pwsh.exe'
      - '\wscript.exe'
      - '\cscript.exe'
      - '\mshta.exe'
      - '\regsvr32.exe'
      - '\rundll32.exe'
  condition: selection_parent and selection_child
level: high
tags:
  - attack.execution
  - attack.t1204.002
```

**Первичная проверка (5 минут):**
- [ ] Определить хост и пользователя
- [ ] Получить имя/хеш файла из алерта
- [ ] Проверить хеш на VirusTotal (`sha256`)
- [ ] Определить, был ли файл запущен (выполнен) или только обнаружен
- [ ] Проверить, карантинирован ли файл AV/EDR

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| VirusTotal: >5 детекций от разных вендоров | TP | <3 детекции → проверить |
| Файл запущен, создал дочерние процессы | TP | Только обнаружен, не запущен → Low |
| Сетевые соединения от процесса | TP | Нет сетевой активности → проверить |
| Файл подписан легитимным издателем | FP вероятен | Не подписан → TP |
| Пользователь знает, откуда файл | Проверить | Легитимная загрузка → FP |

**Критерии эскалации:**
- **На L2:** файл был запущен, есть дочерние процессы
- **На L3:** есть сетевые соединения (C2), затронуто >1 хоста
- **На IR Lead:** обнаружен zero-day или целевая атака (APT)

---

### 3. Сдерживание (Containment)

**Немедленные действия:**

- [ ] **Если файл ещё не запущен — карантинировать:**

```powershell
# Windows Defender:
Set-MpPreference -QuarantineFile "C:\path\to\malware.exe"

# Или вручную переместить (заархивировать с паролем):

Remove-Item "C:\path\to\malware.exe"
```

- [ ] **Если файл запущен — изолировать хост:**

```powershell
# Через EDR-консоль: Network Isolation
# Или отключить сеть:

```

- [ ] **Снять дамп памяти процесса:**

```powershell
# ProcDump (Sysinternals):
procdump.exe -ma <PID> C:\Forensics\malware_dump.dmp
```

- [ ] **Собрать артефакты:**

```powershell
# Скопировать файл для анализа:
Copy-Item "C:\path\to\malware.exe" "C:\Forensics\samples\"

# Собрать Sysmon-логи:
wevtutil epl "Microsoft-Windows-Sysmon/Operational" C:\Forensics\sysmon.evtx

# Получить список процессов:
Get-Process | Export-Csv C:\Forensics\processes.csv
```

**Расширенное сдерживание:**

- [ ] **Заблокировать хеш файла на всех хостах:**

```powershell
# Windows Defender:
Add-MpPreference -ThreatIDDefaultAction_Ids <ThreatID> -ThreatIDDefaultAction_Actions Quarantine

# AppLocker — заблокировать по хешу:
# Через GPO → AppLocker → Executable Rules
```

- [ ] **Заблокировать C2-адреса на файрволе** (если обнаружены)
- [ ] **Проверить другие хосты на тот же IoC:**

```bash
# Wazuh — поиск по хешу:
/var/ossec/bin/agent_control -l | while read agent; do
  /var/ossec/bin/syscheck_control -i $agent -f "sha256:<hash>"
done
```

---

### 4. Устранение (Eradication)

- [ ] Удалить вредоносный файл и все его копии
- [ ] Проверить persistence (autorun, services, scheduled tasks, WMI)
- [ ] Убить все связанные процессы
- [ ] Удалить созданные файлы/ключи реестра
- [ ] Проверить учётные записи на компрометацию

```powershell
# Полная проверка автозапуска (Sysinternals Autoruns):
autorunsc.exe -a * -c -h -s -v -vt | Export-Csv C:\Forensics\autoruns.csv

# Проверить Sysmon на созданные файлы (Event ID 11):
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=11} -MaxEvents 100 |
  Where-Object { $_.TimeCreated -gt (Get-Date).AddHours(-24) }
```

---

### 5. Восстановление (Recovery)

- [ ] Если хост чистый — восстановить сетевое подключение
- [ ] Если хост серьёзно скомпрометирован — переустановить ОС
- [ ] Обновить AV-сигнатуры на всех хостах
- [ ] Мониторинг 48 часов

---

### 6. Lessons Learned

- Как файл попал на хост? (email, USB, загрузка)
- Почему AV/EDR не заблокировал при запуске?
- Нужно ли обновить политики (заблокировать макросы, ограничить USB)?

# ПЛЕЙБУК 4: BRUTE FORCE / CREDENTIAL STUFFING

**Категория:** Account Compromise
**Приоритет:** P2 High
**SLA реагирования:** 1 час
**MITRE ATT&CK:** T1110 (Brute Force), T1110.004 (Credential Stuffing)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- SIEM: множество неудачных входов (Event ID 4625) с одного IP
- SIEM: неудачные входы в разные учётки с одного IP (password spraying)
- WAF/IDS: аномальный объём POST-запросов на страницу входа
- Account lockout алерты (Event ID 4740)

**Sigma-правило (Brute Force):**

```yaml
title: Brute Force — множественные неудачные входы
status: stable
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4625
  timeframe: 10m
  condition: selection | count(TargetUserName) by IpAddress > 10
level: high
tags:
  - attack.credential_access
  - attack.t1110
```

**Sigma-правило (Password Spraying):**

```yaml
title: Password Spraying — один пароль, много учёток
status: experimental
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4625
    SubStatus: '0xC000006A'  # Bad password
  timeframe: 30m
  condition: selection | count(TargetUserName) by IpAddress > 20
level: high
tags:
  - attack.credential_access
  - attack.t1110.003
```

**Wazuh-правило:**

```xml
<rule id="100210" level="12">
  <if_sid>60122</if_sid>
  <same_source_ip />
  <frequency>10</frequency>
  <timeframe>600</timeframe>
  <description>Brute Force: 10+ неудачных входов за 10 мин с одного IP</description>
  <mitre>
    <id>T1110</id>
  </mitre>
</rule>
```

**ELK-запрос:**

```
event.code: "4625" | stats count by source.ip, user.name | where count > 10 | sort -count
```

**Первичная проверка (5 минут):**
- [ ] Определить IP-адрес(а) источника
- [ ] Внутренний это IP или внешний?
- [ ] Какие учётки атакуются?
- [ ] Был ли успешный вход (4624) после серии неудачных?
- [ ] Сколько длится атака?

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| IP внешний, не из known ranges | TP | Внутренний IP сервиса → FP |
| Атакуются разные учётки с одного IP | TP (spraying) | Одна учётка → забыл пароль |
| После неудачных входов есть успешный | TP (критично!) | Нет успешных → только попытка |
| IP в threat intelligence базах | TP | Clean IP → проверить |

**Критерии эскалации:**
- **На L2:** >50 попыток за 10 минут ИЛИ атака на привилегированные учётки
- **На L3:** после brute force зафиксирован успешный вход
- **На руководство:** скомпрометирована учётка с доступом к критичным данным

---

### 3. Сдерживание (Containment)

**Немедленные действия:**

- [ ] **Заблокировать IP-адрес атакующего:**

```bash
# Файрвол Linux:
iptables -A INPUT -s <IP> -j DROP

# Файрвол Windows:
New-NetFirewallRule -DisplayName "Block Brute Force IP" -Direction Inbound -RemoteAddress <IP> -Action Block

# fail2ban (если настроен):
fail2ban-client set sshd banip <IP>

# Suricata:
echo "drop ip <IP> any -> any any (msg:\"Blocked brute force IP\"; sid:9999001; rev:1;)" >> /etc/suricata/rules/local.rules
suricatasc -c reload-rules
```

- [ ] **Если был успешный вход — сбросить пароль учётки:**

```powershell
Set-ADAccountPassword -Identity "username" -Reset -NewPassword (ConvertTo-SecureString "TempStr0ng!2024" -AsPlainText -Force)
Disable-ADAccount -Identity "username"
```

- [ ] **Отозвать сессии:**

```powershell
# Проверить активные сессии:
query user /server:<hostname>

# Завершить сессию:
logoff <session_id> /server:<hostname>
```

**Расширенное сдерживание:**

- [ ] **Включить account lockout policy** (если не включена):

```powershell
# Через GPO:
# Account Lockout Threshold: 5 attempts
# Account Lockout Duration: 30 minutes
# Reset Account Lockout Counter: 30 minutes
```

- [ ] **Настроить rate limiting на прокси/WAF:**

```nginx
# Nginx rate limiting:
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;

location /login {
    limit_req zone=login burst=3 nodelay;
    limit_req_status 429;
    # ...
}
```

- [ ] **Проверить все учётки, на которые были успешные входы с этого IP**
- [ ] **Добавить IP в глобальный blocklist организации**

---

### 4. Устранение (Eradication)

- [ ] Если учётка скомпрометирована — провести полную проверку (см. Плейбук 2)
- [ ] Определить, какие данные были доступны через учётку
- [ ] Проверить, не было ли повышения привилегий

```powershell
# Проверить входы с подозрительного IP:
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $_.Properties[18].Value -eq "<IP>" } |
  Select-Object TimeCreated, @{N='User';E={$_.Properties[5].Value}}, @{N='LogonType';E={$_.Properties[8].Value}}
```

---

### 5. Восстановление (Recovery)

- [ ] Разблокировать заблокированные учётки (после сброса пароля)
- [ ] Убедиться, что MFA включена для всех внешних сервисов
- [ ] Мониторинг IP-адреса и учёток 7 дней

---

### 6. Lessons Learned

- Была ли MFA включена на атакованных сервисах?
- Была ли account lockout policy?
- Используется ли fail2ban / rate limiting?
- Нужно ли внедрить CAPTCHA / adaptive authentication?

# ПЛЕЙБУК 5: DATA EXFILTRATION

**Категория:** Data Breach
**Приоритет:** P1 Critical
**SLA реагирования:** 15 минут
**MITRE ATT&CK:** T1041 (Exfiltration Over C2), T1048 (Exfiltration Over Alternative Protocol)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- DLP: срабатывание правила на передачу конфиденциальных данных
- SIEM/NTA: аномальный объём исходящего трафика
- Прокси: большие загрузки на file-sharing сервисы (Mega, Dropbox, pastebin)
- DNS: аномально длинные DNS-запросы (DNS exfil)
- EDR: массовое чтение файлов из конфиденциальных директорий

**Sigma-правило:**

```yaml
title: Аномальный исходящий трафик — возможная эксфильтрация
status: experimental
logsource:
  product: proxy
detection:
  selection:
    cs-method: POST
    sc-bytes|gt: 10485760  # > 10 MB
  filter_known:
    cs-host|contains:
      - 'microsoft.com'
      - 'windowsupdate.com'
      - 'office365.com'
  condition: selection and not filter_known
level: high
tags:
  - attack.exfiltration
  - attack.t1041
```

**Suricata-правило (DNS exfiltration):**

```
alert dns any any -> any any (msg:"DNS Exfiltration - длинный запрос"; dns.query; content:"."; offset:50; sid:2100001; rev:1;)
```

**Первичная проверка (5 минут):**
- [ ] Определить хост-источник и пользователя
- [ ] Определить назначение трафика (IP/домен)
- [ ] Оценить объём переданных данных
- [ ] Определить тип данных (если DLP сообщает)
- [ ] Проверить, легитимна ли передача (обновления, бэкапы, синхронизация)

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| Назначение — внешний неизвестный сервис | TP | Корпоративный бэкап/облако → FP |
| Передаются файлы с конфиденциальными данными | TP | Обычные рабочие файлы → проверить |
| Передача в нерабочее время | TP вероятен | Плановая задача → FP |
| Используется нестандартный протокол / DNS tunneling | TP | Легитимный DNS → FP |
| Учётка пользователя — привилегированная | Критичнее | Обычный пользователь → стандарт |

**Критерии эскалации:**
- **На L3 немедленно:** подтверждена передача конфиденциальных данных
- **На руководство:** персональные данные клиентов, коммерческая тайна
- **На юристов:** обязательное уведомление регулятора (152-ФЗ: 24 часа в Роскомнадзор)
- **На DPO:** при утечке персональных данных

---

### 3. Сдерживание (Containment)

**Немедленные действия (первые 15 минут):**

- [ ] **Заблокировать назначение на файрволе/прокси:**

```bash
# iptables:
iptables -A OUTPUT -d <IP> -j DROP

# Squid proxy:
echo "acl exfil_dest dstdomain .malicious-site.com" >> /etc/squid/squid.conf
echo "http_access deny exfil_dest" >> /etc/squid/squid.conf
squid -k reconfigure
```

- [ ] **Изолировать хост-источник:**

```powershell
# EDR: Network Isolation
# Или:
Get-NetAdapter | Disable-NetAdapter -Confirm:$false
```

- [ ] **Заблокировать учётку пользователя:**

```powershell
Disable-ADAccount -Identity "username"
```

- [ ] **Сохранить образ трафика (PCAP):**

```bash
# Если есть Zeek/Suricata:
# Логи уже пишутся

# Ручной захват:
tcpdump -i eth0 -w /forensics/exfil_$(date +%Y%m%d_%H%M).pcap host <dest_IP> &
```

**Расширенное сдерживание:**

- [ ] **Заблокировать file-sharing сервисы** (если используются для эксфильтрации):

```
# На прокси — заблокировать категорию "File Sharing":
# Mega.nz, WeTransfer, anonfiles, pastebin и др.
```

- [ ] **Отключить USB на хосте** (если подозревается физическая эксфильтрация):

```powershell
# GPO: Computer Configuration → Administrative Templates → System → Device Installation → Prevent installation of removable devices
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\USBSTOR" -Name "Start" -Value 4
```

---

### 4. Устранение (Eradication)

- [ ] **Определить полный объём утечки:**

```bash
# Zeek — анализ объёма трафика к назначению:
cat conn.log | zeek-cut id.orig_h id.resp_h resp_bytes | awk '$2 == "<dest_IP>" {sum += $3} END {print sum/1048576 " MB"}'
```

- [ ] **Определить, какие именно файлы/данные утекли:**
  - Проверить DLP-логи
  - Проверить access-логи файлового сервера
  - Проверить activity log учётки

- [ ] **Определить root cause:**
  - Insider threat? → Плейбук 6
  - Компрометация учётки? → Плейбук 2
  - Malware? → Плейбук 3

---

### 5. Восстановление (Recovery)

- [ ] Если утечка — через insider: HR-процедура
- [ ] Если утечка — через компрометацию: устранить точку входа
- [ ] **Юридические обязательства:**
  - 152-ФЗ: уведомить Роскомнадзор в 24 часа
  - Уведомить пострадавших субъектов ПДн
  - Подготовить отчёт для руководства
- [ ] Усиленный мониторинг DLP 30 дней

---

### 6. Lessons Learned

- Была ли DLP-система настроена на обнаружение этого типа данных?
- Есть ли классификация данных в организации?
- Нужно ли ограничить доступ к file-sharing сервисам?
- Нужно ли внедрить/усилить DLP?

# ПЛЕЙБУК 6: INSIDER THREAT

**Категория:** Insider Threat
**Приоритет:** P2 High
**SLA реагирования:** 4 часа
**MITRE ATT&CK:** T1078 (Valid Accounts), T1530 (Data from Cloud Storage)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- UEBA: аномальное поведение пользователя (доступ к нетипичным ресурсам)
- DLP: массовое копирование файлов на USB / облако
- HR: сотрудник подал заявление на увольнение (risk signal)
- SIEM: доступ к данным в нерабочее время
- Сообщение коллеги о подозрительном поведении

**Sigma-правило:**

```yaml
title: Массовое копирование файлов на USB
status: experimental
logsource:
  product: windows
  service: sysmon
detection:
  selection:
    EventID: 11  # FileCreate
    TargetFilename|contains:
      - '\\USB'
      - '\\Removable'
  timeframe: 1h
  condition: selection | count() by User > 50
level: high
tags:
  - attack.collection
  - attack.exfiltration
```

**Первичная проверка:**
- [ ] Определить пользователя и его роль
- [ ] Проверить, подал ли заявление на увольнение (HR)
- [ ] Оценить уровень доступа пользователя
- [ ] Определить, к каким данным был доступ
- [ ] Проверить, типично ли такое поведение для этого пользователя

---

### 2. Классификация (Triage)

**Вопросы для определения масштаба:**
- Какова роль сотрудника и уровень доступа?
- Есть ли признаки умысла или это ошибка/халатность?
- Какие данные затронуты (конфиденциальные, ПДн, коммерческая тайна)?
- Есть ли история дисциплинарных нарушений?
- Увольняющийся сотрудник?

**Критерии эскалации:**
- **На L3 + HR + юристы:** подозрение на умышленную утечку
- **На руководство:** привилегированный сотрудник (admin, C-level)
- **На DPO:** затронуты персональные данные

**ВАЖНО:** расследование insider threat требует координации с HR и юристами. Действия должны быть документированы для возможного использования в суде.

---

### 3. Сдерживание (Containment)

**Немедленные действия:**

- [ ] **НЕ уведомлять сотрудника** до согласования с HR и юристами
- [ ] **Усилить мониторинг** (включить полное логирование):

```powershell
# Включить расширенный аудит на файловые ресурсы:
auditpol /set /subcategory:"File System" /success:enable /failure:enable

# Sysmon — убедиться, что логируются все файловые операции
```

- [ ] **Ограничить доступ (аккуратно, чтобы не спугнуть):**
  - Убрать доступ к критичным ресурсам, замаскировав под «техническое обслуживание»
  - Заблокировать USB через GPO
  - Заблокировать file-sharing на прокси

```powershell
# Заблокировать USB для конкретного пользователя (GPO):
# Computer Config → Admin Templates → System → Device Installation
# → Prevent installation of devices → Apply to specific user

# Или PowerShell:
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\USBSTOR" -Name "Start" -Value 4
```

**Расширенное сдерживание (по согласованию с HR/юристами):**

# ПЛЕЙБУК 7: WEB APPLICATION ATTACK

**Категория:** Web Attack
**Приоритет:** P2 High
**SLA реагирования:** 1 час
**MITRE ATT&CK:** T1190 (Exploit Public-Facing Application)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- WAF: блокировка SQLi/XSS/RCE попытки
- IDS: сигнатура веб-атаки
- SIEM: аномальные HTTP-запросы (длинные URL, специальные символы)
- Мониторинг: ошибки 500 на веб-сервере
- Bug bounty: отчёт от исследователя

**Suricata-правило (SQLi):**

```
alert http any any -> $HOME_NET any (msg:"SQL Injection Attempt"; flow:to_server,established; content:"UNION"; nocase; content:"SELECT"; nocase; distance:0; sid:2100010; rev:1;)
```

**ModSecurity (WAF) правило:**

```
SecRule ARGS "@rx (?i)(union\s+select|' or 1=1|<script>|exec\s*\()" \
```

**Sigma-правило:**

```yaml
title: Подозрительные символы в HTTP-запросах (web attack)
status: experimental
logsource:
  product: webserver
detection:
  selection:
    cs-uri-query|contains:
      - "UNION SELECT"
      - "' OR 1=1"

      - "cmd.exe"
      - "| whoami"

level: high
```

**Первичная проверка (5 минут):**
- [ ] Определить атакуемое веб-приложение и URL
- [ ] Определить IP-адрес атакующего
- [ ] Определить тип атаки (SQLi / XSS / RCE / LFI / path traversal)
- [ ] Проверить, была ли атака успешной (ответ 200 с данными?)
- [ ] Проверить, заблокировал ли WAF атаку

---

### 2. Классификация (Triage)

**True/False Positive checklist:**

| Проверка | True Positive | False Positive |
|----------|---------------|----------------|
| WAF заблокировал, ответ 403 | Попытка → Low | — |
| Ответ 200 на вредоносный запрос | TP — возможная успешная атака! | — |
| Данные из БД в ответе | TP Critical | Нет данных → проверить |
| Автоматизированная атака (Burp/sqlmap) | TP | Сканер безопасности → FP |
| Один запрос vs серия | Одиночный → Low | Серия → TP |

**Критерии эскалации:**
- **На L2:** серия атак от одного IP ИЛИ обход WAF
- **На L3:** успешная эксплуатация (RCE, SQLi с данными)
- **На IR Lead:** данные извлечены из БД
- **На руководство:** утечка данных клиентов

# ПЛЕЙБУК 8: DDoS ATTACK

**Категория:** Denial of Service
**Приоритет:** P1 Critical
**SLA реагирования:** 15 минут
**MITRE ATT&CK:** T1498 (Network Denial of Service), T1499 (Endpoint Denial of Service)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- Мониторинг: недоступность сервиса (HTTP 503, timeout)
- NTA: аномальный объём входящего трафика (>10x от нормы)
- Файрвол: SYN flood, UDP flood, ICMP flood
- Пользователи / клиенты: жалобы на недоступность

**Suricata-правило:**

```
alert tcp any any -> $HOME_NET 80 (msg:"DDoS SYN Flood detected"; flags:S; threshold:type both, track by_dst, count 1000, seconds 10; sid:2100020; rev:1;)
```

**Первичная проверка (5 минут):**
- [ ] Подтвердить, что сервис недоступен (не плановое обслуживание)
- [ ] Определить тип: volumetric (трафик), protocol (SYN flood), application (HTTP flood)
- [ ] Оценить объём трафика

```bash
# Быстрая диагностика:
# Текущие соединения:
ss -s
netstat -an | awk '{print $6}' | sort | uniq -c | sort -rn

# Топ IP по соединениям:
netstat -ntu | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -20

# Объём трафика:
iftop -i eth0 -t -s 10
```

- [ ] Определить, один IP или ботнет (множество IP)
- [ ] Определить, какие сервисы затронуты

---

### 2. Классификация (Triage)

**Определение типа DDoS:**

| Тип | Признаки | Защита |
|-----|----------|--------|
| **Volumetric** (UDP/ICMP flood) | Канал забит, >10 Гбит/с | Upstream filtering, CDN |
| **Protocol** (SYN flood) | Много полуоткрытых соединений | SYN cookies, rate limiting |
| **Application** (HTTP flood) | CPU/RAM сервера на 100%, мало трафика | WAF, rate limiting, CAPTCHA |
| **Amplification** (DNS/NTP/memcached) | Огромный объём ответов | BCP38, upstream blocking |

**Критерии эскалации:**
- **На сетевого инженера:** volumetric > 1 Гбит/с
- **На провайдера / DDoS protection:** volumetric > канальная ёмкость
- **На руководство:** бизнес-критичный сервис недоступен > 30 мин

---

### 3. Сдерживание (Containment)

**Немедленные действия:**

- [ ] **Application-level DDoS — rate limiting:**

```bash
# Nginx rate limiting:
# В http блоке:
limit_req_zone $binary_remote_addr zone=ddos:50m rate=30r/m;
limit_conn_zone $binary_remote_addr zone=addr:50m;

# В server/location блоке:
limit_req zone=ddos burst=10 nodelay;
limit_conn addr 10;
limit_req_status 429;
```

- [ ] **SYN Flood — включить SYN cookies:**

```bash
# Linux:
sysctl -w net.ipv4.tcp_syncookies=1
sysctl -w net.ipv4.tcp_max_syn_backlog=65536
sysctl -w net.ipv4.tcp_synack_retries=2
sysctl -w net.core.somaxconn=65536
```

- [ ] **Заблокировать топ-атакующих:**

```bash
# Автоматическая блокировка топ-100 IP:
netstat -ntu | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -100 |
  awk '{if ($1 > 50) print "iptables -A INPUT -s "$2" -j DROP"}' | bash
```

- [ ] **Включить geo-blocking** (если аудитория локальная):

```bash
# iptables + xt_geoip:
iptables -A INPUT -m geoip ! --src-cc RU,BY,KZ -p tcp --dport 80 -j DROP
```

**Расширенное сдерживание:**

- [ ] **Активировать CDN / DDoS protection** (Cloudflare, DDoS-Guard, Qrator):
  - Переключить DNS на CDN
  - Включить «Under Attack» mode
  - Настроить CAPTCHA challenge

- [ ] **Связаться с провайдером:**
  - Запросить blackhole routing для атакующих IP
  - Запросить увеличение канала (если возможно)
  - Активировать DDoS scrubbing (если есть в тарифе)

- [ ] **Масштабировать инфраструктуру** (если облако):

```bash
# Auto-scaling group — увеличить минимум:
# AWS: aws autoscaling update-auto-scaling-group --min-size 10
# Или добавить серверы вручную за балансировщик
```

---

### 4. Устранение (Eradication)

- [ ] Дождаться прекращения атаки (мониторить трафик)
- [ ] Проанализировать паттерн атаки для тонкой настройки фильтров
- [ ] Заблокировать ботнет-IP на постоянной основе
- [ ] Настроить auto-mitigation правила на будущее

---

### 5. Восстановление (Recovery)

- [ ] Убрать emergency rate limiting (постепенно)
- [ ] Проверить, что сервис полностью доступен
- [ ] Проверить, не были ли DDoS-атакой прикрыты другие атаки (отвлечение)
- [ ] Мониторинг 48 часов

---

### 6. Lessons Learned

- Есть ли DDoS protection (CDN, scrubbing)?
- Достаточна ли канальная ёмкость?
- Есть ли runbook по переключению на CDN?
- Нужно ли внедрить auto-scaling?

# ПЛЕЙБУК 11: DNS TUNNELING / C2 DETECTION

**Категория:** Command and Control
**Приоритет:** P1 Critical
**SLA реагирования:** 15 минут
**MITRE ATT&CK:** T1071.004 (DNS), T1572 (Protocol Tunneling)

---

### 1. Обнаружение (Detection)

**Триггеры / алерты:**
- DNS-мониторинг: аномально длинные DNS-запросы (>50 символов в поддомене)
- NTA: высокая частота DNS-запросов к одному домену
- SIEM: TXT-записи с высокой энтропией
- IDS: сигнатура dns2tcp / iodine / dnscat2
- DNS RPZ: запрос к известному C2-домену

**Suricata-правило:**

```
alert dns any any -> any any (msg:"DNS Tunneling - длинный поддомен (>50 символов)"; dns.query; pcre:"/^[a-z0-9]{50,}\./i"; sid:2100030; rev:1;)
```

```powershell
Get-BitLockerVolume -MountPoint "C:" | Select-Object -ExpandProperty KeyProtector
```

- [ ] **Отслеживать попытки входа** с утерянного устройства (по device ID)
- [ ] **Уведомить сотрудника** о сбросе паролей и необходимости смены на всех сервисах

---

### 4. Устранение (Eradication)

- [ ] Если устройство найдено — провести forensic check перед возвратом в эксплуатацию
- [ ] Если не найдено — считать данные скомпрометированными
- [ ] Оценить, какие данные были на устройстве
- [ ] При наличии ПДн — уведомить регулятора (152-ФЗ)

---

### 5. Восстановление (Recovery)

- [ ] Выдать сотруднику новое устройство
- [ ] Восстановить данные из бэкапа/облака
- [ ] Убедиться, что MFA настроена на новом устройстве
- [ ] Провести инструктаж по физической безопасности

---

### 6. Lessons Learned

- Был ли диск зашифрован?
- Есть ли MDM с возможностью Remote Wipe?
- Есть ли политика хранения данных на устройствах?
- Нужно ли усилить policy (mandatory encryption, timeout lock)?

## БЫСТРАЯ СПРАВКА: КАКОЙ ПЛЕЙБУК ИСПОЛЬЗОВАТЬ?

| Вы видите... | Плейбук |
|-------------|---------|
| Файлы зашифрованы, записка о выкупе | → **#1 Ransomware** |
| Пользователь перешёл по фишинг-ссылке | → **#2 Phishing** |
| AV/EDR обнаружил вредоносный файл | → **#3 Malware** |
| Массовые неудачные входы | → **#4 Brute Force** |
| Аномальный исходящий трафик | → **#5 Data Exfiltration** |
| Подозрительные действия сотрудника | → **#6 Insider Threat** |
| SQLi/XSS/RCE на веб-сервере | → **#7 Web Attack** |
| Сервис недоступен, трафик аномальный | → **#8 DDoS** |
| PsExec/WMI/RDP между рабочими станциями | → **#9 Lateral Movement** |
| Вход с необычной страны/устройства | → **#10 Unauthorized Access** |
| Длинные DNS-запросы, C2-активность | → **#11 DNS Tunneling / C2** |
| CPU 100% без причины, mining pool | → **#12 Cryptomining** |
| Compromised dependency / advisory | → **#13 Supply Chain** |
| DCSync, Golden Ticket, Mimikatz | → **#14 AD Compromise** |
| Утерян/украден ноутбук | → **#15 Lost/Stolen Device** |
