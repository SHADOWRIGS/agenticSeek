## Модуль 91: Эксфильтрация данных — Обнаружение и защита

### Что это за угроза

Эксфильтрация данных — финальный этап большинства APT-атак и одна из главных целей злоумышленников. Атакующие извлекают конфиденциальную информацию (базы данных, интеллектуальную собственность, персональные данные, финансовую документацию) за периметр организации. Каналы эксфильтрации разнообразны: HTTPS к облачным хранилищам, DNS-туннелирование, ICMP-каналы, шифрованные архивы по электронной почте, физические носители (USB), стеганография в изображениях и даже Bluetooth/Wi-Fi Direct.

Для защитника критически важно обнаружить эксфильтрацию до того, как значительный объём данных покинет организацию. Это требует комплексного мониторинга сетевого трафика, активности на конечных точках и контроля физических каналов.

### Индикаторы компрометации (IoC)

**Сетевые индикаторы:**
- Аномально большие объёмы исходящего трафика (особенно в нерабочее время)
- DNS-запросы с необычно длинными именами (>50 символов в поддомене)
- Высокая частота DNS-запросов к одному домену (>100 запросов/мин)
- HTTPS-соединения к IP-адресам вместо доменов
- Исходящий трафик на нестандартных портах (4443, 8443, 8080)
- Большие объёмы ICMP-трафика с нестандартным размером пакетов
- Подключения к известным файлообменникам (mega.nz, transfer.sh, anonfiles)
- Трафик к VPS/VPN-провайдерам, не используемым в организации
- Исходящие SSH/SCP-соединения к внешним серверам

**Индикаторы на хосте:**
- Создание крупных архивов (.zip, .rar, .7z) — особенно с паролем
- Массовое чтение файлов из каталогов с конфиденциальными данными
- Использование утилит типа `rar a -hp`, `7z a -p`, `gpg -c`
- Подключение USB-устройств (особенно неизвестных серийных номеров)
- Запуск утилит облачной синхронизации (rclone, gsutil, aws s3 cp)
- Процессы, генерирующие необычно большой сетевой трафик
- Использование средств разработки (curl, wget, python) для HTTP-запросов с передачей файлов

**Поведенческие индикаторы:**
- Доступ к данным за пределами обычной роли сотрудника
- Массовое скачивание файлов из корпоративных хранилищ
- Работа в нерабочее время с большими объёмами данных
- Попытки обхода DLP-систем (переименование расширений, разбиение файлов)

### Обнаружение

**SIEM-правила (Splunk SPL):**

```spl
# Обнаружение аномальных объёмов исходящего трафика
index=firewall sourcetype=paloalto:traffic direction=outbound
| stats sum(bytes_sent) as total_bytes by src_ip
| where total_bytes > 1073741824
| eval GB = round(total_bytes/1073741824, 2)
| sort -total_bytes
| table src_ip, GB, total_bytes

# DNS-туннелирование — длинные поддомены
index=dns sourcetype=dns
| eval subdomain_len = len(mvindex(split(query, "."), 0))
| where subdomain_len > 50
| stats count by src_ip, query
| where count > 10
| sort -count

# Подключение к файлообменникам
index=proxy sourcetype=squid OR sourcetype=bluecoat
| where match(url, "(?i)(mega\.nz|transfer\.sh|anonfiles|gofile\.io|dropmefiles|sendspace)")
| stats count values(url) as urls by src_ip, user
| sort -count
```

### Защита и предотвращение

**Многоуровневая стратегия:**

1. **Сетевой уровень:**
   - Развёртывание DLP на периметре (Forcepoint, InfoWatch, SearchInform)
   - Настройка прокси-сервера с SSL-инспекцией для всего HTTPS-трафика
   - Блокировка файлообменных сервисов на уровне прокси/DNS
   - Ограничение DNS-запросов через внутренний DNS-сервер (блокировка DoH/DoT)
   - Мониторинг и ограничение исходящего трафика по объёму (rate limiting)
   - Развёртывание Network DLP inline (не только passthrough)
   - Сегментация сети — отдельные VLAN для конфиденциальных систем

2. **Хостовый уровень:**
   - Endpoint DLP (DeviceLock, InfoWatch Person Monitor)
   - Контроль USB-устройств — белые списки разрешённых устройств
   - Блокировка или аудит использования облачных клиентов
   - Мониторинг файловых операций на серверах с конфиденциальными данными
   - Контроль установки ПО — запрет на rclone, winscp, filezilla без согласования

3. **Контроль доступа:**
   - Классификация данных (публичные / внутренние / конфиденциальные / совершенно секретные)
   - Принцип минимальных привилегий для доступа к данным
   - Разграничение доступа на уровне файловой системы и БД
   - DRM/IRM для критичных документов (Microsoft Purview, Vaultize)

4. **Организационные меры:**
   - Обучение сотрудников по политике обращения с данными
   - Регулярные аудиты прав доступа
   - Процедуры увольнения — ревокация доступа, контроль в период уведомления
   - NDA и подписки об ответственности

## Модуль 92: Шифровальщики (Ransomware) — Обнаружение и защита

### Что это за угроза

Программы-шифровальщики (ransomware) — один из самых разрушительных типов вредоносного ПО. Они шифруют файлы жертвы и требуют выкуп за ключ дешифрования. Современные ransomware-группы (LockBit, BlackCat/ALPHV, Clop, Akira) используют модель «двойного вымогательства»: сначала эксфильтрация данных, затем шифрование — с угрозой публикации украденных данных.

Для защитника задача — обнаружить ransomware на стадии до массового шифрования (разведка, закрепление, горизонтальное перемещение) или на самом раннем этапе шифрования, когда ущерб ещё минимален.

### Индикаторы компрометации (IoC)

**Ранние признаки (pre-encryption):**
- Отключение Volume Shadow Copy Service (VSS): `vssadmin delete shadows /all /quiet`
- Остановка служб бэкапа (Veeam, SQL Server, Exchange)
- Отключение Windows Defender и других антивирусов
- Удаление точек восстановления: `bcdedit /set {default} recoveryenabled No`
- Массовое сканирование SMB-шар (порт 445) в сети
- Использование PsExec / WMI / WMIC для горизонтального перемещения
- Загрузка/запуск инструментов типа Mimikatz, Cobalt Strike, AnyDesk

**Признаки активного шифрования:**
- Массовое переименование файлов с добавлением нового расширения (.locked, .encrypted, .crypt)
- Высокая нагрузка на диск (I/O) при чтении-записи множества файлов
- Появление файлов с требованием выкупа (README.txt, DECRYPT_FILES.html, HOW_TO_RECOVER.txt)
- Изменение обоев рабочего стола
- Массовое изменение MFT (Master File Table) за короткое время
- Изменение энтропии файлов (зашифрованные файлы имеют энтропию ~7.99 из 8)

**Сетевые признаки:**
- Обращение к C2-серверам (известные IP/домены из threat intelligence)
- Исходящие TOR-соединения
- SMB-трафик между рабочими станциями (нетипично для офиса)
- Попытки доступа к бэкап-серверам из нетипичных источников

### Обнаружение

**SIEM-правила (Splunk SPL):**

```spl
# Обнаружение удаления теневых копий (VSS)
index=wineventlog sourcetype=WinEventLog:Security OR sourcetype=sysmon
| search (CommandLine="*vssadmin*delete*shadows*" OR
          CommandLine="*wmic*shadowcopy*delete*" OR
          CommandLine="*bcdedit*recoveryenabled*No*")
| table _time, host, user, CommandLine, ParentCommandLine
| sort -_time

# Обнаружение массового переименования файлов (canary-file подход)
index=wineventlog sourcetype=WinEventLog:Security EventCode=4663
| where match(ObjectName, "\.(locked|encrypted|crypt|ransom|enc)$")
| stats count dc(ObjectName) as unique_files by host, SubjectUserName
| where count > 50 AND unique_files > 30
| sort -count

# Остановка служб бэкапа
index=wineventlog sourcetype=WinEventLog:System EventCode=7036
| where match(Message, "(?i)(veeam|sql server|exchange|backup)")
  AND match(Message, "stopped")
| stats count by host, Message
| where count > 3
```

**Canary-файлы (Honeyfiles):**

```python
#!/usr/bin/env python3
"""
canary_deploy.py — Развёртывание canary-файлов для раннего обнаружения ransomware.
Canary-файлы размещаются в критичных каталогах; при их изменении
генерируется немедленное оповещение.
"""
import os
import hashlib
import json
import time
import logging
from pathlib import Path
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler

CANARY_DIRS = [
    r"C:\Users\Public\Documents",
    r"C:\Shares\Finance",
    r"C:\Shares\HR",
    r"C:\Shares\Projects",
]

CANARY_NAMES = [
    "!IMPORTANT_README.docx",
    "~$budget_2026.xlsx",
    "Accounts_Receivable.pdf",
]

CANARY_REGISTRY = "canary_registry.json"

logging.basicConfig(
    filename="canary_monitor.log",
    level=logging.WARNING,
    format="%(asctime)s %(levelname)s %(message)s"
)

def create_canary_files():
    """Создаём canary-файлы в критичных каталогах."""
    registry = {}
    for directory in CANARY_DIRS:
        os.makedirs(directory, exist_ok=True)
        for name in CANARY_NAMES:
            path = os.path.join(directory, name)
            content = f"Canary file - DO NOT MODIFY - {time.time()}".encode()
            with open(path, "wb") as f:
                f.write(content)
            file_hash = hashlib.sha256(content).hexdigest()
            registry[path] = {
                "hash": file_hash,
                "created": time.time(),
                "size": len(content)
            }
    with open(CANARY_REGISTRY, "w") as f:
        json.dump(registry, f, indent=2)
    return registry


class CanaryHandler(FileSystemEventHandler):
    """Обработчик событий изменения canary-файлов."""

    def __init__(self, registry):
        self.registry = registry

    def on_modified(self, event):
        if event.src_path in self.registry:
            self._alert("MODIFIED", event.src_path)

    def on_deleted(self, event):
        if event.src_path in self.registry:
            self._alert("DELETED", event.src_path)

    def on_moved(self, event):
        if event.src_path in self.registry:
            self._alert("RENAMED", event.src_path, event.dest_path)

    def _alert(self, action, path, dest=None):
        msg = f"RANSOMWARE ALERT: canary file {action}: {path}"
        if dest:
            msg += f" -> {dest}"
        logging.critical(msg)
        # Здесь — интеграция с SIEM / оповещение SOC
        send_soc_alert(action, path, dest)


def send_soc_alert(action, path, dest=None):
    """Отправка оповещения в SOC через syslog/webhook."""
    import socket
    syslog_msg = f"<2>CANARY_ALERT action={action} path={path}"
    if dest:
        syslog_msg += f" dest={dest}"
    try:
        sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        sock.sendto(syslog_msg.encode(), ("siem.corp.local", 514))
        sock.close()
    except OSError:
        logging.error("Failed to send syslog alert")


if __name__ == "__main__":
    registry = create_canary_files()
    handler = CanaryHandler(registry)
    observer = Observer()
    for directory in CANARY_DIRS:
        observer.schedule(handler, directory, recursive=False)
    observer.start()
    print(f"[+] Canary monitoring active for {len(CANARY_DIRS)} directories")
    try:
        while True:

    except KeyboardInterrupt:

    observer.join()
```

## Модуль 93: Уничтожение данных (Wiper) — Обнаружение и защита

### Что это за угроза

Wiper-малварь — разновидность вредоносного ПО, цель которого — безвозвратное уничтожение данных. В отличие от ransomware, wiper не предлагает возможности восстановления: данные уничтожаются или повреждаются необратимо. Известные примеры: Shamoon (Saudi Aramco, 2012), NotPetya (2017), WhisperGate и HermeticWiper (Украина, 2022), CaddyWiper. Wiper-атаки особенно опасны, так как часто являются частью государственных кибератак (nation-state) и могут нанести катастрофический урон инфраструктуре.

Для защитника приоритет — обнаружить активность wiper до массового уничтожения и иметь надёжную стратегию восстановления.

### Индикаторы компрометации (IoC)

**Файловые индикаторы:**
- Массовое перезаписывание файлов нулями или случайными данными
- Повреждение MBR (Master Boot Record) или GPT (GUID Partition Table)
- Удаление/повреждение системных файлов (ntldr, bootmgr, boot.ini)
- Массовое удаление файлов без создания записей в Корзине
- Перезаписывание MFT (NTFS Master File Table)

**Системные индикаторы:**
- Прямой доступ к физическому диску (\\.\PhysicalDrive0) из пользовательского процесса
- Использование API: `NtRaiseHardError` (вызов BSOD)
- Загрузка драйвера для прямого доступа к диску (rawdisk.sys, EldoS)
- Остановка критических служб (как при ransomware) + нет файла с выкупом
- Перезагрузка системы после подозрительной активности

**Сетевые индикаторы:**
- Быстрое распространение по сети через SMB/WMI/PsExec (горизонтальное перемещение)
- Массовые подключения к \\C$, \\ADMIN$ на множество хостов
- Синхронное поведение — множество хостов затронуты в одно время

### Защита и предотвращение

**Многоуровневая защита от wiper-атак:**

1. **Защита загрузочных записей:**
   - Включить Secure Boot (UEFI) — предотвращает модификацию загрузчика
   - Windows: включить Measured Boot и Device Guard
   - Linux: настроить dm-verity для проверки целостности rootfs
   - BIOS-пароль на изменение порядка загрузки

2. **Защита файловой системы:**
   - Активировать аудит файловых операций (Windows Security Log 4663)
   - Настроить File Integrity Monitoring (OSSEC/Wazuh FIM, Tripwire)
   - NTFS-аудит для критичных каталогов
   - Immutable-флаги для критичных системных файлов (Linux: `chattr +i`)

3. **Сегментация и изоляция:**
   - Жёсткая сетевая сегментация — серверы БД и бэкапов в отдельных VLAN
   - Ограничение SMB-трафика между рабочими станциями (disable SMBv1, limit SMBv3)
   - Запрет прямого admin-доступа к серверам с рабочих станций (jump host / PAM)
   - Separate domain admin accounts (Red Forest / Tiered Admin model)

4. **Бэкапы (ещё более критичны, чем при ransomware):**
   - Air-gapped бэкапы — физически отключённые носители
   - Ежедневные snapshot'ы на СХД с поддержкой immutable snapshots
   - Регулярное тестирование восстановления из бэкапов (DR drill)
   - Бэкап системных образов (bare metal restore)

## Модуль 94: Захват ресурсов (Cryptomining) — Обнаружение и защита

### Что это за угроза

Resource Hijacking — захват вычислительных ресурсов жертвы для целей атакующего, чаще всего для майнинга криптовалют (cryptojacking). Атакующие устанавливают майнеры на серверы, рабочие станции, контейнеры и даже IoT-устройства. Ресурсы также могут использоваться для DDoS-атак (ботнет), спам-рассылки, проксирования трафика или обучения ML-моделей.

Cryptojacking часто воспринимается как «несерьёзная» угроза, однако он приводит к: значительному росту затрат на электричество и облачные ресурсы, деградации производительности, ускоренному износу оборудования и, главное, указывает на компрометацию системы (если установили майнер — могли установить что угодно).

### Индикаторы компрометации (IoC)

**Системные индикаторы:**
- Аномально высокая загрузка CPU/GPU (>80% длительно без причины)
- Процессы с именами: xmrig, minerd, cpuminer, ccminer, т2m, kworkerds
- Замаскированные процессы: имена, похожие на системные (svchost, crond, kworker)
- Cron-задачи или Scheduled Tasks с подозрительными скриптами
- Установленные пакеты для GPU-вычислений (CUDA, OpenCL) на серверах, где они не нужны

**Сетевые индикаторы:**
- Подключения к майнинг-пулам (pool.minexmr.com, xmr.pool.minergate.com, порты 3333, 4444, 5555, 14444)
- Stratum-протокол (JSON-RPC с методами mining.subscribe, mining.authorize)
- Постоянные исходящие соединения на нестандартных портах
- DNS-запросы к доменам майнинг-пулов

**Облачные индикаторы:**
- Необъяснимый рост стоимости облачных ресурсов (>200% от baseline)
- Создание неавторизованных VM/контейнеров (особенно GPU-инстансов)
- Необычное использование Spot/Preemptible инстансов
- API-вызовы для создания ресурсов из неизвестных IP

**Скрипт мониторинга CPU (Linux):**

```bash
#!/bin/bash
# cpu_anomaly_monitor.sh — обнаружение аномальной загрузки CPU
THRESHOLD=80
ALERT_COUNT=0
ALERT_THRESHOLD=5  # 5 последовательных проверок выше порога

while true; do
    CPU_USAGE=$(top -bn1 | grep "Cpu(s)" | awk '{print int($2)}')

    if [ "$CPU_USAGE" -gt "$THRESHOLD" ]; then
        ALERT_COUNT=$((ALERT_COUNT + 1))
        if [ "$ALERT_COUNT" -ge "$ALERT_THRESHOLD" ]; then
            # Собираем информацию о процессах
            TOP_PROCS=$(ps aux --sort=-%cpu | head -6)
            HOSTNAME=$(hostname)

            logger -t cryptomining-alert -p auth.crit \
                "HIGH CPU ALERT: ${CPU_USAGE}% on ${HOSTNAME} for ${ALERT_COUNT} checks"
            logger -t cryptomining-alert -p auth.crit \
                "Top processes: ${TOP_PROCS}"

            # Проверка сетевых подключений подозрительных процессов
            TOP_PID=$(ps aux --sort=-%cpu | sed -n '2p' | awk '{print $2}')
            CONNECTIONS=$(ss -tnp | grep "pid=${TOP_PID}")
            if [ -n "$CONNECTIONS" ]; then
                logger -t cryptomining-alert -p auth.crit \
                    "Network connections of PID ${TOP_PID}: ${CONNECTIONS}"
            fi
        fi
    else
        ALERT_COUNT=0
    fi

    sleep 30
done
```

## Модуль 95: Отказ в обслуживании (DoS/DDoS) — Обнаружение и защита

### Что это за угроза

DoS (Denial of Service) и DDoS (Distributed Denial of Service) — атаки, направленные на нарушение доступности сервиса. Типы атак:

- **Volumetric** (объёмные): UDP flood, ICMP flood, DNS amplification, NTP amplification, Memcached amplification — забивают канал связи
- **Protocol** (протокольные): SYN flood, Ping of Death, Smurf — исчерпывают ресурсы сетевого оборудования
- **Application Layer** (L7): HTTP flood, Slowloris, RUDY (R-U-Dead-Yet), DNS query flood — исчерпывают ресурсы приложения
- **Ransom DDoS (RDDoS)**: DDoS с вымогательством — демонстрационная атака + угроза масштабной

Для защитника критичны: раннее обнаружение, автоматическое митигирование, и быстрое восстановление доступности сервиса.

### Индикаторы компрометации (IoC)

**Сетевые индикаторы (volumetric):**
- Резкий рост входящего трафика (>10x от baseline)
- Трафик от одного протокола составляет >80% (UDP flood, ICMP flood)
- Множество пакетов с подменёнными IP-адресами (spoofed source)
- DNS-ответы без соответствующих запросов (amplification)
- Фрагментированные пакеты большого размера

**Индикаторы SYN Flood:**
- Большое количество полуоткрытых TCP-соединений (SYN_RECEIVED)
- Рост `netstat -s | grep "SYNs to LISTEN"` или `ss -s`
- Переполнение SYN backlog

**Индикаторы L7 (Application Layer):**
- Рост числа запросов к одному URL (>1000 req/s)
- HTTP-запросы без типичных заголовков браузера (User-Agent, Accept)
- Множество запросов с одинаковыми или отсутствующими cookie
- Slowloris: множество долгоживущих HTTP-соединений с медленной отправкой заголовков
- Рост времени ответа (latency) при умеренном трафике (L7 flood)

### Обнаружение

**SIEM-правила:**

```spl
# Обнаружение SYN Flood
index=firewall sourcetype=paloalto:traffic
| where action="deny" AND rule="default-deny"
| bucket _time span=1m
| stats count by _time, dest_ip, dest_port
| where count > 10000
| sort -count

# Обнаружение DNS Amplification
index=network sourcetype=dns
| where query_type="ANY" OR query_type="TXT"
| stats count sum(reply_size) as total_bytes by src_ip
| where count > 500 AND total_bytes > 52428800
| sort -total_bytes

# Рост входящего трафика — аномалия
index=netflow sourcetype=netflow
| bucket _time span=5m
| stats sum(bytes_in) as total_bytes_in by _time
| eventstats avg(total_bytes_in) as avg_bytes, stdev(total_bytes_in) as std_bytes
| eval anomaly = if(total_bytes_in > (avg_bytes + 3 * std_bytes), "YES", "NO")
| where anomaly="YES"
```

## Модуль 96: Манипуляция учётными записями — Обнаружение и защита

### Что это за угроза

Account Manipulation — техники, при которых атакующие создают, модифицируют или повышают привилегии учётных записей для сохранения доступа. Это включает: создание скрытых admin-аккаунтов, добавление пользователей в привилегированные группы, изменение паролей существующих аккаунтов, включение отключённых учёток, создание SSH-ключей, изменение политик доступа (GPO), добавление SPN для Kerberoasting, манипуляция SAML/OAuth-токенами.

Это одна из ключевых техник закрепления (persistence), часто используемая APT-группами.

### Индикаторы компрометации (IoC)

**Active Directory (Windows):**
- Создание учётной записи в AD (Event ID 4720)
- Добавление пользователя в привилегированную группу (Event ID 4728, 4732, 4756)
- Сброс пароля другого пользователя (Event ID 4724)
- Включение ранее отключённой учётной записи (Event ID 4722)
- Изменение UAC-флагов (Event ID 4738) — особенно `DONT_EXPIRE_PASSWD`, `PASSWD_NOTREQD`
- Создание/изменение объектов GPO (Event ID 5136, 5137)
- Добавление SPN к учётной записи (Event ID 4742 с изменением servicePrincipalName)
- Создание доверительных отношений (Trust) с внешними доменами

**Linux/SSH:**
- Создание пользователя через useradd/adduser (audit log `ADD_USER`)
- Добавление пользователя в sudo/wheel группу
- Добавление SSH-ключа в `~/.ssh/authorized_keys`
- Изменение `/etc/passwd` или `/etc/shadow`
- Изменение `/etc/sudoers` или файлов в `/etc/sudoers.d/`
- Создание cron-задачи от имени root

**Облако / SaaS:**
- Создание IAM-пользователя/роли/политики
- Добавление Access Key для IAM-пользователя
- Изменение MFA-настроек
- Создание OAuth-приложения с расширенными правами
- Изменение правил SAML-федерации

## Модуль 97: Сбор электронной почты — Обнаружение и защита

### Что это за угроза

Email Collection — техника, при которой атакующие получают доступ к почтовым ящикам для кражи конфиденциальной переписки. Методы: прямой доступ к почтовому серверу (Exchange, Zimbra), компрометация учётных данных и вход через OWA/IMAP, создание правил пересылки (forwarding rules) для перехвата будущей почты, использование Graph API/EWS для программного доступа, кража OST/PST-файлов с рабочих станций.

Компрометация электронной почты руководства (BEC — Business Email Compromise) — один из самых финансово разрушительных типов кибератак (ФБР: >$2.7B ущерба в 2022 году).

### Индикаторы компрометации (IoC)

**Exchange / Microsoft 365:**
- Создание правил пересылки (forwarding rules) на внешние адреса
- Доступ к почтовому ящику из нетипичного IP/геолокации
- Массовое чтение писем через EWS/Graph API
- Аномальные OAuth-разрешения (Mail.Read, Mail.ReadWrite)
- PowerShell-доступ к Exchange: `New-InboxRule`, `Set-Mailbox -ForwardingSmtpAddress`
- Экспорт PST через `New-MailboxExportRequest`
- Вход в OWA из TOR/VPN (нетипично для пользователя)

**IMAP/POP3:**
- Массовое скачивание писем через IMAP FETCH
- Подключение неизвестных IMAP-клиентов
- Аутентификация с необычными User-Agent

**Хостовые индикаторы:**
- Доступ к OST/PST-файлам: `C:\Users\*\AppData\Local\Microsoft\Outlook\*.ost`
- Копирование PST-файлов на USB или сетевой диск
- Утилиты типа `PSTPassword`, `kernel-pst-viewer`

### Обнаружение

**SIEM-правила:**

```spl
# Обнаружение создания правил пересылки (Exchange/O365)
index=o365 sourcetype=o365:management:activity Operation="Set-Mailbox"
| where match(Parameters, "ForwardingSmtpAddress|ForwardingSm")
| table _time, UserId, Parameters, ClientIP
| sort -_time

# Обнаружение создания inbox rules с пересылкой
index=o365 sourcetype=o365:management:activity Operation="New-InboxRule"
| where match(Parameters, "Forward|Redirect|Delete")
| table _time, UserId, Parameters, ClientIP

# Массовое чтение писем через EWS
index=exchange sourcetype=exchange:ews
| where Operation="GetItem" OR Operation="FindItem"
| stats count by User, ClientIPAddress, span=1h
| where count > 500
| sort -count

# Доступ к PST/OST файлам
index=sysmon sourcetype=sysmon EventCode=1
| where match(CommandLine, "(?i)\.(pst|ost)")
| table _time, host, User, CommandLine, Image
```

## Модуль 98: Перехват буфера обмена — Обнаружение и защита

### Что это за угроза

Clipboard Hijacking — техника, при которой вредоносное ПО мониторит или подменяет содержимое буфера обмена. Основные сценарии: подмена криптовалютных адресов при копировании (clipboard replacer), перехват паролей, скопированных из менеджера паролей, кража данных через мониторинг clipboard, внедрение вредоносного контента через clipboard (paste-jacking).

Хотя это может показаться узкой угрозой, clipboard-атаки привели к потерям миллионов долларов (подмена BTC-адресов при крупных транзакциях).

### Индикаторы компрометации (IoC)

**Системные индикаторы:**
- Процессы, использующие API: `SetClipboardViewer`, `AddClipboardFormatListener`
- Частые вызовы `OpenClipboard` / `GetClipboardData` от нетипичных процессов
- Процесс, который одновременно читает и записывает в clipboard (подмена)
- Незнакомые процессы с доступом к clipboard API

**Поведенческие индикаторы:**
- Скопированный криптокошелёк отличается от вставленного
- Пароль из менеджера паролей не работает при вставке (подменён)
- В буфере обмена появляется контент, который пользователь не копировал

### Обнаружение

**Sysmon-конфигурация для мониторинга clipboard API:**

```xml
<!-- Sysmon config — мониторинг доступа к clipboard -->
<Sysmon schemaversion="4.90">
    <EventFiltering>
        <!-- Clipboard monitoring (Sysmon Event ID 24) -->
        <ClipboardChange onmatch="include">
            <!-- Логировать все изменения clipboard -->
        </ClipboardChange>

        <!-- Мониторинг процессов, обращающихся к clipboard API -->
        <ProcessAccess onmatch="include">
            <CallTrace condition="contains">user32.dll+SetClipboardViewer</CallTrace>
            <CallTrace condition="contains">user32.dll+AddClipboardFormatListener</CallTrace>
        </ProcessAccess>
    </EventFiltering>
</Sysmon>
```

**Sigma-правило:**

```yaml

    product: windows

    selection:
        CommandLine|contains:
            - 'GetClipboardData'
            - 'SetClipboardViewer'
            - 'AddClipboardFormatListener'
            - 'clip.exe'
    filter:
        Image|contains:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\RuntimeBroker.exe'
```

### Защита и предотвращение

1. **Endpoint-защита:**
   - EDR с мониторингом clipboard API
   - Application Whitelisting — только доверенные процессы
   - Регулярное сканирование антивирусом
   - Мониторинг автозапуска (Autoruns от Sysinternals)

2. **Пользовательские практики:**
   - Использование менеджеров паролей с автозаполнением (не через clipboard)
   - Проверка криптоадресов перед отправкой (сравнить первые и последние символы)
   - Очистка clipboard после использования (менеджеры паролей делают это автоматически)

3. **Браузерная защита:**
   - Расширения, предупреждающие о paste-jacking
   - Content Security Policy (CSP) для защиты от веб-clipboard-атак
   - Браузерные настройки: запрет доступа к clipboard без разрешения

4. **Корпоративная политика:**
   - GPO: ограничение clipboard в RDP-сессиях
   - Отключение clipboard-шаринга в виртуальных машинах

```

```

## Модуль 99: Захват экрана и кейлоггинг — Обнаружение и защита

### Что это за угроза

Screen Capture и Keylogging — техники наблюдения, при которых вредоносное ПО: делает снимки экрана (screenshots), записывает видео с экрана, перехватывает нажатия клавиш (кейлоггер), захватывает веб-камеру и микрофон. Эти данные используются для кражи учётных данных, конфиденциальной информации и наблюдения за действиями пользователя.

Кейлоггеры бывают программные (userspace hooks, kernel-level) и аппаратные (USB-адаптер между клавиатурой и компьютером).

### Индикаторы компрометации (IoC)

**Кейлоггер:**
- Процессы, устанавливающие глобальные hooks: `SetWindowsHookEx(WH_KEYBOARD_LL, ...)`
- Raw Input Registration: `RegisterRawInputDevices` для клавиатуры
- Создание файлов логов с нажатиями (.log, .txt в скрытых директориях)
- Нетипичные процессы, читающие keyboard input

**Screen Capture:**
- Вызовы API: `BitBlt`, `PrintWindow`, `CaptureScreen`, `GDI+ Screenshot`
- Создание файлов .png/.jpg/.bmp в temp-директориях
- Регулярные скриншоты (каждые N секунд — паттерн timer + screenshot)
- Нетипичные процессы с доступом к Display Device Context

**Веб-камера/микрофон:**
- Обращение к устройствам захвата (DirectShow, Media Foundation)
- Активация камеры без пользовательского приложения (индикатор LED)
- Процессы с доступом к `/dev/video0` (Linux) или Camera API (Windows)

### Обнаружение

**SIEM-правила:**

```spl
# Обнаружение SetWindowsHookEx (кейлоггер)
index=sysmon sourcetype=sysmon EventCode=1
| where match(CommandLine, "(?i)(SetWindowsHookEx|keyboard|keylog|GetAsyncKeyState)")
| table _time, host, Image, CommandLine, User, ParentImage
| sort -_time

# Обнаружение массового создания скриншотов
index=sysmon sourcetype=sysmon EventCode=11
| where match(TargetFilename, "(?i)\.(png|jpg|bmp|gif)$")
  AND match(TargetFilename, "(?i)(temp|appdata|programdata)")
| bucket _time span=5m
| stats count by _time, host, Image
| where count > 10
| sort -count

# Доступ к веб-камере от нетипичного процесса
index=sysmon sourcetype=sysmon EventCode=1
| where match(CommandLine, "(?i)(ffmpeg.*video|/dev/video|DirectShow|MediaFoundation)")
| where NOT match(Image, "(?i)(zoom|teams|skype|chrome|firefox|obs)")
| table _time, host, Image, CommandLine
```

### Защита и предотвращение

1. **Anti-keylogging:**

## Модуль 100: Антифорензика — Обнаружение и защита

### Что это за угроза

Антифорензика (Anti-Forensics) — комплекс техник, используемых атакующими для уничтожения, сокрытия или искажения улик своей деятельности. Цель — затруднить или сделать невозможным расследование инцидента. Техники включают: очистку логов (Event Log clearing), timestomping (изменение временных меток файлов), удаление артефактов (prefetch, shellbags, журналы), уничтожение файлов (secure delete), шифрование вредоносного ПО, обфускацию, использование fileless-малвари (работа в памяти без файлов на диске), манипуляцию файловой системой.

Для защитника критически важно: обнаружить сам факт антифорензической активности (что атакующий пытается замести следы), обеспечить сохранность улик до того, как они будут уничтожены, и иметь резервные источники логов.

### Индикаторы компрометации (IoC)

**Очистка логов:**
- Event ID 1102: «The audit log was cleared» (Security)
- Event ID 104: «The System log file was cleared» (System)
- Команды: `wevtutil cl Security`, `Clear-EventLog -LogName Security`
- Linux: `> /var/log/auth.log`, `rm -rf /var/log/*`, `history -c`

**Timestomping:**
- Несоответствие $STANDARD_INFORMATION и $FILE_NAME timestamps в NTFS MFT
- Все 4 timestamp'а идентичны (Created = Modified = Accessed = MFT Modified)
- Timestamp до даты создания ОС / до даты производства диска
- Linux: `touch -t`, `touch -d`, `debugfs`

**Уничтожение артефактов:**
- Удаление Prefetch: `del /q C:\Windows\Prefetch\*`
- Очистка USNJournal: `fsutil usn deletejournal /d C:`
- Удаление ShimCache/AMCache
- Очистка браузерной истории
- Удаление файлов .evtx

**Fileless-техники:**
- PowerShell скрипты, загруженные из интернета и выполненные в памяти
- WMI-события для персистенции без файлов
- Рефлективная загрузка DLL
- .NET-assembly, загруженные в память

### Обнаружение

**SIEM-правила — обнаружение очистки логов:**

```spl
# Очистка журнала событий Windows
index=wineventlog (EventCode=1102 OR EventCode=104)
| table _time, host, SubjectUserName, LogName
| sort -_time

# Обнаружение команд очистки логов
index=sysmon sourcetype=sysmon EventCode=1
| where match(CommandLine, "(?i)(wevtutil\s+(cl|clear-log)|Clear-EventLog|Remove-EventLog)")
| table _time, host, User, CommandLine, ParentCommandLine

# Обнаружение удаления USN Journal
index=sysmon sourcetype=sysmon EventCode=1
| where match(CommandLine, "(?i)fsutil\s+usn\s+deletejournal")
| table _time, host, User, CommandLine

# Обнаружение timestomping (Sysmon)
index=sysmon sourcetype=sysmon EventCode=2
| where CreationUtcTime != PreviousCreationUtcTime
| eval time_diff = abs(strptime(CreationUtcTime, "%Y-%m-%d %H:%M:%S") -
                       strptime(PreviousCreationUtcTime, "%Y-%m-%d %H:%M:%S"))
| where time_diff > 86400
| table _time, host, Image, TargetFilename, CreationUtcTime, PreviousCreationUtcTime
```

### Защита и предотвращение

**Стратегия устойчивости к антифорензике:**

1. **Централизованное логирование (основной щит):**
   - **Все логи пересылаются в центральный SIEM в реальном времени**
   - Атакующий может очистить локальные логи, но копия уже в SIEM
   - Syslog forwarding → rsyslog/syslog-ng → SIEM (Wazuh/Splunk/ELK)
   - Windows Event Forwarding (WEF) → Windows Event Collector → SIEM

```bash
# rsyslog — пересылка логов на центральный сервер
# /etc/rsyslog.d/50-remote.conf
*.* @@siem.corp.local:514   # TCP
# или с TLS:
# *.* @@(o)siem.corp.local:6514

# Windows Event Forwarding (WEF) — через GPO:
# Computer Configuration > Administrative Templates >
#   Windows Components > Event Forwarding >
#   Configure target Subscription Manager:
#   Server=http://wef-collector.corp.local:5985/wsman/SubscriptionManager/WEC
```

2. **Write-Once Log Storage:**
   - WORM-хранилище для логов (S3 Object Lock, Write-Once NAS)
   - Подписание логов (log signing) — обнаружение модификации
   - Хранение логов минимум 1 год (требования 152-ФЗ, PCI DSS)

3. **Мониторинг антифорензической активности:**
   - Оповещение при Event ID 1102 (очистка Security log) — всегда красный флаг
   - Мониторинг timestomping через Sysmon Event ID 2
   - Обнаружение удаления log-файлов через auditd

4. **Forensic Readiness — подготовка к расследованию:**
   - Заранее настроенные процедуры сбора артефактов
   - Готовые скрипты для снятия дампа памяти и triage
   - Forensic Toolkit на съёмном носителе (USB с Linux live + инструменты)
   - Цепочка хранения доказательств (chain of custody) — шаблоны документов

**Скрипт быстрого forensic triage (Linux):**

```bash
#!/bin/bash
# forensic_triage.sh — быстрый сбор артефактов до их уничтожения
# Запускать при первых признаках компрометации
# ВАЖНО: запускать с READ-ONLY носителя!

OUTPUT_DIR="/media/forensic_usb/triage_$(hostname)_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$OUTPUT_DIR"

echo "[*] Forensic triage started: $(date -u)"

# 1. Дамп памяти (приоритет — volatile data first)
echo "[*] Capturing memory info..."
free -m > "$OUTPUT_DIR/memory_free.txt"
cat /proc/meminfo > "$OUTPUT_DIR/meminfo.txt"

# 2. Сетевые соединения (volatile!)
echo "[*] Capturing network connections..."
ss -tunap > "$OUTPUT_DIR/network_connections.txt"
ip addr > "$OUTPUT_DIR/ip_addresses.txt"
ip route > "$OUTPUT_DIR/ip_routes.txt"
iptables -L -n -v > "$OUTPUT_DIR/iptables.txt" 2>/dev/null
cat /etc/resolv.conf > "$OUTPUT_DIR/dns_config.txt"

# 3. Процессы
echo "[*] Capturing processes..."
ps auxef > "$OUTPUT_DIR/processes.txt"
ls -la /proc/*/exe 2>/dev/null > "$OUTPUT_DIR/proc_exe_links.txt"
ls -la /proc/*/fd 2>/dev/null | head -500 > "$OUTPUT_DIR/proc_fd_sample.txt"

# 4. Автозапуск и cron
echo "[*] Capturing persistence..."
crontab -l > "$OUTPUT_DIR/crontab_root.txt" 2>/dev/null
ls -la /etc/cron.d/ > "$OUTPUT_DIR/cron_d.txt"
ls -la /etc/cron.daily/ > "$OUTPUT_DIR/cron_daily.txt"
systemctl list-unit-files --type=service > "$OUTPUT_DIR/systemd_services.txt"

# 5. Пользователи и авторизация
echo "[*] Capturing user data..."
cat /etc/passwd > "$OUTPUT_DIR/passwd.txt"
cat /etc/group > "$OUTPUT_DIR/group.txt"
last -a > "$OUTPUT_DIR/last_logins.txt"
lastlog > "$OUTPUT_DIR/lastlog.txt"
who -a > "$OUTPUT_DIR/who.txt"

# 6. SSH-ключи
echo "[*] Capturing SSH keys..."
find /home -name "authorized_keys" -exec cp --parents {} "$OUTPUT_DIR/" \; 2>/dev/null
find /root -name "authorized_keys" -exec cp --parents {} "$OUTPUT_DIR/" \; 2>/dev/null

# 7. Логи (копирование до потенциального уничтожения)
echo "[*] Capturing logs..."
cp -a /var/log/auth.log* "$OUTPUT_DIR/" 2>/dev/null
cp -a /var/log/secure* "$OUTPUT_DIR/" 2>/dev/null
cp -a /var/log/syslog* "$OUTPUT_DIR/" 2>/dev/null
cp -a /var/log/messages* "$OUTPUT_DIR/" 2>/dev/null

# 8. Файловая система — недавно изменённые файлы
echo "[*] Finding recently modified files..."
find / -mtime -7 -type f \
    -not -path "/proc/*" -not -path "/sys/*" -not -path "/dev/*" \
    -not -path "/run/*" 2>/dev/null > "$OUTPUT_DIR/recent_files_7days.txt"

# 9. Хеши критичных файлов
echo "[*] Computing hashes..."
sha256sum /usr/sbin/sshd /usr/bin/sudo /bin/bash /usr/bin/crontab \
    > "$OUTPUT_DIR/critical_hashes.txt" 2>/dev/null

# 10. Итоговая контрольная сумма всего собранного
echo "[*] Computing integrity hash..."
find "$OUTPUT_DIR" -type f -exec sha256sum {} \; > "$OUTPUT_DIR/INTEGRITY_HASHES.txt"

echo "[+] Triage complete: $OUTPUT_DIR"
echo "[+] Files collected: $(find "$OUTPUT_DIR" -type f | wc -l)"
```

**Скрипт Windows forensic triage:**

```powershell
# forensic_triage.ps1 — быстрый сбор артефактов (Windows)
$OutputDir = "D:\Forensic\triage_$($env:COMPUTERNAME)_$(Get-Date -Format 'yyyyMMdd_HHmmss')"
New-Item -ItemType Directory -Path $OutputDir -Force | Out-Null

Write-Host "[*] Forensic triage started: $(Get-Date -Format 'u')"

# 1. Сетевые соединения (volatile)
Write-Host "[*] Network connections..."
Get-NetTCPConnection | Export-Csv "$OutputDir\tcp_connections.csv" -NoTypeInformation
Get-NetUDPEndpoint | Export-Csv "$OutputDir\udp_endpoints.csv" -NoTypeInformation
Get-DnsClientCache | Export-Csv "$OutputDir\dns_cache.csv" -NoTypeInformation

# 2. Процессы
Write-Host "[*] Processes..."
Get-Process | Select-Object Id, ProcessName, Path, StartTime, CPU, WorkingSet64 |
    Export-Csv "$OutputDir\processes.csv" -NoTypeInformation

# 3. Службы
Write-Host "[*] Services..."
Get-Service | Select-Object Name, DisplayName, Status, StartType |
    Export-Csv "$OutputDir\services.csv" -NoTypeInformation

# 4. Автозапуск
Write-Host "[*] Autoruns..."
Get-CimInstance Win32_StartupCommand |
    Export-Csv "$OutputDir\startup_commands.csv" -NoTypeInformation

# 5. Scheduled Tasks
Write-Host "[*] Scheduled tasks..."
Get-ScheduledTask | Where-Object State -ne 'Disabled' |
    Select-Object TaskName, TaskPath, State |
    Export-Csv "$OutputDir\scheduled_tasks.csv" -NoTypeInformation

# 6. Пользователи
Write-Host "[*] Users..."
Get-LocalUser | Export-Csv "$OutputDir\local_users.csv" -NoTypeInformation
Get-LocalGroupMember -Group "Administrators" 2>$null |
    Export-Csv "$OutputDir\admins.csv" -NoTypeInformation

# 7. Логи (последние 24 часа)
Write-Host "[*] Event logs (last 24h)..."
$since = (Get-Date).AddDays(-1)
Get-WinEvent -FilterHashtable @{LogName='Security'; StartTime=$since} -MaxEvents 5000 2>$null |
    Export-Csv "$OutputDir\security_events_24h.csv" -NoTypeInformation
Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=$since} -MaxEvents 2000 2>$null |
    Export-Csv "$OutputDir\system_events_24h.csv" -NoTypeInformation

# 8. Prefetch
Write-Host "[*] Prefetch..."
Copy-Item "C:\Windows\Prefetch\*.pf" "$OutputDir\" -ErrorAction SilentlyContinue

# 9. Недавние файлы
Write-Host "[*] Recent files..."
Get-ChildItem "C:\Users\*\AppData\Roaming\Microsoft\Windows\Recent" -ErrorAction SilentlyContinue |
    Export-Csv "$OutputDir\recent_files.csv" -NoTypeInformation

# 10. Контрольные суммы
Write-Host "[*] Computing hashes..."
Get-ChildItem "$OutputDir" -File | ForEach-Object {
    [PSCustomObject]@{
        File = $_.Name
        SHA256 = (Get-FileHash $_.FullName -Algorithm SHA256).Hash
    }
} | Export-Csv "$OutputDir\INTEGRITY_HASHES.csv" -NoTypeInformation

Write-Host "[+] Triage complete: $OutputDir"
Write-Host "[+] Files: $((Get-ChildItem $OutputDir -File).Count)"
```

### Защита и предотвращение

**Комплексная стратегия:**

1. **Централизованное логирование — основная защита**
2. **Immutable log storage — WORM/Object Lock**
3. **Мониторинг антифорензической активности как индикатора атаки**
4. **Forensic Readiness — готовность к расследованию**
5. **Регулярное тестирование процедур сбора артефактов**

### Инструменты защитника

| Инструмент | Назначение | Лицензия |
|---|---|---|
| **Sysmon** | Мониторинг timestomping (EID 2), process creation | Бесплатно (MS) |
| **Wazuh** | Централизованное логирование + FIM + anti-tampering | Open Source |
| **Velociraptor** | Forensic triage, hunting, artifact collection | Open Source |
| **KAPE** | Быстрый сбор forensic-артефактов Windows | Бесплатно |
| **Volatility** | Анализ дампов оперативной памяти | Open Source |
| **Plaso / log2timeline** | Создание super-timeline из всех артефактов | Open Source |
| **Autopsy** | GUI для forensic-анализа дисков | Open Source |
| **Chainsaw** | Быстрый поиск по Windows Event Logs (Sigma) | Open Source |
| **WORM / S3 Object Lock** | Write-once хранилище логов | Зависит от реализации |

### Практическое задание

**Задание 100.1: Обнаружение антифорензической активности**
1. Настройте Sysmon Event ID 2 (timestomping detection)
2. Создайте SIEM-правило для Event ID 1102 (очистка Security log)
3. Настройте auditd для мониторинга /var/log/ и history-файлов
4. Настройте централизованное логирование (rsyslog → SIEM)
5. Проверьте: очистка локальных логов не влияет на копию в SIEM

**Задание 100.2: Forensic Readiness — подготовка к расследованию**
1. Разверните Velociraptor для сбора артефактов с endpoints
2. Создайте forensic triage kit (USB с Live Linux + скрипты)
3. Проведите тестовый triage: снимите артефакты с Windows-машины (скрипт выше)
4. Создайте super-timeline из собранных артефактов (Plaso/log2timeline)
5. Напишите playbook «Первые 30 минут расследования» с пошаговыми действиями

**Задание 100.3: Итоговый кейс — Full Incident Response**
1. В лабораторной среде симулируйте: атака → компрометация → попытка очистки логов
2. Роль защитника: обнаружьте очистку логов в SIEM, проведите triage, восстановите timeline
3. Определите: как атакующий попал в систему, что делал, что пытался скрыть
4. Напишите полный IR-отчёт с timeline'ом, IoC и рекомендациями
5. Презентуйте результаты расследования (10-минутный briefing для руководства)

**Критерии оценки:**
- Очистка Security log немедленно обнаружена в SIEM
- Centralized logging работает — данные сохранены несмотря на очистку на хосте
- Timeline восстановлен из нескольких источников (SIEM + Prefetch + MFT)
- IR-отчёт содержит: timeline, IoC, root cause, рекомендации
- Briefing для руководства — чёткий, нетехнический, с actionable items

### Общие принципы защиты от Impact-техник

1. **Бэкапы, бэкапы, бэкапы** — 3-2-1, immutable, тестировать регулярно
2. **Централизованное логирование** — все логи в SIEM до того, как атакующий их удалит
3. **Сегментация** — критичные системы, бэкапы, админы — в отдельных сегментах
4. **DLP** — контроль каналов утечки (сеть, USB, email, облако)
5. **Мониторинг аномалий** — базовый профиль (baseline) для трафика, CPU, аккаунтов
6. **Forensic Readiness** — готовность к расследованию ДО инцидента
7. **Incident Response Plan** — плейбуки для каждого типа инцидента, тренировки
