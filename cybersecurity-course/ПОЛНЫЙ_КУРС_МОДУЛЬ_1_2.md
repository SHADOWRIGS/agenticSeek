### Урок 1.1: Модель OSI и TCP/IP — что должен знать защитник

#### Теория

Модель OSI (Open Systems Interconnection) — это семиуровневая абстракция, описывающая, как данные перемещаются от одного устройства к другому по сети. Для SOC-аналитика модель OSI — это карта: она показывает, на каком уровне произошла атака, и подсказывает, где искать следы.

**Семь уровней OSI с точки зрения защитника:**

| Уровень | Название | Что передаётся | Что мониторить | Пример атаки |
|---------|----------|---------------|----------------|--------------|
| 7 | Прикладной (Application) | HTTP, DNS, SMTP, FTP | WAF-логи, прокси-логи, DNS-запросы | SQL-инъекция, XSS, фишинг |
| 6 | Представления (Presentation) | SSL/TLS, кодировки | Сертификаты, аномальные шифры | SSL stripping, downgrade |
| 5 | Сеансовый (Session) | Сессии TCP, NetBIOS | Необычные сессии, длительные подключения | Session hijacking |
| 4 | Транспортный (Transport) | TCP/UDP порты | Сканирование портов, аномальные флаги | SYN flood, port scan |
| 3 | Сетевой (Network) | IP-адреса, маршрутизация | IP-спуфинг, аномальный трафик между VLAN | IP spoofing, ICMP tunnel |
| 2 | Канальный (Data Link) | MAC-адреса, Ethernet-фреймы | ARP-таблицы, дупликаты MAC | ARP spoofing, MAC flood |
| 1 | Физический (Physical) | Биты, электрические сигналы | Физический доступ к портам | Rogue AP, физический тап |

**Модель TCP/IP** — упрощённая версия OSI, которая используется в реальных сетях. Она состоит из 4 уровней:

1. **Канальный (Link)** — Ethernet, Wi-Fi, ARP
2. **Интернет (Internet)** — IP, ICMP, IGMP
3. **Транспортный (Transport)** — TCP, UDP
4. **Прикладной (Application)** — HTTP, DNS, SSH, SMTP

Для защитника важно понимать: **каждый уровень — это отдельная поверхность атаки**. Атакующий может работать на уровне 2 (ARP-спуфинг), а может на уровне 7 (SQL-инъекция). SOC-аналитик должен уметь читать артефакты на каждом уровне.

**Инкапсуляция** — ключевой механизм. Когда вы отправляете HTTP-запрос, он «оборачивается» слоями:

```
[Ethernet-заголовок][IP-заголовок][TCP-заголовок][HTTP-данные]
```

В Wireshark вы видите все эти слои и можете кликнуть на каждый, чтобы увидеть подробности. Это критично при расследовании инцидента: иногда атака видна только на одном уровне.

**TCP трёхстороннее рукопожатие (three-way handshake):**

```
Клиент  →  SYN          →  Сервер     (хочу подключиться)
Клиент  ←  SYN-ACK      ←  Сервер     (подтверждаю, готов)
Клиент  →  ACK          →  Сервер     (подключились)
```

SYN flood — классическая атака: отправляем тысячи SYN без ACK, сервер исчерпывает ресурсы на полуоткрытые соединения.

**Шаг 4: Скрипт для быстрого анализа PCAP (Python)**

```python
#!/usr/bin/env python3
"""Быстрый анализ PCAP-файла: статистика IP, портов, протоколов."""

from collections import Counter
import subprocess
import sys

def analyze_pcap(pcap_file):
    # Извлекаем IP-адреса источника
    result = subprocess.run(
        ["tshark", "-r", pcap_file, "-T", "fields",
         "-e", "ip.src", "-e", "ip.dst", "-e", "tcp.dstport",
         "-e", "_ws.col.Protocol"],
        capture_output=True, text=True
    )

    src_ips = Counter()
    dst_ips = Counter()
    dst_ports = Counter()
    protocols = Counter()

    for line in result.stdout.strip().split("\n"):
        if not line.strip():
            continue
        parts = line.split("\t")
        if len(parts) >= 1 and parts[0]:
            src_ips[parts[0]] += 1
        if len(parts) >= 2 and parts[1]:
            dst_ips[parts[1]] += 1
        if len(parts) >= 3 and parts[2]:
            dst_ports[parts[2]] += 1
        if len(parts) >= 4 and parts[3]:
            protocols[parts[3]] += 1

    print("=" * 60)
    print(f"АНАЛИЗ PCAP: {pcap_file}")
    print("=" * 60)

    print("\n--- ТОП-10 IP-источников ---")
    for ip, count in src_ips.most_common(10):
        print(f"  {ip:20s}  {count} пакетов")

    print("\n--- ТОП-10 IP-назначения ---")
    for ip, count in dst_ips.most_common(10):
        print(f"  {ip:20s}  {count} пакетов")

    print("\n--- ТОП-10 портов назначения ---")
    for port, count in dst_ports.most_common(10):
        print(f"  порт {port:6s}  {count} пакетов")

    print("\n--- Протоколы ---")
    for proto, count in protocols.most_common(10):
        print(f"  {proto:15s}  {count} пакетов")

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print("Использование: python3 analyze_pcap.py <файл.pcap>")
        sys.exit(1)
    analyze_pcap(sys.argv[1])
```

### Урок 1.2: IP-адресация, маршрутизация, VLAN — сегментация как защита

#### Теория

**IP-адресация** — фундамент, без которого невозможно ни мониторить сеть, ни расследовать инцидент. Каждое устройство в сети имеет IP-адрес; задача SOC-аналитика — знать, какие адреса «свои», какие «чужие», и замечать аномалии.

**IPv4-адрес** состоит из 4 октетов (32 бита): `192.168.1.100`. Маска подсети определяет, какая часть адреса — сеть, а какая — хост.

**Частные диапазоны (RFC 1918):**
- `10.0.0.0/8` — 16 млн адресов (крупные организации)
- `172.16.0.0/12` — 1 млн адресов
- `192.168.0.0/16` — 65 тыс. адресов (домашние/малые сети)

Для защитника критично понимать **CIDR-нотацию**: `/24` значит первые 24 бита — сеть (256 адресов), `/16` — 65 536, `/32` — один конкретный хост.

**Маршрутизация** — процесс передачи пакетов между сетями. Маршрутизатор (роутер) читает IP-заголовок и решает, в какой интерфейс отправить пакет. Таблица маршрутизации — это «карта» сети.

**VLAN (Virtual LAN)** — одна из важнейших защитных мер. VLAN логически разделяет одну физическую сеть на несколько изолированных сегментов. Это называется **сетевая сегментация** и является основой принципа **defense-in-depth (эшелонированная оборона)**.

Зачем сегментация:
- Если атакующий проник в сеть бухгалтерии, он НЕ ДОЛЖЕН иметь доступ к серверам разработки.
- IoT-устройства (камеры, принтеры) — в отдельном VLAN, потому что у них слабая защита.
- DMZ (демилитаризованная зона) — отдельный сегмент для внешних сервисов (веб-сервер, почта).

**Типовая сегментация корпоративной сети:**

| VLAN ID | Назначение | Пример подсети | Доступ к интернету | Доступ к серверам |
|---------|------------|----------------|--------------------|--------------------|
| 10 | Управление (IT) | 10.0.10.0/24 | Да | Полный |
| 20 | Сотрудники | 10.0.20.0/24 | Через прокси | Ограниченный |
| 30 | Гости | 10.0.30.0/24 | Через прокси | Нет |
| 40 | IoT/камеры | 10.0.40.0/24 | Нет | Только к NVR |
| 50 | DMZ (веб-серверы) | 10.0.50.0/24 | Да | Ограниченный |
| 100 | Серверы | 10.0.100.0/24 | Нет (NAT) | — |

**Скрипт: инвентаризация сети (Python)**

```python
#!/usr/bin/env python3
"""Быстрая инвентаризация хостов в подсети через ARP."""

import subprocess
import re
import sys

def scan_subnet(subnet):
    """Сканирует подсеть и возвращает список живых хостов."""
    print(f"Сканирование {subnet} ...")
    result = subprocess.run(
        ["nmap", "-sn", subnet, "-oG", "-"],
        capture_output=True, text=True, timeout=120
    )

    hosts = []
    for line in result.stdout.split("\n"):
        match = re.search(r"Host: (\d+\.\d+\.\d+\.\d+) \(([^)]*)\)", line)
        if match:
            ip = match.group(1)
            hostname = match.group(2) or "неизвестно"
            status = "Up" if "Status: Up" in line else "Down"
            hosts.append({"ip": ip, "hostname": hostname, "status": status})

    return hosts

def main():
    subnet = sys.argv[1] if len(sys.argv) > 1 else "192.168.1.0/24"
    hosts = scan_subnet(subnet)

    print(f"\nНайдено хостов: {len(hosts)}")
    print("-" * 50)
    for h in hosts:
        print(f"  {h['ip']:18s}  {h['hostname']}")

if __name__ == "__main__":
    main()
```

### Урок 1.3: DNS, DHCP, ARP — атаки и защита на каждом протоколе

#### Теория

Три протокола — DNS, DHCP и ARP — работают «в тени», но без них сеть не функционирует. И именно они — излюбленная цель атакующих, потому что изначально спроектированы **без аутентификации**.

**DNS (Domain Name System)** — переводит имена в IP-адреса. Когда вы вводите `google.com`, DNS-резолвер отвечает `142.250.185.206`.

Атаки на DNS:
- **DNS spoofing/cache poisoning** — подмена ответа, жертва попадает на фишинговый сайт
- **DNS tunneling** — передача данных через DNS-запросы (обход firewall)
- **DNS zone transfer** — утечка всех записей домена

Защита DNS:
- DNSSEC (подписание записей)
- Мониторинг длинных DNS-запросов (>50 символов = возможный туннель)
- Запрет zone transfer для внешних IP
- Использование DoH/DoT (DNS over HTTPS/TLS)

**DHCP (Dynamic Host Configuration Protocol)** — автоматическая выдача IP-адресов.

Атаки на DHCP:
- **Rogue DHCP** — подмена DHCP-сервера, жертва получает «неправильный» шлюз (трафик идёт через атакующего)
- **DHCP starvation** — исчерпание пула адресов

Защита DHCP:
- DHCP snooping (управляемые коммутаторы)
- Статическая привязка IP-MAC для критичных хостов
- Мониторинг новых DHCP-серверов в сети

**ARP (Address Resolution Protocol)** — связывает IP-адрес с MAC-адресом в локальной сети.

Атаки на ARP:
- **ARP spoofing (ARP poisoning)** — атакующий отправляет ложные ARP-ответы, становится «man-in-the-middle»

Защита ARP:
- Dynamic ARP Inspection (DAI) на коммутаторе
- Статические ARP-записи для шлюзов
- arpwatch для мониторинга изменений

**Скрипт обнаружения DNS-туннеля (Python):**

```python
#!/usr/bin/env python3
"""Обнаружение потенциального DNS-туннелирования по длине запросов."""

import subprocess
from collections import defaultdict

def detect_dns_tunnel(interface="eth0", count=1000):
    """Захватывает DNS-пакеты и ищет аномально длинные запросы."""
    print(f"Мониторинг DNS на {interface} ({count} пакетов)...")

    result = subprocess.run(
        ["tshark", "-i", interface, "-c", str(count),
         "-Y", "dns.flags.response == 0",
         "-T", "fields", "-e", "ip.src", "-e", "dns.qry.name"],
        capture_output=True, text=True, timeout=300
    )

    stats = defaultdict(list)
    suspicious = []

    for line in result.stdout.strip().split("\n"):
        if not line.strip():
            continue
        parts = line.split("\t")
        if len(parts) >= 2:
            src_ip = parts[0]
            domain = parts[1]
            stats[src_ip].append(domain)

            # Подозрительно: домен длиннее 50 символов
            if len(domain) > 50:
                suspicious.append((src_ip, domain))

            # Подозрительно: высокая энтропия (много случайных символов)
            unique_chars = len(set(domain.replace(".", "")))
            if unique_chars > 20 and len(domain) > 30:
                suspicious.append((src_ip, domain))

    print(f"\nВсего DNS-запросов: {sum(len(v) for v in stats.values())}")
    print(f"Уникальных IP: {len(stats)}")

    if suspicious:
        print(f"\n⚠️  ПОДОЗРИТЕЛЬНЫЕ ЗАПРОСЫ ({len(suspicious)}):")
        for ip, domain in suspicious[:20]:
            print(f"  {ip:18s} → {domain[:80]}")
    else:
        print("\n✅ Подозрительных DNS-запросов не обнаружено.")

if __name__ == "__main__":
    detect_dns_tunnel()
```

### Урок 1.4: HTTP/HTTPS, TLS — что видит SOC-аналитик в трафике

#### Теория

**HTTP (HyperText Transfer Protocol)** — основной протокол веба. Работает на порту 80 (или 8080). Передаёт данные **открытым текстом** — SOC-аналитик видит в Wireshark/Suricata всё: URL, заголовки, тело запроса, cookies.

**HTTPS = HTTP + TLS** — шифрованный вариант на порту 443. После TLS-рукопожатия содержимое зашифровано. SOC-аналитик видит только:
- IP-адреса и порты (из заголовка IP/TCP)
- **SNI (Server Name Indication)** — домен в первом пакете TLS (ClientHello). Это критично для мониторинга — даже при HTTPS вы видите, к какому домену обращается клиент.
- JA3/JA3S-хеш — «отпечаток» TLS-клиента/сервера (позволяет идентифицировать малварь)

**HTTP-методы, важные для SOC:**

| Метод | Что делает | На что смотреть |
|-------|-----------|-----------------|
| GET | Получение ресурса | Подозрительные параметры (SQLi в URL) |
| POST | Отправка данных | Эксфильтрация, reverse shell |
| PUT | Загрузка файла | Web shell upload |
| DELETE | Удаление | Деструктивные действия |

**HTTP-коды ответа, важные для SOC:**
- `200` — OK (нормально)
- `301/302` — Редирект (фишинг может использовать цепочки редиректов)
- `401/403` — Не авторизован / Запрещено (brute-force попытки)
- `404` — Не найдено (сканирование директорий)
- `500` — Ошибка сервера (возможно, инъекция сработала)

**TLS-версии и безопасность:**
- TLS 1.0 / 1.1 — **устаревшие**, уязвимы (POODLE, BEAST)
- TLS 1.2 — нормально, но зависит от cipher suite
- TLS 1.3 — **рекомендуется**, быстрее и безопаснее

**JA3-отпечаток** — хеш параметров TLS ClientHello (версия, cipher suites, extensions). Позволяет идентифицировать клиент без расшифровки трафика. Малварь часто имеет уникальный JA3.

#### Практика: анализ HTTP/HTTPS трафика

```bash

  -T fields -e frame.time -e ip.src -e ip.dst \
```

**Скрипт анализа HTTP-логов (Python):**

```python
#!/usr/bin/env python3
"""Анализ HTTP-логов: поиск SQLi, сканирования директорий, подозрительных UA."""

import re
from collections import Counter

SQLI_PATTERNS = [
    r"(?i)(union\s+select|or\s+1\s*=\s*1|'\s*or\s*'|drop\s+table)",
    r"(?i)(;\s*exec|xp_cmdshell|information_schema)",
    r"(?i)(<script|javascript:|onerror=|onload=)",  # XSS
]

SCANNER_PATHS = [
    r"(?i)(\.env|wp-admin|wp-login|phpmyadmin|\.git/config)",
    r"(?i)(admin|login|backup|\.bak|\.sql|\.zip)",
    r"(?i)(shell\.php|cmd\.php|webshell|c99|r57)",
]

def analyze_http_log(log_lines):
    """Анализирует строки HTTP-лога."""
    sqli_attempts = []
    scanner_hits = []
    status_codes = Counter()
    user_agents = Counter()

    for line in log_lines:
        # Поиск SQLi/XSS
        for pattern in SQLI_PATTERNS:
            if re.search(pattern, line):
                sqli_attempts.append(line.strip()[:200])
                break

        # Поиск сканеров
        for pattern in SCANNER_PATHS:
            if re.search(pattern, line):
                scanner_hits.append(line.strip()[:200])
                break

        # HTTP-коды (ищем 3-цифровый код)
        code_match = re.search(r'\s(\d{3})\s', line)
        if code_match:
            status_codes[code_match.group(1)] += 1

    print("=" * 60)
    print("АНАЛИЗ HTTP-ЛОГОВ")
    print("=" * 60)

    if sqli_attempts:
        print(f"\n⚠️  SQLi/XSS ПОПЫТКИ ({len(sqli_attempts)}):")
        for attempt in sqli_attempts[:10]:
            print(f"  {attempt}")

    if scanner_hits:
        print(f"\n⚠️  СКАНИРОВАНИЕ ДИРЕКТОРИЙ ({len(scanner_hits)}):")
        for hit in scanner_hits[:10]:
            print(f"  {hit}")

    print(f"\nHTTP-коды ответов:")
    for code, count in status_codes.most_common():
        flag = " ⚠️" if code in ("401", "403", "500") else ""
        print(f"  {code}: {count}{flag}")

# Пример использования:
# with open("/var/log/apache2/access.log") as f:
#     analyze_http_log(f.readlines())
```

### Урок 2.2: Командная строка: файлы, процессы, права, логи

#### Теория

Командная строка Linux — основной инструмент SOC-аналитика. GUI на серверах чаще всего нет, а расследование инцидентов требует быстрой работы с файлами, процессами и логами.

**Файловая система Linux — структура:**

### Урок 2.3: Сетевые утилиты: netstat, ss, ip, iptables, nftables

#### Теория

Сетевые утилиты Linux — «глаза» защитника в сети. Они показывают, какие соединения активны, какие порты открыты, и позволяют фильтровать трафик.

**ss (socket statistics)** — замена устаревшему netstat, быстрее и информативнее:

```bash
# Все TCP-соединения с именами процессов
ss -tnp

# Только слушающие TCP-порты
ss -tlnp

# Фильтр: соединения к конкретному порту
ss -tn dst :443

# Фильтр: соединения от конкретного IP
ss -tn src 10.0.0.50

# Статистика сокетов
ss -s
```

**iptables** — классический межсетевой экран Linux. Работает с цепочками правил:
- **INPUT** — входящий трафик к этой машине
- **OUTPUT** — исходящий трафик от этой машины
- **FORWARD** — проходящий трафик (для роутера)

```bash
# Показать все правила с номерами строк
sudo iptables -L -n -v --line-numbers

# Заблокировать IP
sudo iptables -A INPUT -s 192.168.1.100 -j DROP

# Разрешить SSH только из подсети
sudo iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/24 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP

# Логировать подозрительный трафик
sudo iptables -A INPUT -p tcp --dport 4444 -j LOG --log-prefix "SUSPICIOUS_4444: "
sudo iptables -A INPUT -p tcp --dport 4444 -j DROP

# Ограничить количество подключений (защита от brute-force)
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m recent --set --name SSH
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
  -m recent --update --seconds 60 --hitcount 5 --name SSH -j DROP
```

**nftables** — современная замена iptables (с ядра 3.13+):

```bash
# Показать текущую конфигурацию
sudo nft list ruleset

# Создать таблицу и цепочку
sudo nft add table inet filter
sudo nft add chain inet filter input { type filter hook input priority 0 \; policy drop \; }

# Разрешить SSH
sudo nft add rule inet filter input tcp dport 22 accept

# Заблокировать IP
sudo nft add rule inet filter input ip saddr 192.168.1.100 drop

# Логирование
sudo nft add rule inet filter input tcp dport 4444 log prefix \"SUSPICIOUS: \" drop
```

#### Практика: скрипт мониторинга сетевых соединений

```python
#!/usr/bin/env python3
"""Мониторинг новых сетевых соединений. Алертит на подозрительные порты."""

import subprocess
import time
from datetime import datetime

SUSPICIOUS_PORTS = {4444, 5555, 6666, 8888, 9999, 1337, 31337, 12345}
KNOWN_PORTS = {22, 53, 80, 443, 8080, 8443}

def get_connections():
    """Получает текущие ESTABLISHED TCP-соединения."""
    result = subprocess.run(
        ["ss", "-tn", "state", "established"],
        capture_output=True, text=True
    )
    connections = set()
    for line in result.stdout.strip().split("\n")[1:]:
        parts = line.split()
        if len(parts) >= 5:
            local = parts[3]
            remote = parts[4]
            connections.add((local, remote))
    return connections

def main():
    print(f"[{datetime.now()}] Запуск мониторинга соединений...")
    print(f"Подозрительные порты: {SUSPICIOUS_PORTS}")
    known = get_connections()
    print(f"Текущих соединений: {len(known)}")

    while True:
        time.sleep(5)
        current = get_connections()
        new_conns = current - known

        for local, remote in new_conns:
            remote_port = int(remote.rsplit(":", 1)[-1]) if ":" in remote else 0
            local_port = int(local.rsplit(":", 1)[-1]) if ":" in local else 0

            if remote_port in SUSPICIOUS_PORTS or local_port in SUSPICIOUS_PORTS:
                print(f"⚠️  [{datetime.now()}] ALERT: Подозрительное соединение "
                      f"{local} → {remote}")
            else:
                print(f"[{datetime.now()}] Новое соединение: {local} → {remote}")

        known = current

if __name__ == "__main__":
    main()
```

### Урок 2.4: Логирование: journalctl, syslog, auditd — настройка и анализ

#### Теория

Логи — «чёрный ящик» системы. Без логов расследование инцидента невозможно. Задача SOC-аналитика — знать, где какие логи, как их читать, и как настроить централизованный сбор.

**Системы логирования Linux:**

| Система | Файл/Команда | Что логирует |
|---------|-------------|--------------|
| syslog/rsyslog | `/var/log/syslog` | Системные события |
| auth.log | `/var/log/auth.log` | Авторизация (SSH, sudo, su) |
| journald | `journalctl` | Все сервисы systemd |
| auditd | `/var/log/audit/audit.log` | Аудит (файлы, процессы, syscalls) |
| kern.log | `/var/log/kern.log` | Ядро (драйверы, ошибки) |
| fail2ban | `/var/log/fail2ban.log` | Блокировки IP |

**auditd** — мощнейший инструмент аудита. Может отслеживать:
- Доступ к файлам (кто прочитал /etc/shadow)
- Изменения файлов (кто изменил /etc/passwd)
- Запуск процессов (кто запустил nmap)
- Системные вызовы (execve, connect, open)

#### Практика: настройка auditd

```bash

-w /etc/shadow -p wa -k identity
-w /etc/group -p wa -k identity

-w /etc/sudoers -p wa -k sudoers

# Мониторинг SSH-конфигурации
-w /etc/ssh/sshd_config -p wa -k sshd_config

# Мониторинг cron (persistence!)
-w /etc/crontab -p wa -k cron
-w /etc/cron.d/ -p wa -k cron
-w /var/spool/cron/ -p wa -k cron

# Мониторинг запуска процессов
-a always,exit -F arch=b64 -S execve -k exec_commands

# Мониторинг сетевых подключений
-a always,exit -F arch=b64 -S connect -k network_connect

# Мониторинг загрузки модулей ядра
-a always,exit -F arch=b64 -S init_module -S finit_module -k kernel_modules
```

**Скрипт анализа логов auth.log (Python):**

```python
#!/usr/bin/env python3
"""Анализ auth.log: brute-force, успешные входы, sudo."""

import re
from collections import Counter, defaultdict

def analyze_auth_log(filepath="/var/log/auth.log"):
    failed_logins = Counter()  # IP → кол-во неудачных входов
    successful_logins = []
    sudo_commands = []

    with open(filepath, "r") as f:
        for line in f:
            # Неудачные SSH-входы
            match = re.search(
                r"Failed password for (?:invalid user )?(\S+) from (\S+)", line
            )
            if match:
                user, ip = match.groups()
                failed_logins[ip] += 1

            # Успешные SSH-входы
            match = re.search(
                r"Accepted (?:password|publickey) for (\S+) from (\S+)", line
            )
            if match:
                user, ip = match.groups()
                timestamp = line[:15]
                successful_logins.append((timestamp, user, ip))

            # Команды sudo
            match = re.search(
                r"(\S+)\s+sudo.*COMMAND=(.+)", line
            )
            if match:
                user = match.group(1)
                cmd = match.group(2).strip()
                sudo_commands.append((user, cmd))

    print("=" * 60)
    print("АНАЛИЗ AUTH.LOG")
    print("=" * 60)

    # Brute-force (>10 попыток)
    bruteforce = {ip: c for ip, c in failed_logins.items() if c > 10}
    if bruteforce:
        print(f"\n⚠️  BRUTE-FORCE ({len(bruteforce)} IP):")
        for ip, count in sorted(bruteforce.items(), key=lambda x: -x[1]):
            print(f"  {ip:20s}  {count} попыток")

    # Успешные входы
    if successful_logins:
        print(f"\n✅ УСПЕШНЫЕ ВХОДЫ (последние 10):")
        for ts, user, ip in successful_logins[-10:]:
            print(f"  {ts}  {user:12s}  от {ip}")

    # Sudo-команды
    if sudo_commands:
        print(f"\n🔧 SUDO-КОМАНДЫ (последние 10):")
        for user, cmd in sudo_commands[-10:]:
            print(f"  {user:12s}  {cmd[:80]}")

if __name__ == "__main__":
    analyze_auth_log()
```

```bash
WATCH_DIRS="/tmp /var/tmp /dev/shm /var/www /etc/cron.d"

    fullpath="${dir}${file}"

    owner=$(stat -c '%U' "$fullpath" 2>/dev/null)

    # Алерт на исполняемые файлы

        echo "⚠️  ALERT: Исполняемый файл создан: $fullpath (владелец: $owner)" | \

    fi
done
```

```bash
#!/bin/bash
# simple_blocker.sh — блокировка IP после N неудачных SSH-попыток

THRESHOLD=10
LOGFILE="/var/log/auth.log"
BLOCKLIST="/var/log/blocked_ips.txt"

touch "$BLOCKLIST"

grep "Failed password" "$LOGFILE" | \
  grep -oP 'from \K[\d.]+' | sort | uniq -c | sort -rn | \
while read count ip; do
    if [ "$count" -ge "$THRESHOLD" ]; then
        if ! grep -q "$ip" "$BLOCKLIST"; then
            echo "[$(date)] Блокировка $ip ($count попыток)" >> "$BLOCKLIST"
            sudo iptables -A INPUT -s "$ip" -j DROP
            echo "⛔ Заблокирован: $ip ($count неудачных попыток)"
        fi
    fi
done
```

**Скрипт 4: Проверка целостности конфигураций**

```bash
#!/bin/bash
# config_integrity.sh — сравнение хешей критичных файлов с baseline

BASELINE="/var/lib/baseline_hashes.txt"
CURRENT="/tmp/current_hashes.txt"
CRITICAL_FILES=(
    /etc/passwd /etc/shadow /etc/group /etc/sudoers
    /etc/ssh/sshd_config /etc/crontab
    /etc/hosts /etc/resolv.conf
)

# Создать baseline (запустить один раз на чистой системе):
# sudo sha256sum "${CRITICAL_FILES[@]}" > /var/lib/baseline_hashes.txt

if [ ! -f "$BASELINE" ]; then
    echo "Создаю baseline..."
    sha256sum "${CRITICAL_FILES[@]}" 2>/dev/null > "$BASELINE"
    echo "Baseline создан: $BASELINE"
    exit 0
fi

# Сравнить текущие хеши с baseline
sha256sum "${CRITICAL_FILES[@]}" 2>/dev/null > "$CURRENT"

echo "Проверка целостности конфигураций..."
CHANGED=0
while IFS= read -r line; do
    hash=$(echo "$line" | awk '{print $1}')
    file=$(echo "$line" | awk '{print $2}')
    baseline_hash=$(grep "$file" "$BASELINE" | awk '{print $1}')

    if [ "$hash" != "$baseline_hash" ]; then
        echo "⚠️  ИЗМЕНЁН: $file"
        CHANGED=$((CHANGED + 1))
    fi
done < "$CURRENT"

if [ "$CHANGED" -eq 0 ]; then
    echo "✅ Все файлы без изменений."
else
    echo "⚠️  Изменено файлов: $CHANGED"
fi

rm -f "$CURRENT"
```

```powershell
Write-Host "Поиск подозрительных процессов..." -ForegroundColor Yellow

# Процессы из нетипичных директорий
$suspiciousPaths = @('\\Temp\\', '\\AppData\\Local\\Temp\\',
    '\\Downloads\\', '\\Public\\', '\\ProgramData\\')

Get-Process | ForEach-Object {
    $proc = $_
    try {
        $path = $proc.Path
        if ($path) {
            foreach ($sp in $suspiciousPaths) {
                if ($path -match [regex]::Escape($sp)) {
                    [PSCustomObject]@{
                        Name = $proc.Name
                        PID  = $proc.Id
                        Path = $path
                        CPU  = [math]::Round($proc.CPU, 2)
                        Flag = "Подозрительная директория"
                    }
                    break
                }
            }
        }
    } catch {}
}  | Format-Table -AutoSize

# Процессы без подписи
Write-Host "`nПроцессы без цифровой подписи:" -ForegroundColor Yellow
Get-Process | Where-Object { $_.Path } | ForEach-Object {
    $sig = Get-AuthenticodeSignature $_.Path -ErrorAction SilentlyContinue
    if ($sig.Status -ne 'Valid') {
        [PSCustomObject]@{
            Name   = $_.Name
            PID    = $_.Id
            Path   = $_.Path
            Signed = $sig.Status
        }
    }
} | Format-Table -AutoSize
```

### Урок 3.3: Active Directory: структура, GPO, основы защиты

#### Теория

**Active Directory (AD)** — служба каталогов Microsoft, сердце корпоративной сети Windows. Контролирует аутентификацию, авторизацию, групповые политики. Компрометация AD = полный контроль над сетью.

**Структура AD:**
- **Домен** — логическая единица (например, `company.local`)
- **Контроллер домена (DC)** — сервер, хранящий базу AD
- **Организационные единицы (OU)** — контейнеры для объектов
- **Объекты** — пользователи, компьютеры, группы
- **GPO** — групповые политики, применяемые к OU

**Ключевые атаки на AD:**
- Kerberoasting (извлечение TGS-хешей)
- Golden/Silver Ticket (подделка Kerberos-тикетов)
- Pass-the-Hash / Pass-the-Ticket
- DCSync (репликация базы AD)
- AdminSDHolder abuse

**Основы защиты AD:**

```powershell
# Аудит: найти пользователей с SPN (уязвимы к Kerberoasting)
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName |
    Select-Object Name, ServicePrincipalName

# Аудит: пользователи, не требующие Kerberos preauthentication (AS-REP roasting)
Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true} |
    Select-Object Name, Enabled

# Аудит: администраторы домена
Get-ADGroupMember "Domain Admins" -Recursive |
    Select-Object Name, ObjectClass, DistinguishedName

# Аудит: компьютеры с устаревшей ОС
Get-ADComputer -Filter * -Properties OperatingSystem |
    Where-Object { $_.OperatingSystem -match "Windows (7|XP|2008)" } |
    Select-Object Name, OperatingSystem

# Установка пароля минимум 14 символов через GPO:
# GPO → Computer Config → Policies → Windows Settings → Security Settings →
#   Account Policies → Password Policy → Minimum password length → 14

# Включить Protected Users group (защита от Pass-the-Hash)
Add-ADGroupMember -Identity "Protected Users" -Members "AdminUser"
```

### Урок 3.4: Криптография: хеши, шифрование, PKI, TLS

#### Теория

Криптография — основа безопасности. SOC-аналитик должен понимать:
- Хеш-функции (целостность)
- Симметричное шифрование (скорость)
- Асимметричное шифрование (обмен ключами)
- PKI и сертификаты (доверие)
- TLS (защита канала)

**Хеш-функции** — преобразуют данные произвольной длины в фиксированную строку. Однонаправленные: из хеша нельзя получить исходные данные.

| Алгоритм | Длина | Статус | Применение |
|----------|-------|--------|------------|
| MD5 | 128 бит | Устаревший, коллизии | Только для checksum |
| SHA-1 | 160 бит | Устаревший | Не использовать |
| SHA-256 | 256 бит | Актуальный | Проверка файлов, подписи |
| SHA-512 | 512 бит | Актуальный | Высокая безопасность |

```bash
# Хеш файла (проверка целостности)
sha256sum /etc/passwd
md5sum suspicious_file.exe

# Сравнение хешей (скачанный файл vs оригинал)
echo "expected_hash  filename" | sha256sum --check
```

**Python: работа с хешами**

```python
#!/usr/bin/env python3
"""Вычисление хешей файлов и проверка по базам VirusTotal."""

import hashlib
import sys

def hash_file(filepath):
    """Вычисляет MD5, SHA-1 и SHA-256 хеши файла."""
    md5 = hashlib.md5()
    sha1 = hashlib.sha1()
    sha256 = hashlib.sha256()

    with open(filepath, "rb") as f:
        while chunk := f.read(8192):
            md5.update(chunk)
            sha1.update(chunk)
            sha256.update(chunk)

    return {
        "md5": md5.hexdigest(),
        "sha1": sha1.hexdigest(),
        "sha256": sha256.hexdigest(),
    }

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print("Использование: python3 hash_file.py <файл>")
        sys.exit(1)

    hashes = hash_file(sys.argv[1])
    print(f"MD5:    {hashes['md5']}")
    print(f"SHA-1:  {hashes['sha1']}")
    print(f"SHA-256: {hashes['sha256']}")
    print(f"\nПроверка на VirusTotal:")
    print(f"  https://www.virustotal.com/gui/file/{hashes['sha256']}")
```

```
Клиент → [Проверка сертификата, обмен ключами]           → Сервер
Клиент ↔ [Шифрованный канал установлен]                  ↔ Сервер
```

### Урок 4.1: Как атакующий проводит разведку и как это видит SOC

#### Теория

Разведка — первая фаза любой атаки (MITRE ATT&CK: Reconnaissance / Discovery). Атакующий собирает информацию: какие хосты в сети, какие порты открыты, какие сервисы работают, какие версии ПО.

**Типы разведки:**

| Тип | Что делает | Как видит SOC |
|-----|-----------|---------------|
| Пассивная | OSINT, Shodan, Google dorks | Не видит (нет трафика к вашей сети) |
| Активная сетевая | Nmap, Masscan | IDS алерты, логи файрвола |
| Active Directory | BloodHound, PowerView | Sysmon, Windows Event Log |
| Веб-приложения | Nikto, Gobuster, SQLmap | WAF-логи, access.log |

**Nmap — глазами защитника:**

Nmap отправляет специально сформированные пакеты для определения открытых портов и сервисов. Каждый тип скана выглядит по-разному в трафике:

| Тип сканирования | Флаги TCP | Что видит IDS | Скрытность |
|-----------------|-----------|---------------|------------|
| SYN scan (-sS) | SYN | Множество SYN без ACK | Средняя |
| Connect scan (-sT) | Full handshake | Полные TCP-сессии | Низкая |
| NULL scan (-sN) | Нет флагов | Пакеты без флагов | Высокая |
| FIN scan (-sF) | FIN | Одинокие FIN-пакеты | Высокая |
| XMAS scan (-sX) | FIN+PSH+URG | «Рождественские» пакеты | Высокая |
| UDP scan (-sU) | UDP | UDP на закрытые порты | Высокая |

#### Практика: обнаружение сканирования

**Suricata-правила для обнаружения Nmap:**

```yaml
# /etc/suricata/rules/local.rules

# Обнаружение SYN-сканирования (множество SYN к разным портам)
alert tcp any any -> $HOME_NET any (msg:"SCAN: Possible Nmap SYN scan"; \
  flags:S,12; threshold:type threshold, track by_src, count 50, seconds 10; \
  sid:1000100; rev:1;)

# Обнаружение NULL-сканирования
alert tcp any any -> $HOME_NET any (msg:"SCAN: TCP NULL scan detected"; \
  flags:0; sid:1000101; rev:1;)

# Обнаружение XMAS-сканирования
alert tcp any any -> $HOME_NET any (msg:"SCAN: TCP XMAS scan detected"; \
  flags:FPU; sid:1000102; rev:1;)

# Обнаружение -sV (version detection) — специфический probe
alert tcp any any -> $HOME_NET any (msg:"SCAN: Nmap service version probe"; \
  flow:to_server,established; content:"OPTIONS / HTTP"; \
  sid:1000103; rev:1;)

# Обнаружение Masscan (отличается от Nmap TTL и window size)
alert tcp any any -> $HOME_NET any (msg:"SCAN: Possible Masscan scan"; \
  flags:S; window:1024; sid:1000104; rev:1;)
```

**Скрипт: анализ логов на предмет сканирования (Python)**

```python
#!/usr/bin/env python3
"""Анализ логов Suricata для обнаружения сканирования."""

import json
from collections import Counter, defaultdict
from datetime import datetime

def analyze_suricata_eve(eve_path="/var/log/suricata/eve.json"):
    """Анализирует eve.json и ищет признаки сканирования."""
    scanners = defaultdict(lambda: {"ports": set(), "count": 0, "first": None, "last": None})

    with open(eve_path) as f:
        for line in f:
            try:
                event = json.loads(line)
            except json.JSONDecodeError:
                continue

            if event.get("event_type") != "flow":
                continue

            src = event.get("src_ip", "")
            dst_port = event.get("dest_port", 0)
            timestamp = event.get("timestamp", "")

            if src and dst_port:
                scanners[src]["ports"].add(dst_port)
                scanners[src]["count"] += 1
                if not scanners[src]["first"]:
                    scanners[src]["first"] = timestamp
                scanners[src]["last"] = timestamp

    print("=" * 60)
    print("АНАЛИЗ НА ПРЕДМЕТ СКАНИРОВАНИЯ")
    print("=" * 60)

    for ip, data in sorted(scanners.items(), key=lambda x: len(x[1]["ports"]), reverse=True):
        port_count = len(data["ports"])
        if port_count > 20:  # >20 уникальных портов = скорее всего скан
            print(f"\n⚠️  ВЕРОЯТНОЕ СКАНИРОВАНИЕ: {ip}")
            print(f"  Уникальных портов: {port_count}")
            print(f"  Всего потоков: {data['count']}")
            print(f"  Первый: {data['first']}")
            print(f"  Последний: {data['last']}")
            print(f"  Топ-порты: {sorted(list(data['ports']))[:20]}")

if __name__ == "__main__":
    analyze_suricata_eve()
```

### Урок 4.2: Suricata IDS: установка, правила, обнаружение

#### Теория

**Suricata** — высокопроизводительная IDS/IPS с открытым кодом. Анализирует сетевой трафик в реальном времени и генерирует алерты по правилам.

**Режимы работы:**
- **IDS (Intrusion Detection System)** — только обнаруживает и логирует
- **IPS (Intrusion Prevention System)** — обнаруживает И блокирует

**Формат правила Suricata:**

```
action protocol src_ip src_port -> dst_ip dst_port (options;)
```

- **action**: alert, drop, pass, reject
- **protocol**: tcp, udp, icmp, http, dns, tls
- **options**: msg, content, pcre, flow, threshold, sid, rev

#### Практика: написание правил Suricata

```yaml
# Правило: обнаружение reverse shell на порту 4444
alert tcp $HOME_NET any -> $EXTERNAL_NET 4444 (msg:"MALWARE: Possible reverse shell to port 4444"; \
  flow:to_server,established; sid:1000200; rev:1;)

# Правило: обнаружение PowerShell download cradle
alert http $HOME_NET any -> $EXTERNAL_NET any (msg:"EXECUTION: PowerShell download cradle"; \
  flow:to_server,established; \
  http.user_agent; content:"PowerShell"; nocase; \
  http.uri; pcre:"/\.(exe|ps1|bat|dll|vbs)/i"; \
  sid:1000201; rev:1;)

# Правило: обнаружение эксфильтрации через DNS (длинные запросы)
alert dns $HOME_NET any -> any any (msg:"EXFILTRATION: Possible DNS tunnel (long query)"; \
  dns.query; pcre:"/^.{60,}/"; \
  threshold:type limit, track by_src, count 1, seconds 60; \
  sid:1000202; rev:1;)

# Правило: обнаружение brute-force SSH
alert tcp $EXTERNAL_NET any -> $HOME_NET 22 (msg:"BRUTEFORCE: SSH brute-force attempt"; \
  flow:to_server; \
  threshold:type threshold, track by_src, count 5, seconds 120; \
  sid:1000203; rev:1;)

# Правило: обнаружение Mimikatz (по User-Agent или содержимому)
alert http any any -> any any (msg:"CREDENTIAL: Possible Mimikatz download"; \
  flow:to_client,established; \
  http.response_body; content:"mimikatz"; nocase; \
  sid:1000204; rev:1;)
```

**Тестирование правил:**

```bash

# Мониторинг eve.json (JSON-формат, для SIEM)
sudo tail -f /var/log/suricata/eve.json | python3 -m json.tool
```

### Урок 4.3: Анализ трафика: Wireshark, tcpdump, Zeek — практика

#### Теория

Анализ трафика — ключевой навык SOC-аналитика. Три основных инструмента:

| Инструмент | Назначение | Когда использовать |
|-----------|-----------|-------------------|
| **Wireshark** | Глубокий анализ с GUI | Расследование инцидента (pcap) |
| **tcpdump** | Захват в CLI | На сервере без GUI |
| **Zeek (Bro)** | Сетевой анализ, метаданные | Долгосрочный мониторинг |

#### Практика: полный цикл анализа трафика

**tcpdump — быстрый захват:**

```bash
# Захват всего трафика на интерфейсе
sudo tcpdump -i eth0 -w /tmp/full_capture.pcap -c 10000

# Только HTTP-трафик
sudo tcpdump -i eth0 port 80 -A -c 100

# Только DNS
sudo tcpdump -i eth0 port 53 -nn -c 50

# Трафик от конкретного IP
sudo tcpdump -i eth0 host 10.0.0.20 -w /tmp/suspicious.pcap

# Не-HTTP, не-DNS, не-SSH (подозрительный)
sudo tcpdump -i eth0 'not port 80 and not port 443 and not port 53 and not port 22' -c 100
```

**Zeek — установка и базовый анализ:**

```bash
# Установка Zeek
sudo apt install -y zeek

# Анализ pcap-файла
zeek -r /tmp/capture.pcap

# Zeek создаёт структурированные логи:
cat conn.log     # Все соединения (IP, порты, длительность, байты)
cat dns.log      # DNS-запросы и ответы
cat http.log     # HTTP-запросы (метод, URL, User-Agent, код)
cat ssl.log      # TLS-сессии (версия, cipher, сертификат, JA3)
cat files.log    # Файлы, переданные по сети

# Поиск подозрительных DNS-запросов
cat dns.log | zeek-cut query | sort | uniq -c | sort -rn | head -20

# Поиск HTTP-запросов к нетипичным портам
cat http.log | zeek-cut id.resp_h id.resp_p host uri | grep -v ":80\|:443"

# Длинные соединения (возможный C2-beaconing)
cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p duration | \
  awk '$4 > 3600 {print}' | sort -t$'\t' -k4 -rn | head -10
```

### Урок 4.4: OSINT против вас: что утекает и как закрыть

### Урок 5.1: Что такое SIEM и зачем он нужен

#### Теория

**SIEM (Security Information and Event Management)** — центральная нервная система SOC. Собирает логи со всех источников, коррелирует события, генерирует алерты.

**Зачем SIEM:**
- **Один экран** вместо десятков серверов с логами
- **Корреляция**: связать SSH brute-force с последующим успешным входом
- **Алерты**: получить уведомление, а не искать вручную
- **Хранение**: логи хранятся централизованно (нельзя удалить с хоста)
- **Compliance**: 152-ФЗ, ГОСТ требуют централизованного логирования

**Популярные SIEM:**

| SIEM | Тип | Стоимость | Для кого |
|------|-----|-----------|----------|
| **Wazuh** | Open Source | Бесплатно | Наш курс, SMB |
| **ELK Stack** | Open Source | Бесплатно | Гибкий, для кастомных решений |
| **Splunk** | Коммерческий | $$$$ | Enterprise |
| **MaxPatrol SIEM** | Коммерческий (РФ) | $$$$ | Крупные компании РФ |
| **KUMA** | Коммерческий (РФ) | $$$ | Kaspersky-экосистема |

**Архитектура SIEM:**

```
[Источники логов]    →    [Сборщик]    →    [Хранилище]    →    [Аналитика]    →    [Дашборд]
  Windows Event Log       Wazuh Agent       Wazuh Indexer      Sigma-правила      Wazuh Dashboard
  Sysmon                  Filebeat          Elasticsearch       Корреляция         Kibana
  Suricata               rsyslog                               Алерты             Grafana
  Linux audit                                                  ML-детекция
  Firewall logs
  Application logs
```

### Урок 5.3: Sigma-правила: формат, написание, конвертация

#### Теория

**Sigma** — универсальный формат правил детекции. Пишется один раз — конвертируется в любой SIEM (Wazuh, Splunk, ELK, QRadar).

**Формат Sigma-правила:**

```yaml
title: Название правила
id: уникальный UUID
status: experimental / test / stable
description: Описание того, что обнаруживает
author: Автор
date: 2026/11/11
references:
    - https://attack.mitre.org/techniques/T1059/
logsource:
    category: process_creation  # Тип источника
    product: windows            # ОС
detection:
    selection:                   # Что ищем
        Image|endswith: '\powershell.exe'
        CommandLine|contains:
            - 'Invoke-Expression'
            - 'IEX'
            - 'DownloadString'
    condition: selection         # Логическое условие
level: high                      # critical / high / medium / low / informational
tags:
    - attack.execution
    - attack.t1059.001
falsepositives:
    - Legitimate admin scripts
```

**Операторы сравнения:**
- `|contains` — содержит подстроку
- `|endswith` — заканчивается на
- `|startswith` — начинается с
- `|re` — регулярное выражение
- `|all` — все значения должны присутствовать

**Скрипт: автоматическая конвертация и загрузка правил в Wazuh (Python)**

```python
#!/usr/bin/env python3
"""Конвертация набора Sigma-правил и генерация Wazuh-конфига."""

import subprocess
import os
import sys

SIGMA_DIR = "/opt/soc/sigma-rules/"
WAZUH_RULES_DIR = "/var/ossec/etc/rules/"

def convert_sigma_to_wazuh(sigma_file):
    """Конвертирует Sigma-правило в формат Wazuh."""
    result = subprocess.run(
        ["sigma", "convert", "-t", "wazuh", "-p", "wazuh", sigma_file],
        capture_output=True, text=True
    )
    if result.returncode == 0:
        return result.stdout
    else:
        print(f"Ошибка конвертации {sigma_file}: {result.stderr}")
        return None

def main():
    if not os.path.isdir(SIGMA_DIR):
        print(f"Создайте директорию {SIGMA_DIR} и положите туда .yml файлы")
        sys.exit(1)

    all_rules = []
    for f in sorted(os.listdir(SIGMA_DIR)):
        if f.endswith(".yml") or f.endswith(".yaml"):
            filepath = os.path.join(SIGMA_DIR, f)
            print(f"Конвертация: {f}")
            wazuh_rule = convert_sigma_to_wazuh(filepath)
            if wazuh_rule:
                all_rules.append(f"<!-- Из {f} -->\n{wazuh_rule}")

    if all_rules:
        output = f"""<group name="sigma_rules">
{''.join(all_rules)}
</group>"""
        output_path = os.path.join(WAZUH_RULES_DIR, "sigma_custom.xml")
        with open(output_path, "w") as fout:
            fout.write(output)
        print(f"\nПравила сохранены: {output_path}")
        print(f"Всего правил: {len(all_rules)}")
        print("Перезапустите Wazuh: sudo systemctl restart wazuh-manager")

if __name__ == "__main__":
    main()
```

### Урок 5.5: Дашборды и алерты: настройка оповещений

#### Теория

Дашборд — визуализация данных SIEM. Хороший дашборд показывает:
- Общую картину (сколько алертов, откуда, какого уровня)
- Тренды (растёт ли количество атак?)
- Топ-источники угроз
- Конкретные инциденты для расследования

**Ключевые виджеты SOC-дашборда:**

| Виджет | Что показывает | Зачем |
|--------|---------------|-------|
| Alarm timeline | Алерты по времени | Видеть всплески |
| Top source IPs | Откуда атакуют | Приоритизация |
| Alert severity | Уровень угроз | Фокус на critical |
| Top rules | Какие правила срабатывают | Тюнинг |
| Agent status | Здоровье агентов | Мониторинг инфраструктуры |
| GeoIP map | Откуда географически | Обнаружение аномалий |

#### Практика: настройка алертов в Wazuh

**Email-уведомления:**


**Webhook для Telegram:**

```python
#!/usr/bin/env python3
"""Wazuh → Telegram: отправка критических алертов."""

import json
import sys
import requests

TELEGRAM_TOKEN = "YOUR_BOT_TOKEN"  # Решение владельца
TELEGRAM_CHAT_ID = "YOUR_CHAT_ID"

def send_telegram(message):
    """Отправляет сообщение в Telegram."""
    url = f"https://api.telegram.org/bot{TELEGRAM_TOKEN}/sendMessage"
    data = {
        "chat_id": TELEGRAM_CHAT_ID,
        "text": message,
        "parse_mode": "HTML"
    }
    requests.post(url, data=data, timeout=10)

def main():
    # Wazuh передаёт алерт через stdin в формате JSON
    alert_file = sys.argv[1] if len(sys.argv) > 1 else None
    if not alert_file:
        return

    with open(alert_file) as f:
        alert = json.load(f)

    rule = alert.get("rule", {})
    level = rule.get("level", 0)

    # Отправлять только critical (level >= 10)
    if level >= 10:
        msg = (
            f"🚨 <b>CRITICAL ALERT</b>\n"
            f"<b>Rule:</b> {rule.get('description', 'N/A')}\n"
            f"<b>Level:</b> {level}\n"
            f"<b>Agent:</b> {alert.get('agent', {}).get('name', 'N/A')}\n"
            f"<b>Source:</b> {alert.get('data', {}).get('srcip', 'N/A')}\n"
            f"<b>Time:</b> {alert.get('timestamp', 'N/A')}"
        )
        send_telegram(msg)

if __name__ == "__main__":
    main()
```
