## Лаборатория 1: Развёртывание сетевого мониторинга с Suricata

**Уровень:** Начальный–Средний
**Время:** 2–3 часа
**Инструменты:** Suricata, tcpreplay, jq, curl
**Предварительные требования:** Linux (Ubuntu 22.04+), базовые знания TCP/IP, права root

### Цель

Научиться устанавливать и настраивать Suricata IDS, писать собственные правила обнаружения, анализировать алерты в формате EVE JSON. После лаборатории вы сможете развернуть сетевой мониторинг для обнаружения сканирования, подозрительных подключений и известных угроз.

### Теория

**Что такое IDS и зачем он нужен**

Система обнаружения вторжений (Intrusion Detection System, IDS) — это программный или аппаратный компонент, который анализирует сетевой трафик в реальном времени и сравнивает его с набором правил. Если трафик соответствует правилу — генерируется алерт.

Существуют два основных подхода к обнаружению:

1. **Сигнатурный анализ** — сравнение трафика с известными паттернами атак. Аналогия: антивирус по базе сигнатур. Преимущество — точность, низкий false positive. Недостаток — не обнаруживает неизвестные атаки.

2. **Поведенческий (аномальный) анализ** — построение модели «нормального» поведения и обнаружение отклонений. Преимущество — может обнаружить zero-day. Недостаток — высокий false positive.

Suricata использует **сигнатурный подход** с элементами протокольного анализа. Она понимает структуру протоколов (HTTP, DNS, TLS, SMB) и может проверять конкретные поля, а не просто байты в потоке.

**Архитектура Suricata:**
- **Capture** — захват пакетов (AF_PACKET, PCAP, DPDK)
- **Decode** — разбор заголовков L2–L4
- **App-layer** — разбор протоколов L7 (HTTP, DNS, TLS, SMB, SSH и др.)
- **Detection** — проверка правил
- **Output** — запись алертов (EVE JSON, fast.log, pcap)

Suricata работает в многопоточном режиме, что даёт ей преимущество на современном оборудовании. Режимы работы: IDS (пассивное обнаружение), IPS (активная блокировка через NFQ/iptables).

**Формат правил Suricata:**

```
action protocol src_ip src_port -> dst_ip dst_port (options)
```

- `action` — alert, drop, pass, reject
- `protocol` — tcp, udp, icmp, http, dns, tls, ssh и др.
- `options` — msg, content, sid, rev, classtype, reference и др.

**Зачем SOC-аналитику знать Suricata:**
- IDS — первая линия обороны в сети
- Алерты Suricata — основной источник событий в SIEM
- Умение писать custom rules = умение обнаруживать целевые атаки
- EVE JSON легко интегрируется в ELK/Wazuh

## Лаборатория 2: Анализ сетевого трафика в Wireshark

**Уровень:** Начальный
**Время:** 2 часа
**Инструменты:** Wireshark, tshark, tcpdump
**Предварительные требования:** Базовые знания TCP/IP, установленный Wireshark

### Цель

Научиться захватывать и анализировать сетевой трафик: применять фильтры, следить за TCP-потоками, извлекать файлы из трафика, находить аномалии. Это базовый навык для SOC-аналитика — каждый инцидент связан с анализом трафика.

### Теория

**TCP/IP из перспективы SOC-аналитика**

Когда вы смотрите на трафик в Wireshark, вы видите реальную коммуникацию между хостами. Понимание протоколов позволяет отличить нормальное поведение от атаки.

**TCP Three-Way Handshake (трёхстороннее рукопожатие):**
1. Клиент → Сервер: SYN (запрос на подключение)
2. Сервер → Клиент: SYN-ACK (подтверждение готовности)
3. Клиент → Сервер: ACK (соединение установлено)

Почему это важно для SOC:
- **SYN без SYN-ACK** = порт закрыт или фильтруется → массово = сканирование
- **SYN-ACK без финального ACK** = half-open scan (Nmap -sS)
- **RST после SYN-ACK** = порт открыт, но клиент не заинтересован → сканирование
- **Множество SYN к разным портам одного хоста** = вертикальное сканирование
- **Множество SYN к одному порту разных хостов** = горизонтальное сканирование

**HTTP в трафике:**
SOC-аналитик видит в HTTP:
- URL-адреса (возможные C2-каналы, web shells)
- User-Agent (поддельные = автоматизированные инструменты)
- POST-тела (эксфильтрация данных)
- Referer (фишинговые редиректы)
- Cookies (украденные сессии)

**DNS в трафике:**
DNS — один из самых злоупотребляемых протоколов:
- Длинные запросы (>50 символов) → DNS tunneling
- Запросы к нехарактерным TLD (.tk, .xyz) → C2, DGA
- Множество NXDOMAIN → DGA-бот ищет свой C2
- TXT-записи большого размера → данные в DNS

**Шаг 5: Python-скрипт анализа PCAP**

```python
#!/usr/bin/env python3
"""
pcap_analyzer.py — анализ PCAP-файла для SOC
Использование: python3 pcap_analyzer.py capture.pcap
"""
import subprocess
import sys
import json
from collections import Counter

def run_tshark(pcap, display_filter, fields):
    """Запуск tshark и получение результатов."""
    cmd = [
        "tshark", "-r", pcap, "-Y", display_filter,
        "-T", "fields"
    ]
    for f in fields:
        cmd.extend(["-e", f])
    cmd.append("-E")
    cmd.append("separator=|")
    result = subprocess.run(cmd, capture_output=True, text=True)
    lines = [l.strip() for l in result.stdout.strip().split("\n") if l.strip()]
    return lines

def analyze_pcap(pcap_path):
    """Полный анализ PCAP-файла."""
    report = []
    report.append("=" * 60)
    report.append(f"АНАЛИЗ PCAP: {pcap_path}")
    report.append("=" * 60)

    # 1. Общая статистика
    result = subprocess.run(
        ["tshark", "-r", pcap_path, "-q", "-z", "io,phs"],
        capture_output=True, text=True
    )
    report.append("\n[1] ПРОТОКОЛЫ:")
    report.append(result.stdout[:500])

    # 2. Уникальные IP-адреса
    lines = run_tshark(pcap_path, "ip", ["ip.src"])
    src_ips = Counter(lines)
    report.append("\n[2] ТОП-10 IP-ИСТОЧНИКОВ:")
    for ip, count in src_ips.most_common(10):
        report.append(f"  {count:>6} пакетов — {ip}")

    # 3. DNS-запросы
    lines = run_tshark(pcap_path, "dns.qr == 0", ["dns.qry.name"])
    dns_queries = Counter(lines)
    report.append("\n[3] ТОП-10 DNS-ЗАПРОСОВ:")
    for domain, count in dns_queries.most_common(10):
        report.append(f"  {count:>4}x — {domain}")

    # 4. Подозрительные DNS (длинные домены)
    report.append("\n[4] ПОДОЗРИТЕЛЬНЫЕ DNS (>40 символов):")
    suspicious = [(d, c) for d, c in dns_queries.items() if len(d) > 40]
    if suspicious:
        for domain, count in suspicious:
            report.append(f"  [!] {domain} ({count}x, {len(domain)} символов)")
    else:
        report.append("  Не обнаружено")

    # 5. HTTP-запросы
    lines = run_tshark(
        pcap_path, "http.request",
        ["ip.src", "http.request.method", "http.host", "http.request.uri"]
    )
    report.append(f"\n[5] HTTP-ЗАПРОСЫ ({len(lines)}):")
    for line in lines[:20]:
        parts = line.split("|")
        if len(parts) >= 4:
            report.append(f"  {parts[0]} {parts[1]} {parts[2]}{parts[3]}")

    # 6. TCP SYN без ответа (возможное сканирование)
    syn_lines = run_tshark(
        pcap_path,
        "tcp.flags.syn == 1 && tcp.flags.ack == 0",
        ["ip.src", "ip.dst", "tcp.dstport"]
    )
    syn_sources = Counter([l.split("|")[0] for l in syn_lines if "|" in l])
    report.append(f"\n[6] TCP SYN ПАКЕТЫ ({len(syn_lines)}):")
    for ip, count in syn_sources.most_common(5):
        flag = " [!] ВОЗМОЖНОЕ СКАНИРОВАНИЕ" if count > 10 else ""
        report.append(f"  {ip}: {count} SYN{flag}")

    print("\n".join(report))

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print(f"Использование: {sys.argv[0]} <файл.pcap>")
        sys.exit(1)
    analyze_pcap(sys.argv[1])
```

## Лаборатория 3: Zeek для сетевой форензики

**Уровень:** Средний
**Время:** 2–3 часа
**Инструменты:** Zeek (бывший Bro), Python 3
**Предварительные требования:** Знание TCP/IP, базовый Linux

### Цель

Научиться использовать Zeek для глубокого анализа сетевого трафика: понимать формат логов, обнаруживать DNS tunneling и C2-beaconing с помощью скриптов Zeek и Python.

### Теория

**Что такое Zeek и чем он отличается от Suricata**

Zeek — это фреймворк сетевого анализа, который не просто ищет сигнатуры, а **понимает** протоколы и создаёт структурированные логи всех соединений. Если Suricata — это охранник с чёрным списком, то Zeek — это видеокамера, которая записывает всё.

Ключевые логи Zeek:
- `conn.log` — каждое TCP/UDP/ICMP соединение (IP, порты, длительность, байты)
- `dns.log` — каждый DNS-запрос и ответ
- `http.log` — каждый HTTP-запрос (метод, URI, User-Agent, статус)
- `ssl.log` / `x509.log` — TLS-сессии и сертификаты
- `files.log` — файлы, переданные по сети (хэш, тип, размер)
- `notice.log` — важные замеченные аномалии
- `weird.log` — нестандартное поведение протоколов

Почему Zeek ценен для SOC:
- **Полная видимость** — запись всех соединений, не только подозрительных
- **Ретроспективный анализ** — можно искать IoC задним числом
- **Обнаружение аномалий** — длительность, объёмы, паттерны
- **Корреляция** — связывание DNS, HTTP, файлов в одну цепочку по uid

```python
#!/usr/bin/env python3
"""
dns_tunnel_detector.py — обнаружение DNS-туннелирования в логах Zeek.
Использование: python3 dns_tunnel_detector.py dns.log
"""
import sys
import math
from collections import Counter, defaultdict

def shannon_entropy(s):
    """Вычисление энтропии Шеннона строки."""
    if not s:
        return 0.0
    freq = Counter(s)
    length = len(s)
    return -sum(
        (count / length) * math.log2(count / length)
        for count in freq.values()
    )

def analyze_dns_log(filepath):
    """Анализ dns.log на признаки туннелирования."""
    domains = defaultdict(list)
    total_queries = 0
    suspicious = []

    with open(filepath) as f:
        for line in f:
            if line.startswith("#"):
                continue
            fields = line.strip().split("\t")
            if len(fields) < 10:
                continue

            total_queries += 1
            ts = fields[0]
            query = fields[9] if len(fields) > 9 else ""

            if not query or query == "-":
                continue

            # Извлекаем базовый домен (последние 2 части)
            parts = query.rstrip(".").split(".")
            if len(parts) >= 2:
                base_domain = ".".join(parts[-2:])
                subdomain = ".".join(parts[:-2])
                domains[base_domain].append({
                    "query": query,
                    "subdomain": subdomain,
                    "ts": ts
                })

    print(f"Всего DNS-запросов: {total_queries}")
    print(f"Уникальных базовых доменов: {len(domains)}")
    print("=" * 70)

    # Анализ каждого домена
    for base_domain, queries in sorted(
        domains.items(), key=lambda x: len(x[1]), reverse=True
    ):
        subdomains = [q["subdomain"] for q in queries if q["subdomain"]]
        if not subdomains:
            continue

        # Метрики подозрительности
        unique_subdomains = len(set(subdomains))
        avg_length = sum(len(s) for s in subdomains) / len(subdomains)
        avg_entropy = sum(shannon_entropy(s) for s in subdomains) / len(subdomains)

        score = 0
        reasons = []

        # Много уникальных поддоменов
        if unique_subdomains > 20:
            score += 3
            reasons.append(f"много уникальных поддоменов ({unique_subdomains})")

        # Длинные поддомены
        if avg_length > 25:
            score += 3
            reasons.append(f"длинные поддомены (ср. {avg_length:.0f} символов)")

        # Высокая энтропия (случайные символы)
        if avg_entropy > 3.5:
            score += 3
            reasons.append(f"высокая энтропия ({avg_entropy:.2f})")

        # Частые запросы
        if len(queries) > 50:
            score += 2
            reasons.append(f"частые запросы ({len(queries)})")

        if score >= 5:
            severity = "КРИТИЧЕСКИЙ" if score >= 8 else "ВЫСОКИЙ" if score >= 6 else "СРЕДНИЙ"
            print(f"\n[{severity}] {base_domain}")
            print(f"  Запросов: {len(queries)}, уникальных: {unique_subdomains}")
            print(f"  Ср. длина поддомена: {avg_length:.1f}, ср. энтропия: {avg_entropy:.2f}")
            print(f"  Причины: {'; '.join(reasons)}")
            print(f"  Примеры: {', '.join(list(set(subdomains))[:3])}")

if __name__ == "__main__":
    if len(sys.argv) != 2:
        print(f"Использование: {sys.argv[0]} <dns.log>")
        sys.exit(1)
    analyze_dns_log(sys.argv[1])
```

**Шаг 5: Скрипт обнаружения C2 beaconing**

```python
#!/usr/bin/env python3
"""
beacon_detector.py — обнаружение C2-beaconing в conn.log Zeek.
Beaconing = регулярные подключения к одному хосту с постоянным интервалом.
Использование: python3 beacon_detector.py conn.log
"""
import sys
from collections import defaultdict
import statistics

def parse_conn_log(filepath):
    """Парсинг conn.log."""
    connections = defaultdict(list)

    with open(filepath) as f:
        for line in f:
            if line.startswith("#"):
                continue
            fields = line.strip().split("\t")
            if len(fields) < 9:
                continue
            try:
                ts = float(fields[0])
                src = fields[2]
                dst = fields[4]
                dport = fields[5]
                proto = fields[6]
            except (ValueError, IndexError):
                continue

            key = f"{src} -> {dst}:{dport}/{proto}"
            connections[key].append(ts)

    return connections

def detect_beaconing(connections, min_connections=10, max_jitter_pct=15):
    """Обнаружение периодических подключений (beaconing)."""
    beacons = []

    for key, timestamps in connections.items():
        if len(timestamps) < min_connections:
            continue

        timestamps.sort()
        intervals = [
            timestamps[i+1] - timestamps[i]
            for i in range(len(timestamps) - 1)
        ]

        if not intervals:
            continue

        avg_interval = statistics.mean(intervals)
        if avg_interval < 1:
            continue

        try:
            stdev = statistics.stdev(intervals)
        except statistics.StatisticsError:
            stdev = 0

        jitter_pct = (stdev / avg_interval * 100) if avg_interval > 0 else 100

        if jitter_pct <= max_jitter_pct:
            beacons.append({
                "pair": key,
                "count": len(timestamps),
                "avg_interval": avg_interval,
                "jitter_pct": jitter_pct,
                "duration_min": (timestamps[-1] - timestamps[0]) / 60
            })

    return sorted(beacons, key=lambda x: x["jitter_pct"])

def main():
    if len(sys.argv) != 2:
        print(f"Использование: {sys.argv[0]} <conn.log>")
        sys.exit(1)

    print("=== Детектор C2 Beaconing ===\n")
    connections = parse_conn_log(sys.argv[1])
    print(f"Проанализировано пар: {len(connections)}")

    beacons = detect_beaconing(connections)
    if beacons:
        print(f"\n[!] Обнаружено {len(beacons)} подозрительных паттернов:\n")
        for b in beacons:
            interval_str = f"{b['avg_interval']:.0f}с" if b['avg_interval'] < 120 else f"{b['avg_interval']/60:.1f}м"
            print(f"  {b['pair']}")
            print(f"    Подключений: {b['count']}, интервал: {interval_str}, "
                  f"jitter: {b['jitter_pct']:.1f}%, длительность: {b['duration_min']:.0f} мин")
    else:
        print("\nBeaconing не обнаружен.")

if __name__ == "__main__":
    main()
```

## Лаборатория 4: Настройка сетевой сегментации

**Уровень:** Средний
**Время:** 2 часа
**Инструменты:** iptables/nftables, Linux networking, iproute2
**Предварительные требования:** Базовые знания сетей, Linux

### Цель

Настроить трёхзонную сетевую архитектуру (LAN, DMZ, WAN) с использованием Linux и файрвола. Понять, зачем нужна сегментация и как она ограничивает распространение атак.

### Теория

**Зачем нужна сетевая сегментация**

Сегментация — это разделение сети на изолированные зоны с контролем трафика между ними. Это одна из самых эффективных мер защиты, потому что:

1. **Ограничивает lateral movement** — атакующий, захвативший один сегмент, не может свободно ходить в другие
2. **Уменьшает blast radius** — если compromised один сервер в DMZ, внутренняя сеть защищена
3. **Упрощает мониторинг** — трафик между зонами проходит через контрольные точки
4. **Соответствует compliance** — PCI DSS, ФСТЭК требуют сегментации

**Классическая 3-зонная архитектура:**

```
[Интернет] <-> [Firewall] <-> [DMZ: веб-серверы, почта]
                    |
                    +-----> [LAN: рабочие станции, файлы]
                    |
                    +-----> [Management: серверы управления, SIEM]
```

Правила между зонами:
- **WAN → DMZ**: Разрешён только трафик к опубликованным сервисам (80, 443)
- **WAN → LAN**: Запрещён полностью
- **LAN → DMZ**: Ограничен (только необходимые сервисы)
- **LAN → WAN**: Разрешён через прокси
- **DMZ → LAN**: Запрещён (DMZ — демилитаризованная зона)

## Лаборатория 5: Мониторинг DNS — обнаружение DGA и tunneling

**Уровень:** Средний
**Время:** 2 часа
**Инструменты:** Python 3, tcpdump, tshark
**Предварительные требования:** Базовый Python, понимание DNS

### Цель

Настроить мониторинг DNS-запросов и научиться обнаруживать два основных вида злоупотребления DNS: DGA (Domain Generation Algorithm) и DNS tunneling. Оба метода активно используются малварью для связи с C2-серверами.

### Теория

**DNS как канал для атакующего**

DNS — идеальный протокол для скрытой коммуникации:
- Почти всегда разрешён через файрволы (порт 53)
- Рекурсивные DNS-серверы пересылают запросы наружу
- Мало кто мониторит DNS-трафик детально

**DGA (Domain Generation Algorithm):**
Малварь генерирует псевдослучайные доменные имена (например, `xkjf3a9v.com`, `m2k5bw8p.net`) и пытается подключиться к каждому. Атакующий регистрирует только один из тысяч доменов — этого достаточно для связи. Признаки DGA:
- Множество запросов с ответом NXDOMAIN
- Случайные комбинации букв и цифр
- Высокая энтропия доменных имён
- Использование дешёвых TLD (.xyz, .top, .click)

**DNS Tunneling:**
Данные кодируются в DNS-запросах (поддомен) и ответах (TXT/CNAME-записи). Признаки:
- Очень длинные поддомены (>50 символов)
- Запросы типа TXT и NULL
- Высокая частота запросов к одному домену
- Кодировка base32/base64 в поддоменах

```python
#!/usr/bin/env python3
"""
dns_threat_detector.py — обнаружение DGA и DNS tunneling.
Анализирует файл с DNS-запросами или dns.log от Zeek.
Использование: python3 dns_threat_detector.py <файл_запросов>
"""
import sys
import math
import re
from collections import Counter, defaultdict

def shannon_entropy(s):
    """Энтропия Шеннона строки."""
    if not s:
        return 0.0
    freq = Counter(s.lower())
    length = len(s)
    return -sum(
        (c / length) * math.log2(c / length)
        for c in freq.values()
    )

def is_hex_like(s):
    """Проверяет, похожа ли строка на hex-encoded данные."""
    hex_chars = set("0123456789abcdef")
    s_lower = s.lower().replace("-", "").replace(".", "")
    if not s_lower:
        return False
    ratio = sum(1 for c in s_lower if c in hex_chars) / len(s_lower)
    return ratio > 0.85

def is_base64_like(s):
    """Проверяет, похожа ли строка на base64/base32."""
    b64_pattern = re.compile(r'^[A-Za-z0-9+/=]{16,}$')
    b32_pattern = re.compile(r'^[A-Z2-7=]{16,}$')
    return bool(b64_pattern.match(s)) or bool(b32_pattern.match(s))

def consonant_ratio(s):
    """Отношение согласных к гласным (высокое = случайная строка)."""
    vowels = set("aeiouAEIOU")
    consonants = set("bcdfghjklmnpqrstvwxyzBCDFGHJKLMNPQRSTVWXYZ")
    v_count = sum(1 for c in s if c in vowels)
    c_count = sum(1 for c in s if c in consonants)
    if v_count == 0:
        return 10.0
    return c_count / v_count

class DNSThreatDetector:
    def __init__(self):
        self.queries = []
        self.domain_stats = defaultdict(list)
        self.alerts = []

    def add_query(self, domain):
        """Добавить DNS-запрос для анализа."""
        domain = domain.strip().rstrip(".")
        if not domain:
            return
        self.queries.append(domain)

        parts = domain.split(".")
        if len(parts) >= 2:
            base = ".".join(parts[-2:])
            subdomain = ".".join(parts[:-2])
            self.domain_stats[base].append(subdomain)

    def detect_dga(self, domain):
        """Проверить домен на DGA."""
        parts = domain.split(".")
        if len(parts) < 2:
            return None

        sld = parts[-2]  # second-level domain

        entropy = shannon_entropy(sld)
        length = len(sld)
        cons_ratio = consonant_ratio(sld)

        score = 0
        reasons = []

        # Высокая энтропия
        if entropy > 3.5:
            score += 2
            reasons.append(f"энтропия {entropy:.2f}")

        # Длинный SLD
        if length > 12:
            score += 1
            reasons.append(f"длина {length}")

        # Много согласных
        if cons_ratio > 3.0:
            score += 2
            reasons.append(f"согл/гласн {cons_ratio:.1f}")

        # Похож на hex
        if is_hex_like(sld):
            score += 2
            reasons.append("hex-подобный")

        # Цифры в доменном имени
        digit_ratio = sum(1 for c in sld if c.isdigit()) / max(len(sld), 1)
        if digit_ratio > 0.3:
            score += 1
            reasons.append(f"цифры {digit_ratio:.0%}")

        # Подозрительный TLD
        suspicious_tlds = {
            "xyz", "top", "click", "club", "work", "tk", "ml",
            "ga", "cf", "gq", "buzz", "icu", "monster"
        }
        tld = parts[-1].lower()
        if tld in suspicious_tlds:
            score += 1
            reasons.append(f"TLD .{tld}")

        if score >= 4:
            return {
                "domain": domain,
                "type": "DGA",
                "score": score,
                "reasons": reasons
            }
        return None

    def detect_tunneling(self):
        """Обнаружить DNS tunneling по агрегированным данным."""
        tunneling_suspects = []

        for base_domain, subdomains in self.domain_stats.items():
            if not subdomains or not any(subdomains):
                continue

            non_empty = [s for s in subdomains if s]
            if len(non_empty) < 3:
                continue

            avg_len = sum(len(s) for s in non_empty) / len(non_empty)
            avg_entropy = sum(shannon_entropy(s) for s in non_empty) / len(non_empty)
            unique_ratio = len(set(non_empty)) / len(non_empty)
            has_encoded = any(is_base64_like(s.replace(".", "")) for s in non_empty)

            score = 0
            reasons = []

            if avg_len > 20:
                score += 3
                reasons.append(f"ср. длина поддомена {avg_len:.0f}")

            if avg_entropy > 3.5:
                score += 2
                reasons.append(f"ср. энтропия {avg_entropy:.2f}")

            if unique_ratio > 0.8 and len(non_empty) > 5:
                score += 2
                reasons.append(f"уникальность {unique_ratio:.0%}")

            if has_encoded:
                score += 3
                reasons.append("base64/32 в поддоменах")

            if len(non_empty) > 20:
                score += 2
                reasons.append(f"частота: {len(non_empty)} запросов")

            if score >= 5:
                tunneling_suspects.append({
                    "domain": base_domain,
                    "type": "DNS_TUNNELING",
                    "score": score,
                    "reasons": reasons,
                    "query_count": len(non_empty),
                    "examples": list(set(non_empty))[:3]
                })

        return tunneling_suspects

    def analyze(self):
        """Полный анализ."""
        print("=" * 60)
        print("DNS THREAT DETECTOR — ОТЧЁТ")
        print("=" * 60)
        print(f"\nВсего запросов: {len(self.queries)}")
        print(f"Уникальных доменов: {len(set(self.queries))}")

        # DGA Detection
        print("\n--- DGA DETECTION ---")
        dga_found = []
        for domain in set(self.queries):
            result = self.detect_dga(domain)
            if result:
                dga_found.append(result)

        if dga_found:
            for r in sorted(dga_found, key=lambda x: x["score"], reverse=True):
                print(f"  [!] {r['domain']} (score: {r['score']})")
                print(f"      Причины: {', '.join(r['reasons'])}")
        else:
            print("  DGA не обнаружен")

        # Tunneling Detection
        print("\n--- DNS TUNNELING DETECTION ---")
        tunneling = self.detect_tunneling()
        if tunneling:
            for t in sorted(tunneling, key=lambda x: x["score"], reverse=True):
                print(f"  [!] {t['domain']} (score: {t['score']})")
                print(f"      Запросов: {t['query_count']}")
                print(f"      Причины: {', '.join(t['reasons'])}")
                print(f"      Примеры: {t['examples']}")
        else:
            print("  DNS tunneling не обнаружен")

        print("\n" + "=" * 60)

def main():
    if len(sys.argv) != 2:
        print(f"Использование: {sys.argv[0]} <файл_с_запросами>")
        sys.exit(1)

    detector = DNSThreatDetector()

    with open(sys.argv[1]) as f:
        for line in f:
            line = line.strip()
            if line and not line.startswith("#"):
                detector.add_query(line)

    detector.analyze()

if __name__ == "__main__":
    main()
```

### Анализ результатов

Детектор использует многофакторный скоринг:
- **DGA**: энтропия + длина + соотношение согласных/гласных + подозрительный TLD
- **Tunneling**: длина поддоменов + энтропия + уникальность + base64-кодировка + частота

Пороги настраиваются в зависимости от среды — в корпоративной сети с легитимными CDN порог может быть выше.

### Цель

Установить и настроить Sysmon для максимальной видимости на endpoint. Понять каждый тип события и написать конфигурацию для обнаружения 10 конкретных техник ATT&CK.

### Теория

**Что такое Sysmon и зачем он нужен**

System Monitor (Sysmon) — бесплатная утилита от Microsoft Sysinternals, которая устанавливается как служба Windows и записывает расширенную телеметрию в Event Log. Стандартные журналы Windows недостаточны для SOC — Sysmon заполняет эти пробелы.

**Ключевые EventID Sysmon:**

| EventID | Событие | Зачем SOC |
|---------|---------|-----------|
| **1** | Process Create | Каждый запущенный процесс: путь, аргументы, хэш, родитель |
| **3** | Network Connection | Исходящие/входящие соединения процесса |
| **6** | Driver Loaded | Загрузка драйверов (руткиты!) |
| **7** | Image Loaded | Загрузка DLL (DLL injection, hijacking) |
| **8** | CreateRemoteThread | Создание потока в другом процессе (injection) |
| **10** | ProcessAccess | Доступ к другому процессу (LSASS credential dump) |
| **11** | FileCreate | Создание файлов (payloads, web shells) |
| **12/13** | Registry | Создание/изменение ключей реестра (persistence) |
| **15** | FileCreateStreamHash | Alternate Data Streams (скрытые данные) |
| **22** | DNSEvent | DNS-запросы процесса (C2 detection) |
| **23** | FileDelete | Удаление файлов (anti-forensics) |
| **25** | ProcessTampering | Модификация образа процесса (hollowing) |

**Почему конфигурация важна:**
Sysmon без конфигурации записывает слишком много или слишком мало. Хорошая конфигурация:
- Включает важные события (process creation, network connections)
- Фильтрует шум (системные процессы, легитимный софт)
- Фокусируется на технике атак (LOLBins, suspicious parent-child)

```powershell
# sysmon_analyzer.ps1 — анализ событий Sysmon

function Get-SysmonSummary {
    param([int]$Hours = 1)

    $startTime = (Get-Date).AddHours(-$Hours)

    Write-Host "=== Сводка Sysmon за последние $Hours час(а) ===" -ForegroundColor Cyan

    # Статистика по EventID
    $events = Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" `
        -FilterXPath "*[System[TimeCreated[@SystemTime >= '$(Get-Date $startTime -Format o)']]]" `
        -ErrorAction SilentlyContinue

    if (-not $events) {
        Write-Host "Событий не найдено"
        return
    }

    Write-Host "`nВсего событий: $($events.Count)"

    $byId = $events | Group-Object Id | Sort-Object Count -Descending
    Write-Host "`nПо типам:"
    foreach ($g in $byId) {
        $name = switch ($g.Name) {
            1  { "Process Create" }
            3  { "Network Connect" }
            6  { "Driver Loaded" }
            7  { "Image Loaded" }
            8  { "CreateRemoteThread" }
            10 { "ProcessAccess" }
            11 { "FileCreate" }
            12 { "Registry Key/Value Create" }
            13 { "Registry Value Set" }
            22 { "DNS Query" }
            25 { "Process Tampering" }
            default { "Event $($g.Name)" }
        }
        Write-Host "  $($g.Count.ToString().PadLeft(6)) — [$($g.Name)] $name"
    }

    # Подозрительные события
    Write-Host "`n--- ПОДОЗРИТЕЛЬНЫЕ СОБЫТИЯ ---" -ForegroundColor Yellow

    # LSASS access
    $lsass = $events | Where-Object {
        $_.Id -eq 10 -and $_.Message -match "lsass\.exe"
    }
    if ($lsass) {
        Write-Host "[!] Доступ к LSASS: $($lsass.Count) событий" -ForegroundColor Red
        $lsass | Select-Object -First 3 | ForEach-Object {
            $xml = [xml]$_.ToXml()
            $source = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "SourceImage" }).'#text'
            Write-Host "    Источник: $source"
        }
    }

    # CreateRemoteThread
    $crt = $events | Where-Object { $_.Id -eq 8 }
    if ($crt) {
        Write-Host "[!] CreateRemoteThread: $($crt.Count) событий" -ForegroundColor Red
    }

    # Неподписанные драйверы
    $drivers = $events | Where-Object {
        $_.Id -eq 6 -and $_.Message -match "Signed.*false"
    }
    if ($drivers) {
```

## Лаборатория 8: Linux auditd мониторинг

**Уровень:** Средний
**Время:** 2 часа
**Инструменты:** auditd, ausearch, aureport, auditctl
**Предварительные требования:** Linux (Ubuntu/CentOS), права root

### Цель

Настроить auditd для мониторинга ключевых событий безопасности на Linux: доступ к файлам, изменение пользователей, выполнение privileged-команд, сетевые подключения.

### Теория

**Linux Audit Framework**

auditd — это подсистема аудита ядра Linux. Она перехватывает системные вызовы (syscalls) и записывает их в лог. Это единственный надёжный способ мониторить, что происходит на Linux-системе на низком уровне.

Компоненты:
- **auditd** — демон, записывает события в /var/log/audit/audit.log
- **auditctl** — управление правилами в реальном времени
- **ausearch** — поиск по логам
- **aureport** — генерация отчётов
- **/etc/audit/rules.d/** — постоянные правила

Типы правил:
- **-w** (watch) — мониторинг файлов/директорий (доступ, изменение)
- **-a** (audit) — мониторинг системных вызовов (execve, connect, open)
- **-k** (key) — метка для удобного поиска

**Шаг 4: Python-скрипт анализа audit.log**

```python
#!/usr/bin/env python3
"""
audit_analyzer.py — анализ /var/log/audit/audit.log
Использование: sudo python3 audit_analyzer.py
"""
import re
from collections import Counter, defaultdict
from datetime import datetime

def parse_audit_log(filepath="/var/log/audit/audit.log"):
    """Парсинг audit.log."""
    events = []
    current = {}

    with open(filepath) as f:
        for line in f:
            line = line.strip()
            if not line:
                continue

            # Парсим тип и timestamp
            type_match = re.search(r'type=(\w+)', line)
            ts_match = re.search(r'msg=audit\((\d+\.\d+):\d+\)', line)

            if type_match and ts_match:
                event_type = type_match.group(1)
                timestamp = float(ts_match.group(1))

                event = {
                    'type': event_type,
                    'timestamp': datetime.fromtimestamp(timestamp),
                    'raw': line
                }

                # Извлекаем ключевые поля
                for field in ['key', 'exe', 'comm', 'uid', 'auid', 'success', 'name']:
                    match = re.search(rf'{field}=("[^"]*"|[^\s]+)', line)
                    if match:
                        event[field] = match.group(1).strip('"')

                events.append(event)

    return events

def analyze(events):
    """Анализ событий."""
    print(f"{'=' * 60}")
    print(f"АНАЛИЗ AUDIT LOG — {len(events)} событий")
    print(f"{'=' * 60}")

    # По типам
    type_counts = Counter(e['type'] for e in events)
    print("\n[1] Типы событий:")
    for t, c in type_counts.most_common(10):
        print(f"  {c:>6} — {t}")

    # Подозрительные: неудачные операции
    failures = [e for e in events if e.get('success') == 'no']
    print(f"\n[2] Неудачные операции: {len(failures)}")
    fail_cmds = Counter(e.get('comm', 'unknown') for e in failures)
    for cmd, c in fail_cmds.most_common(5):
        print(f"  {c:>4}x — {cmd}")

    # Команды по ключам
    keyed = defaultdict(list)
    for e in events:
        if 'key' in e and e['key'] != '(null)':
            keyed[e['key']].append(e)

    print(f"\n[3] По ключам аудита:")
    for key, evts in sorted(keyed.items(), key=lambda x: len(x[1]), reverse=True):
        print(f"  {len(evts):>4} — {key}")

    # Privilege escalation
    priv = keyed.get('privilege_escalation', [])
    if priv:
        print(f"\n[!] PRIVILEGE ESCALATION: {len(priv)} событий")
        for e in priv[-5:]:
            print(f"  {e['timestamp']} — {e.get('exe', '?')} uid={e.get('uid', '?')}")

    # Identity changes
    identity = keyed.get('identity', [])
    if identity:
        print(f"\n[!] ИЗМЕНЕНИЯ УЧЁТНЫХ ДАННЫХ: {len(identity)} событий")
        for e in identity[-5:]:
            print(f"  {e['timestamp']} — {e.get('name', e.get('exe', '?'))}")

if __name__ == "__main__":
    events = parse_audit_log()
    analyze(events)
```

## Лаборатория 9: Hardening Linux по CIS Benchmark

**Уровень:** Средний

### Теория

**Что такое CIS Benchmarks**

Center for Internet Security (CIS) публикует детальные руководства по настройке безопасности для ОС, серверов и приложений. CIS Benchmark — это чеклист из 200+ пунктов, разделённых на:
- **Level 1** — базовая безопасность, минимальное влияние на функционал
- **Level 2** — расширенная безопасность, может ограничить некоторые функции

Почему hardening важен:
- Установка по умолчанию = уязвимая конфигурация
- Hardening закрывает 60-80% типичных векторов атак
- Compliance требует соответствия (PCI DSS, ФСТЭК)
- Уменьшает поверхность атаки

```bash
#!/bin/bash
# cis_check.sh — проверка соответствия CIS Benchmark
# Использование: sudo bash cis_check.sh

PASS=0
FAIL=0
WARN=0

check() {
    local desc="$1"
    local result="$2"  # 0=pass, 1=fail, 2=warn

    case $result in
        0) echo -e "[\033[32mPASS\033[0m] $desc"; ((PASS++));;
        1) echo -e "[\033[31mFAIL\033[0m] $desc"; ((FAIL++));;
        2) echo -e "[\033[33mWARN\033[0m] $desc"; ((WARN++));;
    esac
}

echo "=================================================="
echo "  CIS Benchmark Check — $(date '+%Y-%m-%d %H:%M')"
echo "  Host: $(hostname)"
echo "=================================================="

# --- SSH ---
echo -e "\n=== SSH ==="

grep -q "^PermitRootLogin no" /etc/ssh/sshd_config /etc/ssh/sshd_config.d/* 2>/dev/null
check "SSH: PermitRootLogin no" $?

grep -q "^MaxAuthTries [1-4]$" /etc/ssh/sshd_config /etc/ssh/sshd_config.d/* 2>/dev/null
check "SSH: MaxAuthTries <= 4" $?

check "SSH: X11Forwarding no" $?

[[ "$ufw_status" == *"active"* ]]
check "UFW: активен" $?

# --- Файловая система ---
echo -e "\n=== Файловая система ==="

perms=$(stat -c %a /etc/passwd 2>/dev/null)
[[ "$perms" == "644" ]]
check "/etc/passwd permissions (644)" $?

perms=$(stat -c %a /etc/shadow 2>/dev/null)
[[ "$perms" == "0" || "$perms" == "000" ]]
check "/etc/shadow permissions (000)" $?

# --- Kernel ---
echo -e "\n=== Kernel ==="

val=$(sysctl -n net.ipv4.tcp_syncookies 2>/dev/null)
[[ "$val" == "1" ]]
check "SYN cookies enabled" $?

val=$(sysctl -n kernel.randomize_va_space 2>/dev/null)
[[ "$val" == "2" ]]
check "ASLR enabled" $?

val=$(sysctl -n net.ipv4.conf.all.accept_redirects 2>/dev/null)
[[ "$val" == "0" ]]
check "ICMP redirects disabled" $?

# --- Пароли ---
echo -e "\n=== Пароли ==="

max_days=$(grep "^PASS_MAX_DAYS" /etc/login.defs | awk '{print $2}')
[[ "$max_days" -le 90 ]]
check "PASS_MAX_DAYS <= 90" $?

# --- Auditd ---
echo -e "\n=== Auditd ==="

systemctl is-active --quiet auditd
check "auditd: запущен" $?

# --- Итог ---
echo -e "\n=================================================="
echo "ИТОГО: PASS=$PASS  FAIL=$FAIL  WARN=$WARN"
total=$((PASS + FAIL + WARN))
if [ $total -gt 0 ]; then
    score=$((PASS * 100 / total))
    echo "Соответствие: ${score}%"
fi
echo "=================================================="
CHECK
chmod +x /tmp/cis_check.sh
```

```powershell
# windows_cis_check.ps1 — проверка CIS Benchmark
function Test-CIS {
    param([string]$Name, [bool]$Result)
    $status = if ($Result) { "[PASS]" } else { "[FAIL]" }
    $color = if ($Result) { "Green" } else { "Red" }
    Write-Host "$status $Name" -ForegroundColor $color
    return $Result
}

$pass = 0; $fail = 0

Write-Host "============================================"
Write-Host "  Windows CIS Benchmark Check"
Write-Host "  $(Get-Date -Format 'yyyy-MM-dd HH:mm')"
Write-Host "============================================`n"

Write-Host "=== Политики паролей ===" -ForegroundColor Cyan
$policy = (net accounts 2>$null) -join "`n"

$r = $policy -match "Minimum password length.*1[4-9]|[2-9]\d"
if (Test-CIS "Минимальная длина пароля >= 14" $r) { $pass++ } else { $fail++ }

$r = $policy -match "Lockout threshold.*[1-5]$"
if (Test-CIS "Блокировка после <= 5 попыток" $r) { $pass++ } else { $fail++ }

Write-Host "`n=== Аудит ===" -ForegroundColor Cyan
$audit = auditpol /get /category:* 2>$null

$r = $audit -match "Process Creation.*Success"
if (Test-CIS "Аудит создания процессов" $r) { $pass++ } else { $fail++ }

$r = $audit -match "Logon.*Success and Failure"
if (Test-CIS "Аудит входа (success+failure)" $r) { $pass++ } else { $fail++ }

Write-Host "`n=== Файрвол ===" -ForegroundColor Cyan
$fw = Get-NetFirewallProfile
foreach ($p in $fw) {
    $r = $p.Enabled -eq $true
    if (Test-CIS "Firewall $($p.Name): включён" $r) { $pass++ } else { $fail++ }
}

Write-Host "`n=== Безопасность ===" -ForegroundColor Cyan
$cmdline = (Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" `
    -Name ProcessCreationIncludeCmdLine_Enabled -ErrorAction SilentlyContinue).ProcessCreationIncludeCmdLine_Enabled
$r = $cmdline -eq 1
if (Test-CIS "Command line в Event 4688" $r) { $pass++ } else { $fail++ }

$pslog = (Get-ItemProperty "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" `
    -Name EnableScriptBlockLogging -ErrorAction SilentlyContinue).EnableScriptBlockLogging
$r = $pslog -eq 1
if (Test-CIS "PowerShell Script Block Logging" $r) { $pass++ } else { $fail++ }

Write-Host "`n============================================"
Write-Host "ИТОГО: PASS=$pass  FAIL=$fail"
$total = $pass + $fail
if ($total -gt 0) {
    $score = [math]::Round($pass * 100 / $total)
    Write-Host "Соответствие: ${score}%"
}
Write-Host "============================================"
```

**Шаг 3: Конвертация Sigma в формат SIEM**

```python
#!/usr/bin/env python3
"""sigma_converter.py — конвертация Sigma-правил."""
import yaml
import sys
import json

def sigma_to_wazuh(rule):
    """Конвертация Sigma-правила в Wazuh XML (упрощённая)."""
    title = rule.get('title', 'Unknown')
    level_map = {
        'informational': 3, 'low': 5, 'medium': 8,
        'high': 10, 'critical': 12
    }
    level = level_map.get(rule.get('level', 'medium'), 8)
    description = rule.get('description', '')

    detection = rule.get('detection', {})
    selections = []

    for key, value in detection.items():
        if key in ('condition', 'timeframe'):
            continue
        if isinstance(value, dict):
            for field, pattern in value.items():
                if isinstance(pattern, list):
                    for p in pattern:
                        selections.append(f'<field name="{field.split("|")[0]}">{p}</field>')
                else:
                    selections.append(f'<field name="{field.split("|")[0]}">{pattern}</field>')

    fields_xml = "\n    ".join(selections[:5])

    wazuh_rule = f"""
<rule id="9{level}0001" level="{level}">
  <description>{title}: {description}</description>
  {fields_xml}
  <group>sigma,{','.join(rule.get('tags', []))}</group>
</rule>"""

    return wazuh_rule

def main():
    if len(sys.argv) != 2:
        print(f"Использование: {sys.argv[0]} <sigma_rule.yml>")
        sys.exit(1)

    with open(sys.argv[1]) as f:
        docs = list(yaml.safe_load_all(f))

    for rule in docs:
        if rule:
            print(f"\n# {rule.get('title', 'Unknown')}")
            print(sigma_to_wazuh(rule))

if __name__ == "__main__":
    main()
```

```python
#!/usr/bin/env python3
"""
yara_scanner.py — сканирование файлов и директорий правилами YARA.
Использование: python3 yara_scanner.py <правила.yar> <путь>
"""
import yara
import os
import sys
import hashlib
from datetime import datetime

def md5sum(filepath):
    """Вычисление MD5."""
    h = hashlib.md5()
    try:
        with open(filepath, 'rb') as f:
            for chunk in iter(lambda: f.read(8192), b''):
                h.update(chunk)
        return h.hexdigest()
    except Exception:
        return "error"

def scan_file(rules, filepath):
    """Сканирование одного файла."""
    try:
        matches = rules.match(filepath, timeout=30)
        return matches
    except yara.TimeoutError:
        return None
    except yara.Error:
        return None

def scan_directory(rules_path, target_path):
    """Сканирование директории."""
    try:
        rules = yara.compile(filepath=rules_path)
    except yara.SyntaxError as e:
        print(f"[!] Ошибка синтаксиса правил: {e}")
        sys.exit(1)

    total = 0
    detected = 0
    findings = []

    print(f"{'='*60}")
    print(f"YARA SCANNER")
    print(f"Правила: {rules_path}")
    print(f"Цель: {target_path}")
    print(f"Время: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}")
    print(f"{'='*60}\n")

    if os.path.isfile(target_path):
        files = [target_path]
    else:
        files = []
        for root, dirs, filenames in os.walk(target_path):
            for fn in filenames:
                files.append(os.path.join(root, fn))

    print(f"Файлов для сканирования: {len(files)}\n")

    for filepath in files:
        total += 1
        matches = scan_file(rules, filepath)

        if matches:
            detected += 1
            for match in matches:
                severity = match.meta.get('severity', 'unknown')
                finding = {
                    'file': filepath,
                    'rule': match.rule,
                    'severity': severity,
                    'md5': md5sum(filepath),
                    'size': os.path.getsize(filepath),
                    'strings': [str(s) for s in match.strings[:5]]
                }
                findings.append(finding)

                color = '\033[31m' if severity == 'critical' else \
                        '\033[33m' if severity == 'high' else '\033[0m'
                print(f"{color}[{severity.upper()}] {match.rule}\033[0m")
                print(f"  Файл: {filepath}")
                print(f"  MD5: {finding['md5']}")
                print(f"  Размер: {finding['size']} байт")
                if finding['strings']:
                    print(f"  Совпадения: {finding['strings'][:3]}")
                print()

    print(f"{'='*60}")
    print(f"ИТОГО: проверено {total}, обнаружено {detected}")
    print(f"{'='*60}")

    return findings

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print(f"Использование: {sys.argv[0]} <правила.yar> <файл_или_директория>")
```

## Лаборатория 15: Корреляция событий

**Уровень:** Продвинутый
**Время:** 2–3 часа
**Инструменты:** Python 3, Wazuh
**Предварительные требования:** Опыт работы с SIEM, Python

### Цель

Понять принципы корреляции событий и построить Python-движок, который обнаруживает многоступенчатые атаки: brute force → success, reconnaissance → exploitation → lateral movement.

### Теория

**Что такое корреляция и зачем она нужна**

Отдельное событие (один неудачный вход, одно сетевое подключение) почти всегда безобидно. Атака — это **последовательность** событий. Корреляция связывает отдельные события в цепочку и поднимает алерт, когда паттерн совпадает.

Типы корреляции:
1. **Threshold** — количество событий превышает порог (>5 failed logins за минуту)
2. **Sequence** — события идут в определённом порядке (scan → exploit → shell)
3. **Absence** — ожидаемое событие НЕ произошло (логин без MFA)
4. **Statistical** — отклонение от baseline (трафик в 10 раз больше обычного)

### Пошаговое выполнение

**Шаг 1: Python корреляционный движок**

```python
#!/usr/bin/env python3
"""
correlation_engine.py — движок корреляции событий безопасности.
Обнаруживает многоступенчатые атаки по последовательности событий.
"""
import time
from collections import defaultdict
from datetime import datetime, timedelta
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class SecurityEvent:
    timestamp: datetime
    event_type: str
    src_ip: str
    dst_ip: str = ""
    user: str = ""
    details: str = ""
    severity: str = "info"

@dataclass
class Alert:
    title: str
    severity: str
    description: str
    events: list = field(default_factory=list)
    timestamp: datetime = field(default_factory=datetime.now)

class CorrelationEngine:
    def __init__(self):
        self.events = []
        self.alerts = []
        self.state = defaultdict(lambda: defaultdict(list))
        self.rules = []
        self._register_rules()

    def _register_rules(self):
        """Регистрация корреляционных правил."""
        self.rules = [
            self._rule_brute_force_success,
            self._rule_lateral_movement_chain,
            self._rule_data_exfiltration,
            self._rule_recon_to_exploit,
            self._rule_account_compromise,
        ]

    def add_event(self, event: SecurityEvent):
        """Добавить событие и проверить правила."""
        self.events.append(event)
        self.state[event.src_ip][event.event_type].append(event)

        for rule in self.rules:
            alert = rule(event)
            if alert:
                self.alerts.append(alert)
                self._print_alert(alert)

    def _get_recent(self, src_ip, event_type, minutes=5):
        """Получить недавние события данного типа от IP."""
        cutoff = datetime.now() - timedelta(minutes=minutes)
        return [
            e for e in self.state[src_ip][event_type]
            if e.timestamp > cutoff
        ]

    def _rule_brute_force_success(self, event: SecurityEvent) -> Optional[Alert]:
        """Правило: множество неудачных входов → успешный вход."""
        if event.event_type != "login_success":
            return None

        failures = self._get_recent(event.src_ip, "login_failure", minutes=10)
        if len(failures) >= 5:
            return Alert(
                title="BRUTE FORCE → SUCCESS",
                severity="CRITICAL",
                description=(
                    f"IP {event.src_ip}: {len(failures)} неудачных попыток, "
                    f"затем успешный вход как '{event.user}'"
                ),
                events=failures + [event]
            )
        return None

    def _rule_lateral_movement_chain(self, event: SecurityEvent) -> Optional[Alert]:
        """Правило: вход → сетевое подключение к другим хостам."""
        if event.event_type != "network_connection":
            return None

        logins = self._get_recent(event.src_ip, "login_success", minutes=30)
        connections = self._get_recent(event.src_ip, "network_connection", minutes=30)

        unique_targets = set(e.dst_ip for e in connections if e.dst_ip != event.src_ip)

        if logins and len(unique_targets) >= 3:
            return Alert(
                title="LATERAL MOVEMENT CHAIN",
                severity="HIGH",
                description=(
                    f"IP {event.src_ip}: вход, затем подключения к "
                    f"{len(unique_targets)} хостам: {', '.join(list(unique_targets)[:5])}"
                ),
                events=logins + connections[-5:]
            )
        return None

    def _rule_data_exfiltration(self, event: SecurityEvent) -> Optional[Alert]:
        """Правило: множество файловых доступов → большая сетевая передача."""
        if event.event_type != "large_transfer":
            return None

        file_access = self._get_recent(event.src_ip, "file_access", minutes=60)
        if len(file_access) >= 10:
            return Alert(
                title="DATA EXFILTRATION",
                severity="CRITICAL",
                description=(
                    f"IP {event.src_ip}: {len(file_access)} файловых доступов, "
                    f"затем крупная передача данных наружу"
                ),
                events=file_access[-5:] + [event]
            )
        return None

    def _rule_recon_to_exploit(self, event: SecurityEvent) -> Optional[Alert]:
        """Правило: сканирование → эксплуатация."""
        if event.event_type != "exploit_attempt":
            return None

        scans = self._get_recent(event.src_ip, "port_scan", minutes=30)
        if scans:
            return Alert(
                title="RECON → EXPLOIT",
                severity="HIGH",
                description=(
                    f"IP {event.src_ip}: сканирование портов, затем попытка "
                    f"эксплуатации {event.dst_ip}"
                ),
                events=scans + [event]
            )
        return None

    def _rule_account_compromise(self, event: SecurityEvent) -> Optional[Alert]:
        """Правило: успешный вход из необычной геолокации + действия."""
        if event.event_type != "privilege_change":
            return None

        logins = self._get_recent(event.src_ip, "login_success", minutes=60)
        anomalous = [l for l in logins if "unusual" in l.details.lower()]

        if anomalous:
            return Alert(
                title="ACCOUNT COMPROMISE",
                severity="CRITICAL",
                description=(
                    f"Пользователь '{event.user}': вход из необычного "
                    f"расположения, затем изменение привилегий"
                ),
                events=anomalous + [event]
            )
        return None

    def _print_alert(self, alert: Alert):
        """Вывод алерта."""
        colors = {
            "CRITICAL": "\033[31m",
            "HIGH": "\033[33m",
            "MEDIUM": "\033[36m",
        }
        color = colors.get(alert.severity, "\033[0m")
        reset = "\033[0m"

        print(f"\n{color}{'='*60}")
        print(f"[ALERT] {alert.title}")
        print(f"Severity: {alert.severity}")
        print(f"Time: {alert.timestamp.strftime('%Y-%m-%d %H:%M:%S')}")
        print(f"Description: {alert.description}")
        print(f"Events in chain: {len(alert.events)}")
        print(f"{'='*60}{reset}\n")

    def summary(self):
        """Итоговая сводка."""
        print(f"\n{'='*60}")
        print(f"CORRELATION ENGINE — SUMMARY")
        print(f"{'='*60}")
        print(f"Total events processed: {len(self.events)}")
        print(f"Total alerts generated: {len(self.alerts)}")
        for a in self.alerts:
            print(f"  [{a.severity}] {a.title}: {a.description[:80]}...")

# === Демонстрация ===
def demo():
    engine = CorrelationEngine()
    now = datetime.now()

    print("=== Симуляция атаки: Brute Force → Lateral Movement ===\n")

    # Фаза 1: Brute force
    for i in range(8):
        engine.add_event(SecurityEvent(
            timestamp=now + timedelta(seconds=i*5),
            event_type="login_failure",
            src_ip="10.10.10.50",
            dst_ip="10.0.1.10",
            user="admin",
            details=f"SSH failed attempt #{i+1}"
        ))

    # Фаза 2: Успешный вход
    engine.add_event(SecurityEvent(
        timestamp=now + timedelta(seconds=45),
        event_type="login_success",
        src_ip="10.10.10.50",
        dst_ip="10.0.1.10",
        user="admin",
        details="SSH successful login"
    ))

    # Фаза 3: Lateral movement
    for target in ["10.0.1.20", "10.0.1.30", "10.0.1.40", "10.0.2.10"]:
        engine.add_event(SecurityEvent(
            timestamp=now + timedelta(minutes=2),
            event_type="network_connection",
            src_ip="10.10.10.50",
            dst_ip=target,
            details=f"SMB connection to {target}"
        ))

    engine.summary()

if __name__ == "__main__":
    demo()
```

## Лаборатория 16: Триаж алертов SOC L1

### Теория

**Методология триажа SOC L1:**

1. **Контекст** — кто, откуда, когда, что за хост
2. **Верификация** — алерт реальный или шум?
3. **Масштаб** — один хост или несколько? Один пользователь или все?
4. **Решение** — True Positive → эскалация L2 | False Positive → закрытие с обоснованием

**Чеклист для каждого алерта:**
- [ ] Кто источник? (IP, хост, пользователь)
- [ ] Это известный легитимный процесс/активность?
- [ ] Есть ли контекст в TI? (IP в блоклистах?)
- [ ] Что происходило до и после? (корреляция)
- [ ] Масштаб? (затронуты другие хосты/учётки?)
- [ ] Решение: TP/FP + обоснование

```python
#!/usr/bin/env python3
"""
email_header_analyzer.py — анализ заголовков email на фишинг.
"""
import re
import sys

def analyze_headers(headers_text):
    """Анализ email headers."""
    findings = []
    risk_score = 0

    # SPF check
    spf_match = re.search(r'spf=(\w+)', headers_text, re.IGNORECASE)
    if spf_match:
        spf = spf_match.group(1).lower()
        if spf == 'fail':
            findings.append("[!] SPF: FAIL — отправитель не авторизован")
            risk_score += 3
        elif spf == 'softfail':
            findings.append("[?] SPF: SOFTFAIL — подозрительно")
            risk_score += 2
        elif spf == 'pass':
            findings.append("[+] SPF: PASS")

    # DKIM check
    dkim_match = re.search(r'dkim=(\w+)', headers_text, re.IGNORECASE)
    if dkim_match:
        dkim = dkim_match.group(1).lower()
        if dkim in ('fail', 'none'):
            findings.append(f"[!] DKIM: {dkim.upper()}")
            risk_score += 2
    else:
        findings.append("[!] DKIM: отсутствует")
        risk_score += 2

    # DMARC check
    dmarc_match = re.search(r'dmarc=(\w+)', headers_text, re.IGNORECASE)
    if dmarc_match:
        if dmarc_match.group(1).lower() == 'fail':
            findings.append("[!] DMARC: FAIL")
            risk_score += 3

    # Return-Path vs From mismatch
    return_path = re.search(r'Return-Path:\s*<([^>]+)>', headers_text, re.IGNORECASE)
    from_addr = re.search(r'From:.*<([^>]+)>', headers_text, re.IGNORECASE)
    if return_path and from_addr:
        rp_domain = return_path.group(1).split('@')[-1]
        from_domain = from_addr.group(1).split('@')[-1]
        if rp_domain != from_domain:
            findings.append(f"[!] Return-Path ({rp_domain}) ≠ From ({from_domain})")
            risk_score += 3

    # X-Mailer suspicious
    mailer = re.search(r'X-Mailer:\s*(.+)', headers_text, re.IGNORECASE)
    if mailer:
        m = mailer.group(1).lower()
        if any(s in m for s in ['phpmailer', 'swiftmailer', 'phpmail']):
            findings.append(f"[!] X-Mailer: {mailer.group(1)} — массовая рассылка")
            risk_score += 2

    # Received hops
    received = re.findall(r'Received: from\s+(\S+)', headers_text, re.IGNORECASE)
    findings.append(f"[i] Цепочка серверов: {' → '.join(reversed(received))}")

    # Summary
    verdict = "ФИШИНГ" if risk_score >= 5 else "ПОДОЗРИТЕЛЬНО" if risk_score >= 3 else "ВЕРОЯТНО ЛЕГИТИМНО"

    print(f"\n{'='*50}")
    print(f"EMAIL HEADER ANALYSIS")
    print(f"{'='*50}")
    for f in findings:
        print(f"  {f}")
    print(f"\n  Risk Score: {risk_score}/15")
    print(f"  Verdict: {verdict}")
    print(f"{'='*50}")

if __name__ == "__main__":
    if len(sys.argv) == 2:
        with open(sys.argv[1]) as f:
            analyze_headers(f.read())
    else:
        sample = """From: IT <it@company-update.com>
Received: from mail.evil-server.net (185.234.72.10)
Authentication-Results: spf=fail; dkim=none; dmarc=fail
Return-Path: <bounce@evil-server.net>
X-Mailer: PHPMailer 6.1.7"""
        analyze_headers(sample)
```

### Python-скрипт для timeline

```python
#!/usr/bin/env python3
"""
timeline_builder.py — сборка единого timeline из разных источников логов.
"""
import re
import csv
from datetime import datetime

def parse_syslog(filepath):
    """Парсинг syslog/auth.log."""
    events = []
    with open(filepath) as f:
        for line in f:
            match = re.match(r'(\w+\s+\d+\s+\d+:\d+:\d+)\s+(\S+)\s+(\S+?)(?:\[\d+\])?: (.+)', line)
            if match:
                try:
                    ts = datetime.strptime(f"2024 {match.group(1)}", "%Y %b %d %H:%M:%S")
                except ValueError:
                    continue
                events.append({
                    'timestamp': ts,
                    'source': filepath,
                    'host': match.group(2),
                    'program': match.group(3),
                    'message': match.group(4)
                })
    return events

def parse_csv_log(filepath, ts_field='timestamp', msg_field='message'):
    """Парсинг CSV-лога."""
    events = []
    with open(filepath) as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                ts = datetime.fromisoformat(row[ts_field])
            except (ValueError, KeyError):
                continue
            events.append({
                'timestamp': ts,
                'source': filepath,
                'host': row.get('host', 'unknown'),
                'program': row.get('source', 'unknown'),
                'message': row.get(msg_field, str(row))
            })
    return events

def build_timeline(event_lists):
    """Объединение и сортировка событий."""
    all_events = []
    for events in event_lists:
        all_events.extend(events)
    return sorted(all_events, key=lambda e: e['timestamp'])

def print_timeline(events, limit=100):
    """Вывод timeline."""
    print(f"{'='*80}")
    print(f"{'ВРЕМЯ':>22} | {'ИСТОЧНИК':>12} | {'ХОСТ':>15} | СОБЫТИЕ")
    print(f"{'='*80}")
    for e in events[:limit]:
        ts = e['timestamp'].strftime('%Y-%m-%d %H:%M:%S')
        src = e['program'][:12]
        host = e['host'][:15]
        msg = e['message'][:60]
        print(f"{ts:>22} | {src:>12} | {host:>15} | {msg}")

if __name__ == "__main__":
    print("Timeline Builder — добавьте свои источники логов")
```
